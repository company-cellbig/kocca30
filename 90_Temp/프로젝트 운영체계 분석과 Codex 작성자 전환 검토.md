> 이 저장소는 원자료에서 위키 지식, 프로젝트 설계, 외부 산출물로 지식을 흘려보내는 무형문화유산 프로젝트 지식 기반임. 작성자를 Codex로 바꿀 때는 Claude Code를 주 외부 검토자로 두는 편이 역할 독립성과 결함 발견 다양성을 더 잘 보존함.

# 1. 프로젝트 성격

이 저장소는 한국콘텐츠진흥원 무형문화유산 과제의 지식, 기획, 원자료, 시범콘텐츠, 프로토타입을 함께 관리함. 단순 문서 보관소가 아니라 원자료를 수집 시점에 위키 지식으로 바꾸고, 이를 프로젝트 설계와 외부 산출물에 공급하는 지식 생산 체계임.

핵심 콘텐츠 범위는 남사당놀이 여섯 종목임.

- 개념층: 풍물, 버나, 살판, 어름, 덧뵈기, 덜미를 엔티티로 관리함
- 원자료층: 제안서 변환본, 종목 전사본, 기록영상과 외부 자료 분석을 관리함
- 설계층: 공통 플랫폼, 키오스크, 디바이스, 콘텐츠별 설계를 관리함
- 산출물층: 콘텐츠 기획서 여섯 종과 킥오프 발표자료를 관리함
- 실행 자산층: 클라이언트 데이터, 프로토타입, 이미지와 제작 가이드를 관리함

현재 [[MOC]]에서 구체화 정도가 높은 콘텐츠는 덜미의 `나만의 유람기`와 `나만의 꼭두각시`, 덧뵈기의 `나만의 탈춤`과 `양반 놀리기 4컷`임. 버나와 살판은 기획서 골격 또는 초안 단계이며, 풍물과 어름은 독립 콘텐츠 기획서가 MOC에 등재되지 않음.

# 2. 지침 문서 분석

## 2.1 CLAUDE.md

`CLAUDE.md`는 실질 규칙을 중복해서 담지 않고 `@AGENTS.md`를 불러오는 Claude Code 진입점임. [[AGENTS]]가 다시 [[CONVENTIONS]]를 불러오므로 Claude Code에서는 두 정본을 연쇄 로드하는 구조임.

- 장점: 규칙 중복과 갱신 불일치를 줄임
- 한계: Codex 등 `@import`를 해석하지 않는 도구는 두 문서를 직접 읽어야 함
- 형식 결함: 모든 문서에 `type`과 `status`를 두도록 한 [[CONVENTIONS#3.2 프론트매터 (YAML)]]와 달리 `CLAUDE.md`에는 두 필드가 없음. 도구 진입점 예외를 명시하거나 필드를 보완할 필요가 있음

## 2.2 AGENTS.md

`AGENTS.md`는 AI의 역할, 작업 사이클, 검수 게이트와 수정 권한을 정의함. 현행 역할은 Claude Code 작성자, Codex 외부 검토자, 사용자 중재자임.

강점은 권한과 검증 단계를 명시적으로 분리한 점임.

- 작성과 외부 검토를 다른 도구에 배정함
- 외부 검토 결과를 사용자의 수용 결정 없이 반영하지 못하게 함
- 기계 검수와 의미 검수를 구분함
- 정본과 외부 산출물의 자율 편집을 제한함
- 검토 무발견을 결함 부재의 증명으로 표현하지 못하게 함

운영 부담도 큼. 보통의 본문 변경에도 여러 단계가 이어짐.

- 필수 단계: 구조 설계, 자동 점검 세 종, 자기검수, 맥락 독립 검토, 로그, 커밋, G1
- 조건부 단계: 외부 검토와 G2

고위험 정본에는 적합하지만 내부 설계 메모까지 같은 강도로 적용하면 절차 비용이 본문 작성 비용을 넘어설 수 있음.

## 2.3 CONVENTIONS.md

`CONVENTIONS.md`는 위키의 정보 구조와 문서 작성 문법을 정의함.

- 정보 구조: 원자료, 개념, 설계, 산출물, 실행 데이터를 물리적으로 나눔
- 근거 통제: 수치와 목표에 출처를 요구하고 L1~L5 권위 계층을 적용함
- 변경 통제: `_locked`, `_sources`, `_figures`, `_reviews`, `_archive`를 보호함
- 문서 통제: Atomic Notes, MOC, wikilink, frontmatter, 쉬운 음슴체를 적용함
- 자동화: 헤딩 번호, anchor, 링크, 인용과 파생 문구를 스크립트로 점검함

가장 중요한 문제는 참조 순서와 상호 연결 규칙의 충돌임. 앞 번호 폴더가 뒤 번호 폴더를 근거로 삼지 못하게 하면서 관련 문서의 양방향 연결도 요구함. 근거 의존성과 탐색 링크를 같은 wikilink로 표현하므로 정상적인 역방향 탐색 링크도 참조 순서 경고가 됨.

# 4. 규칙 사이의 주요 충돌

## 4.1 참조 순서와 양방향 링크

`02_References`와 `03_Concepts`를 양방향 연결하면 `02_References`에서 `03_Concepts`로 가는 링크는 참조 순서 위반이 됨. 현재 경고 111건의 다수가 같은 유형임.

해결하려면 근거 링크와 탐색 링크를 구분해야 함.

- 권장: 출처 또는 근거로 선언한 링크만 참조 순서 검사 대상으로 삼음
- 대안: 역방향 연결을 본문에서 제거하고 Obsidian backlinks에 맡김
- 대안: `관련 문서` 절 또는 별도 표기의 링크를 참조 순서 검사에서 제외함

## 4.2 G1 항상 수행과 자동 통과

[[AGENTS#2.4.3 작은 변경 사이클 면제 (엄격)]]은 사용자 G1을 항상 수행한다고 적음. 반면 [[AGENTS#2.4.1 G1: 작성자 자기검수 후]]의 자동 통과 조건은 G1을 생략한다고 적음. 자동 통과가 사용자 응답 없이 통과로 기록하는 것인지, G1 자체를 실행하지 않는 것인지 하나로 확정해야 함.

## 4.3 승인 후 반영과 G1 전 커밋

AGENTS는 모든 본문 반영이 사용자 승인 후라고 선언하지만 작성자 흐름은 G1 전에 본문 작성, 작은 결함 정정, 로그와 커밋을 수행함. 실제 의도가 외부 검토 발견의 정본 반영만 승인 대상으로 삼는 것이라면 해당 선언의 범위를 좁혀야 함.

## 4.4 도구별 역할 고정

현행 규칙은 Codex를 외부 검토자로만 정의함. 사용자가 Codex에 일반 질의, 작성, 유지보수를 직접 요청할 때 어떤 역할을 맡는지 정의하지 않음. 작성자를 Codex로 전환하려면 도구 이름을 역할 정의에서 분리하거나 역할표를 뒤집는 수준의 명시적 개정이 필요함.

# 5. Codex 작성자 전환 검토

## 5.1 권고안

주 작성자는 Codex, 주 외부 검토자는 Claude Code, 중재자는 사용자로 바꾸는 구성을 권고함.

| 역할 | 권고 도구 | 책임 |
|---|---|---|
| 작성자 | Codex | 구조 설계, 초안과 갱신, 자동 검사, 자기검수, 로그와 커밋 |
| 외부 검토자 | Claude Code | 사실과 정합, 논리와 한계, 가독성을 fresh context에서 검토 |
| 중재자 | 사용자 | 발견 항목의 수용, 보류, 반려 결정 |

작성자와 외부 검토자를 다른 모델 계열로 나누면 다음 이점이 있음.

- 작성자의 반복 편향과 표현 습관을 검토자에게 그대로 복제할 가능성이 낮아짐
- 같은 지침을 서로 다르게 해석하는 지점을 발견하기 쉬움
- Codex의 저장소 탐색과 구현 능력을 작성 흐름에 집중시킬 수 있음
- 기존 3역할의 핵심인 작성자와 외부 검토자 사이의 관점 분리를 유지함

Claude Code가 항상 더 정확하다는 뜻은 아님. 권고 근거는 모델 서열이 아니라 작성자와 검토자의 독립성임. 검수 품질을 확보하려면 Claude Code에도 같은 포커스 텍스트 사용, 원자료 접근 보장, fresh context 유지, 발견 항목 형식 준수를 요구해야 함.

## 5.2 Codex 검수 유지안

Codex가 작성과 외부 검토를 모두 맡는 구성은 과도기 대안으로만 적합함.

- 장점: 현재 Codex 검수 포커스와 호출 절차를 많이 재사용할 수 있음
- 한계: fresh context를 써도 모델 특유의 누락과 해석 편향이 반복될 수 있음
- 한계: 작성과 검수의 책임 경계가 흐려지고 사용자가 두 결과의 독립성을 과대평가할 수 있음

Claude Code 호출 통로를 바로 만들 수 없다면 다음처럼 운용함.

1. Codex 작성 세션이 본문과 자기검수를 완료함
2. 작성 의도와 추론을 주지 않은 새 Codex 세션이 완성 텍스트만 검토함
3. 큰 변경과 외부 산출물은 사용자가 Claude Code에 별도 검토를 요청함
4. 보고에는 `동일 모델 fresh-context 검토`라고 명시해 독립성 한계를 숨기지 않음

## 5.3 검수 책임 재배치

작성자 전환 뒤 검수 항목은 다음처럼 나누는 편이 명확함.

- Codex 자기검수: P1 사실과 출처의 1차 대조, P5 링크와 저장소 정합, 자동 검사 수행
- Claude Code 외부 검토: P1 근거 재대조, P2 논리 비약, P3 누락 반론과 한계, P4 가독성
- 사용자 중재: 근거 등급 확인, 정책 선택, 외부 검토 발견의 반영 승인
- 스크립트: 헤딩, anchor, 형식, 인용 범위 등 결정적인 기계 검사를 계속 담당함

# 6. 전환 작업 우선순위

## 6.1 P0 전환 전에 확정할 항목

1. 역할표와 작업 사이클을 Codex 작성자, Claude Code 검토자로 개정함
2. Claude Code가 사용할 외부 검토 호출 절차와 입력 형식을 정의함
3. G1 항상 수행과 자동 통과의 모순을 해소함
4. `모든 본문 반영은 승인 후`의 적용 범위를 외부 검토 발견 반영 등으로 정확히 한정함
5. Claude Code 검토를 호출할 수 없을 때의 동일 모델 fresh-context 대체 절차를 명시함

## 6.2 P1 전환 직후 안정화할 항목

1. `codex 검수 포커스`를 도구 중립적인 `외부 검수 포커스`로 일반화하거나 Claude Code용 대응 문서를 만듦
2. Codex가 `@import` 없이 AGENTS와 CONVENTIONS를 함께 읽도록 진입 절차를 명시함
3. `core.hooksPath` 설치 여부를 진단하고 클론 초기화 절차에 포함함
4. 참조 순서 검사에서 근거 링크와 탐색 링크를 구분해 상시 경고 111건을 정리함
5. 한두 개의 실제 문서를 대상으로 Codex 작성과 Claude Code 검토의 시험 사이클을 실행하고 발견 유형을 기록함

## 6.3 P2 운영 비용을 줄일 항목

1. GitLab 기본 템플릿 상태인 `README.md`를 프로젝트 진입 안내로 교체함
2. AGENTS의 반복 설명을 줄이고 상세 체크리스트를 HowTo 문서로 분리함
3. 루트 도구 진입점과 일반 위키 문서의 frontmatter 예외를 명시함
4. 변경 위험도에 따라 검수 강도를 나누되 정본, 수치, 외부 산출물에는 현행 강도를 유지함
5. 검토 결과에서 모델, 컨텍스트 격리 방식, 대조한 원자료와 발견 건수를 일정한 형식으로 기록함

# 7. 권장 전환 순서

안전한 전환은 앞 절의 우선순위를 다음 순서로 실행함.

1. P0의 역할 전환 원칙과 Claude Code 주 검수자 지정을 사용자가 승인함
2. 나머지 P0 항목을 반영해 역할, 호출, 게이트와 대체 절차를 확정함
3. P1의 검수 포커스, Codex 진입 절차와 자동 검사 환경을 정비함
4. 내부 위키 문서 한 건과 외부 산출물 한 건으로 시험 사이클을 수행함
5. 두 시험의 누락, 중복 발견과 운영 시간을 비교한 뒤 정식 전환함
6. P2 항목은 시험 결과에 따라 순차 적용함

# 8. 종합 판단

이 저장소는 AI가 무엇을 쓰는지만이 아니라 근거, 위치, 승인 권한과 수정 금지 범위까지 통제하는 성숙한 운영체계임. 다만 규칙이 축적되면서 참조 순서와 상호 연결, G1 수행 여부, 승인 전후 시점에 충돌이 생김.

Codex를 작성자로 바꾸는 일은 역할 이름만 뒤집는 변경이 아님. 외부 검토 호출 통로, 포커스 문서의 도구 중립화, Claude Code를 호출할 수 없을 때의 대체 절차와 검토 보고 형식까지 함께 바꿔야 함. 최종 권고는 Codex 작성, Claude Code 주 검수, 사용자 중재이며, 동일 Codex 검수는 Claude Code를 호출할 수 없는 동안의 명시적 과도기 수단으로 제한함.
