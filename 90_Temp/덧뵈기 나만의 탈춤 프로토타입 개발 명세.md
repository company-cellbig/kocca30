> 원전 대사는 생략하지 않고 마당별 상세 진행 안에 배치하며, 원전 지문은 화면 연출의 근거로 보존해 실제 재담 흐름과 플레이 입력의 연결을 검토하는 65인치 가로형 키오스크 프로토타입 개발 명세임.

# 1. 개발 목적과 완료 기준

프로토타입은 화면 시안이나 원전 열람기가 아님. 원전 재담을 처음부터 끝까지 진행하면서 게임의 입력 시점, 흐름의 어색함, 재미와 전체 체험 길이를 판단하는 실행형 검토 도구임.

완료하려면 다음 조건을 모두 충족해야 함.

- 정상 입력 경로에서는 선택한 마당 전체를 끝까지 체험함. 인식 재확인 실패 경로는 승인된 복구 또는 종료 상태에 도달함
- 원전 범위의 대사를 생략, 요약, 의역하거나 순서를 바꾸지 않음. 원전 지문은 보존 데이터와 연출 근거에 남기되 관람객에게 문장으로 표시하지 않음
- 원전 항목과 설계 추가 항목을 데이터와 화면에서 구분함
- 마당별 상세 진행표의 상태, 입력과 성공/실패 분기를 생략하지 않음
- 모든 원전 대사와 설계 대사를 하단 전용 공간에 교대로 표시하고, 행동 안내는 장쇠의 설계 대사로 처리함
- 중앙 무대는 등장인물, 위치, 행동과 결과 연출에만 사용함
- 실제 센서가 없어도 성공, 실패, 무입력, 인식 실패와 완화 경로를 화면 조작으로 시험할 수 있음
- 원전 전수 대조와 상태 전이 경로 검사를 자동으로 다시 실행할 수 있음

# 2. 개발 정본과 충돌 처리

## 2.1 정본

정보마다 다음 정본을 사용함.

| 정보 | 정본 | 적용 범위 |
|---|---|---|
| 원전 대사, 지문, 화자, 사건 순서, 등장과 퇴장 | [[남사당놀이 - 덧뵈기]] | 원문 문자열과 연희본의 사실 |
| 게임 상태, 화면 행동, 플레이어 입력, 판정과 분기 | [[덧뵈기 나만의 탈춤 재설계 방향]] | 4.6, 5.5, 6.5와 7.6 |
| 사용자 확정 지시 | 본 개발 명세의 승인된 결정 | 하단 지문 비표시, 원전 대사 전수 진행, 장쇠의 행동 안내와 구현 게이트 |

## 2.2 충돌 처리

- 원전과 설계를 임의로 섞어 제3의 장면을 만들지 않음
- 원전 데이터는 `원전 대사`와 `원전 지문`으로 구분해 보존함. 화면에는 원전 대사와 설계 대사만 표시하고 새 안내와 동작은 `설계 추가`로 구분함
- 설계가 원전 대목을 제외하거나 바꾼 경우 원전 문자열, 화면 재현과 플레이 입력을 각각 나눠 판단함
- 사용자 결정이 필요한 충돌은 구현 전에 [[#12. 확정된 구현 결정]]에서 확정함
- 결정되지 않은 항목을 일반적인 게임 관행이나 구현 편의로 대신하지 않음

# 3. 산출물과 파일 구조

`prototype/` 폴더만 복사해도 로컬에서 실행되는 자족형 구조로 만듦. CDN, 웹폰트와 외부 스크립트를 사용하지 않음.

| 파일 | 역할 |
|---|---|
| `prototype/덧뵈기-나만의탈춤-프로토타입.html` | 공통 화면, 상태 실행기와 개발자용 시험 조작 |
| `prototype/덧뵈기-원전대사.js` | 원전 대사와 지문의 보존 데이터 |
| `prototype/덧뵈기-진행상태.js` | 상세 진행 상태, 원전 대응, 입력과 분기 데이터 |
| `prototype/덧뵈기-표시도구.js` | HTML과 자동 검증이 함께 쓰는 문장 페이지 분할 도구 |
| `prototype/덧뵈기-프로토타입-검증.js` | 원전 전수, 상태 도달성과 분기 검사 |
| `prototype/assets/` | 프로토타입에서 실제 사용하는 2D 스프라이트와 배경 |

원전 데이터와 진행 상태를 분리함. 화면 코드에 대사와 상태를 직접 흩어 적지 않음.

# 4. 원전 전수 데이터

## 4.1 추출 범위와 건수

비어 있지 않은 원전 행을 보존 단위로 추출함. 건수는 현재 전사본을 기준으로 기계 집계한 값이며, 대사와 지문의 의미 항목 수가 아님. 한 행 안에 대사와 인라인 지문이 함께 있으면 행 안의 `segments`로 나눔.

| 마당 | 원전 범위 | 비어 있지 않은 원전 행 | 유저 배역 |
|---|---:|---:|---|
| 옴탈잡이 | 420~466행 | 24개 | 꺽쇠 |
| 샌님잡이 | 470~626행 | 79개 | 말뚝이 |
| 먹중잡이 | 630~704행 | 38개 | 취발이 |

## 4.2 항목 구조

원전 행마다 다음 필드를 둠.

| 필드 | 뜻 |
|---|---|
| `sourceLine` | 전사본의 원문 행 번호 |
| `sourceText` | 가공하지 않은 원문 문자열 |
| `displayText` | 화면 표시값. 원문과 다르면 변환 이유를 별도 기록함 |
| `segments` | 한 행 안의 대사와 인라인 지문을 순서대로 나눈 목록 |
| `segments[].type` | `dialogue` 또는 `direction` |
| `segments[].speaker` | 화자 이름, 지문이면 `지문` |
| `segments[].text` | 해당 구간의 원문 문자열 |
| `sceneId` | `omtal`, `saennim`, `meokjung` 중 하나 |
| `eventIds` | 해당 행에 걸친 O/S/M 원자 사건 ID 목록 |
| `stateIds` | 해당 행에 걸친 상세 진행 상태 ID 목록 |

`sourceText`는 수정하지 않음. 마크다운 강조 문자를 화면에서 숨길 필요가 있으면 `displayText`만 바꾸고 두 값의 차이를 검사 결과에 표시함.

## 4.3 전수 검사

HTML 구현 전에 다음 검사를 통과해야 함.

- 범위 안의 비어 있지 않은 원전 행과 데이터 행 수가 같음
- 모든 원전 행이 정확히 한 번 대응함
- 첫 행, 마지막 행과 전체 순서가 같음
- `sourceText`가 원문과 문자 단위로 같음
- 한 행에 섞인 대사와 인라인 지문이 `segments`에 원문 순서대로 모두 들어감
- 각 행의 `eventIds`와 `stateIds`에 값이 하나 이상 있어야 함. 하나라도 비면 전수 검사에 실패하고 구현을 시작하지 않음

# 5. 공통 화면과 표시 규칙

## 5.1 화면 영역

- **화면 기준**: 65인치, 16:9 가로형, 1920×1080 논리 좌표를 사용함
- **상단 상태 영역**: 마당 이름과 그만두기 버튼만 표시함
- **중앙 무대 영역**: 배경, 2D 스프라이트, 인물 위치, 동작과 결과를 표시함. 입력 또는 인식이 필요한 순간에는 손 위치 표식, 손가락 방향선과 인식 윤곽을 겹쳐 표시할 수 있음
- **하단 전용 공간**: 원전 대사 또는 설계 대사 중 하나만 표시함. 플레이어 행동 안내는 장쇠의 설계 대사로 표시함
- **개발자 시험 도구**: 키오스크 화면과 구분하고 숨길 수 있게 둠. 원전 행, 현재 상세 상태, 전체 진행률, 상태 이동과 입력 모사를 이 도구에서만 표시함
- **그만두기**: 누르면 진행 중인 자동 재생과 예약 전이를 취소하고 종료 확인 화면으로 이동함. 종료를 확정하면 시작 화면, 취소하면 현재 상태로 돌아감

## 5.2 하단 전용 공간

텍스트 종류를 색과 꼬리표로 구분하되 위치는 바꾸지 않음.

| 종류 | 화자 표시 | 내용 |
|---|---|---|
| 원전 대사 | 실제 화자 | `sourceText` 또는 승인된 `displayText` |
| 설계 대사 | 실제 화자 + `설계` 꼬리표 | 상세 진행표의 설계 대사 |
| 행동 안내 | `장쇠` + `설계` 꼬리표 | 장쇠가 말하는 그 순간 필요한 플레이어 행동 한 가지 |

- 원전 데이터의 잽이 화자 정보와 대사 문자열은 그대로 보존하되, 프로토타입 화면에서는 장쇠가 잽이 대사를 대신 말함
- 장쇠가 대신 말하는 잽이 대사는 `원전 재담`으로 표시해 장쇠의 행동 안내와 구분함

- 말풍선을 사용하지 않음
- 원전 지문은 하단, 중앙 카드, 팝업이나 별도 패널에 문장으로 표시하지 않고 중앙 무대 연출의 근거로만 사용함
- 하단 대사를 두 개 이상 동시에 겹쳐 표시하지 않음
- 긴 대사는 글자를 임의로 줄이지 않고 페이지 나눔이나 문장 단위 이어 보기를 사용함
- 페이지를 나눠도 원문 순서와 전체 문자열을 유지함

## 5.3 등장인물과 장쇠

- 각 마당 시작 때 전체 무대를 보여준 뒤 인물 중심 화면으로 전환함
- 장쇠는 모든 마당의 진행 호스트임
- 장쇠는 배역 소개, 입력 안내와 시범, 장면 전환, 결과 선언, 마무리와 원전 잽이의 대사를 담당함
- 장쇠는 잽이를 제외한 다른 원전 배역의 대사를 대신하거나 원전 사건을 설명으로 대체하지 않음
- 유저 배역은 옴탈잡이 꺽쇠, 샌님잡이 말뚝이, 먹중잡이 취발이로 고정함
- 원전 등장 전 유저 배역은 무대 밖 대기 표시로만 보여줌

# 6. 공통 상태 구조

화면 상태는 다음 세 종류를 사용함.

1. **원전 재생 상태**
   - 원전 대사 하나를 하단에 표시함. 원전 지문은 같은 순서의 중앙 무대 연출 근거로만 사용함
   - 승인된 재현, 순화 또는 비재현 정책에 따라 대응 연출을 중앙 무대에서 재생함
2. **설계 진행 상태**
   - 장쇠의 행동 안내 대사, 입력 연습과 장면 전환을 수행함
   - 원전 항목으로 오인되지 않게 `설계` 또는 `안내`로 표시함
3. **판정 상태**
   - 성공, 실패, 무입력, 인식 끊김과 재확인을 처리함
   - 원전 진행 위치를 바꾸지 않고 정해진 다음 상태로 이동함

각 상태에는 다음 필드를 둠.

- 상태 ID와 상세 진행표의 원래 순서명
- 근거 사건 ID와 원문 행 목록
- 등장인물과 레이어
- 하단 표시 큐
- 화면 행동
- 입력 종류와 판정 시작 신호
- 성공, 실패, 무입력과 인식 실패의 다음 상태
- 재시도 상한과 완화 값
- 종료, 복구 또는 마무리 목적지

# 7. 옴탈잡이 구현 명세

## 7.1 옴탈잡이 상태 뼈대

4.6의 16개 상위 순서를 합치거나 생략하지 않음. 원전 재생을 위해 하위 상태를 추가해도 상위 순서와의 대응을 유지함.

1. 마당 전경
2. 위치와 동작 인식 확인
3. 옴탈 등장
4. 첫 접근 신호
5. 첫 회피 성공
6. 첫 회피 실패
7. 연속 회피 준비
8. 연속 회피 종료
9. 연속 회피 실패
10. 퇴치 전환
11. 첫 퇴치 시도
12. 첫 퇴치 성공
13. 첫 퇴치 실패
14. 마지막 공방
15. 최종 퇴치
16. 마당 마무리

## 7.2 옴탈잡이 필수 입력과 분기

- 위치와 좌우 동작 인식, 재확인 실패 시 종료
- 첫 접근의 반대 방향 회피
- 첫 회피 실패 뒤 같은 접근 재시도
- 재실패 뒤 접근 속도와 충돌 영역 한 차례 완화
- 좌우를 바꾼 복수의 연속 회피
- 연속 회피 실패 뒤 같은 접근 재시도와 완화
- 두 팔 밀어내기 연습과 중립 자세 복귀 확인
- 첫 퇴치 판정 시간 안의 밀어내기
- 첫 퇴치 실패 뒤 재시도와 판정 영역/허용 시간 완화
- 마지막 공방의 가짜 방향 전환, 반대쪽 회피와 정지 뒤 밀어내기
- 마지막 공방 실패 뒤 한 차례 완화와 실패 결말

## 7.3 옴탈잡이 원전 대응 결정

4.6의 회피/밀어내기 구조만으로는 원전 420~466행 전체를 자동 배치할 수 없음.

- 420~430행은 꺽쇠 등장, 옴탈 등장과 쫓고 피하는 흐름이라 3~6번 상태에 대응 가능함
- 432~456행은 꺽쇠가 옴탈의 머리와 얼굴을 직접 붙잡고 문답/채검하는 긴 대목임. 4.6에는 이 대목과 대응하는 상태가 없음
- 458~466행은 옴탈의 대들기, 꺽쇠의 춤과 추격 퇴장이라 10~16번 상태에 일부 대응 가능함

432~456행의 재생 위치와 직접 접촉 처리 방식은 [[#12. 확정된 구현 결정]]을 따름.

# 8. 샌님잡이 구현 명세

## 8.1 샌님잡이 상태 뼈대

5.5의 상세 진행 19개 순서를 합치거나 생략하지 않음.

- 마당 전경

## 8.2 샌님잡이 필수 입력과 분기

- 선택 결과는 샌님의 반응 자산만 바꾸며 원전 사건과 결말을 막지 않음
- 손 인식 재확인 실패는 복구 화면으로 이동함

## 8.3 샌님잡이 원전 대응 결정

- S13의 친족 호칭, 피조리 대상화와 비하 대사는 설계 흐름에서 제외됨

원전 대사 전체 표시와 기존 제외 정책의 충돌은 [[#12. 확정된 구현 결정]]처럼 원문 표시와 화면 행동을 분리해 처리함.

## 9.2 먹중잡이 필수 입력과 분기

- 원전 등장 전 취발이는 무대 밖 대기 표시로만 둠
- 연습 단계에서는 표식과 방향선으로 손가락 지목을 확인함
- M2와 M3은 먹중과 피조리의 집단 반응으로 먼저 보여줌
- 먹중의 부채와 고개 동작은 `설계 추가`로 명시함
- 정시 지목만 포착으로 처리함
- 이른 지목은 확정하지 않고 원전 동작을 계속 보여줌
- 늦은 지목, 무입력, 모호 입력과 판정창 중 인식 끊김은 포착을 생략하고 다음 원전 사건으로 진행함
- 같은 원전 사건을 재시도하거나 다음 지목의 판정 범위를 완화하지 않음
- 포착 수는 마무리 반응만 바꾸며 먹중 퇴장과 결말을 막지 않음

## 9.3 먹중잡이 원전 대응 결정

6.5에는 원전의 민감 표현과 신체 행동을 바꾼 부분이 있음.

- M5에서 원전은 취발이가 먼저 대들고 먹중이 따라 덤빔. 설계 화면은 취발이의 선행 대들기를 직접 재현하지 않을 수 있음
- M10의 피조리 외모 품평, 소유물처럼 다루는 재담과 때리기는 설계에서 제외됨
- M11의 감싸 안고 퇴장하는 동작은 나란히 춤추며 퇴장하는 것으로 바뀜

원전 대사 전체 표시와 M10 제외 정책의 충돌은 [[#12. 확정된 구현 결정]]처럼 원문 표시와 화면 행동을 분리해 처리함.

# 10. 상태 전이 시험

## 10.1 공통 경로

각 마당에서 적용되는 경로를 처음부터 끝까지 자동 또는 수동으로 따라감.

- 모든 입력 성공
- 첫 입력 실패 뒤 성공
- 반복 실패 뒤 판정 완화
- 완화 입력도 실패
- 무입력
- 인식 실패 뒤 재확인 성공
- 인식 재확인 실패 뒤 복구 또는 종료
- 정상 마무리 뒤 시작 화면 복귀

마당에 없는 분기는 억지로 추가하지 않음. 먹중잡이는 같은 사건 재시도와 판정 완화를 시험하지 않고, 무입력 뒤 다음 원전 사건 진행을 시험함.

## 10.2 금지 결함

- 도달할 수 없는 상태
- 다음 상태 이름 불일치
- 재시도 상한이 없는 무한 반복
- 성공하지 않았는데 성공 대사가 나오는 전이
- 무입력인데 포착 또는 선택 성공 설명이 나오는 전이
- 실패 분기에서 원전 대사가 빠지거나 중복되는 전이
- 자동 재생 예약과 이전 문장/이전 항목/그만두기 조작이 충돌하는 전이
- 유저 배역이 원전 등장 전에 무대 전경에 나타나는 화면
- 원전 퇴장 뒤 해당 인물이 계속 남는 화면

# 11. 구현 순서와 사용자 게이트

한 번에 세 마당을 구현하지 않음.

2026-08-24 사용자가 옴탈잡이 확인 뒤 샌님잡이와 먹중잡이의 연속 구현을 함께 지시해 8번 게이트를 통과한 것으로 기록함.

1. 본 명세의 [[#12. 확정된 구현 결정]]을 구현 조건으로 고정함
2. 원전 데이터, 진행 상태 데이터와 자동 검증 스크립트를 새로 작성함
3. 원전 전수 검사만 실행하고 사용자에게 보고함
4. 공통 16:9 화면과 하단 전용 공간을 구현함
5. 옴탈잡이 16개 상위 상태와 승인된 하위 상태를 구현하고 모든 분기와 원전 대응을 검사함
6. 사용자 화면 확인과 승인 전에는 샌님잡이로 넘어가지 않음
7. 샌님잡이 19개 상태를 구현하고 검사함
8. 사용자 화면 확인과 승인 전에는 먹중잡이로 넘어가지 않음
9. 먹중잡이 21개 상태를 구현하고 검사함
10. 사용자 화면 확인 뒤 전체 통합 검사를 실행함

각 마당 구현 뒤 다음을 보고함.

- 구현한 상세 상태 수와 상태 이름
- 대응한 원전 항목 수와 전수 일치 여부
- 성공, 실패, 무입력, 인식 실패와 완화 경로 결과
- 독립 맥락 검토의 발견 건수와 반영 건수
- 실제 브라우저 화면 검사 가능 여부

# 12. 확정된 구현 결정

2026-08-24 사용자 승인으로 다음 세 구현 방식을 확정함.

## 12.1 원전 전체 표시와 기존 제외 정책

- **확정: 원전 대사 검토 우선**
  - 모든 원전 대사를 하단에 표시하고 원전 지문은 화면에 문장으로 표시하지 않음
  - 원전 지문은 보존 데이터와 연출 근거로 사용함
  - 민감 표현과 접촉에 관한 대사는 원문으로 표시하되 중앙 무대에서는 설계안처럼 순화하거나 재현하지 않음
  - 원문 표시 여부와 화면 행동의 재현 여부를 별도 필드와 검사 항목으로 관리함

## 12.2 옴탈잡이 432~456행 배치

- **확정: 연속 회피 사이 재담**
  - 모든 재담 하위 상태의 상위 `stateId`는 `omtal-07`로 고정함
  - 지문이 있으면 지문부터 바로 뒤의 대사까지를 원전 블록 하나로 묶고, 지문 없이 화자가 바뀌면 새 블록을 시작함
  - 7번 연속 회피 준비 안내 뒤 `원전 블록 → 새로운 회피 접근 → 접근 판정`을 한 묶음으로 반복함
  - 준비된 새로운 접근 수는 미리 정하지 않고 위 규칙으로 추출된 원전 블록 수에서 도출함
  - 마지막 원전 블록에 대응하는 접근 판정이 끝나면 8번 연속 회피 종료로 이동함
  - 실패 재시도와 완화 시도 중에는 새 재담 블록을 진행하지 않음

## 12.3 긴 대사 표시

- **확정: 문장 단위 이어 보기**
  - 원문 문자열은 보존하고 화면에서만 문장 단위로 나눠 이어 표시함
  - 사용자가 `이전 문장`과 `다음 문장`으로 넘기며 마지막 문장 뒤에만 다음 상태로 이동함
  - 분할한 문자열을 다시 합치면 원문과 같다는 자동 검사를 추가함
  - 마침표, 물음표와 느낌표가 나오기 전에는 한 문장을 임의의 글자 수로 자르지 않음
  - 한 문장이 하단 영역을 넘으면 자동 축약하거나 자르지 않고 화면 검사 실패로 보고해 글자 크기, 영역 높이 또는 원전 단락 구분을 사용자가 다시 결정하게 함

다음 조작 규칙을 함께 적용함.

- 수동 진행을 기본값으로 사용함. 자동 재생은 개발자 시험 도구에서만 켤 수 있게 함
- 자동 재생의 문장별 표시 시간은 개발자 시험 중 조절하는 매개변수이며 구현 결정이나 완료 조건으로 취급하지 않음
- 사용자가 이전/다음 문장, 이전 항목 또는 그만두기를 누르면 예약된 자동 전이를 즉시 취소함
- 이전 문장은 같은 원전 행 안의 직전 문장으로 이동함
- 이전 항목은 현재 상세 상태의 하단 표시 큐에서 바로 앞의 원전 행 또는 설계 표시로 이동함. 직전 상위 상태로는 이동하지 않음
- 시작 화면 이동은 그만두기 확인을 거쳐서만 실행함. 별도 시작 화면 버튼을 두지 않음
