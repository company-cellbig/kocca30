# 2. Medium (우선 정정 권장, 모두 직접 확인)

## 2.1 버나 UI 화면 수 자기모순 [직접]

- [[버나 - 버나잡이 한 판 UI]] L10 TL;DR "화면 수가 9개" ↔ L16 개요 "대상 화면: 10개"
- 같은 "화면 수"에 9와 10이 공존. 9는 레이아웃과 프롬프트 보유분, 10은 2차연도 학습 토큰 스캔 포함 대상 총계로 보임
- 권장: 두 값의 기준을 구분해 표기(예: L10 "설계 보유 9개", L16 "대상 10개(학습 토큰 스캔 포함)"). 관련 저위험 L5(MOC 대조) 함께 검토

## 2.2 탈춤 UI 존재하지 않는 6절 자기참조 [직접]

- [[덧뵈기 - 나만의 탈춤 UI]] L99 "보조 이어하기 버튼은 2차연도 전방 설계라 1차연도 미배치, §6"
- 이 문서는 1~4절만 존재(H1 헤더 확인). 6절 없음. 자매 4종은 동일 위치에서 화면 목록 표의 "학습 토큰 스캔" 행으로 참조
- 권장: 자매와 동일하게 화면 목록 표의 "학습 토큰 스캔" 행으로 참조하거나 [[플랫폼 사양#6. 2차연도 전방 설계 (디지털 도제 연속성, 현재 구현 밖)]]를 명시하도록 정정

## 2.3 탈춤 UI 동의 화면 라벨-내용 불일치 [직접]

- [[덧뵈기 - 나만의 탈춤 UI]] L152 "필수와 선택 동의를 받음" ↔ 실제 단일 필수 토글만(L158 "동의 항목 토글: 필수 카메라 촬영", L159 주 버튼 활성 조건, 프롬프트 L174 "exactly one / single required consent")
- 선택 항목 없음. 자매 [[덜미 - 나만의 꼭두각시 UI]] L152는 "필수 동의를 받음"으로 올바름
- 권장: L152를 "필수 동의를 받음"으로. 관련 저위험 L6(꼭두각시 L156 "동의 토글 목록" 복수 표현) 함께 검토

## 2.4 버나 UI 실패 안내가 없는 트리거 열거 [직접]

- [[버나 - 버나잡이 한 판 UI]] L338 "기록증 조립이나 전송 실패, 상태 조회 무응답 등 실패 분기가 모이는 공통 화면"
- 버나는 기록증이 실시간 합성이라 생성 대기와 상태 조회 흐름이 아예 없음(L16, L17, 기획서 실시간 완료). "상태 조회 무응답"은 발생 불가 트리거
- 권장: "상태 조회 무응답" 제거(기록증 조립 실패, 전송 실패만 남김)

## 2.5 frontmatter type/status 누락 10파일 [직접]

- [[CONVENTIONS#3. 문서 작성 규칙]]나는 전 문서에 title/type/status/created/updated 요구. 아래는 type과 status가 둘 다 없음(head 확인). 자매 문서([[덧뵈기]], [[시범콘텐츠 공통 사양]] 등)는 보유
- 대상: [[덜미]], [[덜미의 각본 재미 요소]], [[버나]], [[살판]], [[한국 전통 인형극]] (01_Concepts 5), [[codex 검수 포커스]], [[docx 변환 파이프라인]], [[반복 결함 카탈로그]] (02_HowTo 3), `03_References/converted_모순점.md`, `00_Index/MOC.md`
- 권장: type(concept/howto/reference/index) + status(stable/draft 등) 보강. MOC는 `type: index`

# 5. 검수 한계(미확인)

- `updated` stale은 git 최종커밋 날짜 대비로만 판단(내용 무변경 커밋이면 실제 stale 아닐 수 있음)
- L3~L11 저위험은 서브에이전트 보고분으로 근거 인용은 있으나 작성자 직접 재확인은 medium 항목에 집중함
- 외부 아카이브 수치(택견 영상 용량, 데이터셋 건수 등)는 대조할 L1 정본이 없어 미확인
