> 2026-07-14 야간 자율 작업(기획서 5종 신양식 통일 + 위키 정합성 검수)에서 나온 미결 항목. 에이전트가 임의로 정하지 않고 남긴 사용자 결정 대상과, 승인이 필요한 정본 변경을 모은다. 결정되면 해당 문서에 반영하고 이 노트에서 지운다.

# 1. 결정이 필요한 콘텐츠 설계 (에이전트가 지어낼 수 없음)

원문에도 값이나 규칙이 없어 추정하면 창작이 되는 항목이다.

## 가. 덧뵈기 나만의 탈춤

- **일치도 임계와 난이도 곡선의 관계**: 채점 기준은 일치도 임계 70%인데 난이도 곡선은 초반 60%에서 후반 75%로 오른다. 70%가 곡선의 평균인지, 곡선이 70%를 대체하는지 정해야 한다 ([[덧뵈기 - 나만의 탈춤 기획서]] 포즈 채점과 신명 게이지)
- **채점 "구간"의 정의**: 점수를 보류하는 단위인 "구간"이 장단 한 마디인지, 동작 하나인지, 시간 조각인지 정의가 없다
- **유효 촬영이 여러 장일 때 최종본 선택 규칙**: 3회까지 찍는데 어느 장을 기념 사진에 쓰는지 규칙이 없다(마지막, 최고 품질, 유저 선택 등)

## 나. 덧뵈기 양반 놀리기 4컷

- **콘텐츠 입력 3종의 파기 시점**: 캐릭터 정보, 선택 세부 유형, 배정 플롯의 파기 시점이 미정이다(컷별 응답 14일, 결과물 30일은 잠정 확정)
- **별도 탈 디자인 단계 여부**: 캐릭터 정보 개인화로 확정했으나, 탈춤처럼 직접 그리는 단계를 넣을지는 사용자 결정 대상으로 남아 있다

## 다. 버나 버나잡이 한 판

- **센서 막대 주변기기**: 센서 종류, 폼팩터, 무선과 유선, 내구성, 보정 방식이 모두 미정이다. 이 주변기기가 핵심 메커닉(물리 시뮬레이션)을 가른다

## 라. 5종 공통

- **터치 미입력 타임아웃이 콘텐츠마다 다름**: 탈춤만 45초이고 나머지 4종은 60초다. 원문 값을 그대로 보존했으나 공통 사양 기본값(60초)과 어긋난다. 탈춤을 60초로 맞출지, 45초를 유지하고 근거를 적을지 정해야 한다

# 2. 승인이 필요한 정본 변경

에이전트가 손대지 않고 남긴 것이다. 모두 다른 문서에 파급이 있다.

## 가. 실패 안내 팝업의 "처음으로" 버튼

- **문제**: [[시범콘텐츠 공통 사양]] §5.바 실패 안내가 "(선택) 처음으로 보조 버튼"을 허용한다. 그러나 5종 기획서는 모든 실패를 종료 Step으로만 보내기로 했고, "처음으로"는 세션을 살린 채 시작 화면으로 되돌린다는 뜻으로 읽혀 종료 원칙과 충돌한다
- **파급**: 공통 사양, [[공통 UI 컴포넌트]], UI 문서 5종에 같은 서술이 퍼져 있다
- **제안**: 버튼을 "확인" 하나로 통일한다(누르면 즉시 종료 Step, 누르지 않아도 잠깐 뒤 자동 진행)

## 나. 공통 사양과 5종의 값 불일치

- **입력 위반 한도의 의미**가 다르다. 공통 사양은 "3회 **초과** 시 종료", 5종 기획서는 "3회 **위반** 시 종료"다. 유저가 세 번째에 끝나느냐 네 번째에 끝나느냐가 갈린다 (미해결)
- **출력 가드레일 재생성 한도가 콘텐츠마다 다르다**: 유람기와 양반 놀리기는 3회(공통 사양 기본값), 탈춤과 꼭두각시는 2회다. 3D 변환과 아바타 생성이 비싸서 줄인 것으로 보이나 본문에 근거가 없다. 양식 §3.나는 공통과 다르게 잡으면 근거를 붙이라고 요구한다
- **다운로드 가능 기간이 5종 모두 다르다**: 유람기 2일, 탈춤과 꼭두각시와 버나 48시간, 양반 놀리기 30일이다. 48시간과 2일은 같은 값을 다르게 쓴 것이고, 30일만 크게 다르다. 표기를 통일하고 30일의 근거를 정해야 한다
- **운영 알림 임계**: 체험형 3종은 "연속 3회 실패, 5분 오류율 10%"를 표에 두는데 생성형 2종(유람기, 양반)은 수치가 없다. 수치를 지어낼 수 없어 그대로 뒀다
- (반영 완료) AI 호출 재시도 백오프(1차 1초, 2차 3초)와 TTS 호출 타임아웃 30초를 5종에 채워 넣었다

## 다. 공통 사양의 stale 절 (구조 판단 필요)

5종이 신양식으로 바뀌면서 공통 사양의 일부 절이 실제와 어긋난다. 사실 서술만 고쳤고 구조 판단은 남겼다.

- **§3 Step 모델**: "트리거, 시스템, 화면 흐름, 프로세스, 입력, 출력, 다음" 필드를 규정하는데 5종 어디에도 그 필드가 없다. Step 구조의 정본은 이제 [[콘텐츠 기획서 작성 양식]]이다. 공통 사양 §3을 양식 참조로 축약할지 정해야 한다
- **§12 임베드 블록**: `^session-def`, `^step-def`, `^common-params` 등 블록 ID를 부여해 뒀는데 5종이 임베드를 쓰지 않아 아무도 참조하지 않는다
- **§5.라 결과물 전송**: QR 단독 화면을 정의하는데 5종 모두 감상과 받기를 한 화면으로 합쳐 이 화면을 쓰는 콘텐츠가 없다. 적용 범위 문장은 사실에 맞게 고쳤으나, 절 자체를 병합 화면 기준으로 다시 쓸지는 결정이 필요하다
- **에러 케이스와 처리 4갈래, 원인 3분류**가 공통 사양에 없다. 5종이 모두 쓰므로 공통 사양으로 올릴지 검토가 필요하다

## 다. 유람기의 남은 결함 2건 (사용자 보류)

- **역할과 목적에 동작과 규칙이 섞임**: [[덜미 - 나만의 유람기 기획서]] 입력 유효성 검증과 실패 처리
- **AI 가드레일에 "실패와 복구" 항목이 없음**: 호출 실패 처리가 동작과 규칙에 섞여 있다

## 라. read-only 영역의 깨진 링크

- `04_Projects/_archive/덜미 - 나만의 유람기 표준 정합 백로그.md:36`의 anchor가 깨져 lint가 1건 잡는다. `_archive`는 수정 금지 영역이라 손대지 않았다. 폐기 문서라 그대로 둬도 무방하나, lint 0건을 원하면 예외 승인이 필요하다

# 3. UI 문서 5종에 남은 stale (재작성 시 반영할 것)

UI 문서는 전면 재작성 예정이라 손대지 않았다. 재작성할 때 아래를 함께 고쳐야 한다.

- **결과물 화면이 아직 두 개다**: 기획서 5종이 미리보기와 QR을 한 화면으로 합쳤는데, 유람기 UI를 뺀 4종 UI는 여전히 "결과물 미리보기 화면"과 "결과물 QR 화면"으로 쪼개져 있다
- **호스팅을 QR 화면이 수행하는 것으로 서술한다**: 기획서는 호스팅과 URL 발급을 생성 파이프라인 끝으로 옮겼다. 4종 UI의 QR 화면 절이 여전히 그 화면에서 호스팅한다고 적는다
- **양반 놀리기 UI는 Step 번호가 밀려 있다**: 기획서가 7-Step에서 6-Step으로 줄었는데 UI 표가 옛 번호(Step 6, Step 7)를 그대로 쓴다
- **기획서 절 참조가 옛 번호를 가리킨다**: 꼭두각시 UI와 탈춤 UI의 "기획서 §5.나"(개인정보 처리를 가리키려 했으나 지금은 에러 케이스), 꼭두각시 UI의 "§3.라 운영 파라미터"(지금은 진행 중 종료), 유람기 UI의 "§3.카 마당 유형"(지금은 실패 처리) 등
- **유람기 UI의 결과물 화면 타임아웃이 120초**인데 기획서 운영 파라미터는 300초다
- **"처음으로" 버튼**: 5종 UI 전부와 공통 UI 컴포넌트, 공통 사양에 남아 있다(§2.가 참조)
