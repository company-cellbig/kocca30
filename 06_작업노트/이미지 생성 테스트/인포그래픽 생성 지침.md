> 주어진 내용을 분석해 그에 맞는 인포그래픽 구성을 설계하고, 힉스필드(GPT Image 2)로 텍스트 오염 없이 생성하는 4단계 절차. 실증 근거와 프롬프트 예문은 [[이미지 생성 테스트 기록]] 참조.

# 1. 설계 근거

- **문자열 고정이 심장임**: 참고 사례(제미나이 샷 약국 플랫폼 홍보물)가 주요 라벨부터 깨진 원인은 모델 성능만이 아니라, 라벨을 확정하지 않고 밀도 높은 구성을 통째로 맡긴 데 있음. 렌더할 문자열을 계약처럼 고정하고 그 외 텍스트를 금지하면 고밀도 구성에서도 라벨 무결이 나옴 ([[이미지 생성 테스트 기록]] 테스트 2에서 라벨 27개 무결로 실증)
- **참고 사례 4종이 결함 유형의 실증원임**: 같은 소재를 4개 구성으로 생성한 참고 사례를 전수 분석해 결함 8유형(프롬프트 구문 유출, 연출 지시문의 본문화, 레이아웃 위치어의 제목화, 중복 렌더, 소형 단계 라벨 붕괴, 통제 밖 수치와 인용, 차트 의미 붕괴, 상표 노출)을 도출함 ([[이미지 생성 테스트 기록#8. 참고 사례 분석: 제미나이 샷 약국 홍보물 4종 (2026-07-28)]]). 문장형 캡션이 많은 구성일수록 결함이 늘고, 짧은 명사형 라벨 위주 구성에서는 같은 모델이라도 라벨이 대체로 살아남음. 아래 각 절의 규칙이 8유형을 나눠 방어함
- **분석과 설계를 프롬프트 작성과 분리함**: 합쳐 두면 매번 같은 구도를 복붙하게 됨. 내용 분석과 구성 설계를 먼저 거쳐야 주어진 내용에 적합한 구성이 나옴

# 2. 내용 분석 (그리기 전, 산출물은 텍스트)

- 원문에서 다음을 추출함
	- **핵심 메시지 1문장**: 제목이 됨. "X로 Y를 하는 Z" 구조 권장
	- **서사 구조**: 내용을 배경/문제 → 해법/기술 → 성과/비전 흐름으로 재배열함 (원문 순서에 끌려가지 않음)
	- **정보 블록 분류**: 프로세스(단계), 나열(고객, 가치), 대비(전/후), 정량(수치) 중 어느 유형인지 블록마다 판정함
- **렌더 문자열 확정**: 이미지에 넣을 모든 한국어 라벨을 이 단계에서 목록으로 확정함
	- 라벨은 2층 구조까지 허용함: 블록마다 헤더(2~8자 명사형)와 부연 캡션(20자 이내, 명사형 종결)을 둘 다 문자열로 확정할 수 있음. 개수 상한은 못 박지 않고 실증 실적을 기준으로 삼음: 확정 문자열 43개(라벨 개수 기준) 구성까지 오탈자 0건이 실증됐고([[이미지 생성 테스트 기록#5. 테스트 5: 고밀도 2층 라벨 실증 (2026-07-28)]]), 그보다 큰 구성은 새로 실증한 뒤 확장함. 오류율을 가르는 것은 개수보다 라벨 형태(명사형인가 문장형인가)이므로, 문장형 캡션은 개수와 무관하게 금지함
	- 라벨은 명사형으로 씀. 장면 묘사 표현("웃는 노인", "창고형 약국 사진" 류)은 라벨이 아니라 연출이므로 목록에 넣지 않고 [[#4. 프롬프트 작성 (영어, 문자열은 한국어 원문)]]의 영어 연출 서술로 보냄 (참고 사례 결함: 연출 지시문이 캡션으로 렌더됨)
	- 문자열에 포함할 구두점과 기호는 이 단계에서 확정함. 라벨 끝 마침표와 마크다운 기호는 애초에 포함하지 않음 (참고 사례 결함: 제목 앞 "#"이 그대로 렌더됨)
	- 저빈도 합성어와 압축 조어를 피하고 흔한 단어로 씀. 플로우의 소형 단계 라벨일수록 붕괴가 잦으므로("미승", "상품제" 류) 빠짐없이 목록에 올리고 2~4자 고빈도 단어로 둠
	- 같은 문자열은 한 곳에만 배정함. 두 곳에 배치하면 중복 렌더를 유도함 (참고 사례 결함: 같은 슬로건이 2회 렌더됨)
	- 이 목록에 없는 글자는 이미지에 존재하면 안 된다는 전제로 이후 단계를 진행함

# 3. 구성 설계 (레이아웃 선택과 배치)

- 서사 구조에 맞는 레이아웃 패턴을 고름. 패턴은 격자형과 비격자형 두 계열임
- **두 계열 정의**: 격자형은 정보 블록을 채움 색이 있는 둥근 사각 패널로 정렬해 문서 삽화(구성도, 대시보드)에 맞고, 비격자형은 열린 캔버스에 요소를 자유 배치해 홍보물과 표지형에 맞음
- **계열 결정 요인**: 격자 여부는 모델 성향이 아니라 프롬프트 어휘가 결정함. grid, aligned, panels, cards 류를 지시하면 격자가 나오고, 비격자 장치를 지시하면 격자를 벗어남 ([[이미지 생성 테스트 기록#9. 테스트 8: 비격자 구성 3안 (2026-07-29)]]에서 3안 전부 격자 탈피와 문자열 무결 양립으로 실증)
- **격자형 패턴**
	- **히어로 밴드 + 하단 N패널**: 스토리 강조와 섹션 요약이 다 필요할 때 (참고 사례 패턴)
	- **좌→우 플로우**: 프로세스가 주인공일 때
	- **중앙 허브 + 방사형**: 하나의 플랫폼에 여러 요소가 붙을 때
- **비격자형 패턴** (참고 사례 4종의 구성 장치에서 추출, [[이미지 생성 테스트 기록#8. 참고 사례 분석: 제미나이 샷 약국 홍보물 4종 (2026-07-28)]])
	- **커넥터 스파인형**: 세로 중심선에 노드 점을 찍고 항목이 선에 붙는 노선도 구성. 프로세스가 주인공이되 격자를 피할 때
	- **궤도 허브형**: 원형 사진 인셋이 중앙 엠블럼 둘레에 궤도처럼 붙고 곡선 연결선으로 이어지는 구성. 사각 컨테이너 없이 허브형 구성을 만들 때
	- **히어로 지배 비대칭형**: 대형 실사 1장이 중앙을 지배하고 주변 정보 클러스터가 크기를 달리해 비대칭으로 붙는 구성. 스토리 몰입이 최우선일 때
- **비격자 공통 장치**
	- **항목 구분**: 개별 카드 대신 가는 구분선(hairline)으로 나눔
	- **섹션 제목**: 박스 상단 띠가 아니라 리더 라인 달린 pill 배지로 띄움
	- **사진 인셋**: 원형 사진 인셋을 영역 경계에 살짝 겹치게 둠
	- **배경**: 사각 패널 대신 유기적 라운드 형상(중앙으로 좁아지는 화살촉형 등)으로 함
- **비격자 주의**: 컨테이너가 없어 라벨과 시각 요소의 결속이 흐려짐. 영역 서술에서 캡션이 어느 요소 밑에 붙는지 명시하고(directly beneath 류), 연결선 위 소형 단계 라벨은 붕괴가 잦으므로 2~4자 고빈도 단어 규칙을 지킴
- 블록마다 시각 어휘를 배정함: 실사 사진(감성, 현장), UI 목업(제품), 아이콘(개념 나열), 차트(정량). 한 이미지에 서너 어휘를 섞으면 정보가 알차 보이는 밀도가 나옴
- **시각 요소 배정: 사진은 실사, 아이콘은 풀컬러**: 사진 영역은 실사로, 아이콘과 일러스트는 채움 색이 있는 풀컬러(참고 사례의 컬러 아이콘 톤)로 지시함. 단색 라인 아이콘 위주의 미니멀 스타일은 정보가 빈약해 보이므로 피함 (프롬프트에서 thin-line 대신 colorful filled icons, vibrant flat illustrations 류로 지시)
- 시선 흐름을 화살표로 명시함 (좌→우, 상단 서사 → 하단 근거)
- **정량 차트는 추상 장식으로 격하하거나 로컬로 그림**: 이미지 모델은 축 라벨과 추세 방향의 의미를 보장하지 못함 (참고 사례 결함: 사고 예방 성과 자리에 상승 곡선, 축 라벨에 값 표기 혼입). 수치가 의미를 가져야 하는 차트는 Pillow나 SVG로 따로 그려 문서에 별도 삽입하고, 이미지 안 차트는 수치 없는 추상 도형으로만 지시함. 수치를 이미지에 꼭 넣어야 하면 차트에 얹지 말고 차트와 분리된 배지형 라벨(지표명과 값)로 둠. 차트(추상 도형 포함)를 두기로 하면 추세 방향(상승, 하강)을 이 단계에서 확정함: 프롬프트 지시와 검수 대조의 기준값이 됨
- **텍스트를 품기 쉬운 소품 실사를 최소화함**: 달력, 표지판, 차량, 포장 상자류에는 무관한 연도, 브랜드, 영문 문구가 스며듦 (참고 사례 결함: 달력의 무관 연도, 아마존 로고 상자)

# 4. 프롬프트 작성 (영어, 문자열은 한국어 원문)

- **전체 스타일 선언**: 용도(제안서, 홍보), 품질 톤(consulting-deck quality), 배색, 타이포를 첫 문단에 못 박음. 격자/비격자 계열도 여기서 선언함: 비격자면 organic editorial composition, open canvas, NO boxed cards, NO uniform rectangular panels를 명시하고, grid, aligned margins, panels side by side, cards, strip 같은 격자 어휘를 프롬프트 전체에서 쓰지 않음 (격자 어휘는 그 자체로 격자 구성을 유도함)
- **연출과 위치는 영어로만, 한국어는 렌더 문자열에만**: 장면, 인물, 분위기 연출과 영역 지시(TOP, BOTTOM 등)는 영어 산문으로 쓰고, 한국어는 따옴표 안 렌더 문자열에만 둠. 참고 사례에서는 연출 지시("웃는 노인")와 위치어("하단 생태계")가 본문으로 렌더됐는데, 비렌더 지시가 렌더 문자열과 섞인 것이 원인으로 추정됨(원 프롬프트 미보유, [[이미지 생성 테스트 기록#8.2 관찰]]). 원인 확정과 무관하게 이 분리 표기는 자체 테스트에서 라벨 무결로 실증된 방어 규칙임. 프롬프트 본문에 마크다운 문법(#, >, 불릿 기호)을 쓰지 않음
- **텍스트 통제 규칙 (필수)**: 스타일 선언 직후에 다음 조항을 배치함. 확정 문자열만 철자 그대로 1회씩 렌더, 지정 외 텍스트 발명과 추가 금지, 실존 브랜드 로고/상표/워터마크 금지, 장식 요소와 사진의 텍스트 금지, 화면 목업 내부는 추상 도형만 허용
- **영역별 서술**: 구성 설계의 배치대로 zone 단위로 서술하고, 라벨은 전부 따옴표로 감쌈
- 실전 예문: [[이미지 생성 테스트 기록]] 테스트 2 프롬프트 전문

# 5. 생성과 검수

- **설정**: `gpt_image_2`, 16:9 기준. 초안은 1k/medium(저비용 반복), 최종은 2k/high
- **검수 (3중, 순서대로)**
	1. **직접 대조**: 생성물을 내려받아 작성자가 내용 분석의 라벨 목록과 대조함. 화면 목업 등 미세 텍스트 영역은 크롭 확대로 확인함. 단, 작성자는 정답을 알아 기대 편향이 있으므로 이 단계만으로 통과 선언하지 않음
	2. **블라인드 전사**: 정답 라벨을 주지 않은 깨끗한 컨텍스트의 서브에이전트에게 이미지의 모든 텍스트를 보이는 철자 그대로 전사하게 함(오탈자로 보여도 고치지 말 것, 판독 불가 영역은 위치와 함께 표기, 애매하게 뭉개진 글자는 경계 판독 특이사항으로 기록). 차트가 있으면 추세 방향(상승, 하강)과 축 라벨도 기록하게 함. 이미지가 여럿이면 이미지당 1개 에이전트로 병렬 실행함
	3. **기계 대조**: 전사본을 라벨 목록과 항목별로 대조함. 대조는 오탈자 확인에 더해 다음 네 가지를 포함함: 목록 외 판독 가능 텍스트(문자열, 수치, 기관명, 연도) 검출, 같은 문자열의 중복 렌더와 단어 겹침 검출, 실존 브랜드와 로고 검출, 전사된 차트 추세 방향과 구성 설계에서 확정한 방향의 대조. 전사 에이전트가 남긴 경계 판독 특이사항(뭉개진 글자)과 판독 불가 영역도 함께 수집함
- **재생성 기준**: 다음 결함이 1건이라도 있으면 재생성함: 지정 라벨 오탈자, 목록 외 판독 가능한 텍스트(수치와 연도 포함), 지정 문자열의 중복 렌더, 실존 브랜드 노출, 확정 방향과 어긋난 차트 추세. 지정 외 영역의 판독 불가한 미세 유사 한글은 축소 표시에서 안 보이면 허용하되 기록에 남김. 아이콘 내부 문자가 인접한 지정 라벨에 포함된 단어를 그대로 딴 것이면(라벨 "4D 생성"의 큐브 속 "4D", "초경량 AI"의 뇌 속 "AI", "IP 등록"의 방패 속 "IP", 저작권 라벨 옆 ⓒ 기호처럼) 결함으로 보지 않고 [[이미지 생성 테스트 기록]] 해당 테스트 절에 특이사항으로만 남김 (테스트 4, 5에서 반복 관찰되어 결함 판정이 갈리던 유형). 블라인드 전사가 남긴 경계 판독 특이사항은 결함은 아니지만 재생성이나 라벨 단순화(더 짧은 표현)를 검토할 신호로 취급함
