- **대상**: 덜미 - 나만의 유람기 UI, 덧뵈기 - 양반 놀리기 4컷 UI, 버나 - 버나잡이 한 판 UI (사용자 지시 2026-07-01 퇴근 전)
- **방식**: 탈춤/꼭두각시 UI 작성 방식 준용(참조 이미지 기반 공용 화면 + 단독 프롬프트 고유 화면, 중앙 도달 존, 호스트 슬롯, 부정 프롬프트 고정부). 문서당 구조 설계 → 초안 → lint 0 → 자기검수 → commit → Codex 외부 검토(새 스레드) → 발견 처리
- **게이트 처리 (자율 모드)**: 블로킹 질문 없이 합리적 기본값으로 초안. 명백한 자기 결함과 기계적 정정은 즉시 반영, 정책/설계 판단이 필요한 건 본문 미반영하고 아래 §에 "사용자 결정 대기"로 정리
- **공통 준수**: 원문 없는 수치는 확인 필요 표기, `_locked`/`_sources` 미수정, em dash와 가운뎃점 금지, MOC 등록과 양방향 wikilink

# 3. 사용자 결정 대기 (G1/G2)

## 가. 유람기 UI

작성 시 적용한 합리적 기본값 중 사용자 확인이 필요한 항목:

- **동의 토글 문구**: 유람기는 카메라를 쓰지 않아 필수 동의를 "이용 약관 (필수)"로 표본 처리함(기획서가 구체 동의 항목 미명시). 실제 필수 동의 항목과 문구는 규정 검토 확정 대상
- **마당 유형 카드 라벨**: 유저 대면 카드를 "위험을 물리치기 / 뻐기는 자 골리기 / 위선 들추기 / 욕심의 끝" 친근 표본으로 지음(4종 유형에 매핑). 내부 유형명(위협-구원/권력 풍자/위선 폭로/욕심과 다툼)을 그대로 노출하지 않는 편이 매력도에 낫다고 판단. 정확한 카피는 확인 필요
- **캐릭터 카드 라벨**: "아이 남/여 … 장년 남/여" 8종 표본
- **박첨지 질문 예시**: "길에서 누구를 만났나요?" 표본(사전 생성 고정 질문 자리)
- **학습 토큰 스캔 화면**: 자매 UI 일관성 위해 2차연도 stub 화면으로 포함(유람기 기획서 Step 1은 이어하기 미언급). 참고 행으로만 둠

## 나. 4컷 UI

- **소재/호스트**: 덧뵈기(탈춤) 소재라 아트디렉션과 호스트(말뚝이), 전통 정합(일본 노멘/중국 가면 회피)은 탈춤 UI를 따름. 산출물은 4컷 만화. 유람기와 같은 생성형 터치 구조(카메라 없음)
- **세부 유형 카드**: 양반 놀리기 세부 유형을 "허세/탐욕/무능" 3종 표본으로 지음. 기획서가 로스터 미확정(작성 예정)이라 카드 수와 라벨은 확인 필요
- **유저 탈 캐릭터**: 별도 탈 디자인 단계 없이 캐릭터 정보(연령×성별 8종)로 개인화된 배역 탈 캐릭터(기획서 §4.가 3 확정). 캐릭터 카드가 탈 캐릭터 8종
- **동의 토글**: 카메라 없음 → "이용 약관 (필수)" 표본(유람기와 동일 처리)
- **말뚝이 질문 예시**: "양반이 뭐라고 뻐기던가요?" 표본
- **학습 토큰 스캔**: 자매 UI 일관성 위해 2차연도 stub 포함
