# 1. 작업 개요

- **대상**: 덜미 - 나만의 유람기 UI, 덧뵈기 - 양반 놀리기 4컷 UI, 버나 - 버나잡이 한 판 UI (사용자 지시 2026-07-01 퇴근 전)
- **방식**: 탈춤/꼭두각시 UI 작성 방식 준용(참조 이미지 기반 공용 화면 + 단독 프롬프트 고유 화면, 중앙 도달 존, 호스트 슬롯, 부정 프롬프트 고정부). 문서당 구조 설계 → 초안 → lint 0 → 자기검수 → commit → Codex 외부 검토(새 스레드) → 발견 처리
- **게이트 처리 (자율 모드)**: 블로킹 질문 없이 합리적 기본값으로 초안. 명백한 자기 결함과 기계적 정정은 즉시 반영, 정책/설계 판단이 필요한 건 본문 미반영하고 아래 §에 "사용자 결정 대기"로 정리
- **공통 준수**: 원문 없는 수치는 확인 필요 표기, `_locked`/`_sources` 미수정, em dash와 가운뎃점 금지, MOC 등록과 양방향 wikilink

# 3. 사용자 결정 대기 (G1/G2)

## 3.1 유람기 UI

작성 시 적용한 합리적 기본값 중 사용자 확인이 필요한 항목:

- **동의 토글 문구**: 유람기는 카메라를 쓰지 않아 필수 동의를 "이용 약관 (필수)"로 표본 처리함(기획서가 구체 동의 항목 미명시). 실제 필수 동의 항목과 문구는 규정 검토 확정 대상
- **마당 유형 카드 라벨**: 유저 대면 카드를 "위험을 물리치기 / 뻐기는 자 골리기 / 위선 들추기 / 욕심의 끝" 친근 표본으로 지음(4종 유형에 매핑). 내부 유형명(위협-구원/권력 풍자/위선 폭로/욕심과 다툼)을 그대로 노출하지 않는 편이 매력도에 낫다고 판단. 정확한 카피는 확인 필요
- **캐릭터 카드 라벨**: "아이 남/여 … 장년 남/여" 8종 표본
- **박첨지 질문 예시**: "길에서 누구를 만났나요?" 표본(사전 생성 고정 질문 자리)
- **학습 토큰 스캔 화면**: 자매 UI 일관성 위해 2차연도 stub 화면으로 포함(유람기 기획서 Step 1은 이어하기 미언급). 참고 행으로만 둠

## 3.2 4컷 UI

- **소재/호스트**: 덧뵈기(탈춤) 소재라 아트디렉션과 호스트(말뚝이), 전통 정합(일본 노멘/중국 가면 회피)은 탈춤 UI를 따름. 산출물은 4컷 만화. 유람기와 같은 생성형 터치 구조(카메라 없음)
- **세부 유형 카드**: 양반 놀리기 세부 유형을 "허세/탐욕/무능" 3종 표본으로 지음. 기획서가 로스터 미확정(작성 예정)이라 카드 수와 라벨은 확인 필요
- **유저 탈 캐릭터**: 별도 탈 디자인 단계 없이 캐릭터 정보(연령×성별 8종)로 개인화된 배역 탈 캐릭터([[덧뵈기 - 양반 놀리기 4컷 기획서#4) 유저 탈 캐릭터]] 확정). 캐릭터 카드가 탈 캐릭터 8종
- **동의 토글**: 카메라 없음 → "이용 약관 (필수)" 표본(유람기와 동일 처리)
- **말뚝이 질문 예시**: "양반이 뭐라고 뻐기던가요?" 표본
- **학습 토큰 스캔**: 자매 UI 일관성 위해 2차연도 stub 포함

## 3.3 공통 횡단 결정 (전 UI G2, 유람기 Codex 발단)

유람기 Codex가 짚은 두 사안은 5개 UI 공통이라 문서별이 아니라 공통 차원에서 결정하는 게 맞음. 정본 변경이나 새 화면 설계라 자율 미반영, G2 결정 대기:

- **실패 안내 화면 부재 (구조, 권장 수용)**: 생성이나 변환 실패, 상태 조회 무응답 시 기획서는 사과 화면이나 에러 화면을 거쳐 종료 Step으로 가라고 요구하나, 5개 UI 어디에도 그 화면이 설계되거나 화면 목록에 열거되지 않음. 실패는 전 콘텐츠 공통 경로라 [[시범콘텐츠 공통 사양#5. 공통 화면]]에 공통 실패 안내 화면 1종을 추가하고 각 UI가 준용하는 방식을 권장함(대안: 각 UI에 개별 설계). 공통 사양은 정본이라 사용자 승인 필수 → 미반영
- **학습 토큰 스캔 카운팅 (표기, 경미)**: "공용 7"이 7개 모두 1차연도 설계처럼 읽힐 수 있음. "1차연도 작성 N개 + 2차연도 전방 설계 참고 1개"로 조이는 안. 경미해 현 표기 유지도 무방. 원하면 5개 UI 개요 한 줄씩 정정

# 4. Codex 발견과 처분 (문서별)

## 4.1 유람기 UI

- (중, #1) 학습 토큰 스캔 화면이 목록과 공용 7에 있으나 레이아웃과 프롬프트가 2차연도 미작성이라 §13 정합 기준에서 설계 누락으로 읽힘. 개요가 이미 "6개는 [[#5. 커밋 로그와 종합]], 1개는 2차연도 미작성"으로 구분하나 "공용 7" 표기가 오해 소지 → [[#3.3 공통 횡단 결정 (전 UI G2, 유람기 Codex 발단)]] 카운팅
- (중, #2) Step 4 생성 대기 화면이 정상 대기만 설계하고 기획서의 failed와 무응답 분기에서 보여줄 에러나 사과 화면이 없음. 실패 상태 화면이 화면 목록에도 없음 → [[#3.3 공통 횡단 결정 (전 UI G2, 유람기 Codex 발단)]] 실패 안내 화면
- 나머지(도달성, 동의 토글 1개, 전송 고지, 종료 중앙 호스트, 박첨지 오인 방지)는 이상 없음(Codex 확인). 자매 결함류 재발 없음

## 4.2 4컷 UI

Codex 발견 3건(모두 중), 전부 "터치 미입력 타임아웃 분기 미명시" 결함류. 처분: 전수 즉시 정정(위 [[#2. 문서별 진행 상태]] 타임아웃 결함류 참조). 별도 사용자 결정 불요.

- (중) 동의 화면: 터치 미입력 타임아웃 미동의 종료 분기 미명시 → 상태별 안내 추가
- (중) 이름 입력 화면: 타임아웃 Step 7 직행 분기 미명시 → 상태별 안내에 추가
- (중) 전송 화면: 타임아웃 시 연락처 즉시 파기 후 종료 분기 미명시 → 상태별 안내에 추가
- 도달성/설계-프롬프트/호스트/종료 중앙 배치는 이상 없음(Codex 확인)

## 4.3 버나 UI

- **화면 수 9개(자매 12보다 적음)**: 캐릭터 입력 없음 + 생성 대기 없음(기록증 결정적 템플릿 합성이라 실시간). 기획서 정합
- **버나 돌리기 화면 대거리 입력 수단 (확인 필요)**: 센서 막대를 쥔 채 대거리 선택지를 터치하는 조작의 인간공학이 미결(기획서 [[시범콘텐츠 공통 사양#8. 개인정보와 가드레일 원칙]] 미결). 한 손 터치 또는 핸드 트래킹 대안을 설계 단계 확정. 목업엔 대거리 선택지를 도달 존에 두되 flag
- **마무리 연출 화면 별도 화면화**: 기획서 화면 흐름은 "마무리 연출 화면"이나 프로세스 sub-step은 "UI(버나 돌리기 화면)"라 표현이 갈림. 화면 흐름 명칭대로 별도 화면으로 둠(판단 필요 시 조정)
- **매호씨 이중 역할**: 안내형 호스트 + 재담 대결 상대. 공통 화면은 측면 안내, 버나 돌리기는 측면 도발 대결 상대, 종료는 중앙 작별
- **동의 토글/대거리 선택지 표본**

Codex 발견 2건(중 1, 저 1), 둘 다 위 flag와 일치. 경량 명확화라 즉시 반영:

- (중, 도달성) 대거리 입력 물리 모델 미확정 → "한 손 파지+반대 손 터치 / 막대 내려놓고 터치 / 핸드 트래킹" 옵션을 미결로 명시(정답 창작 아님, 설계 단계 확정)
- (저, Step 정합) Step 4 마무리 연출 화면 별도 화면화 vs 기획서 "UI(버나 돌리기 화면)" 표기 → 화면 흐름 명칭을 화면 정본으로, 프로세스 표기는 렌더러 재사용으로 한 줄 정리
- 공통 사양/설계-프롬프트/매호씨 호스트/전송 고지(얼굴 없음)는 이상 없음(Codex 확인)
