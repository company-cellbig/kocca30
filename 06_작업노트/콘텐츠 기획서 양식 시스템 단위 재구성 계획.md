> [[콘텐츠 기획서 작성 양식]]을 레이어별 그룹에서 시스템 단위로 재구성하는 계획. 사용자 승인(2026-07-03)으로 표준 목차를 개요/전체 플로우/공용 시스템/개별 시스템/관련 문서 5절로 확정하고, [[#3. 남은 정합 작업 (후속)]]에 불변식 2개를 못박음. 본 노트는 배경과 결정, 남은 정합 작업을 담은 작업 메모임(정본 아님). 확정 결론은 양식 [[#3. 남은 정합 작업 (후속)]]에 반영함.

# 1. 배경 (현행 양식의 고질)

시스템 하나를 파악하려면 문서 여기저기를 봐야 하는 분산이 근본 문제임. 근거는 파일:줄.

- **기술 정보 이중화**: 같은 시스템의 기술이 [[#4. 관련 문서]] 구성 요소의 "기술 요건"(피처별, `콘텐츠 기획서 작성 양식.md:61`)과 [[시범콘텐츠 공통 사양#5. 공통 화면]] "기술 6영역별"(레이어별, `35`)로 갈림. [[시범콘텐츠 공통 사양#6. 진행 호스트]] 매핑(`123`)도 "피처별 통합 + 영역별 고유 구현"이라 이중 구조를 그대로 안음
- **파라미터 분리**: 운영 파라미터는 [[#3. 남은 정합 작업 (후속)]] Step 상세(`33`)에 따로 모임
- **흐름 중복 위험**: 세션 개요와 Step 상세의 흐름이 겹쳐, 양식이 "중복 금지"를 두 번 경고함(`41`, `134`). 경고 반복은 그 경계가 실제로 잘 무너진다는 신호

# 2. 결정 (사용자 승인 2026-07-03)

## 가. 표준 목차 (콘텐츠 기획서가 따르는 5절)

| 절 | 성격 | 정렬 |
|---|---|---|
| 1. 개요 | 한 줄 정의, 목표 경험, 핵심 메커닉, 플랫폼과 세션 길이 | 현행 유지 |
| 2. 전체 플로우 | sub-step 시퀀스와 큰 분기만. 세션 진행과 갈림을 한눈에. 내부 판정 로직은 배제 | 진행 순 |
| 3. 공용 시스템 | 2개 이상 sub-step에서 쓰이는 기능 + 횡단 정책 | 의존 fan-in 순(많이 의존받는 기반부터) |
| 4. 개별 시스템 | 나머지 시스템, 각자 독립 명세로 자기 완결 | sub-step 진행 순 |
| 5. 관련 문서 | UI 문서, 공통 사양, 플랫폼 사양 등 | 현행 유지 |

- **제거**: 현행 산출물, 일정과 마일스톤, 리스크와 검증 절은 표준 목차에서 뺌(사용자 결정). 산출물은 개요와 각 시스템 출력으로, 일정과 리스크는 별도 관리 문서로 흡수
- 각 시스템(공용, 개별)은 [[콘텐츠 기획서 작성 양식#나. 시스템 독립 명세 양식]] 양식으로 씀. 명세 항목을 볼드 라벨 불릿이 아니라 서브헤더(H3)로 둠(내용이 길고 표가 들어가므로 STRUCT-007). 필수 항목(역할과 목적/동작과 규칙/의존)은 모든 시스템이 갖추고, 조건부 항목(입출력/기술 요건/자산 요구/실패와 복구)은 해당할 때만 두며 없으면 헤더 통째 생략("해당 없음" 강제 금지). 7개 전부 강제는 페르소나, 데이터 풀 등에 빈 칸만 늘려 무리한 규격화라 폐기(2026-07-03). 라벨 불릿에서 헤더로 재전환한 근거: 하위 내용이 길어지고 표가 필요하며, 중복 헤더 앵커는 상호참조를 시스템 이름으로 하면 비문제(2026-07-03)
- 운영 파라미터는 그 시스템 안에 두고, 공통 기본값은 [[시범콘텐츠 공통 사양#9. 운영 파라미터 (공통 기본값)]]를 참고해 직접 적음(부분 임베드 불가라 값만 따로 인용하지 않음)

## 나. §3에 못박을 불변식 2개

1. **흐름과 로직 분리**: 흐름은 전체 플로우에만, 내부 판정 로직은 시스템 절에만. 같은 내용을 두 곳에 중복 서술하지 않음(현행 `41`, `134` 원칙 계승)
2. **공용/개별 경계 테스트**: 2개 이상 sub-step에서 쓰이면 공용, 아니면 개별. 단 횡단 정책(가드레일, 세션과 개인정보)은 사용 횟수와 무관하게 공용

## 다. sub-step 규격화 방침 (적절성 검토 결과)

Step과 sub-step(`N. 행위자: 동작`) 규격은 이산 흐름엔 적절, 실시간과 동시 구간엔 무리한 규격화임.

- **적절**: 마법사형 이산 흐름(입력 → 생성 → 대기 → 표시 → 전송)은 sub-step에 잘 맞고 분기와 실패가 깔끔히 붙음. 전체 플로우 맵도 이 덕에 그려짐
- **무리**: 실시간과 동시 구간을 번호 sub-step에 욱여넣으면 내부 동역학이 사라짐(예: [[버나 - 버나잡이 한 판 기획서|버나]] 돌리기와 재담 동시, [[덧뵈기 - 나만의 탈춤 기획서|탈춤]] 춤사위 실시간 채점). Step 4 병행 생성과 대기를 최근 래퍼로 다시 짠 것도 선형 sub-step 모델이 동시성을 못 담아 생긴 보정임
- **방침**: sub-step을 기본 척추로 두되, 실시간과 동시 구간은 상태기계, 루프, 모드 한 덩이로 표기할 여지를 규칙에 남김

# 3. 남은 정합 작업 (후속)

양식 문서 내부 정합은 완료함(2026-07-03): [[콘텐츠 기획서 작성 양식#3. 표준 목차]], TL;DR, [[콘텐츠 기획서 작성 양식#나. 시스템 독립 명세 양식]] 양식(헤더 구조), [[#4. 관련 문서]] 헤딩과 가, 다 용어(구성 요소 → 시스템), [[콘텐츠 기획서 작성 양식#가. 정렬 원칙]]을 [[#3. 남은 정합 작업 (후속)]] 두 정렬 키와 정합, [[콘텐츠 기획서 작성 양식#6. 현행에서 신양식으로 매핑]] 표를 5절 목차로, [[콘텐츠 기획서 작성 양식#7. 작성 체크리스트]], MOC. 아래는 남은 후속임.

- **현행 기획서 5종 실제 재구성**: 유람기, 양반, 꼭두각시, 탈춤, 버나를 신 목차로 옮기는 것은 별건 대공사. 양식 확정 후 콘텐츠별로 진행. 재구성 시 각 시스템 명세 항목을 볼드 라벨 불릿에서 서브헤더(H3)로 전환하고, 라벨을 [[시범콘텐츠 공통 사양#나. 원인 (실패가 누구에게서 비롯됐는가)]] 항목명으로 맞춤(예: "가드레일과 실패" → "실패와 복구"). Codex 검토(2026-07-03)가 현행 라벨과 공통 사양 소유권 설명의 불일치로 지적, 사용자 결정 "후속에서 해소"
- **`wiki_lint.mjs` 중첩 헤더 앵커 지원(후속, 낮은 우선순위)**: 현재 `:244` `h.text === link.anchor`가 앵커를 통짜 텍스트로 비교해 Obsidian 중첩 경로 `[[파일#시스템#항목]]`을 broken으로 오판정함. 시스템마다 반복되는 명세 항목 헤더(동작과 규칙 등)를 콕 집어 링크하려면 `#`로 분해해 부모→자식 헤더 경로를 순서대로 매칭하는 로직 필요. 지금은 시스템 이름 참조 + 블록 ID로 우회하므로 급하지 않음
