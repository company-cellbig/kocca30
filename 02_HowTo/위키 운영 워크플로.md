> 위키를 키우는 세 동작, 수집(Ingest), 질의(Query), 유지(Maintenance)의 절차 정본임. [[AGENTS#2.8 위키 운영 워크플로 (수집/질의/유지)]] 절과 [[CONVENTIONS]]의 Overview 절을 2026-08-21에 이관받음(상시 로드 감량, SLIM-1). 세 동작이 거치는 게이트 규칙(작성자 동작, G1과 G2)은 AGENTS의 그 절이 정본임.

# 1. 수집 (Ingest): 소스 1개의 연쇄 갱신

새 소스(RFP, 논문, 기사, 회의록 등)를 읽고 위키로 컴파일하는 동작. 한 소스는 보통 페이지 1개가 아니라 관련 페이지 여러 개를 연쇄로 갱신함.

- **변환 선행**: 변환 대상 원본은 `_sources/`에 두고 [[docx 변환 파이프라인]](`/import-doc`)으로 `converted/`에 변환함. 변환본은 L2, `_locked/`는 L1 ([[CONVENTIONS#3.7 외부 근거의 권위 계층]])
- **추출**: 소스에서 핵심 엔티티(고유명사: 사람, 조직, 모델, 제품, 종목), 개념, 정량 주장을 뽑음. 어느 엔티티나 주장이 핵심인지 모호하면 사용자와 먼저 협의함
- **연쇄 갱신**: 한 소스가 닿는 관련 페이지를 모두 갱신함. 엔티티 페이지, 개념 페이지, 해당 주제 종합(overview) 페이지가 대상임. 없으면 적절한 폴더(`03_Concepts` 등)에 새 페이지를 만듦 (처음엔 `status: stub` 허용, [[CONVENTIONS#3.2 프론트매터 (YAML)]])
- **상호 연결**: 새 페이지와 바뀐 페이지를 `[[ ]]`로 서로 연결함 (페이지당 최소 2링크, [[CONVENTIONS#3.5 Wikilink 규칙]]). 정량 주장에는 출처 wikilink를 붙임 ([[CONVENTIONS#3.6 수치/목표 인용 원칙 (엄격)]])
- **모순 보존**: 기존 지식과 충돌하면 삭제하지 않고 모순 블록으로 보존함 ([[CONVENTIONS#3.9 모순(contradiction) 처리]])
- **등록**: 신규 페이지를 `00_Index/MOC.md`에 등록하고, log에 `ingest` 항목을 남김
- **검수**: 정량 인용이나 사실 주장이 다수면 [[AGENTS#3.3 외부 검토자 호출]] 호출 조건에 해당함. G1 통과 후 외부 검토를 제안함

# 2. 질의 (Query): 답의 페이지 환원

위키에 질문해 답을 합성하되, 새로 얻은 합성과 판단을 위키 페이지로 되돌려 탐색이 휘발되지 않게 하는 동작.

- **검색**: `00_Index/MOC.md`에서 관련 페이지를 찾고, 그 페이지와 `[[ ]]` 이웃을 읽음
- **합성**: 인용과 함께 답을 구성함 (출처 wikilink 동반, [[CONVENTIONS#3.6 수치/목표 인용 원칙 (엄격)]])
- **환원**: 위키에 없던 새 합성이나 판단은 페이지로 환원함. 적절한 폴더에 두고 `type: answer`를 부여한 뒤 ([[CONVENTIONS#3.2 프론트매터 (YAML)]]) MOC와 log(`query`)에 등록함. 단순 조회로 끝나 환원할 새 지식이 없으면 환원을 생략하되, 이때도 log에 `query`를 남김
- **게이트**: 환원으로 본문이 생기면 작성자 동작이므로 [[AGENTS#2.3 작업 사이클]]과 G1을 그대로 적용함

# 3. 유지 (Maintenance): 주기적 건강성 점검

사이클마다 도는 자동 lint(`wiki_lint.mjs`, 깨진 링크/anchor/가운뎃점 구조 점검)와 별개로, 위키 그래프의 건강성을 주기적으로 점검하는 동작.

- **주기**: 2주에서 4주마다 정기 수행함. 수집이 뜸해도 멈추지 않음. 수집 중 발견한 문제는 즉시 보강함
- **점검 대상**: 자동 lint가 못 잡는 의미와 그래프 결함
	- 고아 페이지(어디서도 링크되지 않음)와 관련 링크 2개 미만 페이지 ([[CONVENTIONS#3.5 Wikilink 규칙]] 링크 하한선)
	- 오래 `stub`이나 `draft`에 머문 페이지 ([[CONVENTIONS#3.2 프론트매터 (YAML)]] status)
	- MOC와 실제 페이지 불일치 (추가나 삭제 누락)
	- 폐기되거나 중복된 주장, 누락된 엔티티/개념 페이지, 다음에 채울 연구 갭
- **기록**: 건강성 점검은 log에 `lint`로, 구조나 스키마 정비는 `maint`로 남김. 큰 정비는 [[AGENTS#2.3 작업 사이클]]을 적용함

# 4. Overview(종합) 페이지

한 주제의 현재 이해를 서술형으로 합성한 페이지임 (`type: overview`). 단순 링크 목록인 MOC와 구분됨.

- **역할**: 흩어진 엔티티와 개념 페이지를 하나의 이야기로 엮어 "지금까지 아는 것"을 보여줌
- **MOC와의 차이**: MOC(`00_Index`)는 "어디에 무엇이 있는가"(색인)를, Overview는 "그래서 무엇을 아는가"(종합)를 담음
- **위치**: 주제가 속한 폴더(주로 `03_Concepts/`)에 둠. 파일명 예: `남사당놀이 개요.md`
- **유지**: 구성 엔티티나 개념이 갱신되면 함께 갱신함. 본문에서 구성 페이지를 `[[ ]]`로 링크하고 MOC에 등록함
