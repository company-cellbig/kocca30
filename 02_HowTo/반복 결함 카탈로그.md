> 외부 검토자(Codex) 적대 발췌 호출 시 [[codex 검수 포커스]]와 함께 첨부하는 과거 반복 결함 목록. 동일 패턴 재발을 우선 점검하도록 지시함. 운영 규칙은 **"두 번째 재발 시 등재"** — 일회성 결함이 아니라 패턴화된 것만 수록.

# 1. 분류 코드

- **CONV**: 변환 파이프라인(HWPX→MD 등) 관련
- **FACT**: 사실/출처/인용 관련
- **LOGIC**: 논리 비약/추론 관련
- **STRUCT**: 문서 구조/wikilink/MOC 관련
- **CONTENT**: 내용 품질/완전성(설명 부실, 항목 혼동) 관련

# 2. [CONV-001] 표 셀 병합(rowSpan/colSpan) 미반영

- 발견/log: [[log]] 2026-05-11
- 증상: 마일스톤 표 등 셀 병합이 있는 표에서 후속 row의 컬럼이 한 칸씩 밀려 모든 값이 어긋남. 인용 신뢰성 fatal
- 진단: extract_cells가 2D grid가 아닌 단순 리스트로 처리해 cellSpan 무시
- 권고 점검: 표 추출 코드에 cellSpan/rowSpan 처리 있는가. 빈 셀 채움 로직이 있는가
- 재발 시 첨부 포커스 발췌: P1 (출처 일치), P2 (논리 비약)

# 3. [CONV-002] 시각 bullet 기호(□●▶ 등) 본문 잔존

- 발견/log: [[log]] 2026-05-11
- 증상: 출력 마크다운에 `- □ 무형문화유산...`처럼 시각 마커가 텍스트 안에 그대로 노출
- 진단: CIRCLE_BULLET_PAT 정규식 미확장, strip_visual_marker 미적용
- 권고 점검: paragraph/cell 출력 전 시각 마커 strip 호출 여부. 정규식 커버리지 (○●◇◆■□▶▸▣•·ㆍ 등)
- 재발 시 첨부 포커스 발췌: P4 (톤/구조 일관성)

# 4. [CONV-003] bullet block 안 표 처리 (Obsidian list continuation 깨짐)

- 발견/log: [[log]] 2026-05-11 다수
- 증상: bullet 들여쓰기 안에 pipe_table을 그대로 두면 Obsidian이 list continuation으로 해석해 raw text 노출. 표 다음 bullet의 들여쓰기 흐름도 깨짐
- 진단: GFM pipe_table은 들여쓰기 0에서만 보장. 들여쓰기 안에서는 뷰어 구현마다 동작 다름
- 권고 점검: emit_table()이 list block 안일 때 cross-product 평탄화(`- row_label / col_label: value`) 또는 1행 짧은 셀 → bold 라벨로 emit. last_bullet_indent 보존 여부
- 재발 시 첨부 포커스 발췌: P1 (출처 일치), P4

# 5. [CONV-004] 컨테이너 포맷 첫 entry 하드코딩

- 발견/log: [[log]] 2026-05-11 (Codex adversarial review)
- 증상: HWPX의 `Contents/section0.xml`만 처리해 multi-section 문서 본문 silent data loss. PDF/EPUB/DOCX 등 모든 컨테이너 변환기에 일반 원리
- 진단: ZIP/컨테이너의 첫 entry만 가정. 다음 entry 패턴 매칭 누락
- 권고 점검: 변환기 입구에 `^Contents/section(\d+)\.xml$` 같은 패턴 매칭 + 정렬된 순회. stats에 section 수 노출
- 재발 시 첨부 포커스 발췌: P3 (한계 조건 누락 — "첫 section만 처리"는 한계 조건)

# 6. [CONV-005] 시작 dash 이중 처리 (- - text)

- 발견/log: [[log]] 2026-05-11
- 증상: 원본 paragraph 텍스트가 시각적으로 `- 멀티모달...`처럼 dash로 시작하는 케이스에 변환기가 dash를 정보로 보존한 채 다시 `- ` bullet prefix 추가 → `- - text` 이중 dash
- 진단: LEADING_VISUAL_MARK 정규식에 `-` 미포함
- 권고 점검: 시각 마커 strip 정규식이 시작 dash(`-`)도 인정하는가
- 재발 시 첨부 포커스 발췌: P4

# 7. [CONV-006] inline equation 누락 (hp:equation 미추출)

- 발견/log: [[log]] 2026-05-11
- 증상: 평가표 등에서 수식/변수(`FID= LEFT ∥ μ_r - μ_g ...`, `X_r`, `Σ_r` 등)가 변환물에서 통째 누락. 의미 파악 불가
- 진단: paragraph 추출 시 `<hp:t>`만 보고 `<hp:equation>` element 무시. 한컴 원본은 수식을 별도 element 안 `<hp:script>`에 LaTeX-like로 보관
- 권고 점검: paragraph 순회 함수가 텍스트와 수식 element를 함께 수집하는가. 수식은 inline code(백틱)로 감싸 정보 보존
- 재발 시 첨부 포커스 발췌: P1 (사실 누락), P3 (한계 조건)

# 8. [CONV-007] 셀 paragraph hierarchy 손실 (부모/자식 들여쓰기 평탄화)

- 발견/log: [[log]] 2026-05-11
- 증상: 표 셀 안에 원본의 들여쓰기 계층(□ 부모 + • 자식 4개)이 있어도 모두 1단 bullet으로 평탄화. paraPr.heading.type=NONE(부모)와 BULLET idRef=N(자식) 구분 정보 손실
- 진단: 셀 paragraph 추출 시 단순 text 리스트로만 수집해 paraPr 폐기
- 권고 점검: extract_cells가 paraPr_map을 인자로 받고 (text, indent) tuple로 반환하는가
- 재발 일반 원리: **추출 단계에서 메타데이터 폐기 금지 — 단순화는 출력 단계 책임** (PDF font, HTML inline tag, 표 셀 hierarchy 등 모든 변환기에 적용)
- 재발 시 첨부 포커스 발췌: P1, P3

# 9. [CONV-008] read-only 영역 silent overwrite

- 발견/log: [[log]] 2026-05-11 (Codex adversarial review)
- 증상: 같은 basename의 다른 파일을 import하면 `copyFileSync`가 `_sources/` 기존 원본을 덮어씀. AGENTS.md `_xxx/` read-only 정책과 충돌, provenance 손실
- 진단: copy 직전 동일성 검증 없음. 정책 문서만으로는 강제력 부족
- 권고 점검: read-only 영역에 쓰는 코드 경로 모두 동일성 검증(SHA256 등)이 있는가. 다른 hash면 명시적 error
- 재발 일반 원리: **read-only 영역에 쓰는 코드 경로는 모두 동일성 검증** — 정책 문서만으로는 강제력 없음
- 재발 시 첨부 포커스 발췌: P2 (정책 vs 코드 모순)

# 10. [FACT-001] 정량 요건의 충족 범위 오해

- 발견/log: [[log]] 2026-05-14 (덜미 시범콘텐츠 작업)
- 증상: RFP의 "시나리오 6종 이상" 정량 요건을 1차연도 단독 충족으로 본문에 단정. 실제로는 사업 전체(2년 누적) 목표
- 진단: 정량 요건 인용 시 충족 범위(전체/연차별/누적)를 RFP 원문 맥락 확인 없이 추론
- 권고 점검: 정량 요건 인용 본문이 "범위(전체/연차/누적)"를 명시하는가. 충족 주체(연차별 카운트인지 전체 누적인지)가 RFP 원문과 일치하는가
- 재발 시 첨부 포커스 발췌: P1 (출처 일치), P2 (논리 비약)

# 11. [LOGIC-001] 채록본/구비전승을 "정전 텍스트"로 단정

- 발견/log: [[log]] 2026-05-15 (덜미 - 전자책 변환 취사 기준)
- 증상: 꼭두각시놀음처럼 채록본마다 거리/줄거리가 다른 구비전승 인형극을 "정전 플롯이 공유 자산"으로 단정 인용. 실제로는 단일 정전 텍스트 없음
- 진단: 외부 자료에서 작품 자체와 특정 채록본 권리를 구분하지 않음. L4(외부 자료)와 L1(정본)을 혼동
- 권고 점검: 구비전승/채록본 기반 자료를 "정전"으로 단정하지 않는가. 권리 단위(작품 vs 특정 채록본/보존회 연출) 구분 표기 있는가
- 재발 시 첨부 포커스 발췌: P2, P3 (한계 조건 누락)

# 12. [LOGIC-002] 상위개념과 사례를 같은 층위에 평면 나열

- 발견/log: [[log]] 2026-05-14 (덜미 플롯 소재 4종 평면 나열 → 박첨지놀이 단일 구성으로 재정리)
- 증상: 분류 체계상 상위 개념(꼭두각시놀음)과 그 사례(서산 박첨지놀이)를 같은 비교 표에 4행으로 평면 나열. 독자에게 잘못된 계통 관념 전달
- 진단: 비교 표 작성 시 항목들 사이의 부모-자식, 형제 관계 확인 누락
- 권고 점검: 비교 표/리스트의 모든 항목이 같은 계통 층위에 있는가. 부모-자식 관계가 평면으로 섞이지 않는가
- 재발 시 첨부 포커스 발췌: P2 (논리 비약), P5 (구조 일관성)

# 13. [STRUCT-001] 결정 후 stale 표현이 본문 잔류

- 발견/log: [[log]] 2026-05-15 (덜미 - 전자책 변환 — 박첨지놀이 구성 제거 / 콘셉트/결정사항 정정), [[log]] 2026-05-18 (기획서 §4 라벨 stale 4건)
- 증상: 절을 제거/변경/이름 바꾼 뒤에도 다른 절의 옛 전제, 옛 라벨, 옛 참조가 본문 곳곳에 남음. 예시:
	- 마이그/리네임 후 옛 헤딩 라벨 잔류 (예: §4 헤딩이 "시스템 인벤토리" → "기술 구성"으로 바뀌었으나 본문 참조는 "§4 시스템 인벤토리" 잔류)
	- 절 제거 후 다른 절의 옛 전제 잔류 ("정전 플롯 고정" 등)
- 진단: 결정/구조 변경 시 문서 내 교차 참조 점검 누락. 자동 점검 없음
- 권고 점검: 자동 lint(`scripts/wiki_lint.mjs`)로 §/wikilink stale 자동 탐지. 절/라벨 변경 시 grep으로 본문 잔류 확인
- 재발 시 첨부 포커스 발췌: P2 (문서 간 모순), P5 (위키 정합성)

# 14. [STRUCT-002] 도표/표 항목과 부속 정보 혼재

- 발견/log: [[log]] 2026-05-18 (기획서 §2.가 공용 기능 도표 정리)
- 증상: 표 한 컬럼에 항목명 + 괄호 안 부연(sub-목록/동작/설명/효과)이 섞여 행마다 다른 성격의 정보가 한 형식에 들어감. 예: "기능" 컬럼에 "세션 라이프사이클 (생성/종료/타이머/...)"처럼 기능명 + sub-목록 혼재
- 진단: 표 컬럼 정의 시 정보 형식 일관성 점검 누락. 행마다 다른 성격의 부속 정보를 같은 컬럼에 욱여넣음
- 권고 점검: 표 컬럼 정의 시 (1) 모든 행이 같은 형식의 정보를 담는가 (2) 부연 정보는 별도 컬럼이 적절한가
- 재발 시 첨부 포커스 발췌: P4 (구조 일관성), P5 (정합성)

# 15. [STRUCT-003] 도표/표에 위계 다른 항목 섞임

- 발견/log: [[log]] 2026-05-18 (기획서 §2.가 세션 컨테이너 분리)
- 증상: 도표/표 안에 의미 위계가 다른 항목이 같은 레벨로 나열됨. 예: 공용 기능 표(Step이 호출하는 횡단 기능)에 "세션 라이프사이클"(Step의 상위 컨테이너)을 같은 행으로 묶음 — 위계 반대
- 진단: 표 도입부 정의("Step이 호출하는 횡단 기능")와 실제 행 항목의 위계 점검 누락
- 권고 점검: 표/도표 도입부 정의 ↔ 실제 행 위계 매칭. 의미 위계가 다른 항목은 별도 절 또는 별도 표
- 재발 시 첨부 포커스 발췌: P2 (위계 모순), P5 (구조 일관성)

# 16. [STRUCT-004] 잉여 헤딩 계층 (하위가 1개뿐)

- 발견/log: [[log]] 2026-05-18 (기획서 §2 시프트 — 잉여 H2 계층 제거)
- 증상: 상위 헤딩의 하위가 1개뿐인데 분리. 예: §2 사용자 경험 + §2.가 시스템 플로우 한 H2만 있는 구조 → 잉여 1단
- 진단: 새 절 신설 시 "추후 sibling H2 추가될 가능성"을 가정하나 실제 추가 안 됨. 의도적 분리가 아니라 인공 계층
- 권고 점검: 헤딩 신설 시 (1) 같은 레벨의 sibling이 본 작업에서 1개 이상 존재하는가 (2) 추후 추가 확실한가. 둘 다 No면 한 단계 시프트
- 재발 시 첨부 포커스 발췌: P4 (구조 일관성), P5

# 17. [STRUCT-005] 모듈/프로세스(컴포넌트/흐름) 혼재

- 발견/log: [[log]] 2026-06-04 (기획서 §4.가 AI 시스템 — 진행기/조립이 AI 모듈과 혼재)
- 증상: 한 절/목록에 성격이 다른 항목을 같은 종류처럼 나열. 예: "AI 시스템" 절에 비-AI 오케스트레이션(마당 진행 제어, 결과물 조립)을 AI 모듈과 같은 레벨로 나열 → 독자가 모두 하나의 시스템/같은 종류로 오해. 흐름(§2)이 이미 있는데 컴포넌트 절이 흐름을 또 끌어안기도
- 진단: 항목의 "종류"(컴포넌트 vs 흐름, AI vs 비-AI)를 구분하지 않고 평면 나열. 단수 절 제목("AI 시스템")이 이질 항목을 한 덩어리로 봉합
- 권고 점검: 한 묶음의 모든 항목이 같은 종류인가. 비-AI/오케스트레이션/흐름 항목이 "시스템/모듈" 절에 섞이지 않았는가. 흐름은 흐름 절로, 컴포넌트는 컴포넌트 절로 분리됐는가
- 재발 시 첨부 포커스 발췌: P2 (위계/종류 모순), P5 (구조 일관성)

# 18. [STRUCT-006] 개요-상세 순서 역전

- 발견/log: [[log]] 2026-06-04 (기획서 §3.마 — 캐릭터 레퍼런스 원칙(한 분류 상세)이 자산 목록(전체 개요)보다 앞)
- 증상: 전체 개요/목록보다 한 분류의 상세가 먼저 옴. 독자가 전체 그림을 보기 전에 일부 상세부터 읽음. 또 독립 절이던 하위 내용(메커니즘 비교)이 상위 항목의 하위로 들어가야 하는데 평행 절로 남음
- 진단: 절 순서를 개요→상세(상위→하위)로 정렬하지 않음. 특히 볼드 라벨 → 헤더 승격 시 순서 검토 누락
- 권고 점검: 개요(전체 목록/표)가 상세(분류별 원칙/하위)보다 앞에 오는가. 한 분류 전용 하위 내용이 독립 절이 아니라 그 분류 절의 하위 블록인가
- 재발 시 첨부 포커스 발췌: P5 (구조 일관성)

# 19. [CONTENT-001] 동일 형식/이름을 동일 항목으로 혼동

- 발견/log: [[log]] 2026-06-04 (기획서 §3.마 — 마당 사건 풀 vs 마당 플롯 풀이 같은 텍스트/JSON이라 구별 안 됨)
- 증상: 저장 형식·이름이 닮은 두 항목이 표/목록에서 구별 안 돼 같은 것으로 읽힘. 실제로는 역할이 다름(재료 vs 완제품, 입력 vs 출력)
- 진단: 항목 간 관계(상하/입출력/재료-제품)를 명시하지 않고 형식만 적음. "형식 같음 = 같은 항목" 오해 유발
- 권고 점검: 형식·이름이 닮은 형제 항목이 역할/관계로 구별되는가. 재료→완제품, 입력→출력 같은 관계가 본문에 드러나는가
- 재발 시 첨부 포커스 발췌: P2 (논리/관계), P5

# 20. [CONTENT-002] 한 줄 라벨로 항목 설명 갈음 (역할/입출력 부재)

- 발견/log: [[log]] 2026-06-04 (기획서 §3.마 "캐릭터 디자인", §4.가 모듈 한 줄 나열)
- 증상: 항목을 이름 + 한 줄 라벨로만 나열하고 "설명했다"고 종결. 독자가 그게 뭔지, 무엇을 만들/쓰는지 못 뽑음. 표 셀이 동어반복("양식 가이드: 양식 문서/예시")
- 진단: 항목별 역할/입력/출력/용도를 정하지 않고 표면 문장만 생산. 자기검수가 형식만 보고 내용 완전성을 안 봄
- 권고 점검: 각 항목이 역할 + 입력/출력(또는 용도/산출물)까지 적혔는가. 분류와 산출물이 동어반복 아닌가. "이걸 보고 무엇을 만들/쓸지 알 수 있는가"
- 재발 시 첨부 포커스 발췌: P3 (한계/완전성), P4 (구조)
