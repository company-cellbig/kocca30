> 콘텐츠 개발 문서(기획서)의 표준 작성 양식. 개발 담당자(연관 기획자, 프로그래머, 아티스트)가 빠르게 파악하도록 개요 → 전체 플로우 → 구성 요소(의존 순) 순으로 구성함. 화면의 시각과 레이아웃 상세는 별도 UI 문서가 다루고, 그 화면이 받는 입력과 판정 로직은 본 문서에 둠.

# 1. 목적과 독자

- 목적: 콘텐츠별 기획서를 일관된 뼈대로 써서 개발 담당자가 30초 안에 구조를 잡고 자기 관심 부분으로 바로 이동하게 함
- 독자별 관심: 기획자는 동작과 규칙, 프로그래머는 입력과 출력 및 기술 요건, 아티스트는 자산 요구
- 적용: 시범콘텐츠 콘텐츠 개발 문서 전반. 세션과 Step 골격은 [[시범콘텐츠 공통 사양]], 사용자와 연속성은 [[플랫폼 사양]]을 인용함
- 플랫폼 차이: 키오스크(1인)와 미디어 케이브(다중)는 사용자 식별과 누적 방식이 다름. 다중 콘텐츠는 [[플랫폼 사양#7. 미결 항목 (확인 필요)]]의 미디어 케이브 개인화 메커니즘을 따르며, 양식 적용 시 그 차이를 플로우나 구성 요소에 반영함

# 2. 문서 범위

- **포함**: 콘텐츠 로직. 전체 플로우와 그 상태, 분기, 병행, 파기 시점, 구성 요소와 그 동작과 규칙, 기술 요건, 자산 요구, 가드레일, 그리고 화면이 받는 입력과 판정과 상태 로직
- **제외**: 화면의 시각과 레이아웃 상세(배치, 컴포넌트 디자인, 비주얼)는 별도 UI 개발 문서가 정본임. 단 화면이 받는 입력, 판정, 상태, 개인정보 처리 같은 인터랙션 로직은 UI 장식이 아니라 콘텐츠 로직이므로 본문에 남김
- **참조로 대체**: 세션과 그 개인정보 공통 원칙은 [[시범콘텐츠 공통 사양#8. 개인정보와 가드레일 원칙]], 사용자와 연속성 및 프로필 개인정보는 [[플랫폼 사양]], 기술 6영역 템플릿은 [[시범콘텐츠 공통 사양]]을 인용함. 콘텐츠 고유 데이터와 개인정보(영상, 사진, 콘텐츠 결과물 등)는 참조로 대체하지 않고 본문 구성 요소에 둠

# 3. 표준 목차

아래 절 번호는 작성 대상 콘텐츠 기획서의 절을 가리킴 (이 양식 문서 자신의 절 번호와 구분).

| 절 | 내용 |
|---|---|
| 1. 개요 | 한 줄 정의, 목표 경험, 핵심 메커닉, 플랫폼과 세션 길이, 문서 범위(콘텐츠 로직 / UI와 연속성은 별도 문서 링크) |
| 2. 전체 플로우 | Step 시퀀스와 개발에 중요한 상태, 분기, 병행, 파기 시점까지. 흐름도 권장. 화면은 UI 문서 참조만(시각 상세 제외) |
| 3. 구성 요소 | 콘텐츠를 이루는 요소를 의존 순으로. 각 요소는 자족 블록(§4 양식) |
| 4. 공유 계층 참조 | 세션, 사용자와 연속성, 개인정보, 기술 6영역을 공통 사양과 플랫폼 사양으로 참조. 콘텐츠 고유분만 |
| 5. 산출물 | 콘텐츠가 내는 결과물과 규격 |
| 6. 일정과 마일스톤 연계 | 로드맵 마일스톤과의 연결 |
| 7. 리스크와 검증 | 위험과 검증 방법 |
| 8. 관련 문서 | UI 문서, 공통 사양, 플랫폼 사양 등 |

설계 원칙: 전체 플로우는 런타임 흐름(시퀀스, 상태, 분기, 병행, 파기 시점)을 담고, 구성 요소는 피처 내부의 깊은 동작을 담음. 같은 내용을 두 곳에 중복 서술하지 않음. 상태와 분기, 병행, 실패는 흐름도나 상태 표기로 명시하되 시각 디자인은 적지 않음.

# 4. 구성 요소 작성법

## 가. 정렬 원칙 (의존 방향 순)

구성 요소는 의존 방향으로 배열함. 다른 요소가 전제로 삼는(많이 의존받는) 기반부터 두고, 그것을 쓰는 요소를 뒤에 둠. 한 엔진과 그 입력 데이터처럼 강하게 묶인 요소는 인접 배치하고 의존을 명시함. 일반 위계:

1. 핵심 메커닉(생성, 변환, 채점 엔진)과 그것이 전제하는 입력 데이터(사건과 플롯 풀, 채점 기준 등)
2. 진행 호스트와 연출 (페르소나, 추임새 등)
3. 자산
4. 가드레일과 실패 처리 (횡단)

## 나. 요소 자족 블록 양식

각 구성 요소는 아래 고정 소제목을 갖춰, 역할별 독자가 자기 줄로 바로 이동하게 함.

- **역할과 목적**: 이 요소가 콘텐츠에서 하는 일
- **입력과 출력**: 받는 데이터와 내는 데이터, 형식과 규격 (프로그래머)
- **동작과 규칙**: 핵심 로직과 판정 규칙 (기획자)
- **기술 요건**: 모델 확보 방식, 성능 기준 등. [[시범콘텐츠 공통 사양#가. AI 시스템]] 명세 항목 준용 (프로그래머)
- **자산 요구**: 필요한 자산과 규격 (아티스트)
- **가드레일과 실패 처리**: 안전 검사와 실패, fallback
- **의존**: 어느 구성 요소나 플로우 단계와 연결되는가

## 다. 구성 요소 입도

- 한 구성 요소는 독립적으로 설계, 구현, 검증되는 단위로 잡음
- 너무 잘게(한 줄 라벨로 끝날 만큼) 쪼개거나, 서로 다른 메커닉을 한 블록에 뭉치지 않음 ([[반복 결함 카탈로그]] STRUCT-005)
- 라벨만 적고 내용을 비우지 않음. 역할과 입출력, 동작까지 적어 보고 무엇을 만들지 알게 함 (CONTENT-002)

# 5. 현행에서 신양식으로 매핑

현행 두 기획서는 Step 순서 명세(S1~S7 / Step1~7)가 중심 구조이고 화면(UI)과 로직이 섞여 있음. 신양식으로 옮길 때 아래로 재배치함.

| 현행 위치 | 신양식 위치 |
|---|---|
| §2 시스템 플로우/동작의 Step별 명세 | 2. 전체 플로우 (한눈에 요약, UI 제거) + 상세는 3. 구성 요소로 분산 |
| §3 콘텐츠 설계(진행 호스트, 메커닉, 자산, 가드레일) | 3. 구성 요소 (요소별 자족 블록으로 통합) |
| §4/§5 기술 구성(AI 등) | 3. 구성 요소의 "기술 요건"으로 피처별 통합 + 4. 공유 계층 참조 |
| Step 명세의 화면, 별도 UI 문서 | 본문에서 제거, UI 문서로 분리 (플로우에서 참조만) |
| 세션, 개인정보, 연속성 | 4. 공유 계층 참조 (공통 사양, 플랫폼 사양) |

구성 요소 정렬 예시:
- 덜미: 1) 서사 생성 엔진과 그 입력인 사건과 플롯 풀(핵심 메커닉, 엔진이 풀을 전제) 2) 박첨지 진행 호스트 3) 그림동화 결과물 조립 4) 자산 5) 가드레일과 실패
- 덧뵈기: 1) 탈 3D 변환(Step 3, 2D 도안에서 3D) 2) 포즈 채점과 신명 게이지(Step 4) 3) 말뚝이 진행 호스트 4) 리플레이 영상 생성(Step 5) 5) 자산 6) 가드레일과 실패

# 6. 작성 체크리스트

- 개요만 읽어도 콘텐츠가 무엇이고 무엇을 만드는지 잡히는가
- 전체 플로우가 런타임 흐름(상태, 분기, 병행, 파기)을 담고 구성 요소와 중복되지 않는가
- 구성 요소가 의존 방향 순으로 배열됐는가
- 각 요소가 자족 블록(역할/입출력/동작과 규칙/기술 요건/자산 요구/가드레일/의존)을 갖췄는가
- 구성 요소 입도가 적절한가(한 줄 라벨로 끝나거나 서로 다른 메커닉을 한 블록에 뭉치지 않았는가)
- 프로그래머, 아티스트, 기획자가 각자 관심 줄로 바로 이동할 수 있는가
- 화면의 시각과 레이아웃 상세만 UI 문서로 갔고, 화면이 받는 입력과 판정과 상태 로직은 본문에 남았는가
- 공유 계층(세션, 연속성, 공통 개인정보, 기술 6영역)은 참조하고, 콘텐츠 고유 데이터와 개인정보는 본문에 뒀는가
- frontmatter status와 잠정값, 확인 필요 항목이 표기됐는가
