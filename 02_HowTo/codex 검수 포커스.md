> `/codex:adversarial-review` 호출 시 인자로 첨부하는 표준 비판적 검수 프롬프트. 코드 중심 attack surface를 문서 검수용으로 재정의.

# 1. 배경

Codex 플러그인의 `adversarial-review` 시스템 프롬프트는 회의 기조는 강하지만 attack surface가 코드(auth/race/migration 등)로 하드코딩되어 있음. 이 저장소는 마크다운 문서가 산출물이므로 문서 결함을 우선순위로 잡도록 포커스 텍스트를 첨부해야 함.

추가 근거: LLM-as-judge는 명시적 비판 프롬프트 없이는 관대해지는 경향이 있음. 회의 기조와 우선순위/평가 기준을 명시할수록 catch율이 올라감.

# 2. 표준 포커스 텍스트

호출 예시 ([[AGENTS#3. 검수 기준과 호출 방식]] 참조):

```
/codex:adversarial-review --background <아래 텍스트 복사>
```

```
이 저장소는 LLM Wiki(마크다운 문서 저장소). 다음 우선순위로 비판적 검수
수행. "괜찮아 보임"은 사유가 아님: 결함을 적극적으로 찾을 것.

[P1 사실 오류/출처 미스매치]
- 수치/일정/인용이 출처(_locked 또는 wikilink 대상) 원문과 일치하는가
- 출처 없이 들어간 정량 주장이 있는가
- 출처 wikilink가 실제 파일을 가리키는가 (깨진 링크)

[P2 논리적 비약/추론 정정]
- _locked 변경이 외부 원본 검증 없이 추론으로 이뤄졌는가
- 합계/누적/인과 관계에 비약 (예: 연차별 합 ≠ 총량)
- 한 문서 단정 사실이 다른 문서/출처와 모순
- A→B, B→A 상호 참조에서 양쪽 다 "상세는 저쪽"으로 미뤄 실체(정의/값/명세)가 부재한 순환 참조인가 (각자 실체 보유한 정상 정본 분담과 구별)

[P3 누락된 반론/견고성]
- 외부 검증 없이 "확정" 표기된 추정값
- 원문 모순이 정상화되어 감사 추적이 사라졌는가
- 주장에 한계 조건이 빠져 있는가

[P4 톤/구조 일관성 (CONVENTIONS.md 3.4 문체)]
- 음슴체(~임/~함) 준수, 가운뎃점(`·`) 금지, 두괄식/개조식
- 프론트매터 updated 필드가 실제 수정 일자와 일치
- 08_Logs/log.md 기록 양식 준수

[P5 위키 정합성]
- 신규 문서 MOC 등록, 양방향 wikilink, 깨진 링크 없음

기조: 회의가 기본. 단순 "합리적으로 보임"은 approve 사유가 아님:
외부 근거가 있어야 통과. CONVENTIONS.md 3.6 수치/목표 인용 원칙, 3.7
외부 근거의 권위 계층 및 AGENTS.md 3. 검수 기준과 호출 방식 우선 가이드.
```

# 3. 발췌 종류별 가이드 (사실/정합 vs 적대)

[[AGENTS#2.1 역할 분담]]의 외부 검토자(Codex)는 발췌 종류로 시선을 분리함. 단일 호출에 P1~P5 전체를 시키면 P1에 쏠리고 P2/P3가 묻히는 약점 회피. 사실/정합 발췌와 적대 발췌를 병렬 또는 직렬로 호출 가능.

## 3.1 사실/정합 발췌 (P1 + P5)

- 머리말 (회의 기조 + "괜찮아 보임" approve 사유 아님 문장)
- [P1 사실 오류/출처 미스매치] 블록 전문
- [P5 위키 정합성] 블록 전문
- 끝맺음 ("[[CONVENTIONS#3.6 수치/목표 인용 원칙 (엄격)]], [[CONVENTIONS#3.7 외부 근거의 권위 계층]] 및 [[AGENTS#3. 검수 기준과 호출 방식]] 우선 가이드" 문장)

호출 예시:

```
/codex:adversarial-review --background <머리말 + P1 + P5 + 끝맺음>
```

**시선**: 출처 일치, 깨진 링크, 양방향 연결, MOC 등록. 위키 정합성(P5) 영역 중 wikilink anchor 전수 점검은 Codex 권한 sandbox로 차단되는 경우가 많아 작성자의 grep 패스가 보완. 외부 시선의 가치는 사실 정확성(P1)에서 더 두드러짐.

## 3.2 적대 발췌 (P2 + P3 + 반복 결함 카탈로그)

- 머리말 (회의 기조)
- [P2 논리적 비약/추론 정정] 블록 전문
- [P3 누락된 반론/견고성] 블록 전문
- 끝맺음
- **추가 첨부**: [[반복 결함 카탈로그]] 본문: 과거 반복 결함의 재발 우선 점검 지시

호출 예시:

```
/codex:adversarial-review --background <머리말 + P2 + P3 + 끝맺음 + 반복 결함 카탈로그 본문>
```

**필수 조건**: fresh context: Codex 호출마다 새 thread 자동 생성으로 작성자 세션 격리 보장.

**시선**: 논리 비약, 누락 반론, 한계 조건. 회의 기조 강화. 작성자가 자기 작업에 관대해지는 사각지대 보완.

## 3.3 가독성 발췌 (P4 + 명료성, 낯선 독자 시선)

작성자가 자기 글이라 못 보는 모호한 용어, 구어체, 반복을 fresh context Codex가 외부 시선으로 잡음. 큰 변경이나 외부 노출 산출물에서 작성자 자기검수(낯선 독자 패스, [[AGENTS#2.2.1 작성자]])만으로 부족할 때 추가 호출.

**첨부 블록**: 머리말(회의 기조) + 아래 [가독성/명료성] 블록 + 끝맺음

```
[가독성/명료성 (낯선 독자 시선)]
맥락 없는 독자로 각 문장을 읽고 다음을 적극 지적:
- 정의 안 된 용어나 지시어 (예: "분석"이 무슨 분석인지 안 적음, 막연한 "이 기능", "해당 값")
- 구어체, 비표준어, 임의 조어 (예: "이름 없는 토큰" 같은 비표준 표현)
- 같은 뜻을 다른 문장으로 반복하는 군더더기
- 단순 문장 나열 (의미 분류와 항목화 안 됨, 라벨에 서너 줄 욱여넣음)
- 1단계 불릿에 복수 항목(역할/단계/종류별) 욱여넣기, 제목이 복수 주제('A와 B')인데 본문 평면 나열
- 목록 형식 오선택 (조건-결과인데 평문, 담당자별로 갈리는데 한 불릿, 길고 이질적 값인데 표로 셀 과적)
- 같은 수준 항목의 비병렬 구조 (문법 형태 제각각)
- 모호한 항목명("내용", "기타", "참고")만 반복
- 음슴체, 가운뎃점, em-dash, 슬래시 절제 위반 (CONVENTIONS 문체와 구조 우선 작성)
기준: 처음 보는 개발자나 심사자가 한 번에 이해하는가. 30초 안에 구조가 잡히는가.
```

**분담**: 작성자 자기검수(낯선 독자 패스)가 1차 방어, 가독성 발췌는 큰 변경의 외부 안전망. 작은 변경은 자기검수로 충분하면 생략.

# 4. 우선순위 설계 근거

| 층위 | 의미 | 검출 사례 (가설) |
|---|---|---|
| P1 사실 오류 | 가장 비싼 결함: 잘못된 수치가 산출물로 나가는 위험 | RFP 인용 수치 변조, 깨진 wikilink |
| P2 논리적 비약 | 그럴듯한 추론이 검증된 사실로 둔갑하는 위험 | _locked 추론 정정, 합산 모순 |
| P3 누락 반론 | 작성자가 자기 작업에 관대해지는 사각지대 | "확정" 표기된 추정, 한계 조건 누락 |
| P4 톤/구조 | 점진 부식: 개별 위반은 사소하나 누적되면 위키 가치 훼손 | 프론트매터 stale, 음슴체 위반 |
| P5 위키 정합성 | 그래프 구조 무결성 | MOC 미등록, 한쪽 방향 링크 |

# 5. 호출 운용 규칙

- 외부 검토자 호출은 [[#3. 발췌 종류별 가이드 (사실/정합 vs 적대)]]의 발췌본을 사용 (사실/정합=P1+P5, 적대=P2+P3+카탈로그). 단일 호출에 전체 P1~P5를 시키지 않음: 시선 쏠림 회피
- 사실/정합 발췌와 적대 발췌는 같은 commit 대상에 병렬 또는 직렬로 호출 가능 (큰 변경 시 권장)
- 단일 검수가 필요한 경우(소규모 변경, 임시 점검)에는 표준 포커스 텍스트 전문 첨부 가능
- 검수 결과가 새 결함 유형을 시사하면 본 문서 또는 [[반복 결함 카탈로그]]에 점검 항목 추가 (점진 보강)
- 효과 검증: 동일 diff에 대해 (a) 포커스 없는 호출 vs (b) 포커스 첨부 호출의 catch율 비교: 결과는 log.md에 기록
