> 이미지 삽입과 임베드(`![[ ]]`) 문법의 정본임. [[CONVENTIONS#3.5 Wikilink 규칙]]의 상세 블록을 2026-08-21에 이관받음(상시 로드 감량, SLIM-1). 임베드 대상과 이미지 경로가 실제로 있는지는 `scripts/wiki_lint.mjs`가 기계로 검사하므로, 이 문서는 문법을 고를 때 읽으면 됨.

# 1. 임베드 (transclusion)

다른 문서의 블록을 그 자리에 끼워 넣어 단일 정본을 여러 문서가 공유할 때 사용함.

**위키층(`04_Projects/`, `01_Concepts/` 등) 전용임.** 산출물층(`05_산출물/`)은 외부로 나가는 원고라 임베드가 안 풀리므로 쓰지 않고 내용을 직접 적음.

- **블록 임베드 권장** `![[파일명#^블록ID]]`: 헤딩 없는 본문 블록(표, 문단, 콜아웃이나 인용블록)을 끼워 넣음. 헤딩이 호스트 문서로 안 들어와 **헤딩 계층이 꼬이지 않음**
	- 블록 ID `^블록ID`(영문이나 하이픈)는 대상 블록에 부여. 표나 콜아웃, 인용블록은 블록이 끝난 다음 **빈 줄 뒤 독립 줄**에 둠 (문단은 끝 줄에 붙여도 됨)
	- **여러 줄을 한 덩어리로 임베드할 때는 콜아웃이나 인용블록으로 감쌈**. 일반 리스트는 블록 ID가 항목 하나만 잡아 전체가 안 펼쳐지므로, 표가 부적합한 정보(긴 규칙, 이질적 값)는 표 대신 콜아웃으로 묶어 단일 블록으로 만듦
- **헤딩 섹션 임베드** `![[파일명#섹션]]`는 피함: 대상의 헤딩(H1 등)이 호스트 문서에 통째로 들어와 레벨 역전과 하위 묶임을 일으킴. 헤딩은 각 문서가 직접 소유하고, 공유는 블록 임베드 또는 참조로
- **한계**: Obsidian 열람에서만 펼쳐짐. GitHub/raw/PDF 등 외부 출력에서는 안 풀리므로, 외부 제출 시 평탄화(임베드를 실제 내용으로 펼침) 필요
- **임베드 대상 블록은 self-contained로 작성**: 블록 안에 자기 문서 anchor(`[[#4. 헤딩 / 넘버링]]` 등)를 두면, 임베드된 곳에서는 호스트 문서의 절로 읽혀 엉뚱한 데를 가리킴. 문서명을 밝힌 anchor(`[[CONVENTIONS#4. 헤딩 / 넘버링]]`)를 쓰거나 절 이름을 말로 풀어 씀
- lint는 `![[ ]]`도 검증함: 헤딩 anchor는 헤딩 텍스트와, 블록 ID(`#^id`)는 대상 파일의 블록 ID 존재와 대조

# 2. 이미지 삽입 (GitHub 표준)

이미지는 옵시디언 전용 임베드 `![[파일.png]]`를 쓰지 않음. 임베드는 옵시디언 열람에서만 펼쳐지고 GitHub, raw, PDF에서는 안 풀림(위 임베드 한계와 같음). GitHub와 raw에서 바로 렌더링되는 표준 문법으로 넣음.

- **문법**: 폭 지정이 없으면 표준 마크다운, 폭 지정은 배치에 따라 가름 (표준 마크다운에는 폭 인자가 없음)
	- 폭 없음: `![대체텍스트](상대경로)`
	- 폭 지정 + 단독 배치(열0): `<img src="상대경로" width="500">`
	- 폭 지정 + 리스트 안: `![|500](상대경로)` (옵시디언 파이프 폭 문법. `<img>`는 리스트 안에서 렌더가 깨져 사용 불가, 아래 리스트 안 이미지 규칙 참조)
- **경로는 상대경로로 전부 표기**: vault 단축 경로(`유람기/3_1.png`)가 아니라 그 .md 파일 기준 상대경로를 다 적음 (예: `../../../assets/시범콘텐츠/유람기/3_1.png`). 이미지 원본은 `assets/`에 실제로 있어야 함
- **경로 공백은 `%20`로 인코딩**: 경로에 공백이 있으면 `%20`로 바꿈 (예: `팝업_비속어%20검출.png`). 한글은 그대로 둠
- **리스트 안 이미지는 마크다운 파이프 폭 문법으로, 빈 줄 없이 소속 불릿 텍스트 바로 아랫줄에 붙임**: Obsidian 편집 모드는 `<img>` HTML 태그가 한 줄에 단독으로 오면 문단 소속과 들여쓰기에 무관하게 리스트 밖 열0으로 렌더해 리스트를 끊음(빈 줄 유무, 2칸/탭 들여쓰기, span 감싸기, 문단 연속 전부 무효, 2026-07-27 실측). 리스트 안에서는 `<img>` 대신 마크다운 이미지 `![|500](경로)`를 쓰고, 소속 불릿 텍스트에서 빈 줄 없이 줄만 바꿔(시프트 엔터) 붙이며, 들여쓰기는 소속 불릿의 들여쓰기에 2칸을 더함(탭 하위 불릿이면 `\t␣␣![|500](...)`)
	- 절충: GitHub는 파이프 폭을 무시해 원본 크기로 렌더하고, 문단 안 줄바꿈을 공백으로 렌더해 이미지가 불릿 텍스트 끝에 같은 줄로 이어 붙음. 주 작업 환경인 Obsidian 편집 모드의 리스트 유지를 우선한 선택임
	- 단독 배치 이미지(열0, 앞뒤 빈 줄)는 `<img>`가 Obsidian과 GitHub 모두 정상 렌더라 종전대로 씀. 옛 규칙 두 가지(2026-07-24 "앞뒤 빈 줄 + 들여쓰기 독립 블록", 2026-07-27 1차 "문단 연속 `<img>`")는 Obsidian에서 깨지는 것으로 판명되어 폐기함
- **DOCX 제출본을 만들 때의 전처리**: 산출물층 작업이라 본 문서 범위 밖임
- **경로 검증은 기계가 함**: 표준 이미지와 `<img>` 경로의 파일 존재를 `scripts/wiki_lint.mjs`가 검사함. 2026-07-22부터 2026-08-20까지는 "작성자가 직접 확인함"으로 두었는데 한 번도 확인하지 않았고, 그 사이 폴더 이동으로 깨진 경로 32건이 하루 넘게 방치됐음. 자기보고를 검사로 옮긴 자리임
