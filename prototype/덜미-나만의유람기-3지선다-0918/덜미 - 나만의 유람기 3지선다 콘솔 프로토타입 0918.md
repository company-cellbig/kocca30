> 2026년 9월 18일 기준으로 분기한 독립 3지선다 콘솔 프로토타입임. 유니티 착수 전에 대화 콘솔로 유람기 한 세션을 끝까지 돌려 보기 위해 실행에 필요한 플롯 풀, 진행 설정과 합성 프로그램을 이 폴더에 둠.

# 1. 목적과 검증 범위

## 1.1 목적

유니티로 화면을 만들기 전에 LLM 3지선다 방식이 이야기를 자연스럽게 이어 가는지 확인함. 콘솔의 시작, 마당 선택, 주인공 설정과 결과물 생성 흐름은 기존 자유 입력형과 같게 두고, 거리별 응답 방식만 바꿈.

- **확인하려는 질문**: LLM이 매 거리의 질문에 맞는 응답 세 개를 만들 수 있는가. 사용자가 번호만 골라도 선택이 다음 거리와 최종 서사에 분명히 반영되는가. 선택하지 않은 응답이 결과물에 섞이지 않는가
- **다음 단계 입력**: 콘솔에서 확인한 선택지 생성 규칙, 선택 이력 구조와 서사 반영 규칙을 유니티 구현과 프롬프트 설계의 입력으로 넘김

## 1.2 용어

본 문서가 쓰는 용어임. 마당, 거리, 박첨지, 홍동지와 마당 조연 인형은 기획 정본의 서사 구조를 따름. 생성 선택지와 선택 이력은 본 프로토타입에서 새로 정한 용어임.

- **마당**: 한 세션이 다루는 극 한 편. 사용자가 4종 유형(위협-구원형, 권력 풍자형, 위선 폭로형, 욕심과 다툼형) 중 하나를 고르면 그 유형의 이야기 씨앗 하나가 배정됨
- **거리**: 마당을 이루는 장면 단위. 한 마당은 도입, 전개, 절정, 마무리의 4거리로 이뤄지고, 거리 하나가 전자책 한 페이지가 됨
- **박첨지**: 유람을 이끄는 떠돌이 노인 해설자 인형. 세션 내내 진행을 맡고 거리마다 질문을 던짐
- **홍동지**: 붉은 몸의 힘센 인형. 유형과 런타임 전개에 따라 절정에서 주인공을 거들 수 있으며, 욕심과 다툼형에서는 등장하지 않을 수도 있음
- **마당 조연 인형**: 박첨지 외에 마당 유형과 이야기 씨앗에 맞춰 등장할 수 있는 덜미 인형. [[3지선다 전용 플롯 풀 0918#2. 유형별 방향과 조연]]이 후보를 제시하되 실제 등장은 런타임 전개에 따라 달라짐
- **생성 선택지**: LLM이 현재 거리 방향, 누적 이야기 상태, 주인공 정보와 앞서 고른 응답을 받아 런타임 질문에 맞춰 만든 응답 후보 세 개. 도입은 상황과 동기, 전개와 절정은 행동, 마무리는 소회와 마무리 발화를 고르게 함
- **선택 이력**: 거리마다 질문, 실제로 제시한 선택지 세 개, 사용자가 고른 번호와 응답 문안을 함께 저장한 기록
- **AI 가드레일**: 사용자 입력과 생성물의 안전을 검사하는 시스템. 실명이나 실제 인물 풍자 등 차단 항목을 걸러 냄

## 1.3 검증 범위

콘솔로 확인할 수 있는 것과 없는 것을 갈라 둠.

**확인함**

- Step 1~7 진행 순서와 상태 전이
- 사용자가 고른 마당 유형과 배정된 이야기 씨앗, 거리별 박첨지 질문 문안과 LLM 생성 선택지
- 선택지 세 개가 서로 다른 응답이며 현재 질문, 사건과 앞선 선택에 맞는가
- 선택한 응답의 다음 거리와 최종 서사 반영, 주인공 이름과 캐릭터의 슬롯 반영
- 선택하지 않은 응답이 실제 사건처럼 서사에 섞이지 않는가
- 삽화 프롬프트의 인물 일관성 전략과 전자책 페이지 구성
- 생성된 삽화의 시각적 품질과 인물 일관성(GPT 이미지 생성 도구로 만들고, 두 항목 모두 사용자가 판정함)
- 삽화와 생성 서사를 합친 최종 페이지 이미지의 가독성과 구성

**확인 못 함** (유니티 프로토타입이나 실제 연동에서 따로 봄)

- 화면 타임아웃과 터치 미입력 타임아웃
- Step 5의 생성과 대기 병행, 상태 조회
- 실제 생성 지연과 실패 처리
- 다국어와 AI 가드레일 자동 판정 정확도

## 1.4 기획 정본과 다른 점

프로토타입이라 정본대로 하지 않는 지점임. 결과를 읽을 때 감안함.

- **전용 플롯 풀**: 원본의 네 유형마다 플롯 20개씩, 총 80개에서 제목과 4거리 방향만 간추린 [[3지선다 전용 플롯 풀 0918]]을 사용함. 질문과 확정 사건은 저장하지 않고 런타임에 생성함. 원본 풀이 사람 검수 전 초안이므로 배정된 이야기 ID를 런 파일에 남겨 사후 검수를 받음
- **약한 방향 준수**: 사용자가 고른 유형, 4거리 순서와 실제 선택은 강하게 지킴. 이야기 씨앗의 거리 방향, 조연과 해결 방식은 약한 가이드로만 사용해 앞선 선택에 따라 다른 사건과 결말을 허용함
- **LLM 3지선다 진행**: 정본과 기존 콘솔 프로토타입은 거리별 질문에 사용자가 자유 문장으로 답함. 본 프로토타입은 질문을 보여 준 뒤 LLM이 질문에 맞는 응답 선택지 세 개를 생성하고 사용자가 번호로 고르게 함. 정본 반영 여부는 런 결과를 보고 판단함
- **질문 런타임 생성**: 본 프로토타입은 저장된 질문을 꺼내지 않음. 현재 거리 방향, 누적 이야기 상태와 직전까지 고른 응답으로 박첨지 질문을 매 거리 새로 만듦. 정본 반영 여부는 런 결과를 보고 판단함
- **테스트용 이야기 지정**: 정본은 유형 안에서 플롯을 무작위로 배정함. 본 프로토타입은 같은 이야기 씨앗을 재현할 때만 `.madang` 명령에 이야기 ID를 함께 입력해 특정 씨앗을 배정할 수 있음
- **받기 기능 대행**: 정본의 Step 6은 결과물 감상, Step 7은 QR을 통한 받기와 종료를 맡음. 본 프로토타입은 QR과 다운로드 URL을 만들지 않고 Step 6의 `.save`로 런 문서 저장을 확정함
- **이미지 생성 도구**: 본 콘솔 프로토타입의 삽화에 한해 Codex에서 제공하는 GPT 이미지 생성 도구를 사용함. 이 문서에서는 이를 `GPT 이미지 생성 도구`로 부름. 기획 정본의 이미지 생성 모델 선정에는 영향을 주지 않음
- **실패와 이탈**: 정상 진행만 다룸. 비속어 3회 종료, 외부 서비스 실패, 그만두기와 상세 정리 절차는 재현하지 않음. 선택지 검사 실패가 반복되면 운영자가 런을 중단하고 기록만 남김

# 2. 진행 규약

## 2.1 역할 대행

정본 시스템과 본 프로토타입이 새로 둔 기능을 콘솔에서 무엇으로 대신하는지 정리함.

| 구분 | 시스템 또는 기능 | 콘솔 처리 |
| --- | --- | --- |
| 정본 | 세션 데이터 | 에이전트가 대화 안에서 상태로 유지함(필드는 [[#2.4 세션 데이터]]) |
| 정본 | 마당 플롯 생성 LLM과 배정 | [[3지선다 전용 플롯 풀 0918]]에서 사용자가 고른 유형의 이야기 씨앗 20개 중 하나를 기본으로 무작위 배정함. 같은 씨앗을 재현하는 테스트에서만 이야기 ID를 지정함 |
| 프로토타입 신설 | 질문과 선택지 생성 LLM | 에이전트가 현재 거리 방향, 누적 이야기 상태와 앞선 선택으로 박첨지 질문과 그에 답하는 선택지 세 개를 한 번에 생성하고 출력 전 검사함([[#4.1 질문과 선택지 생성]], [[#4.2 선택지 생성 규칙]]) |
| 정본 | 진행 호스트(박첨지) | 텍스트 대사만 출력함. 아바타와 음성 합성(TTS) 없음 |
| 정본 | 입력 유효성 검증과 AI 가드레일 | 에이전트가 간이 판정함([[#4.4 입력 검사]]) |
| 정본 | 유저 입력 가공 LLM | 에이전트가 네 번의 선택으로 거리별 서사를 생성함 |
| 정본 | 이미지 생성 모델 | 에이전트가 영어 프롬프트를 조립해 GPT 이미지 생성 도구로 16:9 삽화를 직접 생성함. 프롬프트 전문과 생성 이미지 경로는 런 파일에 기록함 |
| 정본 | 낭독 음성 생성 | 낭독 대본 텍스트로 대신함([[#4.5 낭독 대본]]) |
| 정본 | 결과물 조립과 호스팅, QR | 로컬 합성 프로그램은 거리별 페이지 PNG 4장을 만듦. 에이전트는 `.save`에서 런 문서를 작성해 저장함([[#6. 페이지 이미지 합성]], [[#7. 런 산출물]]). 다운로드 URL과 QR은 만들지 않음 |

## 2.2 콘솔 명령어

명령은 마침표로 시작함. Step 4의 선택 입력은 숫자 `1`, `2`, `3` 중 하나만 받되 `.state`와 `.reset` 명령은 이때도 유효함. 슬래시(`/`)를 쓰지 않는 이유는 Claude Code가 슬래시 입력을 자기 명령어로 가로채기 때문임(2026-07-13 실행 중 확인).

| 명령 | 동작 | 유효 시점 |
| --- | --- | --- |
| `.start` | 세션을 열고 Step 1 인트로를 진행함 | 세션 없음 |
| `.agree` | 이용 조건에 동의하고 Step 2로 감 | Step 1 |
| `.madang <1~4> [이야기 ID]` | 마당 유형을 고르고 이야기 씨앗을 배정받음. 이야기 ID를 생략하면 무작위 배정하고, 같은 씨앗을 재현하는 테스트에서만 해당 유형의 ID를 입력해 고정함([[#2.3 설정 번호]]) | Step 2 |
| `.char <1~6>` | 캐릭터 카드를 고름([[#2.3 설정 번호]]) | Step 3 |
| `.name <이름>` | 주인공 이름을 정함(20자 상한). 같은 Step에서 다시 치면 덮어씀 | Step 3 (카드 선택 뒤) |
| `1`, `2`, `3` | 현재 거리에 표시된 선택지 중 하나를 고름 | Step 4 선택 입력 |
| `.state` | 세션 데이터를 표로 출력함. 세션이 없으면 없다고 알림 | 언제나 |
| `.save` | 이번 런을 파일로 저장하고 Step 7로 넘어감 | Step 6 |
| `.reset` | 세션을 버리고 시작 대기 상태로 돌아감. 저장하지 않은 런이 있으면 한 번 확인함 | 언제나 |

- **유효 시점 밖의 명령**: 실행하지 않고 지금 무엇을 입력해야 하는지 다시 안내함. 없는 명령도 같게 처리함
- **Step 4와 5 진입**: 별도 명령이 없음. 이름이 확정되면 Step 4 진행이 자동으로 시작됨. 네 거리의 선택이 모두 끝나면 Step 5로 자동으로 넘어가 결과물을 한꺼번에 생성함([[#3.4 Step 4. 이야기 진행]])

## 2.3 설정 번호

`.madang`이 받는 기획 정본의 마당 유형 4종임.

| 번호 | 1 | 2 | 3 | 4 |
| --- | --- | --- | --- | --- |
| 유형 | 위협-구원형 | 권력 풍자형 | 위선 폭로형 | 욕심과 다툼형 |

`.char`가 받는 캐릭터 카드는 기획 정본의 연령대와 성별 조합 6종임. 번호는 본 프로토타입에서 아래와 같이 배정함.

| 번호 | 1 | 2 | 3 | 4 | 5 | 6 |
| --- | --- | --- | --- | --- | --- | --- |
| 카드 | 남자 아이 | 여자 아이 | 남자 청소년 | 여자 청소년 | 남자 어른 | 여자 어른 |
| 설정 ID | `CHILD_M` | `CHILD_F` | `TEEN_M` | `TEEN_F` | `ADULT_M` | `ADULT_F` |

## 2.4 세션 데이터

`.state`가 출력하는 필드임. 기획 정본의 세션 데이터에서 콘솔이 실제로 쓰는 항목만 추림.

| 필드 | 값 |
| --- | --- |
| 세션 ID | 세션마다 부여하는 식별자 |
| 언어 | 한국어 고정(다국어는 범위 밖) |
| 현재 Step과 거리 | 진행 위치 |
| 선택 마당 유형 | `.madang` 입력값 |
| 배정 이야기 씨앗 | [[3지선다 전용 플롯 풀 0918]]에서 배정된 이야기 ID, 4거리 방향과 유형별 조연 후보 |
| 누적 이야기 상태 | 지금까지 확정된 인물, 장소, 사건, 해결되지 않은 문제와 사용자가 고른 응답의 결과 |
| 캐릭터 카드 | 연령대와 성별 |
| 주인공 이름 | `.name` 입력값 |
| 현재 질문과 선택지 | 지금 거리의 질문과 LLM이 생성한 선택지 세 개. 선택을 마치면 다음 거리의 값으로 교체함 |
| 선택 이력 | 거리마다 질문, 제시한 선택지 세 개, 선택 번호와 선택 문안을 누적한 기록 |

## 2.5 턴 출력 형식

에이전트는 매 턴 맨 위에 상태 한 줄을 두고, 그 아래 박첨지 대사나 시스템 안내를 둠. 지금 어느 Step 어느 거리인지 한눈에 보게 함.

```
[Step 4 | 전개(2/4) | 주인공: 홍길동(어른 남) | 마당: 권력 풍자형]
```

Step 4에서는 상태 줄 아래에 질문과 선택지 세 개를 아래 예시와 같은 형식으로 출력함.

```text
박첨지: 홍길동이 억울한 사람들을 보았구먼. 이제 어찌하겠는가?

1. 관리 앞에서 잘못을 따져 묻는다
2. 사람들의 증언을 먼저 모은다
3. 관리의 허세를 재담으로 흉내 낸다

1, 2, 3 중 하나를 입력하세요.
```

# 3. Step별 진행

기획 정본의 Step 1~7 순서를 그대로 따르되 받기 기능은 [[#1.4 기획 정본과 다른 점]]에 적은 방식으로 대행함.

## 3.1 Step 1. 인트로

- **입력**: `.start` 다음 `.agree`
- **에이전트**: 세션 ID를 부여하고 언어를 한국어로 고정함. 박첨지가 맞이하는 대사와 체험 안내를 출력하고, 이용 조건 요지를 한 문단으로 보여 줌
- **다음**: Step 2

## 3.2 Step 2. 마당 유형 선택

- **입력**: `.madang <1~4> [이야기 ID]`
- **에이전트**: [[3지선다 전용 플롯 풀 0918]]에서 사용자가 고른 유형의 이야기 씨앗 20개 중 하나를 배정함
	- 이야기 ID를 생략하면 무작위로 배정함
	- 이야기 ID를 입력하면 해당 유형에 실제로 있는지 확인한 뒤 고정함. ID가 없으면 배정하지 않고 유효한 ID를 입력하거나 생략하도록 안내함
	- 이야기 씨앗의 제목, 4거리 방향과 유형별 조연 후보를 세션 데이터에 저장하되 사용자에게 뒤 거리의 방향을 미리 보여 주지 않음
	- 배정된 이야기 ID를 런 파일에 남겨 같은 조건으로 다시 시험할 수 있게 함
- **다음**: Step 3

## 3.3 Step 3. 주인공 설정

- **입력**: `.char <1~6>` 다음 `.name <이름>`
- **에이전트**: 카드 번호는 연령대와 성별로 풀고, 이름은 입력 검사([[#4.4 입력 검사]])를 통과시킨 뒤, 둘 다 세션 데이터에 적음
- **다음**: 이름이 확정되면 Step 4 선택이 자동으로 시작됨

## 3.4 Step 4. 이야기 진행

- **입력**: 거리마다 `1`, `2`, `3` 중 하나를 골라 총 4회 입력함
- **에이전트**: 도입, 전개, 절정, 마무리 4거리를 차례로 진행함
	- LLM이 현재 거리 방향, 누적 이야기 상태와 앞선 선택을 바탕으로 현재 상황을 짧은 재담으로 담은 박첨지 질문과 그 질문에 답하는 선택지 세 개를 한 번에 생성함. 도입에서는 상황과 동기, 전개와 절정에서는 행동, 마무리에서는 소회와 마무리 발화에 해당하는 선택지를 만듦([[#4.1 질문과 선택지 생성]], [[#4.2 선택지 생성 규칙]])
	- 질문에는 확정된 주인공 이름을 직접 넣고, 이름 뒤 조사는 받침에 맞춰 자동 선택함. 선택지는 이름을 되풀이해야 뜻이 분명할 때만 주인공 이름을 넣음
	- 유효한 번호를 받으면 질문, 제시한 선택지 세 개, 선택 번호와 선택 문안을 선택 이력에 함께 저장함. 선택 결과를 누적 이야기 상태에 반영하고 다음 거리의 질문과 선택지는 확정된 선택만 바탕으로 생성함
	- 이 단계에서는 질문, 선택지와 선택 확인만 출력함. 거리 서사, 낭독 대본, 삽화 프롬프트는 만들거나 출력하지 않음. 결과물 생성은 네 거리의 선택을 모두 받은 뒤 Step 5에서만 시작함
- **다음**: 네 거리의 선택이 끝나면 Step 5로 자동 진입함

## 3.5 Step 5. 결과물 생성

- **입력**: 없음(자동)
- **에이전트**: 이 단계에서 비로소 생성을 시작함
	- **서사 생성 입력**: 배정된 이야기 씨앗의 4거리 방향, 누적 이야기 상태, 주인공 정보, 선택된 사용자 캐릭터 행, 실제 등장한 NPC 행, 설정 제어값, 거리별 런타임 질문, 선택 번호와 선택 문안만 전달함. 고르지 않은 선택지 문안과 의도는 서사 생성 입력에서 제외함
	- **서사 생성**: 네 선택을 한꺼번에 박첨지 화법 서사로 가공하고([[#4. 서사와 문안 규칙]]), 거리마다 낭독 대본을 붙임
	- **비선택 혼입 검사**: 생성이 끝난 뒤 전체 선택 이력과 서사를 별도 대조해 고르지 않은 응답이 주인공의 행동이나 실제 사건으로 들어갔는지 검사함. 혼입됐으면 서사를 다시 생성함
	- **설정 검사**: 선택된 사용자 캐릭터 행과 실제 등장한 NPC 행에 작성된 값, 연령대 제한 및 현재 이야기에 적용되는 제어값을 서사에 다시 대조함. 현재 이야기와 무관한 제어값은 억지로 드러내지 않으며, 적용값을 어기면 서사를 다시 생성함
	- **삽화와 페이지 생성**: 거리마다 삽화 1장씩, 총 4장을 생성할 프롬프트 4개를 조립하고 GPT 이미지 생성 도구로 이미지를 생성함([[#5. 삽화 프롬프트 규약]]). 각 거리의 생성 서사를 텍스트 PNG로 렌더링하고 삽화 PNG와 세로로 합쳐 최종 페이지 PNG 4장을 만듦([[#6. 페이지 이미지 합성]])
- **다음**: Step 6

## 3.6 Step 6. 결과물 감상

- **입력**: `.save`
- **에이전트**: Step 5에서 런 폴더에 저장한 최종 페이지 PNG 4장을 페이지 순으로 보여 줌. `.save`를 받으면 정본 Step 7의 받기 기능을 대신해 런 문서를 작성하고 저장함([[#7. 런 산출물]])
- **다음**: 저장을 마치면 Step 7로 자동 진입함

## 3.7 Step 7. 종료와 리셋

- **입력**: 없음(자동)
- **에이전트**: 박첨지의 마무리 인사를 출력하고 세션 데이터를 비움
- **다음**: `.start`를 기다리는 시작 대기 상태

# 4. 서사와 문안 규칙

콘솔이 출력하는 박첨지 대사, 질문, 서사, 낭독 대본은 사용자가 읽는 콘텐츠 문안임. 위키 문체(음슴체, 개조식)를 적용하지 않고 구어체 재담으로 씀. 본 문서를 포함한 위키 본문은 이 예외 대상이 아님.

## 4.1 질문과 선택지 생성

- **화법**: 박첨지 질문은 떠돌이 노인 해설자의 구어체 재담으로 씀. 능청과 말장난을 살리되 욕설과 비하는 쓰지 않음
- **질문과 선택지 생성 입력**: 마당 유형, 배정된 이야기 씨앗, 현재 거리 방향, 누적 이야기 상태, 주인공 정보, 선택된 사용자 캐릭터 행, 현재 거리에서 등장했거나 등장 가능한 NPC 행, [[3지선다 진행 설정 0918]]의 제어값과 앞선 거리에서 고른 응답만 LLM에 전달함. 앞선 거리에서 고르지 않은 선택지는 전달하지 않음
- **질문 생성**: 현재 거리 방향을 출발점으로 삼되 누적 이야기 상태와 앞선 선택을 우선해 박첨지 질문을 새로 만듦. 씨앗의 표현과 사건을 그대로 되풀이하지 않으며 같은 씨앗으로 다시 시작해도 다른 질문을 만들 수 있음
- **선택지 생성**: 생성한 질문에 직접 답하는 응답 세 개를 같은 호출에서 만듦. 질문과 무관한 선택지, 서로 같은 의도의 선택지와 씨앗의 결말을 강제로 고르는 선택지는 만들지 않음
- **생성 시점**: 현재 거리 진입 때 질문과 선택지 세 개를 한 번 생성함. 유효한 번호를 받을 때까지 같은 질문과 선택지를 유지하며, 입력 오류를 이유로 다시 생성하지 않음
- **표시 범위**: 사용자에게는 질문, 번호와 응답 문안만 보여 줌. 내부 생성 지시, 검사 결과와 선택지 의도는 출력하지 않음

LLM 출력은 먼저 아래 구조로 받아 검사한 뒤 화면 문안으로 바꿈. `type`은 [[3지선다 진행 설정 0918#2. 선택지 유형]]의 주 유형 ID이고, `intent`는 같은 유형 안에서도 선택지 의도를 구별하는 내부 값임. 둘 다 사용자에게 표시하지 않음. 아래 예시는 전개 거리임.

```json
{
  "question": "홍길동이 억울한 사람들을 보았구먼. 이제 어찌하겠는가?",
  "choices": [
    {"id": 1, "type": "SOLVE", "response": "사람들의 증언을 먼저 모은다", "intent": "증거 확보"},
    {"id": 2, "type": "SIDE", "response": "관리 편에 서서 상을 노린다", "intent": "권력자 편들기"},
    {"id": 3, "type": "STIR", "response": "백성과 관리를 말싸움 붙인다", "intent": "갈등 부추김"}
  ]
}
```

## 4.2 선택지 생성 규칙

선택지는 사용자가 현재 질문에 대한 주인공의 응답을 고를 수 있는 문장으로 만듦. 거리 기능과 연령별 수위는 [[3지선다 진행 설정 0918]]을 적용함.

- **개수와 번호**: 항상 세 개를 생성하고 `1`, `2`, `3`을 한 번씩 붙임
- **도입 응답**: 런타임 질문이 묻는 주인공의 상황, 동기나 직전 행동에 답함. 이미 벌어진 일을 묻는 질문이면 그 범위 안에서 과거형 응답을 만듦
- **전개와 절정 응답**: 세 문장 모두 주인공이 직접 말하거나 시작하는 행동으로 씀. 현재 사건을 다음 단계로 밀되 이야기 씨앗의 방향은 약한 가이드로만 사용함
- **절정 종결**: 부추기기, 속이기, 난장, 다른 문제 만들기나 회피를 고르더라도 그 결과로 중심 갈등을 끝내거나 뒤집음. 마무리 뒤까지 이어질 새 중심 사건을 남기지 않음
- **마무리 응답**: 해결된 사건에 대한 소회, 붙일 이름, 남길 말이나 인사를 고르게 함. 새 사건이나 다음 행동을 시작하지 않음
- **이력 반영**: 전개, 절정, 마무리는 앞서 고른 응답의 결과를 이어 받음. 고르지 않은 응답은 다음 선택지와 서사의 사실로 간주하지 않음
- **유형과 단계 유지**: 구체적 사건과 조연은 바꿀 수 있지만 사용자가 고른 마당 유형과 현재 거리의 역할은 바꾸지 않음
- **무작위성**: 같은 이야기 씨앗이라도 질문, 선택지 의도, 사건의 세부와 결말을 고정하지 않음. 앞선 선택으로 생긴 이야기가 씨앗의 거리 방향과 충돌하면 누적 이야기 상태를 우선함
- **차이**: 세 선택지는 말만 바꾼 같은 응답이 아니라 주 유형, 의도와 예상되는 서사가 서로 달라야 함
- **성향 혼합**: 세 선택지는 서로 다른 유형으로 구성함. 도입, 전개와 절정은 `solve_max`와 `complication_min`을 적용하고, 마무리는 자랑, 남 탓, 농담, 후회와 소회 중 서로 다른 세 유형을 사용함([[3지선다 진행 설정 0918#2. 선택지 유형]], [[3지선다 진행 설정 0918#3. 세 선택지 구성]])
- **공정성**: 일부러 실패하거나 아무것도 하지 않는 선택지를 끼워 넣지 않음. 어느 번호를 골라도 이야기로 이어질 만한 선택으로 만듦
- **문안**: 한 문장에 한 응답만 담고 30자 이내를 목표로 함. 결과를 확정하거나 이후 반전을 미리 밝히지 않음
- **안전**: 실명, 실제 정치인과 공공인물, 특정 단체 공격, 노골적 성행위와 잔혹한 상해는 넣지 않음. 관계 일탈, 욕설, 비성적 인형 노출, 잡아먹기와 잡아먹힐 위협은 [[3지선다 진행 설정 0918#4. 연령대 진행 콘셉트]]와 [[3지선다 진행 설정 0918#7. 제어값]]의 연령별 범위 안에서만 사용함

출력 검사기는 생성 입력과 별도로 전체 선택 이력을 받아 아래 조건을 대조함. 생성 LLM에는 앞서 고른 응답만 전달함. 하나라도 어기면 사용자에게 보여 주기 전에 질문과 선택지 묶음을 다시 생성함.

1. `choices`가 정확히 세 개인가
2. `id`가 `1`, `2`, `3`으로 중복 없이 구성됐는가
3. `type`이 설정 문서의 ID 중 서로 다른 세 값이며 `response` 세 문장과 `intent` 세 값이 비어 있지 않고 서로 다른가
4. 도입, 전개와 절정은 `solve_max`와 `complication_min`을 지키고, 마무리는 지정된 종결 유형 세 개를 썼는가
5. 세 응답이 현재 거리의 질문에 직접 답하며 도입, 전개, 절정과 마무리의 응답 성격에 맞는가
6. 앞서 고르지 않은 응답이나 아직 일어나지 않은 결과를 사실처럼 전제하지 않는가
7. 마당 유형과 현재 거리의 역할을 바꾸지 않았는가
8. 안전 규칙을 어기는 표현이 없는가
9. 질문이 현재 상황을 짧은 재담으로 담고 확정된 주인공 이름을 사용하는가
10. 일부러 실패하거나 아무것도 하지 않는 선택지가 없고, 도입과 전개는 다음 사건으로 이어지며 절정은 중심 갈등을 끝내거나 뒤집고 마무리는 이야기를 자연스럽게 닫는가
11. 각 응답이 한 문장이고 30자 이내를 목표로 하며, 결과나 이후 반전을 미리 확정하지 않는가
12. 질문과 선택지에 주인공 이름을 쓴 모든 곳의 조사가 이름 받침에 맞는가

검사 실패 시 사용자에게 보여 주기 전에 질문과 선택지 묶음을 한 차례 다시 생성함. 다시 검사해도 실패하면 자동 재생성을 계속하지 않고 생성 실패로 런을 중단해 관찰 메모에 남김. 그 밖의 서비스 실패 처리는 본 프로토타입의 검증 범위 밖임.

## 4.3 거리별 서사

- **분량**: 거리당 3~5문장(150~250자 잠정). 실제로 읽어 보고 조정함
- **선택 반영**: 각 거리에서 고른 응답이 그 거리의 서사에 반드시 드러나야 함. 주인공 이름과 연령대, 성별을 슬롯으로 반영함
- **설정 반영**: 선택된 사용자 캐릭터 행과 현재 등장한 NPC 행에 입력된 값, 연령대 제한 및 제어값을 적용함. 훈계로 정답을 정하지 않고 선택의 결과를 사건과 웃음으로 회수함
- **비선택 배제**: 같은 거리에서 고르지 않은 두 응답을 주인공이 말하거나 실행한 일처럼 쓰지 않음. 배경 설명에 우연히 같은 소재가 필요하면 선택을 무효화하지 않는 범위에서만 씀
- **절정의 주도권**: 절정은 사용자(주인공)가 주도함. 홍동지가 등장하더라도 사용자를 대신해 해결하지 않음. 아래 조력은 유형을 드러내는 예시일 뿐 고정 사건이 아님

| 마당 유형 | 절정에서 가능한 홍동지 조력 예시 |
| --- | --- |
| 위협-구원형 | 힘으로 맞서는 일을 거들 수 있음 |
| 권력 풍자형 | 조롱으로 허세가 무너지는 일을 거들 수 있음 |
| 위선 폭로형 | 폭로된 위선자를 몰아내는 일을 거들 수 있음 |
| 욕심과 다툼형 | 사용자의 선택이 결말을 가름. 홍동지는 전개에 따라 등장하거나 등장하지 않음 |

## 4.4 입력 검사

이름과 Step 4 선택 번호에 적용함. 기획 정본의 입력 유효성 검증과 AI 가드레일을 간이로 합쳐 아래에 자족적으로 적음.

- **이름**: 20자를 넘거나 비속어, 실명, 실제 정치인과 공공인물, 특정 단체를 가리키는 이름이면 걸린 이유를 알리고 다시 받음. 위반 횟수를 누적해 종료하는 정본 규칙은 재현하지 않음
- **선택 번호**: 현재 선택지가 표시된 동안 선택 입력은 정확히 `1`, `2`, `3` 중 하나만 받음. `.state`와 `.reset`은 명령으로 따로 처리하고, 다른 숫자, 단어, 문장과 빈 입력은 선택으로 저장하지 않음
- **오류 처리**: `1, 2, 3 중 하나를 입력하세요.`라고 알리고 같은 질문과 선택지 세 개를 다시 보여 줌. 선택지는 재생성하지 않음

## 4.5 낭독 대본

- **본문**: 그 거리의 서사 본문을 그대로 씀. 서사와 다른 문장을 새로 쓰지 않음
- **표기 다듬기**: 소리로 들으면 걸리는 표기(숫자, 기호, 괄호)만 말로 풀어 적음
- **연기 지시**: 넣지 않음. 음성 합성의 억양과 속도 조정은 범위 밖임
- **별도 대본을 싣지 않는 경우**: 표기를 다듬은 거리가 없으면 서사 본문으로 대신하고, 거리별 기록 앞에 한 줄로 밝힘
- **별도 대본을 싣는 경우**: 표기를 다듬은 거리만 그 거리의 대본을 따로 실음
- **분리 기준의 이유**: 대본은 표기를 다듬은 자리 말고는 서사와 같아서 전문을 다시 실으면 런 파일 분량만 크게 늘어남

# 5. 삽화 프롬프트 규약

## 5.1 생성 순서와 조립

4거리 서사 생성이 완료되면 Step 5에서 삽화 프롬프트 4개를 일괄 작성함. GPT 이미지 생성 도구로 거리마다 한 장씩, 총 4장을 순차 생성함. 결과를 나란히 제시해 사용자가 인물 일관성을 판정하도록 함.

프롬프트는 네 덩어리로 조립함. 스타일 프리앰블(고정), 캐릭터 시트(세션마다 고정), 장면(페이지마다 교체), 부정 프롬프트(고정)임. 장면을 뺀 세 덩어리를 매 장 똑같이 반복해 붙이는 것이 인물 일관성 전략의 핵심임.

## 5.2 스타일 프리앰블 (고정)

```
A single illustration for a page of a Korean traditional puppet-play storybook (namsadang deolmi / kkokdugaksi).
Style: wooden hand-carved puppet figures on a namsadang booth-curtain (pojangmak) stage, storybook illustration, warm hanji paper texture, obangsaek and dancheong accent colors, expressive and playful, festive folk-theatre mood.
Composition: horizontal landscape 16:9, single wide scene, clear silhouette reading, no panel borders.
```

## 5.3 캐릭터 시트 (세션 고정)

세션의 캐릭터 정보를 슬롯에 채워 매 장 동일하게 반복함. 대괄호는 실제 값으로 치환함.

```
Recurring characters (keep identical in every image of this book):
- HERO: a [character: boy / girl / teenage boy / teenage girl / adult man / adult woman] wooden puppet, Korean hanbok in [fixed color], round cheeks, a small topknot or braid, always the same face and costume.
- BAK CHEOMJI: an old wandering narrator puppet, long white beard, wide-brimmed black hat, plain hemp robe, mischievous grin.
- HONG DONGJI: a strongman puppet with red-painted skin, bald head, [bare torso in adult sessions / short red sleeveless vest in child and teenager sessions], comically powerful build.
```

런타임 전개에서 조연 인형이 삽화 두 장 이상에 등장하면 캐릭터 시트에 `SUPPORTING (this book only, keep identical wherever it appears)` 슬롯으로 더함. [[3지선다 전용 플롯 풀 0918#2. 유형별 방향과 조연]]의 후보 중 실제 이야기 상태에 들어온 인형만 아래 사전에서 골라 슬롯 값으로 붙임.

프롬프트를 조립하기 전에 두 가지를 확인함.

- **등장 인형 확인**: 4장의 장면 슬롯을 먼저 다 적은 뒤, 두 장면 이상에 나오는 조연 인형을 모두 고름. 위협 인형(이시미 등)만 고르고 피해자나 이웃 인형을 빠뜨리지 않음
- **사전 키 대조**: 고른 인형은 아래 사전의 키(대문자 이름)로 캐릭터 시트에 적고, 장면 슬롯에서도 같은 키로 적음. 사전에 없는 인형이면 먼저 사전에 항목을 추가한 뒤 씀

```
Supporting-puppet dictionary (paste only the ones present in this book):
- ISIMI (the monster): a giant coiling serpent-dragon puppet, neither snake nor true dragon, long wooden body with painted obangsaek scales, wide fanged mouth.
- TOHO (the greedy old landlord, 위협-구원형 인간형 위협): a wealthy old landlord puppet, black horsehair gat hat, silk vest over fine hanbok, clutching a rolled land-deed paper, stingy scowling face.
- PYEONGAN GAMSA (the governor): a pompous provincial governor puppet, tall black official hat, embroidered official robe, haughty upturned face.
- IMPOSTER-AUTHORITY (권력 풍자형 변주, this book only): a self-styled authority puppet (fake official, boastful fortune-teller, or pompous rich man), gaudy bright robe, exaggerated dignified pose, comically inflated. Use when the power figure is not the governor.
- SARYEONG (the yamen runner): a yamen runner puppet, headband and short jacket, holding a red signal flag or staff, loud servile face.
- SANGJWA (the errant monk): a young monk puppet, shaved head, grey monk robe, sly hypocritical grin.
- HONGBAEKGA (the two-faced man): a man puppet whose face is split red on one half and white on the other, a two-faced trickster.
- PIJORI (the village girl): a young village-girl puppet, braided hair with a ribbon, plain colorful hanbok.
- MUKDAESA (the true high monk): an old enlightened monk puppet, long grey robe, serene wrinkled face, prayer beads.
- GWIPARI / JAPTAL (commoners): plain village puppets, one with big floppy ears (Gwipari) for the downtrodden. Use these for the unnamed neighbors and kin who quarrel in 욕심과 다툼형.
```

## 5.4 장면 슬롯 (페이지마다 교체)

거리별 서사에서 뽑아 채움. 장면은 사건 하나로 좁히고, 서사 문장을 그대로 옮기지 않음.

```
Scene (this page): [who is present] [doing what] at [where], mood [mood].
```

- **4장 구성**: 도입, 전개, 절정, 마무리 각 거리의 사건을 한 장면으로 압축함. 표지는 만들지 않음(2026-07-28 사용자 결정)

## 5.5 부정 프롬프트 (고정)

```
Avoid: any text or lettering, garbled Hangul, comic sound effects or onomatopoeia text, Japanese Bunraku puppets, Western string marionettes, Disney or anime styling, photorealistic humans, deformed hands and faces, watermark, copyrighted characters.
```

만화 효과음 금지(comic sound effects or onomatopoeia text)는 삽화에 불필요한 글자가 생기는 것을 막기 위해 명시함.

# 6. 페이지 이미지 합성

## 6.1 합성 원칙

페이지 이미지는 AI로 다시 생성하지 않고 삽화 이미지와 텍스트 이미지를 로컬에서 합침. 원본 삽화와 생성 서사, 텍스트 이미지, 최종 페이지 이미지를 각각 보존해 결과를 다시 확인할 수 있게 함.

- **입력**
	- GPT 이미지 생성 도구로 만든 삽화 PNG 1장
	- 해당 거리의 생성 서사를 UTF-8로 저장한 텍스트 파일 1개
- **중간 결과**: 생성 서사를 한글 글꼴로 렌더링한 불투명 배경의 텍스트 PNG 1장
- **최종 결과**: 위쪽에 삽화, 아래쪽에 텍스트 영역을 둔 세로 결합 페이지 PNG 1장. 배치 방향은 모든 페이지에서 고정함
- **반복 단위**: 도입, 전개, 절정, 마무리의 각 거리에 한 번씩 실행해 최종 페이지 PNG 4장을 만듦
- **합성 도구**: `compose-story-page-0918.ps1`. Windows PowerShell과 .NET의 로컬 이미지 처리 기능만 사용하므로 별도 API나 추가 패키지가 필요하지 않음

## 6.2 파일 이름

각 거리의 원본과 중간 결과, 최종 결과를 같은 런 폴더에 저장함. 아래 예시는 도입 거리임.

| 단계 | 파일 이름 | 용도 |
| --- | --- | --- |
| 원본 삽화 | `1_도입_삽화.png` | GPT 이미지 생성 결과 |
| 원본 서사 | `1_도입_서사.txt` | 텍스트 이미지에 넣을 UTF-8 본문 |
| 텍스트 이미지 | `1_도입_텍스트.png` | 생성 서사를 이미지로 렌더링한 중간 결과 |
| 최종 페이지 | `1_도입_페이지.png` | 삽화와 텍스트 이미지를 세로로 합친 결과 |

## 6.3 프로그램 실행

본 프로토타입 폴더를 현재 경로로 연 뒤 거리마다 아래 명령을 실행함. 기본값은 폭 1,600px, 맑은 고딕 42px, 바깥 여백 90px이며 텍스트 높이는 내용에 맞춰 늘어남. 출력 높이는 12,000px, 전체 픽셀은 5,000만 개를 넘지 않도록 제한함.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File ".\compose-story-page-0918.ps1" `
  -IllustrationPath ".\결과물\유람기 3지선다 런 YYYY-MM-DD-N\1_도입_삽화.png" `
  -TextPath ".\결과물\유람기 3지선다 런 YYYY-MM-DD-N\1_도입_서사.txt" `
  -TextImagePath ".\결과물\유람기 3지선다 런 YYYY-MM-DD-N\1_도입_텍스트.png" `
  -OutputPath ".\결과물\유람기 3지선다 런 YYYY-MM-DD-N\1_도입_페이지.png" `
  -Title "도입"
```

프로그램이 성공하면 텍스트 이미지와 최종 페이지 이미지의 절대 경로와 최종 이미지 크기를 출력함. 입력 파일이 없거나 확장자와 실제 형식이 PNG가 아니거나, 본문이 비어 있거나 UTF-8이 아니거나, 지정한 글꼴이 설치되어 있지 않거나, 출력 크기 상한을 넘으면 결과를 만들지 않고 오류를 알림.

# 7. 런 산출물

## 7.1 저장 위치

- **런 문서 경로**: `결과물/유람기 3지선다 런 YYYY-MM-DD-N.md` (같은 날 여러 번 돌리면 N을 올림). `.save`에서 처음 작성해 저장함
- **페이지 파일 경로**: `결과물/유람기 3지선다 런 YYYY-MM-DD-N/`. Step 5에서 이 폴더를 만들고 거리마다 원본 삽화, 원본 서사, 텍스트 이미지, 최종 페이지 이미지를 바로 저장함([[#6.2 파일 이름]]). `.save`는 이미 저장된 페이지 파일을 옮기거나 다시 만들지 않음
- **이미지 삽입**: 거리별 기록에 최종 페이지 이미지(`1_도입_페이지.png`~`4_마무리_페이지.png`)를 단독 배치 `<img src="상대경로" width="500">`로 삽입함. 생성 서사 원문은 이미지 아래에도 텍스트로 남겨 내용 검토와 접근성을 보장함. 삽화 프롬프트 절에는 이미지를 다시 싣지 않고 원본 삽화 경로만 둠. 경로 공백은 `%20`로 인코딩함
- **성격**: 사용자에게 내는 결과물이 아니라 콘솔 검증 기록임

## 7.3 관찰 메모 항목

런이 끝나면 콘텐츠 품질과 결과물 상태를 아래 기준으로 적어 남김. 이 메모는 기획 정본과 원본 마당 플롯 풀의 개정 근거로 씀.

- 선택한 응답이 서사에 실제로 반영됐는가
- 고르지 않은 응답이 주인공의 말이나 행동, 이미 일어난 사건처럼 섞이지 않았는가
- 도입, 전개와 절정의 선택지가 수습과 해결에 쏠리지 않고 서로 다른 유형으로 구성됐는가. 어느 번호도 의도적으로 무의미하거나 즉시 막다른 길인 선택으로 만들지 않았는가
- 선택지가 현재 사건과 앞선 선택을 자연스럽게 이어 갔는가
- 다른 마당 유형으로 돌렸을 때 결과가 확실히 다르게 읽히는가
- 삽화 4장의 주인공이 같은 인물로 보이는가
- 배정된 이야기 씨앗이나 거리 방향 중 서사를 지나치게 고정하거나 망친 항목이 있는가
- 질문과 선택지가 직전 거리까지의 선택과 누적 이야기 상태를 실제로 되받았는가
- 거리 방향을 지나치게 그대로 따라 선택 결과가 무시되지 않았는가. 반대로 마당 유형과 4거리 역할이 사라질 만큼 이탈하지 않았는가
- 같은 이야기 ID를 다시 실행했을 때 질문, 선택지와 결말이 다르게 나올 여지가 있었는가
- 생성된 삽화의 시각적 품질이 전자책에 쓸 수준인가
- 삽화 4장과 텍스트 영역을 합친 페이지 구성이 읽기 쉬운가

첫 런에서는 상태 전이와 입력 처리를 아래 순서로 확인함. 콘텐츠 품질은 [[#7.3 관찰 메모 항목]]에 따로 기록함.

## 8.1 기능 확인

| 상황 | 기대 결과 |
| --- | --- |
| 이름 확정 뒤 Step 4 진입 | 도입 질문과 그 자리에서 생성한 선택지 세 개를 표시함 |
| 같은 이야기 ID, 캐릭터 카드와 이름으로 다시 시작 | `.madang`에 같은 이야기 ID를 입력해 씨앗을 재현해도 저장된 고정 문구를 꺼내지 않고 LLM이 새 질문과 선택지 세 개를 생성함 |
| `1`, `2`, `3` 입력 | 해당 번호와 문안을 선택 이력에 저장하고 다음 거리로 진행함 |
| `0`, `4`, 단어, 문장, 빈 입력 | 선택을 저장하지 않고 같은 질문과 선택지 세 개를 다시 표시함 |
| 전개 이후 선택지 생성 | 앞서 고른 응답만 맥락으로 사용하고 고르지 않은 응답은 전제하지 않음 |
| 네 번째 선택 완료 | 추가 입력 없이 Step 5로 넘어가 네 거리의 결과물을 생성함 |
| `.state` 실행 | 현재 위치와 지금 질문 및 선택지, 확정된 선택 이력을 구분해 표시함 |
