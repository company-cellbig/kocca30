> 유니티 착수 전에 대화 콘솔로 유람기 한 세션을 끝까지 돌려 보는 프로토타입 진행 규약. 사용자가 명령을 입력하면 에이전트가 마당 배정, 박첨지 문답, 서사 생성, 결과물 조립을 대행함. 본 프로토타입의 삽화에 한해 Codex의 GPT 이미지 생성 도구로 직접 생성함. 생성 서사는 로컬 프로그램으로 텍스트 이미지로 변환한 뒤 삽화와 합쳐 최종 페이지 이미지를 만듦. 낭독 음성은 낭독 대본으로 대신함. 검증 대상은 콘텐츠(문답, 서사, 삽화 일관성, 페이지 구성)이고 UI와 지연은 범위 밖임. 기획 정본은 [[덜미 - 나만의 유람기 기획서]].

# 1. 목적과 검증 범위

## 1.1 목적

유니티로 화면을 만들기 전에 콘텐츠 위험을 먼저 해소함. 유람기에서 아직 안 풀린 것은 화면 전환이 아니라 서사가 실제로 재미있게 나오는지임.

- **확인하려는 질문**: 50자짜리 답변 하나가 거리 서사 한 편으로 살아나는가. 마당 유형 4종이 결과물에서 실제로 다르게 읽히는가. 삽화 4장의 주인공이 같은 인물로 보이는가
- **다음 단계 입력**: 콘솔에서 확정한 거리별 질문 문안, 서사 생성 규칙, 삽화 프롬프트를 유니티 구현과 프롬프트 설계의 입력으로 넘김

## 1.2 용어

본 문서가 쓰는 덜미 용어임. 정의 정본은 [[덜미 - 나만의 유람기 기획서#3.12 서사 구조 (규칙과 틀)]]임.

- **마당**: 한 세션이 다루는 극 한 편. 4종 유형(위협-구원형, 권력 풍자형, 위선 폭로형, 욕심과 다툼형) 중 하나로 배정됨
- **거리**: 마당을 이루는 장면 단위. 한 마당은 도입, 전개, 절정, 마무리의 4거리로 이뤄지고, 거리 하나가 전자책 한 페이지가 됨
- **박첨지**: 유람을 이끄는 떠돌이 노인 해설자 인형. 세션 내내 진행을 맡고 거리마다 질문을 던짐
- **홍동지**: 붉은 몸의 힘센 인형. 절정에서 주인공을 거드는 조력자로 등장함
- **마당 조연 인형**: 박첨지와 홍동지 외에 마당 유형마다 원형 거리의 덜미 인형이 조연으로 등장함(예: 위협-구원형의 이시미, 권력 풍자형의 평안 감사). 유형별 배역은 [[마당 플롯 풀#2. 유형별 고정 배역 (원형 거리 인형)]]에서 정함
- **AI 가드레일**: 유저 입력과 생성물의 안전을 검사하는 시스템. 실명이나 실제 인물 풍자 등 차단 항목을 걸러 냄 ([[덜미 - 나만의 유람기 기획서#3.9 AI 가드레일]])

## 1.3 검증 범위

콘솔로 확인할 수 있는 것과 없는 것을 갈라 둠.

**확인함**

- Step 1~7 진행 순서와 상태 전이
- 마당 배정 결과와 거리별 박첨지 질문 문안
- 질문 각색이 문답을 대화로 잇는가(사전 질문 뼈대에 직전 거리까지의 답변을 가미)
- 유저 답변의 서사 반영, 주인공 이름과 캐릭터의 슬롯 반영
- 삽화 프롬프트의 인물 일관성 전략과 전자책 페이지 구성
- 생성된 삽화의 시각적 품질과 인물 일관성(GPT 이미지 생성 도구로 만들고, 두 항목 모두 사용자가 판정함)
- 삽화와 생성 서사를 합친 최종 페이지 이미지의 가독성과 구성

**확인 못 함** (유니티 프로토타입이나 실제 연동에서 따로 봄)

- 화면 타임아웃과 터치 미입력 타임아웃
- Step 5의 생성과 대기 병행, 상태 조회
- 실제 생성 지연과 실패 처리
- 다국어와 AI 가드레일 자동 판정 정확도

## 1.4 기획 정본과 다른 점

프로토타입이라 정본대로 하지 않는 지점임. 결과를 읽을 때 감안함.

- **마당 플롯 검수 상태**: 정본은 사람이 검수해 확정한 풀에서 배정하도록 규정함 ([[덜미 - 나만의 유람기 기획서#3.13 마당 플롯 생성 LLM]]). 콘솔도 유형별 완결 플롯 20개를 사전 생성해 담은 [[마당 플롯 풀]]에서 배정해 정본 방식을 따름. 다만 이 풀은 에이전트가 초안한 것이라 사람 검수가 끝나기 전까지는 잠정임. 배정된 플롯 ID를 런 파일에 남겨 사후 검수를 받음
- **질문 런타임 각색**: 정본은 거리별 사전 질문을 그대로 표시함([[덜미 - 나만의 유람기 기획서#4.4 Step 4. 플롯 문답]], [[마당 플롯 풀#1. 풀 운영 정책]] 사전 고정형). 콘솔은 에이전트가 사전 질문을 뼈대로 직전 거리까지의 유저 답변을 가미해 그 자리에서 각색한 질문을 던짐([[#4.1 박첨지 화법과 질문]]). 정본 반영 여부는 런 결과를 보고 판단함
- **이미지 생성 도구**: 본 콘솔 프로토타입의 삽화에 한해 Codex에서 제공하는 GPT 이미지 생성 도구를 사용함. 이 문서에서는 이를 `GPT 이미지 생성 도구`로 부름. 기획 정본의 이미지 생성 모델 선정에는 영향을 주지 않음
- **실패와 이탈**: 정상 진행만 다룸. 비속어 3회 종료, 생성 실패, 그만두기 같은 분기는 재현하지 않음 ([[덜미 - 나만의 유람기 기획서#5.2 에러 케이스]])

# 2. 진행 규약

## 2.1 역할 대행

정본의 각 시스템을 콘솔에서 무엇으로 대신하는지 정리함.

| 정본 시스템 | 콘솔 처리 |
| --- | --- |
| 세션 데이터 | 에이전트가 대화 안에서 상태로 유지함(필드는 [[#2.4 세션 데이터]]) |
| 마당 플롯 생성 LLM과 배정 | [[마당 플롯 풀]]에서 유저가 고른 유형의 완결 플롯 20개 중 하나를 랜덤 배정함. 콘솔이 그때그때 조합하지 않고 사전 생성한 플롯을 그대로 씀 |
| 거리별 사전 질문 표시 | 에이전트가 사전 질문에 직전 거리까지의 유저 답변을 가미해 각색한 질문을 던짐([[#4.1 박첨지 화법과 질문]]) |
| 진행 호스트(박첨지) | 텍스트 대사만 출력함. 아바타와 음성 합성(TTS) 없음 |
| 입력 유효성 검증과 AI 가드레일 | 에이전트가 간이 판정함([[#4.3 입력 검사]]) |
| 유저 입력 가공 LLM | 에이전트가 거리별 서사를 생성함 |
| 이미지 생성 모델 | 에이전트가 영어 프롬프트를 조립해 GPT 이미지 생성 도구로 16:9 삽화를 직접 생성함. 프롬프트 전문과 생성 이미지 경로는 런 파일에 기록함 |
| 낭독 음성 생성 | 낭독 대본 텍스트로 대신함([[#4.4 낭독 대본]]) |
| 결과물 조립과 호스팅, QR | 로컬 합성 프로그램으로 거리별 페이지 PNG 4장을 만들고 마크다운 전자책 파일과 함께 저장함([[#6. 페이지 이미지 합성]], [[#7. 런 산출물]]). 다운로드 URL과 QR은 만들지 않음 |

## 2.2 콘솔 명령어

명령은 마침표로 시작함. 박첨지 문답 중에는 마침표 없는 입력을 그 거리의 답변으로 받음. 슬래시(`/`)를 쓰지 않는 이유는 Claude Code가 슬래시 입력을 자기 명령어로 가로채기 때문임(2026-07-13 실행 중 확인).

| 명령 | 동작 | 유효 시점 |
| --- | --- | --- |
| `.start` | 세션을 열고 Step 1 인트로를 진행함 | 세션 없음 |
| `.agree` | 이용 조건에 동의하고 Step 2로 감 | Step 1 |
| `.madang <1~4>` | 마당 유형을 고르고 마당 플롯을 배정받음([[#2.3 선택지 번호]]) | Step 2 |
| `.char <1~6>` | 캐릭터 카드를 고름([[#2.3 선택지 번호]]) | Step 3 |
| `.name <이름>` | 주인공 이름을 정함(20자 상한). 같은 Step에서 다시 치면 덮어씀 | Step 3 (카드 선택 뒤) |
| (마침표 없는 입력) | 현재 거리의 답변으로 받음(50자 상한) | Step 4 문답 |
| `.state` | 세션 데이터를 표로 출력함. 세션이 없으면 없다고 알림 | 언제나 |
| `.save` | 이번 런을 파일로 저장하고 Step 7로 넘어감 | Step 6 |
| `.reset` | 세션을 버리고 시작 대기 상태로 돌아감. 저장하지 않은 런이 있으면 한 번 확인함 | 언제나 |

- **유효 시점 밖의 명령**: 실행하지 않고 지금 무엇을 입력해야 하는지 다시 안내함. 없는 명령도 같게 처리함
- **Step 4와 5 진입**: 별도 명령이 없음. 이름이 확정되면 Step 4 문답이 자동으로 시작됨. 문답 도중에는 서사나 삽화를 생성하지 않고, 4거리 답변이 모두 끝나면 Step 5로 자동으로 넘어가 한꺼번에 생성함([[#3.4 Step 4. 플롯 문답]] 문답 중 생성 금지)

## 2.3 선택지 번호

`.madang`이 받는 마당 유형 4종임 ([[덜미 - 나만의 유람기 기획서#3.12 서사 구조 (규칙과 틀)]]).

| 번호 | 1 | 2 | 3 | 4 |
| --- | --- | --- | --- | --- |
| 유형 | 위협-구원형 | 권력 풍자형 | 위선 폭로형 | 욕심과 다툼형 |

`.char`가 받는 캐릭터 카드 6종임 ([[덜미 - 나만의 유람기 기획서#4.3 Step 3. 주인공 설정]]).

| 번호 | 1 | 2 | 3 | 4 | 5 | 6 |
| --- | --- | --- | --- | --- | --- | --- |
| 카드 | 아이 남 | 아이 여 | 청소년 남 | 청소년 여 | 어른 남 | 어른 여 |

## 2.4 세션 데이터

`.state`가 출력하는 필드임. 정본 세션 데이터 표([[덜미 - 나만의 유람기 기획서#3.1 세션 데이터]])에서 콘솔이 실제로 쓰는 항목만 추림.

| 필드 | 값 |
| --- | --- |
| 세션 ID | 세션마다 부여하는 식별자 |
| 언어 | 한국어 고정(다국어는 범위 밖) |
| 현재 Step과 거리 | 진행 위치 |
| 선택 마당 유형 | `.madang` 입력값 |
| 배정 마당 | [[마당 플롯 풀]]에서 배정된 플롯 ID와 4거리(도입, 전개, 절정, 마무리) 사건 |
| 캐릭터 카드 | 연령대와 성별 |
| 주인공 이름 | `.name` 입력값 |
| 거리별 답변 | 거리 순으로 누적한 유저 답변 |

## 2.5 턴 출력 형식

에이전트는 매 턴 맨 위에 상태 한 줄을 두고, 그 아래 박첨지 대사나 시스템 안내를 둠. 지금 어느 Step 어느 거리인지 한눈에 보게 함.

```
[Step 4 | 전개(2/4) | 주인공: 홍길동(어른 남) | 마당: 권력 풍자형]
```

# 3. Step별 진행

정본 [[덜미 - 나만의 유람기 기획서#4. 세션 진행]]의 Step 순서를 그대로 따름.

## 3.1 Step 1. 인트로

- **입력**: `.start` 다음 `.agree`
- **에이전트**: 세션 ID를 부여하고 언어를 한국어로 고정함. 박첨지가 맞이하는 대사와 체험 안내를 출력하고, 이용 조건 요지를 한 문단으로 보여 줌
- **다음**: Step 2

## 3.2 Step 2. 마당 유형 선택

- **입력**: `.madang <1~4>`
- **에이전트**: [[마당 플롯 풀]]에서 유저가 고른 유형의 완결 플롯 20개 중 하나를 랜덤으로 배정함. 플롯은 도입, 전개, 절정, 마무리 4거리의 박첨지 질문과 사건, 조연 인형 배역이 사전에 정해져 있음. 배정된 플롯 ID와 4거리 사건을 화면에 표시하고 런 파일에도 남겨 사후 검수가 가능하게 함
- **다음**: Step 3

## 3.3 Step 3. 주인공 설정

- **입력**: `.char <1~6>` 다음 `.name <이름>`
- **에이전트**: 카드 번호는 연령대와 성별로 풀고, 이름은 입력 검사([[#4.3 입력 검사]])를 통과시킨 뒤, 둘 다 세션 데이터에 적음
- **다음**: 이름이 확정되면 Step 4 문답이 자동으로 시작됨

## 3.4 Step 4. 플롯 문답

- **입력**: 거리별 답변 4회 (마침표 없는 입력)
- **에이전트**: 도입, 전개, 절정, 마무리 4거리를 차례로 진행함. 거리마다 박첨지가 상황을 짧게 재담으로 깔아 질문을 세운 뒤 유저 답변을 받으며, 질문은 배정 플롯의 사전 질문을 각색해 던짐([[#4.1 박첨지 화법과 질문]] 질문 각색). 질문 문안의 `{주인공}` 자리는 유저가 정한 이름으로 치환하고, 뒤따르는 조사는 이름 받침에 맞춰 자동 선택함(은/는, 이/가, 을/를). 답변마다 입력 검사를 적용함
	- **문답 중 생성 금지**: 이 단계에서는 질문과 답변만 주고받음. 답변을 받으면 그 답변으로 거리 서사나 삽화를 만들지 않고 곧장 다음 거리 질문으로 넘어감. 거리 서사와 낭독 대본, 삽화 프롬프트는 한 줄도 출력하지 않음. 생성은 4거리 답변을 모두 받은 뒤 Step 5에서만 함
- **다음**: 4거리 답변이 끝나면 Step 5로 자동 진입함

## 3.5 Step 5. 결과물 생성

- **입력**: 없음(자동)
- **에이전트**: 이 단계에서 비로소 생성을 시작함. 문답에서 모아 둔 4거리 답변 전체를 한꺼번에 박첨지 화법 서사로 가공하고([[#4. 서사와 문안 규칙]]), 거리마다 낭독 대본을 붙임. 이어서 거리마다 삽화 1장씩, 총 4장을 생성할 프롬프트 4개를 조립하고 GPT 이미지 생성 도구로 이미지를 생성함([[#5. 삽화 프롬프트 규약]]). 마지막으로 각 거리의 생성 서사를 텍스트 PNG로 렌더링하고 삽화 PNG와 세로로 합쳐 최종 페이지 PNG 4장을 만듦([[#6. 페이지 이미지 합성]])
- **다음**: Step 6

## 3.6 Step 6. 결과물 감상과 받기

- **입력**: `.save`
- **에이전트**: Step 5에서 런 폴더에 저장한 최종 페이지 PNG 4장을 페이지 순으로 보여 줌. `.save`를 받으면 런 문서만 확정해 저장함([[#7. 런 산출물]])
- **다음**: 저장을 마치면 Step 7로 자동 진입함

## 3.7 Step 7. 종료와 리셋

- **입력**: 없음(자동)
- **에이전트**: 박첨지의 마무리 인사를 출력하고 세션 데이터를 비움
- **다음**: `.start`를 기다리는 시작 대기 상태

# 4. 서사와 문안 규칙

콘솔이 출력하는 박첨지 대사, 질문, 서사, 낭독 대본은 유저가 읽는 콘텐츠 문안임. 위키 문체(음슴체, 개조식)를 적용하지 않고 구어체 재담으로 씀. 본 문서를 포함한 위키 본문은 이 예외 대상이 아님.

## 4.1 박첨지 화법과 질문

- **화법**: 떠돌이 노인 해설자의 구어체 재담. 능청과 말장난을 살리되 욕설과 비하는 쓰지 않음 ([[덜미 - 나만의 유람기 작업노트#2. 설계 근거 (전통 재창조 취사 기준)]])
- **거리별 질문**: 한 거리에 질문 하나. 유저가 사건을 밀고 나가게 하는 열린 질문으로 쓰고, "예"나 "아니요"로 닫히는 질문은 피함. 답변 상한이 50자임을 함께 안내함
- **질문 각색**: 배정 플롯의 사전 질문을 뼈대로 삼고, 직전 거리까지의 유저 답변에서 소재와 말투를 되받아 그 세션만의 질문으로 다듬음. 문답이 정해진 문항 낭독이 아니라 대화로 이어지게 하는 규칙임
	- **뼈대 유지**: 사전 질문이 정한 사건 진행과 묻는 내용은 바꾸지 않음. 답변을 되받는 표현을 더하는 수준으로 각색함
	- **물음의 대상 유지**: 각색해도 주인공이 무엇을 했는지 묻는 틀을 지킴. 유저에게 조연의 대사를 지어내게 하지 않음 ([[마당 플롯 풀#1. 풀 운영 정책]])
	- **도입 거리 예외**: 도입 거리는 앞선 답변이 없으므로 사전 질문을 그대로 씀

## 4.2 거리별 서사

- **분량**: 거리당 3~5문장(150~250자 잠정). 실제로 읽어 보고 조정함
- **입력 반영**: 유저 답변의 내용이 서사에 반드시 드러나야 함. 주인공 이름과 연령대, 성별을 슬롯으로 반영함
- **절정의 주도권**: 절정은 유저(주인공)가 주도함. 홍동지는 거들 뿐 유저를 대신해 해결하지 않음. 조력 방식은 유형마다 다름 ([[덜미 - 나만의 유람기 기획서#3.12 서사 구조 (규칙과 틀)]])

| 마당 유형 | 절정에서 홍동지의 조력 |
| --- | --- |
| 위협-구원형 | 힘으로 함께 처치함 |
| 권력 풍자형 | 조롱으로 허세의 추락을 거듦 |
| 위선 폭로형 | 폭로된 위선자를 쫓아냄 |
| 욕심과 다툼형 | 유저의 선택이 결말을 가름. 홍동지 비중이 낮은 유형이라 조력 변주는 미구체화 ([[마당 사건 풀#4.4 욕심과 다툼형]]) |

## 4.3 입력 검사

이름과 거리별 답변에 적용함. 정본의 입력 유효성 검증과 AI 가드레일을 간이로 합쳐 씀 ([[덜미 - 나만의 유람기 기획서#3.8 입력 유효성 검증]]).

- **길이**: 이름 20자, 답변 50자를 넘으면 다시 받음
- **차단 항목**: 비속어, 실명, 실제 정치인과 공공인물, 특정 단체 풍자, 처첩 삼각관계
- **위반 처리**: 무엇이 걸렸는지 알리고 다시 받음. 횟수를 누적해 종료하는 정본 규칙은 재현하지 않음([[#1.4 기획 정본과 다른 점]])

## 4.4 낭독 대본

- **본문**: 그 거리의 서사 본문을 그대로 씀. 서사와 다른 문장을 새로 쓰지 않음
- **표기 다듬기**: 소리로 들으면 걸리는 표기(숫자, 기호, 괄호)만 말로 풀어 적음
- **연기 지시**: 넣지 않음. 음성 합성의 억양과 속도 조정은 범위 밖임
- **런 파일 게재**: 표기를 다듬은 거리가 없으면 대본을 따로 싣지 않고 서사 본문으로 대신하며, 대신했다는 것을 거리별 기록 앞에 한 줄로 밝힘. 표기를 다듬은 거리만 그 거리의 대본을 따로 실음. 대본은 다듬은 자리 말고는 서사와 같은 텍스트라, 전문을 다시 실으면 런 파일 분량만 크게 늘기 때문임 ([[유람기 런 2026-07-13-1#5.1 규약 결함 (반영 필요)]] 3)

# 5. 삽화 프롬프트 규약

## 5.1 생성 순서와 조립

4거리 서사 생성이 완료된 뒤 Step 5에서 거리마다 삽화 1장씩, 총 4장을 생성할 프롬프트 4개를 일괄 작성하고, GPT 이미지 생성 도구로 이미지를 한 장씩 순차 생성함. 생성 결과를 나란히 제시해 사용자가 인물 일관성을 판정하도록 함.

프롬프트는 네 덩어리로 조립함. 스타일 프리앰블(고정), 캐릭터 시트(세션마다 고정), 장면(페이지마다 교체), 부정 프롬프트(고정)임. 장면을 뺀 세 덩어리를 매 장 똑같이 반복해 붙이는 것이 인물 일관성 전략의 핵심임.

## 5.2 스타일 프리앰블 (고정)

```
A single illustration for a page of a Korean traditional puppet-play storybook (namsadang deolmi / kkokdugaksi).
Style: wooden hand-carved puppet figures on a namsadang booth-curtain (pojangmak) stage, storybook illustration, warm hanji paper texture, obangsaek and dancheong accent colors, expressive and playful, festive folk-theatre mood.
Composition: horizontal landscape 16:9, single wide scene, clear silhouette reading, no panel borders.
```

## 5.3 캐릭터 시트 (세션 고정)

세션의 캐릭터 정보를 슬롯에 채워 매 장 동일하게 반복함. 대괄호는 실제 값으로 치환함.

```
Recurring characters (keep identical in every image of this book):
- HERO: a [age: child / teenager / adult] [gender: boy or man / girl or woman] wooden puppet, Korean hanbok in [fixed color], round cheeks, a small topknot or braid, always the same face and costume.
- BAK CHEOMJI: an old wandering narrator puppet, long white beard, wide-brimmed black hat, plain hemp robe, mischievous grin.
- HONG DONGJI: a red-bodied strongman puppet, bald head, bare torso, comically powerful build.
```

배정 마당의 조연 인형이 삽화 두 장 이상에 등장하면 캐릭터 시트에 `SUPPORTING (this book only, keep identical wherever it appears)` 슬롯으로 더함. 첫 런에서 드러난 조연 일관성 결함을 보강한 것임 ([[유람기 런 2026-07-13-1#5.1 규약 결함 (반영 필요)]] 1). 조연 배역은 유형별로 [[마당 플롯 풀#2. 유형별 고정 배역 (원형 거리 인형)]]에서 정하고, 이 전자책에 등장하는 인형만 아래 사전에서 골라 슬롯 값으로 붙임.

프롬프트를 조립하기 전에 두 가지를 확인함 ([[유람기 런 2026-07-21-1#5.1 규약 결함 (반영 필요)]] 1).

- **등장 인형 확인**: 4장의 장면 슬롯을 먼저 다 적은 뒤, 두 장면 이상에 나오는 조연 인형을 모두 고름. 위협 인형(이시미 등)만 보고 피해자나 이웃 인형을 빠뜨리지 않음
- **사전 키 대조**: 고른 인형은 아래 사전의 키(대문자 이름)로 캐릭터 시트에 적고, 장면 슬롯에서도 같은 키로 적음. 사전에 없는 인형이면 먼저 사전에 항목을 추가한 뒤 씀

```
Supporting-puppet dictionary (paste only the ones present in this book):
- ISIMI (the monster): a giant coiling serpent-dragon puppet, neither snake nor true dragon, long wooden body with painted obangsaek scales, wide fanged mouth.
- TOHO (the greedy old landlord, 위협-구원형 인간형 위협): a wealthy old landlord puppet, black horsehair gat hat, silk vest over fine hanbok, clutching a rolled land-deed paper, stingy scowling face.
- PYEONGAN GAMSA (the governor): a pompous provincial governor puppet, tall black official hat, embroidered official robe, haughty upturned face.
- IMPOSTER-AUTHORITY (권력 풍자형 변주, this book only): a self-styled authority puppet (fake official, boastful fortune-teller, or pompous rich man), gaudy bright robe, exaggerated dignified pose, comically inflated. Use when the power figure is not the governor.
- SARYEONG (the yamen runner): a yamen runner puppet, headband and short jacket, holding a red signal flag or staff, loud servile face.
- SANGJWA (the errant monk): a young monk puppet, shaved head, grey monk robe, sly hypocritical grin.
- HONGBAEKGA (the two-faced man): a man puppet whose face is split red on one half and white on the other, a two-faced trickster.
- PIJORI (the village girl): a young village-girl puppet, braided hair with a ribbon, plain colorful hanbok.
- MUKDAESA (the true high monk): an old enlightened monk puppet, long grey robe, serene wrinkled face, prayer beads.
- GWIPARI / JAPTAL (commoners): plain village puppets, one with big floppy ears (Gwipari) for the downtrodden. Use these for the unnamed neighbors and kin who quarrel in 욕심과 다툼형.
```

## 5.4 장면 슬롯 (페이지마다 교체)

거리별 서사에서 뽑아 채움. 장면은 사건 하나로 좁히고, 서사 문장을 그대로 옮기지 않음.

```
Scene (this page): [who is present] [doing what] at [where], mood [mood].
```

- **4장 구성**: 도입, 전개, 절정, 마무리 각 거리의 사건을 한 장면으로 압축함. 표지는 만들지 않음(2026-07-28 사용자 결정)

## 5.5 부정 프롬프트 (고정)

```
Avoid: any text or lettering, garbled Hangul, comic sound effects or onomatopoeia text, Japanese Bunraku puppets, Western string marionettes, Disney or anime styling, photorealistic humans, deformed hands and faces, watermark, copyrighted characters.
```

만화 효과음 금지(comic sound effects or onomatopoeia text)는 2026-07-28-3 런에서 "whack" 의성어가 그려진 위반이 나와 명시함 ([[유람기 런 2026-07-28-3#5.2 콘텐츠 관찰]]).

# 6. 페이지 이미지 합성

## 6.1 합성 원칙

페이지 이미지는 AI로 다시 생성하지 않고 삽화 이미지와 텍스트 이미지를 로컬에서 합침. 원본 삽화와 생성 서사, 텍스트 이미지, 최종 페이지 이미지를 각각 보존해 결과를 다시 확인할 수 있게 함.

- **입력**
	- GPT 이미지 생성 도구로 만든 삽화 PNG 1장
	- 해당 거리의 생성 서사를 UTF-8로 저장한 텍스트 파일 1개
- **중간 결과**: 생성 서사를 한글 글꼴로 렌더링한 불투명 배경의 텍스트 PNG 1장
- **최종 결과**: 위쪽에 삽화, 아래쪽에 텍스트 영역을 둔 세로 결합 페이지 PNG 1장. 배치 방향은 모든 페이지에서 고정함
- **반복 단위**: 도입, 전개, 절정, 마무리의 각 거리에 한 번씩 실행해 최종 페이지 PNG 4장을 만듦
- **합성 도구**: `prototype/덜미-나만의유람기/compose-story-page.ps1`. Windows PowerShell과 .NET의 로컬 이미지 처리 기능만 사용하므로 별도 API나 추가 패키지가 필요하지 않음

## 6.2 파일 이름

각 거리의 원본과 중간 결과, 최종 결과를 같은 런 폴더에 저장함. 아래 예시는 도입 거리임.

| 단계 | 파일 이름 | 용도 |
| --- | --- | --- |
| 원본 삽화 | `1_도입_삽화.png` | GPT 이미지 생성 결과 |
| 원본 서사 | `1_도입_서사.txt` | 텍스트 이미지에 넣을 UTF-8 본문 |
| 텍스트 이미지 | `1_도입_텍스트.png` | 생성 서사를 이미지로 렌더링한 중간 결과 |
| 최종 페이지 | `1_도입_페이지.png` | 삽화와 텍스트 이미지를 세로로 합친 결과 |

## 6.3 프로그램 실행

저장소 루트에서 거리마다 아래 명령을 실행함. 기본값은 폭 1,600px, 맑은 고딕 42px, 바깥 여백 90px이며 텍스트 높이는 내용에 맞춰 늘어남. 출력 높이는 12,000px, 전체 픽셀은 5,000만 개를 넘지 않도록 제한함.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File ".\prototype\덜미-나만의유람기\compose-story-page.ps1" `
  -IllustrationPath ".\prototype\덜미-나만의유람기\결과물\유람기 런 YYYY-MM-DD-N\1_도입_삽화.png" `
  -TextPath ".\prototype\덜미-나만의유람기\결과물\유람기 런 YYYY-MM-DD-N\1_도입_서사.txt" `
  -TextImagePath ".\prototype\덜미-나만의유람기\결과물\유람기 런 YYYY-MM-DD-N\1_도입_텍스트.png" `
  -OutputPath ".\prototype\덜미-나만의유람기\결과물\유람기 런 YYYY-MM-DD-N\1_도입_페이지.png" `
  -Title "도입"
```

프로그램이 성공하면 텍스트 이미지와 최종 페이지 이미지의 절대 경로와 최종 이미지 크기를 출력함. 입력 파일이 없거나 확장자와 실제 형식이 PNG가 아니거나, 본문이 비어 있거나 UTF-8이 아니거나, 지정한 글꼴이 설치되어 있지 않거나, 출력 크기 상한을 넘으면 결과를 만들지 않고 오류를 알림.

# 7. 런 산출물

## 7.1 저장 위치

- **경로**: `prototype/덜미-나만의유람기/결과물/유람기 런 YYYY-MM-DD-N.md` (같은 날 여러 번 돌리면 N을 올림)
- **페이지 파일 경로**: `prototype/덜미-나만의유람기/결과물/유람기 런 YYYY-MM-DD-N/`. Step 5에서 이 폴더를 만들고 거리마다 원본 삽화, 원본 서사, 텍스트 이미지, 최종 페이지 이미지를 바로 저장함([[#6.2 파일 이름]]). `.save`는 이미 저장된 페이지 파일을 옮기거나 다시 만들지 않음
- **이미지 삽입**: 거리별 기록에 최종 페이지 이미지(`1_도입_페이지.png`~`4_마무리_페이지.png`)를 단독 배치 `<img src="상대경로" width="500">`로 삽입함. 생성 서사 원문은 이미지 아래에도 텍스트로 남겨 내용 검토와 접근성을 보장함. 삽화 프롬프트 절에는 이미지를 다시 싣지 않고 원본 삽화 경로만 둠. 경로 공백은 `%20`로 인코딩함([[CONVENTIONS#3.5 Wikilink 규칙]] 이미지 삽입)
- **성격**: `type: agentnote`. 사용자에게 내는 결과물이 아니라 검증 기록이라 `04_Projects/` 밖에 둠 ([[CONVENTIONS#2. 디렉토리 구조]])

## 7.2 파일 구성

| 절 | 담는 것 |
| --- | --- |
| 세션 데이터 | 세션 ID, 언어, 주인공 이름, 캐릭터 카드, 선택 마당 유형, 배정 플롯, 완주 여부. 진행 중에만 쓰는 "현재 Step과 거리"는 넣지 않고, 거리별 답변은 아래 거리별 기록에서 다룸([[#2.4 세션 데이터]]) |
| 배정 마당 | [[마당 플롯 풀]]에서 배정된 플롯 ID와 4거리 사건, 조연 인형 배역 |
| 거리별 기록 | 거리마다 박첨지 질문(각색해 실제로 던진 문안), 유저 답변, 최종 페이지 이미지, 생성 서사 원문. 이미지 삽입은 [[#7.1 저장 위치]]를 따름. 낭독 대본은 표기를 다듬은 거리만 실음([[#4.4 낭독 대본]]) |
| 삽화 프롬프트 | 거리마다 1개씩, 총 4개의 완성 프롬프트 전문과 원본 삽화 경로. 최종 페이지 이미지 삽입은 거리별 기록이 맡음 |
| 관찰 메모 | 이번 런에서 본 문제와 다음 런에서 바꿀 것([[#7.3 관찰 메모 항목]]) |

## 7.3 관찰 메모 항목

런이 끝나면 아래를 적어 남김. 이 메모가 쌓여 기획서와 [[마당 플롯 풀]]의 개정 근거가 됨. 배정 플롯의 질문이나 배역, 절정 결함은 [[마당 플롯 풀]]로 되돌리고, 시드 수준(사건 유형 자체)의 문제만 [[마당 사건 풀]]로 되돌림.

- 답변이 서사에 실제로 반영됐는가, 아니면 답변과 무관한 이야기가 됐는가
- 질문이 답하기 쉬웠는가. 50자로 답할 수 있는 질문이었는가
- 다른 마당 유형으로 돌렸을 때 결과가 확실히 다르게 읽히는가
- 삽화 4장의 주인공이 같은 인물로 보이는가
- 배정 플롯의 질문이나 사건 중 서사를 망친 항목이 있는가
- 질문 각색이 직전 거리까지의 답변을 실제로 되받았는가. 각색이 사전 질문의 사건 진행을 흐트러뜨리지 않았는가
