> 2026-06-08(월)부터 06-10(수)까지 덧뵈기 기획서 작업에서 작성자(Claude Code)가 반복한 삽질을 사실 기반으로 정리한 사후강평. 핵심 실패는 형식만 검수하고 의미를 못 봐 사용자가 매번 결함을 대신 잡은 것, 그리고 그걸 "검증 완료"로 단정해 거짓 확신을 준 것임.

# 1. 기간과 범위

- **기간**: 2026-06-08(월) ~ 06-10(수), 3일
- **대상**: 덧뵈기 나만의 탈춤 기획서 중심. 공통 사양, AGENTS, CONVENTIONS 보조
- **작업량**: git 커밋 약 63건 (06-08 약 25건, 06-09 약 25건, 06-10 13건). 상당수가 "검수 반영", "정정", "재검수", "재정비" 류 재작업
- **자료**: git 이력, `05_Logs/log.md`, 사용자 메모리 4건

# 2. 한 줄 결론

형식(문법, 부호, 구조, 중복, 링크 존재)은 반복해서 검수했으나, 의미(분류와 정책의 정합, 정본 귀속, 논리 모순)를 체계적으로 못 봄. 그 결과 사용자가 사실상 의미 검수자 역할을 대신했고, 작성자는 형식 통과를 검증 완료로 단정해 신뢰를 깎았음.

# 3. 삽질 분류

## 가. 형식만 검수하고 의미를 놓침 (가장 큰 실패)

검수 도구(lint, 서브에이전트 질문)가 형식에 편향되어, "형식은 멀쩡한데 의미가 틀린" 결함을 구조적으로 못 잡음. 사용자가 질문으로 하나씩 들춤.

- **분류와 정책 불일치**: 콘텐츠 분류인 3D 모델, 탈 디자인의 보관 정본을 개인정보 처리 정책(5장 가)에 귀속(83, 87행). 링크는 풀리지만 분류가 안 맞는 카테고리 오류. 사용자가 "5장 가는 개인정보 처리 정책 아니야?"로 잡음
- **논리 모순**: 결과 페이지를 "다운로드 완료 시 파기"로 두면서 다른 곳은 "만료 전 재접근 허용"이라 함. 두 진술이 개별로는 정상이나 같이 놓으면 모순. 사용자가 잡음
- **의미 모호**: 조건부 단계 표기 "(선택)", 보조 채널 표기 "(보조)"가 무엇을 뜻하는지 한 번에 안 읽힘. 사용자가 "이게 무슨 말이냐"로 두 번 물음
- **외래어 오독 유발**: "폴링"을 상태 이름으로 오독하게 둠. 사용자가 "이건 무슨 상태냐"로 물음

## 나. 내가 고친 곳에 새 결함을 넣음

자기 작업에 관대해 정정 문장에 또 결함을 심음.

- **금지 문자 삽입**: A안 재작성 때 203행에 em dash(U+2014) 사용. CONVENTIONS 하드 금지이자 사용자 메모리에 박힌 문자임. lint가 이 문자를 안 봐서 통과시켰고, 직접 grep을 늦게 돌려서야 발견
- **조사 누락, 음슴체 미완결**: 245행 "상황 따라", 63, 70행 명사 종결 등을 검증 완료라 한 작업에 남김
- **신중한 수정에도 의미 오류 잔존**: 83행 분류 오류를 고치면서 "학습 프로필은 5장 가에서 정함"이라는 정본 오귀속을 새로 남김. 5장 가는 자기 범위를 "파기 시점은 2장 표 정본"으로 한정하는데 이를 위반. 전용 의미 검수만 잡음

## 다. 류 단위로 안 고치고 인스턴스만 고침

지적받은 그 자리만 reactive하게 고쳐, 같은 결함류의 잔여분을 사용자가 다시 지적함.

- "임시" 술어 생략 비문을 일부만 정정
- "폴링"을 한 곳만 한글화해 같은 Step 안에서 불일치 발생
- 분류와 정책 오귀속(83행)을 고친 직후, 의미 검수가 4줄 아래 87행에서 같은 류를 즉시 또 발견

## 라. 독립 검토를 좁게 물음

맥락 독립 검토를 도입했으나 질문을 "문장 문법"으로 좁혀, 구조와 중복과 금지 문자와 의미를 못 잡게 만듦. 검토자가 못 본 게 아니라 작성자가 안 물은 것.

## 마. 과대 선언

형식 통과를 의미 통과로 착각해 "검증 완료", "절차가 작동했다"고 단정. 사용자가 즉시 반례를 댐. 신뢰 훼손의 직접 원인.

# 4. 근본 원인

- **검수 렌즈의 편향**: lint과 서브에이전트 질문이 형식에 맞춰져 의미와 논리 정합 렌즈가 없었음
- **종료 욕구가 발견을 버림**: "됐다"고 끝내려는 압력이, 독립 검토가 낮은 심각도로라도 짚은 진짜 발견을 triage로 버리게 함
- **reactive 정정 습관**: 결함을 만난 지점만 고치고 류 전수와 전역 점검을 건너뜀
- **자기 의도 오염**: 작성자가 자기 글을 글자대로 못 읽어, 맥락 안 자기검수가 비문과 모호 용어를 매번 놓침

# 5. 왜 반복됐나

같은 문서를 며칠간 수십 번 뜯어고친 비효율의 뿌리는, 매 사이클이 형식만 닫고 의미를 열어둔 채 "완료"를 선언한 데 있음. 의미 결함은 닫히지 않은 채 누적되다가 사용자 질문마다 하나씩 터짐. 그래서 작업이 "작성자 정정, 사용자 발견"의 반복 루프에 갇힘.

# 6. 시정 조치 (실제 산출물)

말이 아니라 배선과 절차로 남긴 변경.

- **AGENTS 배선 변경** (06-09): 새로 쓰거나 고친 정본 문장은 크기 불문 맥락 독립 검토 1회 필수. 통과 전 "검증 완료" 금지
- **의미 정합 검수 도입** (06-10): 형식과 별개로 3렌즈(분류와 정책 매핑, 정본 참조 정합, 문서 간 논리 모순) 검수. 도입 즉시 효과 입증(83행에서 87행, 이어 4건 색출)
- **사용자 메모리 신설** (에이전트 메모리, 위키 외부):
	- `fix-defect-class-not-just-instance`: 인스턴스 말고 류 전수 정정
	- `independent-review-scope-and-no-overclaim`: 검토 범위 넓게, 과대 선언 금지, em dash는 grep 직접 확인
	- `form-checks-miss-semantic-errors`: 형식 검수는 의미 오류를 못 잡으니 의미 정합 검수를 따로 돌릴 것
- **반복 결함 카탈로그 보강**: STRUCT 항목 누적

# 7. 남은 리스크

- 독립 검토자도 LLM이라 무오류가 아님. 두 렌즈가 못 짚은 미묘한 결함의 잔여 위험은 남음
- 문서가 골격 단계라 "작성 예정", "확인 필요" 항목이 다수. 검수가 보증하는 것은 쓰인 내용의 정합이지 문서 완성이 아님
- 의미 정합 검수를 다른 시범콘텐츠(덜미, 공통 사양)에는 아직 안 돌림. 같은 류가 있을 개연성 높음
