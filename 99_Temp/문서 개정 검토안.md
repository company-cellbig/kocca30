> 결함 16건은 규칙이 모자라서 통과한 것이 아니라, 규칙 준수를 작성자 자기보고로 확인하기 때문에 통과했음. 개입 12건을 기계 검사 이관(MECH), 작성 절차 변경(FLOW), 규칙 감량(SLIM)으로 나눠 제안함.

# 1. 배경과 범위

이틀 동안 같은 문서를 반복 수정하며 결함 16건이 나왔고, 전부 자동 검사 3종(`wiki_lint`, `wiki_number`, `quote_check`)을 통과한 상태였음. 발견 경로는 사용자 10건, 외부 AI 5건, 작성자 자기검수 1건.

본 문서는 [[CONVENTIONS|위키 작성 규칙]]과 [[AGENTS|에이전트 작업 지침]]을 결함 16건에 비추어 점검하고 개정안을 제시함. 개정 대상은 두 정본 문서와 `scripts/` 검사기임.

**본 문서의 근거 표기 규약**: 규칙 문서의 결함을 지적할 때마다 파일명과 절 번호를 함께 적음. 근거를 찾을 수 없는 지적은 넣지 않음.

**헤딩 번호 없음**: [[CONVENTIONS#4.3 번호 자동 부여]]에 따라 번호를 손으로 붙이지 않았음. 저장소에 넣은 뒤 `node scripts/wiki_number.mjs --write`로 부여할 것.

# 2. 진단

## 2.1 결론

문서 안에 이미 답이 있음. [[CONVENTIONS#3.5 Wikilink 규칙]] 이미지 경로 항목에 이렇게 적혀 있음.

> 경로 검증은 기계가 함. 2026-07-22부터 2026-08-20까지는 "작성자가 직접 확인함"으로 두었는데 한 번도 확인하지 않았고, 그 사이 폴더 이동으로 깨진 경로 32건이 하루 넘게 방치됐음. 자기보고를 검사로 옮긴 자리임.

이 원칙이 이미지 경로 한 곳에만 적용됐음. 나머지 규칙 대부분은 여전히 "작성자가 직접 확인함" 상태이고, 결함 16건은 그 자리에서 나왔음. 따라서 개정 방향은 **규칙 추가가 아니라 기존 원칙의 전면 적용**임.

## 2.2 규칙 문서 자체의 결함 (증거)

위키에서 가장 자주 읽히고 가장 많이 검토됐을 두 정본 문서에 결함이 남아 있음. 전부 유형 B(본문 수정 후 파생 텍스트 미동기)에 해당함. 사람이 확인하는 항목의 실효를 보여주는 직접 증거임.

- **`updated` 필드가 stale**:
	- 실태: [[CONVENTIONS]]는 `updated: 2026-07-24`인데 본문에 2026-08-19 폴더 신설(2. 디렉토리 구조), 2026-08-20 lint 이관(3.5)이 기재돼 있음. [[AGENTS]]는 `updated: 2026-06-30`인데 본문에 2026-08-19(2.9), 2026-08-20(2.2.1) 변경이 네 군데 있음
	- 무게: [[AGENTS#2.2.1 작성자]] 셀프체크에 "frontmatter `updated` 필드가 오늘 날짜와 일치하는가"가 있음. **체크리스트를 담은 문서가 그 체크리스트 항목에서 실패했음**
	- 대응: MECH-1
- **폐기된 용어가 살아남음**:
	- 실태: [[CONVENTIONS#4.2 헤딩 넘버링]]이 "옛 `한국 공문서 넘버링`(`가.` `1)` `가)`)은 2026-07-14에 폐기함"이라 선언했으나, 5.1의 4번은 "`한국 공문서 넘버링` 적용 ([[CONVENTIONS#4. 헤딩 / 넘버링]] 나)"로 남아 있음. 문서 생성 절차가 폐기된 규칙을 지시하고 있고, 괄호 안 "나)"는 `§` 표기 폐지 이전 잔재임. 7. 로그 항목 양식의 양식 규칙에도 같은 용어가 남음
	- 무게: 폐기 선언과 잔존 표현이 한 문서 안에 공존함. 오염 전파의 표본임
	- 대응: MECH-2
- **anchor가 상위 절로 뭉개짐**:
	- 실태: [[AGENTS#3.3 외부 검토자 호출]] 마지막 불릿이 "작성자 4단계 흐름 `[[#2. 에이전트 작업 지침]]`"이라 쓰는데 실제 대상은 2.2.1임. 2.4.1도 "작은 변경 면제 `[[#3. 검수 기준과 호출 방식]]`"이라 쓰는데 정의는 2.4.3에 있음(두 군데)
	- 무게: `wiki_lint`는 헤딩 존재만 보므로 통과함. **anchor 검사가 "유효한 링크"와 "맞는 링크"를 구분하지 못함**
	- 대응: 기계 판정 불가 영역. FLOW-2의 독립 검토가 맡음
- **비문과 표기 불일치**:
	- 실태: [[CONVENTIONS#3.1 파일명]]의 "공백 대신 언더스코어(`_`) 사용 금지: Obsidian은 공백 허용"은 두 번 읽어야 뜻이 잡힘. 3.2 type 표 `overview` 행의 "(`[[CONVENTIONS#3.9 Overview(종합) 페이지]]` 페이지)"는 별칭 처리 실패(당시 anchor 표기, 그 절은 2026-08-21에 [[위키 운영 워크플로]]로 이관됨). 3.2 `sources` 예시 `[1. 연구개발의 필요성]`은 wikilink 이중 대괄호가 아닌 단일 대괄호임
	- 무게: [[CONVENTIONS#3.4.2 쉽게 쓰기]]의 "한 가지 뜻으로만 읽히게 씀"에 걸림
	- 대응: 개정 시 직접 정정
- **같은 규칙이 두 곳에 기재됨**:
	- 실태: 링크 하한선이 [[CONVENTIONS#1. 핵심 원칙]] 6번과 3.5에, 작은 변경 면제 조건이 [[AGENTS#2.4.3 작은 변경 사이클 면제 (엄격)]]와 3.3에 각각 중복 기재됨
	- 무게: 규칙 문서가 단일 정본 원칙을 어기면 파생 텍스트 미동기가 규칙에서부터 시작됨
	- 대응: SLIM-2

## 2.3 결함군별 구멍의 위치

### 2.3.1 유형 A: 원전 사실 왜곡 6건

- **3.6이 원전 서사에 걸리지 않음**: [[CONVENTIONS#3.6 수치/목표 인용 원칙 (엄격)]]의 대상 항목은 정량 지표, 목표 진술, 일정과 기한, 조직 정보, 산출물 명세 다섯 가지임. **원전의 사건 진행, 순서, 결말, 승패가 이 목록에 없음.** 이 절은 RFP와 사업 수치를 겨냥해 만들어졌고 전사본 서사는 대상이 아님. 그래서 "원문 미명시" 표기 의무도 출처 wikilink 의무도 A형 6건에 걸리지 않았음. `quote_check.mjs`는 따옴표와 행번호가 붙은 인용만 보고, A형은 인용이 아니라 요약과 서술이라 기계도 못 봤음. **엄격 인용 원칙과 자동 검사 사이로 빠져나간 자리임** (대응: MECH-3)
- **3.8.2가 사후 점검 자리에 놓임**: `[[CONVENTIONS#3.8.2 사실 층과 설계 층의 도출 경계]]`(2026-08-21에 삭제된 절)의 내용은 정확함. 문제는 배치임. [[AGENTS#2.2.1 작성자]]의 4단계 흐름에서 1단계가 "구조 설계 선행"이고 `[재료 선행]` 점검은 3단계 자기검수의 체크 항목임. 틀을 먼저 세워 쓴 다음에 "틀에서 역산하지 않았는가"를 스스로 묻는 구조라, 이미 왜곡된 뒤에 왜곡한 당사자가 점검하게 됨. **작성 순서의 문제를 사후 체크리스트로 옮기면 무력화됨** (대응: FLOW-1)
- **두 규칙이 정면으로 충돌함**: [[CONVENTIONS#3.8.1 작성 전 절차]] 3번 "목차 먼저 설계"와 3.8.2 "틀을 먼저 세우면 왜곡됨"이 부딪침. 3.8.2가 "형식의 설계이지 내용의 선결정이 아님"으로 봉합하나, 이는 쓰는 동안 머릿속에서 유지해야 하는 구분이라 압력이 걸리면 무너짐. 충돌하는 쪽이 볼드로 1단계에 있고 교정하는 쪽은 다른 문서 H3 아래 하위 절에 있어, **눈에 띄는 정도가 우선순위와 반대임** (대응: FLOW-1, FLOW-3)
- **병렬 구조에 명시적 우선권이 부여돼 있음**: `[[CONVENTIONS#3.8.7 목록 형식 선택과 라벨형, 중첩 블릿 규칙]]`(당시 위치, 현 [[문서 작성 세부 규칙]]) 다) 마지막 줄이 "항목별 최적화보다 묶음 병렬성 우선"이라 못박음. 문서 어디에도 "사실이 형식보다 우선"이라는 선언은 없는데 "병렬성이 우선"이라는 선언은 있음. 3칸 틀의 빈칸을 창작으로 채운 결함에 규칙이 알리바이를 제공한 셈임. [[CONVENTIONS#3.7 외부 근거의 권위 계층]]은 근거 등급 사이의 순서일 뿐 규칙 사이의 순서가 아님 (대응: FLOW-3)

### 2.3.2 유형 B: 본문 수정 후 이름표와 요약 미동기 7건

- **5.2에 파생 텍스트 동반 갱신 단계가 없음**: [[CONVENTIONS#5.2 문서 갱신 시]]는 다섯 단계인데, 파생 텍스트를 다루는 것은 4번의 "헤딩 추가/삭제 시 후속 번호 재조정 + 다른 문서 anchor 갱신"뿐임. 그런데 그것은 이미 `wiki_number.mjs`가 자동으로 하는 일임. **정작 사람만 할 수 있는 일(본문을 고쳤으면 그 절의 제목, 라벨, 표 셀, TL;DR, MOC 요약도 다시 볼 것)이 절차에 없음.** 기계가 하는 것을 절차에 적고 기계가 못 하는 것을 빠뜨렸음 (대응: MECH-4, FLOW-4)
- **제목이 사실을 주장할 수 있음**: "그 인물이 이기는 방식"처럼 절 제목이 승패와 인과를 담으면 제목이 틀릴 수 있게 됨. [[CONVENTIONS#4.1 헤딩 레벨 사용 규칙]]에 제목의 기능 제한이 없음 (대응: MECH-5)
- **용어의 단일 정의처가 없음**: 3.4.2에 약어 병기 규칙은 있으나 용어를 한 곳에서만 정의하고 나머지가 참조하게 하는 구조가 없음. 한 용어를 네 곳에서 다르게 부른 결함의 토대임 (대응: MECH-2 확장)

### 2.3.3 유형 C: 자기 발화 미검증 3건

- **채팅이 무검사 채널임**: [[AGENTS#2.2.1 작성자]] 3단계가 자기검수 발견을 "채팅에 인라인으로 보고함"이라 규정함. 보고 채널이 곧 무검사 채널임. `quote_check.mjs`는 커밋된 파일을 보지 채팅에서 말한 행번호는 보지 않음 (대응: MECH-6, FLOW-4)
- **L5 표기 의무가 본문에만 걸림**: [[CONVENTIONS#3.7 외부 근거의 권위 계층]]의 "추정", "확인 필요" 표기 의무는 본문 규칙이라 채팅 단정("유일하게 검증 가능한 방법")에 걸리지 않음 (대응: MECH-5)

## 2.4 게이트 설계 결함

[[AGENTS#2.4.1 G1: 작성자 자기검수 후]]의 자동 통과 조건이 "자동 lint 0건 + 자기검수 발견 0건 + 사용자 직접 검토 추가 발견 0건"이고, 2.3 작업 사이클에 "발견 0건이면 G1 생략"이 있음.

자기검수 검출률은 16건 중 1건임. **검출력이 거의 없는 검사의 0건이 게이트 생략의 근거가 되는 구조임.** 자기검수 0건은 "결함 없음"이 아니라 "정보 없음"으로 취급해야 함 (대응: FLOW-4).

## 2.5 자기검수 무력화의 구조적 이유

[[AGENTS#2.2.1 작성자]] 3단계는 "작성자는 자기 의도를 이미 알아 글자 그대로 읽지 못함"을 정확히 진단하고 맥락 독립 검토를 도입했음. 설계는 옳으나 적용 범위가 좁음.

- 서브에이전트에게 주는 지시가 "문법, 명료성, 중복, 구조 결함을 찾아라"로 한정됨
- **사실 대조가 지시에 없음.** 원전 전사본을 대조하는 과제가 독립 검토에 포함되지 않음
- 결과: 현재 구조에서 A형을 잡을 주체가 사용자밖에 없음. 외부 AI가 5건을 잡은 것이 이 공백의 크기임 (대응: FLOW-2)

# 3. 개입안

## 3.1 기계로 옮길 것 (MECH)

작성자 자기보고에 의존하던 항목을 검사기로 이관함. [[CONVENTIONS#3.5 Wikilink 규칙]] 이미지 경로 항목이 이미 밟은 경로임.

- **MECH-1 `updated` 자동화**: `scripts/hooks/pre-commit`에서 스테이징된 `.md`의 frontmatter `updated`가 오늘 날짜가 아니면 실패시키거나 자동 갱신함. 성공 시 [[AGENTS#2.2.1 작성자]] 셀프체크에서 해당 항목을 삭제함
- **MECH-2 폐기 어휘 검사**: `deprecated_terms.txt`를 두고 폐기할 때마다 그 설계의 고유 어휘를 등록함. `wiki_lint.mjs`가 `04_Projects/_archive/`와 `08_Logs/`를 제외한 활성 문서에서 검사함
	- 첫 등록 대상: `한국 공문서 넘버링`, 폐기된 `§` 표기, 이번에 폐기한 옛 설계 어휘
	- 용어 일관성으로 확장: 정본 용어와 금지 변이형을 같은 파일에 등록해 한 용어가 여러 이름으로 불리는 것을 검사함
	- 효력: 검증 불가능한 선언("옛 설계를 참조하지 않겠음")을 검증 가능한 검사로 번역한 것임
- **MECH-3 원전 서사에 근거 마커 의무화**: [[CONVENTIONS#3.6 수치/목표 인용 원칙 (엄격)]]의 대상 항목에 "원전 서사 사실(사건의 진행과 순서, 결말, 승패, 인물의 행위)"을 추가함
	- 표기: 전사본을 다루는 표와 목록에 `근거` 열이나 필드를 필수로 둠. 값은 행 범위(예: `618~622행`) 아니면 `원문 미명시`
	- 검사 범위: `quote_check.mjs`가 마커의 존재와 행번호 유효성을 봄. 요약의 충실도는 여전히 기계가 못 봄
	- 효력: **"아무 근거 없이 지어낸 것"과 "근거는 있는데 요약이 어긋난 것"이 분리됨.** 전자는 하드 실패로 떨어지고, 후자만 사람이 보면 되므로 검토 부담이 줄어듦
- **MECH-4 diff 동반성 검사**: 스테이징된 diff에서 한 헤딩 구간의 본문 라인이 변경됐는데 그 구간의 헤딩 라인, 표, TL;DR이 그대로면 "확인 요구" 목록으로 출력함. 자동 반려가 아니라 목록 출력으로 충분함. 유형 B 7건을 직접 겨냥함
- **MECH-5 단정 어휘와 제목 어휘 검사**:
	- 단정 어휘: "유일한", "반드시", "항상", "모든"이 근거 링크 없이 쓰이면 경고함. 오탐이 나오나 재현율을 우선함
	- 제목 어휘: 절 제목에 승패, 인과, 결말 어휘를 금지함. 제목은 가리키기만 하고 주장하지 않음. **제목이 주장할 수 없으면 제목은 틀릴 수 없음**
- **MECH-6 편집 후 행번호 무효 알림**: Claude Code `PostToolUse` 훅으로 Edit 성공 시 "이 파일의 행 번호 기억은 폐기됨, 인용 전 재읽기 필요"를 출력함. 유형 C의 stale 행번호 인용이 구조적으로 막힘

## 3.2 작성 절차를 바꿀 것 (FLOW)

규칙 추가가 아니라 순서와 역할의 변경임.

- **FLOW-1 작성 순서 뒤집기**: 사실 층 문서는 재료 목록을 먼저 파일로 만들어 커밋하고, 구조를 그 목록에서 뽑고, 본문을 마지막에 씀
	- [[AGENTS#2.2.1 작성자]] 1단계를 "구조 설계 선행"에서 "재료 수집과 목록 확정"으로 바꾸고 구조 설계를 2단계로 내림
	- [[CONVENTIONS#3.8.1 작성 전 절차]] 3번 "목차 먼저 설계"에 사실 층 예외를 명시함
	- 대응 재료 파일이 없으면 본문 작성을 막는 것까지 기계 검사로 가능함
	- 핵심: **3.8.2를 셀프체크에서 빼서 작성 순서로 승격시킴**
- **FLOW-2 독립 검토에 사실 대조 과제 추가**: 현행 서브에이전트 지시는 가독성과 구조만 봄. 별도 패스를 하나 더 둠
	- 지시문: 원전 전사본 경로를 주고 "각 사실 주장의 근거 행번호를 원문에서 찾아 제시하라. 못 찾으면 '없음'이라고 답하라"
	- 설계 의도: 실패가 눈에 보이는 형태의 과제임. "검토해 달라"는 지시는 실패가 보이지 않음
	- 전제: 검토 세션에 작성자의 대화 이력과 의도를 주지 않음(현행 규정 유지)
- **FLOW-3 규칙 충돌 우선순위 명시**: [[CONVENTIONS#1. 핵심 원칙]]에 세 줄을 추가함
	- 우선순위: 사실 > 구조 > 형식. 규칙이 충돌하면 이 순서로 판정함
	- `원문 미명시`가 병렬 형식을 만족하는 정당한 값임을 명시함. **빈칸을 합법화하면 창작 압력이 사라짐**
	- `[[CONVENTIONS#3.8.7 목록 형식 선택과 라벨형, 중첩 블릿 규칙]]`(당시 위치, 현 [[문서 작성 세부 규칙]]) 다)의 "묶음 병렬성 우선" 조항을 삭제하거나 "재료가 있는 항목에 한해"로 한정함
- **FLOW-4 게이트 신호 정정**:
	- [[AGENTS#2.4.1 G1: 작성자 자기검수 후]]의 자동 통과 조건에서 "자기검수 발견 0건"을 제외함. 남는 것은 자동 lint 0건과 사용자 검토이며 그것이 실제 검출력의 정직한 반영임
	- [[CONVENTIONS#5.2 문서 갱신 시]]에 파생 텍스트 동반 점검 단계를 추가함(MECH-4가 출력한 확인 요구 목록을 처리하는 자리)
	- 채팅에서 행번호, 수치, 표를 말하지 않고 파일에 쓰고 링크함

## 3.3 규칙을 덜어낼 것 (SLIM)

효과가 가장 크고 실행 의지가 가장 필요한 항목임.

- **SLIM-1 상시 규칙과 참조 규칙의 물리 분리**: 현재 `CLAUDE.md` → `AGENTS.md` → `CONVENTIONS.md` 체인으로 800줄 남짓이 매 세션 로드됨
	- 그중 프로토타입 자족성, 이미지 경로 문법, 시범콘텐츠 폴더 넘버링, 변환 파이프라인 규약은 해당 작업을 할 때만 필요함
	- 상시 로드를 20줄에서 30줄로 줄이고 나머지를 `02_HowTo/`로 옮겨 작업 시 Read하게 함
	- 근거: **컨텍스트 안에서 실제로 작동하는 규칙 수는 유한함.** 800줄 안에서는 "사실이 형식보다 우선"이 묻힘
- **SLIM-2 중복 기재 제거**: 링크 하한선(핵심 원칙 6번과 3.5), 작은 변경 면제 조건([[AGENTS#2.4.3 작은 변경 사이클 면제 (엄격)]]와 3.3)을 각각 한 곳으로 모으고 나머지는 참조로 바꿈. 앞으로 같은 규칙을 두 곳에 적지 않음

# 6. 측정

개입 효과를 발견 건수로 재지 않음. 검출력이 좋아지면 발견 건수는 오히려 늘어남.

- **검출자별 발견 목록을 따로 기록함**: 자기검수, 자동 검사, 사용자, 외부 AI 넷을 분리해 남김
- **중복 건수로 총량을 추정함**: 사용자와 외부 AI는 상당히 독립적인 검출자이므로, 두 집합의 겹침이 작으면 실제 결함이 발견 건수보다 훨씬 많다는 뜻임
- **개입의 성공 기준**: 총 추정량의 감소, 그리고 자동 검사가 잡는 비율의 증가
