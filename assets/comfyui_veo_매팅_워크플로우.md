# ComfyUI 매팅 워크플로우 안내

Veo 3로 뽑은 시범 동작 영상에서 배경을 빼고 알파를 남기는 워크플로우임. 같은 폴더의 `comfyui_veo_매팅_워크플로우.json`을 ComfyUI 화면에 끌어다 놓으면 열림.

## 흐름

```
1. Veo 결과 영상 불러오기 (VHS_LoadVideo)
        │  IMAGE(프레임들)
        ├──────────────► 2. 매팅 ──► MASK
        │                              │
        └──────────────► 3. 알파 붙이기 (JoinImageWithAlpha) ──► RGBA 프레임
                                                                  ├─► 4-A. PNG 시퀀스 저장
                                                                  └─► 4-B. 알파 WebM 저장 (우회 상태)
```

원본 프레임은 매팅 노드를 거치지 않고 3번으로 바로 갑니다. 매팅 노드가 내주는 것은 마스크뿐이고, 색은 원본을 그대로 써야 화질이 안 떨어집니다.

## 필요한 커스텀 노드

| 노드 | 출처 | 비고 |
|---|---|---|
| `VHS_LoadVideo`, `VHS_VideoCombine` | ComfyUI-VideoHelperSuite | 영상 입출력. 코어에는 영상 로더가 없음 |
| 매팅 노드 (2번) | 아래 참조 | **설치한 팩에 맞게 교체 필요** |
| `JoinImageWithAlpha`, `SaveImage` | ComfyUI 코어 | 설치 불필요 |

## 2번 노드는 반드시 교체할 것

JSON에는 `BiRefNet`이라는 이름으로 자리만 잡아 뒀습니다. 매팅 노드는 팩마다 클래스 이름과 위젯이 달라서, **설치한 팩의 노드로 바꿔 끼워야 합니다**. 열었을 때 그 자리가 빨갛게 뜨면 노드가 없다는 뜻입니다.

바꿀 때 볼 것은 둘뿐입니다.

- 입력이 `IMAGE`인가
- 출력에 `MASK`가 있는가 (없고 RGBA `IMAGE`만 내주는 노드면 3번을 건너뛰고 바로 저장으로 연결)

후보와 성격은 다음과 같습니다.

- **RVM (Robust Video Matting)**: 앞뒤 프레임을 함께 봐서 경계 떨림이 적음. 휘둘러 쫓기처럼 빠른 동작에 유리
- **BiRefNet**: 정지 이미지용이라 경계가 가장 날카로움. 살피기처럼 느린 동작에 유리하고, 프레임마다 따로 처리해 미세한 떨림이 생길 수 있음
- **SAM2**: 첫 프레임에서 대상을 지정해 따라가게 함. 인물이 하나뿐이라 굳이 쓸 필요는 적음

## 저장 형식

- **4-A PNG 시퀀스**: 기본값. 손실 없음. 프레임 수만큼 파일이 생김
- **4-B 알파 WebM**: 지금은 우회(bypass) 상태임. 쓰려면 노드를 켜고 VideoHelperSuite에서 알파를 지원하는 형식과 코덱인지 확인할 것. 프로토타입이 HTML이라 최종 납품은 이쪽이 맞음

## 미리 알아 둘 것

- **배경 대비**: 지금 캐릭터 이미지 배경이 밝은 회색인데 상모와 바지가 흰색이라 경계가 약합니다. 매팅 품질이 안 나오면 배경을 짙은 색으로 바꾼 캐릭터 이미지로 영상을 다시 뽑는 편이 빠릅니다
- **모션 블러**: 빠르게 지나가는 팔은 반투명이라 어느 모델이든 애매하게 잘립니다. 영상 전용 모델이 이 구간을 덜 뭉갭니다
- **판정용에는 매팅이 필요 없음**: 포즈 추정은 배경이 있어도 관절만 뽑습니다. 매팅은 시범 클립을 판 위에 겹칠 때만 씁니다

## 순서 권고

동작이 쓸 만한지부터 보는 것이 먼저입니다. 배경이 있는 상태로 Veo 결과를 다섯 가지(제자리, 정면 유지, 탈 일관성, 홀드 유지, 손과 관절 왜곡)로 검수하고, 통과한 클립에만 이 워크플로우를 돌리십시오.
