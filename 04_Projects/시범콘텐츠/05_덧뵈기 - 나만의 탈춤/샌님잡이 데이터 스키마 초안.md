# 2. 구조 대응

근거 단위를 데이터의 소유 주체와 바뀌는 시점에 따라 네 실행 데이터 묶음, 한 QA 데이터 묶음과 한 검증 조건으로 정리함.

| 구조 ID | 대응 근거 | 데이터 종류 | 합친 이유 |
|---|---|---|---|
| T1 | D1, D2, D3, D8, D10 | 입력 콘텐츠 | 슬롯, 소재, 비틀기 방식과 조합이 하나의 선택 조회 관계를 이루며 함께 작성됨 |
| T2 | D4, D5 | 공용 반응 | 여러 조합이 같은 반응 유형 ID로 하나의 공용 반응 묶음을 재사용함 |
| T3 | D6, D7, D8, D9a, D9b | 판정 및 진행 규칙 | 재입력, 분노 합산, 조건부 관계 역전과 전체 진행에 넘길 승패 결과가 함께 적용됨 |
| T4 | D7 | 세션 실행 상태 | 플레이 중에만 생기며 정적 콘텐츠 파일에 보관하지 않아야 함 |
| T5 | D11b | QA 기준과 시험 경로 | 높은 값의 기준, 필요한 승리 경로 수, 시험 조합 집합과 목표 승패 비율을 실제 QA 입력으로 사용함 |
| V1 | D11a | 스키마 검증 조건 | 실행 데이터와 QA 데이터의 값 및 참조를 검사하는 조건으로 바꿈 |

- **선택한 구조**: 런타임 정적 데이터는 `content`, `reactions`, `rules` 세 파일로 나누고 세션 실행 상태는 메모리나 세션 저장소에 둠. QA 기준과 시험 경로는 런타임에서 로드하지 않는 별도 파일로 둠.
- **가능한 대안**: 정적 데이터 세 종류를 한 파일에 합칠 수 있음. 다만 조합 작성, 공용 반응 자산 교체, 판정값 조정의 주기가 서로 달라 세 파일 구조를 우선함.
- **설계 추가**: 영문 필드명, 파일 분리, 실행 상태 열거형과 자산 참조 필드의 자료형은 개발 전달을 위해 추가함. 5절의 한국어 열과 영문 조합 필드는 아래 표에서 일대일로 대응함. 5절에 없는 대사, 행동, 음향 값은 만들지 않음.

# 3. 데이터 파일

이 스키마가 승인된 뒤 런타임용 실제 값은 신설 예정인 `06_클라이언트 데이터/나만의 탈춤/` 아래 세 JSON 파일에 둠. QA 파일은 런타임 배포에서 제외하며 저장 위치는 테스트 실행 환경을 정할 때 확정함. 이 문서는 값의 중복 사본을 두지 않고 스키마만 소유함.

| 파일 | 소유 데이터 | 사용처 |
|---|---|---|
| `saennimjabi_content.json` | 입력 슬롯, 소재, 비틀기 방식, 유효 조합 | 입력 후보 표시, 조합 조회, 원전 대사와 행동 재생 |
| `saennimjabi_reactions.json` | 반응 유형별 공용 반응 묶음 | 조합 판정 뒤 샌님, 말뚝이, 관객 및 음향 반응 재생 |
| `saennimjabi_rules.json` | 재입력, 점수와 관계 역전 설정 | 입력 제어, 최종 승패 계산, 전체 진행에 결과 전달 |
| `saennimjabi_qa.json` | 높은 값의 기준, 승리 경로 수, 시험 경로와 목표 승패 비율 | 조합표와 승패 기준 QA. 런타임에서는 로드하지 않음 |

세션 실행 상태는 정적 JSON에 넣지 않음. 클라이언트에 신설할 `SaennimjabiSessionState`가 실행 단계와 입력 상태, 현재 선택, 슬롯별 최종 결과와 승패를 보유함.

# 4. 공통 자료형

- **`LineRange`**: `start`와 `end` 두 양의 정수만 가지며 `start`는 `end`보다 클 수 없음.
- **`ReactionTypeId`**: `MISS`, `COMPLY`, `WORDPLAY`, `PROVOKE`, `SELF_TRAP`, `REVERSAL` 여섯 값만 허용함.

# 5. 입력 콘텐츠 스키마

`saennimjabi_content.json`은 실제 선택 후보와 조합 결과를 정규화해 보관함. 소재 목록과 비틀기 방식 목록을 조합마다 반복하지 않음.

## 5.1 입력 콘텐츠 최상위 구조

| 필드 | 자료형 | 필수 | 제약 |
|---|---|---:|---|
| `slots` | `Slot[]` | 예 | 정확히 네 레코드이며 `slotId`가 1부터 4까지 한 번씩 존재해야 함 |
| `materials` | `Material[]` | 예 | 모든 레코드는 한 슬롯에 속하고 유효 조합에서 한 번 이상 참조되어야 함 |
| `twistTypes` | `TwistType[]` | 예 | `OTHER_MEANING`, `LITERAL`, `REVERSE`를 한 번씩 가져야 함 |
| `combinations` | `Combination[]` | 예 | 화면에서 선택 가능한 유효한 소재와 비틀기 방식의 쌍만 보관함 |

## 5.2 Slot

슬롯은 표시할 원문 대사와 네 번째 슬롯의 조건부 관계 역전 시퀀스를 소유함. 다음 슬롯은 `slotId` 순서로 정함.

| 필드 | 자료형 | 필수 | 제약 |
|---|---|---:|---|
| `slotId` | `integer` | 예 | 1 이상 4 이하이며 중복될 수 없음 |
| `promptDialogueId` | `string` | 예 | 플레이어가 소재를 고르는 기준이 되는 샌님 원문 대사의 식별자임 |
| `promptSourceLines` | `LineRange` | 예 | `promptDialogueId`가 가리키는 원문 대사의 행 범위임 |
| `reversalSequenceId` | `string 또는 null` | 예 | 슬롯 4만 실제 시퀀스 ID를 가지며 나머지 슬롯은 `null`임 |

## 5.3 Material

소재는 화면에서 실제 선택 영역으로 제시할 원문 단어나 표현임.

| 필드 | 자료형 | 필수 | 제약 |
|---|---|---:|---|
| `materialId` | `string` | 예 | 전체 파일에서 중복될 수 없음 |
| `slotId` | `integer` | 예 | `slots.slotId`를 참조함 |
| `text` | `string` | 예 | 샌님의 원문 대사에서 고른 실제 단어나 표현이어야 함 |

## 5.4 TwistType

비틀기 방식은 5절에서 정한 세 선택지만 보관함.

| 필드 | 자료형 | 필수 | 제약 |
|---|---|---:|---|
| `twistTypeId` | `enum` | 예 | `OTHER_MEANING`, `LITERAL`, `REVERSE` 중 하나이며 중복될 수 없음 |
| `label` | `string` | 예 | 각각 `딴뜻`, `그대로`, `뒤집기`를 사용함 |

## 5.5 Combination

조합은 한 차례 판정의 단일 정본임. 소재를 고른 뒤 표시할 비틀기 방식은 같은 `slotId`와 `materialId`를 가진 조합에서 역으로 구함.

| 필드 | 자료형 | 필수 | 제약 |
|---|---|---:|---|
| `combinationId` | `string` | 예 | 전체 파일에서 중복될 수 없음 |
| `slotId` | `integer` | 예 | `slots.slotId`를 참조함 |
| `sourceEventIds` | `string[]` | 예 | `S6`부터 `S11`까지 중 실제 대응 사건을 하나 이상 기록함 |
| `materialId` | `string` | 예 | 같은 슬롯에 속한 `materials.materialId`를 참조함 |
| `twistTypeId` | `enum` | 예 | `twistTypes.twistTypeId`를 참조함 |
| `reactionTypeId` | `ReactionTypeId` | 예 | 허용된 여섯 값 중 하나임 |
| `angerEffect` | `number` | 예 | 해당 조합이 슬롯의 최종 결과로 확정될 때 합계에 한 번 반영함. 범위는 QA 뒤 확정해야 함 |
| `sourceLines` | `LineRange` | 예 | 원문 행의 시작과 끝을 양의 정수로 기록함 |
| `dialogueId` | `string` | 예 | 재생할 실제 원문 대사 식별자임 |
| `malttugiActionId` | `string` | 예 | 대사와 함께 재생할 말뚝이 행동 시퀀스 식별자임 |

5절 조합표의 한국어 열과 JSON 필드는 다음처럼 일대일로 대응함.

| 5절 열 | JSON 필드 |
|---|---|
| 조합 ID | `combinationId` |
| 입력 슬롯 | `slotId` |
| 대응 사건 | `sourceEventIds` |
| 소재 | `materialId` |
| 비틀기 방식 | `twistTypeId` |
| 반응 유형 ID | `reactionTypeId` |
| 분노 효과값 | `angerEffect` |
| 원문 행 | `sourceLines` |
| 대사 식별자 | `dialogueId` |
| 말뚝이 행동 | `malttugiActionId` |

# 6. 공용 반응 스키마

`saennimjabi_reactions.json`은 여섯 반응 유형과 실행 자산의 대응만 보관함. 반응 이름이나 기능 설명은 실행에 쓰지 않으므로 넣지 않음.

## 6.1 공용 반응 최상위 구조

| 필드 | 자료형 | 필수 | 제약 |
|---|---|---:|---|
| `reactions` | `Reaction[]` | 예 | 반응 유형별로 정확히 한 레코드를 가져야 함 |

## 6.2 Reaction

| 필드 | 자료형 | 필수 | 제약 |
|---|---|---:|---|
| `reactionTypeId` | `ReactionTypeId` | 예 | 허용된 여섯 값 중 하나이며 중복될 수 없음 |
| `reactionBundleId` | `string` | 예 | 전체 파일에서 중복될 수 없음 |
| `malttugiActionId` | `string` | 예 | 말뚝이 공용 반응 시퀀스 식별자임 |
| `saennimActionId` | `string` | 예 | 샌님 공용 반응 시퀀스 식별자임 |
| `audienceReactionId` | `string 또는 null` | 예 | 관객 웃음이나 추임새 자산 식별자임. 관객 반응을 두지 않으면 `null`임 |
| `rhythmSfxCueId` | `string 또는 null` | 예 | 장단 강조나 음향 효과 큐 식별자임. 음향을 두지 않으면 `null`임 |

반응 유형과 공용 반응 묶음 ID는 5절의 대응을 그대로 고정함. 자산 ID는 반응 의미를 만족하는 실제 자산을 가리켜야 함.

| `reactionTypeId` | `reactionBundleId` | `audienceReactionId` 값 또는 제약 | `rhythmSfxCueId` 값 또는 제약 |
|---|---|---|---|
| `MISS` | `REACTION_MISS` | `null` | `null` |
| `COMPLY` | `REACTION_COMPLY` | 실제 자산 ID 필수 | `null` |
| `WORDPLAY` | `REACTION_WORDPLAY` | 실제 자산 ID 필수 | `null` |
| `PROVOKE` | `REACTION_PROVOKE` | 실제 자산 ID 필수 | `null` |
| `SELF_TRAP` | `REACTION_SELF_TRAP` | 실제 자산 ID 필수 | 실제 자산 ID 필수 |
| `REVERSAL` | `REACTION_REVERSAL` | 실제 자산 ID 필수 | 실제 자산 ID 필수 |

분노 효과값은 공용 반응 파일에 두지 않음. 같은 반응 유형이라도 조합마다 값이 다를 수 있으므로 `combinations.angerEffect`만 사용함.

# 7. 판정 및 진행 규칙 스키마

`saennimjabi_rules.json`은 콘텐츠 값과 분리해 QA에서 조정할 판정값과 실행 분기를 보관함.

## 7.1 판정 규칙 최상위 구조

| 필드 | 자료형 | 필수 | 제약 |
|---|---|---:|---|
| `input` | `InputRule` | 예 | 미입력과 `MISS` 재시도, 손 인식 중단 시 일시 정지, 재생 중 입력 잠금을 제어함 |
| `scoring` | `ScoringRule` | 예 | 네 슬롯의 최종 분노 효과값으로 승패를 정함 |
| `reversal` | `ReversalRule` | 예 | 슬롯 4의 조건부 관계 역전 재생 조건을 정함 |

## 7.2 InputRule

| 필드 | 자료형 | 필수 | 값 또는 제약 |
|---|---|---:|---|
| `selectionTimeoutMs` | `integer` | 예 | 0보다 커야 함. 5절에 값이 없어 확정 필요함 |
| `pauseOnTrackingLoss` | `boolean` | 예 | `true`임 |
| `trackingGuideId` | `string` | 예 | 손 인식이 끊겼을 때 다시 보여줄 인식 안내 자산 식별자임 |
| `inputGuideId` | `string` | 예 | 미입력 뒤 다시 보여줄 입력 안내 자산 식별자임 |
| `lockInputDuringPlayback` | `boolean` | 예 | `true`임 |
| `discardPreviousAttemptOnRetry` | `boolean` | 예 | `true`임 |
| `resolutionTransitions` | `ResolutionTransition[]` | 예 | 미입력과 조합 결과의 시도별 반응 재생 및 다음 행동을 고정함 |

`ResolutionTransition`은 실제 상태 전이에 필요한 네 필드를 가짐.

| 필드 | 자료형 | 필수 | 제약 |
|---|---|---:|---|
| `triggerType` | `enum` | 예 | `NO_INPUT`, `MISS`, `NON_MISS_COMBINATION` 중 하나임 |
| `attempt` | `enum` | 예 | `FIRST`, `FINAL`, `ANY` 중 하나임 |
| `playReaction` | `boolean` | 예 | 공용 반응 재생 여부임 |
| `nextAction` | `enum` | 예 | `RETRY_SLOT` 또는 `ADVANCE`임. `ADVANCE`는 슬롯 1~3에서 다음 슬롯으로 가고 슬롯 4에서 관계 역전 조건을 확인한 뒤 승패를 계산함 |

전이 배열은 아래 다섯 레코드를 정확히 한 번씩 가져야 함. `NON_MISS_COMBINATION`은 `MISS`를 제외한 다섯 반응 유형의 조합을 뜻함.

| `triggerType` | `attempt` | `playReaction` | `nextAction` |
|---|---|---:|---|
| `NO_INPUT` | `FIRST` | `false` | `RETRY_SLOT` |
| `NO_INPUT` | `FINAL` | `false` | `ADVANCE` |
| `MISS` | `FIRST` | `true` | `RETRY_SLOT` |
| `MISS` | `FINAL` | `true` | `ADVANCE` |
| `NON_MISS_COMBINATION` | `ANY` | `true` | `ADVANCE` |

## 7.3 ScoringRule

| 필드 | 자료형 | 필수 | 값 또는 제약 |
|---|---|---:|---|
| `noEffectAngerValue` | `number` | 예 | `MISS`와 최종 미입력에 공통으로 적용함. 5절에 값이 없어 확정 필요함 |
| `victoryThreshold` | `number` | 예 | QA 뒤 확정해야 함 |
| `aggregation` | `enum` | 예 | 네 최종값을 합산하므로 `SUM`임 |
| `winComparison` | `enum` | 예 | 합계가 기준 이상일 때 승리하므로 `GTE`임 |
| `reversalRequiredForWin` | `boolean` | 예 | `false`임 |

## 7.4 ReversalRule

| 필드 | 자료형 | 필수 | 값 또는 제약 |
|---|---|---:|---|
| `triggerSlotId` | `integer` | 예 | `4`임 |
| `triggerReactionTypeId` | `ReactionTypeId` | 예 | `REVERSAL`임 |

재생할 시퀀스 ID는 `slots[slotId=4].reversalSequenceId`에서 찾음. 다른 반응 유형이면 관계 역전 시퀀스를 재생하지 않음.

재담 시스템은 계산한 `outcomeId`만 전체 진행에 넘김. 승패별 퇴장 시퀀스, 장쇠의 결과 대사와 공통 마무리 화면 ID는 이 파일이 소유하지 않음.

# 8. QA 기준 스키마

`saennimjabi_qa.json`은 조합표와 승패 기준을 검사할 때 실제로 돌릴 시험 조건과 경로만 보관함. 설명, 검토 의견과 실행 결과 보고서는 넣지 않음.

## 8.1 QA 기준 최상위 구조

| 필드 | 자료형 | 필수 | 제약 |
|---|---|---:|---|
| `highAngerThreshold` | `number` | 예 | 높은 분노 효과값을 가르는 기준임 |
| `requiredWinningPathCount` | `integer` | 예 | 서로 다른 선택 경로로 확보해야 할 최소 승리 경로 수이며 1 이상이어야 함 |
| `targetOutcomeRatio` | `OutcomeRatio` | 예 | 모든 후보 설정과 비교할 공통 목표 승리 및 패배 비율임 |
| `testPaths` | `TestPath[]` | 예 | 승패 계산에 실제로 넣을 조합 경로 집합임 |
| `scoreScenarios` | `ScoreScenario[]` | 예 | 분노 효과값과 승리 기준의 후보 설정을 비교할 수 있도록 두 개 이상 가져야 함 |

## 8.2 TestPath

| 필드 | 자료형 | 필수 | 제약 |
|---|---|---:|---|
| `pathId` | `string` | 예 | QA 파일 안에서 중복될 수 없음 |
| `combinationIds` | `string[]` | 예 | 슬롯 1부터 4까지 순서대로 조합 ID 네 개를 가짐 |

## 8.3 ScoreScenario

| 필드 | 자료형 | 필수 | 제약 |
|---|---|---:|---|
| `scenarioId` | `string` | 예 | QA 파일 안에서 중복될 수 없음 |
| `angerEffects` | `CombinationAngerEffect[]` | 예 | 실제 조합마다 후보 분노 효과값을 하나씩 가짐 |
| `noEffectAngerValue` | `number` | 예 | 이 후보 설정에서 분노 효과가 없는 최솟값임 |
| `victoryThreshold` | `number` | 예 | 이 후보 설정에 적용할 승리 기준임 |

### 8.3.1 CombinationAngerEffect

| 필드 | 자료형 | 필수 | 제약 |
|---|---|---:|---|
| `combinationId` | `string` | 예 | `combinations.combinationId`를 참조하며 한 후보 설정 안에서 중복될 수 없음 |
| `angerEffect` | `number` | 예 | 해당 조합에 적용할 후보 분노 효과값임 |

`OutcomeRatio`는 `win`과 `lose` 두 수를 가지며 각각 0 이상 1 이하이고 합은 1이어야 함. 시험 경로별 승패와 전체 승패 비율은 저장하지 않고 각 후보 설정으로 계산함. 계산한 비율은 공통 `targetOutcomeRatio`와 나란히 제시하는 QA 출력이며 스키마 통과 조건으로 사용하지 않음.

# 9. 세션 실행 상태 스키마

신설할 `SaennimjabiSessionState`는 한 세션의 실행 단계와 입력 상태, 현재 선택, 슬롯별 최종 결과와 승패를 보관함. 재입력 전에 나온 미입력이나 `MISS`는 폐기하며 시도 이력을 별도 데이터로 남기지 않음.

## 9.1 세션 상태 최상위 구조

| 필드 | 자료형 | 필수 | 제약 |
|---|---|---:|---|
| `phase` | `enum` | 예 | `SELECT_MATERIAL`, `SELECT_TWIST`, `PLAY_COMBINATION`, `PLAY_REACTION`, `CALCULATE_OUTCOME`, `OUTCOME_READY`, `COMPLETE` 중 하나임 |
| `inputStatus` | `enum` | 예 | `ACTIVE`, `PAUSED_TRACKING`, `LOCKED_PLAYBACK` 중 하나임 |
| `currentSlotId` | `integer` | 예 | 1 이상 4 이하임 |
| `currentAttempt` | `integer` | 예 | `1` 또는 `2`임 |
| `selectedMaterialId` | `string 또는 null` | 예 | 소재 선택 전에는 `null`임 |
| `selectedTwistTypeId` | `enum 또는 null` | 예 | 비틀기 방식 선택 전에는 `null`임 |
| `slotResults` | `SlotResult[]` | 예 | 완료된 슬롯마다 최종 결과 하나만 가지며 최대 네 레코드임 |
| `outcomeId` | `enum 또는 null` | 예 | 네 슬롯 완료 전에는 `null`, 이후에는 `WIN` 또는 `LOSE`임 |

## 9.2 SlotResult

| 필드 | 자료형 | 필수 | 제약 |
|---|---|---:|---|
| `slotId` | `integer` | 예 | 완료된 슬롯 ID이며 중복될 수 없음 |
| `combinationId` | `string 또는 null` | 예 | 조합 확정이면 해당 ID, 최종 미입력이면 `null`임 |
| `reactionTypeId` | `ReactionTypeId 또는 null` | 예 | 조합의 반응 유형 ID이며 최종 미입력이면 `null`임 |
| `angerEffect` | `number` | 예 | 선택된 `Combination.angerEffect` 또는 `scoring.noEffectAngerValue`임 |

# 10. 검증 조건

파일을 실제 값으로 채울 때 기계로 판정할 조건과 원문 및 실행 화면을 사람이 확인할 조건을 나눔.

## 10.1 기계 스키마 검증

- **참조 무결성**
	- 모든 `slotId`, `materialId`, `twistTypeId`와 `reactionTypeId` 참조가 실제 레코드에 닿아야 함.
	- 모든 대사, 행동, 반응, 음향, 안내와 시퀀스 ID가 클라이언트 자산 레지스트리의 실제 ID여야 함.
- **선택 완전성**
	- 소재 목록은 유효 조합이 하나 이상 있는 항목만 포함해야 함.
	- 소재 선택 뒤 비틀기 방식 목록은 유효 조합에서 역으로 구해야 함.
	- `(slotId, materialId, twistTypeId)` 조합은 중복될 수 없음.
	- 각 슬롯에 유효 조합이 하나 이상 있어야 함.
	- 슬롯 1의 `sourceEventIds`는 `S6`, 슬롯 2는 `S7`, 슬롯 3은 `S8`과 `S9`만 가져야 함.
	- 슬롯 4의 `sourceEventIds`는 `S10`을 가져야 하며, `S11`은 `reactionTypeId`가 `REVERSAL`인 조합에서만 추가할 수 있음.
- **판정 일관성**
	- `MISS` 조합의 `angerEffect`는 모두 `noEffectAngerValue`와 같아야 함.
	- `noEffectAngerValue`는 모든 `combinations.angerEffect` 값 가운데 최솟값이어야 함.
	- `resolutionTransitions`는 [[#7.2 InputRule]]의 다섯 고정 전이와 일치해야 함.
	- 반응 유형마다 [[#6.2 Reaction]]의 고정 공용 반응 묶음 ID와 자산 필수 조건이 정확히 하나 있어야 함.
- **QA 기준 일관성**
	- 각 `TestPath.combinationIds`는 슬롯마다 하나씩 실제 조합을 참조해야 함.
	- 각 `ScoreScenario.angerEffects`는 실제 조합마다 후보 값을 하나씩 가져야 함.
	- 각 후보 설정의 모든 `MISS` 값은 해당 `noEffectAngerValue`와 같고 후보값 전체의 최솟값이어야 함.
	- 각 후보 설정에서 특정 소재에 속한 모든 조합이 `highAngerThreshold` 이상이면 실패로 판정해야 함.
	- 각 후보 설정에서 특정 비틀기 방식에 속한 모든 조합이 `highAngerThreshold` 이상이면 실패로 판정해야 함.
	- 각 후보 설정에서 서로 다른 승리 경로 수가 `requiredWinningPathCount` 이상이어야 함.

## 10.2 원문 대조와 실행 검수

- **원문 대응**
	- 각 `Slot.promptSourceLines`가 `promptDialogueId`의 실제 원문 행 범위와 일치해야 함.
	- 각 `Combination.sourceLines`가 해당 원문 대사의 실제 행 범위와 일치해야 함.
	- 각 조합의 `sourceEventIds`, `sourceLines`, `dialogueId`와 `malttugiActionId`가 같은 원전 사건에 대응해야 함.
- **실행 결과**
	- 슬롯 결과는 한 슬롯에 하나만 남기며 첫 미입력이나 `MISS` 결과를 합산하지 않아야 함.
	- `REVERSAL` 여부는 사용하지 않고 분노 효과 합계와 `victoryThreshold`를 `GTE`로 비교해 승패를 정해야 함.
	- 분노 효과값과 그 합계는 모든 화면과 접근성 문구에 표시하지 않아야 함.
	- 조합의 분노 효과값이 공용 반응 자산 선택을 바꾸지 않아야 함.
	- 슬롯 4의 최종 반응 유형이 `REVERSAL`일 때만 관계 역전 시퀀스를 재생해야 함.
- **자산 내용**
	- 여섯 반응 유형별 말뚝이, 샌님, 관객과 장단 자산이 [[덧뵈기 나만의 탈춤 재설계 방향#5.6 샌님의 반응 상태]]의 반응 의미와 일치해야 함.
	- S8 조합 자산은 욕설을 직접 되풀이하지 않아야 함.
	- S9 조합 자산은 씨름을 포함하지 않아야 함.
	- S11 관계 역전 자산은 슬롯 4의 `REVERSAL`에서만 재생해야 함.

# 11. 제외한 데이터

5절에 나오더라도 실행이나 실제 값 검수에 쓰지 않는 설명은 클라이언트 데이터로 만들지 않음.

- S1~S13의 사건 설명 전문과 `사용`, `각색`, `제외` 사유를 별도 데이터로 만들지 않음. 실제 조합이 참조하는 사건 ID만 보관함.
- 반응 유형의 한국어 이름, 판정 기준과 반응의 기능 설명을 JSON에 넣지 않음. 실행 키인 반응 유형 ID와 자산 참조만 보관함.
- QA 실행 결과 보고서와 검토 메모는 실행 입력이 아니므로 `saennimjabi_qa.json`에 넣지 않음.
- 원문 대사, 행동, 음향과 화면 자산의 설명용 사본을 넣지 않음. 실제 자산 식별자만 참조함.
- 첫 미입력이나 첫 `MISS`의 폐기된 결과를 세션 결과에 남기지 않음.
- S3~S5의 시작 재담과 세 마당 공통 진행 데이터는 샌님잡이 재담 시스템의 데이터에서 제외함.
- 승패별 퇴장 시퀀스, 장쇠의 결과 대사와 공통 마무리 화면 데이터는 전체 진행이 소유하므로 제외함.

# 12. 확정이 필요한 실제 값

아래 항목은 스키마에 필요하지만 5절만으로 값을 정할 수 없음. 임시값으로 채우지 않음.

- `materials`, `combinations`의 실제 레코드
- 모든 대사, 행동, 반응, 음향, 안내와 관계 역전 시퀀스 ID
- `selectionTimeoutMs`
- `angerEffect`의 값 범위와 각 조합의 값
- `noEffectAngerValue`
- `victoryThreshold`
- `highAngerThreshold`, `requiredWinningPathCount`와 공통 `targetOutcomeRatio`
- `testPaths`의 실제 경로
- `scoreScenarios`의 후보 분노 효과값, 분노 효과가 없는 값과 승리 기준
- `saennimjabi_qa.json`의 저장 위치
- [[덧뵈기 나만의 탈춤 재설계 방향#5.5 조합별 효과표 양식]]의 "위 열 이름과 같은 필드"를 같은 의미로 보고 `combinationId` 등 영문 키를 쓸지, `조합 ID` 등 한국어 열 이름을 JSON 키로 유지할지에 대한 결정
