> 키오스크 화면의 QR을 스캔한 유저가 자기 휴대폰에서 여는 웹페이지의 사양. 플랫폼 사양이 백엔드 책임으로 이름만 정해 둔 「다운로드 페이지 호스팅」의 실체를 정의함. 네 콘텐츠가 한 페이지 골격을 공유하고 결과물 구성만 콘텐츠별로 갈림. 키오스크 안에서 벌어지는 일은 각 기획서가, 호스팅과 만료 파기 백엔드는 플랫폼 사양이 소관임.

# 1. 개요

## 1.1 페이지의 정의

체험을 마친 유저가 결과물을 자기 기기로 가져가는 유일한 통로임. 키오스크는 결과물을 보여 주기만 하고 전달하지 않으므로, 이 페이지가 실패하면 유저는 빈손으로 돌아감.

- **진입 경로**: 키오스크 화면의 QR을 유저 휴대폰 카메라로 스캔함. 다른 진입 경로는 두지 않음
- **운영 주체**: 백엔드가 호스팅함. 키오스크 클라이언트는 주소를 QR로 그리는 일만 함
- **수명**: 결과물과 함께 만료됨. 만료 뒤에는 같은 주소가 만료 안내 화면으로 응답함

## 1.2 적용 범위

QR 다운로드를 쓰는 콘텐츠 네 종이 대상임. 결과물을 남기지 않는 살판 - 발장단 한 판과 덜미 - 나만의 꼭두각시는 대상이 아님. 콘텐츠별 구성은 3절에 콘텐츠 이름으로 절을 두었음.

| 콘텐츠 | 받아 가는 것 |
|---|---|
| 덜미 - 나만의 유람기 | 전자책 |
| 덧뵈기 - 나만의 탈춤 | 베스트샷 사진 1장 |
| 덧뵈기 - 양반 놀리기 4컷 | 4컷 만화 한 편 |
| 버나 - 버나잡이 한 판 | 기념 기록증 |

## 1.3 다른 문서와의 경계

- **각 콘텐츠 기획서 소관**: 결과물을 무엇으로 어떻게 만드는가, 키오스크 화면의 QR 표시와 스캔 안내, 세션 실패 처리
- **플랫폼 사양 소관**: 업로드 수신, 만료형 주소 발급, 만료 파기 같은 백엔드 동작
- **본 문서 소관**: 그 주소를 연 유저가 보는 화면과 그 화면의 규칙

# 2. 공통 구성

네 콘텐츠가 같은 골격을 씀. 다른 것은 결과물 목록과 문구뿐임.

## 2.1 화면 상태

주소 하나가 아래 다섯 상태 중 하나로 응답함. 준비 중을 뺀 넷은 한 화면에서 끝나고, 준비 중만 자동 전환을 기다림.

| 상태 | 언제 | 화면 |
|---|---|---|
| 정상 | 유효한 주소이고 만료 전임 | 결과물 미리보기와 받기 버튼, 만료 시각 |
| 준비 중 | 주소는 발급됐으나 결과물 업로드가 아직 안 끝남 | 준비 중 안내. 끝나면 자동으로 정상 화면으로 넘어감 |
| 만료됨 | 발급 뒤 다운로드 기간이 지남 | 만료 안내와 재발급 불가 안내. 받기 버튼 없음 |
| 없는 주소 | 주소가 틀렸거나 발급된 적이 없음 | 잘못된 주소 안내. 만료됨과 문구를 구분함 |
| 서버 오류 | 호스팅이나 저장소 장애 | 잠시 뒤 다시 시도 안내. 주소가 살아 있음을 알림 |

- **만료됨과 없는 주소를 가르는 이유**: 만료는 유저가 늦은 것이고 없는 주소는 잘못 들어온 것임. 같은 문구로 뭉치면 제때 온 유저가 자기 잘못으로 오해함
- **준비 중이 걸리는 곳**: 주소 발급과 업로드 완료 사이에 유저가 닿을 수 있는 콘텐츠에만 실제로 나타남. 지금은 탈춤 하나임. 유람기처럼 결과물 생성 구간에서 업로드를 끝내는 콘텐츠는 이 상태에 닿지 않음
- **오류 코드 노출 금지**: 유저 화면에는 사람 말로만 적음. 진단 정보는 서버 로그에 남김

## 2.2 결과물 표시와 받기

- **미리보기**: 받기 전에 무엇인지 확인하게 함. 한 장짜리 결과물은 그대로 띄우고, 여러 페이지짜리는 페이지를 넘겨 보게 함
- **받기 버튼**: 결과물마다 적어도 하나 둠. 여러 페이지짜리는 전체 받기와 현재 페이지 받기로 나눠 둘 수 있음. 버튼에 파일 종류와 크기를 함께 적어 데이터 소모를 예측하게 함
- **공유 버튼 없음**: 사회관계망 공유나 링크 복사 버튼을 두지 않음. 얼굴이 담길 수 있는 결과물을 한 번의 터치로 밖에 내보내는 경로를 만들지 않으려는 것임. 유저가 스스로 주소를 옮기는 것은 막지 않음
- **파일명 규칙**: 콘텐츠 이름, 결과물 종류, 발급 일자를 이 순서로 이어 붙임. 유저 기기의 다운로드 폴더에서 무엇인지 알아보게 함. 순서는 확정이고, 구분자와 날짜 표기 형식은 구현 단계에서 정함(확인 필요)

## 2.3 만료 안내

- **다운로드 기간**: 주소를 발급한 시각부터 48시간임(잠정). 네 콘텐츠가 같은 값을 쓰며, 값의 정본은 각 콘텐츠 기획서의 운영 파라미터 표임
- **얼굴이 안 담기는 결과물도 같음**: 유람기 전자책처럼 얼굴이 담기지 않는 결과물에도 같은 만료를 적용함(2026-08-14 사용자 결정). 콘텐츠마다 기간이 갈리면 유저가 언제까지 받을 수 있는지 헷갈리고, 무기한 보관은 결과물이 쌓이는 만큼 운영과 규정 부담이 늘기 때문임
- **표기 방식**: 정상 상태 화면에 만료 시각을 유저 기기의 시간대로 적음. "48시간 남음" 같은 상대 표기만 두면 언제까지인지 유저가 계산해야 함
- **받은 뒤 안내**: 받기가 끝나면 만료 뒤에는 다시 받을 수 없다는 것과 기기에 보관하라는 것을 알림
- **재발급 없음**: 만료된 주소를 되살리는 경로를 두지 않음. 세션이 이미 끝나 결과물을 다시 만들 근거가 없음

## 2.4 접근과 식별

- **익명 접근**: 로그인과 연락처를 요구하지 않음. 주소를 아는 것이 곧 접근 권한임
- **추측 불가 주소**: 주소를 난수로 만들고 세션 식별자나 수행 기록과 이어 붙이지 않음. 주소를 훑어 남의 결과물에 닿을 수 없게 함
- **주소 길이**: 난수를 128비트 이상으로 둠(잠정). 짧은 토큰은 무작위 대입으로 남의 결과물에 닿을 수 있고, 얼굴이 담긴 결과물에서는 그 피해가 큼. 확정값은 구현 단계에서 정함(확인 필요)
- **검색 차단**: 검색 엔진 수집을 막음(`robots.txt`와 `noindex`). 얼굴이 담긴 결과물(탈춤 베스트샷 사진)이 검색 결과로 노출되는 것을 막는 최소 조치임
- **공유의 성격**: 유저가 스스로 주소를 공유하는 것은 막지 않음. 다만 주소를 받은 사람은 누구나 결과물을 볼 수 있다는 것을 페이지에 알림

## 2.5 화면과 표기

- **모바일 우선**: 유입이 전부 휴대폰 스캔이라 세로 화면을 기본으로 설계함. 데스크톱은 같은 내용을 넓게 배치하는 정도로 둠
- **언어**: 한국어와 영어를 제공함. 키오스크 현지화 범위와 같은 두 언어임. 언어는 브라우저 설정을 따르고 화면에서 바꿀 수 있게 함
- **접근성**: 이미지에 대체 텍스트를 넣고, 글자와 배경의 명도 대비와 터치 표적 크기를 확보함
	- 본문을 이미지로 만들어 보여 주는 경우에는 그 페이지의 글을 대체 텍스트로 함께 실음. 그러지 않으면 화면 낭독기가 아무것도 읽지 못해 결과물이 통째로 닫힘
- **표시 정보**: 콘텐츠 이름과 사업명, 주관 기관 표기를 둠. 체험 회차나 순위 같은 경쟁 정보는 두지 않음

## 2.6 고지

- **파기 고지**: 만료 시 서버 사본을 지운다는 것과 받은 파일은 유저 소유라는 것을 적음
- **얼굴 포함 고지**: 얼굴이 담긴 결과물을 내는 콘텐츠에만 둠. 공유 전에 확인하라는 안내를 함께 적음
- **이용 조건**: 무형유산을 소재로 한 결과물의 이용 범위를 적음. 문구는 규정 검토에서 확정함(확인 필요)

## 2.7 집계

- **남기는 지표**: 페이지 열람 수와 받기 성공 수를 익명으로 셈. 결과물이 실제로 유저에게 닿는지를 보는 운영 지표임
- **남기지 않는 값**: 접속자를 식별하거나 기기를 추적하는 값은 남기지 않음. 1차연도를 익명 세션으로만 운영하기 때문임

# 3. 콘텐츠별 구성

## 3.1 덜미 - 나만의 유람기

전자책 하나만 다루는 페이지임.

- **결과물**: 다중 페이지 전자책. 페이지는 PNG 이미지임
- **낭독 음성 제외 (2026-08-14 사용자 결정)**: 낭독 음성은 이 페이지에 두지 않음. 재생 버튼도 받기 버튼도 없음. 음성은 키오스크 감상 화면에서 듣는 것으로 끝나고 반출하지 않음
- **파일 형식 (2026-08-14 사용자 결정)**: 열람은 페이지 PNG로, 전체 받기는 PDF 한 벌, 현재 페이지 받기는 PNG 한 장임
	- PDF로 전체를 주는 이유는 순서와 책 형태가 한 파일에 보존되고 기기를 가리지 않고 열리기 때문임. 페이지별을 PNG로 주는 이유는 한 페이지만 남기려는 유저가 바로 쓰게 하려는 것임
- **지은이 표기**: 표지에 유저가 지은 주인공 이름과 박첨지를 나란히 지은이로 적음(예: "○○, 박첨지 지음"). 받은 파일이 아니라 자기가 쓴 책으로 남게 함. 문안은 문안 작성과 함께 확정함(확인 필요)
- **페이지 표시**: 전자책의 각 페이지를 PNG로 만들어 한 페이지씩 보여 줌. 첫 페이지가 표지임. 기기와 브라우저에 따라 글꼴과 배치가 깨지지 않음. 페이지 글은 대체 텍스트로 함께 실음
- **페이지 넘김**: 이전과 다음 버튼으로 넘김. 지금이 몇 페이지이고 모두 몇 페이지인지 함께 보여 주며, 첫 페이지에서는 이전을, 마지막 페이지에서는 다음을 누를 수 없게 둠
- **받기 버튼 둘**: 전체 받기와 현재 페이지 받기를 나란히 둠. 현재 페이지 받기는 보고 있는 페이지가 바뀌면 받는 것도 바뀌므로, 버튼에 몇 페이지인지 함께 적어 어느 것을 받는지 헷갈리지 않게 함(예: "이 페이지 받기 PNG 4/12")

## 3.2 덧뵈기 - 나만의 탈춤

결과물 하나이고 얼굴이 담김. 고지 비중이 가장 큰 콘텐츠임.

- **결과물**: 베스트샷 사진 1장. **액자 합성본을 받음** (2026-08-14 사용자 결정). 마당 이름, 배역 이름, 이수 단계를 얹은 그림이며 키오스크 결과 화면에 띄우는 것과 같음
- **원본 미제공**: 액자 없는 카메라 원본은 제공하지 않음. 배경과 맥락이 없는 사진은 무엇인지 알기 어렵고, 두 벌을 두면 유저가 고르는 부담과 호스팅 용량이 함께 늘기 때문임
- **미리보기**: 받을 그림을 그대로 표시함. 키오스크에서 본 것과 받는 파일이 같아 미리보기와 결과가 어긋나지 않음
- **얼굴 포함 고지**: 적용 대상임(고지 내용은 공통 구성의 고지가 소유함)
- **준비 중 응답**: 이 콘텐츠는 유저가 결과 화면에 들어설 때 업로드를 시작하므로, 유저가 곧바로 스캔하면 업로드가 끝나기 전에 닿을 수 있음. 이때 준비 중 상태로 응답함. 대기 상한과 상한 초과 시 처리는 구현 단계에서 정함(확인 필요)

## 3.3 덧뵈기 - 양반 놀리기 4컷

작성 예정. 결과물은 4컷 만화 한 편임. 양반 놀리기 4컷 기획서의 결과물 명세가 확정된 뒤 이 절을 채움.

## 3.4 버나 - 버나잡이 한 판

작성 예정. 결과물은 기념 기록증 이미지임. 버나잡이 한 판 기획서의 결과물 명세가 확정된 뒤 이 절을 채움.

# 4. 실패와 복구

- **저장소 읽기 실패**: 서버 오류 상태로 응답하고 주소는 살려 둠. 유저에게 잠시 뒤 다시 시도하라고 안내함
- **다운로드 중단**: 유저 기기의 통신이 끊겨 받기가 끊긴 경우임. 페이지를 다시 열어 받게 함. 만료 전이면 횟수 제한 없이 다시 받을 수 있음
- **만료와 파기의 시차**: 만료 시각이 지났으나 파기 작업이 아직 안 돈 사이에 접근하면 만료됨 상태로 응답함. 파일이 남아 있어도 제공하지 않음
- **파기 뒤 접근**: 결과물을 지운 뒤에도 주소의 만료 기록을 일정 기간 남겨 만료됨 상태로 응답함. 그 기간마저 지나면 없는 주소로 응답함. 늦게 온 유저가 "잘못된 주소"를 보고 자기가 틀린 줄 오해하는 것을 막으려는 것임. 기록 존치 기간은 구현 단계에서 정함(확인 필요)
- **키오스크 쪽 실패와의 관계**: 업로드나 주소 발급이 실패해 QR 자체가 안 뜬 경우는 이 페이지의 실패가 아님. 각 기획서의 실패 처리가 다룸
