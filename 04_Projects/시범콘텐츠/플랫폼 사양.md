> 키오스크와 미디어 케이브 전 플랫폼이 공유하는 사용자와 연속성 정본. 사용자 모델, 연속 플레이(이어하기), 여러 콘텐츠에 걸친 진척과 자산 누적, 개인정보와 보안, 공통 백엔드를 정의함. 1회 사용의 골격은 [[시범콘텐츠 공통 사양]], 콘텐츠 고유 설계는 각 기획서에 둠.

# 1. 적용 범위와 RFP 추적

빠른 이동(독자별 관심). 각자 관심 절로 바로 이동함.

- 프로그래머: §2 사용자 모델, §5 공통 백엔드(식별자, 토큰, 데이터 모델)
- 기획자: §3 연속 플레이, §4 개인정보와 보안(흐름과 정책)
- 운영: §6 운영 파라미터, §7 미결 항목
- 아티스트: 해당 없음. 본 문서는 데이터와 정책 사양이라 자산은 각 콘텐츠 기획서가 다룸

## 가. 적용 범위

- **적용 대상**: 키오스크와 미디어 케이브 전 플랫폼의 사용자와 연속성 계층. 콘텐츠별 기획서가 본 문서(정본)를 참조함
- **공통 사양과의 경계**: 한 번의 사용(세션, 휘발)은 [[시범콘텐츠 공통 사양#2. 세션]]이 정본이고, 그 위에 쌓이는 사용자(재방문 누적, 서버 저장)는 본 문서가 정본임

## 나. RFP 추적

- **RFP 추적**: 본 사업의 최종 목표는 실시간 상호작용 체험과 학습 서비스 플랫폼 기술 개발임 ([[ref_제안요청서#가. 최종 목표]]). 그 안의 디지털 도제(Digital Apprentice) 요구가 돌아오는 학습자의 연속 학습 근거임 ([[ref_제안요청서#3. 활용방안 예시]])
- **근거 구분**: "유저 정보를 서버에 저장한 연속 플레이"는 RFP가 직접 명시한 문구가 아니라, 디지털 도제와 에듀테크 학습 도구 방침에서 도출한 내부 결정임. 최종 목표 문장에서 직접 도출된 것으로 단정하지 않음 (근거 등급은 §9 참고)

# 2. 사용자 모델

## 가. 두 계층 (세션과 사용자)

- 세션: 한 번의 사용(시작 Step에서 종료 Step까지). 끝나면 임시 데이터 파기, 휘발됨 ([[시범콘텐츠 공통 사양#2. 세션]])
- 사용자: 재방문에 걸쳐 진척과 자산이 누적되는 주체. 옵트인 시에만 서버에 보관됨

## 나. 세 단계

성숙도 순으로 셋을 둠. 현재 구현 범위는 1, 2단계임.

| 단계 | 식별 방식 | 보관 | 비고 |
|---|---|---|---|
| 익명 1회성 | 식별자 없음 | 세션 종료 시 파기 | 옵트인 미동의 시 기본값 |
| 가명 학습 프로필 | 무계정 가명 토큰(subject_id 참조) | 옵트인 시 서버 보관 | 현재 구현 대상 |
| 계정 | 로그인 자격증명 | 서버 보관 | 전방 호환 설계만, 현재 구현 밖 (§5.나) |
^user-tiers

- 진척의 실제 소유자는 내부 식별자 subject_id임. 토큰이나 계정은 그 식별자를 가리키는 자격증명일 뿐임 (§5.나 전방 호환과 연결)

# 3. 연속 플레이와 이어하기

## 가. 학습 토큰과 이어하기 흐름

- 발급: 옵트인 학습자에게 사용 종료 시점에 학습 토큰(QR)을 발급하거나 갱신함
- 복원: 다음 방문 시작 화면에서 이어하기로 토큰을 스캔하면 진척과 직전 동의 기록을 불러옴. 동의 약관을 다시 받지 않음 (동의 기록은 토큰이 아니라 서버 프로필에 보관)
- 미옵트인: 토큰이 없으므로 이어하기를 쓰지 않고 익명 1회성으로 진행함

## 나. 콘텐츠 횡단 누적

- 한 subject_id가 여러 콘텐츠의 진척과 자산을 함께 누적함. 예: 만든 탈([[덧뵈기]]), 만든 꼭두각시 이야기([[박첨지놀이]]) 등을 같은 프로필에 모음
- 이로써 한 종목 한 콘텐츠에 갇히지 않고 플랫폼 전체에서 돌아오는 학습자의 도제 경험이 이어짐 (디지털 도제)
- 누적 데이터 모델(콘텐츠별 진척 키, 자산 참조, 병합 규칙)은 구현 전 정의함 (작성 예정)

## 다. 플랫폼별 적용

사용자 연속성 사양은 전 플랫폼에 균일하게 적용함. 다만 개인 식별과 누적의 구현 방식은 플랫폼 환경에 따라 다름.

- 키오스크(1인): 개인이 직접 토큰을 스캔해 식별과 누적이 자연스러움
- 미디어 케이브(다중): 다중 관람과 참여 환경이라 개인 식별이 키오스크보다 어려움
	- 체험형(풍물, 상모놀이, 어름산이 되기): 개인이 자기 토큰으로 입장해 진척 누적
	- 순수 관람형(탈춤 군무, 외줄, 곤두질): 개인 누적이 어려움
	- 다중 환경의 개인 토큰 적용 메커니즘은 설계 과제임 (확인 필요)

# 4. 개인정보와 보안

세션 1회 데이터(연락처 등)의 개인정보 원칙은 [[시범콘텐츠 공통 사양#6. 개인정보와 가드레일 원칙]]을 따름. 본 절은 사용자 프로필(누적)의 개인정보와 보안을 정의함.

## 가. 비연결 설계

- 익명 통계는 신원을 알 수 있는 정보와 묶지 않음
- 학습 프로필 진척은 가명 토큰(subject_id)에만 붙이고, 얼굴이나 영상, 연락처 같은 직접 식별정보와 묶지 않음
- 한계: 직접 식별정보를 안 붙였어도 진척과 자산이 쌓이면 누구인지 좁혀질 수 있어 완전 익명으로 보지 않음. 가명 개인정보로 보호함
- 콘텐츠 횡단 누적은 재식별 위험을 더 키우므로 아래 통제를 함께 적용함
	- 최소 수집: 학습 목적에 필요한 진척과 자산만 보관하고, 원본 식별정보(얼굴, 영상)는 프로필에 두지 않음
	- 목적 제한: 프로필 데이터는 학습 연속성과 도제 피드백 용도로만 사용함
	- 접근 통제: subject_id 기반 접근에 권한과 감사 로그를 두고, 감사 로그에서 개인정보를 제외함
	- 프로필 분리: 익명 집계 통계와 옵트인 프로필을 분리 저장함

## 나. 동의 모델

- 학습 프로필 생성과 진척 보관은 별도 선택 동의(옵트인)임. 미동의 시 익명 1회성 유지
- 변경과 철회: 재방문자는 이어하기로 동의 약관을 건너뛰므로, 복원된 동의를 바꾸거나 철회하는 경로를 별도로 둠. 학습 프로필 관리 진입점에서 선택 동의를 켜고 끄거나, 철회 시 프로필과 토큰을 삭제해 익명 1회성으로 되돌림
- 진입점 위치와 본인 확인 방식은 UX와 법무 검토 단계에서 확정함 (확인 필요)

## 다. 학습 토큰 보안

베어러 방식이라 토큰을 가진 사람이 곧 접근 권한을 가짐. 아래를 설계에 명시함 (확인 필요).

- 토큰 값: 추측 못 하게 무작위성을 높이고(고엔트로피), 의미 정보를 안 담는 불투명 값으로 만듦
- 저장: 서버에 원문이 아니라 해시로 저장함 (유출돼도 토큰 복원 불가)
- 표시와 수명: QR 화면 표시 시간과 토큰 유효 시간을 짧게 둠
- 생명주기: 주기적 교체(회전), 폐기, 재발급, 토큰 값 중복 방지, 스캔 시도 횟수 제한(rate limit)
- 유출 대비: 접근 토큰과 분리, 감사 로그에서 개인정보 제외, 분실이나 도난 시 복구 불가 고지

## 라. 아동과 기관 사용

- 전제: RFP의 학교, 문화원 등 공공 체험과 교육 활용 ([[ref_제안요청서#3. 활용방안 예시]])
- 법무 검토 후 확정 항목 (임의 추정 금지):
	- 보호자와 기관 동의
	- 보관 기간
	- 열람과 삭제권
	- 기관별 접근 제한과 테넌트 분리
	- 자산 저장 최소화

# 5. 공통 백엔드와 계정 서비스

## 가. 식별자와 프로필

- 진척과 자산은 subject_id에 묶고, subject_id는 콘텐츠와 무관한 플랫폼 공통 식별자임
- 프로필은 subject_id에 연결된 진척, 자산 참조, 동의 기록을 담음 (보관 기간은 법무 검토 후 확정, 확인 필요)

## 나. 전방 호환 (향후 계정 확장, 현재 구현 밖)

- 적용 시점: 현재는 무계정 가명 토큰만 구현. 아래는 나중에 계정(분실 복구, 기기 간 연속성)을 붙일 때를 위한 방향이며 이번 구현 범위가 아님
- 설계 방향: 로그인 자격증명에서 subject_id를 찾는 경로를 인증 모듈로 분리. 한 식별자가 토큰과 계정 등 여러 자격증명을 갖도록 데이터 모델을 열어 둠
- 구현 전 정의 필요(작성 예정):
	- 상태 모델: 식별자(subject_id), 자격증명(credential), 프로필(profile)
	- 처리 규칙: 계정 연결, 복수 토큰 병합, 충돌, 철회, 부분 실패, 재시도와 idempotency
	- 분리 규칙: 익명 통계와 옵트인 프로필 분리

# 6. 운영 파라미터

연속성 관련 공통 운영 파라미터의 잠정 기본값을 정리함. 구현과 운영 단계에서 확정함 (근거 등급은 §9 참고).

| 파라미터 | 잠정 기본값 | 확정 시점 | 관련 위치 |
|---|---|---|---|
| 학습 토큰 유효 시간 | 확인 필요 | 구현 | §4.다 |
| QR 화면 표시 시간 | 짧게 (확인 필요) | 구현 | §4.다 |
| 토큰 회전 주기 | 확인 필요 | 운영 | §4.다 |
| 프로필 보관 기간 | 법무 검토 후 확정 | 법무 | §5.가 |

# 7. 미결 항목 (확인 필요)

설계와 구현, 법무 검토 단계에서 닫아야 할 미결 항목임. 닫히기 전까지 단정하지 않음.

- 미디어 케이브 다중 환경의 개인 토큰 식별과 누적 메커니즘 (§3.다)
- 프로필 보관 기간, 학습 토큰 유효 시간과 회전 주기 (§4, §6, 법무와 운영 확정)
- 계정 전방 호환의 식별자, 자격증명, 프로필 상태 모델과 병합, 철회 규칙 (§5.나)
- 아동과 기관 사용의 보호자, 기관 동의, 열람과 삭제권, 테넌트 분리 (§4.라, 법무)
