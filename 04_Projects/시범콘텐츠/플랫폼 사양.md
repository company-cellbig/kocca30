> 키오스크와 미디어 케이브 전 플랫폼이 공유하는 사용자와 연속성 정본. 서버에 누적되는 데이터 모델과 그 작업 단위별 구현을 정의함. 개요와 전체 플로우로 시작해 서버 데이터 모델과 작업 단위로 이어짐. 1회 사용(세션) 골격은 [[시범콘텐츠 공통 사양]], 콘텐츠 고유 설계는 각 기획서에 둠.

# 1. 개요

## 가. 플랫폼의 정의

키오스크와 미디어 케이브에서 여러 무형문화유산 시범콘텐츠를 운영하고, 콘텐츠를 가로질러 사용자 식별과 학습 연속성을 관리하는 통합 시스템임.

- **전시 환경**: 1인 터치형 키오스크와 다중 참여형 미디어 케이브(공간 몰입 전시) 두 환경을 함께 포괄함 ([[콘셉트 정리]], [[시범콘텐츠 공통 사양]])
- **공통 계층**: 콘텐츠(덜미, 덧뵈기 등) 고유 설계와 분리해, 사용자 식별과 이어하기, 콘텐츠를 가로지른 학습 진척과 자산 누적을 플랫폼이 담당함
- **학습 지향**: 1회 체험이 아니라 디지털 도제(Digital Apprentice), 곧 다시 찾는 학습자의 연속 학습을 전제로 함 (RFP 근거는 §1.다)

## 나. 적용 범위

- **본 문서 소관**: 키오스크와 미디어 케이브 전 플랫폼의 사용자와 연속성 계층. 콘텐츠별 기획서가 본 문서(정본)를 참조함
- **공통 사양과의 경계**: 한 번의 사용(세션, 휘발)은 [[시범콘텐츠 공통 사양#2. 세션]]이 정본이고, 그 위에 쌓이는 사용자(재방문 누적, 서버 저장)는 본 문서가 정본임
- **제외 (각 콘텐츠 기획서 소관)**: 콘텐츠 고유 상호작용과 기획(플롯, 채점, 페르소나 등), 전시 환경별 UI와 공간 연출은 본 문서가 다루지 않음

## 다. RFP 추적

- **RFP 직접 요구**: 본 사업 최종 목표는 실시간 상호작용 체험과 학습 서비스 플랫폼 기술 개발임 ([[ref_제안요청서#가. 최종 목표]]). 그 안의 디지털 도제 요구가 다시 찾는 학습자의 연속 학습 근거임 ([[ref_제안요청서#3. 활용방안 예시]])
- **내부 도출 결정**: "서버 저장 연속 플레이"는 RFP가 직접 명시한 문구가 아니라, 디지털 도제와 에듀테크 학습 도구 방침에서 도출한 내부 결정임. 최종 목표 문장에서 직접 도출된 것으로 단정하지 않음 (근거 등급은 §9 참고)

# 2. 사용자 모델

## 가. 두 계층 (세션과 사용자)

- **세션**: 한 번의 사용(시작 Step에서 종료 Step까지). 여기서 Step은 키오스크 사용을 이루는 진행 단위임(예: 시작, 입력, 감상, 종료). 끝나면 임시 데이터 파기, 휘발됨 ([[시범콘텐츠 공통 사양#2. 세션]])
- **사용자**: 재방문에 걸쳐 진척과 자산이 누적되는 주체. 옵트인(선택 동의) 시에만 서버에 보관됨

## 나. 세 단계

성숙도 순으로 셋을 둠. 현재 구현 범위는 1, 2단계임.

| 단계 | 식별 방식 | 보관 | 비고 |
|---|---|---|---|
| 익명 1회성 | 식별자 없음 | 세션 종료 시 파기 | 옵트인 미동의 시 기본값 |
| 가명 학습 프로필 | 학습 토큰(무계정 가명, subject_id 참조) | 옵트인 시 서버 보관 | 현재 구현 대상 |
| 계정 | 로그인 자격증명 | 서버 보관 | 전방 호환 설계만, 현재 구현 밖 (§6) |
^user-tiers

- **subject_id**: 진척과 자산의 실제 소유자인 내부 식별자(서버 보관, 콘텐츠 무관). 토큰이나 계정은 이를 가리키는 자격증명일 뿐임 (§6 전방 호환과 연결)

# 3. 전체 플로우

## 가. 데이터 생애 흐름

사용자와 데이터의 생애를 단계로 정리함. 각 단계 끝의 `(→§5)`는 그 단계를 실행하는 작업 단위임. 단계가 만지는 데이터는 §4 서버 데이터 모델에 정의함. 1번 익명 진입은 서버 작업이 없어 작업 단위 태그가 없음.

1. **익명 진입**: 식별자 없이 세션 시작. 서버 누적 없음 (세션은 [[시범콘텐츠 공통 사양#2. 세션]] 소관)
2. **옵트인**: 학습 프로필 생성에 선택 동의. 미동의 시 1번에 머묾 (→§5.가)
3. **발급(식별)**: subject_id 생성, 프로필 생성 (→§5.가)
4. **세션 중 누적**: 진척과 자산 참조를 프로필에 쌓음 (→§5.라)
5. **세션 종료**: 세션 데이터 파기, 프로필 서버 보관, 학습 토큰(QR) 발급 또는 갱신, 토큰 해시 저장 (→§5.나)
6. **재방문 이어하기**: 토큰 스캔으로 프로필 복원, 동의 약관 생략 (→§5.다)
7. **콘텐츠 횡단 누적**: 한 subject_id가 여러 콘텐츠 진척과 자산을 모음 (→§5.라)
8. **동의 변경과 철회**: 동의를 바꾸거나 철회함. 철회 시 프로필과 토큰 삭제, 1번 익명으로 되돌림 (→§5.마)

## 나. 플랫폼별 적용

사용자 연속성 사양은 전 플랫폼에 적용하되, 개인 식별과 누적의 구현은 환경에 따라 다름. 환경별로 토큰 사용과 프로필 누적 정책을 정리함.

| 환경 | 토큰 사용 | 프로필 누적 | 비고 |
|---|---|---|---|
| 키오스크 (1인) | 사용 | 개인별 누적 | 개인이 직접 토큰을 스캔해 식별과 누적이 자연스러움 |
| 미디어 케이브 체험형 | 사용 | 개인별 누적 | 관객이 직접 참여해 조작 (예: 풍물, 상모놀이). 개인이 자기 토큰으로 입장 |
| 미디어 케이브 순수 관람형 | 미사용 | 익명 통계만 | 보기만 하는 공연형 (예: 탈춤 군무, 외줄, 곤두질). 개인 식별 어려움. 개인 토큰 메커니즘은 확인 필요 (§7) |

# 4. 서버 데이터 모델

## 가. 엔티티와 저장 값

플랫폼이 서버에 누적하는 데이터를 분류, 값, 보관과 파기로 정리함. 세션 휘발 데이터는 [[시범콘텐츠 공통 사양#2. 세션]] 소관임. 정량 보관 기간은 §4.다에 모음.

| 데이터 | 분류 | 값과 구성 | 보관과 파기 |
|---|---|---|---|
| subject_id | 가명 식별자 | 콘텐츠 무관 내부 식별자, 진척과 자산의 실제 소유자 | 서버 보관, 프로필과 동일 수명, 철회 시 삭제 |
| 학습 토큰 | 자격증명(베어러) | 고엔트로피 불투명 값, subject_id로 매핑 | 사용자 QR 소지 + 서버 해시 저장, 유효 시간은 §4.다 |
| 프로필 | 가명 개인정보 | subject_id에 연결된 진척, 자산 참조, 동의 기록 | 옵트인 시 서버 보관, 철회 시 삭제, 보관 기간 §4.다 |
| 진척 | 가명 개인정보 | 콘텐츠별 진척 키 (병합 규칙 §5.라) | 프로필에 종속 |
| 자산 참조 | 가명 개인정보 | 산출물 참조, 원본 식별정보(얼굴, 영상)는 미보관 | 프로필에 종속, 원본 자산 저장소 정책은 각 기획서 |
| 동의 기록 | 가명 개인정보 | 옵트인 동의 상태와 약관 버전 | 프로필에 종속, 철회 시 삭제 |
| 익명 통계 | 익명(비식별) | 유저 수, 완주율, 오류율 등 집계 지표 | 프로필과 분리 저장, 개인 미연결 |

콘텐츠별 누적과 토큰 상태의 잠정 스키마임 (확인 필요, 구현 전 확정).

- **진척 키**: `{종목ID}:{콘텐츠ID}:{항목}` 네임스페이스로 콘텐츠 간 충돌 방지
- **자산 참조**: 산출물 저장소 경로나 ID, 원본 식별정보(얼굴, 영상)는 미포함
- **병합 규칙**: 같은 subject_id의 여러 콘텐츠 진척을 키 기준으로 병합, 같은 키는 최신 우선. 동시 갱신은 idempotency 키로 중복 방지 (상세 작성 예정)
- **토큰 상태**: active(유효), rotated(회전 교체), revoked(철회 폐기), expired(유효 시간 만료). 회전 시 기존 토큰은 rotated로 두고 유예 후 폐기, 복원은 active만 허용 (§5.다)

## 나. 식별과 비연결 설계

서버 누적 데이터는 직접 식별정보와 묶지 않는 비연결 설계를 따름.

- **익명 통계**: 익명 통계(개인을 식별하지 않고 집계하는 플랫폼 사용 지표, 예: 유저 수, 완주율, 오류율)는 신원을 알 수 있는 정보와 묶지 않음
- **진척의 가명 연결**: 학습 프로필 진척은 가명 식별자 subject_id에만 붙이고, 얼굴이나 영상, 연락처 같은 직접 식별정보와 묶지 않음
- **한계**: 직접 식별정보를 안 붙였어도 진척과 자산이 쌓이면 누구인지 좁혀질 수 있어 완전 익명으로 보지 않음. 가명 개인정보(직접 식별자 없이 가명에만 연결된 개인정보)로 보호함
- **횡단 누적 통제**: 콘텐츠 횡단 누적은 재식별 위험을 더 키우므로 아래 통제를 함께 적용함
	- 최소 수집: 학습 목적에 필요한 진척과 자산만 보관하고, 원본 식별정보(얼굴, 영상)는 프로필에 두지 않음
	- 목적 제한: 프로필 데이터는 학습 연속성과 도제 피드백 용도로만 사용함
	- 접근 통제: subject_id 기반 접근에 권한과 감사 로그를 두고, 감사 로그에서 개인정보를 제외함
	- 프로필 분리: 익명 통계와 옵트인 프로필을 분리 저장함

세션 1회 데이터(연락처 등)의 개인정보 원칙은 [[시범콘텐츠 공통 사양#6. 개인정보와 가드레일 원칙]]을 따름.

## 다. 보관과 파기 기준

연속성 관련 보관 기간과 토큰 수명의 잠정 기본값을 한 곳에 모음. 정량값은 이 표에만 두고, 다른 절은 본 절을 참조함. 구현과 운영, 규정 검토 단계에서 확정함 (근거 등급은 §9 참고).

| 파라미터 | 잠정 기본값 | 확정 시점 | 적용 대상 |
|---|---|---|---|
| 프로필 보관 기간 | 규정 검토 후 확정 (확인 필요) | 규정 검토 | 프로필, subject_id |
| 학습 토큰 유효 시간 | 확인 필요 (프로필 보관 기간 범위 내) | 구현 | 학습 토큰 |
| 토큰 회전 주기 | 확인 필요 | 운영 | 학습 토큰 |
| QR 화면 표시 시간 | 짧게 (확인 필요) | 구현 | QR 표시 |

# 5. 작업 단위별 실행

§3 전체 플로우의 단계를 구현 작업으로 쪼갬. 각 작업은 트리거, 입력, 처리 규칙, 출력, 저장으로 정의함. 저장 대상은 §4 데이터 모델, 보관 기간은 §4.다를 따름.

## 가. 옵트인과 프로필 생성

- **트리거**: 사용자가 학습 프로필 생성에 선택 동의 (플로우 2~3)
- **입력**: 동의 의사, 세션 컨텍스트
- **처리 규칙**: subject_id 생성, 프로필 생성, 동의 기록 적재
- **출력**: subject_id (내부 식별자)
- **저장**: 프로필 (§4.가). 보관 기간 §4.다
- **미동의 경로**: 익명 1회성 유지, 서버 누적 없음

## 나. 토큰 발급과 갱신

옵트인 학습자에게 학습 토큰(QR)을 발급하거나 갱신함. 베어러 방식이라 토큰을 가진 사람이 곧 접근 권한을 가지므로 아래 보안 규칙을 처리에 명시함 (확인 필요).

- **트리거**: 옵트인 학습자의 세션 종료 시점 (플로우 5). 최초 발급도 세션 종료 때 일어남
- **입력**: subject_id
- **처리 규칙**
	- 토큰 값: 추측 못 하게 무작위성을 높이고(고엔트로피), 의미 정보를 안 담는 불투명 값으로 만듦. subject_id를 직접 담지 않음
	- 저장: 서버에 원문이 아니라 해시로 저장함 (유출돼도 토큰 복원 불가)
	- 생명주기: 주기적 교체(회전), 폐기, 재발급, 토큰 값 중복 방지, 스캔 시도 횟수 제한(rate limit). 상태 전이는 §4.가
	- 유출 대비: 접근 토큰과 분리, 감사 로그에서 개인정보 제외, 분실이나 도난 시 복구 불가 고지
- **출력**: 학습 토큰(QR). 사용자가 소지함
- **표시와 수명**: QR 화면 표시 시간은 짧게 둠(훔쳐보기 방지). 토큰 유효 시간은 재방문 이어하기에 맞춰 정함(짧게 두면 연속 플레이가 끊김). 정량값은 §4.다
- **저장**: 학습 토큰 해시 (§4.가)

## 다. 이어하기 복원

- **트리거**: 재방문 시작 화면에서 이어하기로 토큰 스캔 (플로우 6)
- **입력**: 스캔된 학습 토큰(QR)
- **처리 규칙**: 토큰 해시로 subject_id를 조회해 프로필을 복원함. 진척과 직전 동의 기록을 불러오고, 동의 약관을 다시 받지 않음 (동의 기록은 토큰이 아니라 서버 프로필에 있음)
- **출력**: 복원된 세션 (진척 이어받기)
- **저장**: 없음 (읽기 전용 복원)
- **무효 토큰 경로**: 토큰 상태가 expired(만료)나 revoked(철회)거나 서버 해시와 불일치하면 복원을 거부하고 익명 1회성으로 진행함. 복원은 active 토큰만 허용 (상태는 §4.가, 재발급은 §5.나)
- **미옵트인 경로**: 토큰이 없으면 이어하기를 쓰지 않고 익명 1회성으로 진행함

## 라. 콘텐츠 횡단 누적

- **트리거**: 옵트인 사용자가 여러 콘텐츠를 사용 (플로우 4, 7)
- **입력**: subject_id, 콘텐츠별 진척과 자산
- **처리 규칙**: 한 subject_id가 여러 콘텐츠의 진척과 자산을 함께 누적함. 예: 만든 탈([[덧뵈기]]), 만든 꼭두각시 이야기([[박첨지놀이]]) 등을 같은 프로필에 모음
- **출력**: 갱신된 프로필 (진척과 자산 참조 추가)
- **저장**: 콘텐츠별 진척 키, 자산 참조 (§4.가)
- **미정**: 누적 데이터 모델의 병합과 충돌 상세는 §4.가 잠정 스키마를 따르며 구현 전 확정함 (작성 예정)
- **효과**: 한 종목 한 콘텐츠에 갇히지 않고 플랫폼 전체에서 돌아오는 학습자의 도제 경험이 이어짐

## 마. 동의 변경과 철회

- **트리거**: 학습 프로필 관리 진입점 (플로우 8)
- **입력**: 본인 식별 수단 (진입점에서 프로필 특정, 확인 방식은 아래 미정)
- **처리 규칙**: 재방문자는 이어하기로 동의 약관을 건너뛰므로, 복원된 동의를 바꾸거나 철회하는 경로를 별도로 둠. 선택 동의를 켜고 끄거나, 철회 시 프로필과 토큰을 삭제해 익명 1회성으로 되돌림
- **출력**: 변경된 동의, 또는 철회 완료(프로필과 토큰 삭제, 익명 1회성)
- **저장**: 동의 변경 시 갱신된 동의 기록 (§4.가). 철회 시 프로필과 함께 삭제되어 동의 기록도 사라짐 (철회 감사 레코드 보존은 §7 미결)
- **미정**: 진입점 위치와 본인 확인 방식은 UX와 규정 검토 단계에서 확정함 (확인 필요)

# 6. 전방 호환 (향후 계정 확장, 현재 구현 밖)

- **적용 시점**: 현재는 학습 토큰(무계정 가명)만 구현. 아래는 나중에 계정(분실 복구, 기기 간 연속성)을 붙일 때를 위한 방향이며 이번 구현 범위가 아님
- **설계 방향**: 로그인 자격증명에서 subject_id를 찾는 경로를 인증 모듈로 분리. 한 식별자가 토큰과 계정 등 여러 자격증명을 갖도록 데이터 모델을 열어 둠
- **구현 전 정의 필요**(작성 예정):
	- 상태 모델: 식별자(subject_id), 자격증명(credential), 프로필(profile)
	- 처리 규칙: 계정 연결, 복수 토큰 병합, 충돌, 철회, 부분 실패, 재시도와 idempotency
	- 분리 규칙: 익명 통계와 옵트인 프로필 분리

# 7. 미결 항목 (확인 필요)

설계와 구현, 규정 검토 단계에서 닫아야 할 미결 항목임. 닫히기 전까지 단정하지 않음.

- 미디어 케이브 다중 환경의 학습 토큰 식별과 누적 메커니즘 (§3.나)
- 프로필 보관 기간, 학습 토큰 유효 시간과 회전 주기 (§4.다, 규정 검토와 운영에서 확정)
- 계정 전방 호환의 식별자, 자격증명, 프로필 상태 모델과 병합, 철회 규칙 (§6)
- 철회 이행 감사 레코드 보존 여부 (개인정보 없는 비식별 기록, 규정 검토)
- 아동과 기관 사용의 보호자, 기관 동의, 열람과 삭제권, 테넌트 분리 (규정 검토)
