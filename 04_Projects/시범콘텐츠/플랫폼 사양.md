> 키오스크 시범콘텐츠가 1년차에 공유하는 플랫폼 계층 정본. 콘텐츠 독립 개발과 런처 통합, 결과물 저장과 다운로드 서버, 익명 1회성 사용자 모델을 정의함. 1년차는 계정과 이어하기 없이 콘텐츠를 우선 개발함. 1회 사용(세션) 골격은 [[시범콘텐츠 공통 사양]], 하드웨어는 [[디바이스 사양]], 디지털 도제 연속성(이어하기, 학습 프로필)은 2차연도 전방 설계로 §6에 보존함.

# 1. 개요

## 가. 플랫폼의 정의

키오스크 시범콘텐츠 5종을 한 플랫폼에서 운영하는 공용 소프트웨어 계층임. 콘텐츠 고유 설계 밖의 공통 시스템(런처, 서버, 결과물 호스팅, 사용자 모델)을 담음.

- **공용 계층**: 콘텐츠(덜미, 덧뵈기 등) 고유 설계와 분리해, 콘텐츠를 가로지르는 공통 시스템을 플랫폼이 담당함
- **단일 진입**: 단일 키오스크 플랫폼에서 콘텐츠를 선택해 진입함. 콘텐츠는 각자 독립 개발하고 런처로 메뉴만 통합함 (§2)
- **1년차 운영 모델**: 계정과 이어하기 없이 익명 1회성으로 운영함. 서버는 결과물 저장과 다운로드만 가동함. 학습 연속성(이어하기, 학습 프로필, 콘텐츠 횡단 누적)은 2차연도로 둠 (근거 §1.다, 전방 설계 §6)

## 나. 적용 범위

- **본 문서 소관**: 콘텐츠 통합과 런처(§2), 서버(§3), 결과물 전송과 호스팅 백엔드(§4), 사용자 모델(§5), 2차연도 연속성 전방 설계(§6)
- **공통 사양과의 경계**: 한 번의 사용(세션, 휘발)과 그 골격은 [[시범콘텐츠 공통 사양]]이 정본임. [[시범콘텐츠 공통 사양#2. 세션]], [[시범콘텐츠 공통 사양#5. 공통 화면]](결과물 전송 화면 포함), 기술 구성([[시범콘텐츠 공통 사양#7. 기술 구성 (6영역 템플릿)]], AI와 STT와 TTS와 디지털 휴먼 등), [[시범콘텐츠 공통 사양#8. 개인정보와 가드레일 원칙]]은 본 문서가 다루지 않음
- **디바이스와의 경계**: 키오스크 등 물리 하드웨어는 [[디바이스 사양]]이 정본임
- **제외 (각 콘텐츠 기획서 소관)**: 콘텐츠 고유 상호작용과 기획(플롯, 채점, 페르소나 등), 콘텐츠별 결과물 형식과 자산 저장 정책

## 다. 1년차 범위 결정 (근거)

1년차 플랫폼 범위는 아래 세 정본으로 한정함. 미승인 문서(로드맵, 기획서 등)는 근거로 쓰지 않음.

- **콘텐츠 통합**: 콘텐츠는 각자 독립 개발하고 런처로 메뉴만 통합함. 빌드 단계 통합은 안 함 ([[큐랩셀빅 사전회의 - 2026-06-22#2. 핵심 합의]], [[1년차 셀빅 개발 준비자료#2. 2026년 셀빅 개발 콘텐츠]])
- **서버 범위**: 1년차는 결과물 저장과 익명 운영(결과물 다운로드)만 가동함. 학습 정보 저장과 이어하기는 2차연도에 추가함. 회원 정보 관리 방식은 추후 결정 대상임 ([[1년차 셀빅 개발 준비자료#4. 공용 시스템]], [[큐랩셀빅 사전회의 - 2026-06-22#바. 거버넌스와 1차연도 운영]])
- **2차연도 이관**: 통합과 RnD 요소는 2차연도로 둠. 1차연도 평가는 돌아가는 콘텐츠 시연으로 대비함 ([[컨소시엄 회의록 - 2026-06-22#바. 실증과 거버넌스]], [[큐랩셀빅 사전회의 - 2026-06-22#바. 거버넌스와 1차연도 운영]])

# 2. 콘텐츠 통합과 런처

콘텐츠를 가로지르는 통합 방식과 진입 앱을 정의함.

- **독립 개발**: 콘텐츠 5종은 각자 독립 개발함. 빌드 단계에서 하나로 합치지 않음 ([[큐랩셀빅 사전회의 - 2026-06-22#2. 핵심 합의]])
- **런처**: 콘텐츠를 메뉴로 묶는 단일 진입 앱임. 콘텐츠가 나온 뒤 통합 단계에서 조립함 ([[1년차 셀빅 개발 준비자료#4. 공용 시스템]])
- **선택 진입**: 런처에서 콘텐츠를 골라 들어가고, 콘텐츠 종료 시 런처로 돌아옴
- **미정**: 런처와 콘텐츠 사이의 호출 규약(실행, 종료, 복귀 처리)은 콘텐츠 개발이 구체적 요구를 끌어낸 뒤 통합 단계에서 확정함 (작성 예정)

# 3. 서버

## 가. 1년차 서버 범위

서버는 결과물 저장과 익명 운영만 가동함. 기능을 최소로 두어 콘텐츠 개발을 우선함.

- **가동 기능**: 결과물 저장과 결과물 다운로드. 기기 간 동기화는 없음 ([[1년차 셀빅 개발 준비자료#4. 공용 시스템]], [[큐랩셀빅 사전회의 - 2026-06-22#바. 거버넌스와 1차연도 운영]])
- **익명 운영**: 사용자 식별자와 학습 프로필을 두지 않음. 사용자 모델은 §5
- **2차연도 이관**: 학습 정보 저장과 이어하기는 2차연도에 추가함. 설계 방향은 §6
- **개발 주체**: 큐랩 또는 셀빅이 개발함 ([[큐랩셀빅 사전회의 - 2026-06-22#바. 거버넌스와 1차연도 운영]])

## 나. 저장 데이터 (1년차)

서버가 보관하는 데이터를 분류, 값, 보관과 파기로 정리함. 세션 휘발 데이터(세션 ID, 연락처 등)는 [[시범콘텐츠 공통 사양#2. 세션]] 소관이고, 그 개인정보 처리는 [[시범콘텐츠 공통 사양#8. 개인정보와 가드레일 원칙]]을 따름.

| 데이터   | 분류       | 값과 구성                       | 보관과 파기                       |
| ----- | -------- | --------------------------- | ---------------------------- |
| 결과물   | 산출물      | 콘텐츠가 생성한 다운로드용 산출물(전자책, 사진 등) | 다운로드 제공 기간만 보관, 만료 시 파기 (§4) |
| 익명 통계 | 익명(비식별)  | 유저 수, 완주율, 오류율 등 집계 지표      | 개인과 연결하지 않고 집계만 보관           |

- **사용자 식별 없음**: 1년차 서버는 subject_id, 학습 프로필, 학습 토큰을 두지 않음. 결과물과 익명 통계는 개인 식별자와 묶지 않음
- **결과물 원본 보호**: 얼굴이나 영상 같은 원본 식별정보는 다운로드 산출물 생성에 쓴 뒤 서버에 누적하지 않음. 콘텐츠별 자산 저장 정책은 각 기획서 소관
- **미정**: 결과물 다운로드 보관 기간과 파기 시점은 규정 검토와 운영에서 확정함 (확인 필요)

# 4. 결과물 전송과 호스팅

콘텐츠 산출물을 사용자에게 전달하는 백엔드를 정의함. 사용자가 보는 전송 화면 흐름은 [[시범콘텐츠 공통 사양#5. 공통 화면]]이 정본이고, 본 절은 그 뒤의 호스팅과 다운로드를 다룸.

- **전달 방식**: 결과물을 웹에 올려 다운로드로 제공함. 별도 모바일 앱은 만들지 않음 ([[큐랩셀빅 사전회의 - 2026-06-22#2. 핵심 합의]])
- **다운로드 접근**: 다운로드 링크나 QR을 발급함. 포토 결과는 인화 없이 이미지로 내려받게 함 ([[1년차 셀빅 개발 준비자료#4. 공용 시스템]])
- **백엔드 책임**: 결과물 업로드, 다운로드 페이지 호스팅, 링크와 QR 발급, 만료 파기
- **연락처 처리**: 결과물 전송에 쓰는 연락처는 세션 휘발 데이터로, 발송 후 즉시 파기함 ([[시범콘텐츠 공통 사양#8. 개인정보와 가드레일 원칙]])

# 5. 사용자 모델 (1년차)

1년차는 익명 1회성 사용자만 둠. 계정과 이어하기 없이 각 콘텐츠를 사용함.

- **익명 1회성**: 식별자를 두지 않음. 사용은 세션 단위로 일어나고 종료 시 휘발함. 서버 누적은 결과물과 익명 통계뿐임(§3.나)
- **회원과 로그인**: 6/22 회의는 서버에 "로그인 정도"가 필요하다고 보았으나, 1년차 셀빅 개발 준비자료가 1년차를 익명 운영으로 좁힘. 회원 정보 관리 방식은 추후 결정 대상이며 2차연도 학습 정보 설계와 직결됨 (미결 §7, [[큐랩셀빅 사전회의 - 2026-06-22#4. 미결 과제와 후속 액션]])
- **익명 통계**: 개인을 식별하지 않는 집계 지표(유저 수, 완주율, 오류율)만 둠. 개인 식별정보와 묶지 않음

# 6. 2차연도 전방 설계 (디지털 도제 연속성, 현재 구현 밖)

RFP 디지털 도제(Digital Apprentice) 요구는 다시 찾는 학습자의 연속 학습임 ([[rfp_제안요청서#가. 최종 목표]], [[rfp_제안요청서#3. 활용방안 예시]]). 1년차 익명 모델 위에 2차연도에 얹을 연속성 계층의 설계 방향을 보존함. 상세 데이터 모델과 작업 단위 명세는 2차연도 설계에서 확정함 (작성 예정).

## 가. 식별 단계 (성숙도)

식별 성숙도 순으로 셋을 둠. 1년차 구현은 익명 1회성뿐임.

| 단계        | 식별 방식                        | 보관                  | 적용 시점               |
| --------- | ---------------------------- | ------------------- | ------------------- |
| 익명 1회성    | 식별자 없음                       | 보관 안 함 (1회 사용 후 파기) | 1년차 (현재 구현, §5)     |
| 가명 학습 프로필 | 학습 토큰(무계정 가명, subject_id 참조) | 옵트인 시 서버 보관         | 2차연도               |
| 계정        | 로그인 자격증명                     | 서버 보관               | 전방 호환 설계 (§6.라)     |
^user-tiers

## 나. 핵심 모델

2차연도에 구현할 연속성의 핵심 개념임.

- **subject_id**: 진척과 자산의 실제 소유자인 내부 가명 식별자. 콘텐츠 무관, 서버 보관. 토큰이나 계정은 이를 가리키는 자격증명일 뿐임
- **학습 토큰**: 무계정 가명 자격증명(베어러). 사용자가 QR로 소지하고 서버는 해시로 저장함. 옵트인 학습자에게 세션 종료 시 발급하거나 갱신함
- **옵트인 프로필**: 선택 동의 시에만 생성하는 가명 개인정보. subject_id에 진척, 자산 참조, 동의 기록을 연결함
- **이어하기 복원**: 재방문 시작 화면에서 토큰을 스캔해 프로필을 복원함. 동의 약관은 다시 받지 않음(동의 기록이 프로필에 있음). 무효 토큰이면 익명 1회성으로 진행함
- **콘텐츠 횡단 누적**: 한 subject_id가 여러 콘텐츠의 진척과 자산을 함께 누적함. 한 콘텐츠에 갇히지 않고 플랫폼 전체에서 도제 경험이 이어짐

## 다. 비연결 보안 원칙

연속성 데이터는 직접 식별정보와 묶지 않는 비연결 설계를 따름.

- **가명 연결**: 진척과 자산은 subject_id에만 붙이고, 얼굴이나 영상, 연락처 같은 직접 식별정보와 묶지 않음
- **최소 수집**: 학습 목적에 필요한 진척과 자산만 보관하고, 원본 식별정보는 프로필에 두지 않음
- **목적 제한**: 프로필 데이터는 학습 연속성과 도제 피드백 용도로만 사용함
- **접근 통제**: subject_id 기반 접근에 권한과 감사 로그를 두고, 감사 로그에서 개인정보를 제외함
- **프로필 분리**: 익명 통계와 옵트인 프로필을 분리 저장함

## 라. 계정 전방 호환

가명 학습 프로필 다음 단계인 계정(분실 복구, 기기 간 연속성)을 붙일 때를 위한 방향임. 1년차와 2차연도 구현 범위 밖임.

- **설계 방향**: 로그인 자격증명에서 subject_id를 찾는 경로를 인증 모듈로 분리함. 한 식별자가 토큰과 계정 등 여러 자격증명을 갖도록 데이터 모델을 열어 둠
- **구현 전 정의 필요**(작성 예정): 식별자와 자격증명과 프로필 상태 모델, 계정 연결과 복수 토큰 병합과 충돌, 철회와 부분 실패와 재시도

# 7. 미결 항목 (확인 필요)

설계와 구현, 규정 검토 단계에서 닫아야 할 미결 항목임. 닫히기 전까지 단정하지 않음.

- 런처와 콘텐츠 사이 호출 규약(실행, 종료, 복귀) (§2)
- 결과물 다운로드 보관 기간과 파기 시점 (§3.나, §4, 규정 검토와 운영에서 확정)
- 회원 정보 관리 방식과 학습 기록 포함 여부 (§5, 2차연도 학습 정보 설계와 직결, [[큐랩셀빅 사전회의 - 2026-06-22#4. 미결 과제와 후속 액션]])
- 2차연도 연속성의 상세 데이터 모델과 작업 단위 명세, 보관 기간과 토큰 파라미터 (§6, 규정 검토와 구현에서 확정)
- 아동과 기관 사용의 보호자, 기관 동의, 열람과 삭제권 (2차연도 연속성과 함께 규정 검토)
