> 버나(접시돌리기)를 소재로, 유저가 버나잡이가 되어 센서 막대로 버나를 돌리는 묘기와 대화자 매호씨와의 재담 대거리를 동시에 수행하는 키오스크 체험 시범콘텐츠 개발 문서. 묘기 유지와 재담 적절성을 함께 채점해 신명(興) 게이지로 보상하고 난이도를 올림. 한 판 결과는 점수와 등급을 담은 기념 기록증(성적표)으로 만들어 전송함. [[콘텐츠 기획서 작성 양식]] 적용. 골격 단계로 점차 채움.

# 1. 개요

- **콘텐츠 정의**: 버나(접시돌리기)를 소재로 한 묘기와 재담 동시 체험 키오스크 콘텐츠. 유저가 버나잡이가 되어 묘기를 부리면서 매호씨의 도발 재담에 받아치는 능동 체험임
- **소재**: 남사당놀이 연희 종목 버나(접시돌리기) ([[버나]]), 재담 상대역 [[매호씨]]
- **목표 경험**: 버나의 전통 골격(묘기놀음과 매호씨 재담의 결합)은 고정하고, 유저가 직접 버나를 돌리며 매호씨와 재담을 주고받아 자기만의 한 판을 완성함
- **핵심 메커닉**: 묘기 유지(센서 막대 균형)와 재담 적절성(반응 윈도우 선택)을 동시에 채점해 신명(興) 게이지로 보상하고, 게이지가 오르면 더 어려운 묘기와 빠른 재담 공세로 난이도를 올림 (상세 §4.다 묘기와 재담 채점)
- **결과물 (기념 기록증 추가 확정)**: 한 판 결과로 신명 게이지 점수와 등급, 묘기 통계를 담은 기념 기록증(성적표)을 만들어 전송함(2026-07-01 사용자 결정)
	- 콘셉트에는 없던 산출물이나 자매 체험(나만의 탈춤, 나만의 꼭두각시)과의 일관성과 매력도를 위해 더함
	- 기록증은 사전 제작 템플릿에 세션 점수를 결정적으로 얹는 방식이라 AI 생성이 아님. 생성 없는 체험형을 유지함(§4.아 AI 가드레일)
	- 리플레이 영상은 더 무거운 확장 옵션으로 후순위임(작성 예정)

# 2. 세션 개요

세션을 한눈에 파악하는 절. 세션 정의와 흐름을 담고, 세션 데이터 상세는 §5.가 세션과 데이터, Step별 상세 명세는 §3 Step 상세에 둠.

## 가. 세션 정의

1회 완결로 버나 한 판(묘기와 재담)을 벌이는 세션임. 컨테이너 정의와 라이프사이클은 공통 정의를 따름.

![[시범콘텐츠 공통 사양#^session-def]]

## 나. 세션 흐름

Step 1 인트로(동의) → Step 2 버나 돌리기(도입) → Step 3 매호씨 재담 대결(핵심, 돌리기와 동시) → Step 4 마무리와 기록증 생성 → Step 5 결과물 전송 → Step 6 종료와 리셋

- **분기**: 대부분 이탈(미동의, 터치 미입력 타임아웃)로 Step 6 직행
- **병행**: Step 3(묘기 돌리기와 재담 대거리 동시), Step 4(백그라운드 기록증 생성 + 포그라운드 마무리 연출)
- **파기**: Step 6 종료 시 세션 임시 데이터 파기(기념 기록증 결과물은 다운로드 만료 시 파기, 연락처 미수집)

# 3. Step 상세

각 Step의 명세를 담음. Step 정의와 명세 양식은 공통 모델을 따르고, 여러 Step에 걸친 공용 기능과 운영 파라미터를 함께 둠.

Step 정의와 명세 항목은 공통 모델을 따름.

## 나. 공용 기능

흐름이 호출하는 공용 기능(타임아웃, 가드레일, 개인정보 처리, 외부 호출 래퍼, 에러/fallback, 로그)은 아래 표를 따름. 기념 기록증 결과물을 화면 QR로 전달하며 결과물 전송 공용 기능을 씀(§5.나 개인정보와 연속성).

## 다. Step별 흐름

상세 레이아웃과 화면 확정은 [[버나 - 버나잡이 한 판 UI]] 소관임. 상세 동작과 규칙은 §4 구성 요소에 둠.

### 1) Step 1. 인트로 (시작 + 동의)

- **트리거**: 유저가 시작하기 터치
- **시스템**: 클라이언트 UI (§5.다 5 클라이언트 UI), 백엔드 (§5.다 3 백엔드)
- **화면 흐름**: 시작 화면 → 가이드 화면(센서 막대 잡는 법 포함) → 동의 약관 화면
- **프로세스**
	1. 백엔드: 신규 세션 생성 (익명)
	2. UI(가이드 화면): 진행 흐름과 센서 막대 사용법 안내
	3. UI(동의 약관 화면): 약관 표시, 동의 입력 감지(동의하고 시작이 동의, 그만두기가 미동의) (화면 타임아웃 미적용)
		- 호출 공용 기능: 터치 미입력 타임아웃
		- 분기: 그만두기 버튼 터치, 미동의, 또는 터치 미입력 타임아웃이면 Step 6 직행
	4. 백엔드: 동의 기록 저장
- **동의 항목**: 이용 약관 동의. 연락처를 받지 않아 결과물 전송용 개인정보 수집이 없고, 카메라 촬영도 없음
- **입력**: 터치 이벤트, 동의 결정
- **출력**: 세션 ID, 동의 기록
- **다음**: Step 2 (시작 화면은 Step 6 복귀 화면과 동일한 대기 상태)

### 2) Step 2. 버나 돌리기 (도입)

- **트리거**: Step 1 완료
- **시스템**: AI 시스템(묘기 채점, §4.다 묘기와 재담 채점), 클라이언트 UI(버나 시뮬 렌더러, §5.다 5 클라이언트 UI), 백엔드 (§5.다 3 백엔드)
- **화면 흐름**: 버나 돌리기 화면
- **프로세스**
	1. UI(버나 돌리기 화면): 센서 막대 보정과 묘기 입문 안내, 버나 회전 시작
		- 호출 공용 기능: 화면 타임아웃, 터치 미입력 타임아웃 (모션 화면, 센서 막대 입력 기준)
		- 분기: 화면 타임아웃 발동 시 체류 상한으로 보고 Step 3으로 정상 진행
		- 분기: 터치 미입력 타임아웃(센서 막대 입력 미검출)이면 유저 이탈로 보고 Step 6 직행
	2. AI 묘기 채점: 센서 막대 입력으로 버나 회전과 균형, 낙하를 물리 시뮬레이션하고 묘기 유지 채점 시작 (§4.나 버나 물리 시뮬레이션, §4.다 묘기와 재담 채점)
	3. UI(매호씨): 숙련도에 따라 실시간 추임새 (예: "얼씨구!", "밥 굶겠네", §4.바 매호씨 진행 호스트)
- **입력**: 센서 막대 동작
- **출력**: 버나 회전 상태, 묘기 유지 점수
- **다음**: Step 3

### 3) Step 3. 매호씨 재담 대결 (핵심 체험, 돌리기와 동시)

- **트리거**: 버나 돌리기 도입 완료(안정 구간 진입)
- **시스템**: AI 시스템(묘기와 재담 채점, §4.다 묘기와 재담 채점), 클라이언트 UI(버나 시뮬 렌더러, §5.다 5 클라이언트 UI), 백엔드 (§5.다 3 백엔드)
- **화면 흐름**: 버나 돌리기 화면(재담 대거리 오버레이)
- **프로세스** (돌리기 유지와 재담 대거리가 동시 진행, 묘기 유지가 끊기지 않게 한 화면에서 운영)
	1. UI(매호씨): 안정 구간에 도발 재담과 소리로 끼어들어 집중을 흔들고, 반응 윈도우를 엶 (§4.라 매호씨 재담 대결)
	2. UI(버나 돌리기 화면): 유저가 돌리기를 유지하며 손 기반 대거리 선택지(2~3개) 중 하나를 택함 (반응 윈도우 시간 제한, 동문서답 함정 선택지 포함)
		- 호출 공용 기능: 화면 타임아웃, 터치 미입력 타임아웃 (모션 화면)
		- 분기: 반응 윈도우 안에 선택이 없으면 무응답으로 판정(매호씨 승, 게이지 정체)
		- 분기: 화면 타임아웃 발동 시 체류 상한으로 보고 Step 4로 정상 진행
		- 분기: 터치 미입력 타임아웃(센서 막대 입력 미검출)이면 유저 이탈로 보고 Step 6 직행
	3. AI 채점: 대거리 적절성과 묘기 유지를 함께 판정해 신명 게이지를 갱신 (§4.다 묘기와 재담 채점)
		- 적절하면서 묘기를 유지하면 매호씨 말문 막힘으로 게이지 상승
		- 부적절하거나 묘기 실패면 매호씨 승으로 게이지 정체
	4. UI(매호씨): 판정에 따라 실시간 재담 응수 (§4.바 매호씨 진행 호스트)
	5. UI(버나 돌리기 화면): 난이도 상승 (더 어려운 묘기 예: 던질 사위, 더 빠른 재담 공세로 sub-step 1~4 반복)
- **입력**: 센서 막대 동작, 대거리 선택(손 기반 터치)
- **출력**: 묘기 유지 점수, 대거리 적절성 판정, 신명 게이지, 난이도 단계
- **다음**: 게이지 달성이나 체류 상한 도달 시 Step 4

### 4) Step 4. 마무리와 기록증 생성

- **트리거**: 신명 게이지 달성 또는 체류 상한 도달
- **시스템**: 클라이언트 UI (§5.다 5 클라이언트 UI), 백엔드(기록증 조립 §4.마 기념 기록증 생성, §5.다 3 백엔드)
- **화면 흐름**: 마무리 연출 화면. 기록증 생성은 백그라운드라 화면 없음
- **프로세스** (백그라운드와 포그라운드 동시)
	- **포그라운드: 마무리 연출**
		1. UI(버나 돌리기 화면): 게이지 결과 연출. 달성 시 환호 사운드(군중 추임새, 박수)로 버나 한 판 완성, 미달 시 매호씨가 적당히 눙치며 마무리
			- 호출 공용 기능: 화면 타임아웃
			- 분기: 화면 타임아웃 발동 시 Step 5로 정상 진행
	- **백그라운드: 기록증 생성**
		1. 백엔드: 신명 게이지 점수와 등급, 묘기 통계를 사전 제작 기록증 템플릿에 결정적으로 얹어 기념 기록증(성적표) 이미지를 조립함 (§4.마 기념 기록증 생성). AI 생성이 아니라 템플릿 합성이라 실시간 완료됨
			- 실패: 조립 실패 시 재시도(한도 §3.라 운영 파라미터) 후 fallback (기록증 없이 종료 안내)
- **입력**: 신명 게이지 종합 결과(점수, 등급, 묘기 통계)
- **출력**: 한 판 결과 연출, 기념 기록증(성적표)
- **다음**: Step 5

### 5) Step 5. 결과물 전송

- **트리거**: 마무리와 기록증 생성 완료
- **시스템**: 클라이언트 UI (§5.다 5 클라이언트 UI), 백엔드(결과물 호스팅, §5.다 3 백엔드), 외부 서비스(결과물 호스팅, §5.다 4 외부 서비스 연동). 전송 화면 공통 동작은 [[시범콘텐츠 공통 사양#라. 결과물 전송]] 준용
- **화면 흐름**: 기록증 미리보기 화면 → 결과물 QR 화면
- **프로세스**
	1. UI(기록증 미리보기 화면): 기념 기록증 미리보기
		- 호출 공용 기능: 화면 타임아웃
		- 분기: 화면 타임아웃 발동 시 sub-step 2(URL 발급)로 정상 진행
	2. 백엔드: 기념 기록증 결과물을 웹에 호스팅하고 만료형 다운로드 URL(유효기간 48시간, 개발 중 조정) 발급
		- 호출 공용 기능: 외부 서비스 호출 래퍼, 에러와 fallback
		- 분기: 업로드나 호스팅, URL 발급 실패 시 재시도(결과물 호스팅 재시도 2회 잠정), 한도 초과 시 상황 안내 뒤 Step 6 + 운영 알림
	3. UI(결과물 QR 화면): 발급된 다운로드 URL을 인코딩한 QR을 화면에 표시하고 스캔 안내와 다운로드 가능 기간을 함께 보여줌. 유저가 본인 휴대폰으로 스캔해 웹에서 기록증을 받고, 마침 선택 시 Step 6 진행
		- 연락처를 받지 않으므로 전송 동의나 입력 유효성 검증이 없음
		- 호출 공용 기능: 화면 타임아웃
		- 분기: 화면 타임아웃 발동 시 Step 6으로 정상 진행
- **입력**: 터치(마침)
- **출력**: 결과 페이지와 다운로드 URL, 화면 QR
- **파기**: 결과 페이지(기념 기록증)는 다운로드 만료(48시간) 시 파기, 연락처 미수집 (§5.가 세션 데이터 표)
- **다음**: Step 6

### 6) Step 6. 종료와 리셋

- **트리거**: 결과물 전송 완료 또는 미동의 또는 터치 미입력 타임아웃(유저 이탈)
- **시스템**: 클라이언트 UI (§5.다 5 클라이언트 UI), 백엔드 (§5.다 3 백엔드)
- **화면 흐름**: 마무리 인사 화면 → 시작 화면 복귀(Step 1과 공유)
- **프로세스**
	1. UI(매호씨): 마무리 인사
	2. 백엔드: 세션 종료와 임시 데이터 파기(센서 막대 입력 버퍼). 결과 페이지(기념 기록증)는 다운로드 만료(48시간)까지 유지 (§5.가 세션 데이터 표)
	3. UI(시작 화면): 시작 화면 복귀
- **입력**: 직전 Step 완료 또는 이탈 신호
- **출력**: 세션 종료, 임시 데이터 파기 완료
- **다음**: 다음 유저용 Step 1 대기

# 4. 구성 요소

콘텐츠를 이루는 요소를 의존 순(앞 요소가 뒤 요소의 입력 기반)으로 둠. 각 요소는 역할, 입력과 출력, 동작과 규칙, 기술 요건, 자산 요구, 가드레일과 실패, 의존을 모두 갖춘 독립 명세임.

## 가. 버나와 재담 고증 (공통 레퍼런스)

전통 고증 레퍼런스. 버나 도구와 묘기 사위, 매호씨 재담, 한 판의 거리 골격의 전통 기준을 정의해, 여러 구성 요소가 시뮬레이션 기준이나 재담 시드로 공유함. 공통 입력 기반이라 맨 앞에 둠.

- **버나 도구**: 쳇바퀴를 포개 만든 버나, 접시, 대접 등 돌리는 대상과 앵두나무막대기, 곰방대 등 돌리는 연장 ([[버나#2. 사용 도구]]). 시뮬레이션 대상 도구의 물리 특성 기준
- **묘기 사위**: 회전과 균형, 낙하, 던질 사위 등 묘기 동작의 고증 매핑 (작성 예정, 고증 자문 연계). §4.다 채점의 기준 동작
- **매호씨 재담**: 버나잡이와 주고받는 매호씨의 도발과 추임새 재담 ([[매호씨]]). §4.라 재담 대결의 시드
- **한 판 거리 골격**: 묘기 입문(도입), 재담 대결(전개와 절정), 맺음(마무리)의 거리 골격
- **시각과 음향 정체성**: 버나 도구 양식과 풍물 장단, 추임새의 전통 정합성 유지 (작성 예정)
- **의존**: 선행 의존 없음(기반). 본 레퍼런스를 §4.나 물리 시뮬레이션(도구 특성), §4.다 채점(기준 동작), §4.라 재담 대결(재담 시드), §4.아 가드레일(전통 왜곡 판정 기준)이 공유함

## 나. 버나 물리 시뮬레이션 (Step 2~3)

- **역할**: 센서 막대 입력을 받아 버나 회전과 균형, 낙하를 실시간 물리 시뮬레이션함. 묘기 체감을 만드는 기반 엔진
- **입력과 출력**: 입력은 센서 막대 동작(각도, 속도 등, 센서 규격 확인 필요). 출력은 버나 회전 상태(회전 속도, 균형 기울기, 낙하 여부)
- **동작과 규칙**: 센서 막대 동작을 버나 회전에 연동해 균형과 낙하를 시뮬레이션함. 도구별(버나, 접시, 대접) 물리 특성은 §4.가 고증 기준. 묘기 유지 채점(§4.다)의 입력 신호를 제공함
- **기술 요건**: 실시간 물리 시뮬레이션 엔진과 센서 막대 입력 처리. 센서 종류(관성 센서 등)와 막대 폼팩터, 보정 방식은 미정(확인 필요). 판정 기준은 입력 지연(프레임률), 시뮬레이션 안정성. 서버와 온디바이스 여부 확인 필요
- **자산 요구**: 버나 도구 3D 모델과 물리 파라미터(§4.사 콘텐츠 자산), 풍물 장단 음원(§4.사 콘텐츠 자산)
- **가드레일과 실패**: 센서 막대 입력이 안 잡히면 재시도 안내(한도 §3.라 운영 파라미터), 터치 미입력 타임아웃(센서 미검출) 시 Step 6
- **의존**: 입력은 §4.가 고증의 도구 물리 특성과 센서 막대(§5.다 2 하드웨어). 출력 회전 상태는 §4.다 묘기 채점이 사용

## 다. 묘기와 재담 채점, 신명 게이지 (Step 2~3, 핵심 메커닉)

- **역할**: 묘기 유지(물리 시뮬 균형)와 재담 적절성(반응 윈도우 선택)을 함께 채점해 신명(興) 게이지로 시각화하고, 달성 시 보상하며 난이도를 올리는 핵심 루프
- **입력과 출력**: 입력은 버나 회전 상태(§4.나 물리 시뮬레이션)와 대거리 선택 적절성(§4.라 매호씨 재담 대결). 출력은 묘기 유지 점수, 재담 적절성 판정, 신명 게이지 값, 난이도 단계, 채점 기록
- **동작과 규칙**
	- 채점 입력: 묘기 유지(균형 안정도)와 재담 적절성(대거리 선택의 적절성)을 종합함. 둘 다 좋으면 매호씨 말문 막힘으로 게이지 상승, 부적절하거나 묘기 실패면 매호씨 승으로 게이지 정체
	- 동시 수행 가중: 돌리기를 유지하면서 재담에 받아치는 동시 수행이 핵심이라, 한쪽만 잘해서는 게이지가 덜 오르게 가중함(가중치 확인 필요)
	- 난이도 상승: 게이지가 오르면 더 어려운 묘기(던질 사위 등)와 더 빠른 재담 공세로 난이도를 올림
	- 게이지와 보상: 달성 시 환호 사운드(군중 추임새, 박수) 보상, 미달 시 매호씨가 눙치며 마무리
	- 학습 진척(디지털 도제, 2차연도): 1차연도는 당회 채점만. 재방문 진척 누적(향상 곡선, 약점 피드백)은 2차연도 전방 설계로 둠 ([[플랫폼 사양#6. 2차연도 전방 설계 (디지털 도제 연속성, 현재 구현 밖)]])
	- 임계와 가중치, 난이도 곡선은 §3.라 운영 파라미터. 세부 설계(가중치, 게이지 임계, 미달 처리, 향상 곡선 산출)는 작성 예정
- **기술 요건**: 묘기 채점은 물리 시뮬 균형값 기반 자체 규칙, 재담 채점은 사전 정의 선택지 적절성 매핑. 판정 기준은 채점 임계와 가중치, 실시간 처리 지연. 채점 정확도 검증 방법은 작성 예정. AI 명세는 [[시범콘텐츠 공통 사양#가. AI 시스템]] 준용
- **자산 요구**: 묘기 사위 채점 기준(§4.가 고증), 환호와 추임새 사운드(§4.사 콘텐츠 자산)
- **가드레일과 실패**: 입력이 안 잡히거나 신뢰도가 낮으면 재시도 안내(한도 §3.라 운영 파라미터), 지연 시 구간 점수 보류
- **의존**: 입력은 §4.나 물리 시뮬레이션과 §4.라 매호씨 재담 대결. 출력 게이지가 §3.다 4) Step 4 마무리 연출과 §4.마 기념 기록증 생성에 반영

## 라. 매호씨 재담 대결 (Step 3, 반응 윈도우와 선택지)

- **역할**: 매호씨가 도발 재담으로 끼어들어 반응 윈도우를 열고, 유저가 돌리기를 유지하며 대거리 선택지를 고르게 하는 인터랙티브 재담 층. 묘기에 재담 대결을 얹어 극성을 만듦
- **입력과 출력**: 입력은 안정 구간 진입 신호와 유저의 대거리 선택. 출력은 도발 재담 제시, 대거리 선택지(2~3개), 선택 적절성 신호(§4.다 채점 입력)
- **동작과 규칙**
	- 도발과 윈도우: 안정 구간에 매호씨가 도발 재담과 소리로 끼어들어 집중을 흔들고 반응 윈도우(시간 제한, §3.라 운영 파라미터)를 엶
	- 대거리 선택지: 사전 정의 선택지 2~3개를 제시함. 동문서답 함정 선택지를 섞어 적절성 판정에 변별을 줌
	- 적절성 판정: 선택의 적절성(매호씨 도발에 맞받았는가)을 사전 정의 매핑으로 판정해 §4.다 채점에 넘김. 무응답(윈도우 초과)은 매호씨 승
	- 사전 생성과 검수: 도발 재담과 대거리 선택지는 사전에 작성하고 가드레일 검수를 거침(런타임 자유 입력과 신규 생성이 없음, §4.아 AI 가드레일)
	- 세부 설계(재담 풀 구성, 선택지 적절성 매핑, 난이도별 공세 패턴)는 작성 예정
- **기술 요건**: 사전 정의 재담과 선택지 풀의 런타임 제시와 판정 로직. 자유 입력이나 신규 생성이 없어 런타임 생성 모델은 쓰지 않음(매호씨 음성은 사전 제작 또는 TTS, 확인 필요). 적절성 판정은 규칙 기반
- **자산 요구**: 매호씨 도발 재담과 대거리 선택지 풀(§4.사 콘텐츠 자산), 매호씨 음성과 추임새(§4.사 콘텐츠 자산)
- **가드레일과 실패**: 재담과 선택지 풀은 사전 가드레일 검수가 주 지점임(§4.아 AI 가드레일). 무응답은 매호씨 승으로 흐름 유지
- **의존**: 입력은 §4.가 고증의 매호씨 재담 시드. 출력 적절성 신호는 §4.다 묘기와 재담 채점이 사용. 연출은 §4.바 매호씨 진행 호스트

## 마. 기념 기록증 생성 (Step 4)

- **역할**: 한 판 결과(신명 게이지 점수와 등급, 묘기 통계)를 사전 제작 기록증 템플릿에 얹어 기념 기록증(성적표) 이미지를 만듦
- **입력과 출력**: 입력은 신명 게이지 종합 결과(점수, 등급, 묘기 통계, §4.다 묘기와 재담 채점). 출력은 기념 기록증 이미지(전송 대상)
- **동작과 규칙**
	- 결정적 합성: 사전 제작 기록증 템플릿(레이아웃과 버나 양식 배경)에 세션 점수와 등급, 통계를 얹는 결정적 합성임. AI 생성이나 자유 입력이 없어 새 콘텐츠가 생기지 않음
	- 생성 없는 체험형 유지: 결정적 템플릿 합성이라 런타임 생성 지점이 아니며, 안전은 템플릿 사전 검수로 갈음함(§4.아 AI 가드레일, [[시범콘텐츠 공통 사양#나. 가드레일 적용 3지점]] 적용 원칙)
	- 형식(이미지 규격, 파일 형식)은 구현 확정
- **기술 요건**: 템플릿 이미지 합성과 텍스트 오버레이. 키오스크 부하 고려해 서버에서 진행. AI 모델이 아닌 백엔드 조립 계층임(§5.다 3 백엔드)
- **자산 요구**: 기념 기록증 템플릿과 등급 스탬프(§4.사 콘텐츠 자산)
- **가드레일과 실패**: 기록증은 사전 검수된 템플릿에 세션 수치를 얹을 뿐이라 런타임 출력 검사 대상이 아님(사전 템플릿 검수로 갈음, §4.아 AI 가드레일). 조립 실패 시 재시도 후 fallback(기록증 없이 종료)
- **의존**: 입력은 §4.다 묘기와 재담 채점의 게이지 결과. 출력 기록증은 §3.다 5) Step 5 전송이 사용

## 바. 매호씨 진행 호스트

- **역할**: 버나잡이와 재담을 주고받는 대화자이자 대결 상대. 묘기에 도발과 추임새로 끼어들어 극적 재미를 끌어올리는 어릿광대 배역을 진행 호스트로 계승 ([[매호씨]], 공통 골격은 [[시범콘텐츠 공통 사양#6. 진행 호스트]])
- **동작과 규칙**: 숙련도에 따른 실시간 추임새(예: "얼씨구!", "밥 굶겠네")와 도발 재담. 다른 콘텐츠의 안내형 호스트(박첨지, 말뚝이, 산받이)와 달리 유저와 겨루는 대결 상대 성격을 겸함(§4.라 재담 대결 연동). 세부 페르소나(말투, 어휘, 반응 패턴)는 작성 예정
- **기술 요건**: 매호씨 호스트 렌더러는 공통 UI 컴포넌트임. 구현 정본은 §5.다 5) 클라이언트 UI. 렌더 방식과 음성(사전 제작 또는 TTS)은 확인 필요
- **자산 요구**: 매호씨 호스트 에셋(비주얼, 음성, 추임새와 재담 대사, §4.사 콘텐츠 자산)
- **가드레일과 실패**: 재담 대사 자산은 사전 가드레일 검수 대상(§4.아 AI 가드레일). 연출 실행 자체는 안전 검사 대상 아님
- **의존**: 전 Step 연출. 재담 대결(§4.라 매호씨 재담 대결)과 채점(§4.다 묘기와 재담 채점) 결과를 피드백
- **고증 주의**: 버나에서의 매호씨 역할은 위키 내부 고증 수준임([[매호씨#2. 종목별 역할]], 전용 권위 출처 보강 확인 필요). 세부 검증은 고증 자문

## 사. 콘텐츠 자산

제작과 발주, 견적 입력용 자산 목록. 정량(수량, 규격, 제작 방식)은 확인 필요(골격, 작성 예정). 각 자산이 어느 구성 요소에 쓰이는지 용도에 표기.

1. **버나 도구 3D 모델과 물리 파라미터** (시뮬레이션 자산)
	- 제작 방식: 외주 또는 자체(확인 필요)
	- 용도: 버나, 접시, 대접 등 돌리는 대상의 시뮬레이션 (§4.나 버나 물리 시뮬레이션, Step 2~3)
2. **묘기 사위 채점 기준 데이터** (채점 기준)
	- 제작 방식: 고증 자문, 자체
	- 용도: 묘기 동작 채점 기준 (§4.다 묘기와 재담 채점, Step 3)
3. **풍물 장단 음원** (음향)
	- 제작 방식: 무저작권, 자체, AI 생성
	- 용도: 묘기 타이밍과 분위기 (Step 2~3)
4. **환호와 추임새 사운드** (음향)
	- 제작 방식: 확인 필요
	- 용도: 신명 게이지 달성 보상 (Step 3~4)
5. **매호씨 도발 재담과 대거리 선택지 풀** (서사 데이터)
	- 제작 방식: 자체 작성 + 사전 가드레일 검수(작성 예정)
	- 용도: 재담 대결 도발과 선택지 (§4.라 매호씨 재담 대결, Step 3)
6. **매호씨 호스트 에셋** (캐릭터와 음성)
	- 제작 방식: 확인 필요(비주얼, 음성(사전 제작 또는 TTS), 대사)
	- 용도: 진행 호스트 (§4.바 매호씨 진행 호스트)
7. **기념 기록증 템플릿과 등급 스탬프** (출력 양식)
	- 제작 방식: 외주 또는 자체(확인 필요), 사전 가드레일 검수
	- 용도: 한 판 기록증(성적표) 레이아웃과 등급 스탬프 (§4.마 기념 기록증 생성, Step 4)
8. **키오스크 UI와 화면 그래픽** (UI 디자인)
	- 제작 방식: 외주 또는 자체(확인 필요)
	- 용도: 전 화면(상세는 [[버나 - 버나잡이 한 판 UI]]). 화면 수는 UI 설계에서 확정(잠정값)

## 아. AI 가드레일 (전 단계 횡단)

- **역할**: 매호씨 재담과 대거리 선택지 등 콘텐츠 자산의 안전성과 전통 정합성 검사
- **입력과 출력**: 입력은 검사 대상(사전 작성 재담과 선택지, 매호씨 대사). 출력은 통과 또는 차단 판정과 사유
- **동작과 규칙 (적용 3지점 매핑)**: 공용 기능 AI 가드레일을 준용하되, 본 콘텐츠는 런타임 자유 입력과 신규 생성물이 없어 사전 지점이 주 검사 지점임 ([[시범콘텐츠 공통 사양#나. 가드레일 적용 3지점]])
	- 사전(운영 전 생성): 매호씨 도발 재담과 대거리 선택지 풀, 호스트 대사, 기념 기록증 템플릿을 사전 검수함(주 지점)
	- 런타임 입력: 유저 입력이 사전 정의 선택지 택1이라 자유 텍스트 검사 대상이 없음(선택 무결성만 검증)
	- 런타임 출력: 사전 검수된 자산을 재생할 뿐 신규 생성물이 없어 출력 검사 대상이 없음. 기념 기록증도 사전 검수 템플릿에 세션 수치를 얹는 결정적 합성이라 새 생성물이 아님(§4.마 기념 기록증 생성)
- **정합 (공통 사양 예외 반영)**: [[시범콘텐츠 공통 사양#나. 가드레일 적용 3지점]]에 생성 없는 체험형 예외(적용 원칙)가 추가되어(2026-07-01 사용자 결정), 본 콘텐츠는 런타임 두 지점 검사 대상이 없어 사전 지점 검수로 갈음함. 기념 기록증 전송을 더해도 기록증은 결정적 템플릿 합성이라 새 생성이 아니어서 이 예외가 유지됨. 런타임에 AI 생성이나 자유 입력이 새로 생기면 그 지점 검사를 다시 적용함
- **기술 요건**: 부적절 콘텐츠 분류와 전통 왜곡 판정(사전 검수 중심). 외부 가드레일 API와 자체 기준 조합 검토(확인 필요)
- **자산 요구**: 부적절 재담과 전통 왜곡 판정 기준 데이터(작성 예정)
- **가드레일과 실패**: 사전 검수에서 위반 자산은 풀에서 제외함. 런타임 실패 처리는 §3.다 Step별 흐름의 타임아웃과 fallback을 따름
- **의존**: 횡단. §4.라 매호씨 재담 대결과 §4.바 매호씨 진행 호스트의 자산에 사전 적용하며, 전통 왜곡과 정합성 판정 기준은 §4.가 고증을 따름. 세부 정책(부적절 재담 분류, 전통 왜곡 판정)은 작성 예정

# 5. 공유 계층과 기술 구성

세션, 개인정보와 연속성, 기술 6영역은 [[시범콘텐츠 공통 사양]]과 [[플랫폼 사양]]을 따르고, 본 콘텐츠 고유분만 적음.

## 가. 세션과 데이터

라이프사이클과 Step별 동작은 [[시범콘텐츠 공통 사양#2. 세션]] 준용. 본 콘텐츠 고유 데이터(센서 입력, 채점)로 재정의함.

- **라이프사이클**: 생성(Step 1) → 갱신(Step 2~5 채점과 기록증과 전송) → 종료(Step 6 파기와 리셋)

세션이 담는 데이터를 분류, 값, 보관과 파기로 정리함. 본 콘텐츠는 기념 기록증 결과물을 화면 QR로 전달해 연락처를 받지 않으므로 세션이 저장하는 개인정보는 없음. 카메라도 쓰지 않아 얼굴 영상이 없음. 표는 어떤 값이 들어가는지까지만 적고, 타입과 저장 스키마 같은 구현 모델은 설계 단계에서 정함.

| 데이터 | 분류 | 값과 구성 | 보관과 파기 |
| --- | --- | --- | --- |
| 세션 ID | 시스템 | 세션 고유 식별자 | 세션 종료 시 파기 |
| 동의 기록 | 시스템 | 약관 버전 + 동의 시각 | 보관 (기간 확인 필요) |
| 센서 막대 입력 버퍼 | 콘텐츠 | 실시간 센서 막대 동작 스트림(시뮬레이션 입력) | 메모리 임시, 처리 직후 파기 |
| 묘기와 재담 채점 기록 | 콘텐츠 | 묘기 유지 점수, 재담 적절성, 신명 게이지, 난이도 단계 | 익명 통계 보관, 세션 식별 원본은 종료 시 파기 |
| 기념 기록증 | 콘텐츠 | 점수와 등급, 묘기 통계를 얹은 성적표 이미지 | 결과 페이지 임시 보관, 다운로드 만료(48시간) 시 파기 |

- **결과물 파기**: 결과 페이지(기념 기록증)는 다운로드 만료(48시간) 시 파기함. 연락처를 받지 않아 전송 수단별 분기가 없음
- **개인정보 최소화**: 결과물을 화면 QR로 전달해 연락처를 받지 않고, 카메라도 쓰지 않아 얼굴 영상이 없으므로 수집하는 개인정보가 없음. 채점 기록은 콘텐츠 데이터로 식별 원본을 세션 종료 시 파기하고 익명 통계만 누적함

## 나. 개인정보와 연속성

데이터별 보관과 파기는 위 가. 세션 데이터 표가 정본임. 본 절은 본 콘텐츠 고유의 개인정보 범위와 연속성 정책을 정의함.

- **개인정보 범위**: 없음
	- 결과물을 화면 QR로 익명 다운로드하며 연락처를 받지 않고, 카메라를 쓰지 않아 얼굴 영상이 없음
	- 센서 입력과 채점 기록, 기념 기록증은 콘텐츠 데이터로 개인정보가 아님. 식별 원본은 세션 종료 시 파기함
- **결과물 전달**: 화면 QR로 익명 다운로드하며 연락처를 수집하지 않음(Step 5 결과물 전송). 결과물 호스팅과 만료 파기 정본은 [[플랫폼 사양#4. 결과물 전송과 호스팅]]임
- **동의 범위**: Step 1 이용 약관. 연락처 전송 동의와 카메라 촬영이 없음
- **재방문 연속성 (2차연도 전방 설계, 1차연도 미적용)**: 학습 프로필, 이어하기, 학습 토큰, 콘텐츠 횡단 누적은 2차연도로 두며 1차연도는 익명 1회로 운영함. 모델과 보안은 [[플랫폼 사양#6. 2차연도 전방 설계 (디지털 도제 연속성, 현재 구현 밖)]] 정본(현재 구현 밖)
- **세부 정책 (작성 예정)**: 보관 기간 잠정값은 규정 검토 후 확정, 임의 추정 금지

## 다. 기술 구성

본 콘텐츠 구현 시스템을 영역별로 정리함. 영역 구분과 1차연도 공통 기술 방향(LLM, STT, 모션 인식 한계 등)은 [[시범콘텐츠 공통 사양#7. 기술 구성 (6영역 템플릿)]]을 따르고, 아래는 영역별 본 콘텐츠 구현 내용임.

### 1) AI 시스템

묘기와 재담 채점(물리 시뮬 균형값과 사전 정의 선택지 적절성 기반 자체 규칙), AI 가드레일(사전 검수 중심)로 구성됨. 본 콘텐츠는 런타임 생성 모델(LLM, 이미지 생성)을 쓰지 않음. 각 모듈 명세는 §4 구성 요소(§4.다 묘기와 재담 채점, §4.아 AI 가드레일)에서 다룸. 물리 시뮬레이션(§4.나)은 AI 모델이 아닌 시뮬레이션 엔진임.

### 2) 하드웨어 (키오스크)

공통 키오스크 하드웨어를 씀(물리 사양 정본은 [[디바이스 사양]], 공통 골격은 [[시범콘텐츠 공통 사양#나. 하드웨어 (키오스크)]]). 본 콘텐츠는 센서 막대 주변기기가 더해짐. 입출력 구성:

- **디스플레이**: 16:9 가로형 터치 (크기와 해상도 확인 필요)
- **센서 막대 주변기기**: 버나를 돌리는 동작을 감지하는 막대형 입력 장치(센서 종류, 폼팩터, 무선과 유선, 내구성 확인 필요). 콘셉트 고유 하드웨어 요건
- **음향 출력**: 풍물 장단과 매호씨 음성, 환호 사운드 (스피커 사양 확인 필요)
- **연산 유닛**: 본체 연산. 실시간 물리 시뮬 부하 고려(GPU 사양 확인 필요)
- **카메라**: 미사용(1차연도 기본 설계). 손 기반 대거리 선택은 터치가 기본이며 핸드 트래킹 구현은 확인 필요. 핸드 트래킹을 채택하면 카메라 영상 입력이 생겨 카메라 미사용(얼굴 영상 없음) 전제(§5.가, §5.나)를 재검토해야 함
- **네트워크**: 운영 모니터링 통신 (대역폭 확인 필요)

### 3) 백엔드

### 4) 외부 서비스 연동

- **결과물 전송 서비스 (기념 기록증)**
	- 채널: 화면 QR 1경로. 기록증을 결과 페이지로 묶어 웹에 호스팅하고 다운로드 URL을 QR로 표시. 연락처를 받지 않음
	- 결과 페이지: 만료형 다운로드 URL(48시간). 만료 전 재접근 허용
	- 저장과 파기: 저장 제공자, URL 만료, 파기 트리거(48시간) 명세 필요(세션 표와 정합). 제공자와 스토리지 확인 필요
- **AI API (외부 모델 사용 시)**: 매호씨 음성을 TTS로 합성할 경우의 TTS 서비스 등(확인 필요). 본 콘텐츠는 런타임 생성 모델을 쓰지 않아 외부 AI 연동이 최소임

### 5) 클라이언트 UI (키오스크 앱)

화면의 시각과 레이아웃 상세는 [[버나 - 버나잡이 한 판 UI]] 정본. 본 절은 공통 컴포넌트와 구현 기술만 적음.

- **공통 UI 컴포넌트**: 여러 화면이 재사용하는 컴포넌트. 매호씨 호스트 렌더러(역할 §4.바 매호씨 진행 호스트), 버나 시뮬 렌더러(회전과 균형 시각화), 재담 대거리 선택 오버레이, 신명 게이지
- **입력 수단**: 센서 막대, 터치(대거리 선택. 막대를 한 손으로 쥔 채 반대 손 터치로 확정, 2026-07-02). 핸드 트래킹 미채택
- **세션 종료와 리셋**: 화면 타임아웃과 터치 미입력 타임아웃 처리, 다음 유저용 시작 화면 복귀(Step 6)
- **구현 기술 (미정, 설계 단계 확정)**: 키오스크 앱 프레임워크, 센서 막대 연동 방식, 실시간 시뮬 렌더 방식. 구체 기술 선택은 아직 미정

### 6) 운영과 모니터링

- **가동 모니터링**: 키오스크 온라인과 오프라인, 센서 막대 연결과 장애 상태
- **사용 로그와 지표**: 유저 수, 완주율, Step별 이탈, 오류율
- **알림**: 센서 장애, 파기 실패 시 운영 알림(임계 §3.라 운영 파라미터)
- **에러 fallback**: [[시범콘텐츠 공통 사양#바. 운영과 모니터링]] 준용

# 6. 산출물

- **기념 기록증(성적표)**: 신명 게이지 점수와 등급, 묘기 통계를 사전 제작 템플릿에 얹은 이미지. 사용자 얼굴이나 영상은 담기지 않음. 사전 검수 템플릿에 세션 수치를 결정적으로 얹는 방식이라 AI 생성물이 아님
- **전송과 파기 정책**: §5.가 세션 데이터 표(결과물 파기)
- **형식과 규격 (구현 확정)**: 이미지 해상도, 파일 형식 등
- **리플레이 영상 (확장 옵션, 후순위)**: 한 판 리플레이 영상은 더 무거운 확장 옵션으로 후순위 검토(작성 예정)

# 7. 일정과 마일스톤 연계

- **개발 순서**: [[1차연도 셀빅 개발 준비자료#나. 콘텐츠 개발 순서]] 체험형 계열(실시간 물리 시뮬과 채점 스택). 센서 막대 주변기기 확보가 선행 의존. 세부 일정과 마일스톤은 미정

# 8. 리스크와 검증

- **고증과 저작권**: 검증위원회 자문, 저작권과 고증 확인. 버나에서의 매호씨 역할은 위키 내부 고증 수준이라 권위 출처 보강이 필요함([[매호씨#2. 종목별 역할]], 확인 필요)
- **확정 (결과물 범위)**: 한 판 기념 기록증(성적표) 생성과 화면 QR 전송을 추가함(2026-07-01 사용자 결정). 콘셉트에 없던 산출물이나 자매 일관성과 매력도를 위해 더함. 기록증은 사전 검수 템플릿에 세션 수치를 얹는 결정적 합성이라 AI 생성이 아님(§4.마 기념 기록증 생성, §6). 리플레이 영상은 후순위 확장 옵션
- **확정 (가드레일 3지점 정합)**: [[시범콘텐츠 공통 사양#나. 가드레일 적용 3지점]]에 생성 없는 체험형 예외(적용 원칙)를 추가함(2026-07-01 사용자 결정). 본 콘텐츠는 런타임 생성과 자유 입력이 없어 사전 지점 검수로 갈음하고, 기념 기록증도 결정적 템플릿 합성이라 이 예외가 유지됨(§4.아 AI 가드레일)
- **미결 (센서 막대 주변기기)**: 센서 종류와 막대 폼팩터, 무선과 유선, 내구성, 보정 방식이 미정. 주변기기 확보가 핵심 메커닉(§4.나 물리 시뮬레이션)을 가름(확인 필요)
- **확정 (대거리 입력 수단)**: 손 기반 대거리 선택은 센서 막대를 한 손으로 쥔 채 반대 손으로 터치하는 방식으로 확정함(2026-07-02 사용자 결정, §5.다 5 클라이언트 UI). 핸드 트래킹은 미채택이라 카메라 미사용(얼굴 영상 없음) 전제(§5.가, §5.나)를 유지함(핸드 트래킹 채택 시 영상 개인정보 처리 재검토가 필요했으나 미채택으로 해당 없음)
- **추가 리스크 (작성 예정)**: 그 외 리스크와 검증 항목
