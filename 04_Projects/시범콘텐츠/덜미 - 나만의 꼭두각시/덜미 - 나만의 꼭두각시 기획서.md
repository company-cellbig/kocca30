> 덜미(꼭두각시놀음)를 소재로, 유저가 자기 얼굴로 만든 목각 인형 아바타와 마주 서서 몸을 움직이면 인형과 그 내부 조작 구조가 실시간으로 따라 움직여, 덜미 인형이 실제로 어떻게 조종되는지를 보여주는 인형 연동 시연 체험 시범콘텐츠의 개발 기획서.

# 1. 개요

- **콘텐츠 정의**: 덜미를 소재로 한 인형 연동 시연 키오스크 콘텐츠. 유저가 자기 얼굴로 만든 목각 인형 아바타를 몸으로 움직여 보는 체험임
- **소재**: 남사당놀이 인형극 덜미
- **목표 경험**: 유저가 자기 얼굴 인형 아바타와 마주 서서 몸을 움직이고, 그 움직임을 만드는 실제 덜미 조작(대잡이의 손놀림)을 눈으로 확인하며 인형 조종의 원리를 익힘
- **핵심 메커닉**: 전신 포즈 추정으로 유저 움직임을 인형의 가동 부위에 실시간 매핑하고, 화면 우측의 인형 내부 조작 구조 뷰가 그 동작을 만드는 조작을 함께 시연함
- **결과 안내**: 채점과 반출 결과물(사진 저장, 파일 다운로드)이 없는 순수 시연 체험임. 신명 게이지가 연동 활동을 비추고 달성 시 환호로 보상함

# 2. 전체 플로우

1회 완결로 자기 얼굴 인형을 만들어 몸으로 움직여 보고 조작법을 확인하는 세션임. Step 1 인트로 → Step 2 얼굴 촬영 → Step 3 아바타 생성과 대기 화면(병행) → Step 4 인형 연동 시연(핵심) → Step 5 종료와 리셋.

- **중단 처리**
	- 대상: 진행 중 이탈(그만두기, 터치 미입력 타임아웃, 카메라 촬영 미동의, 얼굴 입력 가드레일 위반 한도 초과)과 실패(아바타 생성 실패, 카메라와 인식 계통의 지속 장애, 상태 조회 무응답)가 모두 이 공통 처리로 모임
	- 처리: 마무리 인사 화면을 건너뛰고, 세션을 종료해 파기한 뒤 시작 화면으로 돌아감(비완주 종료). 실패는 상황 안내 팝업을 띄운 뒤 진행하고, 이탈은 팝업 없이 진행함. 세션 생성 실패만 정리할 세션이 없어 종료 처리 없이 곧장 시작 화면으로 되돌림
	- 상세: 케이스별 조건과 처리는 [[#3.10 실패 처리]]와 [[#5.2 에러 케이스]]가 정본
- **병행**: Step 3에서 백그라운드 아바타 생성과 포그라운드 대기 화면이 동시 진행하고 상태 조회로 동기화함
- **파기**: Step 5 종료 시 남은 세션 임시 데이터(연동 활동 기록의 식별 원본)를 파기함. 영상 피드와 얼굴 캡처는 처리 직후 실시간 파기라 종료 시점에는 남지 않음. 3D 인형 아바타는 별도 저장소 보관이며 파기 시점은 규정 검토 후 확정함(세션 데이터 표 기준)

# 3. 공용 시스템

## 3.1 세션 데이터

### 3.1.1 역할과 목적

한 세션이 만드는 데이터를 담는 시스템. 전 Step이 같은 상태를 공유하게 하고, 데이터 종류별 보관과 파기를 관리하기 쉽게 함.

### 3.1.2 동작과 규칙

세션이 저장하는 데이터를 분류, 값, 보관 기간으로 정리함. 어떤 값이 들어가는지까지만 적고 데이터 타입과 저장 스키마는 설계 단계에서 정함. 얼굴이 담긴 데이터(영상 피드, 얼굴 캡처)에는 최소 보관 원칙을 적용함.

| 데이터 | 분류 | 들어가는 값과 구성 | 보관 기간 | 비고 |
|---|---|---|---|---|
| 세션 ID | 시스템 | 세션마다 부여되는 고유 식별자 | 보관 (잠정, 규정 검토 후 확정) | Step 1에서 생성. 디버깅과 품질 분석용 |
| 현재 언어 | 시스템 | 세션에 적용 중인 언어(기본 한국어) | 보관 (잠정, 규정 검토 후 확정) | 시작 화면 언어 선택에서 설정. 현지화 기준 |
| 현재 Step | 시스템 | 현재 진행 중인 Step | 보관 (잠정, 규정 검토 후 확정) | 진행 단계 기록 |
| 에러 유형 | 시스템 | 에러 발생 시 에러 케이스 유형 기록 | 보관 (잠정, 규정 검토 후 확정) | 디버깅과 품질 분석용 |
| 동의 기록 | 시스템 | 약관 버전, 동의 시각, 동의 항목(필수: 카메라 촬영) | 보관 (잠정, 규정 검토 후 확정) | 약관 버전 체계는 운영 단계에서 결정함 |
| 얼굴 캡처 | 콘텐츠 입력 | 아바타 생성 입력용 얼굴 프레임 | 메모리 임시, 아바타 생성 직후 파기 | Step 2 산출. 얼굴 포함 |
| 3D 인형 아바타 | 콘텐츠 생성 | 생성된 3D 아바타 자산 | 별도 저장소 보관 (파기 시점 규정 검토 후 확정) | Step 3 산출 |
| 연동 활동 기록 | 콘텐츠 생성 | 연동 활동량(가동 부위를 움직인 지속 시간과 부위 다양성), 신명 게이지 | 익명 통계는 보관, 식별 원본은 세션 종료 시 파기 | Step 4 산출 |
| 영상 피드 | 콘텐츠 입력 | 카메라 원본 스트림(얼굴 촬영, 전신 포즈 추정 입력) | 메모리 임시, 처리 직후 파기 | 디스크 저장 금지. 얼굴과 신체 포함 |

- **Step별 세션 동작**: Step 1 생성, Step 2~Step 4 갱신, Step 5 종료와 임시 데이터 파기와 리셋
- **서버 전송 시점 (이벤트 기반)**: 각 화면의 세션 데이터 갱신은 클라이언트 로컬 상태에만 반영하고, 서버로는 정기 전체 동기화 없이 이벤트 시점에만 전송함. 이어하기가 없는 1차연도 기준임
	- 단계 이동: 각 Step 진입과 종료 시 현재 Step을 전송함
	- 동의 기록: 이용 동의 화면에서 동의 확정 시 동의 이벤트(약관 버전, 동의 시각, 동의 항목)를 전송함. 클라이언트는 서버의 저장 확인 응답을 받은 뒤에만 다음 단계로 진행함(동의 기록 유실 방지)
	- 에러와 이탈: 에러 발생 시, 이탈(미동의, 얼굴 입력 가드레일 한도 초과 종료, 미입력 타임아웃 종료) 시 전송함
	- 생성 입력: 얼굴 캡처는 아바타 생성(Step 3) 트리거 시 전송함
- **3D 아바타 저장**: 3D 아바타는 재변환 비용을 아끼고 품질을 분석하려고 별도 저장소에 보관함(영상 피드와 얼굴 캡처의 메모리 임시와 파기 규칙은 개인정보 처리 참조)
- **분류 축과 개인정보 축**: 분류는 시스템, 콘텐츠 입력, 콘텐츠 생성 셋만 씀. 개인정보 여부는 분류와 직교하는 성질이라 분류 값이 아니라 비고에 적음(영상 피드, 얼굴 캡처가 해당)

## 3.2 개인정보 처리

### 3.2.1 역할과 목적

유저 얼굴과 신체가 담긴 데이터를 다루는 시스템. 쓰임이 끝난 촬영 데이터를 즉시 파기해 유출 위험을 낮춤.

### 3.2.2 동작과 규칙

세션이 다루는 개인정보를 개발이 지킬 구현 제약과 규정 검토가 확정할 정책 값으로 나눠 정리함. 프로그래머는 구현 제약을 스펙으로 지키고, 규정 검토 대기 항목은 검토 결과가 나오면 값을 채움.

#### 1) 구현 제약

- **개인정보 범위**: 어느 데이터가 민감정보라 메모리 전용으로 다뤄지는지 가르는 분류임
	- 얼굴과 신체 영상, 얼굴 캡처(영상 피드. 얼굴 촬영과 전신 포즈 추정에 쓰임)
- **카메라 동의 게이트**: 카메라 촬영(얼굴 촬영과 아바타 생성, 전신 포즈 추정)이 필수 동의임. 동의가 없으면 아바타 생성과 포즈 연동을 할 수 없어 세션을 진행하지 않음(Step 1 이용 동의, 진행 중 종료의 미동의 처리와 연결)
- **영상 피드와 얼굴 캡처 처리**: 메모리에서 임시로 처리한 뒤 즉시 파기하고, 디스크에 저장하거나 로그로 기록하지 않음. 얼굴 캡처는 아바타 생성이 끝나는 즉시 파기함. 사진이나 영상 등 반출 결과물을 만들지 않음
- **포즈 추정의 개인정보 표면**: 얼굴 촬영에 쓰는 카메라를 전신 포즈 추정에 함께 쓰므로 개인정보 표면이 더 늘지 않음

#### 2) 규정 검토 대기

- **동의 고지 문구**: 카메라 영상은 아바타 생성과 포즈 연동에만 쓰고 저장하지 않는다는 내용을 개인정보 수집과 이용 안내에 포함함. 정확한 안내 문구와 동의 범위는 규정 검토 후 확정함
- **보관 기간**: 3D 아바타 보관과 파기 시점 등 잠정값은 규정 검토 후 확정하며 임의 추정하지 않음
- **재방문 연속성**: 학습 프로필, 이어하기, 학습 토큰, 콘텐츠 횡단 누적은 2차연도 확장 설계로 두며 1차연도는 익명 1회로 운영함

## 3.3 언어 선택 시스템

### 3.3.1 역할과 목적

세션 전체에 적용할 언어를 정하는 관문. UI 카피와 AI 생성물(산받이 대사)을 유저가 고른 언어로 제공해, 다른 언어를 쓰는 유저도 자기 언어로 한 판 놀음을 체험하게 함.

### 3.3.2 입력과 출력

- **입력**: 유저의 언어 선택
- **출력**: 현재 언어(세션 데이터에 저장). 현지화 JSON(localization.json)에서 해당 언어값을 불러옴

### 3.3.3 동작과 규칙

- 유저가 언어를 선택하고 시작하기 버튼을 터치하면 현재 언어로 반영함. 기본값은 한국어임
- **현지화 범위**: UI 카피뿐 아니라 AI 생성물까지임. 산받이 진행 호스트 대사와 TTS, 안내 팝업을 현재 언어로 제공함. 지원 언어는 한국어와 영어를 우선 적용함

## 3.4 산받이 진행 호스트

### 3.4.1 역할과 목적

인형에게 말을 붙이고 관객과 대거리하던 덜미 산받이를 세션 진행 호스트로 세운 시스템. 그 전통 역할을 계승해 얼굴 촬영부터 마무리 인사까지 한 목소리로 잇고 덜미의 전통 정체성을 살림.

### 3.4.2 동작과 규칙

- **범위**: 전 Step 진행 호스트
- **페르소나**: 산받이 전통 인물과 화법(말투, 어휘, 반응 패턴)은 세부 설계에서 정함(작성 예정)
- **조작법 해설과 추임새**: 유저의 움직임에 맞춰 얹는 발화 묶음(대사 문안은 작성 예정)
	- 해설: 인형 조작법(대잡이의 손놀림)을 재담으로 풀어 설명함
	- 안내: 반영되지 않는 움직임(다리, 보행)을 재담으로 안내함
	- 마무리: 게이지 미달 시 눙치며 마무리함
- **발화 방식**: TTS 음성으로 대사를 재생하고 같은 대사를 화면에 텍스트로 표시함. 발화 중 다음 버튼을 누르면 발화를 중단하고 다음으로 진행함
- **표현 형식**: 본문 주기능을 가리지 않는 위치와 크기로 두고, 작업 집중이 우선인 화면(얼굴 촬영, 인형 연동 시연)에서는 작게 두거나 숨김
- **타임아웃 연동**: 발화 중에는 터치 미입력 타임아웃을 멈추고, 발화가 끝난 뒤 측정을 시작함
- **고증 주의**: 산받이 배역 해석은 덜미 채록본 수준의 추정임. 세부 검증은 고증 자문(확인 필요)

### 3.4.3 필요 리소스

- 산받이 호스트 캐릭터(비주얼, 애니메이션 가능하게 제작, 제작 방식 확인 필요)
- 산받이 TTS 보이스
- 추임새와 재담 대사(제작 방식 확인 필요)

### 3.4.4 실패와 복구

아바타 렌더나 TTS 재생이 실패하면 음성과 애니메이션 없이 대표 이미지와 텍스트 박스로만 진행함. 대사는 표시하고 세션은 계속함.

## 3.5 진행 중 종료

### 3.5.1 역할과 목적

유저에게 진행 중 그만둘 수단을 주는 시스템. 원치 않는 세션을 빨리 끝내 키오스크 회전율을 높임.

### 3.5.2 동작과 규칙

#### 1) 일반 규칙

- **처리**
	- 진행 중인 화면을 멈추고 마무리 인사 화면을 건너뛰어 세션 종료와 파기 후 시작 화면으로 복귀함(비완주 종료)
	- 유저 쪽 능동 이탈이라 상황 안내 팝업 없이 종료함

#### 2) 유저의 종료 선택 시 규칙

- **처리**
	- 그만두기 터치 시 그만두기 확인 팝업 표시
	- 그만두기 확인 시 종료 처리하고, 취소 시 원래 화면 복귀
- **적용 화면**
	- Step 1 가이드 화면, 이용 동의 화면
	- Step 2 얼굴 촬영 화면
	- Step 4 인형 연동 시연 화면
- **예외 (미적용)**
	- Step 1 시작 화면
	- Step 3 대기 화면 (작업이 도는 중이라 이탈로 보지 않음)
	- Step 5 마무리 화면 (처음으로 버튼과 화면 타임아웃으로 넘김)
- **그만두기와 동시 이벤트 처리 (카메라 화면)**: Step 2와 Step 4에서 그만두기가 카운트다운이나 타임아웃과 겹칠 때의 규칙임
	- 확정된 그만두기는 진행 중인 카운트다운과 포즈 연동을 멈추고 세션 종료로 감
	- 확인 팝업이 열린 동안에는 터치 미입력 타임아웃과 사람이나 얼굴, 포즈 미검출 측정을 멈춤(산받이 발화 중 멈춤과 같은 방식)
	- 종료는 한 번만 처리해 이중 종료를 막음

#### 3) 미동의 시 규칙

- **처리**
	- 이용 동의 화면에서 그만두기를 확정하거나 터치 미입력 타임아웃이 발동하면 카메라 촬영 미동의로 보고 종료 처리
	- 카메라 촬영 동의가 없으면 아바타 생성과 포즈 연동을 할 수 없어 세션을 이어 갈 수 없음

#### 4) 얼굴 입력 가드레일 위반 시 종료 규칙

- **처리**
	- 매 위반 시 위반 횟수가 표시된 안내 팝업 표시 후 재촬영 받고 3회(잠정) 위반 시 종료 처리
	- 위반 횟수는 화면마다 초기화하여 따로 셈

## 3.6 화면 타임아웃

### 3.6.1 역할과 목적

유저가 한 화면에 오래 머무는 것을 막아, 무인 키오스크가 한 유저에게 묶이지 않게 하는 시스템.

### 3.6.2 동작과 규칙

- **처리**
	- 한 화면에서 60초(잠정) 이상 머물면 그 화면의 정상 진행 경로로 넘어감
	- 화면별 오버라이드: 모션 화면(인형 연동 시연) 5분(잠정). 마무리 인사 화면은 처음으로 버튼이 주 종료라 기본값(60초, 잠정) 적용
	- 호스트 발화 중에는 측정을 멈추고, 발화 종료나 스킵 후 재개함(잠정)
- **예외**: 필수 입력, 가이드, 대기, 팝업 화면 미적용

## 3.7 터치 미입력 타임아웃

### 3.7.1 역할과 목적

입력이 끊긴 유저 이탈을 감지해 방치된 세션을 정리하고 키오스크 회전율을 높이는 시스템.

### 3.7.2 동작과 규칙

- **처리**
	- 한 화면에서 45초(잠정) 이상 터치나 동작 입력이 없으면 이탈로 보고 진행 중 종료 처리
	- 카메라와 모션 화면(얼굴 촬영, 인형 연동 시연)은 터치가 없는 화면이라 사람이나 얼굴, 포즈 미검출을 이탈 기준으로 삼음
	- 산받이 발화 중에는 측정을 멈추고, 발화가 끝나거나 스킵한 뒤부터 측정 시작
- **예외**: 대기 화면과 마무리 인사 화면 미적용

## 3.8 AI 가드레일

### 3.8.1 역할과 목적

입력과 생성물의 안전과 전통 정합성을 검사하는 시스템. 유해하거나 전통을 왜곡한 콘텐츠가 유저에게 노출되지 않게 막음.

### 3.8.2 동작과 규칙

#### 1) 적용 지점

전통 왜곡과 정합성 판정 기준은 인형과 조작 고증을 따름.

- **사전(운영 전 제작)**: 인형 양식 레퍼런스와 내부 조작 구조 에셋, 산받이 대사 등 사전 제작 자산 검수
- **런타임 입력(Step 2)**: 얼굴 촬영 입력 검사
- **런타임 출력(Step 3)**: 생성 3D 아바타 검사

#### 2) 위반 시 처리

- **입력 위반 검출**: 매 위반 시 위반 횟수가 표시된 안내 팝업 표시 후 재촬영 받고 3회(잠정) 위반 시 종료 처리
	- 위반 횟수는 화면마다 초기화하여 따로 셈
	- 부적절 입력 분류 세부 정책은 작성 예정
- **입력 가드레일 호출 실패**: 검사 호출 자체가 실패하면 통과로 보지 않음. 재시도(2회 잠정)해도 실패하면 재촬영을 안내함
	- **위반 횟수에 세지 않음**: 유저 얼굴이 아니라 검사 서비스 장애가 원인이라 유저에게 종료 부담을 지우지 않음
- **출력 위반 검출**: 재생성 한도 2회(잠정)까지 다시 만들고, 한도를 넘기면 위험 생성물을 파기하고 중단 처리함

### 3.8.3 기술 요건

- **모델 확보 (결정 필요)**: 범용 유해물은 외부 안전 API로 거르고, 전통 정체성 왜곡처럼 범용 API가 못 잡는 판정은 자체 규칙이나 도메인 분류기로 보완함. API 대 자체 구축 비중은 후보 조사 후 확정
- **판정 기준**: 이미지(얼굴 촬영)와 3D(생성 아바타)를 모두 검사하므로 이미지 모더레이션과 3D 형상 검사가 둘 다 필요함. 무인 운영이라 미탐(유해물 통과)이 오탐보다 위험하므로 미탐을 낮추는 보수적 임계로 잡음. 오탐률과 미탐률, 임계 목표는 검증 데이터 확보 후 정량 확정
- **적용**: 런타임 서버 호출. 입력과 출력 검사는 유저 대기 구간이라 검사 응답 지연 상한이 필요함(정량 미정)
- **데이터**: 부적절 입력과 전통 왜곡 판정 기준 데이터(작성 예정)

### 3.8.4 실패와 복구

가드레일 자신이 실패하는 경우를 다룸. 검사 결과가 위반으로 나오는 것은 실패가 아니라 정상 동작이며, 그 처리는 위 3) 동작과 규칙에 있음.

- **입력 검사 호출 실패**: 통과로 보지 않음. 외부 서비스 호출 래퍼로 재시도(2회 잠정)해도 실패하면 재촬영을 안내함. 유저 잘못이 아니라 검사 서비스 장애가 원인이라 위반 횟수에 세지 않고, 운영 알림 대상으로 둠
- **출력 검사 호출 실패**: 통과로 보지 않음. 재시도(2회 잠정)해도 실패하면 아바타 생성 파이프라인을 `failed`로 보냄. 재생성 한도 초과와는 원인이 달라(생성물이 계속 위반 대 검사 서비스 장애) 세션 데이터의 에러 유형에 따로 기록함
- **검사 서비스가 오래 죽어 있는 경우**: 유저는 다시 시도해도 앞으로 못 가므로 그만두기로 이탈함. 그래서 입력 검사 호출 실패를 운영 알림 대상으로 두어, 장애를 조기에 알아채게 함

## 3.9 외부 서비스 호출 래퍼

### 3.9.1 역할과 목적

외부 서비스 호출(아바타 생성, 가드레일 검사, TTS)을 감싸는 공통 계층. 재시도와 타임아웃 대응을 한 곳에 모아, 호출마다 장애 처리를 따로 짜지 않게 함.

### 3.9.2 동작과 규칙

- **재시도 횟수**
	- 2회(잠정). 백오프는 1차 1초, 2차 3초(잠정)
- **호출 타임아웃**
	- TTS 30초, 아바타 생성과 가드레일 검사 60초(모두 잠정)
- **한도 초과**
	- 재시도 한도를 넘긴 실패는 실패 처리로 넘김

## 3.10 실패 처리

### 3.10.1 역할과 목적

런타임 실패를 어떻게 다룰지 정하는 정책. 무인 운영에서 실패가 방치되지 않게 함.

### 3.10.2 동작과 규칙

본 절은 판정 규칙만 정의함. 케이스별 발생 지점과 처리, 팝업, 이후 동작은 [[#5.2 에러 케이스]] 표가 정본임.

- **처리 갈래**: 실패가 세션을 어떻게 만드는지로 셋을 나눔
	- **재입력**: 유저 입력만 다시 받으면 이어 감. 얼굴 미검출 재촬영, 얼굴 입력 가드레일 위반과 호출 실패가 여기 속함
	- **기능 축소**: 보조 기능이 빠져도 체험이 남음. 그 기능만 빼고 세션을 이어 감. 포즈 순간 미검출 구간의 연동 일시 정지, 산받이 발화 실패가 여기 속함
	- **중단**: 핵심 생성(아바타)이 실패하거나 카메라와 인식 계통이 지속 장애면 체험을 이어 갈 수 없음
- **대체 입력 갈래를 두지 않는 이유**: 유일한 입력 수단이 카메라와 터치라 대체할 다른 수단이 없음
- **중단 공통 처리**: 상황 안내 팝업을 띄우고 비완주 종료라 마무리 인사 화면을 건너뛰어 세션 종료와 파기 후 시작 화면으로 자동 진행함. 별도 실패 화면을 두지 않고 미완성이나 위반 생성물을 파기함
	- 예외: 세션 생성 실패는 정리할 세션 자체가 없어 종료 처리도 거치지 않고 시작 화면으로 되돌림
	- 생성 파이프라인의 중단은 `failed` 상태 하나로 모으고, 어느 단계에서 났는지는 세션 데이터의 에러 유형에 남김
	- 실패 시점: 아바타 생성이 Step 3이라 유저는 핵심 체험에 들어가기 전에 생성 실패를 알게 됨
- **운영 알림**: 원인이 외부 서비스나 시스템이면 보내고, 유저면 보내지 않음(알림 채널 미정)

## 3.11 인형과 조작 고증 (공통 레퍼런스)

### 3.11.1 역할과 목적

목각 인형 양식과 조작 구조, 가동 부위의 전통 기준을 정의하는 설계 레퍼런스. 아바타 생성과 포즈 연동 시연, 가드레일이 함께 참조해 전통 정합성을 한 기준으로 맞추게 함.

### 3.11.2 동작과 규칙

- **인형 양식**: 덜미 등장 인형(박첨지, 홍동지 등) 목각 양식을 아바타 질감과 캐릭터 레퍼런스로 씀(목록과 종수는 「남사당놀이 여섯 가지」 전사본 기준 확정 검토, 고증 자문)
- **가동 부위와 동작**: 일반 덜미 인형은 양손과 상반신만 움직이며, 동작은 양손 놀림과 상반신 흔들기임. 등장 인형 중 상좌 2인만 포대 괴뢰(布袋傀儡, 자루형 인형) 구조라 목과 양손, 허리까지 움직임(「남사당놀이 여섯 가지」 전사본 근거). 포즈 연동 시연의 매핑 자유도 기준이 됨
- **조작 구조**: 대잡이가 덜미 대를 잡고 인형을 놀리는 조종 방식이 문헌 근거임. 내부 조작 구조 뷰에 표현할 세부 부품과 손놀림은 확인 필요(고증 자문)
- **시각 정체성**: 목각 인형 양식과 질감의 전통 정합성 유지(작성 예정)

# 4. 세션 진행

## 4.1 Step 1. 인트로

### 4.1.1 클라이언트: 시작 화면

#### 1) 진행

- 언어를 선택하고 시작하기 버튼 터치 시 선택 언어를 세션 현재 언어로 반영하고 다음 단계 진행.
	- 서버로 신규 세션 생성 요청

### 4.1.2 서버: 세션 생성

#### 1) 진행

- 신규 세션 생성(익명) 및 세션 ID 부여
	- 분기: 세션 생성 실패 시 재시도(2회 잠정) 후 상황 안내 팝업 → 시작 화면 복귀

### 4.1.3 클라이언트: 가이드 화면

#### 1) 진행

- 진행 흐름 안내, 다음 버튼 터치 시 다음 단계 진행
	- 분기: 미입력 타임아웃 → 종료 처리
	- 분기: 그만두기 선택 시 확인 팝업 → 확정 시 종료 처리

### 4.1.4 클라이언트: 이용 동의 화면

카메라로 얼굴과 전신을 찍으므로 카메라 촬영 동의를 필수로 받음(약관에 포함, 별도 토글 없음). 정확한 동의 항목과 문구는 규정 검토에서 확정함.

#### 1) 진행

- 동의하고 시작하기 터치 시 동의 이벤트를 서버에 전송하고, 서버의 저장 확인 응답을 받은 뒤 다음 단계로 진행함 (이 화면은 화면 타임아웃 미적용)
	- 분기: 미입력 타임아웃 → 카메라 촬영 미동의로 종료 처리
	- 분기: 그만두기 선택 시 확인 팝업 → 확정 시 미동의로 종료 처리

### 4.1.5 서버: 동의 기록 저장

#### 1) 진행

- 동의 기록 저장(세션 ID, 약관 버전, 타임스탬프, 동의 항목)

## 4.2 Step 2. 얼굴 촬영

### 4.2.1 클라이언트: 얼굴 촬영 화면

#### 1) 진행

- 얼굴 정렬 가이드를 보여주고 카운트다운 촬영으로 유저 얼굴을 캡처함(카운트다운 3초 잠정)
	- 분기: 카메라에 얼굴이 안 잡히면 다시 정렬하도록 안내함
	- 분기: 사람이나 얼굴 미검출이 터치 미입력 타임아웃 임계를 넘기면 이탈로 보고 종료 처리

### 4.2.2 서버: 얼굴 촬영 입력 가드레일

#### 1) 진행

- AI 가드레일 런타임 입력 검사 실행
	- 호출 주체: 클라이언트가 캡처 프레임을 서버로 보내고, 서버가 외부 서비스 호출 래퍼로 가드레일 입력 검사를 호출함
	- 분기: 위반 시 안내 팝업 → 3회(잠정) 위반 시 종료 처리
	- 분기: 가드레일 호출이 재시도 한도를 넘기면 안내 팝업 → 위반 횟수에 세지 않고 재촬영 받음

### 4.2.3 서버: 얼굴 프레임 임시 저장

#### 1) 진행

- 세션에 얼굴 캡처 프레임을 임시 저장함(아바타 생성 입력용, 메모리 임시)

## 4.3 Step 3. 아바타 생성과 대기 화면 (병행)

백그라운드 생성과 포그라운드 대기가 동시 진행되고 상태 조회로 동기화됨. 아바타 생성은 백그라운드라 화면이 없음.

### 4.3.1 서버: 아바타 생성 (백그라운드)

#### 1) 진행

- **생성 파이프라인**
	1. 서버: 아바타 생성 작업 큐 등록
	2. 얼굴 기반 인형 아바타 생성: 얼굴 캡처에서 특징을 추출해 전통 목각 인형 질감의 3D 아바타로 변환
		- 분기: 호출 실패 시 재시도(2회 잠정), 한도 초과 시 상태 `failed` 전환
	3. AI 가드레일: 생성 아바타 검사
		- 분기: 위반 시 2로 재생성(한도 2회, 잠정). 한도 초과 시 위험물 파기, 상태 `failed` 전환
		- 분기: 검사 호출 실패 시 통과로 보지 않고 재시도(2회 잠정), 한도 초과 시 상태 `failed` 전환
	4. 서버: 통과한 3D 아바타 저장. 입력으로 쓴 얼굴 캡처는 여기서 파기함
- **실패(생성 단계 공통)**
	- 어느 단계에서 `failed`가 됐는지를 세션 데이터의 에러 유형에 기록함. 포그라운드 상태 조회가 `failed`를 검출하면 그 케이스의 상황 안내 팝업을 띄우고 종료 처리함
	- 재시도 2회(잠정), 상태 조회 주기 2초(잠정)
- **상태 머신**
	- `generating` / `completed`(가드레일 통과분만) / `failed`(생성 실패, 가드레일 한도 초과)

#### 2) 얼굴 기반 인형 아바타 생성

##### (1) 역할과 목적

유저 얼굴을 목각 인형으로 바꾸는 런타임 엔진. 전통 인형 질감과 얼굴 개인화를 함께 잡아, 유저가 조작할 자기 인형을 만듦.

##### (2) 동작과 규칙

얼굴 특징을 목각 인형 두상에 입혀 인형 양식(인형과 조작 고증)으로 생성함. 키오스크 부하를 고려해 서버 백그라운드에서 생성하고, 대기 화면이 상태 조회로 동기화함. 3D를 지양하는 공통 비주얼 방향의 예외로, 콘셉트가 정의한 콘텐츠 고유 3D 요건임.

##### (3) 기술 요건

- **모델 확보**: 얼굴 기반 3D 아바타 생성 모델. 자체 학습 부담이 커 외부 API와 사전학습 모델을 우선 검토함(후보 조사 확인 필요). 미확보 시 대안 검토(확인 필요)
- **산출 규격**: 3D 아바타 자산(연동 렌더와 내부 조작 구조 뷰 결합용)의 형식 규격은 확인 필요
- **판정 기준**: 생성 성공률, 전통 양식 정합성(가드레일 연계), 생성 시간(대기 조회 주기와 연동). 품질 평가 기준과 평가 데이터는 작성 예정
- **적용**: 서버 백그라운드 배치. Step 3에서 호출

##### (4) 필요 리소스

- 목각 인형 양식 레퍼런스(고증 자문, 자체 제작)
- 인형 두상과 몸체 베이스 모델(외주나 자체, 확인 필요)

##### (5) 실패와 복구

생성 아바타는 출력 가드레일 검사를 받음. 호출이 재시도 한도(2회 잠정)를 넘겨 실패하거나 가드레일 재생성 한도(2회 잠정)를 넘기면 생성 파이프라인의 `failed` 처리로 이어짐. 두 경우는 원인이 달라(생성 서비스 장애 대 생성물이 계속 위반) 세션 데이터에 따로 기록함.

### 4.3.2 클라이언트: 아바타 생성 대기 화면 (포그라운드)

#### 1) 진행

- 대기 콘텐츠 노출(덜미 준비 과정 영상 등)
- 서버 상태 조회(주기 2초, 잠정). 두 타임아웃 미적용
- 분기: `generating` → 대기 유지 / `completed` → 즉시 Step 4 / `failed` → 상황 안내 팝업 → 종료 처리 / 상태 조회 연속 3회 무응답(잠정) → 상황 안내 팝업 → 종료 처리

## 4.4 Step 4. 인형 연동 시연 (핵심 체험)

### 4.4.1 클라이언트: 인형 연동 시연 화면

#### 1) 진행

1. 화면에 유저 카메라 뷰(거울 방식)를 비추고, 우측에 내 인형 아바타와 그 내부 조작 구조 뷰를 나란히 표시함
2. 산받이가 놀이를 열고 조작법 해설을 시작함(대사 문안은 작성 예정)
3. 유저가 몸을 움직이면 인형의 가동 부위가 실시간으로 따라 움직이고, 내부 조작 구조 뷰가 그 동작을 만드는 대잡이의 조작을 함께 시연함
4. 연동 활동이 쌓이면 신명 게이지가 오르고, 달성 시 환호 사운드로 보상함. 미달인 채 마치면 산받이가 눙치며 마무리함
5. 마치기 터치 시 완주로 보고 Step 5 마무리 인사 화면으로 진행함
	- 분기: 화면 타임아웃(5분, 잠정) → 완주로 보고 Step 5로 정상 진행
	- 분기: 그만두기 선택 시 확인 팝업 → 확정 시 종료 처리
	- 분기: 사람이나 포즈 미검출이 터치 미입력 타임아웃 임계를 넘기면 이탈로 보고 종료 처리

#### 2) 포즈 연동과 조작 구조 시연

##### (1) 역할과 목적

유저의 움직임을 인형과 그 조작 구조에 실시간으로 잇는 핵심 엔진. 내 몸짓을 인형으로 만들어 내는 실제 덜미 조작을 보게 함.

##### (2) 입력과 출력

- **입력**: 카메라 영상 프레임(전신 포즈 추정)
- **출력**: 인형 가동 부위 구동 값(아바타와 구조 뷰 렌더), 연동 활동량(신명 게이지 가산과 시연 활동 기록에 전달)

##### (3) 동작과 규칙

- **연동 파이프라인**: 카메라 프레임에서 유저의 2D 키포인트를 실시간 추출하고, 인형의 가동 부위 값으로 매핑해 아바타와 내부 조작 구조 뷰를 같은 값으로 구동함
- **가동 부위 매핑 (고증 제약)**: 일반 덜미 인형은 양손과 상반신만 움직임(인형과 조작 고증). 유저의 팔과 상체 움직임만 인형에 매핑하고 다리와 보행은 반영하지 않음. 반영되지 않는 움직임은 산받이가 재담으로 안내함
- **조작 구조 시연**: 내부 조작 구조 뷰는 대잡이가 덜미 대를 잡고 인형을 놀리는 손놀림을 표현함. 인형 동작과 조작 표현이 항상 같은 프레임에서 일치하게 구동함. 구조 표현의 세부(부품, 시점)는 확인 필요(고증 자문)
- **미러 규약**: 유저 카메라 뷰는 거울 방식으로 표시하고, 인형과 구조 뷰도 같은 방향 기준으로 맞춤
- **연동 활동 기록**: 가동 부위를 움직인 지속 시간과 부위 다양성을 연동 활동량으로 기록함(신명 게이지 가산과 익명 통계 입력)
- **세부 설계 (작성 예정)**: 관절-가동 부위 사상표, 구조 뷰 표현 수준

##### (4) 기술 요건

- **모델 확보**: 실시간 전신 포즈 추정은 사전학습 경량 2D 키포인트 모델과 온디바이스 SDK를 우선 검토함(확인 필요, 탈춤과 같은 스택). 가동 부위 사상과 구조 뷰 구동은 자체 구현
- **판정 기준**: 연동 지연(유저 움직임과 인형 반응 사이, 정량 미정), 포즈 추정 정확도, 실시간 처리 프레임률
- **적용**: 전부 클라이언트 로컬 처리임. 서버 왕복 없음

##### (5) 필요 리소스

- 인형 내부 조작 구조 에셋(아바타와 결합하는 구조 뷰, 고증 자문 연계, 제작 방식 확인 필요)
- 관절-가동 부위 사상 데이터(매핑 정의)
- 굿거리 장단 음원(배경 연출, 잠정. 채택 여부 확인 필요)
- 환호와 추임새 사운드(게이지 달성 보상, 제작 방식 확인 필요)

##### (6) 실패와 복구

- 포즈가 순간적으로 인식되지 않거나 신뢰도가 낮을 시 처리
	- 인형과 구조 뷰를 마지막 자세로 잠시 유지하고, 인식이 돌아오면 연동을 재개함(그동안 게이지 가산은 멈춤)
- 사람이나 포즈 미검출이 터치 미입력 타임아웃 임계를 넘길 시 처리
	- 미입력 타임아웃으로 간주하여 종료 처리
- 카메라 영상이 들어오지 않거나 모든 프레임 저신뢰가 지속될 시 처리(지속 임계는 잠정, 개발 단계 확정)
	- 유저 요인이 아니라 시스템 장애(카메라 고장이나 가림, 조명, 성능 저하)로 보고 상황 안내 팝업 후 중단 처리함. 운영 알림 대상임

#### 3) 신명 게이지

##### (1) 역할과 목적

채점 없는 시연 체험에 성취의 리듬을 주는 보상 장치. 몸을 오래, 다양하게 움직일수록 차오르게 해 적극적인 움직임을 이끌어 냄.

##### (2) 동작과 규칙

- **가산 기준**: 연동 활동량(인형 가동 부위를 움직인 지속 시간과 부위 다양성)에 따라 가산함(잠정, 기준 상세는 개발 단계 확정). 동작의 잘잘못을 매기는 채점이 아님
- **달성 보상**: 게이지가 달성 임계(정량 미정, 개발 단계 확정)를 넘기면 환호 사운드(군중 추임새, 박수)로 보상함
- **미달 처리**: 임계 미달인 채 마치면 산받이가 눙치며 마무리함

## 4.5 Step 5. 종료와 리셋

완주와 비완주 두 경로로 진입함. 완주(Step 4 인형 연동 시연 화면에서 마치기 터치 또는 화면 타임아웃으로 정상 진행)만 마무리 인사 화면을 거치고, 비완주 종료(그만두기, 터치 미입력 타임아웃, 카메라 촬영 미동의, 얼굴 입력 가드레일 위반 한도 초과, 실패 중단)는 마무리 인사 화면을 건너뛰고 곧장 세션 종료와 파기로 감.

### 4.5.1 클라이언트: 산받이 마무리 인사 화면

#### 1) 진행

- 완주로 진입한 경우에만 표시함. 산받이가 마무리 인사를 하고, 곧장 나가도록 "처음으로" 버튼을 둠
	- 분기: 처음으로 버튼 터치 또는 화면 타임아웃(기본 60초, 잠정) → 다음 단계 진행

### 4.5.2 클라이언트: 종료 이벤트 전송과 리셋

#### 1) 진행

- 종료 이벤트(완주 또는 이탈 결과)를 서버로 전송하고, 서버의 저장 확인 응답을 받은 뒤 클라이언트 세션 데이터를 초기화함. 종료 이벤트는 세션 ID 기준으로 멱등 처리해 재전송이 중복 종료를 만들지 않게 함
	- 확인 응답을 재시도(2회 잠정) 후에도 받지 못하면 로컬 세션 데이터를 파기하고 시작 화면으로 복귀함(다음 유저의 키오스크 점유가 우선). 미종료로 남은 서버 세션의 정리 방식은 서버 구현에서 확정함(확인 필요)
	- 완주는 유형(마치기 터치, 시연 화면 타임아웃)을 구분해 기록함: 완주율 관측에서 방치 완주를 분리함

## 5.2 에러 케이스

### 5.2.1 케이스 목록과 처리

**처리**는 그 실패가 세션을 어떤 상태로 끝내는지를, **원인**은 실패가 어디에서 비롯되었는지를 나타냄. 원인이 외부 서비스나 시스템일 경우에만 운영 알림을 보냄. 갈래를 나누는 판정 규칙은 실패 처리 시스템에 있고, 본 표는 그 규칙을 케이스에 적용한 결과임. 이후 동작의 Step 5는 모두 비완주 종료라 마무리 인사 화면을 건너뛰고 세션 종료와 파기 후 시작 화면으로 복귀함.

| 발생 지점 | 처리 | 원인 | 팝업 | 이후 동작 |
|---|---|---|---|---|
| 얼굴 촬영 중 얼굴 미검출 | 재입력 | 유저 | 안내 | 다시 정렬하도록 안내 |
| 얼굴 입력 가드레일 위반 검출 | 재입력 | 유저 | 위반 안내 | 같은 화면 재촬영, 3회(잠정) 위반 시 종료 |
| 얼굴 입력 가드레일 호출 실패 | 재입력 | 외부 서비스 | 안내 | 같은 화면 재촬영, 위반 횟수에 세지 않음 |
| 산받이 발화 실패 | 기능 축소 | 시스템 | 없음 | 세션 계속, 대표 이미지와 텍스트로 진행 |
| 세션 생성 실패 | 중단 | 시스템 | 상황 안내 | 시작 화면 복귀 |
| 아바타 생성 호출 실패 | 중단 | 외부 서비스 | 상황 안내 | Step 5, 생성물 파기 |
| 아바타 출력 가드레일 재생성 한도 초과 | 중단 | 시스템 | 상황 안내 | Step 5, 생성물 파기 |
| 아바타 출력 가드레일 호출 실패 | 중단 | 외부 서비스 | 상황 안내 | Step 5, 생성물 파기 |
| 카메라 미수신이나 모든 프레임 저신뢰 지속(임계 잠정) | 중단 | 시스템 | 상황 안내 | Step 5 |
| 상태 조회 3회(잠정) 연속 무응답 | 중단 | 시스템 | 상황 안내 | Step 5, 생성물 파기 |
