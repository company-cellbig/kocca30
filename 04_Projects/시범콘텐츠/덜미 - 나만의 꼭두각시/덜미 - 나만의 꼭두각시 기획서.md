> 덜미(꼭두각시놀음)를 소재로, 유저가 자기 얼굴로 만든 목각 인형 아바타를 양손과 장단으로 조작하며 산받이와 재담을 주고받는 인형놀음 체험 시범콘텐츠 개발 문서. 사용자가 얼굴을 촬영하면 전통 목각 인형 질감의 3D 아바타를 생성하고, 그 아바타를 양손 조작과 장단 타이밍으로 놀린 뒤(채점), 골계적 반전(홍동지 등장, 이시미 퇴치)으로 절정을 맺고 인형과 기념 촬영함. [[콘텐츠 기획서 작성 양식]] 적용. 골격 단계로 점차 채움.

# 1. 개요

- **콘텐츠 정의**: 덜미(꼭두각시놀음)를 소재로 한 인형놀음 체험 키오스크 콘텐츠. 유저가 자기 얼굴로 만든 목각 인형 아바타를 직접 조작해 한 판 놀이를 벌이는 능동 체험임
- **소재**: 남사당놀이 인형극 덜미(꼭두각시놀음) ([[덜미]])
- **목표 경험**: 덜미의 전통 골격(박첨지 일가 놀음, 산받이 재담, 홍동지 응징의 골계)은 고정하고, 유저가 자기 얼굴 아바타로 직접 인형을 놀려 자기만의 한 판을 완성함
- **핵심 메커닉**: 양손 조작과 장단 타이밍의 동작 일치도를 실시간 채점해 신명(興) 게이지로 보상하고, 절정에서 골계적 반전(홍동지 등장, 이시미 퇴치)을 결정적 빠른 입력 이벤트(Quick Time Event, 정해진 짧은 시간 안에 맞춰 누르는 연출 조작)로 맺음

# 2. 세션 개요

세션을 한눈에 파악하는 절. 세션 정의와 흐름을 담고, 세션 데이터 상세는 §5.가 세션과 데이터, Step별 상세 명세는 §3 Step 상세에 둠.

## 가. 세션 정의

1회 완결로 자기 얼굴 인형으로 한 판 놀이를 벌이고 기념물을 남기는 세션임. 컨테이너 정의와 라이프사이클은 공통 정의를 따름.

![[시범콘텐츠 공통 사양#^session-def]]

## 나. 세션 흐름

Step 1 인트로(동의) → Step 2 얼굴 촬영 → Step 3 아바타 생성과 대기 → Step 4 아바타 조작 한 판(핵심) → Step 5 기념 촬영과 생성 → Step 6 결과물 전송 → Step 7 종료와 리셋

- **분기**: 대부분 이탈(미동의, 터치 미입력 타임아웃)로 Step 7 직행, 생성과 변환 실패는 실패 처리 후 Step 7
- **병행**: Step 3(백그라운드 아바타 생성 + 포그라운드 대기), Step 5(백그라운드 생성 + 포그라운드 대기)
- **파기**: 기념 사진은 결과 페이지 임시 보관 후 다운로드 만료 시 파기(연락처 미수집), Step 7 종료 시 세션 임시 데이터 파기

# 3. Step 상세

각 Step의 명세를 담음. Step 정의와 명세 양식은 공통 모델을 따르고, 여러 Step에 걸친 공용 기능과 운영 파라미터를 함께 둠.

## 다. Step별 흐름

상세 레이아웃과 화면 확정은 [[덜미 - 나만의 꼭두각시 UI]] 소관임. 상세 동작과 규칙은 §4 구성 요소에 둠.

### 1) Step 1. 인트로 (시작 + 동의)

- **트리거**: 유저가 시작하기 터치
- **시스템**: 클라이언트 UI (§5.다 5 클라이언트 UI), 백엔드 (§5.다 3 백엔드)
- **화면 흐름**: 시작 화면 → 가이드 화면 → 동의 약관 화면
- **프로세스**
	1. 백엔드: 신규 세션 생성 (익명)
	2. UI(가이드 화면): 진행 흐름 안내
	3. UI(동의 약관 화면): 약관 표시, 동의 입력 감지(동의하고 시작이 동의, 그만두기는 확인 팝업 거쳐 확정 시 미동의) (화면 타임아웃 미적용)
		- 호출 공용 기능: 터치 미입력 타임아웃
		- 분기: 그만두기 버튼 터치 시 확인 팝업을 거쳐 확정 시 미동의로 Step 7 직행. 카메라 촬영 미동의나 터치 미입력 타임아웃도 Step 7 직행
	4. 백엔드: 동의 기록 저장
- **동의 항목**: 필수(카메라 촬영)
- **입력**: 터치 이벤트, 동의 결정
- **출력**: 세션 ID, 동의 기록
- **다음**: Step 2 (시작 화면은 Step 7 복귀 화면과 동일한 대기 상태)

### 2) Step 2. 얼굴 촬영

- **트리거**: Step 1 동의 완료
- **시스템**: 클라이언트 UI (§5.다 5 클라이언트 UI), AI 가드레일 (§4.아 AI 가드레일), 백엔드 (§5.다 3 백엔드)
- **화면 흐름**: 얼굴 촬영 화면
- **프로세스**
	1. UI(얼굴 촬영 화면): 얼굴 정렬 가이드 제시, 카운트다운 촬영으로 유저 얼굴 캡처
		- 호출 공용 기능: 터치 미입력 타임아웃 (카메라 화면, 사람이나 얼굴 미검출 기준)
		- 실패: 카메라에 얼굴이 안 잡히면 다시 정렬하도록 안내
		- 분기: 터치 미입력 타임아웃(사람이나 얼굴 미검출)이면 유저 이탈로 보고 Step 7 직행
	2. AI 가드레일: 촬영 입력 검사 (§4.아 AI 가드레일)
		- 호출 공용 기능: AI 가드레일
		- 실패: 부적절 입력 검출 시 재촬영 안내(한도 §3.라 운영 파라미터), sub-step 1로 재진입. 한도 초과 시 실패 처리 후 Step 7
	3. 백엔드: 세션에 얼굴 캡처 프레임 임시 저장 (아바타 생성 입력용, 메모리 임시)
- **입력**: 카메라 영상 프레임
- **출력**: 얼굴 캡처 프레임 (아바타 생성 입력)
- **다음**: Step 3

### 3) Step 3. 아바타 생성 + 대기 화면

- **트리거**: 얼굴 촬영 완료
- **시스템**: AI 시스템(아바타 생성, §4.나 얼굴 기반 인형 아바타 생성), AI 가드레일 (§4.아 AI 가드레일), 클라이언트 UI (§5.다 5 클라이언트 UI), 백엔드 (§5.다 3 백엔드)
- **화면 흐름**: 생성 대기 화면. 아바타 생성은 백그라운드라 화면 없음
- **프로세스** (백그라운드와 포그라운드 동시, 상태 조회로 동기화)
	- **백그라운드: 아바타 생성**
		- 생성 단계
			1. 백엔드: 아바타 생성 작업 큐 등록
			2. AI 아바타 생성: 얼굴 캡처에서 특징을 추출해 전통 목각 인형 질감의 3D 아바타로 변환 (엔진 §4.나 얼굴 기반 인형 아바타 생성)
			3. AI 가드레일: 생성 아바타 검사 (§4.아 AI 가드레일)
				- 분기: 위반 시 sub-step 2로 재생성(한도 §3.라 운영 파라미터). 한도 초과 시 상태 failed
			4. 백엔드: 통과한 3D 아바타 저장
		- 실패(생성 단계 공통): 생성 실패 시 재시도(한도 §3.라 운영 파라미터) 후 failed, 실패 처리 공용 기능
	- **포그라운드: 생성 대기 화면** ([[시범콘텐츠 공통 사양#다. 생성과 변환 대기]] 준용)
		1. UI(생성 대기 화면): 생성 대기 표시 (두 타임아웃 미적용)
		2. UI(생성 대기 화면): 백엔드 상태 조회 (주기 §3.라 운영 파라미터)
			- 분기: 생성 중이면 대기 유지, 완료면 Step 4 전환, failed면 실패 처리 후 Step 7
			- 분기: 상태 조회 무응답이 임계(§3.라 운영 파라미터)를 넘으면 failed로 처리해 실패 처리 후 Step 7 (대기 화면은 두 타임아웃 미적용이라 무한 대기를 막는 별도 탈출)
- **입력**: 얼굴 캡처 프레임
- **출력**: 3D 인형 아바타
- **다음**: 생성 완료 시 Step 4

### 4) Step 4. 아바타 조작 한 판 (핵심 체험)

- **트리거**: 아바타 생성 완료
- **시스템**: AI 시스템(동작 채점, §4.다 양손 조작과 장단 채점), 클라이언트 UI(아바타 조작 렌더러, §5.다 5 클라이언트 UI), 백엔드 (§5.다 3 백엔드)
- **화면 흐름**: 인형 조작 체험 화면
- **프로세스**
	1. UI(산받이): 산받이가 상황과 미션을 재담으로 제시 (예: "어디서 온 누구인고? 유람가 한 자락 뽑아보게!"). 미션과 거리 골격은 §4.가 인형과 조작 고증
	2. UI(인형 조작 체험 화면): 양손 조작 입력과 장단 타이밍으로 아바타 동작 수행, 동작 캡처
		- 호출 공용 기능: 화면 타임아웃, 터치 미입력 타임아웃 (카메라/모션 화면)
		- 분기: 화면 타임아웃 발동 시 체류 상한으로 보고 Step 5로 정상 진행
		- 분기: 터치 미입력 타임아웃(입력이나 손 미검출)이면 유저 이탈로 보고 Step 7 직행
	3. AI 동작 채점: 동작 일치도와 장단 타이밍 채점, 신명 게이지 상승 (§4.다 양손 조작과 장단 채점)
		- 실패: 입력이 안 잡히거나 신뢰도가 낮으면 재시도 안내(한도 §3.라 운영 파라미터), 지연 시 해당 구간 점수 보류
	4. UI(산받이): 채점에 따라 실시간 추임새 (점수가 낮으면 재담으로 응수, §4.바 산받이 진행 호스트)
	5. UI(인형 조작 체험 화면): 골계 반전 하이라이트 (홍동지 등장, 이시미 퇴치를 결정적 빠른 입력 이벤트로 연출, §4.라 골계 반전 연출)
	6. UI(인형 조작 체험 화면): 게이지 결과 연출 (달성 시 환호 사운드 보상, 미달 시 산받이가 눙치는 마무리)
- **입력**: 양손 조작(카메라 핸드 트래킹), 장단 타이밍, 카메라 영상 프레임
- **출력**: 동작 채점 기록, 신명 게이지, 골계 반전 결과
- **다음**: Step 5

### 5) Step 5. 기념 촬영

- **트리거**: 아바타 조작 한 판 완료
- **시스템**: AI 시스템(생성, §4.마 기념 사진 생성), AI 가드레일 (§4.아 AI 가드레일), 클라이언트 UI (§5.다 5 클라이언트 UI), 백엔드 (§5.다 3 백엔드)
- **화면 흐름**: 기념 촬영 화면 → 생성 시작 시 생성 대기 화면(병행)
- **프로세스**
	1. UI(기념 촬영 화면): 3D 인형 아바타를 카메라 뷰에 라이브 합성, 사용자가 그 옆에서 포즈
		- 실패: 카메라에 사람이 안 잡히면 다시 서도록 안내
	2. UI(기념 촬영 화면): 카운트다운 촬영 (채점 없음, 촬영 횟수 n회까지)
		- 호출 공용 기능: 화면 타임아웃, 터치 미입력 타임아웃 (카메라/모션 화면)
		- 분기: 유효 촬영이 1회 이상인 채로 촬영 횟수 소진이나 촬영 자체 타임아웃, 또는 화면 타임아웃(긴 안전 상한)이면 sub-step 3으로 정상 진행
		- 분기: 유효 촬영 0회로 타임아웃되면(유효 촬영 전 이탈) 사진 생성을 생략하고 실패 처리 후 Step 7
		- 분기: 터치 미입력 타임아웃(사람이나 포즈 미검출)이면 Step 7 직행
	3. AI 생성: 기념 사진 생성 (촬영본에 인형 아바타 캐릭터를 고품질 재합성하고, 테두리 프레임을 두르고 신명 게이지 점수와 등급을 스탬프로 표기). 생성 §4.마 기념 사진 생성
		- (병행) UI(생성 대기 화면): 생성 대기 표시 (상태 조회로 동기화)
		- 실패: 생성 상태 조회 무응답이 임계(§3.라 운영 파라미터)를 넘으면 실패 처리 처리
	4. AI 가드레일: 생성 사진 검사, 통과물만 확정 (§4.아 AI 가드레일)
		- 실패: 가드레일 미통과나 재생성 한도 초과 시 위험 생성물 파기, 재생성 실패 시 에러 안내
- **입력**: 카메라 영상, 3D 인형 아바타, Step 4 신명 게이지 점수와 등급
- **출력**: 기념 사진(신명 게이지 점수와 등급을 스탬프로 표기)
- **다음**: Step 6 (통과 산출물이 있을 때만 진행)

### 6) Step 6. 결과물 전송

- **트리거**: 기념 사진 생성 완료
- **시스템**: 클라이언트 UI (§5.다 5 클라이언트 UI), 백엔드 (§5.다 3 백엔드), 외부 서비스(결과물 호스팅, §5.다 4 외부 서비스 연동)
- **화면 흐름**: 결과물 미리보기 화면 → 결과물 QR 화면
- **프로세스**
	1. UI(결과물 미리보기 화면): 결과물 미리보기
		- 호출 공용 기능: 화면 타임아웃
		- 분기: 화면 타임아웃 발동 시 sub-step 2(URL 발급)로 정상 진행 (URL 발급을 건너뛰지 않게 미리보기 다음 단계로 보냄)
	2. 백엔드: 기념 사진 결과물을 웹에 호스팅하고 만료형 다운로드 URL(유효기간 48시간, 개발 중 조정) 발급 ([[시범콘텐츠 공통 사양#라. 결과물 전송]] 준용)
		- 호출 공용 기능: 외부 서비스 호출 래퍼, 실패 처리
		- 분기: 업로드나 호스팅, URL 발급 실패 시 재시도(결과물 호스팅 재시도 2회 잠정, §3.라 운영 파라미터), 한도 초과 시 상황 안내 뒤 Step 7 + 운영 알림
	3. UI(결과물 QR 화면): 발급된 다운로드 URL을 인코딩한 QR을 화면에 표시하고 스캔 안내와 다운로드 가능 기간을 함께 보여줌. 유저가 본인 휴대폰으로 스캔해 웹에서 결과물을 받고, 마침 선택 시 Step 7 진행
		- 호출 공용 기능: 화면 타임아웃
		- 연락처를 받지 않으므로 전송 동의나 입력 유효성 검증이 없음
		- 분기: 화면 타임아웃 발동 시 Step 7로 정상 진행
- **입력**: 터치(마침)
- **출력**: 결과 페이지와 만료형 다운로드 URL, 화면 QR 표시
- **파기**: 결과 페이지는 다운로드 만료(48시간) 시 파기. 연락처를 수집하지 않음 (§5.가 세션과 데이터)
- **다음**: Step 7

### 7) Step 7. 종료와 리셋

- **트리거**: 결과물 전송 완료 또는 미동의 또는 터치 미입력 타임아웃(유저 이탈)
- **시스템**: 클라이언트 UI (§5.다 5 클라이언트 UI), 백엔드 (§5.다 3 백엔드)
- **화면 흐름**: 마무리 인사 화면 → 시작 화면 복귀(Step 1과 공유)
- **프로세스**
	1. UI(산받이): 마무리 인사
	2. 백엔드: 세션 종료와 임시 데이터 파기(영상 피드, 얼굴 캡처). 결과 페이지는 다운로드 만료(48시간)까지 유지 (§5.가 세션과 데이터)
	3. UI(시작 화면): 시작 화면 복귀
- **입력**: 직전 Step 완료 또는 이탈 신호
- **출력**: 세션 종료, 임시 데이터 파기 완료
- **다음**: 다음 유저용 Step 1 대기

# 4. 구성 요소

콘텐츠를 이루는 요소를 의존 순(앞 요소가 뒤 요소의 입력 기반)으로 둠. 각 요소는 역할, 입력과 출력, 동작과 규칙, 기술 요건, 자산 요구, 가드레일과 실패, 의존을 모두 갖춘 독립 명세임.

## 가. 인형과 조작 고증 (공통 레퍼런스)

전통 고증 레퍼런스. 목각 인형 양식과 조작 동작, 한 판의 거리 골격의 전통 기준을 정의해, 여러 구성 요소가 생성 시작점이나 전통 정합성 판정 기준으로 공유함. 공통 입력 기반이라 맨 앞에 둠.

- **인형 양식**: 덜미 등장 인형(박첨지, 홍동지, 이시미 등) 목각 양식을 아바타 질감과 캐릭터 레퍼런스로 활용 (목록과 종수 확인 필요, [[덜미]] 기준 보강)
- **조작 동작과 장단**: 따라 하는 인형 동작(들썩임, 좌우 놀림 등)과 풍물 장단의 고증 매핑 (작성 예정, 고증 자문 연계). §4.다 채점의 기준 동작
- **한 판 거리 골격**: 산받이 등장과 미션 제시(도입), 인형 놀음(전개), 골계 반전(절정), 맺음(마무리)의 거리 골격. 원형은 [[덜미#2. 박첨지마당 (4거리)]] 박첨지유람거리와 이시미거리의 골계 구조
- **시각 정체성**: 목각 인형 양식과 질감의 전통 정합성 유지 (작성 예정)
- **의존**: 선행 의존 없음(기반). 본 레퍼런스를 §4.나 아바타 생성(질감 기준), §4.다 동작 채점(기준 동작), §4.라 골계 반전(연출 골격), §4.아 가드레일(전통 왜곡 판정 기준)이 공유함

## 나. 얼굴 기반 인형 아바타 생성 (Step 3)

- **역할**: 유저 얼굴 캡처에서 특징을 추출해 조작용 3D 목각 인형 아바타로 생성. 전통 인형 질감과 얼굴 개인화를 함께 잡음
- **입력과 출력**: 입력은 얼굴 캡처 프레임(Step 2 산출). 출력은 3D 인형 아바타(조작 렌더와 기념 합성용, 형식 규격 확인 필요)
- **동작과 규칙**: 얼굴 특징을 목각 인형 두상에 입혀 인형 양식(§4.가 고증)으로 생성함. 키오스크 부하를 고려해 서버 백그라운드 생성, 대기 화면이 상태 조회로 동기화함. 콘셉트가 정의한 콘텐츠 고유 3D 요건임 ([[시범콘텐츠 공통 사양#1. 개요]] 공통 비주얼, 3D 지양이되 콘텐츠 고유 요건은 예외)
- **기술 요건**: 얼굴 기반 3D 아바타 생성 모델. 자체 학습 부담이 커 외부 API와 사전학습 모델 우선 검토(후보 조사 확인 필요). 판정 기준은 생성 성공률, 전통 양식 정합성(가드레일 연계), 생성 시간(대기 조회 주기 연동, 구현 확정). 생성 품질 평가 기준과 평가 데이터는 작성 예정. AI 모듈 명세는 [[시범콘텐츠 공통 사양#가. AI 시스템]] 준용
- **자산 요구**: 목각 인형 양식 레퍼런스(§4.가 고증), 인형 두상과 몸체 베이스 모델(§4.사 콘텐츠 자산)
- **가드레일과 실패**: 얼굴 입력 가드레일(Step 2)과 아바타 출력 가드레일(Step 3, §4.아 가드레일). 생성 실패나 가드레일 한도 초과 시 실패 처리, 재시도 한도는 §3.라 운영 파라미터. 생성 모델 미확보 시 대안 검토(확인 필요)
- **의존**: 입력은 §4.가 고증의 인형 양식과 Step 2 얼굴 캡처. 출력 3D 아바타는 §4.다 조작 채점과 §4.마 기념 사진 생성이 사용

## 다. 양손 조작과 장단 채점, 신명 게이지 (Step 4, 핵심 메커닉)

- **역할**: 유저의 양손 조작과 장단 타이밍을 받아 인형 동작 일치도와 타이밍을 실시간 채점하고 신명(興) 게이지로 시각화, 달성 시 보상하는 핵심 루프
- **입력과 출력**: 입력은 양손 조작 입력과 풍물 장단 타이밍(입력 수단은 동작과 규칙 참조). 출력은 동작 키포인트, 동작 일치도, 타이밍 점수, 신명 게이지 값, 동작 채점 기록
- **동작과 규칙**
	- 입력 수단: 양손 조작은 카메라 핸드 트래킹으로 받음(사용자 결정, 2026-07-01). 얼굴 촬영에 쓰는 카메라를 손 추정에 함께 활용하므로 별도 개인정보 표면은 늘지 않음
	- 채점 입력: 동작 일치도(인형 동작 기준 대비)와 풍물 장단 대비 타이밍 (기념 촬영 Step 5는 채점 안 함)
	- 게이지와 보상: 채점이 쌓이면 게이지 상승. 달성 시 환호 사운드(군중 추임새, 박수) 보상, 미달 시 산받이가 눙치며 마무리
	- 종합 점수와 등급 출력: 게이지 종합 점수와 등급은 Step 5 기념 사진 스탬프로 표기
	- 학습 진척(디지털 도제, 2차연도): 1차연도는 당회 채점만. 재방문 진척 누적(향상 곡선, 약점 동작 피드백)은 2차연도 전방 설계로 둠 ([[플랫폼 사양#6. 2차연도 전방 설계 (디지털 도제 연속성, 현재 구현 밖)]])
	- 임계와 가중치, 난이도 곡선은 §3.라 운영 파라미터. 세부 설계(가중치, 게이지 임계, 미달 처리, 향상 곡선 산출)는 작성 예정
- **기술 요건**: 실시간 손 추정(핸드 트래킹)으로 양손 동작을 받음. 사전학습 모델과 온디바이스 SDK 우선 검토(후보 확인 필요). 채점 로직은 레퍼런스 동작 대비 자체 규칙. 판정 기준은 입력 인식 정확도, 채점 임계와 가중치, 실시간 처리 지연(프레임률). 채점 정확도 검증 방법은 작성 예정. 서버와 온디바이스 여부 확인 필요. AI 명세는 [[시범콘텐츠 공통 사양#가. AI 시스템]] 준용
- **자산 요구**: 인형 조작 동작 레퍼런스(§4.사 콘텐츠 자산), 환호와 추임새 사운드(§4.사 콘텐츠 자산), 풍물 장단 음원(§4.사 콘텐츠 자산)
- **가드레일과 실패**: 입력이 안 잡히거나 신뢰도가 낮으면 재시도 안내(한도 §3.라 운영 파라미터), 지연 시 구간 점수 보류, 터치 미입력 타임아웃(입력이나 손 미검출) 시 Step 7
- **의존**: 입력은 §4.가 고증의 조작 동작 기준과 §4.나 3D 아바타. 출력 게이지 점수와 등급이 §4.마 생성의 입력. 절정 연출은 §4.라 골계 반전으로 이어짐

## 라. 골계 반전 연출 (Step 4 절정)

- **역할**: 한 판의 절정에서 골계적 반전(홍동지 등장과 이시미 퇴치)을 결정적 빠른 입력 이벤트(Quick Time Event)로 연출해 카타르시스를 줌
- **입력과 출력**: 입력은 절정 진입 신호(누적 채점이나 거리 진행)와 유저의 타이밍 입력. 출력은 반전 연출 결과(성공과 실패 분기)와 게이지 가산
- **동작과 규칙**
	- 절정 연출: 홍동지가 등장해 이시미(이무기)를 때려잡는 덜미 이시미거리의 골계 구조를 연출함 ([[덜미#2. 박첨지마당 (4거리)]] 이시미거리)
	- 빠른 입력 이벤트: 정해진 짧은 시간 안에 제시 입력을 맞추면 퇴치 성공 연출, 놓치면 산받이가 눙치는 대체 연출로 자연스럽게 맺음(무인 운영이라 실패해도 흐름이 끊기지 않게)
	- 입력 윈도우는 §3.라 운영 파라미터. 세부 연출(컷 구성, 성공과 실패 분기 대사)은 작성 예정
- **기술 요건**: 사전 제작 연출 자산의 재생과 타이밍 입력 판정. 별도 AI 없이 클라이언트 연출 로직으로 구현(서버 채점 연동 여부 확인 필요)
- **자산 요구**: 골계 반전 연출 컷과 사운드, 홍동지와 이시미 캐릭터 에셋(§4.사 콘텐츠 자산)
- **가드레일과 실패**: 연출 요소라 안전 검사 대상은 사전 자산 검수(§4.아 가드레일 사전 지점). 입력 실패 시 대체 연출로 맺어 흐름 유지
- **의존**: 입력은 §4.다 채점의 절정 진입과 §4.가 고증의 거리 골격. 출력 결과는 §4.다 게이지와 §4.마 기념 사진(달성 등급)에 반영

## 마. 기념 사진 생성 (Step 5)

- **역할**: 촬영본에 3D 인형 아바타를 재합성하고 신명 게이지 점수와 등급을 스탬프로 표기한 기념 사진을 만듦
- **입력과 출력**: 입력은 카메라 촬영본, 3D 인형 아바타(캐릭터 합성용), Step 4 신명 게이지 점수와 등급. 출력은 기념 사진(점수와 등급을 스탬프로 표기)
- **동작과 규칙**
	- 기념 사진: 라이브 화면은 포즈용 미리보기, 최종 저장본은 촬영본에 인형 아바타 캐릭터를 고품질 재합성하고 테두리 프레임을 두른 뒤 신명 게이지 점수와 등급을 스탬프로 표기함
- **기술 요건**: 사진 합성과 스탬프 오버레이는 키오스크 부하 고려해 서버에서 진행. 정량값(해상도, 파일 형식)은 구현 시 확정
- **자산 요구**: 기념 사진 프레임(§4.사 콘텐츠 자산), 점수와 등급 스탬프(§4.사 콘텐츠 자산)
- **가드레일과 실패**: 생성된 기념 사진의 출력 가드레일. 미통과나 재생성 한도 초과 시 위험물 파기, 재생성 실패 시 에러. 촬영 0회 시 사진 생성 생략하고 실패 처리
- **의존**: 입력은 §4.나 아바타와 §4.다 채점 결과(점수와 등급). 출력은 §6 산출물과 Step 6 전송

## 바. 산받이 진행 호스트

- **역할**: 인형과 재담을 주고받는 덜미 산받이의 화자. 무대 밖에서 인형에게 말을 붙이고 관객과 대거리하는 전통 기능을 진행 안내와 추임새로 계승 (버나 매호씨와 같은 재담 상대역 계열, [[버나 - 버나잡이 한 판 기획서#바. 매호씨 진행 호스트]]). 전 Step을 잇는 목소리로 미션 제시부터 채점 추임새, 기념 촬영까지 안내 (공통 골격은 [[시범콘텐츠 공통 사양#6. 진행 호스트]])
- **동작과 규칙**: 재담과 추임새. 동작 채점 피드백을 추임새로 전달(§4.다 연동), 점수가 낮으면 재담으로 응수. 게이지 미달 시 눙치며 마무리. 세부 페르소나(말투, 어휘, 반응 패턴)는 작성 예정
- **기술 요건**: 산받이 호스트 렌더러는 공통 UI 컴포넌트임. 구현 정본은 §5.다 5) 클라이언트 UI. 렌더 방식과 구현 기술은 작성 예정
- **자산 요구**: 산받이 호스트 에셋(비주얼, 음성(TTS), 추임새와 대사, §4.사 콘텐츠 자산)
- **가드레일과 실패**: 해당 없음(연출 요소)
- **의존**: 전 Step 연출. 채점(§4.다 양손 조작과 장단 채점) 결과를 피드백
- **고증 주의**: 산받이 배역 해석은 [[덜미]] 채록본 수준의 추정임. 세부 검증은 고증 자문(확인 필요)

## 사. 콘텐츠 자산

제작과 발주, 견적 입력용 자산 목록. 정량(수량, 규격, 제작 방식)은 확인 필요(골격, 작성 예정). 각 자산이 어느 구성 요소에 쓰이는지 용도에 표기.

1. **인형 두상과 몸체 베이스 모델** (생성 베이스)
	- 제작 방식: 외주 또는 자체(확인 필요)
	- 용도: 얼굴 기반 아바타 생성의 목각 인형 베이스 (§4.나 얼굴 기반 인형 아바타 생성, Step 3)
2. **목각 인형 양식 레퍼런스** (생성 레퍼런스)
	- 제작 방식: 고증 자문, 자체
	- 용도: 아바타 질감과 캐릭터 양식 기준 (§4.가 인형과 조작 고증, §4.나 아바타 생성)
3. **인형 조작 동작 레퍼런스** (채점 기준)
	- 제작 방식: 모캡 등(확인 필요), 고증 자문
	- 용도: 따라 하기 대상과 채점 기준 (§4.다 양손 조작과 장단 채점, Step 4)
4. **풍물 장단 음원** (음향)
	- 제작 방식: 무저작권, 자체, AI 생성
	- 용도: 조작 타이밍 기준 (Step 4)
5. **환호와 추임새 사운드** (음향)
	- 제작 방식: 확인 필요
	- 용도: 신명 게이지 달성 보상 (Step 4)
6. **골계 반전 연출 컷과 캐릭터 에셋** (연출)
	- 제작 방식: 외주 또는 자체(확인 필요)
	- 용도: 절정 연출, 홍동지와 이시미 캐릭터 (§4.라 골계 반전 연출, Step 4)
7. **기념 사진 프레임과 점수 등급 스탬프** (출력 양식)
	- 제작 방식: 외주 또는 자체(확인 필요)
	- 용도: 기념 사진 프레임과 신명 게이지 점수 등급 스탬프 오버레이 (Step 5)
8. **산받이 호스트 에셋** (캐릭터와 음성)
	- 제작 방식: 확인 필요(비주얼, TTS, 대사)
	- 용도: 진행 호스트 (§4.바 산받이 진행 호스트)
9. **키오스크 UI와 화면 그래픽** (UI 디자인)
	- 제작 방식: 외주 또는 자체(확인 필요)
	- 용도: 전 화면(상세는 [[덜미 - 나만의 꼭두각시 UI]]). 화면 수는 UI 설계에서 확정(잠정값)
10. **대기 화면 콘텐츠** (대기 콘텐츠)
	- 제작 방식: 확인 필요
	- 용도: Step 3 생성 대기, Step 5 생성 대기

## 아. AI 가드레일 (전 Step 입출력, 횡단)

- **역할**: 얼굴 촬영 입력, 생성 아바타, 기념 사진 출력의 안전성과 전통 정합성 검사
- **입력과 출력**: 입력은 검사 대상(얼굴 이미지, 3D 아바타, 기념 사진). 출력은 통과 또는 차단 판정과 사유
- **동작과 규칙**: 입력(Step 2)과 출력(Step 3, Step 5) 검사. 공용 기능 AI 가드레일 호출, 적용 3지점 준용 ([[시범콘텐츠 공통 사양#나. 가드레일 적용 3지점]])
	- 사전(운영 전 생성): 인형 양식과 골계 반전 연출 자산 검수 (§4.가 고증, §4.라 골계 반전 연출)
	- 입력(Step 2): 부적절 촬영 입력 차단 후 재촬영
	- 출력(Step 3): 아바타 위반 시 재생성, 한도 초과 시 대체 처리
	- 출력(Step 5): 기념 사진 위반 시 재생성, 한도 초과 시 에러
- **기술 요건**: 부적절 콘텐츠 분류와 전통 왜곡 판정. 외부 가드레일 API와 자체 기준 조합 검토(확인 필요). 판정 기준은 차단 정확도(오탐과 미탐), 재생성 한도, 검사 지연(정량 구현 확정)
- **자산 요구**: 부적절 입력과 전통 왜곡 판정 기준 데이터(작성 예정)
- **가드레일과 실패**: 재시도와 재생성 한도는 §3.라 운영 파라미터
- **의존**: 횡단. §4.나 아바타 생성, 마 기념 사진 생성의 입출력에 적용하며, 전통 왜곡과 정합성 판정 기준은 §4.가 고증을 따름. 세부 정책(부적절 입력 분류, 전통 왜곡 판정, 동의 항목 구체화)은 작성 예정

# 5. 공유 계층과 기술 구성

세션, 개인정보와 연속성, 기술 6영역은 [[시범콘텐츠 공통 사양]]과 [[플랫폼 사양]]을 따르고, 본 콘텐츠 고유분만 적음.

## 가. 세션과 데이터

라이프사이클과 Step별 동작은 [[시범콘텐츠 공통 사양#2. 세션]] 준용. 본 콘텐츠 고유 데이터(얼굴 캡처, 3D 아바타, 채점, 사진)로 재정의함.

- **라이프사이클**: 생성(Step 1, 미동의나 타임아웃 시 종료 처리에서 파기) → 갱신(Step 2~6 산출물 저장) → 종료(Step 7 파기와 리셋)

세션이 담는 데이터를 분류, 값, 보관과 파기로 정리함. 개인정보 민감 데이터(영상 피드, 얼굴 캡처, 기념 사진)에 최소 보관 원칙을 적용함. 보관 기간 잠정값은 규정 검토 후 확정함(임의 추정 금지).

| 데이터 | 분류 | 값과 구성 | 보관과 파기 |
| --- | --- | --- | --- |
| 세션 ID | 시스템 | 세션 고유 식별자 | 세션 종료 시 파기 |
| 동의 기록 | 시스템 | 약관 버전 + 동의 일시 + 동의 항목(필수: 카메라 촬영) | 보관 (기간 확인 필요) |
| 얼굴 캡처 | 개인정보 | 아바타 생성 입력 얼굴 프레임 | 메모리 임시, 아바타 생성 직후 파기 |
| 3D 인형 아바타 | 콘텐츠 | 생성된 3D 아바타 자산 | 별도 저장소 보관 |
| 동작 채점 기록 | 콘텐츠 | 동작 일치도와 타이밍 점수, 신명 게이지 | 익명 통계 보관, 식별 원본은 세션 종료 시 파기 |
| 기념 사진 | 콘텐츠 | 사용자와 인형 아바타 동반 포즈 사진(신명 게이지 점수와 등급을 스탬프로 표기) | 결과 페이지 임시 보관, 다운로드 만료(48시간) 시 파기 |
| 영상 피드 | 개인정보 | 카메라 원본 스트림(얼굴 촬영, 아바타 조작 핸드 트래킹, 기념 촬영 입력) | 메모리 임시, 처리 직후 파기 |

임시 데이터를 저장 위치로 나눠 정리함. 파기 시점은 위 §5.가 세션 데이터 표를 따름.

- **메모리 임시 보관** (영상 피드, 얼굴 캡처)
	- 보관: 메모리나 임시 버퍼에만, 디스크 영속화와 로그 기록 금지
	- 파기: 파기 시점은 위 §5.가 표가 정본. 시점이 되면 메모리를 명시적으로 덮어쓰는 방식으로 즉시 파기함 ([[시범콘텐츠 공통 사양#가. 개인정보 처리 정책 (공통 원칙)]] 준용)
- **결과 페이지 임시 보관** (기념 사진)
	- 보관: 다운로드 제공용 서버 임시 저장소에만 두고 로그 기록 금지
	- 파기: 다운로드 만료(48시간) 시 파기(만료 전 재열람과 재다운로드 자유). 결과물을 화면 QR로 익명 다운로드하며 연락처를 수집하지 않아 전송 수단별 분기가 없음 (§3.다 6) Step 6. 결과물 전송)
- **별도 저장소 보관**
	- 목적: 3D 아바타는 재변환 비용 회피와 품질 분석
	- 파기 시점: 미정, 규정 검토 후 확정(콘텐츠 자산 저장소 정책, 작성 예정)

- **카메라 촬영 주의**: 카메라로 얼굴을 촬영(아바타 생성, 기념 사진)하므로 개인정보 민감도가 높음. 세부 처리와 규정 검토는 아래 나. 개인정보와 연속성

## 나. 개인정보와 연속성

데이터별 보관과 파기는 위 가. 세션 데이터 표가 정본임. 본 절은 본 콘텐츠 고유의 개인정보 범위와 동의를 정의하고, 사용자 프로필과 연속성 공통 정책은 [[플랫폼 사양]]을 따름.

- **개인정보 범위** (전화번호 미수집)
	- 얼굴과 손 영상, 얼굴 캡처 (영상 피드, 개인정보. 얼굴 촬영과 Step 4 핸드 트래킹, 기념 촬영에 쓰임)
	- 기념 사진 (분류는 콘텐츠지만 얼굴이 담긴 결과물이라 개인정보 처리 병행)
- **결과물 전달**: 화면 QR로 익명 다운로드하며 연락처를 수집하지 않음 (§3.다 6) Step 6. 결과물 전송). 결과물 호스팅과 만료 파기 정본은 [[플랫폼 사양#4. 결과물 전송과 호스팅]]
- **동의 범위**
	- 필수: 카메라 촬영 (얼굴 촬영과 아바타 생성, 기념 사진 촬영)
	- 고지: 기념 사진은 얼굴이 담긴 결과물임. 이를 생성하고 저장하며 결과 페이지로 48시간 제공하는 처리를 개인정보 수집 및 이용 안내에 포함함 (정확한 안내 문구와 동의 범위는 규정 검토 후 확정)
- **재방문 연속성 (2차연도 전방 설계, 1차연도 미적용)**: 학습 프로필, 이어하기, 학습 토큰, 콘텐츠 횡단 누적은 2차연도로 두며 1차연도는 익명 1회로 운영함. 모델과 보안은 [[플랫폼 사양#6. 2차연도 전방 설계 (디지털 도제 연속성, 현재 구현 밖)]] 정본(현재 구현 밖)
- **세부 정책 (작성 예정)**: 보관 기간 잠정값은 규정 검토 후 확정, 임의 추정 금지

## 다. 기술 구성

본 콘텐츠 구현 시스템을 영역별로 정리함. 영역 구분과 1차연도 공통 기술 방향(LLM, STT, 모션 인식 한계 등)은 [[시범콘텐츠 공통 사양#7. 기술 구성 (6영역 템플릿)]]을 따르고, 아래는 영역별 본 콘텐츠 구현 내용임.

### 1) AI 시스템

얼굴 기반 인형 아바타 생성, 양손 조작과 장단 채점, 기념 사진 생성, AI 가드레일로 구성됨. 각 모듈 명세는 §4 구성 요소(§4.나 얼굴 기반 인형 아바타 생성, §4.다 양손 조작과 장단 채점, §4.마 기념 사진 생성, §4.아 AI 가드레일)에서 다룸. 골계 반전 연출(§4.라)은 사전 자산 재생이라 AI 모듈이 아닌 클라이언트 연출 로직임.

### 2) 하드웨어 (키오스크)

공통 키오스크 하드웨어를 씀(물리 사양 정본은 [[디바이스 사양]], 공통 골격은 [[시범콘텐츠 공통 사양#나. 하드웨어 (키오스크)]]). 본 콘텐츠는 얼굴 촬영과 양손 조작 때문에 카메라와 연산 요건이 더해짐. 입출력 구성:

- **디스플레이**: 16:9 가로형 터치 (크기와 해상도 확인 필요)
- **카메라**: 얼굴 촬영, 기념 촬영, 양손 핸드 트래킹용 (해상도와 프레임률 확인 필요)
- **음향 출력**: 풍물 장단과 산받이 음성, 환호 사운드 (스피커 사양 확인 필요)
- **마이크**: 음성 입력 사용 시 (미사용이면 생략 가능, 확인 필요)
- **연산 유닛**: 본체 연산. 온디바이스 추론 채택 시 GPU 사양 확인 필요
- **네트워크**: AI 서버 통신, 기념 사진 전송 (대역폭 확인 필요)

### 3) 백엔드

| 요소 | 역할 | 요건과 참조 |
| --- | --- | --- |
| API (키오스크와 AI 서버) | 요청과 응답 중계, 신뢰 경계 | 규격과 프로토콜, 인증(기기 자격/토큰 또는 mTLS), TLS, 개인정보 로깅 제외 (확인 필요) |
| 세션 관리 | 라이프사이클과 상태 저장 | 키오스크당 1세션 가정(동시 세션 수 확인 필요). §5.가 세션과 데이터 |
| 진행 제어(상태 머신) | Step 순차 진행과 분기, 에러 분기 | 주요 상태: 동의 대기와 거부, 생성 실패, 호스팅 실패, 타임아웃, 실패 처리, 정리와 파기, 리셋. 분기 상세는 §3.다 Step별 흐름 |

| 개인정보 처리 집행 | 영상 피드, 얼굴 캡처, 기념 사진 임시 저장과 파기 집행(파기 시점은 §5.가 표) | §5.나 개인정보와 연속성 |

### 4) 외부 서비스 연동

- **결과물 호스팅 서비스 (기념 사진)**
	- 방식: 기념 사진을 결과 페이지로 묶어 웹에 호스팅하고 그 다운로드 주소를 QR로 화면에 표시. 유저가 본인 휴대폰으로 스캔해 받음. 연락처를 받지 않음 ([[플랫폼 사양#4. 결과물 전송과 호스팅]] 준용)
	- 결과 페이지: 만료형 다운로드 URL(48시간). 기념 사진은 페이지 안 열람과 다운로드, 만료 전 재접근 허용
	- 저장과 파기: 저장 제공자, URL 만료, 파기 트리거(48시간) 명세 필요(세션 표와 정합). 제공자와 스토리지, 연동 방식 확인 필요
- **AI API (외부 모델 사용 시)**: 아바타 생성, 손 추정, 가드레일 등 외부 모델 호출(§4 구성 요소). 호출 래퍼와 재시도는 공용 기능 준용. 제공자와 요금 확인 필요

### 5) 클라이언트 UI (키오스크 앱)

화면의 시각과 레이아웃 상세는 [[덜미 - 나만의 꼭두각시 UI]] 정본. 본 절은 공통 컴포넌트와 구현 기술만 적음.

- **공통 UI 컴포넌트**: 여러 화면이 재사용하는 컴포넌트. 산받이 호스트 렌더러(역할 §4.바 산받이 진행 호스트), 아바타 조작 렌더러(3D 아바타 조작과 골계 반전 연출), 카메라 프리뷰와 촬영, 신명 게이지
- **입력 수단**: 카메라(얼굴과 양손 핸드 트래킹), 터치, 마이크(필요 시)
- **세션 종료와 리셋**: 화면 타임아웃과 터치 미입력 타임아웃 처리, 다음 유저용 시작 화면 복귀(Step 7)
- **구현 기술 (미정, 설계 단계 확정)**: 키오스크 앱 프레임워크, 페이지 전환과 터치 인터랙션 방식, 컴포넌트 렌더러 방식. 공통 컴포넌트를 어떤 기술로 구현할지 정하는 자리이나, 구체 기술 선택은 아직 미정

### 6) 운영과 모니터링

- **가동 모니터링**: 키오스크 온라인과 오프라인, 장애 상태
- **사용 로그와 지표**: 유저 수, 완주율, Step별 이탈, 오류율
- **알림**: AI 호출, 외부 서비스, 파기 실패 시 운영 알림(임계 §3.라 운영 파라미터)
- **실패 처리**: [[시범콘텐츠 공통 사양#바. 운영과 모니터링]] 준용

# 6. 산출물

- **기념 사진**: 맨 얼굴의 사용자 본인과 사용자 얼굴로 만든 3D 목각 인형 아바타가 나란히 포즈한 사진. 테두리 프레임을 두르고 신명 게이지 점수와 등급을 스탬프로 표기함
- **결과물 전달과 파기 정책**: §5.가 세션과 데이터 (화면 QR 익명 다운로드, 다운로드 만료 시 파기)
- **형식과 규격 (구현 확정)**: 해상도, 파일 형식 등

# 7. 일정과 마일스톤 연계

- **개발 순서**: [[1차연도 셀빅 개발 준비자료#나. 콘텐츠 개발 순서]] 체험형 계열(얼굴 기반 3D 생성과 실시간 동작 채점 스택 공유). 세부 일정과 마일스톤은 미정

# 8. 리스크와 검증

- **고증과 저작권**: 검증위원회 자문, 저작권과 고증 확인. 산받이와 골계 반전 해석은 [[덜미]] 채록본 기준 검증
- **카메라 촬영 개인정보**: 카메라로 얼굴을 촬영(아바타 생성, 기념 사진)해 개인정보 민감도가 높음. 영상 피드와 얼굴 캡처는 메모리 임시 처리 후 즉시 파기
- **양손 조작 입력 수단 (확정)**: 카메라 핸드 트래킹으로 확정함(2026-07-01 사용자 결정). 얼굴 촬영 카메라를 손 추정에 함께 쓰므로 개인정보 표면은 늘지 않음. 손 추정 모델 후보와 인식 정확도는 확인 필요(§4.다 양손 조작과 장단 채점)
- **추가 리스크 (작성 예정)**: 그 외 리스크와 검증 항목
