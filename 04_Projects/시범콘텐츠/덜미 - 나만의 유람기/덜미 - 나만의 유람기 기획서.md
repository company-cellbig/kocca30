> 덜미(꼭두각시놀음)를 소재로, 유저가 박첨지의 유람에 합류해 자기만의 유람기 한 편(그림동화 전자책)을 완성하는 AI 시범콘텐츠의 개발 기획서. 골격 단계로, 점차 채워나감.

# 1. 개요

## 가. 콘텐츠 정의

덜미(꼭두각시놀음)를 소재로 한 AI 그림동화 콘텐츠. 유저는 박첨지(떠돌이 노인)의 유람에 주인공으로 합류해, AI가 제시한 마당(플롯)을 거리별 선택과 응답으로 채워 자기만의 유람기 한 편을 완성함. "나만의 유람기"는 이 경험을 가리키고, 그 산출물은 그림동화 전자책 형식으로 남음.

- **소재**: 한국 전통 인형극 덜미(꼭두각시놀음) ([[덜미]])
- **기본 구조**: 덜미 위계는 `굿(극) > 마당(막) > 거리(장/경)` (심우성 남사당놀이 분류). 본 콘텐츠의 플롯 단위는 **마당**, 그 안을 **거리**가 구성 (상세 §3.나)
- **플로우**: AI가 거리 문법 기반 플롯 제시 → 유저가 캐릭터 정보와 거리별 응답(상황별 행동, 이야기 전개)을 입력 → AI가 일러스트와 서사를 묶어 그림동화 전자책 생성- **매체**: 16:9 가로형 키오스크 터치 인터페이스- **핵심 특성**: 덜미의 문학적 골격(재담, 풍자, 거리식 구성)은 고정하고, 그 안의 사건과 해설과 이야기를 유저 입력과 AI 생성으로 채워 매번 다른 그림동화를 만듦- **산출물**: 2D 일러스트 + 텍스트 (PDF, EPUB, 이미지 묶음 등 형식은 미정)
- **사용자 연속성 (1년차 범위)**: 본 콘텐츠 1년차는 익명 1회성으로 운영함(결과물 전송 후 파기). [[플랫폼 사양]]의 옵트인 학습 프로필과 이어하기, 콘텐츠 횡단 누적 연계는 2차연도로 둠 ([[플랫폼 사양#6. 2차연도 전방 설계 (디지털 도제 연속성, 현재 구현 밖)]])

목표, 범위 등 나머지 개요 항목은 작성 예정.

# 2. 시스템 플로우

- 매체: 16:9 가로형 키오스크 터치. 플레이타임 목표 5분 (세션 전체 S1~S7 합산 목표, 강제 카운트다운 아님)
- 큰 흐름(스케치): 인트로(동의 약관) → 거리별 입력 → AI 생성 → 그림동화 결과

> 단계별 진행, 담당 시스템, 프로세스, 입출력을 표기. 사용자 측 기본 흐름(시작/진행/마무리)을 시스템 관점으로 확장. §4 기술 구성의 각 모듈이 단계별로 어떻게 협력하는지 보임.

**표기**: `S` = Step(순차 단계). S1~S7은 진행 순서대로의 단계 ID

**개요**: S1 인트로 → S2 캐릭터 정보 입력 → S3 마당 선택 + 플롯 문답 → S4 결과물 생성 + 대기 화면 (병행) → S5 결과물 표시 → S6 결과물 전송 → S7 종료/리셋

## 가. 세션

### 1) 세션 정의

한 유저의 키오스크 사용 전체(S1 시작 → S7 종료)를 감싸는 상위 컨테이너. 하위 Step들이 세션 안에서 순차 실행됨.

- **라이프사이클**: 생성(S1, 신규) → 상태 저장 반복(S2~S6, 진행 중) → 종료 + 리셋(S7, 종료)
- **관리 모듈**: §4.다 백엔드 (세션 라이프사이클과 세션 안 데이터 저장 책임을 가진 §4 시스템 영역)

### 2) 세션 안 저장 데이터

콘텐츠 입력은 개인정보 아님(그림동화 생성용). 개인정보는 전화번호 단일. 아래 표는 세션이 저장하는 데이터와 들어가는 값을 정리함. **타입/저장 스키마/인덱스 등 구현 모델은 적지 않음**. "어떤 값이 들어가는가"까지가 기획 범위, 구현 모델은 §4.다 백엔드 및 개발자 결정.

| 데이터 | 분류 | 들어가는 값과 구성 | 수명 | 비고 |
|---|---|---|---|---|
| 세션 ID | 시스템 | 세션마다 부여되는 고유 식별자 | 휘발 (세션 종료 시 파기) | S1 sub-step 1에서 생성 |
| 동의 기록 | 시스템 | 약관 버전 + 동의 시각 | 보관 (§4.다.1, 잠정 5년) | 약관 버전 체계 운영 결정 |
| 캐릭터 정보 | 콘텐츠 입력 | 연령대(아이/청소년/청년/장년), 성별(남/여), 이름 | 확인 필요 (§4.다.1 콘텐츠 데이터 보관 정책. S7 임시 데이터 파기와 정합 미정) | 8개 카드 = 연령대 × 성별. 유저 주인공 설정 |
| 선택 마당 | 콘텐츠 입력 | 유저가 고른 유형(위협-구원/권력/위선/욕심 중 1) + 그 유형 풀에서 랜덤 배정된 마당 플롯 | 확인 필요 (동일) | §3.나.4 (유형 선택 + 랜덤 배정) |
| 거리별 응답 | 콘텐츠 입력 | 거리별(도입/전개/절정/마무리) 유저 응답, 거리 순서대로 누적 | 확인 필요 (동일) | 본편 응답 |
| 박첨지 진행 대화 로그 | 콘텐츠 입력 | 거리별 박첨지 질문 + 유저 응답 쌍 | 보관 (§4.다.1, 잠정 14일) | 디버깅/품질 분석용 |
| 그림동화 결과물 | 콘텐츠 입력 | 다중 페이지 결과물 + 메타(생성 시각 등) | 보관 (§4.다.1, 호스팅 잠정 30일) | 포맷(PDF, EPUB, 이미지 묶음) 결정 미정 |
| 전화번호 | 개인정보 | 유저 연락처 (SMS 발송용) | 휘발 (발송 후 즉시 파기, 거부 시 즉시) | S6 전송 동의 시 임시 저장. 상세 §4.다.1 |

### 3) Step별 세션 동작

| Step | 세션 동작 |
|---|---|
| S1 | 세션 생성 |
| S2~S6 | 세션 데이터 갱신 |
| S7 | 세션 종료 + 임시 데이터 파기 + 리셋 |

## 나. Step

Step은 시스템 플로우의 순차 단위. 본 절에서 Step 정의 및 공용 기능과 Step별 명세를 다룸.

### 1) Step 프레임 (공통)

Step 정의와 명세 항목은 [[시범콘텐츠 공통 사양#3. Step 모델]] 참조. 공용 기능은 아래 공통 표를 따름 (본 콘텐츠 적용 지점: 입력 유효성=S2 이름/S3 응답/S6 전화번호, 가드레일=사전 플롯/S3/S4 3지점은 §2.나.2 Step별 명세와 §3.라 가드레일 참조).

### 2) Step별 명세

#### 가) S1. 인트로 (시작 + 동의)

- **트리거**: 유저가 시작 버튼 터치
- **시스템**: 클라이언트 UI (§4.마), 백엔드 (§4.다)
- **프로세스**
	1. 백엔드: 신규 세션 생성
	2. UI: 인사말 화면 표시 + "터치하세요" 안내
	3. UI: 터치 감지 → 진행 가이드 화면
	4. UI: 터치 감지 → 고객 동의 약관(주의사항) 화면
	5. UI: 동의 버튼 터치 감지 (동의 화면, 화면 타임아웃 미적용)
		- 호출 공용 기능: 터치 미입력 타임아웃
		- 분기: 터치 미입력 타임아웃 발동 시 미동의로 간주 → S7 직행 (별도 거부 버튼 없음)
	6. 백엔드: 동의 기록 저장 (세션 ID, 약관 버전, 타임스탬프)
- **입력**: 터치 이벤트, 동의 결정
- **출력**: 세션 ID, 동의 기록
- **다음**: S2

#### 나) S2. 캐릭터 정보 입력

- **트리거**: S1 동의 완료
- **시스템**: 클라이언트 UI (§4.마), 백엔드 (§4.다)
- **프로세스**
	1. UI: 이름 입력 폼 (유저 주인공 설정. §3.다.2 유저 입력 슬롯 설계와 연동)
	2. UI: 이름 유효성 검증 (클라이언트 비속어 필터)
		- 호출 공용 기능: 입력 유효성 검증
		- 분기: 비속어 검출 시 팝업 안내 → sub-step 1로 재진입
	3. UI: 8개 카드(아이/청소년/청년/장년 × 남/여) 중 1개 선택
		- 호출 공용 기능: 터치 미입력 타임아웃 (이름 입력, 카드 선택 모두 필수 입력 화면, 화면 타임아웃 미적용)
		- 분기: 터치 미입력 타임아웃 → S7 직행
	4. 백엔드: 세션에 캐릭터 정보 저장
- **입력**: 이름, 카드 선택(성별 × 연령대)
- **출력**: 세션 캐릭터 정보 갱신
- **다음**: S3

#### 다) S3. 마당 선택 + 플롯 문답 (거리별 반복)

- **트리거**: 캐릭터 정보 입력 완료
- **시스템**: AI 시스템 (§4.가), 클라이언트 UI (§4.마), 백엔드 (§4.다)
- **프로세스**: 유저가 마당 유형을 고르면 시스템이 그 유형 풀에서 랜덤 마당을 배정(sub-step 1~2), 이후 배정된 마당의 4거리(도입/전개/절정/마무리, §3.나.2)를 순서대로 sub-step 3~5 묶음 반복
	1. UI: 마당 유형 4종 카드 제시 → 유저가 1개 선택
		- 호출 공용 기능: 터치 미입력 타임아웃 (필수 입력 화면, 화면 타임아웃 미적용)
		- 분기: 터치 미입력 타임아웃 → S7 직행
	2. 백엔드: 선택 유형 풀에서 랜덤 마당 1개 배정 (사전 생성/검수된 플롯, §3.나.4)
	3. UI(박첨지): 박첨지 캐릭터 + 해당 거리의 사전 생성 질문 표시(고정), 유저 응답 입력 받기 (가상 키보드 기본, 음성 인식(STT) 입력 병행 → 변환된 텍스트로 처리)
		- 호출 공용 기능: 터치 미입력 타임아웃 (필수 입력 화면, 화면 타임아웃 미적용)
		- 분기: 터치 미입력 타임아웃 → S7 직행
	4. AI 가드레일: 유저 응답 검사 (§3.라)
		- 호출 공용 기능: AI 가드레일
		- 분기: 위반 시 팝업 안내 → sub-step 3으로 재진입 (유저 재입력)
	5. 백엔드: 응답을 세션에 누적 저장
- **입력**: 마당 유형 선택(유저), 거리별 응답(텍스트: 가상 키보드 또는 STT 음성)
- **출력**: 선택 유형 + 배정 마당, 거리별 응답 누적, 박첨지 진행 대화 로그
- **다음**: 모든 거리 완료 시 S4

#### 라) S4. 결과물 생성 + 대기 화면 (병행)

- **트리거**: 플롯 문답 완료
- **시스템**: AI 시스템 (§4.가), 클라이언트 UI (§4.마), 백엔드 (§4.다), 외부 서비스 (§4.라)
- **프로세스** (백그라운드와 포그라운드 동시, 상태 조회로 동기화)
	- **백그라운드: 결과물 생성**
		1. AI 유저 입력 가공 대규모 언어 모델(LLM): 응답을 거리별 서사 텍스트로 변환
		2. AI 이미지 생성 모델: 거리별 일러스트 생성 (§3.가 시각 정체성, §3.마 자산)
		3. 결과물 조립(§4.다 백엔드): 서사와 일러스트를 그림동화 페이지로 결합
		4. **AI 가드레일: 생성물 출력 검사** (§3.라). 서사(유저 입력 삽입 포함)/일러스트가 가드레일 정책 통과하는지 검사
			- 분기: 위반 시 sub-step 1로 재생성 (N회 한도). 한도 초과 시 상태 `failed`
		5. 백엔드: 검사 통과한 결과물을 저장소에 저장
		- 실패: AI 호출(LLM/이미지 생성) 실패 시 재시도 N회(예: 2회) 후 failed 전환. 포그라운드 상태 조회가 검출 → 사과 화면 → S7. 구체 N/상태 조회 주기는 구현 단계 운영 파라미터로 확정 (§4.바 운영/모니터링)
		- 백엔드 상태 머신: `generating` / `completed`(가드레일 통과분만) / `failed` (생성 실패 또는 가드레일 한도 초과)
	- **포그라운드: 대기 화면**
		1. UI: 대기 콘텐츠 노출: 덜미 준비 과정 영상(§3.마 자산) 또는 큐레이션된 다른 유저 결과물(공개 동의분 운영 선별, 비제작 운영 기능)
		2. UI: 백엔드 상태 조회 (주기 예: 1초)
			- 분기:
				- `generating` → 대기 화면 유지
				- `completed` → 즉시 S5 전환
				- `failed` → 사과 화면 → S7
				- 상태 조회 N회 연속 무응답 (예: 5회) → 자체 에러 화면 → S7
- **입력**: 세션 응답 전체, 캐릭터 이름
- **출력**: 그림동화 파일 (다중 페이지)
- **다음**: 포그라운드 상태 조회가 `completed` 받으면 즉시 S5

#### 마) S5. 결과물 표시

- **트리거**: 그림동화 파일 생성 완료
- **시스템**: 클라이언트 UI (§4.마), 백엔드 (§4.다)
- **프로세스**
	1. UI: 결과물 첫 페이지 표시
	2. UI: 페이지 넘김 인터랙션(터치). 감상/열람 화면 (터치 미입력 타임아웃 미적용)
		- 호출 공용 기능: 화면 타임아웃
		- 분기: 화면 타임아웃 발동 시 정상 진행 경로를 따라 전송 단계(S6)로 넘어감(감상 종료로 간주)
	3. UI: 마지막 페이지 도달 시 "전송" 버튼 노출 (자동 전환 옵션도 UI 디자인 단계에서 검토)
- **입력**: 그림동화 파일
- **출력**: 유저가 결과물 확인
- **다음**: 유저가 "전송" 버튼 진행 → S6 (전송 안내 화면은 S6 시작 단계에서 표시)

#### 바) S6. 결과물 전송

- **트리거**: 유저가 전송 안내 화면에서 진행
- **시스템**: 클라이언트 UI (§4.마), 백엔드 (§4.다), 외부 서비스 (§4.라)
- **프로세스**
	1. UI: 전화번호 입력 폼, 개인정보 수집과 이용 안내 (필수 입력 화면, 화면 타임아웃 미적용). 전송 버튼 탭이 곧 발송 동의, 받지 않기 탭이 거부임(별도 동의 토글 없음, 고지 요소는 [[시범콘텐츠 공통 사양#5. 공통 화면]] 라)
		- 호출 공용 기능: 터치 미입력 타임아웃
		- 분기: 전송 거부 시 SMS 단계 생략, S7로
		- 분기: 터치 미입력 타임아웃 발동 시 유저 이탈로 보고 연락처 즉시 파기 + S7 직행
	2. 백엔드: 전화번호 임시 저장 (개인정보 처리 정책 1차/즉시 파기: 전송 동의 시 SMS 발송 직후, 거부 시 즉시. 세션 끝까지 보유 안 함)
	3. 외부 서비스 SMS: 결과물 호스팅 URL 또는 이미지 전송
		- 호출 공용 기능: 외부 서비스 호출 래퍼
		- 분기 (실패 유형별):
			- 통신 경로 일시 장애 (네트워크/게이트웨이/통신사) → 재시도 N회 (예: 2회, 백오프 1차 1초, 2차 3초)
			- 수신 번호 영구 실패 (없는 번호, 잘못된 형식, 차단된 번호) → "전화번호 확인" 팝업 + 재입력 1회 허용 후 S7
			- 그 외 영구 실패 (콘텐츠 거부 등) → 사과 후 S7 + 운영 모니터링 알림
- **입력**: 전화번호, 전송/받지 않기 선택(= 발송 동의/거부)
- **출력**: SMS 발송 결과
- **다음**: S7

#### 사) S7. 종료 / 리셋

- **트리거**: 결과물 전송 완료 또는 미동의 또는 터치 미입력 타임아웃 (유저 이탈)
- **시스템**: 클라이언트 UI (§4.마), 백엔드 (§4.다)
- **프로세스**
	1. UI: 마무리 인사 화면
	2. 백엔드: 세션 종료, 임시 데이터 파기 (개인정보 처리 정책: 전화번호 잔류 시 즉시 파기 = 2차/백스톱. 콘텐츠 데이터는 결과물 호스팅 후 정책 기간 보관)
	3. UI: 시작 화면 복귀 (다음 유저 대기)
- **입력**: 종료 트리거
- **출력**: 키오스크 idle 상태
- **다음**: 다음 유저용 S1 대기

# 3. 콘텐츠 설계

본 콘텐츠의 정체성(박첨지 진행 호스트, 플롯 구조, 변주, 가드레일, 자산)을 정의. §4 기술 구성은 본 절에서 정의된 것의 구현/배치를 다룸.

## 가. 박첨지 진행 호스트

본 콘텐츠의 정체성 중심. 유저가 주인공으로 이야기 중심에 서고, 모든 플롯 진행을 박첨지가 해설/길잡이로 엮음. 공통 골격은 [[시범콘텐츠 공통 사양#6. 진행 호스트]]를 따르고, 아래는 박첨지 고유 페르소나임.

- **역할**: 떠돌이 노인 해설자/길잡이, 거리를 잇는 목소리. 유저가 사건 주인공이고, 박첨지는 그 여정을 해설/안내 (전통 "해설자 겸 주역"의 해설 기능 계승)
- **화법**: 산받이/관객과 주고받는 재담 양식 ([[덜미의 각본 재미 요소]] 참조)
- **시각 정체성**: 나무 인형극 박첨지 캐릭터의 도구와 의상 고유 특징 유지
- 세부 페르소나(말투, 어휘, 반응 패턴 등) 작성 예정

## 나. 플롯 구조

> 한 세션 = 한 마당 = 완결된 그림동화 한 편. AI가 덜미 문법으로 4종 마당 유형의 플롯을 사전 생성해 두고, 유저가 유형을 고르면 그 유형 마당 하나가 랜덤으로 주어져 거리 단위로 채움. 유저가 주인공, 박첨지는 그 여정을 잇는 해설자/길잡이.

**플롯 단위 = 마당** (위계는 §1.가 기본 구조). 정리된 덜미 문법(마당/거리 분석으로 추출한 설계 자산)을 토대로 AI가 **다수의 마당 플롯을 생성**. 마당마다 틀(구조)이 다른 여러 골격(4종)임.

### 1) 마당 = 플롯 단위

- **마당 정의**: 박첨지 등장(도입)부터 닫는 해설(마무리)까지 하나의 인과 줄기로 이어지는 응집된 극 단위. 원형은 [[덜미]] 2마당 7거리
- **한 세션 = 한 마당 = 한 편의 그림동화**
- **여러 틀 중 하나로 생성 (4종)**: 마당은 고정된 한 틀이 아니라 4종 유형(§3.나.3) 중 하나로 만들어짐. 각 유형은 자기 고유 서사를 가진 독립 완결 구조임
- **같은 틀, 다른 내용 → 매번 다른 결과 (비고정 출력)**: 고정된 건 틀(유형의 구조)뿐. 세션마다 다른 결과는 두 축(① 사전 풀에서 랜덤 배정, ② 유저 입력)에서 나옴. 메커니즘은 §3.나.4, 변주가 일어나는 슬롯은 §3.다 참조

### 2) 마당 공통 골격

모든 유형은 박첨지가 여닫는 공통 골격을 공유. 한 마당 = 4거리. **플레이타임 목표 5분은 세션 전체(S1~S7, 마당 선택 포함) 합산 목표** (§2, 강제 카운트다운 아님). 아래는 본편 거리의 대략 배분 (비-거리 단계와 함께 5분 안에 듦):

| 거리(장면) | 기능 | 적용 범위 | 목표 시간 |
|---|---|---|---|
| 도입 | 박첨지 등장/유람 + 유저(주인공) 합류, 첫 재담 | 모든 유형 공통 | ~0.5분 |
| 전개 | 선택된 유형의 갈등 등장 | 유형별 (§3.나.3) | ~1.5분 |
| 절정 | 선택된 유형의 해소 | 유형별 (§3.나.3) | ~1.5분 |
| 마무리 | 박첨지 닫는 해설/맺음 인사 | 모든 유형 공통 | ~0.5분 |

- 본편 4거리 ~4분, 나머지 ~1분은 인트로/마당 선택/생성 대기/전송 등 비-거리 단계 (세션 전체 5분 목표 안)
- **도입/마무리는 박첨지가 직접 여닫음** (해설자/길잡이, 가져갈 것 1). **유저가 주인공**. 박첨지는 유저의 여정을 잇는 해설자/안내자 (본 문서 §3.가 박첨지 진행 호스트와 일치)
- 유형별로 다른 건 **전개+절정 2거리**. 이게 4종 구조를 가름

### 3) 마당 유형 (4종)

덜미 7거리의 갈등 핵을 4종 마당 구조로 정리. **각 구조는 전개→절정이 인과로 직결된 독립 완결 단위**. 전개의 갈등 대상이 그 마당의 절정에서 해소됨:

| 마당 유형  | 전개 (갈등)  | 절정 (해소)                            | 원형 거리    |
| ------ | -------- | ---------------------------------- | -------- |
| 위협-구원형 | 외부 위협 고조 | 유저가 맞서고 홍동지가 힘을 보태 함께 처치           | 이시미거리    |
| 권력 풍자형 | 권력자 허세   | 유저가 허세를 들춰내고 홍동지가 조롱으로 거듦 → 골계적 추락 | 매사냥+상여거리 |
| 위선 폭로형 | 위선 행각    | 유저가 위선을 드러내고 홍동지가 축출로 거듦 → 폭로/망신   | 피조리거리    |
| 욕심/다툼형 | 욕심 다툼    | 유저의 선택이 파국/손해/떠남을 가름               | 꼭두각시거리   |

- **절정은 유저(주인공)가 주도, 홍동지는 조력**(대체 아님). 홍동지 응징 카타르시스(가져갈 것 4)는 유형별로 다른 형태로 거듦: 위협-구원형(힘), 권력형(조롱), 위선형(축출). 보편 단일 절정 아님
- **욕심/다툼형은 홍동지 비중이 낮은 유형**: 원형 꼭두각시거리가 박첨지 가정사 중심이라 본디 홍동지가 약함. 대신 **유저의 선택이 파국/손해/떠남을 가름**(유저 능동성 유지). 홍동지 조력 변주는 추후 확장
- 각 유형 내부는 유저 입력 기반 무한 변주 (§3.나.4)

### 4) 생성/제시/채움 (사전 생성 + 런타임 선택)

> **A 고정 하이브리드**: 마당 플롯(거리별 질문 포함)은 사전 생성/검수, 런타임은 선택과 응답 수집만. 키오스크 무인 운영의 안전/속도/안정 우선 (§3.라, [[rfp_제안요청서]] §2 나 검증위원회).

- **사전 생성**: 마당 플롯 생성 LLM(§4.가)으로 유형별 다수 마당 플롯을 미리 생성. 거리별 박첨지 질문 텍스트까지 고정. 사전 가드레일 검수 후 풀에 저장 ([[마당 사건 풀]] 시드 활용)
- **유저 선택 (유형 단위)**: 유저는 **마당 유형 4종 중 하나를 선택**(병렬 카드). 시스템이 그 유형 풀에서 **랜덤으로 마당 1개 배정** = 주어진 마당 (§2.나 S3). 미입력 시 터치 미입력 타임아웃 정책
- **거리별 채움**: 주어진 마당의 거리(도입/전개/절정/마무리)를 순서대로 제시(고정 질문) → 유저가 각 거리에 응답. 이름/캐릭터는 슬롯 치환 정도의 가벼운 개인화
- **전자책 생성**: 종료 후 유저 응답 전체를 토대로 서사/일러스트를 런타임 생성 (§2.나 S4, §4.가 유저 입력 가공 LLM)
- **다양성 (비고정 출력의 근거)**: 마당 유형(4) × 유형별 사전 풀 크기 × 유저 응답 → 같은 유형도 매번 다름. 질문 적응형(유저 답 반영 재질문)은 2년차 검토 대상

## 다. 변주

### 1) 변주 정의

**변주** = 같은 틀(마당 유형/거리 골격)에 다른 내용(사건/풍자 대상/인물)을 넣어 매번 다른 결과를 만드는 것. 변주곡처럼 틀은 그대로 두고 내용만 바뀜. 변주는 두 갈래에서 일어남: 유저 입력 슬롯(§3.다.2), 사전 생성 단계의 AI 질문 변주(§3.다.3).

### 2) 유저 입력 슬롯

유저가 채운 입력이 이야기 전개의 재료가 됨 (원리: 유저 세계에서 생성된 위선과 권위로 교체). 다양성 메커니즘은 §3.나.4 생성/제시/채움 참조.

- **이름**: 주인공 이름
- **마당 선택**: 마당 유형 4종 중 택1
- **합류 계기**: 도입 거리 응답 (박첨지 여정에 합류하는 사연)
- **거리별 응답**: 전개/절정/마무리 각 거리의 유저 답

### 3) AI 질문 변주 (사전 생성)

같은 마당 유형이라도 질문이 단조롭지 않도록, 사전 생성 단계에서 유형 풀에 아래 차원의 변주를 충분히 마련하고 런타임은 그 풀에서 랜덤 선택.

- **사건 형태**: 거리 안에서 사건 컨텍스트가 변주 (예: 도입 거리가 길에서 / 잔치에서 / 시장에서 등)
- **풍자 대상**: 추상화된 권위/위선 형태 변주 (예: 권력 풍자형이 허세 권위자 / 겉만 번지르 / 횡포한 자 등)
- **박첨지 입장**: 목격자 / 당사자 / 풍자자 등 역할 변주
- **구현**: §4.가 사전 질문 생성 단계에서 다양성 메커니즘 적용 (prompt 변주, 유형별 사건 풀, temperature 조절 등; 구체 메커니즘은 구현 단계에서 발전). 사전 가드레일 검수로 §3.라 정책(특정 실명/단체 차단 등)을 풀 전체에 일관 적용

**변주 vs 일관성**: 위 3차원만 변주하고, 마당 유형/공통 골격의 고정 문법(§3.나.2~3)은 일관 유지. 예: 도입 거리는 항상 "박첨지 등장 + 유저 합류" 골격 유지, 그 안의 사건만 다양.

### 4) 세부 설계 (작성 예정)

유저 응답 → 사건 매핑 LLM 프롬프트, 마당 유형 제시/선택 로직 등. 작성 예정.

## 라. 가드레일

콘텐츠 정체성/안전 정책을 본 절에서 정의. 구현은 §4.가 AI 시스템의 가드레일 모듈에서.

### 1) 안전 체계

- **안전장치**: AI 가드레일 + 인트로 동의 약관 절차
- **외부 검증**: 검증위원회 자문 ([[rfp_제안요청서]] §2 나)

### 2) 적용 3지점

가드레일은 3지점에 적용. 사전 검수만으로 무인 안전이 닫히지 않으므로 출력 단계에서도 반드시 검사함.

- **사전** (운영 전 생성 단계): 마당 플롯 질문 생성 검수 (§4.가)
- **런타임 입력** (S3): 유저 응답 검사
- **런타임 출력** (S4): 전자책 생성물(서사/일러스트) 검사
	- 검사 항목: 유저 입력 삽입 안전, 전통 정체성 왜곡, 부적절 콘텐츠, 이미지 안전

### 3) 유형별 가드레일

마당 유형 4종(§3.나.3)별로 특정 대상 풍자를 차단하고 추상 대상으로 전환:

| 마당 유형 | 차단 | 추상화 방향 |
|---|---|---|
| 위협-구원형 | 특정 사람/집단 비방 | 가상의 위협 (특정 대상 아님) |
| 권력 풍자형 | 실제 정치인/공공인물 풍자 | 추상화된 권위 |
| 위선 폭로형 | 특정 실명/단체 풍자 | 윤리적 위선 (남을 속이는 행위 등) |
| 욕심/다툼형 | **처첩 삼각관계 default 금지** | 재산/명예/기회 |

### 4) 세부 정책 (작성 예정)

전통 왜곡 판정 기준, 부적절 콘텐츠 분류, 동의 약관 항목 구체화 등. 작성 예정.

## 마. 콘텐츠 자산

> 본 콘텐츠 제작에 필요한 자산 목록(발주/견적 입력). 산출 방식, 호스팅은 §4 기술 구성에서.

### 1) 자산 목록

**분류별 용도**: 캐릭터 레퍼런스/양식 가이드 = 생성 레퍼런스(이미지 모델 conditioning). 서사 데이터 = 실사용(산출물 직접 투입). 운영 영상 = 실사용(비출력, 그림동화 미포함).

| 자산 | 분류 (산출물) | 비고 |
|---|---|---|
| 덜미 인형 (전체) | 캐릭터 레퍼런스 (메커니즘 종속↓) | 박첨지/홍동지 등 전 인형. 상세는 2) 캐릭터 레퍼런스 |
| 유저 주인공 | 캐릭터 레퍼런스 (메커니즘 종속↓) | 연령×성별 8종, §2 S2 |
| 인형극 시각 양식 가이드 | 양식 가이드 (아트 디렉션 문서+예시) | 나무 인형 양식(질감/포장/색감) 정의, 동화풍 배제 |
| [[마당 사건 풀]] | 서사 데이터 (텍스트/JSON) | 플롯 생성용 사건 시드(**재료**). 거리/유형별 목표 5~10 (현 절정 ~4 보강 필요, §1), §3.다/§4.가 |
| 마당 플롯 풀(사전 생성) | 서사 데이터 (텍스트/JSON) | 사건 풀로 사전 생성한 완성 플롯(**완제품**, 런타임 배정 대상). 가드레일 검수, §3.나.4 |
| 대기 화면 영상 | 운영 영상 (영상 파일) | 덜미 준비 과정, 제작 방식 확인 필요(실사/애니/AI) |

### 2) 캐릭터 레퍼런스

- **대상**: 덜미에 등장하는 인형 전부가 시각 정체성 고정(레퍼런스) 대상. 핵심 인물(박첨지, 홍동지 등)은 시각 정체성을 고정하며, 전 인형으로 확대는 본 프로젝트 내부 결정. 유저 주인공 8종(§2 S2)은 별도 자산
- **시각/서사 분리**: 풍자 대상의 추상화(§3.라.3)는 서사 차원. 시각은 원작 덜미 인형을 레퍼런스로 양식 유지
- **종수 (미확정)**: 전체 인형 목록과 종수는 확인 필요. [[덜미]]가 현재 주요 6종만 문서화 → 채록본 기준 보강 후 종수 확정 (상세 추가 예정). **종수 미확정이라 하단 메커니즘/견적은 잠정, 인형 목록 확정 후 재산정**
- **산출물 형태 (미확정)**: 참조 이미지 수 장 vs 학습셋 수백 장은 일관성 메커니즘에 종속 → 하단 비교표 참조 (아트팀 협의 확정)

**일관성 메커니즘 비교 (아트팀 협의 후 확정)**

캐릭터 레퍼런스를 매 세션 일관 생성하는 방법. 선택에 따라 위 캐릭터 자산의 산출물 형태/수량/공수가 결정됨. 본 콘텐츠는 미정이며, 아트팀과 협의해 확정함.

| 메커니즘 | 발주 산출물 | 인물 일관성 | 제작 공수 | 비고 |
|---|---|---|---|---|
| 프롬프트/스타일 토큰 | 인물별 묘사 프롬프트 + 양식 예시 수 장 | 약함(세션 변동) | 낮음 | 빠르나 정체성 흔들림 |
| IP-Adapter/참조 이미지 | 인물별 참조 이미지 수 장(정면/측면/표정) | 중간 | 중간 | 학습 불필요, 런타임 조건화 |
| LoRA/파인튜닝 | 인물별 학습 데이터셋 수십~수백 장(태깅) + 학습 | 강함 | 높음 | 인물 수 많을수록 학습 부담↑ |

# 4. 기술 구성

본 콘텐츠 구현에 필요한 시스템을 6개 영역으로 정리. **AI 시스템(핵심 생성)을 앞에 두고, 기반(하드웨어/백엔드) → 연동(외부 서비스) → UI → 운영 순으로 배치.** 콘텐츠 자산(덜미 인형/양식 가이드/사건 풀/플롯 풀/대기 영상)은 §3.마로 분리.

## 가. AI 시스템

본 콘텐츠의 AI 모듈 4종. 각 독립 컴포넌트이며, 모듈 간 협력 흐름은 §2 S4 참조. 비-AI 오케스트레이션(마당 진행 제어, 결과물 조립)은 §4.다 백엔드. 각 모듈은 [[시범콘텐츠 공통 사양#가. AI 시스템]] 명세 항목을 준용함 (구현 코드와 하이퍼파라미터는 설계 단계, 기획은 요건까지).

### 1) 마당 플롯 생성 LLM (사전)

- **역할**: 마당 플롯(거리별 해설과 질문)을 사전 생성. §3.가 박첨지 진행 호스트(해설자, 길잡이) 화법을 적용 (생성형 전통 서사 AI 활용)
- **입력과 출력**: 입력은 [[마당 사건 풀]] 시드와 페르소나, 거리 문법. 출력은 거리별 박첨지 해설과 질문(고정)으로 묶인 마당 플롯 풀
- **동작과 규칙** (생성 4단계):
	1. **사건 구성**: [[마당 사건 풀]]에서 도입, 전개, 마무리 사건을 골라 한 마당의 사건 라인을 구성. **절정은 그 전개의 해소로 생성**(전개→절정 인과 직결, §3.나.3, 절정은 독립 선택 아님). 다양성은 마당 수준: 한 유형당 여러 마당을 사전 생성하되 전개를 달리해 마당끼리 겹치지 않게
	2. **해설과 질문 생성**: 사건을 박첨지 재담 화법(§3.가)으로 해설하고, 유저(주인공)의 행동과 선택을 묻는 질문 생성. 절정 거리에서 유저 주도 유도(홍동지 조력, §3.나.3). temperature 0.7~0.9 (§2.다)
	3. **AI 가드레일 사후 검사** (§3.라): 출력 해설과 질문이 가드레일 정책을 통과하는지 검사
	4. **재생성과 확정**: 위반 시 2단계 재시도(한도 §2.다). 통과분을 플롯에 고정해 풀에 저장
- **기술 요건**: 생성형 대규모 언어 모델(LLM). 모델 확보는 외부 API 또는 사전학습 모델 우선 검토(후보 확인 필요). 판정 기준은 거리 문법 정합, 플롯 품질, 가드레일 통과율 (정량 미정, 확인 필요). 사전 배치 생성이라 실시간 아님
- **자산 요구**: [[마당 사건 풀]] 시드(§3.마), 박첨지 페르소나와 거리 문법(§3.가, §3.나)
- **가드레일과 실패**: 사전 플롯 검수가 가드레일 3지점 중 첫 지점(§3.라.2). 재생성 한도 초과 시 해당 플롯 폐기(런타임 아닌 사전 단계라 유저 영향 없음)
- **의존**: 입력은 §3.마 [[마당 사건 풀]]. 출력 마당 플롯 풀은 §2.나 S3 랜덤 배정과 §4.다 백엔드 진행 제어가 사용

### 2) 유저 입력 가공 LLM (런타임)

- **역할**: 유저의 거리별 응답을 거리별 서사 텍스트로 변환 (§2.나 S4 백그라운드)
- **입력과 출력**: 입력은 거리별 유저 응답과 캐릭터 정보(이름, 연령대, 성별). 출력은 거리별 서사 텍스트
- **동작과 규칙**: 유저 응답을 박첨지 서사 화법(§3.가)에 녹여 거리별 서사를 생성. 이름과 캐릭터 설정은 슬롯 치환 수준의 가벼운 개인화(§3.나.4). 사전 생성 플롯의 거리 컨텍스트를 따름
- **기술 요건**: 생성형 LLM. 모델 확보는 외부 API 또는 사전학습 모델 우선 검토(후보 확인 필요). 판정 기준은 서사 일관성, 응답 시간(S4 대기 영향) (정량 미정, 확인 필요)
- **자산 요구**: 박첨지 화법과 거리 문법(§3.가, §3.나), 사전 생성 마당 플롯(§4.가.1)
- **가드레일과 실패**: 생성물 서사는 출력 가드레일(S4, §3.라) 대상(유저 입력 삽입 안전 포함). 생성 실패 시 재시도 후 failed 전환(§2.나 S4, §2.다)
- **의존**: 입력은 §2.나 S3 유저 응답과 §4.가.1 마당 플롯. 출력 서사는 §4.가.3 이미지 생성과 §4.다 결과물 조립이 사용

### 3) 이미지 생성 모델 (런타임)

- **역할**: §3.가 시각 정체성 기반 인형극 양식 일러스트 생성
- **입력과 출력**: 입력은 거리별 서사와 캐릭터, 양식 레퍼런스(§3.마). 출력은 거리별 일러스트
- **동작과 규칙**: 거리별 서사에 맞춰 인형극 양식 일러스트를 생성. 인형 시각 정체성을 레퍼런스로 고정(§3.마 캐릭터 레퍼런스), 동화풍 배제(나무 인형 양식)
- **기술 요건**: 이미지 생성 모델. 인물 일관성 메커니즘은 §3.마 비교표(프롬프트, IP-Adapter, LoRA)로 아트팀 협의 확정. 모델 확보는 사전학습 이미지 생성 모델이나 외부 API 우선 검토(후보 확인 필요). 판정 기준은 인물 일관성, 양식 정합, 생성 시간 (정량 미정, 확인 필요)
- **자산 요구**: 캐릭터 레퍼런스, 인형극 시각 양식 가이드(§3.마)
- **가드레일과 실패**: 생성물 일러스트는 출력 가드레일(S4, §3.라) 대상(이미지 안전). 생성 실패 시 재시도 후 failed 전환(§2.나 S4, §2.다)
- **의존**: 입력은 §4.가.2 서사와 §3.마 레퍼런스. 출력 일러스트는 §4.다 결과물 조립이 사용

### 4) AI 가드레일 (전 단계 공통)

- **역할**: 입출력 안전 검사. §3.라 가드레일 정책을 전 단계에 공통으로 적용하는 모듈임
- **입력과 출력**: 입력은 검사 대상(사전 플롯 텍스트, 유저 응답, 생성물 서사와 일러스트). 출력은 통과나 위반 판정, 위반 시 재생성이나 차단 트리거
- **동작과 규칙**: 적용 3지점은 사전 플롯 검수, 런타임 입력(S3), 런타임 출력(S4)으로 모두 필수(§3.라.2). 검사 항목은 유저 입력 삽입 안전, 전통 정체성 왜곡, 부적절 콘텐츠, 이미지 안전(§3.라.2). 마당 유형별 차단과 추상화는 §3.라.3
- **기술 요건**: 분류와 필터 모델에 자체 규칙 결합. 모델 확보는 외부 안전 API나 자체 규칙 우선 검토(후보 확인 필요). 판정 기준은 오탐율, 미탐율, 임계 (정량 미정, 확인 필요). 세부 정책은 §3.라.4 작성 예정
- **자산 요구**: 가드레일 정책 정의, 차단과 추상화 매핑(§3.라)
- **가드레일과 실패**: 위반 시 재생성(한도 §2.다), 한도 초과 시 failed로 전환해 에러/fallback 경로 합류(§2.나, §4.바). 가드레일 미탐 위험은 외부 검증위원회 자문으로 보완(§3.라.1)
- **의존**: AI 모듈 1~3의 입출력에 공통 적용. 정책은 §3.라, 실패 경로는 §2.나와 §4.바

- 고객 동의 약관 관리 (AI 악용 방지: §3.라, 버전/동의 기록)

### 1) 개인정보 처리 정책

- **개인정보 범위**: 전화번호 단일 (S6 임시 저장). 캐릭터 정보/응답/대화 로그/그림동화 결과물은 콘텐츠 데이터로 개인정보 영역 외
- **전화번호 처리**
	- "임시 저장": 메모리 only, 디스크 영속화 금지, 로그 미기록
	- "즉시 파기": SMS 발송 응답 수신 직후 (성공/실패 무관) 메모리 명시적 0 덮어쓰기 + 변수 해제
- **데이터 보관 기간** (잠정값, 규정 검토 후 확정. §2.다 운영 파라미터 참조)
	- 동의 기록: 5년 (감사/분쟁 대응)
	- 그림동화 결과물 (호스팅): 30일, 이후 파기
	- 박첨지 진행 대화 로그 (디버깅용): 14일, 이후 파기
- **동의 미보유 상태 처리**: S1 sub-step 1에서 세션 생성되나 sub-step 5 터치 미입력 타임아웃(미동의) 시 세션 전체 즉시 파기 (동의 기록 미생성, 세션 데이터 미보존)
- **입력 유효성 백엔드 측 재검증**: S2 이름 / S6 전화번호는 클라이언트 검증 외 백엔드 재검증 필수 (클라이언트 우회 대비)

## 가. 정체성 매핑 (전통 정합 검증)

전통 재창조 취사 기준(가져갈 것과 버릴 것)이 기획에 빠짐없이 반영됐는지 추적:

| 원칙 (전통 재창조 취사 기준) | 적용 위치 |
|---|---|
| 박첨지 = 해설자/길잡이 (가져갈 것 1, 전통 "해설자 겸 주역"의 해설 기능 계승) | §3.가 진행 호스트, §3.나.2 도입/마무리 박첨지가 여닫음, 유저가 주인공 |
| 재담과 메타연극성 (가져갈 것 2) | 전 거리 박첨지 진행 |
| 풍자 정신 (가져갈 것 3) | 4종 유형 풍자 초점 (위협/권력/위선/욕심) |
| 홍동지 응징 카타르시스 (가져갈 것 4) | 절정에서 유저가 주도, 홍동지가 힘(위협-구원형)/조롱(권력형)/축출(위선형)로 조력. 욕심/다툼형은 유저 선택이 가름(홍동지 약함) |
| 에피소드(거리)식 구성 (가져갈 것 5) | 마당 유형 다양성 + 거리 단위 + 내용 변주 |
| 골계적 반전 (가져갈 것 6) | 권력 풍자형 절정 (허세의 허망한 추락) |
| 인형극 시각 양식 (가져갈 것 7) | §3.마 자산 적용 |
| 고정 줄거리 버림 (버릴 것 1) | 유형 골격만 고정, 풍자 대상/사건은 유저 입력 변주 |
| 시대적으로 낡은 내용 버림 (버릴 것 2) | 욕심/다툼형 가드레일 (처첩 default 금지) |
| 연행 규모 버림 (버릴 것 3) | 2시간 2마당 7거리 → 5분 한 마당 4거리 |

[[덜미]] 매핑: 7거리의 갈등 핵 4종(위협/권력/위선/욕심)을 각각 독립 마당 유형으로, 도입(박첨지유람)/마무리(절 짓고 허는 거리)는 공통 골격으로.
