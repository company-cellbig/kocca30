> 덜미(꼭두각시놀음)를 소재로, 유저가 박첨지의 유람에 합류해 자기만의 유람기 한 편(전자책과 낭독 음성 파일)을 완성하는 AI 시범콘텐츠의 개발 기획서.

# 1. 개요

- **콘텐츠 정의**: 덜미를 소재로 한 AI 전자책 키오스크 콘텐츠
- **소재**: 한국 전통 인형극 덜미
- **목표 경험**: 덜미의 문학적 골격은 고정하고, 그 안의 사건과 해설을 유저 입력과 AI 생성으로 채워 매번 다른 이야기를 만듦
- **핵심 메커닉**: AI가 4종 마당 유형의 플롯을 사전 생성해 두고, 유저가 유형을 고르면 그 유형 마당 하나가 랜덤 배정되어 거리 단위로 채워짐
- **산출물**: 2D 일러스트와 텍스트를 엮은 전자책과 그 본문을 박첨지 목소리로 낭독한 음성 파일

# 2. 전체 플로우

1회 완결로 자기만의 유람기(전자책과 낭독 음성 파일) 한 편을 만드는 세션임. Step 1 인트로 → Step 2 캐릭터 정보 입력 → Step 3 마당 선택과 플롯 문답 → Step 4 결과물 생성과 대기 화면(병행) → Step 5 결과물 감상과 받기 → Step 6 종료와 리셋.

- **큰 분기**: 이탈 분기(유저 그만두기, 터치 미입력 타임아웃, 입력 유효성 위반과 런타임 입력 가드레일의 재검출이나 호출 실패 한도 초과)는 진행 중 종료 처리.
- **병행**: Step 4에서 백그라운드 결과물 생성과 포그라운드 대기 화면이 동시 진행. 결과물 호스팅과 다운로드 URL 발급까지 이 구간에서 끝내, Step 5가 QR을 곧바로 띄움
- **현지화**: Step 1 시작 화면에서 유저가 언어를 고르면 세션 전체(UI 카피와 AI 생성물인 서사, 낭독 음성)를 그 언어로 제공함(기본 한국어)
- **종료**: Step 6 종료 시 세션 데이터 서버에 저장 및 초기화

# 3. 공용 시스템

## 가. 세션 데이터

### 1) 역할과 목적

한 세션 진행에 필요한 데이터를 관리하는 시스템. 전 Step이 같은 상태를 공유하게 하고, 세션 데이터의 관리를 용이하게 함.


### 2) 동작과 규칙

| 데이터      | 분류     | 들어가는 값과 구성                           | 비고                               |
| -------- | ------ | ------------------------------------ | -------------------------------- |
| 세션 ID    | 시스템    | 세션마다 부여되는 고유 식별자                     | Step 1에서 생성                      |
| 현재 언어    | 시스템    | 현재 적용 중인 언어 유형                       | 적용 언어 유형 기록.                     |
| 현재 Step  | 시스템    | 현재 진행 중인 Step                        | 진행 단계 기록.                        |
| 에러 유형    | 시스템    | 에러 발생 시 에러 케이스 ID 기록                  | 값 목록은 §5.나 에러 케이스. 디버깅과 품질 분석용.    |
| 동의 기록    | 시스템    | 약관 버전 + 동의 시각                        | 약관 버전 체계 운영 결정                   |
| 캐릭터 정보   | 콘텐츠 입력 | 이름, 연령대(아이/청소년/어른), 성별(남/여)          | 주인공 이름과 6개 카드 = 연령대 × 성별로 주인공 설정 |
| 선택 마당 유형 | 콘텐츠 입력 | 유저가 고른 마당 유형 1종                      | 서사 구조                            |
| 배정 마당 플롯 | 콘텐츠 생성 | 선택 유형 풀에서 랜덤 배정된 사전 생성 플롯            | 마당 플롯 생성 LLM의 산출물                |
| 거리별 응답   | 콘텐츠 입력 | 거리별(도입/전개/절정/마무리) 유저 응답, 순서대로 누적     | 본편 응답 기록. 디버깅과 품질 분석용.           |
| 결과물      | 콘텐츠 생성 | 다중 페이지 전자책, 본문 낭독 음성 파일, 메타(생성 시각 등) | 포맷 결정 미정                         |
| 다운로드 URL | 콘텐츠 생성 | 결과물 호스팅 주소(만료형)                      | Step 4에서 발급, Step 5가 QR로 인코딩     |

- **Step별 세션 동작**: Step 1 생성, Step 2~Step 5 갱신, Step 6 종료와 리셋
- **데이터 보관 기간 (잠정값, 규정 검토 후 확정)**: 우선 디버깅과 품질 분석을 위해 잠정 30일 적용하고 이후 규정 검토 후 확정

## 나. 개인정보 처리

### 1) 역할과 목적

본 콘텐츠가 다루는 개인정보를 정의하는 시스템. 본 콘텐츠는 세션에서 개인정보를 수집하지 않으나 향후 추가될 수 있으므로 항목을 유지함.

### 2) 동작과 규칙

- **개인정보 범위**: 없음
	- 캐릭터 정보, 응답, 결과물은 콘텐츠 데이터로 개인정보가 아님
	- 이름은 유저 본인 이름이 아니라 주인공 캐릭터에 붙이는 이름임. 화면이 "주인공 이름 입력"으로 묻고 실명을 요구하지 않으므로 개인정보로 분류하지 않음
	- 전자책 일러스트는 유저 얼굴이 아니라 유저가 고른 캐릭터로 그려져 생체정보를 담지 않음
	- 낭독 음성은 유저 목소리가 아니라 박첨지 합성 음성(TTS)이라 음성 생체정보를 담지 않음. 유저의 음성 입력은 문자로 변환하고 원본 녹음은 저장하지 않음
- **결과물 전달**: 화면 QR로 익명 다운로드하며 연락처를 수집하지 않음

## 다. 언어 선택 시스템

### 1) 역할과 목적

세션 전체에 적용할 언어를 정하는 관문. UI 카피와 AI 생성물(서사, 낭독 음성)을 유저가 고른 언어로 제공해, 다른 언어를 쓰는 유저도 자기 언어로 유람기를 체험하게 함.

### 2) 입력과 출력

- **입력**: 유저의 언어 선택
- **출력**: 현재 언어(세션 데이터에 저장). 현지화(로컬라이제이션) JSON에서 해당 언어값을 불러옴

### 3) 동작과 규칙

- 유저가 언어를 선택하고 시작하기 버튼을 터치하면 현재 언어로 반영함. 기본값은 한국어임.
- **현지화 범위**: UI 카피뿐 아니라 AI 생성물까지임. 서사(유저 입력 가공 LLM)와 낭독 음성(낭독 음성 생성), 진행 호스트 대사를 현재 언어로 생성하고, 가드레일도 그 언어를 검사함. 지원 언어 범위는 한국어와 영어 우선 적용

## 라. 진행 호스트

### 1) 역할과 목적

박첨지를 디지털 휴먼 아바타로 구현한 세션 진행 호스트. 화면에 등장해 유저를 맞이하고 진행을 안내하며 이끎. 박첨지라는 덜미 정체성을 아바타로 살려 덜미의 전통요소 강화

### 2) 동작과 규칙

- **범위**
	- 전 세션 호스트
- **발화 방식**
	- TTS 음성으로 대사를 재생하고 같은 대사를 화면에 텍스트로 표시함.
	- 대사와 화면 텍스트는 세션의 현재 언어로 제공함(TTS도 현재 언어로 합성, 낭독 음성 생성과 보이스 공유)
	- 발화 중 동작 애니메이션(입 모양 포함)을 재생함
- **입 모양**
	- 립싱크는 맞추지 않고 사전 생성한 입 움직임 애니메이션을 발화 중 재생함
- **재생 컨트롤러**
	- 동작 애니메이션 재생과 동시에 TTS 오디오를 재생하고 그 길이만큼 입 애니메이션을 루프
	- 립싱크가 없어 음소 정렬은 불필요
- **스킵**
	- 발화 중 다음 버튼을 누르면 발화를 중단하고 다음으로 진행함
- **타임아웃**
	- 발화 중에는 터치 미입력 타임아웃을 멈추고, 발화가 끝난 뒤 시간 체크 시작
- **대사 적용**
	- 적용 방법 논의 후 추가 예정

### 3) 필요 리소스

- 호스트 캐릭터는 인형극 양식으로, 애니메이션 가능하게 제작하며 픽처북 삽화 박첨지와 시각 정체성 일치해야 함
- 동작 애니메이션 세트(대기, 인사, 말하기, 제스처)
- 입 모양 애니메이션(발화 중 루프)
- 박첨지 TTS 보이스

### 4) 실패와 복구

- 아바타 렌더나 TTS 재생 실패 시 음성과 애니메이션 없이 대표 이미지와 텍스트 박스로만 진행함(대사는 표시하고 세션은 계속)

## 마. 진행 중 종료

### 1) 역할과 목적

유저에게 진행 중 종료할 수 있는 수단을 제공하여 키오스크 회전율 높임

### 2) 동작과 규칙

#### 가) 일반 규칙

- **처리**
	- 현재 진행 중인 상황을 멈추고 Step 6 직행
#### 나) 유저의 종료 선택 시 규칙

- **처리**
	- 그만두기 터치 시 그만두기 확인 팝업(투 버튼) 표시
	- 그만두기 확인 시 종료 처리하고, 취소 시 원래 화면 복귀
	- 유저가 스스로 고른 정상 종료라 에러가 아님. 따라서 에러 케이스 ID를 부여하지 않고 세션 데이터의 에러 유형에도 기록하지 않음(§5.나 에러 케이스)
- **팝업 문구**
	- 제목: 그만두시겠습니까?
	- 본문: 지금 그만두면 만들던 결과물을 받을 수 없습니다.
	- 버튼: 계속하기(주, 원래 화면 복귀), 그만두기(보조, 종료)
- **적용 화면**
	- Step 1 가이드 화면, 동의 약관 화면
	- Step 2 이름 입력과 캐릭터 카드 선택
	- Step 3 마당 유형 선택과 박첨지 문답
- **예외 (미적용)**
	- Step 1 시작 화면
	- Step 4 대기 화면
	- Step 5 결과물 감상과 받기
	- Step 6 마무리 화면

#### 다) 입력 유효성 및 AI 가드레일 위반 시 종료 규칙

- **처리**
	- 3회(잠정) 위반 시 위반 종료 안내 팝업(원 버튼) 표시. 비속어 위반 한도 초과는 END-01, 가드레일 위반 한도 초과는 END-02임 (§5.나 에러 케이스)
	- 확인 시 종료 처리

## 바. 화면 타임아웃

### 1) 역할과 목적

플레이 중 한 화면에 장시간 체류하는 것을 방지함.

### 2) 동작과 규칙

- **처리**
	- 한 화면에서 60초(잠정) 이상 체류하면 다음 단계로 진행함.
	- 화면별 오버라이드: 결과물 감상과 받기 화면 300초(잠정), 마무리 인사 화면 3초(잠정)
- **예외**
	- 필수 입력, 호스트 대화, 대기, 팝업 화면 미적용

## 사. 터치 미입력 타임아웃

### 1) 역할과 목적

유저 이탈에 대응해 방치된 세션을 정리하여 키오스크 회전율을 높임.

### 2) 동작과 규칙

- **처리**
	- 한 화면에서 60초(잠정) 이상 터치 미입력 시 진행 중 종료 진행. 
	- 호스트 발화 시 발화 종료나 스킵 후부터 측정 시작(발화 중에는 멈춤)
- **예외**
	- 시작 화면, 대기 화면, 결과물 감상과 받기, 마무리 화면에 미적용

## 아. 입력 유효성 검증

### 1) 역할과 목적

유저 입력을 길이와 표현으로 거르는 시스템. 길이는 입력 단계에서 넘지 못하게 막고, 비속어는 제출 시 걸러 재입력을 받음. 잘못된 입력을 초기에 막아 생성과 전달 등 후속 처리가 정상 작동하게 함. 유저가 입력하는 모든 화면(Step 2 이름, Step 3 거리별 답변)에 적용함.

### 2) 동작과 규칙

| 입력              | 길이 상한 (입력 단계 차단) | 표현 검사 (제출 시)  |
| --------------- | ---------------- | ------------- |
| 이름 (Step 2)     | 20자              | 클라이언트 비속어 필터  |
| 거리별 답변 (Step 3) | 50자              | 클라이언트 비속어 필터  |

- **길이 처리 (팝업 없음)**: 상한에 닿으면 가상 키보드가 더 글자를 받지 않아 초과 입력 자체가 생기지 않음
- **비속어 처리**: 검출 시 위반 안내 팝업(원 버튼, IN-01)으로 재입력을 받음. 같은 화면에서 위반이 3회(잠정)를 넘으면 진행 중 종료 처리함(END-01)
	- 위반 횟수는 화면마다 초기화하여 따로 셈
- 음성 답변은 STT 변환 텍스트 결과물에 같은 검사를 적용함
- 길이값은 잠정이며 콘텐츠 문안 확정 시 조정
- 거리별 답변은 본 검사를 통과한 뒤 AI 가드레일(런타임 입력) 검사를 받음(내용 안전은 가드레일 소관)
	- 비속어 위반 횟수와 가드레일 위반 횟수는 서로 독립임

## 자. AI 가드레일

### 1) 역할과 목적

입력과 생성물의 안전을 검사하는 시스템으로 유해하거나 전통을 왜곡한 콘텐츠가 유저에게 노출되지 않도록 막음.

### 2) 입력과 출력

- **입력**: 검사 대상(유저 응답, 생성물 서사와 일러스트)
- **출력**: 통과나 위반 판정. 위반 시 재생성이나 차단 트리거 실행

### 3) 동작과 규칙

#### 가) 적용 지점

- **런타임 입력**: 유저 이름, 유저 응답 검사
- **런타임 출력**: 전자책 생성물(서사, 일러스트) 검사. 검사 항목은 전통 정체성 왜곡, 부적절 콘텐츠, 이미지 안전
	- 낭독 음성 합성은 출력 검사를 통과한 텍스트만 입력으로 받음. 따라서 합성된 음성에 별도 검사를 두지 않음

#### 나) 유형별 차단과 설계 지향

| 마당 유형   | 차단              | 설계 지향               |
| ------- | --------------- | ------------------- |
| 위협-구원형  | 특정 사람과 집단 비방    | 가상의 위협(특정 대상 아님)    |
| 권력 풍자형  | 실제 정치인과 공공인물 풍자 | 추상화된 권위             |
| 위선 폭로형  | 특정 실명과 단체 풍자    | 윤리적 위선(남을 속이는 행위 등) |
| 욕심과 다툼형 | 처첩 삼각관계 금지      | 재산, 명예, 기회          |

#### 다) 위반 시 처리

- **위반 검출**: 위반 안내 팝업(원 버튼, IN-02)으로 다른 내용으로 바꿔 달라고 안내하고 재입력을 받음. 같은 화면에서 위반이 3회(잠정)를 넘으면 진행 중 종료 처리함(END-02)
	- 위반 횟수는 화면마다 초기화하여 따로 셈
- **호출 실패**: 입력 가드레일 호출 자체가 실패하면(서비스 에러) 통과로 보지 않고 위반과 동일하게 처리함. 외부 서비스 호출 래퍼로 재시도(2회 잠정)해도 실패하면 1회 위반으로 세어 위 3회 한도에 합산함
	- 재입력 안내는 위반 검출과 다른 팝업(원 버튼, IN-03)을 씀. 유저 입력이 아니라 검사 서비스 장애가 원인이라 문구를 나누고 운영 알림 대상으로 둠 (§5.나 에러 케이스)

### 4) 기술 요건

- **검사 범위**
	- 텍스트(유저 응답, 생성 서사)와 이미지(생성 일러스트)를 모두 검사하므로 텍스트 모더레이션과 이미지 모더레이션 둘 다 필요함. 
	- 유저 입력과 생성 서사가 세션의 현재 언어로 작성되므로 텍스트 모더레이션은 지원 언어 전체를 커버해야 함(다국어 안전성, 확인 필요)
- **접근 (결정 필요)**
	- 범용 유해물은 외부 안전 API로 거르고, 전통 정체성 왜곡처럼 범용 API가 못 잡는 판정은 자체 규칙이나 도메인 분류기로 보완함. 
	- API 대 자체 구축 비중은 후보 조사 후 확정
- **품질 기준**
	- 무인 운영이라 미탐(유해물 통과)이 오탐보다 위험하므로 미탐을 낮추는 보수적 임계로 잡음. 
	- 오탐율, 미탐율, 임계 목표는 검증 데이터 확보 후 정량 확정
- **지연 예산**
	- 런타임 입력과 출력 검사는 유저 대기 구간이라 검사 응답 지연 상한이 필요함(정량 미정)

## 차. 외부 서비스 호출 래퍼

### 1) 역할과 목적

외부 서비스 호출(STT, TTS, AI, 결과물 호스팅)을 감싸는 공통 계층임. 재시도와 타임아웃 대응을 한 곳에 모아, 호출마다 장애 대응을 따로 작성하지 않게 함.

### 2) 동작과 규칙

- **재시도 횟수**
	- 2회(잠정)
- **호출 타임아웃**
	- STT 10초, TTS 30초, LLM 30초, 이미지 생성과 결과물 호스팅 60초(모두 잠정)
	- TTS 상한 30초는 호스트 대사 한 마디와 결과물 낭독 4거리 분량에 함께 적용함. 낭독은 분량이 훨씬 길어, 합성 시간을 실측한 뒤 상한 분리를 검토함

## 카. 실패 처리

### 1) 역할과 목적

런타임 실패의 처리 정책으로 종료 경로와 부분 실패 분기를 함께 정의하여 오류가 방치되지 않게 세션을 안전하게 마무리하거나 이어감. 

### 2) 동작과 규칙

자동 복구(재시도, 재생성)를 다 쓴 뒤에도 남는 실패를 갈래별로 처리함. 세션을 이어 유람기를 완성할 수 있으면 부분 실패로 두고, 완성할 수 없으면 종료 경로로 보냄.

- **판정 기준**: 실패한 기능이 유람기 완성에 필수인지로 갈래를 나눔
	- 보조 수단(낭독 음성, 음성 입력, 호스트 발화)이 실패하면 부분 실패로 두고 세션을 유지
	- 핵심 생성(서사, 일러스트, 조립)이나 결과물 전달(호스팅)이 실패하면 결과물이 남지 않으므로 종료 처리
- **부분 실패 (fallback, 세션 계속)**: 세 갈래임. 실패한 보조 기능을 대체 경로(fallback)로 메워 세션을 이어 감. STT와 호스트 발화는 즉시 쓸 대체 수단이 있고, 낭독은 대체 없이 그 기능만 빠짐
	- 낭독 음성 합성 실패(TTS-01): 전자책만 조립해 전달함. 이야기 본체(서사와 일러스트)가 이미 완성된 상태라 음성만 빠짐. 음성 없이 전달하는 손실이 세션을 통째로 버리는 손실보다 작음. 유저에게 별도 안내를 띄우지 않음
	- 음성 인식(STT) 실패: 가상 키보드로 계속 입력받음. 실패 시 안내 팝업(원 버튼)으로 재시도를 안내하고, 이 경우 횟수로 인한 종료 처리는 없음. 원인이 셋이라 팝업 문구를 나눔. 무음은 STT-01, 인식 결과가 없거나 불명확하면 STT-02, 호출이 재시도 한도를 넘기면 STT-03임
	- 호스트 발화 실패(HOST-01, 아바타 렌더나 TTS 재생): 음성과 애니메이션 없이 대표 이미지와 텍스트 박스로만 진행함. 유저에게 별도 안내를 띄우지 않음
- **종료 경로 (진입 조건)**: 네 갈래임
	- 생성 파이프라인 `failed`: 낭독 음성 생성을 뺀 모든 단계의 실패임. 유저 입력 가공 LLM 호출 실패(GEN-01), 이미지 생성 모델 호출 실패(GEN-02), 출력 가드레일 재생성 한도 초과(GEN-03), 결과물 조립 실패(GEN-04), 결과물 호스팅과 URL 발급 실패(GEN-05)가 이 상태로 모임
		- 출력 가드레일 호출 자체가 실패하면 통과로 보지 않고 재시도한 뒤 GEN-03으로 보냄
	- 상태 조회 무응답(NET-01): 대기 화면이 서버 상태를 연속 3회(잠정, 조회 주기 2초 기준 약 6초) 받지 못한 경우임. 파이프라인이 어디까지 갔는지 알 수 없어 결과물을 보장하지 못함
	- 세션 생성 실패(SES-01): Step 1에서 서버가 세션을 만들지 못한 경우임. 세션이 없어 진행할 수 없으므로 상황 안내 뒤 시작 화면으로 되돌림(Step 6을 거치지 않음. 정리할 세션 자체가 없음)
	- 마당 플롯 배정 실패(DATA-01): Step 3에서 서버가 사전 생성 플롯 풀에서 마당을 배정하지 못한 경우임. 문답을 시작할 재료가 없어 이어 갈 수 없음
	- 공통 처리: 상황 안내 팝업을 띄우고 자동으로 Step 6 종료로 보냄(SES-01만 시작 화면 복귀). 별도 실패 화면을 두지 않고, 전달하지 못한 생성물 일체를 파기함
	- 실패 시점: 호스팅을 Step 4에서 끝내므로 유저는 감상을 시작하기 전에 실패를 알게 됨
- **운영 알림**: 후속 조치가 필요한 실패에만 보냄(알림 채널 미정). 원인이 외부 서비스나 시스템에 있으면 대상이고, 원인이 유저 입력이나 발화에 있으면 비대상임. 케이스별 원인은 §5.나 에러 케이스 표의 원인 열이 정본임
	- 대상: GEN-01~GEN-05, NET-01, SES-01, DATA-01, TTS-01, HOST-01, IN-03, STT-03
	- IN-03을 대상에 넣는 이유: 가드레일 호출 실패는 유저에게 위반 1회로 계산되므로, 알리지 않으면 검사 서비스가 죽은 동안 유저들이 영문 모른 채 END-02로 종료됨
	- 비대상: IN-01, IN-02, END-01, END-02, STT-01, STT-02. 유저 쪽 원인이라 운영 조치가 필요 없음

## 타. 서사 구조 (규칙과 틀)

### 1) 역할과 목적

덜미의 서사 문법(마당 단위, 4거리 골격, 4종 유형, 변주 규칙)을 고정한 설계 모델. 규칙과 틀만 정의하고 직접 생성하지는 않음. 마당 플롯 생성 LLM이 이 규칙으로 실물 플롯을 만들고, 가드레일과 박첨지도 이를 전제로 동작함. 목적은 전통 요소(재담, 풍자, 거리식 구성)를 틀로 지키면서 그 안의 내용은 유저 입력과 AI 생성으로 매번 다르게 해, 다양한 결과물을 내는 것.

### 2) 동작과 규칙

#### 가) 마당 (플롯 단위)

- **마당 정의**: 박첨지 등장(도입)부터 닫는 해설(마무리)까지 하나의 인과 줄기로 이어지는 응집된 극 단위로 한 세션은 하나의 마당을 다룸
- **사전 고정형**: 마당 플롯과 거리별 박첨지 질문을 사전에 생성하고 검수해 고정함(런타임 생성 아님)

#### 나) 거리 골격 (공통 4거리)

모든 유형은 박첨지가 여닫는 공통 골격을 공유함. 한 마당 = 4거리. 아래는 본편 거리의 상대 비중으로, 도입과 마무리는 짧고 전개와 절정에 무게가 실림.

| 거리(장면) | 기능                            | 적용 범위    | 비중  |
| ------ | ----------------------------- | -------- | --- |
| 도입     | 박첨지 등장과 유람 + 유저(주인공) 합류, 첫 재담 | 모든 유형 공통 | 낮음  |
| 전개     | 선택된 유형의 갈등 등장                 | 유형별      | 높음  |
| 절정     | 선택된 유형의 해소                    | 유형별      | 높음  |
| 마무리    | 박첨지 닫는 해설과 맺음 인사              | 모든 유형 공통 | 낮음  |

#### 다) 마당 유형 (4종)

덜미 7거리의 갈등 핵을 4종 마당 구조로 정리함. 각 구조는 전개에서 절정으로 인과가 직결된 독립 완결 단위로, 전개의 갈등 대상이 그 마당의 절정에서 해소됨.

| 마당 유형 | 전개 (갈등) | 절정 (해소) | 원형 거리 |
|---|---|---|---|
| 위협-구원형 | 외부 위협 고조 | 유저가 맞서고 홍동지가 힘을 보태 함께 처치 | 이시미거리 |
| 권력 풍자형 | 권력자 허세 | 유저가 허세를 들춰내고 홍동지가 조롱으로 거듦, 골계적 추락 | 매사냥거리, 상여거리 |
| 위선 폭로형 | 위선 행각 | 유저가 위선을 드러내고 홍동지가 축출로 거듦, 폭로와 망신 | 피조리거리 |
| 욕심과 다툼형 | 욕심 다툼 | 유저의 선택이 파국, 손해, 떠남을 가름 | 꼭두각시거리 |

- **절정은 유저(주인공)가 주도하고 홍동지는 조력함**(대체 아님). 홍동지 응징의 카타르시스는 유형별로 다른 형태로 나타남(위협-구원형은 힘, 권력형은 조롱, 위선형은 축출). 보편 단일 절정이 아님
- 각 유형 내부는 유저 입력 기반으로 무한 변주될 수 있도록 디자인해야 함

#### 라) 변주

같은 틀(마당 유형과 거리 골격)에 다른 내용(사건, 풍자 대상, 인물)을 넣어 매번 다른 결과를 만드는 시스템으로 두 지점에서 적용함. 변주곡처럼 틀은 두고 내용만 바뀜.

- **갈래 1. 유저 입력 슬롯**
	- 유저가 채운 입력이 이야기 전개의 재료가 됨
	- 슬롯은 이름(주인공), 캐릭터 카드(유형 6개 중 택1), 마당 선택(유형 4종 중 택1), 거리별 응답(도입/전개/절정/마무리)
- **갈래 2. AI 질문 변주 (사전 생성)**
	- 같은 유형이라도 질문이 단조롭지 않게, 사전 생성 단계에서 유형 풀에 변주를 마련하고 런타임은 랜덤 선택함
		- 사건 형태: 거리 안 사건 컨텍스트 변주 (예: 도입이 길에서 / 잔치에서 / 시장에서)
		- 풍자 대상: 추상화된 권위와 위선 형태 변주 (예: 허세 권위자 / 겉만 번지르 / 횡포한 자)
		- 박첨지 입장: 목격자 / 당사자 / 풍자자 등 역할 변주
- **일관성 유지**
	- 위 두 갈래만 변주하고 마당 공통 골격과 마당 유형의 고정 문법은 일관 유지함.

## 파. 마당 플롯 생성 LLM

### 1) 역할과 목적

서사 구조(규칙과 틀)를 입력으로 받아, 유형별 마당 플롯(거리별 박첨지 해설과 질문)을 구체 실물로 사전 생성하는 시스템. 런타임에 생성 지연 없이 플롯을 즉시 배정할 수 있도록, 운영 전에 사람 검수까지 끝낸 플롯 풀을 사전에 만들어 둠.

### 2) 입력과 출력

- **입력**: 추상화된 사건 상황 모음(별도 설계 예정), 박첨지 페르소나, 거리 문법.
- **출력**: 마당 플롯 풀(텍스트와 JSON). 풀 스키마와 크기, Step 3 마당 선택과 플롯 문답 진행 시 이 풀에서 마당을 조회하고 받아 쓰는 방식은 구현 단계에서 정함

### 3) 동작과 규칙

1. **사건 구성**: 사건 상황 모음에서 도입/전개/마무리 사건을 골라 사건 라인 구성. 절정은 전개의 해소로 생성(마당 유형)
2. **해설과 질문 생성**: 사건을 박첨지 재담 화법으로 해설하고 유저 주도 질문 생성. temperature 잠정 0.7~0.9
3. **사람 검수와 확정**: 생성한 플롯 후보를 사람이 읽고 거리 문법 정합, 플롯 품질, 전통 정합을 판정함. 통과한 것만 풀에 올림. 반려한 것은 올리지 않으며 필요하면 프롬프트를 고쳐 다시 생성함

### 4) 기술 요건

생성형 LLM 모델 확보는 외부 상용 API나 사전학습 모델 우선 검토. 판정 기준은 거리 문법 정합, 플롯 품질(정량 미정).

#### 가) 진행

	- 분기: 그만두기 선택 시 확인 팝업(§3.마 진행 중 종료) → 확정 시 종료 처리

#### 가) 진행

	- 분기: 미입력 타임아웃 → 종료 처리
	- 분기: 그만두기 선택 시 확인 팝업(§3.마 진행 중 종료) → 확정 시 종료 처리

## 다. Step 3. 마당 선택과 플롯 문답 (거리별 반복)

#### 가) 진행

- 마당 유형 4종 카드 선택 후 다음 진행 버튼 터치 시 세션 데이터에 선택 마당 유형 정보 갱신하고 다음 단계 진행
	- 분기: 미입력 타임아웃 → 종료 처리
	- 분기: 그만두기 선택 시 확인 팝업(§3.마 진행 중 종료) → 확정 시 종료 처리

### 2) 서버

#### 가) 진행

- 유저가 선택한 마당 유형 풀에서 마당 1개를 랜덤으로 배정 후 클라이언트의 세션 데이터 저장 및 갱신
	- 마당 플롯 생성 LLM 사전 산출물 사용
	- 분기: 풀 조회나 배정 실패 시 재시도(2회 잠정) 후 상황 안내 팝업(DATA-01) → 종료 처리

### 3) UI(박첨지 문답)

#### 가) 진행

- 거리별 사전 질문을 표시하고 유저 응답 입력 확정 시 다음 단계 진행
	- 가상 키보드를 기본으로 제공하고 STT 음성 입력 병행
	- 길이 상한(50자)은 입력 단계에서 막음(팝업 없음)
	- 분기: 미입력 타임아웃 → 종료 처리
	- 분기: 비속어 검출 시 안내 팝업(IN-01) → 재입력 3회(잠정) 초과 시 종료 처리(END-01)
	- 분기: 음성 인식 실패 시 안내 팝업(무음 STT-01, 인식 실패 STT-02, 호출 재시도 한도 초과 STT-03) 후 가상 키보드로 계속 입력받음(실패 처리의 부분 실패)
	- 분기: 그만두기 선택 시 확인 팝업(§3.마 진행 중 종료) → 확정 시 종료 처리

### 4) AI 가드레일: 유저 응답 검사

#### 가) 진행

- AI 가드레일 런타임 입력 검사 실행
	- 분기: 위반 시 안내 팝업(IN-02) → 재검출 3회(잠정) 초과 시 종료 처리(END-02)
	- 분기: 가드레일 호출이 재시도 한도를 넘기면 안내 팝업(IN-03) → 위반 1회로 세어 같은 한도에 합산

### 5) 클라이언트

#### 가) 진행

- 세션 데이터에 진행 상황과 응답 내용을 누적 저장

## 라. Step 4. 결과물 생성과 대기 화면 (병행)

백그라운드 생성과 포그라운드 대기가 동시 진행되고 상태 조회로 동기화됨.

### 1) 백그라운드: 결과물 생성

#### 가) 진행

- **생성 파이프라인**
	1. 유저 입력 가공 LLM: 응답을 거리(페이지) 별 서사로 변환
		- 분기: 호출 실패 시 재시도(2회 잠정), 한도 초과 시 상태 `failed` 전환(GEN-01)
	2. 이미지 생성 모델: 서사로 거리(페이지) 별 일러스트 생성
		- 분기: 호출 실패 시 재시도(2회 잠정), 한도 초과 시 상태 `failed` 전환(GEN-02)
	3. AI 가드레일: 생성물(서사, 일러스트) 출력 검사
		- 분기: 위반 시 1로 재생성 (한도 잠정 3회). 한도 초과 시 상태 `failed` 전환(GEN-03)
	4. 낭독 음성 생성: 검사를 통과한 거리(페이지) 별 서사를 박첨지 음성으로 합성
		- 분기: 합성 실패 시 `failed`로 가지 않고 음성 없이 5로 진행함(TTS-01, 실패 처리의 부분 실패)
	5. 결과물 조립: 서사와 일러스트를 하나로 합친 이미지 파일과 낭독 음성을 결과물 한 벌로 결합
		- 분기: 조립 실패 시 재시도(2회 잠정), 한도 초과 시 상태 `failed` 전환(GEN-04)
	6. 결과물 호스팅: 조립한 결과물을 웹에 호스팅하고 만료형 다운로드 URL을 발급. Step 5가 이 URL로 QR을 만듦
		- 전자책과 낭독 음성을 한 페이지에서 함께 받게 해 QR과 URL은 하나만 씀.
		- 낭독 음성 합성이 실패한 세션은 음성 없이 호스팅함(실패 처리의 부분 실패)
		- 분기: 업로드나 호스팅, URL 발급 실패 시 재시도(결과물 호스팅 재시도 2회 잠정), 한도 초과 시 상태 `failed` 전환(GEN-05)
	7. 결과물 및 다운로드 URL 클라이언트 세션 데이터에 저장
- **실패(생성 단계 공통)**
	- 어느 단계에서 `failed`가 됐는지를 세션 데이터의 에러 유형(GEN-01~GEN-05)에 기록함. 포그라운드 상태 조회가 `failed`를 검출하면 그 케이스의 상황 안내 팝업을 띄우고 종료 처리함
	- 재시도 2회(잠정), 상태 조회 주기 2초(잠정)
	- 운영 알림은 GEN-01~GEN-05와 TTS-01 모두 대상임(§3.카 실패 처리)
- **상태 머신**
	- `generating` / `completed`(가드레일 통과분을 호스팅하고 다운로드 URL까지 받은 상태) / `failed`(생성 실패, 가드레일 한도 초과, 호스팅 영구 실패)

#### 나) 유저 입력 가공 LLM (개별 시스템)

##### (1) 역할과 목적

유저의 거리별 응답을 박첨지 화법의 거리별 서사로 변환하는 런타임 엔진. 사전 고정 플롯 위에 유저 입력을 녹여 매번 다른 "나만의 유람기" 본문을 만드는 게 목적.

##### (2) 입력과 출력

- **입력**: 배정된 마당 플롯(거리 컨텍스트), 거리별 유저 응답, 캐릭터 정보(이름, 연령대, 성별), 현재 언어(세션 데이터)
- **출력**: 거리별 서사 텍스트(현재 언어)

##### (3) 동작과 규칙

응답을 박첨지 서사 화법에 녹여 거리별 서사를 생성함. 이름과 캐릭터는 슬롯 치환 수준으로 개인화하고, 사전 생성 플롯의 거리 컨텍스트를 따름. 현지화 범위가 AI 생성물까지라 서사 본문을 세션의 현재 언어로 생성함.

##### (4) 기술 요건

생성형 LLM 모델 확보는 외부 API나 사전학습 모델 우선 검토(확인 필요). 다국어 서사 생성이 필요하므로 선택 언어별 생성 품질을 확보해야 함(지원 언어 범위는 한국어, 영어 우선 적용용). 판정 기준은 서사 일관성, 언어별 표현 자연성, 응답 시간(정량 미정).

##### (5) 필요 리소스

박첨지 화법, 사전 생성 마당 플롯(마당 플롯 생성 LLM).

##### (6) 실패와 복구

생성 서사는 출력 가드레일 검사를 받음. 호출이 재시도 한도(2회 잠정)를 넘겨 실패하면 GEN-01임. 가드레일 미통과 시에는 재생성 한도(3회 잠정) 안에서 파이프라인 1단계부터 다시 생성하고, 한도를 넘기면 GEN-03임. 둘 다 생성 파이프라인의 `failed` 처리(실패 처리)로 이어짐.

#### 다) 이미지 생성 모델

##### (1) 역할과 목적

거리별 서사를 인형극 양식 일러스트로 시각화하는 런타임 엔진. 인형 시각 정체성을 레퍼런스로 고정하고 동화풍을 배제해(나무 인형 양식), 전자책이 덜미다운 룩을 갖게 하는 게 목적.

##### (2) 입력과 출력

- **입력**: 거리별 서사와 캐릭터, 양식 레퍼런스
- **출력**: 거리별 일러스트(세로 형식)

##### (3) 동작과 규칙

거리별 서사에 맞춰 인형극 양식 일러스트를 생성함. 캐릭터 레퍼런스로 인물 일관성을 고정함.

##### (4) 기술 요건

이미지 생성 모델. 모델 확보는 사전학습 모델이나 외부 API 우선 검토(확인 필요). 판정 기준은 인물 일관성, 양식 정합, 생성 시간(정량 미정).

##### (5) 필요 리소스

캐릭터 레퍼런스, 인형극 시각 양식 가이드.

##### (6) 실패와 복구

생성 일러스트는 출력 가드레일 검사를 받음. 호출이 재시도 한도(2회 잠정)를 넘겨 실패하면 GEN-02임. 가드레일 미통과 시에는 재생성 한도(3회 잠정) 안에서 파이프라인 1단계부터 다시 생성하고, 한도를 넘기면 GEN-03임. 둘 다 생성 파이프라인의 `failed` 처리(실패 처리)로 이어짐.

#### 라) 낭독 음성 생성 (개별 시스템)

##### (1) 역할과 목적

거리별 서사를 박첨지 목소리 음성으로 합성하는 런타임 엔진. 유저가 받아 가는 결과물에 전자책과 짝을 이루는 낭독본을 붙여, 글을 읽기 어려운 유저(아이 등)도 자기 유람기를 듣게 하는 게 목적.

##### (2) 입력과 출력

- **입력**: 출력 가드레일을 통과한 거리별 서사 텍스트(현재 언어), 박첨지 TTS 보이스(진행 호스트와 공유), 현재 언어(세션 데이터)
- **출력**: 거리(페이지) 단위로 나뉜 낭독 음성 파일. 파일 형식과 거리별 분리 대 단일 파일 결합은 구현 단계에서 정함

##### (3) 동작과 규칙

거리 순으로 서사 텍스트를 박첨지 목소리로 합성함. 진행 호스트 대사와 같은 보이스를 써서 세션 내내 화자가 하나로 들리게 함. 합성 결과는 Step 5 화면 재생과 다운로드 전달에 같은 파일을 씀.

##### (4) 기술 요건

상용 음성 합성(TTS) API. 진행 호스트가 쓰는 TTS와 같은 서비스를 씀. 현지화가 AI 생성물까지라 현재 언어로 낭독함. 단일 한국어 보이스로는 다른 언어를 낭독할 수 없어, 언어별 박첨지 보이스나 다국어 지원 보이스 확보가 필요함. 판정 기준은 화자 일관성, 낭독 자연성, 언어별 발음 품질, 합성 시간(정량 미정).

##### (5) 필요 리소스

박첨지 TTS 보이스.

##### (6) 실패와 복구

합성 호출 실패 시 재시도하고, 한도를 넘기면 음성 없이 전자책만 전달함(실패 처리의 부분 실패). 이 엔진의 실패는 세션을 끝내지 않음. 입력 서사가 이미 가드레일을 통과했으므로 음성 자체의 가드레일 검사는 없음(AI 가드레일 §3.자 3) 가) 적용 지점).

#### 마) 결과물 조립

##### (1) 역할과 목적

거리별 서사와 일러스트, 낭독 음성을 유람기 한 편으로 묶는 비-AI 오케스트레이션. 흩어진 생성물을 유저가 받는 최종 산출물(전자책과 낭독 음성 파일)로 조립하는 게 목적.

##### (2) 입력과 출력

- **입력**: 거리별 서사(유저 입력 가공 LLM), 거리별 일러스트(이미지 생성 모델), 거리별 낭독 음성(낭독 음성 생성, 합성 실패 시 없음)
- **출력**: 다중 페이지 전자책 파일과 낭독 음성 파일, 메타(생성 시각 등)

##### (3) 동작과 규칙

거리 순으로 서사와 일러스트를 페이지로 묶고 같은 거리의 낭독 음성을 그 페이지에 대응시켜 조립, 저장함. 출력 가드레일 통과분만 저장함. 낭독 음성이 없으면(합성 실패) 전자책만 조립함. 형식은 미정.

##### (4) 기술 요건

서버에서 결합과 저장 로직 실행.

##### (5) 실패와 복구

조립 전 출력 가드레일 검사. AI 생성 실패나 가드레일 한도 초과 시 `failed` 경로에 합류(실패 처리). 조립 자체가 실패하면 재시도 2회(잠정) 뒤 `failed`로 보냄.

## 나. 에러 케이스

세션이 정상 흐름을 잇지 못하고 끊기는 상황만 담음. 유저가 스스로 고르는 그만두기는 정상 종료라 에러 케이스가 아니며, 팝업 문구까지 §3.마 진행 중 종료가 소유함. 타임아웃도 유저 이탈 대응이라 여기 두지 않음(§3.바 화면 타임아웃, §3.사 터치 미입력 타임아웃).

케이스 ID는 세 곳에서 같은 값으로 쓰임. 세션 데이터의 에러 유형 필드(§3.가 세션 데이터), 운영 알림(§3.카 실패 처리), 그리고 아래 안내 문구임.

### 1) 케이스 목록과 처리

케이스를 두 축으로 나눔. **처리**는 그 실패가 세션을 어떻게 만드는지고(재입력, 대체 입력, 기능 축소, 중단), **원인**은 실패가 누구에게서 비롯됐는지임(유저, 외부 서비스, 시스템). 운영 알림 여부는 원인 축에서 바로 나옴. 원인이 외부 서비스나 시스템이면 알림 대상이고, 유저면 비대상임(§3.카 실패 처리).

### 2) 안내 문구

케이스마다 제목이나 본문 중 하나 이상을 다르게 써서, 화면 문구만 보고도 어느 케이스인지 가려짐. 다만 문구는 진단의 정본이 아님. 진단 정본은 세션 데이터의 에러 유형 값이고, 문구는 유저 행동을 이끄는 게 목적임(오류 코드와 기술 세부는 노출하지 않음, [[시범콘텐츠 공통 사양#바. 실패 안내 (상황 안내 모달 팝업)]]).

문구는 세션의 현재 언어로 제공함(§3.다 언어 선택 시스템). 아래는 한국어 원본이고 다른 언어는 현지화 JSON에서 대응 값을 불러옴. 콘텐츠 고유 소재어(박첨지, 마당 등)를 쓰지 않아 다른 시범콘텐츠도 그대로 쓸 수 있음. 팝업이 없는 TTS-01과 HOST-01은 화면 문구가 없어 이 표에 두지 않음.
