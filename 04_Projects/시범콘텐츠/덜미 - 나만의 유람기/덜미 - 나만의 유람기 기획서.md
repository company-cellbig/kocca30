> 덜미(꼭두각시놀음)를 소재로, 유저가 박첨지의 유람에 합류해 자기만의 유람기 한 편(전자책과 낭독 음성 파일)을 완성하는 AI 시범콘텐츠의 개발 기획서.

# 1. 개요

- **콘텐츠 정의**: 덜미를 소재로 한 AI 전자책 키오스크 콘텐츠
- **소재**: 한국 전통 인형극 덜미
- **목표 경험**: 덜미의 문학적 골격은 고정하고, 그 안의 사건과 해설을 유저 입력과 AI 생성으로 채워 매번 다른 이야기를 만듦
- **핵심 메커닉**: AI가 4종 마당 유형의 플롯을 사전 생성해 두고, 유저가 유형을 고르면 그 유형 마당 하나가 랜덤 배정되어 거리 단위로 채워짐
- **산출물**: 2D 일러스트와 텍스트를 엮은 전자책과 그 본문을 박첨지 목소리로 낭독한 음성 파일

# 2. 전체 플로우

1회 완결로 자기만의 유람기(전자책과 낭독 음성 파일) 한 편을 만드는 세션임. Step 1 인트로 → Step 2 캐릭터 정보 입력 → Step 3 마당 선택과 플롯 문답 → Step 4 결과물 생성과 대기 화면(병행) → Step 5 결과물 표시 → Step 6 결과물 다운로드 안내 → Step 7 종료와 리셋.

- **큰 분기**: 대부분 이탈(미동의, 터치 미입력 타임아웃)로 Step 7 직행, 생성 실패는 사과 화면 후 Step 7
- **병행**: Step 4에서 백그라운드 결과물 생성과 포그라운드 대기 화면이 동시 진행
- **파기**: Step 7 종료 시 세션 임시 데이터 파기(결과물은 다운로드 호스팅 만료 시 파기, 연락처 미수집)

# 3. 공용 시스템

여러 sub-step에 걸쳐 쓰이는 시스템과 횡단 정책, 설계 골격임.

## 가. 세션 데이터

### 1) 역할과 목적

한 세션이 만드는 데이터를 담는 시스템. 전 Step이 같은 상태를 공유하게 하고, 데이터 종류별 보관과 파기 관리를 용이하게 함.

### 2) 동작과 규칙

본 콘텐츠의 세션 저장 데이터임. 카메라를 쓰지 않아 얼굴 영상이 없고, 결과물을 화면 QR로 전달해 전화번호를 받지 않으므로 세션이 저장하는 개인정보는 없음. 분류 열은 데이터 종류를 뜻하며 개인정보 여부를 뜻하지 않음. 표는 어떤 값이 들어가는지까지만 적고, 타입과 저장 스키마 같은 구현 모델은 설계 단계에서 정함.

| 데이터 | 분류 | 들어가는 값과 구성 | 수명 | 비고 |
|---|---|---|---|---|
| 세션 ID | 시스템 | 세션마다 부여되는 고유 식별자 | 휘발 (세션 종료 시 파기) | Step 1에서 생성 |
| 동의 기록 | 시스템 | 약관 버전 + 동의 시각 | 보관 (잠정 5년) | 약관 버전 체계 운영 결정 |
| 캐릭터 정보 | 콘텐츠 입력 | 연령대(아이/청소년/어른), 성별(남/여), 이름 | 확인 필요 (파기 시점 미결) | 6개 카드 = 연령대 × 성별. 유저 주인공 설정 |
| 선택 마당 유형 | 콘텐츠 입력 | 유저가 고른 마당 유형 1종 | 확인 필요 (파기 시점 미결) | 서사 구조 |
| 배정 마당 플롯 | 콘텐츠 생성 | 선택 유형 풀에서 랜덤 배정된 사전 생성 플롯 | 확인 필요 (파기 시점 미결) | 마당 플롯 생성 LLM 산출물 |
| 거리별 응답 | 콘텐츠 입력 | 거리별(도입/전개/절정/마무리) 유저 응답, 순서대로 누적 | 보관 (잠정 14일, 만료 시 파기) | 본편 응답. 박첨지 질문은 배정 마당 플롯이 소유하므로 응답만 저장하고 질문은 거리 번호로 참조. 디버깅과 품질 분석에 이 행을 씀 |
| 결과물 | 콘텐츠 생성 | 다중 페이지 전자책 + 본문 낭독 음성 파일 + 메타(생성 시각 등) | 보관 (다운로드 호스팅 잠정 30일, 만료 시 파기) | 포맷 결정 미정 |

- **Step별 세션 동작**: Step 1 생성, Step 2~Step 6 갱신, Step 7 종료와 임시 데이터 파기와 리셋
- **데이터 보관 기간 (잠정값, 규정 검토 후 확정)**: 동의 기록 5년, 결과물 호스팅 30일, 거리별 응답 14일

## 나. 개인정보 처리

### 1) 역할과 목적

본 콘텐츠가 다루는 개인정보를 정의하는 시스템. 결과물을 화면 QR로 전달해 전화번호를 받지 않으므로, 본 콘텐츠는 세션에서 개인정보를 수집하지 않음.

### 2) 동작과 규칙

- **개인정보 범위**: 없음
	- 캐릭터 정보, 응답, 결과물은 콘텐츠 데이터로 개인정보가 아님
	- 이름은 유저 본인 이름이 아니라 주인공 캐릭터에 붙이는 이름임. 화면이 "주인공 이름 입력"으로 묻고 실명을 요구하지 않으므로 개인정보로 분류하지 않음
	- 전자책 일러스트는 유저 얼굴이 아니라 유저가 고른 캐릭터로 그려져 생체정보를 담지 않음
	- 낭독 음성은 유저 목소리가 아니라 박첨지 합성 음성(TTS)이라 음성 생체정보를 담지 않음. 유저의 음성 입력은 문자로 변환하고 원본 녹음은 저장하지 않음
- **결과물 전달**: 화면 QR로 익명 다운로드하며 연락처를 수집하지 않음(Step 6 결과물 다운로드 안내). 결과물 호스팅과 만료 파기 정본은 플랫폼 사양임
- **공통 원칙**: 세션 데이터 개인정보 공통 원칙은 시범콘텐츠 공통 사양을 따름

## 다. 서사 구조 (플롯 모델)

### 1) 역할과 목적

덜미의 서사 문법(마당 단위, 4거리 골격, 4종 유형, 변주 규칙)을 고정한 설계 모델. 규칙과 틀만 정의하고 직접 생성하지는 않음. 마당 플롯 생성 LLM이 이 규칙으로 실물 플롯을 만들고, 가드레일과 박첨지도 이를 전제로 동작함. 목적은 전통 요소(재담, 풍자, 거리식 구성)를 틀로 지키면서 그 안의 내용은 유저 입력과 AI 생성으로 매번 다르게 해, 다양한 결과물을 내는 것.

### 2) 동작과 규칙

#### 가) 마당 (플롯 단위)

- **마당 정의**: 박첨지 등장(도입)부터 닫는 해설(마무리)까지 하나의 인과 줄기로 이어지는 응집된 극 단위로 한 세션은 하나의 마당을 다룸
- **사전 고정형**: 마당 플롯과 거리별 박첨지 질문을 사전에 생성하고 검수해 고정함(런타임 생성 아님)

#### 나) 거리 골격 (공통 4거리)

모든 유형은 박첨지가 여닫는 공통 골격을 공유함. 한 마당 = 4거리. 아래는 본편 거리의 상대 비중으로, 도입과 마무리는 짧고 전개와 절정에 무게가 실림.

| 거리(장면) | 기능                            | 적용 범위    | 비중  |
| ------ | ----------------------------- | -------- | --- |
| 도입     | 박첨지 등장과 유람 + 유저(주인공) 합류, 첫 재담 | 모든 유형 공통 | 낮음  |
| 전개     | 선택된 유형의 갈등 등장                 | 유형별      | 높음  |
| 절정     | 선택된 유형의 해소                    | 유형별      | 높음  |
| 마무리    | 박첨지 닫는 해설과 맺음 인사              | 모든 유형 공통 | 낮음  |

#### 다) 마당 유형 (4종)

덜미 7거리의 갈등 핵을 4종 마당 구조로 정리함. 각 구조는 전개에서 절정으로 인과가 직결된 독립 완결 단위로, 전개의 갈등 대상이 그 마당의 절정에서 해소됨.

| 마당 유형 | 전개 (갈등) | 절정 (해소) | 원형 거리 |
|---|---|---|---|
| 위협-구원형 | 외부 위협 고조 | 유저가 맞서고 홍동지가 힘을 보태 함께 처치 | 이시미거리 |
| 권력 풍자형 | 권력자 허세 | 유저가 허세를 들춰내고 홍동지가 조롱으로 거듦, 골계적 추락 | 매사냥거리, 상여거리 |
| 위선 폭로형 | 위선 행각 | 유저가 위선을 드러내고 홍동지가 축출로 거듦, 폭로와 망신 | 피조리거리 |
| 욕심과 다툼형 | 욕심 다툼 | 유저의 선택이 파국, 손해, 떠남을 가름 | 꼭두각시거리 |

- **절정은 유저(주인공)가 주도하고 홍동지는 조력함**(대체 아님). 홍동지 응징의 카타르시스는 유형별로 다른 형태로 나타남(위협-구원형은 힘, 권력형은 조롱, 위선형은 축출). 보편 단일 절정이 아님
- 각 유형 내부는 유저 입력 기반으로 무한 변주될 수 있도록 디자인해야 함

#### 라) 변주

같은 틀(마당 유형과 거리 골격)에 다른 내용(사건, 풍자 대상, 인물)을 넣어 매번 다른 결과를 만드는 시스템으로 두 지점에서 적용함. 변주곡처럼 틀은 두고 내용만 바뀜.

- **갈래 1. 유저 입력 슬롯**
	- 유저가 채운 입력이 이야기 전개의 재료가 됨
	- 슬롯은 이름(주인공), 캐릭터 카드(유형 6개 중 택1), 마당 선택(유형 4종 중 택1), 거리별 응답(전개/절정/마무리)
- **갈래 2. AI 질문 변주 (사전 생성)**
	- 같은 유형이라도 질문이 단조롭지 않게, 사전 생성 단계에서 유형 풀에 변주를 마련하고 런타임은 랜덤 선택함
		- 사건 형태: 거리 안 사건 컨텍스트 변주 (예: 도입이 길에서 / 잔치에서 / 시장에서)
		- 풍자 대상: 추상화된 권위와 위선 형태 변주 (예: 허세 권위자 / 겉만 번지르 / 횡포한 자)
		- 박첨지 입장: 목격자 / 당사자 / 풍자자 등 역할 변주
- **일관성 유지**
	- 위 두 갈래만 변주하고 마당 공통 골격과 마당 유형의 고정 문법은 일관 유지함. 

## 라. 마당 플롯 생성 LLM

### 1) 역할과 목적

서사 구조(규칙과 틀)를 입력으로 받아, 유형별 마당 플롯(거리별 박첨지 해설과 질문)을 구체 실물로 사전 생성하는 시스템. 런타임에 생성 지연 없이 안전한(가드레일 통과) 플롯을 즉시 배정할 수 있도록 운영 전에 검수까지 끝낸 플롯 풀을 사전 생성함.

### 2) 입력과 출력

- **입력**: 추상화된 사건 상황 모음(별도 설계 예정), 박첨지 페르소나, 거리 문법. 
- **출력**: 마당 플롯 풀(텍스트와 JSON). 풀 스키마와 크기, Step 3 마당 선택과 플롯 문답 진행 시 이 풀에서 마당을 조회하고 받아 쓰는 방식은 구현 단계에서 정함

### 3) 동작과 규칙

1. **사건 구성**: 사건 상황 모음에서 도입/전개/마무리 사건을 골라 사건 라인 구성. 절정은 전개의 해소로 생성(마당 유형)
2. **해설과 질문 생성**: 사건을 박첨지 재담 화법으로 해설하고 유저 주도 질문 생성. temperature 잠정 0.7~0.9
3. **가드레일 검수**: 출력 해설과 질문이 정책을 통과하는지 검사
4. **재생성과 확정**: 위반 시 재시도(한도 잠정 3회), 통과분을 풀에 고정

### 4) 기술 요건

생성형 LLM. 모델 확보는 외부 API나 사전학습 모델 우선 검토(확인 필요). 판정 기준은 거리 문법 정합, 플롯 품질, 가드레일 통과율(정량 미정). 사전 배치라 실시간 아님

### 5) 실패와 복구

플롯이 가드레일을 통과 못 해 재생성을 반복하다 한도(잠정 3회)를 넘기면, 그 플롯은 풀에 넣지 않고 폐기함. 사전 배치 단계라 런타임 유저에겐 영향 없음. 폐기로 풀이 부족하면 사건 데이터나 프롬프트를 보강해 배치를 다시 돌림.

## 마. AI 가드레일

### 1) 역할과 목적

입력과 생성물의 안전을 검사하는 시스템으로 유해하거나 전통을 왜곡한 콘텐츠가 유저에게 노출되지 않게 방지함.

### 2) 입력과 출력

- **입력**: 검사 대상(사전 플롯 텍스트, 유저 응답, 생성물 서사와 일러스트)
- **출력**: 통과나 위반 판정. 위반 시 재생성이나 차단 트리거 실행

### 3) 동작과 규칙

#### 가) 적용 지점

- **사전(운영 전 생성)**: 마당 플롯 질문 생성 검수
- **런타임 입력**: 유저 응답 검사
- **런타임 출력**: 전자책 생성물(서사, 일러스트) 검사. 검사 항목은 유저 입력 삽입 안전, 전통 정체성 왜곡, 부적절 콘텐츠, 이미지 안전
	- 낭독 음성 합성은 출력 검사를 통과한 서사 텍스트만 입력으로 받음. 따라서 합성된 음성에 별도 검사를 두지 않음

#### 나) 유형별 차단과 설계 지향

| 마당 유형 | 차단 | 설계 지향 |
|---|---|---|
| 위협-구원형 | 특정 사람과 집단 비방 | 가상의 위협(특정 대상 아님) |
| 권력 풍자형 | 실제 정치인과 공공인물 풍자 | 추상화된 권위 |
| 위선 폭로형 | 특정 실명과 단체 풍자 | 윤리적 위선(남을 속이는 행위 등) |
| 욕심과 다툼형 | 처첩 삼각관계 default 금지 | 재산, 명예, 기회 |

#### 다) 세부 정책 (작성 예정)

전통 왜곡 판정 기준, 부적절 콘텐츠 분류, 동의 약관 항목 구체화 등

### 4) 기술 요건

- **검사 범위**: 텍스트(사전 플롯, 유저 응답, 생성 서사)와 이미지(생성 일러스트)를 모두 검사하므로 텍스트 모더레이션과 이미지 모더레이션 둘 다 필요함
- **접근 (결정 필요)**: 범용 유해물은 외부 안전 API로 거르고, 전통 정체성 왜곡처럼 범용 API가 못 잡는 판정은 자체 규칙이나 도메인 분류기로 보완함. API 대 자체 구축 비중은 후보 조사 후 확정
- **품질 기준**: 무인 운영이라 미탐(유해물 통과)이 오탐보다 위험하므로 미탐을 낮추는 보수적 임계로 잡음. 오탐율, 미탐율, 임계 목표는 검증 데이터 확보 후 정량 확정
- **지연 예산**: 런타임 입력과 출력 검사는 유저 대기 구간이라 검사 응답 지연 상한이 필요함(정량 미정)

## 바. 입력 유효성 검증

### 1) 역할과 목적

유저 입력을 형식과 길이로 검사하는 시스템. 잘못된 입력을 초기에 걸러내어 생성과 전달 등 후속 처리가 정상 작동하게 함.

### 2) 동작과 규칙

| 입력              | 검사                      |
| --------------- | ----------------------- |
| 이름 (Step 2)     | 최대 10자. 클라이언트 비속어 필터    |
| 거리별 답변 (Step 3) | 5~100자. 가드레일(런타임 입력) 적용 |

- 음성 답변은 STT 변환 텍스트에 같은 검사를 적용함
- 길이값(이름 10자, 답변 5~100자)은 잠정이며 콘텐츠 문안 확정 시 조정

## 사. 화면 타임아웃

### 1) 역할과 목적

플레이 중 한 화면에 장시간 체류하는 것을 방지함.

### 2) 동작과 규칙

- **처리**
	- 한 화면에서 N초(예. 60초) 이상 체류할 경우 다음 단계 진행함.
- **예외**
	- 필수 입력, 호스트 대화, 대기, 팝업 화면 미적용

## 아. 터치 미입력 타임아웃

### 1) 역할과 목적

유저 이탈에 대응해 방치된 세션을 정리하여 키오스크 회전율을 높임.

### 2) 동작과 규칙

- **처리**
	- 한 화면에서 N초(예: 45초) 이상 터치 미입력 시 종료 처리
	- 박첨지 발화 화면은 발화 종료나 스킵 후부터 측정 시작(발화 중에는 멈춤)
- **예외**
	- 대기, 감상 화면 미적용

## 자. 외부 서비스 호출 래퍼

### 1) 역할과 목적

외부 서비스 호출(STT, TTS, AI, 결과물 호스팅)을 감싸는 공통 계층 정리. 재시도와 타임아웃 대응을 한 곳에 모아, 매 호출 시 장애 처리를 별도 처리하지 않게 함.

### 2) 동작과 규칙

- **재시도 횟수**
	- 2회(잠정)
- **호출 타임아웃**
	- STT 10초, TTS 30초, LLM 30초, 이미지 생성과 결과물 호스팅 60초(모두 잠정)
	- TTS 상한 30초는 호스트 대사 한 마디와 결과물 낭독 4거리 분량에 함께 적용함. 낭독은 분량이 훨씬 길어, 합성 시간을 실측한 뒤 상한 분리를 검토함

## 차. 에러와 fallback

### 1) 역할과 목적

콘텐츠 전반의 실패를 받아 처리하는 단일 종료 경로. 무인 운영에서 오류가 방치되지 않도록 하여 세션을 안전하게 마무리함.

### 2) 동작과 규칙

- **진입 조건**
	- 재시도 한도를 넘긴 외부 호출 실패 (AI, STT, 결과물 호스팅)
	- 가드레일 재생성 한도 초과
	- 생성 파이프라인 실패
	- 결과물 호스팅 영구 실패
- **공통 처리**
	- 유저에게 안내 팝업을 띄우고 종료 처리.
- **유형별 처리**
	- 생성 실패, 가드레일 한도 초과: 사과 → Step 7. 미완성이나 위반 생성물은 파기
	- 결과물 호스팅 영구 실패: 사과 → Step 7. 재시도 한도를 넘겨 결과물을 호스팅하지 못한 경우이며, 후속 조치를 위해 운영에 알림
- **부분 실패 (종료 경로 미진입)**
	- 낭독 음성 합성 실패: 세션을 끝내지 않고 전자책만 조립해 전달하며, 운영에 알림
	- 근거: 이야기 본체(서사와 일러스트)는 이미 완성된 상태라, 음성 없이 전달하는 손실보다 세션을 통째로 버리는 손실이 큼
- **운영 알림**
	- 후속 조치가 필요한 실패(결과물 호스팅 실패, 낭독 음성 합성 실패 등)일 경우 실행

## 카. 박첨지 진행 호스트

### 1) 역할과 목적

박첨지를 디지털 휴먼 아바타로 구현한 전 세션 진행 호스트. 화면에 등장해 유저를 맞이하고 진행을 안내하며 이끎. 박첨지라는 덜미 정체성을 아바타로 살려 덜미의 전통요소 강화

### 2) 동작과 규칙

- **범위**
	- 전 세션 호스트. 
- **발화 방식**
	- TTS 음성으로 대사를 재생하고 같은 대사를 화면에 텍스트로 표시함. 
	- 발화 중 동작 애니메이션(입 모양 포함)을 재생함
- **입 모양**
	- 립싱크는 맞추지 않고 사전 생성한 입 움직임 애니메이션을 발화 중 재생함
- **재생 컨트롤러**
	- 동작 애니메이션 재생과 동시에 TTS 오디오를 재생하고 그 길이만큼 입 애니메이션을 루프
	- 립싱크가 없어 음소 정렬은 불필요
- **스킵**
	- 발화 중 다음 버튼을 누르면 발화를 중단하고 다음으로 진행함
- **타임아웃**
	- 발화 중에는 터치 미입력 타임아웃을 멈추고, 발화가 끝난 뒤 시간 체크 시작
- **대사 적용**
	- 적용 방법 논의 후 추가 예정

### 3) 필요 리소스

- 호스트 캐릭터는 인형극 양식으로, 애니메이션 가능하게 제작하며 픽처북 삽화 박첨지와 시각 정체성 일치해야 함
- 동작 애니메이션 세트(대기, 인사, 말하기, 제스처)
- 입 모양 애니메이션(발화 중 루프)
- 박첨지 TTS 보이스

### 5) 실패와 복구

- 아바타 렌더나 TTS 재생 실패 시 음성과 애니메이션 없이 텍스트 박스로만 진행함(대사는 표시하고 세션은 계속)

## 라. Step 4. 결과물 생성과 대기 화면 (병행)

백그라운드 생성과 포그라운드 대기가 동시 진행되고 상태 조회로 동기화됨.

### 1) 백그라운드: 결과물 생성

- **생성 파이프라인**
	1. 유저 입력 가공 LLM: 응답을 거리별 서사로 변환
	2. 이미지 생성 모델: 서사를 거리별 일러스트로 생성
	3. AI 가드레일: 생성물(서사, 일러스트) 출력 검사
		- 분기: 위반 시 1로 재생성 (한도 잠정 3회). 한도 초과 시 상태 `failed`
	4. 낭독 음성 생성: 검사를 통과한 거리별 서사를 박첨지 목소리 음성으로 합성
	5. 결과물 조립: 서사와 일러스트, 낭독 음성을 결과물 한 벌로 결합
- **실패(생성 단계 공통)**
	- AI 호출 실패 시 재시도 2회 후 `failed` 전환(에러와 fallback). 
	- 포그라운드 상태 조회 시 failed 검출 → 사과 화면 → Step 7. 재시도와 상태 조회 주기는 잠정 2회, 2초
	- 예외: 4단계 낭독 음성 생성만 실패하면 `failed`로 가지 않고 전자책만 조립해 `completed`로 진행함(에러와 fallback의 부분 실패)
- **상태 머신**
	- `generating` / `completed`(가드레일 통과분만) / `failed`(생성 실패 또는 가드레일 한도 초과)

### 2) 포그라운드: 대기 화면

- **UI(대기 화면)**
	- 대기 콘텐츠 노출(덜미 준비 과정 영상, 또는 공개 동의분 큐레이션 결과물)
	- 백엔드 상태 조회(주기 2초, 잠정)
	- 분기: `generating` → 대기 유지 / `completed` → 즉시 Step 5 / `failed` → 사과 화면 → Step 7 / 상태 조회 연속 무응답 임계 초과 → 에러 화면 → Step 7

### 3) 유저 입력 가공 LLM (개별 시스템)

#### 가) 역할과 목적

유저의 거리별 응답을 박첨지 화법의 거리별 서사로 변환하는 런타임 엔진. 사전 고정 플롯 위에 유저 입력을 녹여 매번 다른 "나만의 유람기" 본문을 만드는 게 목적.

#### 나) 입력과 출력

- **입력**: 배정된 마당 플롯(거리 컨텍스트), 거리별 유저 응답, 캐릭터 정보(이름, 연령대, 성별)
- **출력**: 거리별 서사 텍스트

#### 다) 동작과 규칙

응답을 박첨지 서사 화법에 녹여 거리별 서사를 생성함. 이름과 캐릭터는 슬롯 치환 수준으로 개인화하고, 사전 생성 플롯의 거리 컨텍스트를 따름.

#### 라) 기술 요건

생성형 LLM. 모델 확보는 외부 API나 사전학습 모델 우선 검토(확인 필요). 판정 기준은 서사 일관성, 응답 시간(정량 미정).

#### 마) 필요 리소스

박첨지 화법, 사전 생성 마당 플롯(마당 플롯 생성 LLM).

#### 바) 실패와 복구

생성 서사는 출력 가드레일 검사를 받음. 호출 실패나 가드레일 미통과는 생성 파이프라인의 `failed` 처리(에러와 fallback)로 이어짐.

### 4) 이미지 생성 모델 (개별 시스템)

#### 가) 역할과 목적

거리별 서사를 인형극 양식 일러스트로 시각화하는 런타임 엔진. 인형 시각 정체성을 레퍼런스로 고정하고 동화풍을 배제해(나무 인형 양식), 전자책이 덜미다운 룩을 갖게 하는 게 목적.

#### 나) 입력과 출력

- **입력**: 거리별 서사와 캐릭터, 양식 레퍼런스
- **출력**: 거리별 일러스트(세로 형식)

#### 다) 동작과 규칙

거리별 서사에 맞춰 인형극 양식 일러스트를 생성함. 캐릭터 레퍼런스로 인물 일관성을 고정함.

#### 라) 기술 요건

이미지 생성 모델. 모델 확보는 사전학습 모델이나 외부 API 우선 검토(확인 필요). 판정 기준은 인물 일관성, 양식 정합, 생성 시간(정량 미정).

#### 마) 필요 리소스

캐릭터 레퍼런스, 인형극 시각 양식 가이드.

#### 바) 실패와 복구

생성 일러스트는 출력 가드레일 검사를 받음. 호출 실패나 가드레일 미통과는 생성 파이프라인의 `failed` 처리(에러와 fallback)로 이어짐.

### 5) 낭독 음성 생성 (개별 시스템)

#### 가) 역할과 목적

거리별 서사를 박첨지 목소리 음성으로 합성하는 런타임 엔진. 유저가 받아 가는 결과물에 전자책과 짝을 이루는 낭독본을 붙여, 글을 읽기 어려운 유저(아이 등)도 자기 유람기를 듣게 하는 게 목적.

#### 나) 입력과 출력

- **입력**: 출력 가드레일을 통과한 거리별 서사 텍스트, 박첨지 TTS 보이스(박첨지 진행 호스트와 공유)
- **출력**: 거리(페이지) 단위로 나뉜 낭독 음성 파일. 파일 형식과 거리별 분리 대 단일 파일 결합은 구현 단계에서 정함

#### 다) 동작과 규칙

거리 순으로 서사 텍스트를 박첨지 목소리로 합성함. 진행 호스트 대사와 같은 보이스를 써서 세션 내내 화자가 하나로 들리게 함. 합성 결과는 Step 5 감상 화면 재생과 Step 6 결과물 다운로드 안내에 같은 파일을 씀.

#### 라) 기술 요건

상용 음성 합성(TTS) API. 박첨지 진행 호스트가 쓰는 TTS와 같은 서비스를 씀. 판정 기준은 화자 일관성, 낭독 자연성, 합성 시간(정량 미정).

#### 마) 필요 리소스

박첨지 TTS 보이스(박첨지 진행 호스트 §3.카 3) 필요 리소스와 동일 자산).

#### 바) 실패와 복구

합성 호출 실패 시 재시도하고, 한도를 넘기면 음성 없이 전자책만 전달함(에러와 fallback의 부분 실패). 이 엔진의 실패는 세션을 끝내지 않음. 입력 서사가 이미 가드레일을 통과했으므로 음성 자체의 가드레일 검사는 없음(AI 가드레일 §3.마 3) 가) 적용 지점).

### 6) 결과물 조립 (개별 시스템, 비-AI)

#### 가) 역할과 목적

거리별 서사와 일러스트, 낭독 음성을 유람기 한 편으로 묶는 비-AI 오케스트레이션. 흩어진 생성물을 유저가 받는 최종 산출물(전자책과 낭독 음성 파일)로 조립하는 게 목적.

#### 나) 입력과 출력

- **입력**: 거리별 서사(유저 입력 가공 LLM), 거리별 일러스트(이미지 생성 모델), 거리별 낭독 음성(낭독 음성 생성, 합성 실패 시 없음)
- **출력**: 다중 페이지 전자책 파일과 낭독 음성 파일, 메타(생성 시각 등)

#### 다) 동작과 규칙

거리 순으로 서사와 일러스트를 페이지로 묶고 같은 거리의 낭독 음성을 그 페이지에 대응시켜 조립, 저장함. 출력 가드레일 통과분만 저장함. 낭독 음성이 없으면(합성 실패) 전자책만 조립함. 형식은 미정.

#### 라) 기술 요건

백엔드 결합과 저장 로직. AI 모델이 아닌 백엔드 오케스트레이션.

#### 마) 실패와 복구

조립 전 출력 가드레일 검사. AI 생성 실패나 가드레일 한도 초과 시 `failed` 경로에 합류(에러와 fallback).

## 마. Step 5. 결과물 표시

### 1) UI(결과물 감상/열람 화면): 결과물 첫 페이지 표시

- **진행**: 결과물 첫 페이지 표시하고 해당 페이지의 낭독 음성을 재생(생성 파이프라인이 만든 파일). 받기 버튼 터치 시 재생을 멈추고 다음 단계 진행
	- 분기: 낭독 음성이 없으면(합성 실패) 재생 없이 페이지만 표시함
- **적용 시스템**: 화면 타임아웃

## 바. Step 6. 결과물 다운로드 안내

### 1) 백엔드

- **진행**: 결과물(전자책과 낭독 음성 파일)을 웹에 호스팅하고 만료형 다운로드 URL 발급
	- 전자책과 낭독 음성을 한 페이지에서 함께 받게 해 QR과 URL은 하나만 씀. 묶음 형식(개별 다운로드 대 압축 한 벌)은 구현 단계에서 정함
	- 낭독 음성 합성이 실패한 세션은 전자책만 호스팅함(에러와 fallback의 부분 실패)
	- 분기: 업로드나 호스팅, URL 발급 실패 시 재시도(결과물 호스팅 재시도 2회 잠정), 한도 초과 시 사과 후 Step 7 + 운영 알림
- **적용 시스템**: 외부 서비스 호출 래퍼, 에러와 fallback

### 2) UI(결과물 QR 화면)

- **진행**: 발급된 다운로드 URL을 인코딩한 QR을 화면에 표시하고 스캔 안내와 다운로드 가능 기간을 함께 보여줌. 유저가 본인 휴대폰으로 스캔해 웹에서 결과물을 받고, 마침 선택 시 Step 7 진행
	- 연락처를 받지 않으므로 전송 동의나 입력 유효성 검증이 없음
	- 분기: 화면 타임아웃 발동 시 Step 7로 정상 진행
- **적용 시스템**: 화면 타임아웃

## 사. Step 7. 종료와 리셋

### 1) UI(마무리 인사 화면)

- **진행**: 마무리 인사 표시

### 2) 백엔드

- **진행**: 세션 종료 및 임시 데이터 파기

### 3) UI(시작 화면): 시작 화면 복귀 (다음 유저 대기, Step 1과 공유)

- **진행**: Step 1의 시작 화면 복귀하여 다음 유저 대기.
