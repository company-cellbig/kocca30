> 덜미(꼭두각시놀음)를 소재로, 유저가 박첨지의 유람에 합류해 자기만의 유람기 한 편(그림동화 전자책)을 완성하는 AI 시범콘텐츠의 개발 기획서. [[콘텐츠 기획서 작성 양식]]을 따름. 골격 단계로, 점차 채워나감.

# 1. 개요

- **콘텐츠 정의**: 덜미(꼭두각시놀음)를 소재로 한 AI 그림동화 콘텐츠. 유저는 박첨지(떠돌이 노인)의 유람에 주인공으로 합류해, AI가 제시한 마당(플롯)을 거리별 선택과 응답으로 채워 자기만의 유람기 한 편을 완성함. "나만의 유람기"는 이 경험을 가리키고, 그 산출물은 그림동화 전자책 형식으로 남음
- **소재**: 한국 전통 인형극 덜미(꼭두각시놀음) ([[덜미]]). 위계는 `굿(극) > 마당(막) > 거리(장/경)`(심우성 남사당놀이 분류)이며, 본 콘텐츠의 플롯 단위는 마당, 그 안을 거리가 구성함 (상세 §3.가)
- **목표 경험**: 덜미의 문학적 골격(재담, 풍자, 거리식 구성)은 고정하고, 그 안의 사건과 해설과 이야기를 유저 입력과 AI 생성으로 채워 매번 다른 그림동화를 만듦
- **핵심 메커닉**: 한 세션 = 한 마당 = 완결된 그림동화 한 편. AI가 4종 마당 유형의 플롯을 사전 생성해 두고, 유저가 유형을 고르면 그 유형 마당 하나가 랜덤 배정되어 거리 단위로 채워짐 (상세 §3.가)
- **플랫폼과 세션 길이**: 16:9 가로형 키오스크 터치, 1인 사용. 플레이타임 목표 5분(세션 전체 합산, 강제 카운트다운 아님). 1회 세션과 공용 기능 골격은 [[시범콘텐츠 공통 사양]]
- **문서 범위**: 콘텐츠 로직(전체 플로우, 구성 요소, 기술 요건, 자산, 가드레일)을 담음. 세션과 공용 기능과 기술 6영역 골격은 [[시범콘텐츠 공통 사양]], 1년차 사용자 모델은 [[플랫폼 사양#5. 사용자 모델 (1년차)]](연속성은 2차연도 [[플랫폼 사양#6. 2차연도 전방 설계 (디지털 도제 연속성, 현재 구현 밖)]])을 참조함. 화면의 시각과 레이아웃 상세를 다루는 UI 문서는 미작성이며, 작성 시 분리함
- **사용자 연속성 (1년차)**: 익명 1회성으로 운영함(결과물 전송 후 파기). 학습 프로필과 이어하기, 콘텐츠 횡단 누적은 2차연도로 둠 (상세 §4.나)

목표와 세부 범위 등 나머지 개요 항목은 작성 예정.

# 2. 전체 플로우

런타임 흐름(Step 시퀀스, 상태, 분기, 병행, 파기 시점)을 담음. 화면의 시각 설계는 다루지 않고, 각 구성 요소의 깊은 로직은 §3을 참조함.

- **Step 개요**: S1 인트로 → S2 캐릭터 정보 입력 → S3 마당 선택과 플롯 문답 → S4 결과물 생성과 대기 화면(병행) → S5 결과물 표시 → S6 결과물 전송 → S7 종료와 리셋

Step 정의와 명세 항목은 [[시범콘텐츠 공통 사양#3. Step 모델]]을 따름. 여러 Step에 걸친 공용 기능(입력 유효성, 가드레일, 타임아웃, 에러와 fallback 등)은 아래 공통 표를 따름.

## 가. Step별 흐름

### 1) S1. 인트로 (시작 + 동의)

- **트리거**: 유저가 시작 버튼 터치
- **시스템**: 클라이언트 UI (§4.다), 백엔드 (§4.다)
- **프로세스**
	1. 백엔드: 신규 세션 생성
	2. UI: 인사말 화면 표시 + "터치하세요" 안내
	3. UI: 터치 감지 → 진행 가이드 화면
	4. UI: 터치 감지 → 고객 동의 약관(주의사항) 화면
	5. UI: 동의 버튼 터치 감지 (동의 화면, 화면 타임아웃 미적용)
		- 호출 공용 기능: 터치 미입력 타임아웃
		- 분기: 터치 미입력 타임아웃 발동 시 미동의로 간주 → S7 직행 (별도 거부 버튼 없음)
	6. 백엔드: 동의 기록 저장 (세션 ID, 약관 버전, 타임스탬프)
- **입력**: 터치 이벤트, 동의 결정
- **출력**: 세션 ID, 동의 기록
- **다음**: S2

### 2) S2. 캐릭터 정보 입력

- **트리거**: S1 동의 완료
- **시스템**: 클라이언트 UI (§4.다), 백엔드 (§4.다)
- **프로세스**
	1. UI: 이름 입력 폼 (유저 주인공 설정. §3.가 변주의 유저 입력 슬롯과 연동)
	2. UI: 이름 유효성 검증 (클라이언트 비속어 필터)
		- 호출 공용 기능: 입력 유효성 검증
		- 분기: 비속어 검출 시 팝업 안내 → sub-step 1로 재진입
	3. UI: 8개 카드(아이/청소년/청년/장년 × 남/여) 중 1개 선택
		- 호출 공용 기능: 터치 미입력 타임아웃 (이름 입력, 카드 선택 모두 필수 입력 화면, 화면 타임아웃 미적용)
		- 분기: 터치 미입력 타임아웃 → S7 직행
	4. 백엔드: 세션에 캐릭터 정보 저장
- **입력**: 이름, 카드 선택(성별 × 연령대)
- **출력**: 세션 캐릭터 정보 갱신
- **다음**: S3

### 3) S3. 마당 선택과 플롯 문답 (거리별 반복)

- **트리거**: 캐릭터 정보 입력 완료
- **시스템**: AI 시스템 (§3.아 가드레일; 배정 플롯은 §3.나 사전 산출물), 클라이언트 UI (§4.다), 백엔드 (§4.다)
- **프로세스**: 유저가 마당 유형을 고르면 시스템이 그 유형 풀에서 랜덤 마당을 배정(sub-step 1~2), 이후 배정된 마당의 4거리(도입/전개/절정/마무리, §3.가)를 순서대로 sub-step 3~5 묶음 반복
	1. UI: 마당 유형 4종 카드 제시 → 유저가 1개 선택
		- 호출 공용 기능: 터치 미입력 타임아웃 (필수 입력 화면, 화면 타임아웃 미적용)
		- 분기: 터치 미입력 타임아웃 → S7 직행
	2. 백엔드: 선택 유형 풀에서 랜덤 마당 1개 배정 (사전 생성과 검수된 플롯, §3.가)
	3. UI(박첨지): 박첨지 캐릭터 + 해당 거리의 사전 생성 질문 표시(고정), 유저 응답 입력 받기 (가상 키보드 기본, 음성 인식(STT) 입력 병행 → 변환된 텍스트로 처리)
		- 호출 공용 기능: 터치 미입력 타임아웃 (필수 입력 화면, 화면 타임아웃 미적용)
		- 분기: 터치 미입력 타임아웃 → S7 직행
	4. AI 가드레일: 유저 응답 검사 (§3.아)
		- 호출 공용 기능: AI 가드레일
		- 분기: 위반 시 팝업 안내 → sub-step 3으로 재진입 (유저 재입력)
	5. 백엔드: 응답을 세션에 누적 저장
- **입력**: 마당 유형 선택(유저), 거리별 응답(텍스트: 가상 키보드 또는 STT 음성)
- **출력**: 선택 유형과 배정 마당, 거리별 응답 누적, 박첨지 진행 대화 로그
- **다음**: 모든 거리 완료 시 S4

### 4) S4. 결과물 생성과 대기 화면 (병행)

- **트리거**: 플롯 문답 완료
- **시스템**: AI 시스템 (§3.다~라, §3.아), 백엔드 (§3.마, §4.다), 클라이언트 UI (§4.다), 외부 서비스 (§4.다)
- **프로세스** (백그라운드와 포그라운드 동시, 상태 조회로 동기화)
	- **백그라운드: 결과물 생성**
		1. 유저 입력 가공 LLM (§3.다): 응답을 거리별 서사 텍스트로 변환
		2. 이미지 생성 모델 (§3.라): 거리별 일러스트 생성
		3. 결과물 조립 (§3.마): 서사와 일러스트를 그림동화 페이지로 결합
		4. AI 가드레일 (§3.아): 생성물(서사와 일러스트) 출력 검사
			- 분기: 위반 시 sub-step 1로 재생성 (N회 한도). 한도 초과 시 상태 `failed`
		5. 백엔드: 검사 통과한 결과물을 저장소에 저장
		- 실패: AI 호출(LLM, 이미지 생성) 실패 시 재시도 N회(예: 2회) 후 `failed` 전환. 포그라운드 상태 조회가 검출 → 사과 화면 → S7. 구체 N과 상태 조회 주기는 §2.나 운영 파라미터
		- 백엔드 상태 머신: `generating` / `completed`(가드레일 통과분만) / `failed`(생성 실패 또는 가드레일 한도 초과)
	- **포그라운드: 대기 화면** ([[시범콘텐츠 공통 사양#다. 생성과 변환 대기]] 준용)
		1. UI: 대기 콘텐츠 노출(덜미 준비 과정 영상 §3.사, 또는 공개 동의분 큐레이션 결과물)
		2. UI: 백엔드 상태 조회 (주기는 §2.나)
			- 분기: `generating` → 대기 유지 / `completed` → 즉시 S5 / `failed` → 사과 화면 → S7 / 상태 조회 연속 무응답 임계 초과 → 에러 화면 → S7
- **입력**: 세션 응답 전체, 캐릭터 정보
- **출력**: 그림동화 파일 (다중 페이지)
- **다음**: 포그라운드 상태 조회가 `completed`를 받으면 즉시 S5

### 5) S5. 결과물 표시

- **트리거**: 그림동화 파일 생성 완료
- **시스템**: 클라이언트 UI (§4.다), 백엔드 (§4.다)
- **프로세스**
	1. UI: 결과물 첫 페이지 표시
	2. UI: 페이지 넘김 인터랙션(터치). 감상과 열람 화면 (터치 미입력 타임아웃 미적용)
		- 호출 공용 기능: 화면 타임아웃
		- 분기: 화면 타임아웃 발동 시 정상 진행 경로로 전송 단계(S6)로 넘어감(감상 종료로 간주)
	3. UI: 마지막 페이지 도달 시 "전송" 버튼 노출
- **입력**: 그림동화 파일
- **출력**: 유저가 결과물 확인
- **다음**: 유저가 "전송" 진행 → S6

### 6) S6. 결과물 전송

- **트리거**: 유저가 전송 안내 화면에서 진행
- **시스템**: 클라이언트 UI (§4.다), 백엔드 (§4.다), 외부 서비스 (§4.다). 전송 화면 공통 동작은 [[시범콘텐츠 공통 사양#5. 공통 화면]] 라 준용
- **프로세스**
	1. UI: 전화번호 입력 폼과 개인정보 수집 이용 안내 (필수 입력 화면, 화면 타임아웃 미적용). 전송 탭이 곧 발송 동의, 받지 않기 탭이 거부임(별도 동의 토글 없음)
		- 호출 공용 기능: 터치 미입력 타임아웃
		- 분기: 전송 거부 시 SMS 단계 생략 → S7
		- 분기: 터치 미입력 타임아웃 발동 시 유저 이탈로 보고 연락처 즉시 파기 → S7 직행
	2. 백엔드: 전화번호 임시 저장 (개인정보 처리 §4.나)
	3. 외부 서비스 SMS: 결과물 호스팅 URL이나 이미지 전송
		- 호출 공용 기능: 외부 서비스 호출 래퍼
		- 분기(실패 유형별): 일시 장애 → 재시도 N회(§2.나) / 수신 번호 영구 실패 → 재입력 1회 허용 후 S7 / 그 외 영구 실패 → 사과 후 S7 + 운영 알림
- **입력**: 전화번호, 전송과 받지 않기 선택(= 발송 동의와 거부)
- **출력**: SMS 발송 결과
- **다음**: S7

### 7) S7. 종료와 리셋

- **트리거**: 결과물 전송 완료, 미동의, 또는 터치 미입력 타임아웃(유저 이탈)
- **시스템**: 클라이언트 UI (§4.다), 백엔드 (§4.다)
- **프로세스**
	1. UI: 마무리 인사 화면
	2. 백엔드: 세션 종료, 임시 데이터 파기 (전화번호 잔류 시 즉시 파기 = 백스톱. 콘텐츠 데이터 보관 정책은 §4.나)
	3. UI: 시작 화면 복귀 (다음 유저 대기)
- **입력**: 종료 트리거
- **출력**: 키오스크 idle 상태
- **다음**: 다음 유저용 S1 대기

## 나. 운영 파라미터

전체 플로우의 잠정 기본값을 정리함. 구현과 운영 단계에서 확정함(견적과 구현 추정 보조 목적). 공통 운영 파라미터는 [[시범콘텐츠 공통 사양#9. 운영 파라미터 (공통 기본값)]]을 따르고, 아래는 본 콘텐츠 관련 값임.

| 파라미터 | 잠정 기본값 | 확정 시점 | 관련 위치 |
|---|---|---|---|
| 화면 타임아웃 | 예: 60초 | 구현 | §2.가 감상과 열람 화면 |

# 3. 구성 요소

콘텐츠를 이루는 요소를 의존 순으로 배열함. 설계 골격(플롯 구조)을 먼저 두고, 그것을 쓰는 생성 엔진을 파이프라인 순으로, 이어 진행 호스트와 자산, 끝으로 전 단계를 가로지르는 가드레일을 둠. 생성 엔진(나~마)과 가드레일(아)은 역할과 목적, 입력과 출력, 동작과 규칙, 기술 요건, 자산 요구, 가드레일과 실패, 의존을 갖춘 독립 명세로 적음. 설계 골격(가), 진행 호스트(바), 자산(사)은 엔진이 아니라 설계와 연출과 자산 정의라 서술형으로 적음.

## 가. 플롯 구조

본 콘텐츠의 서사 골격. 모든 생성 엔진이 이 골격을 전제로 동작함.

### 1) 마당 = 플롯 단위

- **마당 정의**: 박첨지 등장(도입)부터 닫는 해설(마무리)까지 하나의 인과 줄기로 이어지는 응집된 극 단위. 원형은 [[덜미]] 2마당 7거리
- **한 세션 = 한 마당 = 한 편의 그림동화**
- **여러 틀 중 하나로 생성 (4종)**: 마당은 고정된 한 틀이 아니라 4종 유형(아래 마당 유형) 중 하나로 만들어짐. 각 유형은 자기 고유 서사를 가진 독립 완결 구조임
- **같은 틀, 다른 내용 (비고정 출력)**: 고정된 것은 틀(유형의 구조)뿐. 세션마다 다른 결과는 두 축(사전 풀에서 랜덤 배정, 유저 입력)에서 나옴. 메커니즘은 아래 생성과 제시와 채움, 변주 슬롯은 변주 참조

### 2) 마당 공통 골격

모든 유형은 박첨지가 여닫는 공통 골격을 공유함. 한 마당 = 4거리. 플레이타임 목표 5분은 세션 전체(S1~S7, 마당 선택 포함) 합산 목표임(§2). 아래는 본편 거리의 대략 배분으로, 비-거리 단계와 함께 5분 안에 듦.

| 거리(장면) | 기능 | 적용 범위 | 목표 시간 |
|---|---|---|---|
| 도입 | 박첨지 등장과 유람 + 유저(주인공) 합류, 첫 재담 | 모든 유형 공통 | 약 0.5분 |
| 전개 | 선택된 유형의 갈등 등장 | 유형별 | 약 1.5분 |
| 절정 | 선택된 유형의 해소 | 유형별 | 약 1.5분 |
| 마무리 | 박첨지 닫는 해설과 맺음 인사 | 모든 유형 공통 | 약 0.5분 |

- 본편 4거리 약 4분, 나머지 약 1분은 인트로, 마당 선택, 생성 대기, 전송 등 비-거리 단계임(세션 전체 5분 목표 안)
- **도입과 마무리는 박첨지가 직접 여닫음**(해설자와 길잡이). 유저가 주인공이고 박첨지는 그 여정을 잇는 해설자와 안내자임 (§3.바와 일치)
- 유형별로 다른 것은 전개와 절정 2거리이며, 이것이 4종 구조를 가름

### 3) 마당 유형 (4종)

덜미 7거리의 갈등 핵을 4종 마당 구조로 정리함. 각 구조는 전개에서 절정으로 인과가 직결된 독립 완결 단위로, 전개의 갈등 대상이 그 마당의 절정에서 해소됨.

| 마당 유형 | 전개 (갈등) | 절정 (해소) | 원형 거리 |
|---|---|---|---|
| 위협-구원형 | 외부 위협 고조 | 유저가 맞서고 홍동지가 힘을 보태 함께 처치 | 이시미거리 |
| 권력 풍자형 | 권력자 허세 | 유저가 허세를 들춰내고 홍동지가 조롱으로 거듦, 골계적 추락 | 매사냥거리, 상여거리 |
| 위선 폭로형 | 위선 행각 | 유저가 위선을 드러내고 홍동지가 축출로 거듦, 폭로와 망신 | 피조리거리 |
| 욕심과 다툼형 | 욕심 다툼 | 유저의 선택이 파국, 손해, 떠남을 가름 | 꼭두각시거리 |

- **절정은 유저(주인공)가 주도하고 홍동지는 조력함**(대체 아님). 홍동지 응징의 카타르시스는 유형별로 다른 형태로 나타남(위협-구원형은 힘, 권력형은 조롱, 위선형은 축출). 보편 단일 절정이 아님
- **욕심과 다툼형은 홍동지 비중이 낮은 유형**임. 원형 꼭두각시거리가 박첨지 가정사 중심이라 본디 홍동지가 약함. 대신 유저의 선택이 파국, 손해, 떠남을 가름(유저 능동성 유지). 홍동지 조력 변주는 추후 확장
- 각 유형 내부는 유저 입력 기반으로 무한 변주됨(아래 변주)

### 4) 생성과 제시와 채움 (사전 생성 + 런타임 선택)

마당 플롯(거리별 질문 포함)은 사전 생성과 검수를 거치고, 런타임은 선택과 응답 수집만 함. 키오스크 무인 운영의 안전과 속도와 안정을 우선한 사전 생성 고정형 하이브리드 방식임 (§3.아, [[rfp_제안요청서#나. 연구 내용]] 검증위원회).

- **사전 생성**: 마당 플롯 생성 LLM(§3.나)으로 유형별 다수 마당 플롯을 미리 생성함. 거리별 박첨지 질문 텍스트까지 고정하고, 사전 가드레일 검수 후 풀에 저장함 ([[마당 사건 풀]] 시드 활용)
- **유저 선택 (유형 단위)**: 유저는 마당 유형 4종 중 하나를 선택함(병렬 카드). 시스템이 그 유형 풀에서 랜덤으로 마당 1개를 배정함. 런타임 선택 흐름과 타임아웃은 §2.가 3) S3
- **거리별 채움**: 주어진 마당의 거리(도입/전개/절정/마무리)를 순서대로 제시(고정 질문)하고 유저가 각 거리에 응답함. 이름과 캐릭터는 슬롯 치환 정도의 가벼운 개인화임
- **전자책 생성**: 종료 후 유저 응답 전체를 토대로 서사와 일러스트를 런타임 생성함(§2.가 4) S4, §3.다)
- **다양성**: 마당 유형(4) × 유형별 사전 풀 크기 × 유저 응답으로 같은 유형도 매번 다름. 질문 적응형(유저 답 반영 재질문)은 2년차 검토 대상

### 5) 변주

변주는 같은 틀(마당 유형과 거리 골격)에 다른 내용(사건, 풍자 대상, 인물)을 넣어 매번 다른 결과를 만드는 것임. 변주곡처럼 틀은 두고 내용만 바뀜. 두 갈래에서 일어남.

- **유저 입력 슬롯**: 유저가 채운 입력이 이야기 전개의 재료가 됨(원리: 작품의 추상화된 위선과 권위 자리를 유저가 입력한 소재로 채움). 슬롯은 이름(주인공), 마당 선택(유형 4종 중 택1), 합류 계기(도입 거리 응답), 거리별 응답(전개/절정/마무리)
- **AI 질문 변주 (사전 생성)**: 같은 유형이라도 질문이 단조롭지 않게, 사전 생성 단계에서 유형 풀에 변주를 마련하고 런타임은 랜덤 선택함
	- 사건 형태: 거리 안 사건 컨텍스트 변주 (예: 도입이 길에서 / 잔치에서 / 시장에서)
	- 풍자 대상: 추상화된 권위와 위선 형태 변주 (예: 허세 권위자 / 겉만 번지르 / 횡포한 자)
	- 박첨지 입장: 목격자 / 당사자 / 풍자자 등 역할 변주
	- 구현은 §3.나 사전 질문 생성에서 다양성 메커니즘 적용(prompt 변주, 유형별 사건 풀, temperature 조절 등). 사전 가드레일 검수로 §3.아 정책을 풀 전체에 일관 적용
- **변주와 일관성**: 위 차원만 변주하고 마당 공통 골격과 마당 유형의 고정 문법은 일관 유지함. 예: 도입 거리는 항상 "박첨지 등장 + 유저 합류" 골격을 지키고 그 안의 사건만 다양함
- **세부 설계 (작성 예정)**: 유저 응답에서 사건으로의 매핑 LLM 프롬프트, 마당 유형 제시와 선택 로직 등

### 6) 마당 사건 풀과 플롯 풀 (데이터)

생성 엔진이 소비하는 입력 데이터임. 정의는 여기 두고, 생성 동작은 §3.나가 다룸.

- **[[마당 사건 풀]]** (서사 데이터, 텍스트와 JSON): 플롯 생성용 사건 시드(재료)임. 거리와 유형별 목표 5~10(현 절정 약 4로 보강 필요). §3.나 마당 플롯 생성 LLM의 입력
- **마당 플롯 풀** (서사 데이터, 텍스트와 JSON): 사건 풀로 사전 생성한 완성 플롯(완제품, 런타임 배정 대상)임. 가드레일 검수를 거침. §3.나의 출력이며 §2.가 3) S3에서 랜덤 배정됨

## 나. 마당 플롯 생성 LLM (사전)

- **역할과 목적**: 마당 플롯(거리별 해설과 질문)을 사전 생성함. §3.바 박첨지 진행 호스트의 화법을 적용함
- **입력과 출력**: 입력은 [[마당 사건 풀]] 시드와 박첨지 페르소나, 거리 문법. 출력은 거리별 박첨지 해설과 질문(고정)으로 묶인 마당 플롯 풀
- **동작과 규칙 (생성 4단계)**:
	1. 사건 구성: [[마당 사건 풀]]에서 도입, 전개, 마무리 사건을 골라 한 마당의 사건 라인을 구성함. 절정은 그 전개의 해소로 생성함(전개에서 절정으로 인과 직결, §3.가 3), 절정은 독립 선택 아님). 다양성은 마당 수준으로, 한 유형당 여러 마당을 전개를 달리해 겹치지 않게 생성함
	2. 해설과 질문 생성: 사건을 박첨지 재담 화법(§3.바)으로 해설하고, 유저(주인공)의 행동과 선택을 묻는 질문을 생성함. 절정 거리에서 유저 주도를 유도함(홍동지 조력, §3.가 3). temperature는 0.7~0.9 (§2.나)
	3. AI 가드레일 사후 검사 (§3.아): 출력 해설과 질문이 가드레일 정책을 통과하는지 검사함
	4. 재생성과 확정: 위반 시 재시도(한도 §2.나). 통과분을 플롯에 고정해 풀에 저장함
- **기술 요건**: 생성형 대규모 언어 모델(LLM). 모델 확보는 외부 API나 사전학습 모델 우선 검토(후보 확인 필요). 판정 기준은 거리 문법 정합, 플롯 품질, 가드레일 통과율(정량 미정, 확인 필요). 사전 배치 생성이라 실시간이 아님. AI 모듈 명세 항목은 [[시범콘텐츠 공통 사양#가. AI 시스템]] 준용
- **자산 요구**: [[마당 사건 풀]] 시드(§3.가 6), 박첨지 페르소나와 거리 문법(§3.바, §3.가)
- **가드레일과 실패**: 사전 플롯 검수가 가드레일 3지점 중 첫 지점임(§3.아). 재생성 한도 초과 시 해당 플롯을 폐기함(사전 단계라 유저 영향 없음)
- **의존**: 입력은 §3.가 6) [[마당 사건 풀]]. 출력 마당 플롯 풀은 §2.가 3) S3 랜덤 배정과 §4.다 백엔드 진행 제어가 사용

## 다. 유저 입력 가공 LLM (런타임)

- **역할과 목적**: 유저의 거리별 응답을 거리별 서사 텍스트로 변환함 (§2.가 4) S4 백그라운드)
- **입력과 출력**: 입력은 거리별 유저 응답과 캐릭터 정보(이름, 연령대, 성별). 출력은 거리별 서사 텍스트
- **동작과 규칙**: 유저 응답을 박첨지 서사 화법(§3.바)에 녹여 거리별 서사를 생성함. 이름과 캐릭터 설정은 슬롯 치환 수준의 가벼운 개인화임(§3.가 4). 사전 생성 플롯의 거리 컨텍스트를 따름
- **기술 요건**: 생성형 LLM. 모델 확보는 외부 API나 사전학습 모델 우선 검토(후보 확인 필요). 판정 기준은 서사 일관성, 응답 시간(S4 대기 영향)(정량 미정, 확인 필요). 명세 항목은 [[시범콘텐츠 공통 사양#가. AI 시스템]] 준용
- **자산 요구**: 박첨지 화법과 거리 문법(§3.바, §3.가), 사전 생성 마당 플롯(§3.나)
- **가드레일과 실패**: 생성 서사는 출력 가드레일(S4, §3.아) 대상임(유저 입력 삽입 안전 포함). 생성 실패 시 재시도 후 `failed` 전환(§2.가 4) S4, §2.나)
- **의존**: 입력은 §2.가 3) S3 유저 응답과 §3.나 마당 플롯. 출력 서사는 §3.라 이미지 생성과 §3.마 결과물 조립이 사용

## 라. 이미지 생성 모델 (런타임)

- **역할과 목적**: 인형극 양식 일러스트를 생성함. 인형 시각 정체성을 레퍼런스로 고정하고 동화풍을 배제함(나무 인형 양식)
- **입력과 출력**: 입력은 거리별 서사와 캐릭터, 양식 레퍼런스(§3.사). 출력은 거리별 일러스트
- **동작과 규칙**: 거리별 서사에 맞춰 인형극 양식 일러스트를 생성함. 인형 시각 정체성을 레퍼런스로 고정함(§3.사 캐릭터 레퍼런스). 결과물 이미지는 그림동화(세로) 형식이며 화면 방향(가로)과 별개임
- **기술 요건**: 이미지 생성 모델. 인물 일관성 메커니즘은 §3.사 비교표(프롬프트, IP-Adapter, LoRA)로 아트팀 협의 확정. 모델 확보는 사전학습 이미지 생성 모델이나 외부 API 우선 검토(후보 확인 필요). 판정 기준은 인물 일관성, 양식 정합, 생성 시간(정량 미정, 확인 필요). 명세 항목은 [[시범콘텐츠 공통 사양#가. AI 시스템]] 준용
- **자산 요구**: 캐릭터 레퍼런스, 인형극 시각 양식 가이드(§3.사)
- **가드레일과 실패**: 생성 일러스트는 출력 가드레일(S4, §3.아) 대상임(이미지 안전). 생성 실패 시 재시도 후 `failed` 전환(§2.가 4) S4, §2.나)
- **의존**: 입력은 §3.다 서사와 §3.사 레퍼런스. 출력 일러스트는 §3.마 결과물 조립이 사용

## 마. 그림동화 결과물 조립 (백엔드)

- **역할과 목적**: AI가 생성한 거리별 서사와 일러스트를 그림동화 한 편으로 결합하는 비-AI 오케스트레이션임
- **입력과 출력**: 입력은 거리별 서사(§3.다)와 거리별 일러스트(§3.라). 출력은 다중 페이지 그림동화 파일과 메타(생성 시각 등)
- **동작과 규칙**: 거리 순서대로 서사와 일러스트를 페이지로 묶어 그림동화를 조립하고 저장소에 저장함. 출력 가드레일(§3.아) 통과분만 저장함. 형식(PDF, EPUB, 이미지 묶음)은 미정
- **기술 요건**: 백엔드 결합과 저장 로직. AI 모델이 아닌 오케스트레이션 계층임(§4.다 백엔드)
- **자산 요구**: 없음(생성 산출물을 결합)
- **가드레일과 실패**: 조립 전 출력 가드레일 검사를 거침. AI 생성 실패나 가드레일 한도 초과 시 `failed` 경로로 합류(§2.가 4) S4)
- **의존**: 입력은 §3.다, §3.라. 출력 그림동화는 §2.가 5) S5 표시와 §2.가 6) S6 전송이 사용

## 바. 박첨지 진행 호스트

본 콘텐츠의 정체성 중심. 유저가 주인공으로 이야기 중심에 서고, 모든 플롯 진행을 박첨지가 해설과 길잡이로 엮음. 공통 골격은 [[시범콘텐츠 공통 사양#6. 진행 호스트]]를 따르고, 아래는 박첨지 고유 페르소나임.

- **역할과 목적**: 떠돌이 노인 해설자와 길잡이, 거리를 잇는 목소리. 유저가 사건 주인공이고 박첨지는 그 여정을 해설하고 안내함(전통 "해설자 겸 주역"의 해설 기능 계승)
- **동작과 규칙(화법)**: 산받이와 관객이 주고받는 재담 양식 ([[덜미의 각본 재미 요소]] 참조). 세부 페르소나(말투, 어휘, 반응 패턴)는 작성 예정
- **자산 요구**: 박첨지 캐릭터 비주얼(시각 정체성 고정, §3.사), 음성과 대사([[시범콘텐츠 공통 사양#6. 진행 호스트]] 에셋 요구 준용)
- **의존**: §3.나와 §3.다 LLM이 박첨지 화법을 적용. 렌더링은 §4.다 클라이언트 UI

## 사. 콘텐츠 자산

본 콘텐츠 제작에 필요한 자산 목록(발주와 견적 입력). 산출 방식과 호스팅은 §4를 따름.

분류별 용도: 캐릭터 레퍼런스와 양식 가이드는 생성 레퍼런스(이미지 모델 conditioning). 운영 영상은 실사용(비출력, 그림동화 미포함). 엔진 입력 서사 데이터(마당 사건 풀, 마당 플롯 풀)는 §3.가 6) 참조.

| 자산 | 분류 (산출물) | 비고 |
|---|---|---|
| 덜미 인형 (전체) | 캐릭터 레퍼런스 | 박첨지와 홍동지 등 전 인형. 상세는 아래 캐릭터 레퍼런스 |
| 유저 주인공 | 캐릭터 레퍼런스 | 연령 × 성별 8종 (§2.가 2) S2) |
| 인형극 시각 양식 가이드 | 양식 가이드 (아트 디렉션 문서와 예시) | 나무 인형 양식(질감, 마감, 색감) 정의, 동화풍 배제 |
| 대기 화면 영상 | 운영 영상 (영상 파일) | 덜미 준비 과정. 제작 방식 확인 필요(실사, 애니, AI) |

### 1) 캐릭터 레퍼런스

- **대상**: 덜미에 등장하는 인형 전부가 시각 정체성 고정(레퍼런스) 대상임. 핵심 인물(박첨지, 홍동지 등)은 시각 정체성을 고정하며, 전 인형으로 확대는 본 프로젝트 내부 결정임. 유저 주인공 8종(§2.가 2) S2)은 별도 자산
- **시각과 서사 분리**: 풍자 대상의 추상화(§3.아)는 서사 차원임. 시각은 원작 덜미 인형을 레퍼런스로 양식을 유지함
- **종수 (미확정)**: 전체 인형 목록과 종수는 확인 필요. [[덜미]]가 현재 주요 6종만 문서화해, 채록본 기준 보강 후 종수를 확정함. 종수 미확정이라 아래 메커니즘과 견적은 잠정이며 인형 목록 확정 후 재산정함
- **산출물 형태 (미확정)**: 참조 이미지 수 장 대 학습셋 수백 장은 일관성 메커니즘에 종속됨(아래 비교표, 아트팀 협의 확정)

캐릭터 레퍼런스를 매 세션 일관 생성하는 방법임. 선택에 따라 위 캐릭터 자산의 산출물 형태와 수량과 공수가 결정됨. 본 콘텐츠는 미정이며 아트팀과 협의해 확정함.

| 메커니즘 | 발주 산출물 | 인물 일관성 | 제작 공수 | 비고 |
|---|---|---|---|---|
| 프롬프트와 스타일 토큰 | 인물별 묘사 프롬프트 + 양식 예시 수 장 | 약함(세션 변동) | 낮음 | 빠르나 정체성 흔들림 |
| IP-Adapter와 참조 이미지 | 인물별 참조 이미지 수 장(정면, 측면, 표정) | 중간 | 중간 | 학습 불필요, 런타임 조건화 |
| LoRA와 파인튜닝 | 인물별 학습 데이터셋 수십~수백 장(태깅) + 학습 | 강함 | 높음 | 인물 수 많을수록 학습 부담 증가 |

## 아. AI 가드레일 (전 단계 횡단)

콘텐츠 정체성과 안전 정책을 정의하고 전 단계에 적용하는 횡단 모듈임.

- **역할과 목적**: 입출력 안전 검사. 가드레일 정책을 전 단계에 공통 적용함. 사전 검수만으로 무인 안전이 닫히지 않으므로 출력 단계에서도 반드시 검사함
- **입력과 출력**: 입력은 검사 대상(사전 플롯 텍스트, 유저 응답, 생성물 서사와 일러스트). 출력은 통과나 위반 판정, 위반 시 재생성이나 차단 트리거
- **동작과 규칙 (적용 3지점, 모두 필수)**:
	- 사전(운영 전 생성): 마당 플롯 질문 생성 검수 (§3.나)
	- 런타임 입력(S3): 유저 응답 검사
	- 런타임 출력(S4): 전자책 생성물(서사, 일러스트) 검사. 검사 항목은 유저 입력 삽입 안전, 전통 정체성 왜곡, 부적절 콘텐츠, 이미지 안전
- **유형별 차단과 추상화**: 마당 유형 4종(§3.가)별로 특정 대상 풍자를 차단하고 추상 대상으로 전환함

| 마당 유형 | 차단 | 추상화 방향 |
|---|---|---|
| 위협-구원형 | 특정 사람과 집단 비방 | 가상의 위협(특정 대상 아님) |
| 권력 풍자형 | 실제 정치인과 공공인물 풍자 | 추상화된 권위 |
| 위선 폭로형 | 특정 실명과 단체 풍자 | 윤리적 위선(남을 속이는 행위 등) |
| 욕심과 다툼형 | 처첩 삼각관계 default 금지 | 재산, 명예, 기회 |

- **안전 체계와 외부 검증**: AI 가드레일과 인트로 동의 약관 절차를 둠. 가드레일 미탐 위험은 외부 검증위원회 자문으로 보완함 ([[rfp_제안요청서#나. 연구 내용]])
- **기술 요건**: 분류와 필터 모델에 자체 규칙을 결합함. 모델 확보는 외부 안전 API나 자체 규칙 우선 검토(후보 확인 필요). 판정 기준은 오탐율, 미탐율, 임계(정량 미정, 확인 필요)
- **자산 요구**: 가드레일 정책 정의, 차단과 추상화 매핑
- **가드레일과 실패**: 위반 시 재생성(한도 §2.나), 한도 초과 시 `failed`로 전환해 에러와 fallback 경로에 합류함(§2.가, §4.다)
- **의존**: AI 모듈 전체(§3.나~라)의 입출력에 공통 적용. 실패 경로는 §2.가와 §4.다
- **세부 정책 (작성 예정)**: 전통 왜곡 판정 기준, 부적절 콘텐츠 분류, 동의 약관 항목 구체화 등

# 4. 공유 계층과 기술 구성

세션, 개인정보, 기술 6영역의 공통 골격은 [[시범콘텐츠 공통 사양]]과 [[플랫폼 사양]]을 참조하고, 본 절은 콘텐츠 고유분만 둠.

## 가. 세션과 데이터

세션 정의와 라이프사이클은 [[시범콘텐츠 공통 사양#2. 세션]]을 따름. 한 유저의 키오스크 사용 전체(S1 시작 → S7 종료)를 감싸는 컨테이너이며, 관리 모듈은 §4.다 백엔드임.

아래는 본 콘텐츠의 세션 저장 데이터임. 콘텐츠 입력은 개인정보가 아니며(그림동화 생성용), 개인정보는 전화번호 단일임. 표는 어떤 값이 들어가는지까지만 적고, 타입과 저장 스키마 같은 구현 모델은 설계 단계에서 정함.

| 데이터 | 분류 | 들어가는 값과 구성 | 수명 | 비고 |
|---|---|---|---|---|
| 세션 ID | 시스템 | 세션마다 부여되는 고유 식별자 | 휘발 (세션 종료 시 파기) | S1에서 생성 |
| 동의 기록 | 시스템 | 약관 버전 + 동의 시각 | 보관 (§4.나, 잠정 5년) | 약관 버전 체계 운영 결정 |
| 캐릭터 정보 | 콘텐츠 입력 | 연령대(아이/청소년/청년/장년), 성별(남/여), 이름 | 확인 필요 (§7 미결) | 8개 카드 = 연령대 × 성별. 유저 주인공 설정 |
| 선택 마당 | 콘텐츠 입력 | 유저가 고른 유형 + 그 유형 풀에서 랜덤 배정된 마당 플롯 | 확인 필요 (§7 미결) | §3.가 4) |
| 거리별 응답 | 콘텐츠 입력 | 거리별(도입/전개/절정/마무리) 유저 응답, 순서대로 누적 | 확인 필요 (§7 미결) | 본편 응답 |
| 박첨지 진행 대화 로그 | 콘텐츠 입력 | 거리별 박첨지 질문 + 유저 응답 쌍 | 보관 (§4.나, 잠정 14일) | 디버깅과 품질 분석용 |
| 그림동화 결과물 | 콘텐츠 입력 | 다중 페이지 결과물 + 메타(생성 시각 등) | 보관 (§4.나, 호스팅 잠정 30일) | 포맷 결정 미정 |
| 전화번호 | 개인정보 | 유저 연락처 (SMS 발송용) | 휘발 (발송 후 즉시 파기, 거부 시 즉시) | S6 전송 동의 시 임시 저장. 상세 §4.나 |

Step별 세션 동작: S1 생성, S2~S6 갱신, S7 종료와 임시 데이터 파기와 리셋.

## 나. 개인정보와 연속성

세션(1회 사용) 개인정보의 공통 원칙은 [[시범콘텐츠 공통 사양#8. 개인정보와 가드레일 원칙]]을 따르고, 아래는 본 콘텐츠 고유분임.

### 1) 개인정보 처리

- **개인정보 범위**: 전화번호 단일(S6 임시 저장). 캐릭터 정보, 응답, 대화 로그, 그림동화 결과물은 콘텐츠 데이터로 개인정보 영역 밖
- **전화번호 처리**: "임시 저장"은 메모리만 쓰고 디스크 영속화와 로그 기록을 금지함. "즉시 파기"는 SMS 발송 응답 수신 직후(성공과 실패 무관) 메모리를 명시적으로 0으로 덮어쓰고 변수를 해제함
- **데이터 보관 기간 (잠정값, 규정 검토 후 확정)**: 동의 기록 5년, 그림동화 결과물 호스팅 30일, 박첨지 대화 로그 14일 (§2.나)
- **동의 미보유 처리**: S1에서 세션이 생성되나 미동의(터치 미입력 타임아웃) 시 세션 전체를 즉시 파기함(동의 기록 미생성)
- **입력 유효성 백엔드 재검증**: S2 이름과 S6 전화번호는 클라이언트 검증 외에 백엔드 재검증을 필수로 함(클라이언트 우회 대비)

### 2) 사용자 모델과 연속성

- **1년차 사용자 모델**: 익명 1회성으로 운영함. 서버 누적은 결과물과 익명 통계뿐임([[플랫폼 사양#5. 사용자 모델 (1년차)]])
- **2차연도 연속성**: 학습 프로필, 이어하기, 콘텐츠 횡단 누적은 2차연도로 둠([[플랫폼 사양#6. 2차연도 전방 설계 (디지털 도제 연속성, 현재 구현 밖)]])

## 다. 기술 구성 (6영역)

콘텐츠 구현 시스템을 [[시범콘텐츠 공통 사양#7. 기술 구성 (6영역 템플릿)]] 6영역으로 정리하고, 아래는 본 콘텐츠 고유분임. AI 시스템 영역의 모듈(마당 플롯 LLM, 유저 입력 가공 LLM, 이미지 생성, 가드레일)과 결과물 조립은 §3 구성 요소에서 다룸.

- **하드웨어 (키오스크)**: 16:9 가로형 디스플레이(터치), 음향 출력(인트로와 배경음), 마이크(S3 거리 응답 STT용), 네트워크 연결. 물리 사양 정본은 [[디바이스 사양]]
- **백엔드**: 키오스크와 AI 서버 통신, 세션 관리, 마당 진행 제어(유형 선택 → 풀에서 랜덤 마당 배정 → 거리 순차 제시, §3.가 4), 결과물 저장소, 고객 동의 약관 관리(버전과 동의 기록). 결과물 조립은 §3.마, 개인정보 처리는 §4.나
- **외부 서비스 연동**: SMS 발송 서비스, AI API(LLM, 이미지 생성), STT 서비스(음성 입력, S3), 결과물 호스팅(전송 링크 방식, 설계 미정)
- **클라이언트 UI (키오스크 앱)**: 페이지 전환과 터치 인터랙션, 화면 흐름(§2.가 S1~S7 구현), 박첨지 진행 호스트 렌더링(§3.바), 입력 UI(가상 키보드와 음성, 카드 선택), 화면 타임아웃과 터치 미입력 타임아웃 처리와 리셋
- **운영과 모니터링**: 공통 항목(가동 상태, 사용 로그, 에러 fallback)은 [[시범콘텐츠 공통 사양#바. 운영과 모니터링]] 준용. 본 콘텐츠 고유로, 가드레일 한도 초과(`failed`) 시에도 에러와 fallback과 같은 경로로 합류함(§3.아)

# 5. 산출물

- **형식**: 2D 일러스트와 텍스트로 묶은 그림동화 전자책. 인형 시각 정체성 유지. 결과물 이미지는 세로 형식이며 화면 방향(가로)과 별개임. 파일 형식(PDF, EPUB, 이미지 묶음)은 미정
- **4D 미연계**: 2D 일러스트와 텍스트 산출물로 한정함. 프로젝트 4D 코어와 분리된 산출물임
- **언어 범위**: 1년차는 한국어 한정. 글로벌 실증은 2차연도 대비 대상
- 세부 규격은 작성 예정

# 6. 일정과 마일스톤 연계

- **개발 순서**: [[1년차 셀빅 개발 준비자료#나. 콘텐츠 개발 순서]]에서 1번(가장 쉬움, LLM과 이미지 생성이며 실시간 동작 없음). 첫 콘텐츠로 공용 시스템을 끌어냄
- 세부 일정과 마일스톤은 미정

# 7. 리스크와 검증

- **외부 검증**: 검증위원회 자문 ([[rfp_제안요청서#나. 연구 내용]])
- **저작권**: 사용자가 저작권 확인을 진행(예정). 덜미 자체는 공유 자산이나 특정 보존회 대본이나 연출 차용 시 권리 확인이 필요함
- **미결 (데이터 수명 정합, 확인 필요)**: 콘텐츠 입력 3종(캐릭터 정보, 선택 마당, 거리별 응답)의 파기 시점이 미정임. 세션 종료 시 임시 데이터로 파기할지, 콘텐츠 결과물처럼 보관할지 [[시범콘텐츠 공통 사양]] 정본과의 정합이 안 됨(§4.가 표에 "확인 필요" 표기). 사용자 결정 대상
- 그 외 리스크와 검증 항목은 작성 예정

## 가. 정체성 매핑 (전통 정합 검증)

전통 재창조 취사 기준(가져갈 것과 버릴 것)이 기획에 빠짐없이 반영됐는지 추적함.

| 원칙 (전통 재창조 취사 기준) | 적용 위치 |
|---|---|
| 박첨지 = 해설자와 길잡이 (전통 "해설자 겸 주역"의 해설 기능 계승) | §3.바 진행 호스트, §3.가 2) 도입과 마무리를 박첨지가 여닫음, 유저가 주인공 |
| 재담과 메타연극성 | 전 거리 박첨지 진행 |
| 풍자 정신 | 4종 유형 풍자 초점 (위협, 권력, 위선, 욕심) |
| 홍동지 응징 카타르시스 | 절정에서 유저가 주도, 홍동지가 힘(위협-구원형), 조롱(권력형), 축출(위선형)로 조력. 욕심과 다툼형은 유저 선택이 가름 |
| 에피소드(거리)식 구성 | 마당 유형 다양성 + 거리 단위 + 내용 변주 |
| 골계적 반전 | 권력 풍자형 절정 (허세의 허망한 추락) |
| 인형극 시각 양식 | §3.사 자산 적용 |
| 고정 줄거리 버림 | 유형 골격만 고정, 풍자 대상과 사건은 유저 입력 변주 |
| 시대적으로 낡은 내용 버림 | 욕심과 다툼형 가드레일 (처첩 default 금지) |
| 연행 규모 버림 | 2시간 2마당 7거리 → 5분 한 마당 4거리 |

전통 재창조 취사 기준의 상세(가져갈 것과 버릴 것의 근거)는 작업 노트에 둠(에이전트 설계 참고).
