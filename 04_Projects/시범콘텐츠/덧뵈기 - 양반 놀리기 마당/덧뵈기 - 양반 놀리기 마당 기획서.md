> 덧뵈기를 소재로, 유저가 견습 말뚝이가 되어 바닥에 투사된 마당 위를 장단에 맞춰 밟고 돌며 큰 동작으로 양반의 허세에 응수해 체면을 무너뜨리고, 체험 중 정해진 시점마다 자동으로 찍힌 사진에서 상위 4컷을 골라 기념 사진으로 받는 바닥 기반 체험 키오스크 콘텐츠의 개발 기획서.

# 1. 개요

- **콘텐츠 정의**: 덧뵈기를 소재로 한 바닥 마당 기반 체험 키오스크 콘텐츠
- **소재**: 남사당놀이 탈놀음 덧뵈기
- **목표 경험**: 유저가 견습 말뚝이가 되어, 바닥에 투사된 덧뵈기 마당 위를 풍물 장단에 맞춰 밟고 돌며 큰 동작으로 양반의 허세에 응수해 그 체면을 무너뜨림. 말뚝이 스승이 놀리는 수를 먼저 시범하고 유저가 따라 익힌 뒤 실전 마당에서 겨룸
- **핵심 메커닉**: 바닥 마당의 놀림 자리를 장단에 맞춰 선점하고 팔과 상체 큰 동작으로 응수하면, 유저 위치와 동작 타이밍을 실시간 채점해 신명 게이지로 보상하고 양반 체면 게이지를 깎으며, 체험 중 정해진 시점마다 자동으로 사진을 찍어 상위 4컷을 남김
- **산출물**: 마당에서 양반을 놀리는 유저의 기념 사진 4컷. 정해진 시점마다 찍은 사진 중 상위 4컷에 말뚝이 탈을 합성하고 마당 배경 연출과 최종 점수 표시를 얹음

# 2. 전체 플로우

1회 완결로 한 마당의 양반 놀리기를 체험하고 기념물을 남기는 세션임. Step 1 인트로 → Step 2 마당 선택 → Step 3 마당놀이(핵심, 베스트샷 자동 선별 포함) → Step 4 기념 사진 생성과 대기(병행) → Step 5 결과물 감상 → Step 6 종료와 리셋.

- **중단 처리**
	- 대상: 진행 중 이탈(그만두기, 터치나 동작 미입력 타임아웃, 약관 미동의)과 실패(기념 사진 생성 실패, 결과물 호스팅 실패, 상태 조회 무응답)가 모두 이 공통 처리로 모임
	- 처리: 마무리 인사 화면을 건너뛰고, 세션을 종료해 파기한 뒤 시작 화면으로 돌아감(비완주 종료). 실패는 상황 안내 팝업을 띄운 뒤 진행하고, 이탈은 팝업 없이 진행함. 세션 생성 실패만 정리할 세션이 없어 종료 처리 없이 곧장 시작 화면으로 되돌림
	- 상세: 케이스별 조건과 처리는 [[#3.10 실패 처리]]와 [[#5.2 에러 케이스]]가 정본
- **병행**: 상태 조회로 동기화
	- Step 4에서 백그라운드 기념 사진 생성과 포그라운드 대기가 동시 진행함
- **파기**
	- Step 6 종료 시 세션 임시 데이터(영상 피드, 위치와 동작 채점 식별 원본) 파기
	- 기념 사진(최대 4장)은 다운로드 호스팅 만료 시 파기함

# 3. 공용 시스템

## 3.1 세션 데이터

### 3.1.1 역할과 목적

한 세션이 만드는 데이터를 담는 시스템. 전 Step이 같은 상태를 공유하게 하고, 데이터 종류별 보관과 파기를 관리하기 쉽게 함.

### 3.1.2 동작과 규칙

세션이 저장하는 데이터를 분류, 값, 보관 기간으로 정리함. 어떤 값이 들어가는지까지만 적고 데이터 타입과 저장 스키마는 설계 단계에서 정함.

| 데이터 | 분류 | 들어가는 값과 구성 | 보관 기간 | 비고 |
|---|---|---|---|---|
| 세션 ID | 시스템 | 세션마다 부여되는 고유 식별자 | 보관 (잠정, 규정 검토 후 확정) | Step 1에서 생성 |
| 현재 언어 | 시스템 | 세션에 적용 중인 언어(기본 한국어) | 보관 (잠정, 규정 검토 후 확정) | 시작 화면 언어 선택에서 설정. 현지화 기준 |
| 현재 Step | 시스템 | 현재 진행 중인 Step | 보관 (잠정, 규정 검토 후 확정) | 진행 단계 기록 |
| 에러 유형 | 시스템 | 에러 발생 시 에러 케이스 유형 기록 | 보관 (잠정, 규정 검토 후 확정) | 디버깅과 품질 분석용 |
| 동의 기록 | 시스템 | 약관 버전, 동의 시각, 동의 항목(필수: 카메라 촬영) | 보관 (잠정, 규정 검토 후 확정) | 약관 버전 체계는 운영 단계에서 결정함 |
| 선택 마당 | 콘텐츠 입력 | 유저가 고른 놀리기 마당 식별자(그 마당의 각본과 놀림 자리, 놀리기 동작 세트를 가리킴) | 보관 (잠정, 규정 검토 후 확정) | Step 2 산출. 식별자만 저장(각본은 사전 배포) |
| 놀리기 채점 기록 | 콘텐츠 생성 | 위치 정확도와 리액션 타이밍 점수, 신명 게이지, 양반 체면 게이지 | 익명 통계는 보관, 식별 원본은 세션 종료 시 파기 | Step 3 산출 |
| 베스트샷 후보 | 콘텐츠 생성 | 마당 타임테이블 시점마다 찍은 프레임과 영역 변화량 점수(상위 최대 4컷 선별) | 메모리 임시, 생성 트리거 후 파기 | Step 3 산출. 얼굴과 신체 포함. 디스크 저장 금지 |
| 기념 사진 | 콘텐츠 생성 | 베스트샷(최대 4컷)에 말뚝이 탈을 합성하고 마당 연출과 최종 점수 표시를 얹은 결과물(통과분 최대 4장) | 호스팅 만료 시 파기 (다운로드 제공 기간 48시간, 잠정) | Step 4 산출. 얼굴과 신체 포함 |
| 다운로드 URL | 콘텐츠 생성 | 기념 사진(최대 4장) 다운로드 페이지 주소(만료형) | 호스팅 만료까지 유지 | Step 4에서 발급, Step 6이 QR로 인코딩 |
| 영상 피드 | 콘텐츠 입력 | 카메라 원본 스트림(사람 분리와 위치 추정, 포즈 추정, 베스트샷 캡처 입력) | 메모리 임시, 처리 직후 파기 | 디스크 저장 금지. 얼굴과 신체 포함 |

- **Step별 세션 동작**
	- Step 1 생성, Step 2~Step 5 갱신, Step 6 종료와 임시 데이터 파기와 리셋
- **서버 전송 시점 (이벤트 기반)**: 각 화면의 세션 데이터 갱신은 클라이언트 로컬 상태에만 반영하고, 서버로는 정기 전체 동기화 없이 이벤트 시점에만 전송함. 이어하기가 없는 1차연도 기준임
	- 단계 이동: 각 Step 진입과 종료 시 현재 Step을 전송함
	- 동의 기록: 이용 동의 화면에서 동의 확정 시 동의 이벤트(약관 버전, 동의 시각, 동의 항목)를 전송함
	- 에러와 이탈: 에러 발생 시, 이탈(약관 미동의, 미입력 타임아웃 종료) 시 전송함
	- 생성 입력: 선택 마당 식별자는 Step 2 확정 시 서버 세션에 반영하고, 베스트샷(최대 4컷)은 기념 사진 생성(Step 4) 트리거 시점에 서버로 전송함
	- 결과물: 기념 사진(통과분, 최대 4장)과 다운로드 URL은 생성 완료 시 서버 세션에 반영함

## 3.2 개인정보 처리

### 3.2.1 역할과 목적

유저 얼굴과 신체가 담긴 데이터를 다루는 시스템. 쓰임이 끝난 촬영 데이터를 즉시 파기해 유출 위험을 낮춤.

### 3.2.2 동작과 규칙

세션이 다루는 개인정보를 개발이 지킬 구현 제약과 규정 검토가 확정할 정책 값으로 나눠 정리함. 프로그래머는 구현 제약을 스펙으로 지키고, 규정 검토 대기 항목은 검토 결과가 나오면 값을 채움.

#### 1) 구현 제약

- **개인정보 범위**: 어느 데이터가 민감정보라 메모리 전용으로 다뤄지는지 가르는 분류임
	- 얼굴과 신체 영상(영상 피드. 사람 분리와 위치 추정, 포즈 추정, 베스트샷 캡처에 쓰임)
	- 베스트샷 후보 프레임(마당 타임테이블 시점마다 찍은 얼굴과 신체가 담긴 프레임. 메모리 임시)
	- 기념 사진(통과분, 최대 4장. 분류는 콘텐츠 생성이지만 얼굴과 신체가 담긴 결과물이라 개인정보로 함께 다룸)
- **카메라 동의 게이트**: 카메라 촬영(사람 분리와 위치 추정, 포즈 추정, 베스트샷 캡처)이 필수 동의임. 동의가 없으면 촬영과 채점, 베스트샷을 할 수 없어 세션을 진행하지 않음(Step 1 이용 동의, 진행 중 종료의 미동의 처리와 연결)
- **영상 피드 처리**: 메모리에서 임시로 처리한 뒤 즉시 파기하고, 디스크에 저장하거나 로그로 기록하지 않음
- **결과물 전달**: 화면 QR로 익명 다운로드함

#### 2) 규정 검토 대기

- **동의 고지 문구**: 기념 사진(최대 4장)은 얼굴과 신체가 담긴 결과물이라, 만들고 저장하며 다운로드로 48시간(잠정) 제공하는 처리를 개인정보 수집과 이용 안내에 포함함. 제공 컷 수만큼 저장 결과물이 늘어나 동의 문구에 장수를 반영함. 정확한 안내 문구와 동의 범위는 규정 검토 후 확정함
- **보관 기간**: 잠정값은 규정 검토 후 확정함
- **재방문 연속성**: 학습 프로필, 이어하기, 학습 토큰, 콘텐츠 진행 결과 누적은 2차연도 확장 설계로 두며 1차연도는 익명 1회로 운영함

## 3.3 언어 선택 시스템

### 3.3.1 역할과 목적

세션 전체에 적용할 언어를 정하는 관문. UI 카피와 말뚝이 스승과 양반 대사, 안내 팝업을 유저가 고른 언어로 제공해, 다른 언어를 쓰는 유저도 자기 언어로 마당놀이를 체험할 수 있도록 함.

### 3.3.2 입력과 출력

- **입력**: 유저의 언어 선택
- **출력**: 현재 언어(세션 데이터에 저장). 현지화 JSON(localization.json)에서 해당 언어값을 불러옴

### 3.3.3 동작과 규칙

- 유저가 언어를 선택하고 시작하기 버튼을 터치하면 현재 언어로 반영함. 기본값은 한국어임
- **현지화 범위**: UI 카피, 말뚝이 스승과 양반 대사와 TTS 음성, 안내 팝업을 현재 언어로 제공함. 최종 점수는 언어 중립 값이라 기념 사진 이미지에 텍스트로 새겨 넣고 현지화하지 않음. 지원 언어는 한국어와 영어를 우선 적용함
- **재담 현지화 한계**: 덧뵈기 재담은 말장난과 말맛에 기대 직역이 어려움. 대사는 뜻과 풍자 의도를 옮기는 의역으로 제공하고, 놀리기 수의 원리(허세 들추기, 말꼬리 잡기)가 전달되게 함. 번역 문안 확정은 콘텐츠 문안 단계에서 함(작성 예정)

## 3.4 말뚝이 진행 호스트

### 3.4.1 역할과 목적

양반을 놀리는 탈춤 풍자의 화자 말뚝이를 스승 역할의 세션 진행 호스트로 세운 시스템. 시범과 재담으로 유저(견습 말뚝이)의 놀리기를 이끌어 덧뵈기의 재담과 풍자 정체성을 살림. 대사 인식이나 발화 채점은 없음.

### 3.4.2 동작과 규칙

- **범위**
	- 전 세션 호스트
- **발화 방식**
	- TTS 음성으로 대사를 재생하고 같은 대사를 화면에 텍스트로 표시함
	- 대사와 화면 텍스트는 세션의 현재 언어로 제공함(TTS도 현재 언어로 합성)
	- 발화 중 동작 애니메이션(입 모양 포함)을 재생함
- **입 모양**
	- 립싱크는 맞추지 않고 사전 생성한 입 움직임 애니메이션을 발화 중 재생함
- **재생 컨트롤러**
	- 동작 애니메이션 재생과 동시에 TTS 오디오를 재생하고 그 길이만큼 입 애니메이션을 루프
	- 립싱크가 없어 음소 정렬은 불필요
- **스킵**
	- 발화 중 다음 버튼을 누르면 발화를 중단하고 다음으로 진행함
- **타임아웃**
	- 발화 중에는 터치 미입력 타임아웃을 멈추고, 발화가 끝난 뒤 시간 체크 시작
- **양반 대사 연동**: 실전 마당에서 양반(샌님 등 놀림 대상)의 도발 대사도 같은 발화 방식으로 재생함. 양반 대사는 놀리기 채점의 반응 창을 여는 신호와 함께 연출함
- **대사 적용**
	- 적용 방법 논의 후 추가 예정

### 3.4.3 필요 리소스

- 말뚝이 스승 캐릭터(덧뵈기 양식, 2D, 애니메이션 가능하게 제작, 기념 사진의 말뚝이 탈 양식과 시각 정체성 일치)
- 양반(놀림 대상) 캐릭터(마당별 대상. 시각 정체성 고정, 제작 방식 확인 필요)
- 동작 애니메이션 세트(대기, 인사, 말하기, 시범, 제스처)
- 말뚝이 스승과 양반 TTS 보이스(지원 언어별 확보 필요)
- 추임새와 재담 대사(제작 방식 확인 필요)

### 3.4.4 실패와 복구

아바타 렌더나 TTS 재생이 실패하면 음성과 애니메이션 없이 대표 이미지와 텍스트 박스로만 진행함. 대사는 표시하고 세션은 계속함.

## 3.5 진행 중 종료

### 3.5.1 역할과 목적

유저에게 진행 중 그만둘 수단을 주는 시스템. 원치 않는 세션을 빨리 끝내 키오스크 회전율을 높임.

### 3.5.2 동작과 규칙

#### 1) 일반 규칙

- **처리**
	- 진행 중인 화면을 멈추고 마무리 인사 화면을 건너뛰어 세션 종료와 파기 후 시작 화면으로 복귀함(비완주 종료)

#### 2) 유저의 종료 선택 시 규칙

- **처리**
	- 그만두기 터치 시 그만두기 확인 팝업 표시
	- 확인 시 종료 처리하고, 취소 시 원래 화면 복귀
- **적용 화면**
	- Step 1 가이드 화면, 이용 동의 화면
	- Step 2 마당 선택 화면
	- Step 3 마당놀이 화면
	- Step 5 결과물 감상 화면
- **예외 (미적용)**
	- Step 1 시작 화면
	- Step 4 대기 화면 (작업이 도는 중이라 이탈로 보지 않음)
	- Step 6 마무리 화면 (화면 타임아웃으로 넘김)
- **그만두기와 동시 이벤트 처리 (마당놀이 화면)**: Step 3에서 그만두기가 채점이나 타임아웃과 겹칠 때의 규칙임
	- 확정된 그만두기는 진행 중인 채점 루프와 베스트샷 캡처, 생성 전환을 취소하고 세션 종료로 감
	- 확인 팝업이 열린 동안에는 터치나 동작 미입력 타임아웃과 사람이나 포즈 미검출 측정을 멈춤(말뚝이 발화 중 멈춤과 같은 방식)
	- 종료는 한 번만 처리해 이중 종료를 막음

#### 3) 미동의 시 규칙

- **처리**
	- 이용 동의 화면에서 그만두기를 확정하거나 터치 미입력 타임아웃이 발동하면 약관 미동의로 보고 종료 처리
	- 카메라 촬영 동의가 없으면 위치와 동작 채점, 베스트샷 캡처를 할 수 없어 세션을 이어 갈 수 없음

## 3.6 화면 타임아웃

### 3.6.1 역할과 목적

유저가 한 화면에 오래 머무는 것을 막아, 무인 키오스크가 한 유저에게 묶이지 않게 하는 시스템.

### 3.6.2 동작과 규칙

- **처리**
	- 한 화면에서 60초(잠정) 이상 머물면 그 화면의 정상 진행 경로로 넘어감
	- 화면별 오버라이드: 마당놀이 화면 5분(잠정), 결과물 감상 화면 5분(잠정). 마당 선택 화면과 마무리 인사 화면은 기본값(60초, 잠정) 적용(마무리 인사 화면은 처음으로 버튼이 주 종료)
- **작업 상태**
	- 유저 선택 상태가 있으면 세션에 확정 저장한 뒤 진행함(선택 마당. 기본 마당이 사전 선택돼 있어 항상 값이 있음). 없으면 바로 다음으로 진행함
- **예외**
	- 필수 입력, 호스트 대화, 가이드, 대기, 팝업 화면 미적용

## 3.7 터치 미입력 타임아웃

### 3.7.1 역할과 목적

입력이 끊긴 유저 이탈을 감지해 방치된 세션을 정리하고 키오스크 회전율을 높이는 시스템.

### 3.7.2 동작과 규칙

- **처리**
	- 한 화면에서 45초(잠정) 이상 터치나 동작 입력이 없으면 이탈로 보고 진행 중 종료 처리
	- 카메라와 모션 화면(마당놀이)은 터치가 없는 화면이라 사람이나 포즈 미검출을 이탈 기준으로 삼음
	- 말뚝이 발화 중에는 측정을 멈추고, 발화가 끝나거나 스킵한 뒤부터 측정 시작
- **예외**
	- 대기 화면, 감상 성격 화면(결과물 감상), 마무리 인사 화면 미적용. 마무리 인사 화면은 완주 뒤 화면이라 화면 타임아웃이 주 종료임(터치 미입력을 이탈로 보지 않음)

## 3.8 AI 가드레일

### 3.8.1 역할과 목적

사전 제작 자산과 생성물의 안전과 전통 정합성을 검사하는 시스템. 유해하거나 전통을 왜곡한 콘텐츠가 유저에게 노출되지 않도록 막음.

### 3.8.2 동작과 규칙

#### 1) 적용 지점

전통 왜곡과 정합성 판정 기준은 마당과 놀리기 동작 고증을 따름. 유저가 이미지나 자유 텍스트를 만들지 않아(마당 선택과 몸동작 입력) 런타임 입력 검사는 두지 않고, 결과물 생성 검사만 둠.

- **사전(운영 전 제작)**: 마당 각본과 재담, 놀림 대상 캐릭터, 놀리기 동작 레퍼런스, 말뚝이 대사 등 사전 제작 자산 검수
- **런타임 출력(Step 4)**: 생성 기념 사진(장 단위) 검사

#### 2) 위반 시 처리

- **출력 위반 검출**: 재생성 한도 2회(잠정)까지 다시 만들고, 한도를 넘기면 위험 생성물을 파기하고 중단 처리함

검사 호출 자체가 실패하는 경우(위반 검출이 아님)는 실패와 복구에서 다룸.

#### 3) 풍자 추상화 (사전 검수 지향)

양반 풍자 특성상 권력과 위선을 다루되 특정 실존 대상으로 흐르지 않게 사전 제작 각본과 재담을 추상화함. 사전 자산 검수에서 성별, 지역, 종교 등 혐오 조장과 특정 실존 인물이나 단체를 겨눈 풍자를 걸러내고, 골계는 권위의 허망한 추락으로 향하게 함. 런타임 생성물(기념 사진)은 유저 얼굴과 마당 연출 합성이라 이 검사 대상이 아니며, 이미지 안전과 전통 정합성으로만 검사함.

### 3.8.3 기술 요건

- **모델 확보 (결정 필요)**
	- 범용 유해물은 외부 안전 API로 거르고, 전통 정체성 왜곡처럼 범용 API가 못 잡는 판정은 자체 규칙이나 도메인 분류기로 보완함
	- API 대 자체 구축 비중은 후보 조사 후 확정
- **판정 기준**
	- 기념 사진(이미지)을 검사하므로 이미지 모더레이션이 필요함. 마당 각본과 재담은 사전 검수 자산이라 런타임 텍스트 검사는 두지 않음
	- 무인 운영이라 미탐(유해물 통과)이 오탐보다 위험하므로 미탐을 낮추는 보수적 임계로 잡음
	- 오탐률과 미탐률, 임계 목표는 검증 데이터 확보 후 정량 확정
- **적용**
	- 런타임 서버 호출. 출력 검사는 유저 대기 구간이라 검사 응답 지연 상한이 필요함(정량 미정)

### 3.8.4 실패와 복구

가드레일 자신이 실패하는 경우를 다룸. 검사 결과가 위반으로 나오는 것은 실패가 아니라 정상 동작이며, 그 처리는 위 동작과 규칙에 있음.

- **출력 검사 호출 실패**
	- 통과로 보지 않으며 외부 서비스 호출 래퍼로 재시도(2회 잠정)해도 실패하면 그 장을 기념 사진 생성 파이프라인에서 탈락시킴
	- 재생성 한도 초과와는 원인이 달라(생성물이 계속 위반 대 검사 서비스 장애) 세션 데이터의 에러 유형에 따로 기록함
- **검사 서비스가 오래 죽어 있는 경우**
	- 생성분이 전량 탈락하면 기념 사진 생성 파이프라인을 `failed`로 보내고 중단 처리함
	- 출력 검사 호출 실패를 운영 알림 대상으로 두어, 장애를 조기에 알아채게 함

## 3.9 외부 서비스 호출 래퍼

### 3.9.1 역할과 목적

외부 서비스 호출(AI, 이미지 생성, 결과물 호스팅, TTS)을 감싸는 공통 계층. 재시도와 타임아웃 대응을 한 곳에 모아, 호출마다 장애 처리를 따로 짜지 않게 함.

### 3.9.2 동작과 규칙

- **재시도 횟수**
	- 2회(잠정). 백오프는 1차 1초, 2차 3초(잠정)
- **호출 타임아웃**
	- TTS 30초, 가드레일과 이미지 생성, 결과물 호스팅 60초(모두 잠정)
- **한도 초과**
	- 재시도 한도를 넘긴 실패는 실패 처리로 넘김

## 3.10 실패 처리

### 3.10.1 역할과 목적

런타임 실패의 처리 정책. 무인 운영에서 실패가 방치되지 않게 함.

### 3.10.2 동작과 규칙

- **처리 갈래**: 실패가 세션을 어떻게 만드는지로 셋을 나눔
	- **재입력**: 유저 입력만 다시 받으면 이어 감. 이 콘텐츠는 유저 생성 입력(도안, 자유 텍스트)이 없어 1차연도에는 해당 케이스가 없음(마당 선택과 몸동작은 가드레일 검사를 두지 않음). 공통 taxonomy 유지를 위해 갈래는 남겨 둠
	- **기능 축소**: 보조 기능이 빠져도 체험이 남음. 그 기능만 빼고 세션을 이어 감. 포즈나 위치 미검출 구간의 채점 보류와 말뚝이 발화 실패가 여기 속함
	- **중단**: 핵심 생성(기념 사진)이나 결과물 전달(호스팅)이 실패해 기념물이 남지 않음
- **대체 입력 갈래를 두지 않는 이유**: 유일한 입력 수단이 카메라와 터치라 대체할 다른 수단이 없음. 음성 입력을 쓰는 생성형 콘텐츠와 다른 점임
- **중단 공통 처리**: 상황 안내 팝업을 띄우고 비완주 종료라 마무리 인사 화면을 건너뛰어 세션 종료와 파기 후 시작 화면으로 자동 진행함. 별도 실패 화면을 두지 않고 전달하지 못한 미완성이나 위반 생성물을 파기함
	- 예외: 세션 생성 실패는 정리할 세션 자체가 없어 종료 처리도 거치지 않고 곧장 시작 화면으로 되돌림
	- 생성 파이프라인의 중단은 `failed` 상태 하나로 모으고, 어느 단계에서 났는지는 세션 데이터의 에러 유형에 남김
	- 실패 시점: 호스팅을 Step 4에서 끝내므로 유저는 결과물을 보기 전에 실패를 알게 됨
- **운영 알림**: 원인이 외부 서비스나 시스템이면 보내고, 유저면 보내지 않음(알림 채널 미정)

## 3.11 마당과 놀리기 고증 (공통 레퍼런스)

### 3.11.1 역할과 목적

놀리기 마당과 그 놀림 자리, 놀리기 동작의 기준을 정의하는 설계 레퍼런스. 마당 선택 목록과 위치 채점, 놀리기 채점, 가드레일이 함께 참조해 전통 정합성을 한 기준으로 맞추게 함.

### 3.11.2 동작과 규칙

- **놀리기 마당**: 덧뵈기 네 마당 중 놀림이 축인 마당을 제공함. 소재 변환본(`03_References/converted/남사당놀이/남사당놀이 - 덧뵈기.md`) 기준 샌님잡이(샌님, 곧 양반 놀리기), 옴탈잡이(꺽쇠가 옴탈을 놀림), 먹중잡이(취발이가 파계승 먹중을 놀림)를 후보로 둠. 실제 제공할 마당과 종수는 정함(확인 필요, 고증 자문). 1차연도 대표 마당은 양반 놀리기인 샌님잡이임
- **놀림 대상 배역**: 마당별 놀림 대상(샌님, 옴탈, 먹중)과 그 도발 대사, 무너지는 골계 반전을 각본으로 둠. 소재의 재담(예: 샌님의 지체 자랑과 말뚝이의 말대꾸)을 근거로 함
- **바닥 마당과 놀림 자리**: 덧뵈기는 멍석 위 원형 마당놀이라, 바닥 프로젝션 2m×2m를 마당(놀이판)으로 투사하고 놀림 자리와 이동 경로, 피하기 구역을 바닥에 표시함(소재 놀이판 구조 근거). 마당별 놀림 자리 배치와 이동 각본은 작성 예정(고증 자문 연계)
- **놀리기 동작 세트**: 마당별 놀리기 큰 동작 세트와 풍물 장단의 고증 매핑(작성 예정, 고증 자문 연계). 덧뵈기 전승 춤사위 3종(나비춤, 닭이똥 사위, 피조리춤)과 소재의 놀리기 몸짓(절하다 뒤집기, 뒤로 휙 돌기 등)을 코어로 두고, 팔과 상체 큰 동작 중심으로 세움(전신 싱글 카메라가 손목까지 인식하는 범위와 정합). 위치 채점과 놀리기 채점의 기준이 됨
- **시각 정체성**: 마당 배경 연출과 탈 양식, 질감의 전통 정합성 유지(작성 예정). 한국 탈춤 탈 양식을 유지하고 일본 노멘이나 중국 가면과 혼동하지 않음

	- 서버로 신규 세션 생성 요청

	- 분기: 세션 생성 실패 시 재시도(2회 잠정) 후 상황 안내 팝업 → 시작 화면 복귀

#### 1) 진행

	- 분기: 미입력 타임아웃 → 약관 미동의로 종료 처리
	- 분기: 그만두기 선택 시 확인 팝업 → 확정 시 종료 처리

## 4.2 Step 2. 마당 선택

### 4.2.1 클라이언트: 마당 선택 화면

#### 1) 진행

- 사전 제작한 놀리기 마당 목록을 보여줌. 유저가 마당을 고르거나 기본 선택을 그대로 두고 확정하면 다음 단계로 진행함
	- 분기: 화면 타임아웃(기본 60초, 잠정) → 현재 선택 마당을 확정하고 다음 단계로 정상 진행
	- 분기: 미입력 타임아웃 → 종료 처리
	- 분기: 그만두기 선택 시 확인 팝업 → 확정 시 종료 처리

#### 2) 마당 선택 목록

##### (1) 역할과 목적

유저가 체험할 마당 하나를 고르는 선택 도구. 전통 마당과 놀림 대상을 그대로 제공해, 전통 정합성을 유지하면서 유저가 자기 마당을 정하게 함.

##### (2) 동작과 규칙

- **목록 구성**: 사전 제작한 놀리기 마당 전체를 목록에 담음. 제공 마당과 종수, 목록 순서는 마당과 놀리기 고증에서 확정함
- **기본 선택**: 진입 시 목록 첫 번째 마당을 기본 선택으로 둠(목록 순서가 기본 마당을 정함)
- **미리보기**: 선택한 마당의 놀림 대상과 놀리는 수 소개를 보여줌(표시 형태는 확인 필요)

##### (3) 필요 리소스

놀리기 마당 세트(마당별 각본과 놀림 자리 배치, 놀리기 동작 세트, 놀림 대상 캐릭터, 소개 문구)를 사전 제작함.

### 4.2.2 서버: 선택 마당 저장

#### 1) 진행

- 세션에 선택 마당 식별자를 저장함. 유저 생성물이 없어 가드레일 입력 검사는 두지 않음

## 4.3 Step 3. 마당놀이 (핵심 체험)

### 4.3.1 클라이언트: 마당놀이 화면

바닥에 마당(놀이판)을 투사하고 정면 화면에 놀림 대상 양반을 세워, 유저가 마당 위를 움직이며 양반을 놀림. 카메라는 2m 거리 전신 구도로 위치와 큰 동작을 잡음. 유저 얼굴에 탈을 실시간으로 덧씌우는 증강현실(AR)을 두지 않아, 근거리 얼굴 구도가 필요 없어 전신 구도를 온전히 씀.

#### 1) 진행

1. 말뚝이 스승이 이번 마당의 놀리는 수를 바닥 시범과 재담으로 가르침(따라 하기 도입)
2. 실전 마당: 양반이 도발 대사로 허세를 부리면 바닥에 놀림 자리가 뜨고, 유저가 그 자리를 장단에 맞춰 선점하고 팔과 상체 큰 동작으로 응수함. 유저 위치와 동작을 채점하며, 동시에 마당 타임테이블 시점마다 사진을 찍어 둠(뒤에 영역 변화량 순위로 상위 4컷 선별)
3. 말뚝이 스승이 추임새로 결과를 연출함(양반 체면이 무너지면 환호 사운드 보상, 미달 시 눙치는 마무리)
	- 분기: 그만두기 선택 시 확인 팝업 → 확정 시 종료 처리
	- 분기: 화면 타임아웃(마당놀이 화면 5분, 잠정) → 체류 상한으로 보고 Step 4로 정상 진행
	- 분기: 사람이나 포즈 미검출이 터치 미입력 타임아웃 임계를 넘기면 이탈로 보고 종료 처리
	- 분기: 위치나 포즈 미검출이나 저신뢰 시 해당 채점 단위는 게이지가 오르지 않는 것으로 보류하고, 화면을 끊는 팝업 대신 비모달 가이드(바닥 자리 하이라이트, 말뚝이 추임새)로 안내함. 채점은 다음 단위로 계속함

#### 2) 위치와 놀리기 채점, 신명 게이지

##### (1) 역할과 목적

유저가 마당 위를 움직이며 양반을 놀린 수행에 즉각 피드백을 주는 핵심 루프. 유저 위치와 동작 타이밍을 실시간으로 채점해 신명(興) 게이지와 양반 체면 게이지로 보여주고, 양반의 체면을 무너뜨리면 보상해 체험의 성취감을 줌.

##### (2) 입력과 출력

- **입력**: 카메라 영상 프레임(사람 분리와 위치, 포즈 키포인트), 풍물 장단과 양반 도발 타이밍
- **출력**: 유저 마당 위치, 포즈 키포인트, 위치 정확도, 리액션 타이밍과 진폭 점수, 신명 게이지 값, 양반 체면 게이지 값, 놀리기 채점 기록

##### (3) 동작과 규칙

- **채점 입력**: 놀림 자리 선점의 위치 정확도(유저가 제때 맞는 자리에 섰나)와 응수 큰 동작의 장단 대비 타이밍과 진폭
- **채점 방법**: 바닥 마당 좌표에서 유저 위치(뎁스 카메라 사람 분리와 위치 추정, 저가 라이다 보조)를 구역 단위로 판정하고, 유저 포즈에서 뽑은 포즈 키포인트(스켈레톤)로 응수 큰 동작의 타이밍과 진폭을 판정함. 이 스켈레톤 대비 방식은 주관 기관 Qlab 「댄스 마스터」가 플레이어와 트레이너의 스켈레톤을 실시간 비교하는 사례를 참고함(외부 참고, L4)
- **채점 기준**: 위치 정확도와 리액션 타이밍, 진폭을 가중 합산해 판정함. 위치 허용 반경과 반응 창(양반 도발부터 응수까지 허용 시간), 축별 가중치는 개발 단계에서 실제 인식 성능을 보고 정함(정량 미정). 어떤 방식으로 잴지 정하기 전에 수치를 먼저 박지 않음
- **두 게이지와 보상**: 채점이 쌓이면 신명 게이지가 오르고 양반 체면 게이지가 깎임. 양반 체면이 무너지는 임계를 넘기면 환호 사운드(군중 추임새, 박수)로 보상하고, 미달 시 말뚝이가 눙치며 마무리함. 두 게이지의 임계는 개발 단계에서 정함(정량 미정)
- **난이도 상승**: 마당이 진행될수록 양반 도발이 빨라지고 놀림 자리 이동 폭이 커짐(소재의 장단 몰아가기 구조 반영). 난이도 곡선은 개발 단계에서 정함(정량 미정)
- **종합 점수 출력**: 신명 게이지 종합 점수를 최종 점수로 확정해 Step 4에 넘기고, Step 4 기념 사진 생성이 그 값을 각 장에 표기함
- **학습 진척**: 1차연도는 당회 채점만 함. 재방문 진척 누적(향상 곡선, 약점 수 피드백)은 2차연도 확장 설계로 둠
- **세부 설계 (작성 예정)**: 가중치, 두 게이지 임계, 미달 처리, 반응 창

##### (4) 기술 요건

- **모델 확보**: 실시간 포즈 추정과 사람 위치 추정은 사전학습 모델과 온디바이스 SDK를 우선 검토함(후보 확인 필요). 바닥 위치는 뎁스 카메라 사람 분리와 저가 라이다 보조를 씀. 채점 로직은 각본의 놀림 자리와 놀리기 동작 대비 자체 규칙. 주관 기관 Qlab 「댄스 마스터」(스켈레톤 실시간 비교 엔진) 자산의 재사용이나 라이선스와 자체 구현을 함께 열어 두고 개발 규모를 보고 확정함(확인 필요)
- **판정 기준**: 사람 위치 추정과 포즈 추정 정확도, 채점 임계와 가중치, 실시간 처리 지연(프레임률). 채점 정확도 검증 방법은 확인 필요
- **적용**: 실시간 처리. 온디바이스 처리를 우선 검토함(「댄스 마스터」가 키오스크 로컬 GPU에서 실시간 채점하는 사례 참고, L4). 서버 처리는 대안으로 둠. 모션 인식은 전신 싱글 카메라 기준 손목까지가 현실적이라 놀리기 동작을 팔과 상체 큰 동작으로 설계함. 덧뵈기 전승 춤사위가 팔 중심(상체 위주)이라 이 범위와 방향이 맞음
- **선결 과제 (바닥 위치 센싱)**: 이 콘텐츠는 유저의 바닥 위치를 실시간으로 판정하는 게 핵심이라 개발 착수 1순위 검증 대상임. 뎁스 카메라 사람 분리와 저가 라이다는 사람 위치 분할이 본래 용도라 구역 단위 위치 판정은 가능하나, 놀림 자리 선점을 발끝 단위로 정밀 판정하려면 바닥 투사면과 센서 좌표의 정합(캘리브레이션) 검증이 필요함. 발끝 정밀 히트가 어려우면 놀림 자리를 발 주변 링이나 구역으로 넓혀 구역 단위로 설계함
	- **검증 항목(통과와 실패 기준)**: 바닥 좌표와 센서 좌표의 정합 오차, 유저 위치 추정의 구역 판정 정확도와 지연, 다수 구역 배치 시 인접 구역 오판율. 목표값은 개발 단계에서 실제 인식 성능을 보고 정함(정량 미정)
	- **바닥 가림 대응**: 유저가 바닥 투사 위에 서면 발밑 표적이 자기 몸그림자에 가려짐. 놀림 자리를 발밑 점이 아니라 발 주변 링이나 화면 정면 표시와 병행해 가림에 강하게 설계함
	- **하드웨어 공유 이점**: 바닥 프로젝션과 위치 센싱은 택견 스텝(품밟기) 위치 표시와 같은 하드웨어를 씀. 바닥 좌표 정합과 위치 판정 개발을 두 콘텐츠가 공유할 여지가 있음
- **데이터**: 놀리기 동작 모션 레퍼런스와 마당별 놀림 자리 배치가 채점 기준 데이터임(국가유산청 공식 기록영상 활용이나 모캡 등 확보 방식 확인 필요, 고증 자문)

##### (5) 필요 리소스

- 놀리기 동작 모션 레퍼런스(따라 하기 대상과 채점 기준, 마당별 동작 세트, 모캡이나 기록영상 확인 필요, 고증 자문)
- 마당별 바닥 놀림 자리와 이동 경로 배치 데이터
- 풍물 장단 음원(타이밍 기준, 무저작권이나 자체 제작, AI 생성)
- 양반 도발 대사와 환호, 추임새 사운드(게이지 결과 연출과 보상, 제작 방식 확인 필요)

##### (6) 실패와 복구

위치나 포즈가 안 잡히거나 신뢰도가 낮으면 재시도를 안내함(한도 3회, 잠정). 한도를 넘기면 해당 채점 단위의 점수를 보류하고 다음 단위로 진행함(채점 루프는 계속). 인식이 지연될 때도 그 단위의 점수를 보류함. 채점 단위(놀림 자리 하나인지 응수 하나인지 등)는 채점 방식과 함께 개발 단계에서 정함. 사람이나 포즈 미검출이 터치 미입력 타임아웃 임계를 넘기면 진행 중 종료로 감.

#### 3) 베스트샷 자동 선별

##### (1) 역할과 목적

체험 중 별도 촬영 단계 없이 기념물 원본을 확보하는 엔진. 유저가 가장 활발히 논 순간을 기념 사진 재료로 남김.

##### (2) 동작과 규칙

- **촬영 시점 (타임테이블)**: 마당별 타임테이블이 지정한 시점마다 프레임을 캡처함. 마당마다 놀리기 진행이 달라 타임테이블도 마당별로 둠. 상시 스트림이 아니라 시점 기반이라 어떤 놀림 대목이 담겼는지 특정됨
- **주체 선정 (누구를 담을지)**: 세션 시작 시 화면의 모든 사람을 사각형(바운딩 박스)으로 잡고, 각 촬영 시점에 박스 영역 변화량이 가장 큰 사람(가장 활발히 움직인 참가자)을 골라 그 사람 이미지를 캡처함. 마당 밖 구경꾼이 아닌 활성 참가자가 담김. 세부 알고리즘은 타 콘텐츠 기구현 방식을 따름
- **순위와 선별**: 촬영분을 영역 변화량 내림차순으로 정렬해 상위 4컷만 기념 사진 생성(Step 4)으로 넘김. 타임테이블 시점이 4곳을 넘어도 이 정렬로 4컷을 추림. 각 컷이 서로 다른 시점이라 컷 간 시간 간격은 자연히 확보됨
- **컷 수 (상한)**: 상위 4컷을 상한으로 둠(정확히 4컷을 채워야 하는 건 아님). 상한을 안정적으로 채우려면 촬영 시점이 4곳보다 넉넉해야 하므로, 마당별 타임테이블 시점을 4곳 이상 여유 있게 정의함(정확한 수는 개발 단계 확정)
	- 완주 시 상위 4컷이 대개 채워짐. 시점이 4곳 미만이거나 유저가 일부만 지나면 1~3컷만 남음. 4컷이든 1~3컷이든 예외가 아니라 정상 완료로 Step 4로 넘김(감상과 다운로드는 통과분만큼만 노출)
	- 촬영 시점을 하나도 지나지 않고 이탈하면 캡처가 없어(0컷) 이탈 종료로 감(기념물 없음). 0컷은 Step 4에 도달하지 않음
- **채점 루프와 공유**: 위치와 놀리기 채점과 같은 카메라 프레임 스트림과 인물 검출을 공유해 추가 카메라 파이프라인을 두지 않음. 순위는 영역 변화량이라는 자체 지표로 매기며 위치와 놀리기 채점 점수와는 별개임
- **미검출 처리**: 촬영 시점에 사람이 잡히지 않으면 그 시점은 건너뜀(캡처 없이 다음 시점으로). 최종 품질 게이트는 생성 단계와 출력 가드레일임
- **세부 설계 (작성 예정)**: 마당별 타임테이블 시점 정의(놀리기 각본과 연계)

##### (3) 기술 요건

- **모델 확보**: 다중 인물 검출과 바운딩 박스 영역 추적은 타 콘텐츠 기구현 방식을 재사용함. 위치와 놀리기 채점과 카메라 프레임 버퍼를 공유함
- **판정 기준**: 시점별 영역 변화량 계산과 주체 선정 정확도. 목표값은 개발 단계에서 실제 동작을 보고 정함(정량 미정)
- **적용**: 채점과 같은 카메라 피드를 공유하는 온디바이스 처리를 우선 검토함. 베스트샷은 원본 프레임을 캡처하고 말뚝이 탈은 기념 사진 생성에서 합성하므로 라이브 합성 품질 문제는 없음. 전신 거리 프레임의 사진 품질(선명도, 프레이밍)만 확보하면 됨

##### (4) 필요 리소스

- 마당별 촬영 타임테이블(촬영 시점 목록, 놀리기 각본과 연계해 마당별로 작성)
- 카메라 프레임과 인물 검출은 위치와 놀리기 채점 루프와 공유(추가 리소스 없음)

## 4.4 Step 4. 기념 사진 생성과 대기 (병행)

Step 3에서 확정된 베스트샷(최대 4컷)으로 백그라운드(서버 기념 사진 생성)와 포그라운드(클라이언트 대기 화면)가 동시 진행되고 상태 조회로 동기화됨. 별도 촬영 화면이 없어 유저는 체험이 끝나면 바로 대기 화면으로 넘어감.

### 4.4.1 서버: 기념 사진 생성 (백그라운드)

#### 1) 진행

- **생성 입력 전송 (클라이언트)**: 클라이언트가 Step 3 베스트샷(최대 4컷)과 신명 게이지 최종 점수를 서버로 전송해 생성을 트리거함
- **생성 파이프라인**
	1. 서버: 기념 사진 생성 작업 큐 등록
	2. 기념 사진 생성: 각 컷마다 베스트샷 프레임에 말뚝이 탈을 고품질로 합성하고 마당 배경 연출과 테두리 프레임, 신명 게이지 최종 점수를 표기해 장 단위로 최대 4장을 만듦
		- 분기: 한 장의 호출 실패 시 그 장 재시도(2회 잠정), 한도 초과 시 그 장 탈락
	3. AI 가드레일: 생성 기념 사진을 장 단위로 검사
		- 분기: 위반 시 그 장을 2로 재생성(한도 2회, 잠정). 한도 초과 시 그 장 위험물 파기, 탈락
		- 분기: 검사 호출 실패 시 통과로 보지 않고 그 장 재시도(2회 잠정), 한도 초과 시 그 장 탈락
	4. 서버: 통과한 기념 사진(1~4장) 저장
	5. 결과물 호스팅: 통과분을 한 다운로드 페이지에 묶어 웹에 호스팅하고 만료형 다운로드 URL(48시간, 잠정) 1개를 발급함. Step 6이 이 URL로 QR을 만듦
		- 분기: 업로드나 호스팅, URL 발급 실패 시 재시도(2회 잠정), 한도 초과 시 상태 `failed` 전환
		- 원자적 publish: 통과분 전량 업로드와 URL 발급을 검증한 뒤에만 다운로드 페이지를 공개함. 중간 실패 시 이미 올라간 사진을 전량 삭제하고 재시도하며(재시도는 idempotency 키로 중복 업로드 방지), 부분 업로드 상태의 페이지는 공개하지 않음
	6. 결과물(기념 사진 통과분, 최대 4장)과 다운로드 URL을 서버 세션에 저장하고(생성 완료 이벤트) 클라이언트 세션 데이터에 반영
- **실패(생성 단계 공통)**
	- 어느 단계에서 `failed`가 됐는지를 세션 데이터의 에러 유형에 기록함. 포그라운드 상태 조회가 `failed`를 검출하면 그 케이스의 상황 안내 팝업을 띄우고 종료 처리함
	- 장 단위 처리라 일부 컷만 탈락하면 남은 통과분으로 정상 완료하고, 통과분이 1장도 없을 때만 `failed`로 둠(생성한 사진이 전량 실패, 전량 가드레일 탈락, 전량 검사 호출 실패)
	- 통과분이 4장 미만인 `completed`에서도 감상 화면과 다운로드 페이지는 통과분 수만큼만 노출함(빈 슬롯이나 깨진 링크를 만들지 않음). 세션 저장과 파기도 실제 통과분 수를 기준으로 함
- **상태 머신**
	- `generating` / `completed`(통과분 1장 이상을 호스팅하고 다운로드 URL까지 받은 상태) / `failed`(생성분 전량 실패, 생성분 전량 가드레일 한도 초과, 생성분 전량 가드레일 검사 호출 실패, 호스팅 영구 실패)

#### 2) 기념 사진 생성

##### (1) 역할과 목적

유저가 가져갈 한 판의 기념물을 만드는 런타임 엔진. 체험의 순간이 유저가 소장하는 기념 사진으로 남게 함.

##### (2) 입력과 출력

- **입력**: Step 3 베스트샷(최대 4컷), 선택 마당(말뚝이 탈과 마당 연출용), Step 3 신명 게이지 최종 점수
- **출력**: 기념 사진(통과분, 최대 4장. 각 장에 세션 공통 최종 점수 표기)

##### (3) 동작과 규칙

최종 저장본은 각 컷마다 베스트샷 프레임의 유저 얼굴에 말뚝이 탈을 고품질로 자연스럽게 합성하고 마당 배경 연출을 얹은 뒤 테두리 프레임을 두른 결과임. 근거리 얼굴 AR을 런타임에 두지 않으므로, 탈을 쓴 말뚝이 모습은 이 생성 단계에서 만들어 냄. 컷당 한 장씩 최대 4장을 만듦. 합성은 키오스크 부하를 고려해 서버에서 처리함. 해상도와 파일 형식은 구현 시 확정함.

##### (4) 기술 요건

- **모델 확보**: 이미지 합성과 생성 모델. 외부 API와 사전학습 모델 우선 검토(확인 필요)
- **판정 기준**: 합성 자연스러움, 말뚝이 탈과 마당 연출의 시각 정합, 생성 시간(대기 조회 주기와 연동). 정량 미정
- **적용**: 서버 백그라운드 배치. Step 4에서 호출

##### (5) 필요 리소스

- 기념 사진 프레임(테두리)과 마당 배경 연출 에셋
- 기념 사진용 말뚝이 탈 합성 에셋(베스트샷 프레임의 검출 얼굴에 말뚝이 탈을 고품질로 합성. 사전 제작, 비율과 해상도 확인 필요)

##### (6) 실패와 복구

생성 사진은 장 단위로 출력 가드레일 검사를 받음. 한 장의 호출이 재시도 한도(2회 잠정)를 넘겨 실패하거나 가드레일 재생성 한도(2회 잠정)를 넘기면 그 장을 파기하고 탈락시킴. 일부 컷만 탈락하면 남은 통과분으로 완료하고, 생성한 사진이 전량 탈락하면 생성 파이프라인의 `failed` 처리로 이어짐.

### 4.4.2 클라이언트: 기념 사진 생성 대기 화면 (포그라운드)

#### 1) 진행

- 대기 콘텐츠 노출(덧뵈기 공연 실제 영상)
	- 미리 여러 개로 분할한 영상을 준비하여 랜덤 재생
- 서버 상태 조회(주기 2초, 잠정). 두 타임아웃 미적용
- 분기: `generating` → 대기 유지 / `completed` → 즉시 Step 5 / `failed` → 상황 안내 팝업 → 종료 처리 / 상태 조회 연속 3회 무응답(잠정) → 상황 안내 팝업 → 종료 처리

## 4.5 Step 5. 결과물 감상

### 4.5.1 클라이언트: 결과물 감상 화면

#### 1) 진행

- 완성된 기념 사진(통과분, 최대 4장)을 함께 보여줌(그리드나 스와이프 등 배치는 디자인 단계에서 확정). 다음으로 터치 시 완주로 보고 Step 6 마무리 인사 화면으로 진행함
	- 분기: 그만두기 선택 시 확인 팝업 → 확정 시 종료 처리
	- 분기: 화면 타임아웃 → 완주로 보고 Step 6 마무리 인사 화면으로 진행([[시범콘텐츠 공통 사양#5.4 결과물 감상]])

## 4.6 Step 6. 종료와 리셋

완주와 비완주 두 경로로 진입함. 완주(Step 5 결과물 감상 화면에서 다음으로 터치 또는 화면 타임아웃으로 정상 진행)만 마무리 인사 화면을 거치고, 비완주 종료(그만두기, 터치나 동작 미입력 타임아웃, 약관 미동의, 실패 중단)는 마무리 인사 화면을 건너뛰고 곧장 세션 종료와 파기로 감.

### 4.6.1 클라이언트: 말뚝이 마무리 인사 화면

호스팅과 다운로드 URL 발급은 Step 4에서 이미 끝냈으므로, 이 화면은 그 URL로 QR을 그려 받기를 겸함.

#### 1) 진행

- 완주로 진입한 경우에만 표시함. 말뚝이 스승의 마무리 인사와 함께 QR을 띄워 유저가 결과물을 받게 함. 스캔을 마친 유저가 곧장 나가도록 "처음으로" 버튼을 둠
	- QR: Step 4가 발급한 다운로드 페이지 URL을 인코딩해 표시하고, 스캔 안내와 다운로드 가능 기간(48시간, 잠정)을 함께 보여줌. 유저가 본인 휴대폰으로 스캔해 다운로드 페이지에 접속하면 생성된 기념 사진(최대 4장)을 각각 내려받음
	- 분기: 처음으로 버튼 터치 또는 화면 타임아웃(기본 60초, 잠정) → 다음 단계 진행

### 4.6.2 클라이언트: 종료 이벤트 전송과 리셋

## 5.2 에러 케이스

### 5.2.1 케이스 목록과 처리

**처리**는 그 실패가 세션을 어떻게 만드는지고, **원인**은 실패가 누구에게서 비롯되었는지임. 원인이 외부 서비스나 시스템일 경우에만 운영 알림을 보냄. 갈래를 나누는 판정 규칙은 실패 처리에 있고, 본 표는 그 규칙을 케이스에 적용한 결과임. 이후 동작의 Step 6은 모두 비완주 종료라 마무리 인사 화면을 건너뛰고 세션 종료와 파기 후 시작 화면으로 복귀함. Step 4 기념 사진 생성과 가드레일은 장 단위로 처리하며, 아래 생성 관련 중단 케이스는 생성한 사진이 전량 실패한 경우임. 일부 컷만 탈락하면 남은 통과분으로 정상 완료함.

| 발생 지점 | 처리 | 원인 | 팝업 | 이후 동작 |
|---|---|---|---|---|
| 말뚝이 스승이나 양반 TTS 합성이나 호출 실패 | 기능 축소 | 외부 서비스 | 없음 | 세션 계속, 대표 이미지와 텍스트로 진행 |
