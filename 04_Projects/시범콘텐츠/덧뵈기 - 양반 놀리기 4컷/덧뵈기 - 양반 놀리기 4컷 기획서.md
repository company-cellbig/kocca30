> 덧뵈기의 양반 풍자를 소재로, 유저가 양반 놀리기 세부 유형을 골라 질문에 답을 채우면 자기 탈 캐릭터가 등장하는 4컷 만화를 AI가 만들어 주는 생성형 시범콘텐츠의 개발 기획서.

# 1. 개요

- **콘텐츠 정의**: 덧뵈기의 양반 풍자를 소재로 한 AI 4컷 만화 생성 키오스크 콘텐츠
- **소재**: 남사당놀이 탈놀음 덧뵈기
- **목표 경험**: 덧뵈기의 풍자 골격인 양반 풍자와 말뚝이의 재담식 조롱은 고정하고, 그 안의 사건과 대사를 유저 입력과 AI 생성으로 채워 매번 다른 4컷 만화를 만듦
- **핵심 메커닉**: AI가 양반 놀리기 세부 유형별 플롯을 사전 생성해 두고, 유저가 세부 유형을 고르면 그 유형 플롯 하나가 랜덤 배정되어 컷 단위로 채워짐
- **산출물**: 유저 탈 캐릭터가 주인공으로 등장하는 4컷 만화 한 편. 컷별 이미지와 말풍선 대사를 4칸 레이아웃으로 묶음

# 2. 전체 플로우

1회 완결로 자기 탈 캐릭터가 주인공인 4컷 만화 한 편을 만드는 세션임. Step 1 인트로 → Step 2 세부 유형 선택 → Step 3 주인공 설정 → Step 4 플롯 문답 → Step 5 결과물 생성과 대기 화면(병행) → Step 6 결과물 감상 → Step 7 종료와 리셋.

- **중단 처리**
	- 대상: 진행 중 이탈(그만두기, 터치 미입력 타임아웃, 미동의, 비속어나 입력 가드레일 위반 한도 초과)과 실패(생성 파이프라인 실패, 결과물 호스팅 실패, 상태 조회 무응답, 플롯 배정 실패)가 모두 이 공통 처리로 모임
	- 처리: 마무리 인사 화면을 건너뛰고, 세션을 종료해 파기한 뒤 시작 화면으로 돌아감(비완주 종료). 실패는 상황 안내 팝업을 띄운 뒤 진행하고, 이탈은 팝업 없이 진행함. 세션 생성 실패만 정리할 세션이 없어 종료 처리 없이 곧장 시작 화면으로 되돌림
	- 상세: 케이스별 조건과 처리는 [[#3.11 실패 처리]]와 [[#5.2 에러 케이스]]가 정본
- **병행**: Step 5에서 백그라운드 결과물 생성과 포그라운드 대기 화면이 동시 진행함. 결과물 호스팅과 다운로드 URL 발급까지 이 구간에서 끝내, 완주 시 마무리 인사 화면이 그 URL로 QR을 띄움.
- **파기**: Step 7 종료 시 세션 데이터를 서버에 저장하고 초기화함. 결과물은 다운로드 호스팅 만료 시 파기함.

# 3. 공용 시스템

## 3.1 세션 데이터

### 3.1.1 역할과 목적

한 세션 진행에 필요한 데이터를 담는 시스템. 전 Step이 같은 상태를 공유하게 하고, 데이터 종류별 보관과 파기를 관리하기 쉽게 함.

### 3.1.2 동작과 규칙

세션이 저장하는 데이터를 분류, 값, 보관 기간으로 정리함. 어떤 값이 들어가는지까지만 적고 데이터 타입과 저장 스키마는 설계 단계에서 정함. 카메라를 쓰지 않아 얼굴 영상이 없고, 결과물을 화면 QR로 전달해 연락처를 받지 않으므로 세션이 저장하는 개인정보는 없음.

| 데이터 | 분류 | 들어가는 값과 구성 | 보관 기간 | 비고 |
|---|---|---|---|---|
| 세션 ID | 시스템 | 세션마다 부여되는 고유 식별자 | 보관 (잠정, 규정 검토 후 확정) | Step 1에서 생성 |
| 현재 언어 | 시스템 | 세션에 적용 중인 언어(기본 한국어) | 보관 (잠정, 규정 검토 후 확정) | 시작 화면 언어 선택에서 설정. 현지화 기준 |
| 현재 Step | 시스템 | 현재 진행 중인 Step | 보관 (잠정, 규정 검토 후 확정) | 진행 단계 기록 |
| 에러 유형 | 시스템 | 에러 발생 시 에러 케이스 유형 기록 | 보관 (잠정, 규정 검토 후 확정) | 디버깅과 품질 분석용 |
| 동의 기록 | 시스템 | 약관 버전, 동의 시각 | 보관 (기간 미정, 규정 검토 후 확정) | 약관 버전 체계는 운영 단계에서 결정함 |
| 캐릭터 정보 | 콘텐츠 입력 | 이름, 연령대(아이/청소년/어른), 성별(남/여) | 30일 (잠정, 디버깅과 품질 분석용) | 주인공 이름과 6개 카드 = 연령대 × 성별로 주인공 설정 |
| 선택 세부 유형 | 콘텐츠 입력 | 유저가 고른 양반 놀리기 세부 유형 1종 | 30일 (잠정, 디버깅과 품질 분석용) | 풍자 플롯 구조가 정의 |
| 배정 플롯 | 콘텐츠 생성 | 선택 유형 풀에서 랜덤 배정된 사전 생성 플롯 | 30일 (잠정, 디버깅과 품질 분석용) | 풍자 플롯 생성 LLM의 산출물 |
| 컷별 응답 | 콘텐츠 입력 | 컷별(기/승/전/결) 유저 응답, 순서대로 누적 | 14일 (잠정, 규정 검토 후 확정) | 말뚝이 질문은 배정 플롯이 소유하므로 응답만 저장하고 질문은 컷 번호로 참조. 디버깅과 품질 분석용 |
| 결과물 | 콘텐츠 생성 | 4컷 만화 파일, 메타(생성 시각 등) | 호스팅 만료 시 파기 (다운로드 제공 기간 48시간, 잠정) | 포맷 결정 미정 |
| 다운로드 URL | 콘텐츠 생성 | 결과물 호스팅 주소(만료형) | 호스팅 만료까지 유지 | Step 5에서 발급, Step 7이 QR로 인코딩 |

- **Step별 세션 동작**: Step 1 생성, Step 2~Step 6 갱신, Step 7 종료와 리셋
- **서버 전송 시점 (이벤트 기반)**: 각 화면의 세션 데이터 갱신은 클라이언트 로컬 상태에만 반영하고, 서버로는 정기 전체 동기화 없이 이벤트 시점에만 전송함. 이어하기가 없는 1차연도 기준임
	- 단계 이동: 각 Step 진입과 종료 시 현재 Step을 전송함
	- 에러와 이탈: 에러 발생 시, 이탈(비속어나 가드레일 한도 초과 종료, 미입력 타임아웃 종료) 시 전송함
	- 생성 입력: 캐릭터 정보와 컷별 응답을 생성 Step(Step 5) 진입 시 전송함. 컷별 응답은 이에 앞서 Step 4 AI 가드레일 입력 검사 요청으로도 서버에 보내지만, 그건 서비스 호출이라 세션 데이터 전송과 별개이고 정본은 클라이언트에 남음
	- 결과물: 결과물과 다운로드 URL을 생성 완료 시 서버 세션에 반영함
- **보관 기간 잠정값**: 시스템 데이터와 콘텐츠 데이터(캐릭터 정보와 선택 세부 유형은 입력, 배정 플롯은 생성)는 디버깅과 품질 분석을 위해 30일(잠정) 보관하고 규정 검토 후 확정함

## 3.2 개인정보 처리

### 3.2.1 역할과 목적

본 콘텐츠가 다루는 개인정보를 정의하는 시스템. 본 콘텐츠는 세션에서 개인정보를 수집하지 않으나 향후 추가될 수 있으므로 항목을 유지함.

### 3.2.2 동작과 규칙

- **개인정보 범위**: 없음
	- 캐릭터 정보, 응답, 결과물은 콘텐츠 데이터로 개인정보가 아님
	- 이름은 유저 본인 이름이 아니라 주인공 캐릭터에 붙이는 이름임. 화면이 "주인공 이름 입력"으로 묻고 실명을 요구하지 않으므로 개인정보로 분류하지 않음
	- 4컷 만화는 유저 얼굴이 아니라 유저가 고른 탈 캐릭터로 그려져 생체정보를 담지 않음(카메라 미사용). 유저의 음성 입력은 문자로 변환하고 원본 녹음은 저장하지 않음
- **결과물 전달**: 화면 QR로 익명 다운로드함
- **동의 미보유 처리**: Step 1에서 세션이 생성되나 미동의(그만두기나 터치 미입력 타임아웃) 시 세션을 보존하지 않고 종료 처리에서 전체 파기함

## 3.3 언어 선택 시스템

### 3.3.1 역할과 목적

세션 전체에 적용할 언어를 정하는 관문. UI 카피와 AI 생성물(4컷 만화 대사, 말뚝이 대사)을 유저가 고른 언어로 제공해, 다른 언어를 쓰는 유저도 자기 언어로 양반 놀리기를 체험하게 함.

### 3.3.2 입력과 출력

- **입력**: 유저의 언어 선택
- **출력**: 현재 언어(세션 데이터에 저장). 현지화 JSON(localization.json)에서 해당 언어값을 불러옴

### 3.3.3 동작과 규칙

- 유저가 언어를 선택하고 시작하기 버튼을 터치하면 현재 언어로 반영함. 기본값은 한국어임
- **현지화 범위**: UI 카피뿐 아니라 AI 생성물까지임. 4컷 만화의 장면과 말풍선 대사(유저 입력 가공 LLM), 말뚝이 진행 호스트 대사를 현재 언어로 생성하고, 가드레일도 그 언어를 검사함. 지원 언어 범위는 한국어와 영어 우선 적용

## 3.4 말뚝이 진행 호스트

### 3.4.1 역할과 목적

양반을 놀리는 탈춤 풍자의 화자 말뚝이를 세션 진행 호스트로 세운 시스템. 유저 탈 캐릭터가 주인공인 풍자를 재담으로 거들어 덧뵈기의 전통 정체성을 살림.

### 3.4.2 동작과 규칙

- **범위**: 전 Step 진행 호스트
- **페르소나**: 말뚝이 전통 인물과 화법(말투, 어휘, 반응 패턴)은 세부 설계에서 정함(작성 예정). 말뚝이 배역 해석은 소재 원본 작성 후 검증함(확인 필요)
- **화법**: 양반을 재담으로 조롱하는 말뚝이 화법. 컷별 질문 제시와 결 컷 맺음 조롱을 맡음
- **발화 방식**: TTS 음성으로 대사를 재생하고 같은 대사를 화면에 텍스트로 표시함. 발화 중 다음 버튼을 누르면 발화를 중단하고 다음으로 진행함
- **타임아웃 연동**: 발화 중에는 터치 미입력 타임아웃을 멈추고, 발화가 끝난 뒤 측정을 시작함

### 3.4.3 필요 리소스

- 말뚝이 캐릭터 비주얼(시각 정체성 고정, 제작 방식 확인 필요)
- 말뚝이 TTS 보이스
- 추임새와 재담 대사(제작 방식 확인 필요)

### 3.4.4 실패와 복구

아바타 렌더나 TTS 재생이 실패하면 음성과 애니메이션 없이 대표 이미지와 텍스트 박스로만 진행함. 대사는 표시하고 세션은 계속함.

## 3.5 진행 중 종료

### 3.5.1 역할과 목적

유저에게 진행 중 그만둘 수단을 주는 시스템. 원치 않는 세션을 빨리 끝내 키오스크 회전율을 높임.

### 3.5.2 동작과 규칙

#### 1) 일반 규칙

- **처리**
	- 진행 중인 화면을 멈추고 마무리 인사 화면 없이 곧장 세션 종료와 파기 후 시작 화면으로 복귀함
	- 유저 쪽 능동 이탈이라 상황 안내 팝업 없이 종료함

#### 2) 유저의 종료 선택 시 규칙

- **처리**
	- 그만두기 터치 시 그만두기 확인 팝업 표시
	- 그만두기 확인 시 종료 처리하고, 취소 시 원래 화면 복귀
- **적용 화면**
	- Step 1 가이드 화면, 이용 동의 화면
	- Step 2 세부 유형 선택
	- Step 3 캐릭터 카드 선택과 이름 입력
	- Step 4 말뚝이 문답
- **예외 (미적용)**
	- Step 1 시작 화면
	- Step 5 대기 화면
	- Step 6 결과물 감상
	- Step 7 마무리 화면

#### 3) 입력 유효성 및 AI 가드레일 위반 시 종료 규칙

- **처리**
	- 매 위반 시 위반 횟수가 표시된 안내 팝업 표시 후 재입력 받고 3회(잠정) 위반 시 종료 처리

## 3.6 화면 타임아웃

### 3.6.1 역할과 목적

유저가 한 화면에 오래 머무는 것을 막아, 무인 키오스크가 한 유저에게 묶이지 않게 하는 시스템.

### 3.6.2 동작과 규칙

- **처리**
	- 한 화면에서 60초(잠정) 이상 머물면 다음 단계로 진행함
	- 화면별 오버라이드: 결과물 감상 화면 300초(잠정). 마무리 인사 화면은 처음으로 버튼이 주 종료라 기본값(60초, 잠정) 적용
	- 호스트 발화 중에는 측정을 멈추고, 발화 종료나 스킵 후 재개함(잠정)
- **예외**: 필수 입력, 가이드, 대기, 팝업 화면 미적용

## 3.7 터치 미입력 타임아웃

### 3.7.1 역할과 목적

입력이 끊긴 유저 이탈을 감지해 방치된 세션을 정리하고 키오스크 회전율을 높이는 시스템.

### 3.7.2 동작과 규칙

- **처리**
	- 한 화면에서 45초(잠정) 이상 터치 미입력 시 진행 중 종료 처리
	- 말뚝이 발화 중에는 측정을 멈추고, 발화가 끝나거나 스킵한 뒤부터 측정 시작
- **예외**: 시작 화면, 대기 화면, 결과물 감상, 마무리 화면 미적용

## 3.8 입력 유효성 검증

### 3.8.1 역할과 목적

유저 입력을 길이와 표현으로 거르는 시스템. 잘못된 입력을 초기에 막아 생성과 전달 등 후속 처리가 정상 작동하게 함.

### 3.8.2 동작과 규칙

| 입력 | 길이 상한 (입력 단계 차단) | 표현 검사 (제출 시) |
|---|---|---|
| 이름 (Step 3) | 20자 | 클라이언트 비속어 필터 |
| 컷별 응답 (Step 4) | 50자 | 클라이언트 비속어 필터 |

- **길이 처리**: 상한에 닿으면 가상 키보드가 더 글자를 받지 않아 초과 입력 자체가 생기지 않음
- **비속어 처리**: 매 위반 시 위반 횟수가 표시된 안내 팝업 표시 후 재입력 받고 3회(잠정) 위반 시 종료 처리
	- 위반 횟수는 화면마다 초기화하여 따로 셈
- 음성 답변은 음성 인식(STT) 변환 텍스트에 같은 검사를 적용함
- 길이값은 유람기 기준을 준용한 잠정값이며 콘텐츠 문안 확정 시 조정함
- 컷별 응답은 본 검사를 통과한 뒤 AI 가드레일(런타임 입력) 검사를 받음
	- 비속어 위반 횟수와 가드레일 위반 횟수는 서로 독립임
- 이름은 클라이언트 검증 외에 백엔드 재검증을 거침

## 3.9 AI 가드레일

### 3.9.1 역할과 목적

입력과 생성물의 안전을 검사하는 시스템. 유해하거나 전통을 왜곡한 콘텐츠가 유저에게 노출되지 않게 막음.

### 3.9.2 동작과 규칙

#### 1) 적용 지점

- **런타임 입력(Step 4)**: 유저 응답 검사
- **런타임 출력(Step 5)**: 만화 생성물(이미지, 대사) 검사. 검사 항목은 유저 입력 삽입 안전, 전통 정체성 왜곡, 부적절 콘텐츠, 이미지 안전
- 사전 생성 플롯과 컷별 질문의 검수는 AI 가드레일 자동 검사가 아니라 풍자 플롯 생성 LLM의 사람 검수로 함(사전 지점)

#### 2) 풍자 추상화와 차단

양반 풍자 특성상 권력과 위선을 다루되 특정 실존 대상으로 흐르지 않게 추상화함. 세부 유형([[#3) 세부 유형]])별 차단과 설계 지향임.

| 세부 유형 | 차단 | 설계 지향 |
|---|---|---|
| 허세 자랑형 | 실제 정치인과 공공인물, 특정 가문과 문중 풍자 | 추상화된 권위와 문벌 허세 |
| 헛똑똑이형 | 특정 지역과 학벌, 집단의 무지 비하 | 헛똑똑이의 골계(권위의 무지) |
| 위선형 | 특정 실명과 단체의 위선 지목 | 윤리적 위선(겉치레, 남 속이기) |
| 탐욕과 인색형 | 성적 대상화, 처첩 삼각관계, 특정인 비방 | 재물욕과 인색, 부림의 골계적 추락 |

- **모든 유형 공통 차단**: 성별, 지역, 종교 등 혐오 조장과 특정 실존 인물이나 단체를 겨눈 풍자를 막음. 골계는 권위의 허망한 추락으로 향하게 함

#### 3) 위반 시 처리

- **입력 위반 검출**: 매 위반 시 위반 횟수가 표시된 안내 팝업 표시 후 재입력 받고 3회(잠정) 위반 시 종료 처리
	- 위반 횟수는 화면마다 초기화하여 따로 셈
- **입력 가드레일 호출 실패**: 검사 호출 자체가 실패하면 통과로 보지 않음. 재시도(2회 잠정)해도 실패하면 재입력을 안내함
	- **위반 횟수에 세지 않음**: 유저 입력이 아니라 검사 서비스 장애가 원인이라 유저에게 종료 부담을 지우지 않음
	- **연속 실패 한도**: 같은 세션에서 호출 실패가 연속 3회(잠정)에 닿으면 검사 서비스 장애로 간주하고, 재입력을 더 요구하지 않고 중단 처리함
- **출력 위반 검출**: 재생성 한도 3회(잠정)까지 다시 만들고, 한도를 넘기면 위험 생성물을 파기하고 중단 처리함

### 3.9.3 기술 요건

- **모델 확보 (결정 필요)**: 범용 유해물은 외부 안전 API로 거르고, 전통 정체성 왜곡처럼 범용 API가 못 잡는 판정은 자체 규칙이나 도메인 분류기로 보완함. API 대 자체 구축 비중은 후보 조사 후 확정
- **판정 기준**: 텍스트(유저 응답, 생성 대사)와 이미지(생성 컷)를 모두 검사하므로 텍스트 모더레이션과 이미지 모더레이션이 둘 다 필요함. 무인 운영이라 미탐(유해물 통과)이 오탐보다 위험하므로 미탐을 낮추는 보수적 임계로 잡음. 오탐률과 미탐률, 임계 목표는 검증 데이터 확보 후 정량 확정
- **적용**: 런타임 서버 호출. 입력과 출력 검사는 유저 대기 구간이라 검사 응답 지연 상한이 필요함(정량 미정)
- **데이터**: 전통 왜곡 판정 기준과 부적절 콘텐츠 분류 기준(작성 예정). 가드레일 미탐 위험은 외부 검증위원회 자문으로 보완함

### 3.9.4 실패와 복구

가드레일 자신이 실패하는 경우를 다룸. 검사 결과가 위반으로 나오는 것은 실패가 아니라 정상 동작이며, 그 처리는 위 3) 동작과 규칙에 있음.

- **입력 검사 호출 실패**: 통과로 보지 않음. 외부 서비스 호출 래퍼로 재시도(2회 잠정)해도 실패하면 재입력을 안내함. 유저 잘못이 아니라 검사 서비스 장애가 원인이라 위반 횟수에 세지 않고, 운영 알림 대상으로 둠
- **출력 검사 호출 실패**: 통과로 보지 않음. 재시도(2회 잠정)해도 실패하면 결과물 생성 파이프라인을 `failed`로 보냄. 재생성 한도 초과와는 원인이 달라(생성물이 계속 위반 대 검사 서비스 장애) 세션 데이터의 에러 유형에 따로 기록함
- **검사 서비스가 오래 죽어 있는 경우**: 호출 실패가 연속 3회(잠정)에 닿으면 서비스 장애로 간주하고 상황 안내 팝업 후 중단 처리함. 유저에게 재입력을 계속 요구하지 않음. 입력 검사 호출 실패는 운영 알림 대상으로 두어, 장애를 조기에 알아채게 함

## 3.10 외부 서비스 호출 래퍼

### 3.10.1 역할과 목적

외부 서비스 호출(음성 인식, AI, 이미지 생성, 결과물 호스팅)을 감싸는 공통 계층. 재시도와 타임아웃 대응을 한 곳에 모아, 호출마다 장애 처리를 따로 짜지 않게 함.

### 3.10.2 동작과 규칙

- **재시도 횟수**
	- 2회(잠정). 백오프는 1차 1초, 2차 3초(잠정)
- **호출 타임아웃**
	- 음성 인식 10초, TTS 30초, LLM 30초, 이미지 생성과 결과물 호스팅 60초(모두 잠정)
- **한도 초과**
	- 재시도 한도를 넘긴 실패는 실패 처리로 넘김

## 3.11 실패 처리

### 3.11.1 역할과 목적

런타임 실패를 어떻게 다룰지 정하는 정책. 무인 운영에서 실패가 방치되지 않게 함.

### 3.11.2 동작과 규칙

본 절은 판정 규칙만 정의함. 케이스별 발생 지점과 처리, 팝업, 이후 동작은 [[#5.2 에러 케이스]] 표가 정본임.

- **처리 갈래**: 실패가 세션을 어떻게 만드는지로 넷을 나눔
	- **재입력**: 유저 입력만 다시 받으면 이어 감. 비속어 검출, 입력 가드레일 위반과 호출 실패가 여기 속함
	- **대체 입력**: 입력 수단 하나가 막힌 경우라 다른 수단으로 바꿔 이어 감. 음성 인식이 실패하면 가상 키보드로 계속 받음
	- **기능 축소**: 보조 기능이 빠져도 결과물이 남음. 말뚝이 발화 실패가 여기 속함
	- **중단**: 핵심 생성(장면과 대사, 컷 이미지, 조립)이나 결과물 전달(호스팅), 진행 재료(세션, 배정 플롯)가 실패해 결과물이 남지 않음
- **중단 공통 처리**: 상황 안내 팝업을 띄우고 마무리 인사 화면 없이 세션 종료와 파기 후 시작 화면으로 복귀함. 별도 실패 화면을 두지 않고 전달하지 못한 생성물을 파기함
	- 예외: 세션 생성 실패는 파기할 세션 자체가 없어 종료 처리도 거치지 않고 곧장 시작 화면으로 되돌림
	- 생성 파이프라인의 중단은 `failed` 상태 하나로 모으고, 어느 단계에서 났는지는 세션 데이터의 에러 유형에 남김
	- 실패 시점: 호스팅을 Step 5에서 끝내므로 유저는 감상을 시작하기 전에 실패를 알게 됨
- **운영 알림**: 원인이 외부 서비스나 시스템이면 보내고, 유저면 보내지 않음(알림 채널 미정)

## 3.12 풍자 플롯 구조 (규칙과 틀)

### 3.12.1 역할과 목적

덧뵈기의 풍자 문법(4컷 단위, 기승전결 골격, 세부 유형, 변주 규칙)을 고정한 설계 모델로, 실물 생성은 풍자 플롯 생성 LLM이 맡음. 이 규칙을 생성 LLM과 가드레일, 말뚝이가 공통 전제로 참조해 전통 틀은 지키고 내용은 매번 다르게 함.

### 3.12.2 동작과 규칙

#### 1) 4컷 (풍자 플롯 단위)

- **4컷 정의**: 도입(기)부터 맺음(결)까지 하나의 풍자 줄기로 이어지는 4칸 만화. 마지막 컷에서 골계적 반전(양반의 허세나 위선이 들통나 무너짐)으로 맺음
- **1차연도 대주제**: 양반 놀리기 하나임(사용자 결정, 2026-07-01). 파계승이나 부부 갈등 등 다른 풍자 계열은 현대 정합성을 고려해 1차연도에서 제외함
- **사전 고정형**: 풍자 플롯과 컷별 말뚝이 질문을 사전에 생성하고 검수해 고정함(런타임 생성 아님)
- **한 세션 = 한 세부 유형 = 한 편의 4컷 만화**

#### 2) 컷 골격 (공통 기승전결)

모든 세부 유형은 4컷 기승전결 골격을 공유함. 도입은 짧고, 갈등 고조와 골계적 반전에 무게가 실림.

| 컷 | 기능 | 적용 범위 |
|---|---|---|
| 기(도입) | 주인공(유저 탈 캐릭터)과 풍자 대상 양반 등장, 상황 제시 | 모든 세부 유형 공통 |
| 승(전개) | 선택된 세부 유형의 갈등 고조(양반의 허세나 탐욕 부풀기) | 세부 유형별 |
| 전(절정) | 유저의 한 수로 양반의 허점 노출 | 세부 유형별 |
| 결(반전) | 골계적 추락과 맺음(말뚝이 조롱으로 마무리) | 모든 세부 유형 공통 |

- 세부 유형별로 다른 것은 승과 전 두 컷이며, 이것이 세부 유형을 가름. 기와 결은 골계 골격을 공유함
- 주인공은 유저 탈 캐릭터이고 말뚝이는 풍자를 거드는 화자임

#### 3) 세부 유형

덧뵈기 샌님잡이 마당의 양반 풍자([[덧뵈기#2. 네 마당]])를 4종 세부 유형으로 정리함. 각 유형은 양반의 어떤 허물을 놀리는지로 갈리며, 승(전개)의 허물이 전(절정)에서 유저의 한 수로 들통나 결(반전)의 골계적 추락으로 이어짐. 세부 유형별로 다른 것은 승과 전 두 컷임([[#2) 컷 골격 (공통 기승전결)]]).

| 세부 유형 | 승 (전개: 허물 부풀기) | 전 (절정: 유저의 한 수) | 원형 (샌님잡이 풍자 모티프) |
|---|---|---|---|
| 허세 자랑형 | 문벌, 지체, 벼슬을 부풀려 뻐김 | 유저가 근본과 실상을 들춰 허풍이 빈 껍데기로 드러남 | 샌님의 지체 자랑, 문벌 허세 |
| 헛똑똑이형 | 글과 학식을 과시함 | 유저가 낸 한 수(엉뚱한 물음, 말장난)에 무식이 탄로남 | 글 모르는 양반, 파자와 언어유희 재담 |
| 위선형 | 체면과 청렴을 내세움 | 유저가 뒤로 챙기던 잇속과 이중성을 드러냄 | 체면 차리는 샌님의 겉과 속 |
| 탐욕과 인색형 | 재물을 탐하거나 아랫사람을 인색하게 부림 | 유저의 한 수로 욕심이 과해 스스로 손해와 망신을 봄 | 인색한 샌님, 하인 부림, 재물 탐 |

- **절정(전)은 유저 탈 캐릭터가 주도하고 말뚝이는 조력함**(대체 아님). 말뚝이 조롱의 골계는 유형과 무관하게 결 컷에서 공통으로 맺음
- 각 유형 내부는 유저 입력 기반으로 무한 변주될 수 있도록 디자인해야 함([[#5) 변주]])
- 로스터는 사용자 확정 전 잠정임. 유형별 실물 플롯 풀은 풍자 플롯 생성 LLM이 사전 생성해 별도 자산으로 관리함([[#3.13 풍자 플롯 생성 LLM]])

#### 4) 유저 탈 캐릭터

- **정의**: 4컷 만화 주인공으로 등장하는 탈을 쓴 캐릭터. 유저를 대신하는 캐릭터로, 캐릭터 정보(연령대 × 성별 6종)로 개인화하고 시각은 덧뵈기 배역 탈 양식을 따름
- **해석 확정**: 콘셉트의 "사용자 탈을 쓴 캐릭터"는 유저가 직접 디자인한 탈이 아니라 캐릭터 정보로 개인화된 배역 탈 양식 캐릭터로 확정함(사용자 결정, 2026-07-01). 별도 탈 디자인 단계는 두지 않음

#### 5) 변주

같은 틀(세부 유형과 컷 골격)에 다른 내용(사건, 풍자 형태, 대사)을 넣어 매번 다른 결과를 만드는 시스템으로 두 지점에서 적용함.

- **갈래 1. 유저 입력 슬롯**
	- 유저가 채운 입력이 만화 전개의 재료가 됨
	- 슬롯은 이름(주인공), 캐릭터 카드(6종 중 택1), 세부 유형 선택, 컷별 응답(기/승/전/결)
- **갈래 2. AI 질문 변주 (사전 생성)**
	- 같은 세부 유형이라도 질문이 단조롭지 않게, 사전 생성 단계에서 유형 풀에 변주를 마련하고 런타임은 랜덤 선택함
		- 사건 형태: 컷 안 사건 컨텍스트 변주 (예: 잔칫집, 길거리, 관아)
		- 풍자 형태: 같은 유형 안에서 허물이 드러나는 형태 변주 (예: 허세 자랑형이라도 문벌 자랑, 벼슬 자랑, 재주 자랑)
- **일관성 유지**
	- 위 두 갈래만 변주하고 컷 공통 골격과 세부 유형의 고정 문법은 일관 유지함. 결 컷은 항상 골계적 추락과 말뚝이 맺음 골격을 지키고 그 안의 사건만 다양함
- **세부 설계 (작성 예정)**: 유저 응답에서 사건으로 잇는 프롬프트, 세부 유형 제시와 선택 로직, 풍자 사건 시드 풀

## 3.13 풍자 플롯 생성 LLM

### 3.13.1 역할과 목적

풍자 플롯 구조를 입력으로 받아, 세부 유형별 플롯(컷별 장면 골격과 말뚝이 질문)을 구체 실물로 사전 생성하는 시스템. 런타임에 생성 지연 없이 플롯을 즉시 배정할 수 있도록, 운영 전에 사람 검수까지 끝낸 플롯 풀을 사전에 만들어 둠.

### 3.13.2 입력과 출력

- **출력**: 풍자 플롯 풀(텍스트와 JSON). 컷별 말뚝이 질문까지 고정한 완성 플롯임. 풀 스키마와 크기, 저장과 조회 키, Step 2가 이 풀에서 플롯을 받아 쓰는 방식은 구현 단계에서 정함

### 3.13.3 동작과 규칙

1. **사건 구성**: 풍자 사건 시드에서 기, 승, 결 사건을 골라 사건 라인을 구성함. 전(절정)은 승의 해소로 생성함. 한 세부 유형당 여러 플롯을 승을 달리해 겹치지 않게 만듦
2. **장면과 질문 생성**: 사건을 말뚝이 재담 화법으로 장면화하고, 유저(주인공)의 한 수를 묻는 질문을 생성함. 전 컷에서 유저 주도를 유도함. temperature 잠정 0.7~0.9
3. **사람 검수와 확정**: 생성한 플롯 후보를 사람이 읽고 컷 문법 정합, 플롯 품질, 풍자 안전(추상화, 실존 대상 회피)을 판정함. 통과한 것만 풀에 올리고, 반려한 것은 올리지 않으며 필요하면 프롬프트를 고쳐 다시 생성함

### 3.13.4 기술 요건

- **모델 확보**: 생성형 대규모 언어 모델(LLM). 외부 API나 사전학습 모델 우선 검토(후보 확인 필요)
- **판정 기준**: 컷 문법 정합, 플롯 품질, 풍자 안전(사람 검수 판정, 정량 미정)
- **적용**: 사전 배치 생성. 런타임이 아님
- **생성 튜닝값**: temperature 0.7~0.9(잠정)
- **데이터**: 풍자 사건 시드 풀(입력 데이터, 작성 예정)

### 3.13.5 필요 리소스

풍자 사건 시드(작성 예정), 말뚝이 페르소나와 컷 문법.

### 3.13.6 실패와 복구

사전 단계라 유저 영향이 없음. 사람 검수에서 반려된 플롯은 풀에 올리지 않고, 필요하면 프롬프트를 고쳐 다시 생성함.

# 4. 세션 진행

## 4.1 Step 1. 인트로

### 4.1.1 클라이언트: 시작 화면

#### 1) 진행

- 시작하기 버튼 터치 시 선택한 언어를 반영하여 다음 단계 진행
	- 서버로 신규 세션 생성 요청

### 4.1.2 서버: 세션 생성

#### 1) 진행

- 신규 세션 생성 및 세션 ID 부여 및 선택 언어 정보 저장
	- 분기: 세션 생성 실패 시 재시도(2회 잠정) 후 상황 안내 팝업 → 시작 화면 복귀

### 4.1.3 클라이언트: 가이드 화면

#### 1) 진행

- 진행 흐름 안내, 다음 버튼 터치 시 다음 단계 진행
	- 분기: 미입력 타임아웃 → 종료 처리
	- 분기: 그만두기 선택 시 확인 팝업 → 확정 시 종료 처리

### 4.1.4 클라이언트: 이용 동의 화면

본 콘텐츠는 카메라를 쓰지 않고 개인정보를 수집하지 않으므로 개인정보 수집 동의가 아님. AI가 만든 결과물의 책임 범위 같은 이용 조건에 동의를 받음(약관 항목은 규정 검토에서 확정).

#### 1) 진행

- 동의하고 시작하기 터치 시 클라이언트가 약관 동의 정보(약관 버전, 타임스탬프)를 동의 확정 이벤트로 서버에 전송하고 다음 단계로 진행함(화면 타임아웃 미적용). 서버는 이 이벤트를 받아 세션에 동의 기록을 저장함
	- 분기: 미입력 타임아웃 → 미동의로 종료 처리
	- 분기: 그만두기 선택 시 확인 팝업 → 확정 시 미동의로 종료 처리

## 4.2 Step 2. 세부 유형 선택

### 4.2.1 클라이언트: 세부 유형 선택 화면

#### 1) 진행

- 양반 놀리기 세부 유형 카드 선택 후 다음 진행 버튼 터치 시 클라이언트 세션 데이터의 선택 세부 유형 갱신하고, 선택한 세부 유형을 서버로 전송해 다음 단계(플롯 배정) 진행
	- 분기: 미입력 타임아웃 → 종료 처리
	- 분기: 그만두기 선택 시 확인 팝업 → 확정 시 종료 처리

### 4.2.2 서버: 플롯 배정

#### 1) 진행

- 클라이언트가 전송한 선택 세부 유형의 풀에서 플롯 1개를 랜덤으로 배정하고, 배정 결과를 서버 세션에 저장한 뒤 클라이언트에 반환함. 클라이언트는 받은 배정 결과를 세션 데이터에 반영함
	- 풍자 플롯 생성 LLM 사전 산출물 사용
	- 분기: 풀 조회나 배정 실패 시 재시도(2회 잠정) 후 상황 안내 팝업 → 종료 처리

## 4.3 Step 3. 주인공 설정

### 4.3.1 클라이언트: 캐릭터 카드 선택 화면

#### 1) 진행

- 캐릭터 카드(6개: 아이/청소년/어른 × 남/여) 중 1개 선택 후 다음 진행 버튼 터치 시 클라이언트 세션 데이터의 캐릭터 정보 갱신하고 다음 단계 진행
	- 분기: 미입력 타임아웃 → 종료 처리
	- 분기: 그만두기 선택 시 확인 팝업 → 확정 시 종료 처리

### 4.3.2 클라이언트: 이름 입력 화면

#### 1) 진행

- 이름 입력 확정 후 유효성 검증 통과 시 클라이언트 세션 데이터의 캐릭터 정보 갱신하고 다음 단계 진행
	- 길이 상한(20자)은 입력 단계에서 막음(팝업 없음)
	- 분기: 미입력 타임아웃 → 종료 처리
	- 분기: 비속어 검출 시 안내 팝업 → 3회(잠정) 위반 시 종료 처리
	- 분기: 그만두기 선택 시 확인 팝업 → 확정 시 종료 처리

#### 2) 이름 랜덤 입력

- **역할**: 사전 작성한 이름 목록에서 하나를 뽑아 이름 입력 필드를 채우는 보조 입력 수단. 유저가 이름을 직접 떠올리지 않아도 바로 시작하게 함
- **동작**
	- 유저가 랜덤 입력 버튼을 터치하면 사전 이름 목록에서 하나를 랜덤으로 골라 이름 입력 필드에 표시함
	- 직전과 같은 이름을 연속으로 뽑지 않게 하는 중복 회피 적용
	- 현재 언어(세션 데이터)에 맞는 이름 텍스트를 표시함
	- 채워진 이름은 일반 입력과 동일하게 다룸: 그대로 다음으로 넘기거나, 가상 키보드로 편집하거나, 랜덤 입력을 다시 눌러 바꿀 수 있음(반복 가능)
- **이름 목록**
	- 사전 작성하고 검수해 고정한 이름 풀(character_name_pool.json). 언어별로 마련해 현재 언어에 맞는 텍스트를 제공함
	- 목록 이름은 비속어 필터와 길이 상한(20자)을 이미 통과하도록 사전 검수함. 랜덤 채움만으로는 유효성 위반이 생기지 않음
	- 유저가 채워진 이름을 편집하면 일반 입력이 되어, 다음으로 넘길 때 유효성 검증을 그대로 받음

## 4.4 Step 4. 플롯 문답

본 절의 진행 단위(말뚝이 문답 화면부터 세션 저장까지)는 배정된 플롯의 4컷(기/승/전/결)을 순서대로 반복함.

### 4.4.1 클라이언트: 말뚝이 문답 화면

#### 1) 진행

- 컷별 사전 질문을 표시하고 유저 응답 입력 확정 시 다음 단계 진행
	- 가상 키보드를 기본으로 제공하고 음성 인식(STT) 입력 병행
	- 길이 상한(50자)은 입력 단계에서 막음(팝업 없음)
	- 분기: 미입력 타임아웃 → 종료 처리
	- 분기: 비속어 검출 시 안내 팝업 → 3회(잠정) 위반 시 종료 처리
	- 분기: 음성 인식 실패 시 안내 팝업 후 가상 키보드로 계속 입력받음
	- 분기: 그만두기 선택 시 확인 팝업 → 확정 시 종료 처리

### 4.4.2 서버: 유저 응답 가드레일

#### 1) 진행

- AI 가드레일 런타임 입력 검사 실행
	- 호출 주체: 클라이언트가 응답을 서버로 보내고, 서버가 외부 서비스 호출 래퍼([[#5.1 운영 파라미터]] 가드레일 호출)로 가드레일 입력 검사를 호출함
	- 응답 전송: 검사를 위해 컷별 응답을 서버로 보냄. 이는 서비스 호출이라 세션 데이터 전송과 별개이며, 응답 정본은 클라이언트에 남아 생성 입력으로 Step 5에서 전송함([[#3.1 세션 데이터]] 서버 전송 시점)
	- 분기: 위반 시 안내 팝업 → 3회(잠정) 위반 시 종료 처리
	- 분기: 가드레일 호출이 재시도 한도를 넘기면 안내 팝업 → 위반 횟수에 세지 않고 재입력 받음

### 4.4.3 클라이언트: 세션 저장

#### 1) 진행

- 세션 데이터에 진행 상황과 응답 내용을 누적 저장

## 4.5 Step 5. 결과물 생성과 대기 화면 (병행)

백그라운드 생성과 포그라운드 대기가 동시 진행되고 상태 조회로 동기화됨.

### 4.5.1 서버: 결과물 생성 (백그라운드)

#### 1) 진행

- **생성 입력 전송 (클라이언트)**: 클라이언트가 Step 5 진입 시 생성 입력(캐릭터 정보, 컷별 응답, 현재 언어)을 서버로 전송해 생성을 트리거함
- **배정 플롯 로드 (서버)**: 생성은 Step 2에서 서버 세션에 저장한 배정 플롯을 함께 입력으로 씀([[#4.2 Step 2. 세부 유형 선택]] 플롯 배정). 클라이언트 전송 입력에 플롯을 다시 싣지 않고 세션 ID로 조회함. 배정 플롯이 없거나 세션과 어긋나면 생성을 트리거하지 않고 실패 처리함(중단, 에러 유형 기록)
- **생성 파이프라인 (서버)**
	1. 유저 입력 가공 LLM: 응답을 컷별 장면 묘사와 말풍선 대사로 변환
		- 분기: 호출 실패 시 재시도(2회 잠정), 한도 초과 시 상태 `failed` 전환
	2. 4컷 만화 이미지 생성 모델: 장면 묘사로 컷별 만화 이미지 생성
		- 분기: 호출 실패 시 재시도(2회 잠정), 한도 초과 시 상태 `failed` 전환
	3. AI 가드레일: 생성물(만화 이미지, 대사) 출력 검사
		- 분기: 위반 시 1로 재생성 (한도 3회, 잠정). 한도 초과 시 위험물 파기, 상태 `failed` 전환
		- 분기: 검사 호출 실패 시 통과로 보지 않고 재시도(2회 잠정), 한도 초과 시 상태 `failed` 전환
	4. 결과물 조립: 컷 이미지와 말풍선 대사를 4컷 만화 한 편으로 결합
		- 분기: 조립 실패 시 재시도(2회 잠정), 한도 초과 시 상태 `failed` 전환
	5. 결과물 호스팅: 조립한 결과물을 웹에 호스팅하고 만료형 다운로드 URL(48시간, 잠정)을 발급. Step 7이 이 URL로 QR을 만듦
		- 분기: 업로드나 호스팅, URL 발급 실패 시 재시도(2회 잠정), 한도 초과 시 상태 `failed` 전환
	6. 결과물과 다운로드 URL을 서버 세션에 저장하고(생성 완료 이벤트) 클라이언트 세션 데이터에 반영
- **실패(생성 단계 공통)**
	- 어느 단계에서 `failed`가 됐는지를 세션 데이터의 에러 유형에 기록함. 포그라운드 상태 조회가 `failed`를 검출하면 그 케이스의 상황 안내 팝업을 띄우고 종료 처리함
	- 재시도 2회(잠정), 상태 조회 주기 2초(잠정)
- **상태 머신**
	- `generating` / `completed`(가드레일 통과분을 호스팅하고 다운로드 URL까지 받은 상태) / `failed`(생성 실패, 가드레일 한도 초과, 호스팅 영구 실패)

#### 2) 유저 입력 가공 LLM

##### (1) 역할과 목적

유저의 컷별 응답을 말뚝이 화법의 장면과 대사로 바꾸는 런타임 엔진. 사전 고정 플롯 위에 유저 입력을 녹여 매번 다른 4컷 만화 본문을 만듦.

##### (2) 동작과 규칙

응답을 말뚝이 풍자 화법에 녹여 컷별 장면과 대사를 현재 언어로 생성함. 이름과 캐릭터는 슬롯 치환 수준으로 개인화하고, 사전 생성 플롯의 컷 컨텍스트를 따름.

##### (3) 기술 요건

- **모델 확보**: 생성형 LLM. 외부 API나 사전학습 모델 우선 검토(확인 필요)
- **판정 기준**: 장면 일관성, 응답 시간(대기 구간에 영향). 정량 미정
- **적용**: 서버 백그라운드 배치. Step 5에서 호출

##### (4) 필요 리소스

말뚝이 화법과 컷 문법, 사전 생성 풍자 플롯(풍자 플롯 생성 LLM).

##### (5) 실패와 복구

생성 장면과 대사는 출력 가드레일 검사를 받음. 호출이 재시도 한도(2회 잠정)를 넘겨 실패하거나 가드레일 재생성 한도(3회 잠정)를 넘기면 생성 파이프라인의 `failed` 처리로 이어짐. 두 경우는 원인이 달라 세션 데이터에 따로 기록함.

#### 3) 4컷 만화 이미지 생성 모델

##### (1) 역할과 목적

컷별 장면을 만화 양식 이미지로 시각화하는 런타임 엔진. 탈 캐릭터의 시각 정체성을 레퍼런스로 고정해, 4컷이 한 편으로 읽히는 룩을 갖게 함.

##### (2) 동작과 규칙

장면 묘사에 맞춰 만화 양식 이미지를 생성함. 세션의 캐릭터 정보(연령대 × 성별)로 유저 탈 캐릭터 레퍼런스를 고르고, 그 시각 정체성과 덧뵈기 탈 양식을 레퍼런스로 고정해 컷 사이 캐릭터 일관성을 유지함.

##### (3) 기술 요건

- **모델 확보**: 이미지 생성 모델. 사전학습 모델이나 외부 API 우선 검토(확인 필요)
- **판정 기준**: 인물 일관성, 양식 정합, 생성 시간. 정량 미정
- **적용**: 서버 백그라운드 배치. Step 5에서 호출
- **인물 일관성 메커니즘 (아트팀 협의 확정)**: 세 후보를 비교해 고름. 선택에 따라 캐릭터 자산의 산출물 형태와 수량, 공수가 정해짐

| 메커니즘 | 발주 산출물 | 인물 일관성 | 제작 공수 | 비고 |
|---|---|---|---|---|
| 프롬프트와 스타일 토큰 | 인물별 묘사 프롬프트와 양식 예시 수 장 | 약함(컷 변동) | 낮음 | 빠르나 정체성이 흔들림 |
| IP-Adapter와 참조 이미지 | 인물별 참조 이미지 수 장(정면, 측면, 표정) | 중간 | 중간 | 학습 불필요, 런타임 조건화 |
| LoRA와 파인튜닝 | 인물별 학습 데이터셋 수십에서 수백 장(태깅)과 학습 | 강함 | 높음 | 인물 수가 많을수록 학습 부담이 커짐 |

##### (4) 필요 리소스

- 덧뵈기 배역 탈 레퍼런스(말뚝이, 양반 등. 종수 확인 필요, 소재 원본 보강 예정)
- 유저 탈 캐릭터 레퍼런스(연령대 × 성별 6종)
- 만화 시각 양식 가이드(선화, 색감, 컷 연출 정의)

##### (5) 실패와 복구

생성 이미지는 출력 가드레일 검사를 받음. 호출이 재시도 한도(2회 잠정)를 넘겨 실패하거나 가드레일 재생성 한도(3회 잠정)를 넘기면 생성 파이프라인의 `failed` 처리로 이어짐.

#### 4) 결과물 조립

##### (1) 역할과 목적

컷별 이미지와 대사를 4컷 만화 한 편으로 묶는 비-AI 오케스트레이션. 흩어진 생성물을 유저가 받는 최종 산출물로 조립함.

##### (2) 동작과 규칙

컷 순서대로 이미지를 4칸 레이아웃에 배치하고 말풍선 대사를 얹어 조립하고 저장함. 출력 가드레일 통과분만 저장함. 형식(이미지 묶음, PDF)은 미정임.

##### (3) 기술 요건

- **모델 확보**: AI 모델을 쓰지 않는 서버 결합 로직임
- **판정 기준**: 말풍선 조판과 컷 레이아웃 규격에 맞게 조립되는가. 규격은 작성 예정

##### (4) 필요 리소스

4컷 레이아웃 프레임과 말풍선 양식.

##### (5) 실패와 복구

조립 전 출력 가드레일 검사를 거침. 조립 자체가 실패하면 재시도(2회 잠정) 뒤 `failed`로 보냄.

### 4.5.2 클라이언트: 대기 화면 (포그라운드)

#### 1) 진행

- 대기 콘텐츠 노출(덧뵈기 소개 영상 등)
- 서버 상태 조회(주기 2초, 잠정). 두 타임아웃 미적용
- 분기: `generating` → 대기 유지 / `completed` → 즉시 Step 6 / `failed` → 상황 안내 팝업 → 종료 처리 / 상태 조회 연속 3회 무응답(잠정) → 상황 안내 팝업 → 종료 처리

## 4.6 Step 6. 결과물 감상

완성된 4컷 만화를 감상하는 화면임. 받기(QR)는 완주 뒤 Step 7 마무리 인사 화면에서 함. 호스팅과 다운로드 URL 발급은 Step 5에서 이미 끝냄.

### 4.6.1 클라이언트: 결과물 감상 화면

#### 1) 진행

- 4컷 만화를 크게 보여주고 컷 확대와 넘김을 지원함. 마침 터치 시 완주로 보고 Step 7 마무리 인사 화면으로 진행함(받기는 그 화면에서 QR로 함, [[#4.7 Step 7. 종료와 리셋]])
	- 분기: 화면 타임아웃(300초, 잠정) → 완주로 보고 Step 7 마무리 인사 화면으로 진행([[시범콘텐츠 공통 사양#5.4 결과물 감상]])

## 4.7 Step 7. 종료와 리셋

완주와 비완주 두 경로로 진입함. 완주(Step 6에서 마침 터치 또는 화면 타임아웃으로 정상 진행)만 마무리 인사 화면을 거치고, 비완주 종료(그만두기, 터치 미입력 타임아웃, 미동의, 비속어나 입력 가드레일 위반 한도 초과, 실패 중단)는 마무리 인사 화면을 건너뛰고 곧장 세션 종료와 파기로 감.

### 4.7.1 클라이언트: 마무리 인사 화면

호스팅과 다운로드 URL 발급은 Step 5에서 이미 끝냈으므로, 이 화면은 그 URL로 QR을 그려 받기를 겸함.

#### 1) 진행

- 완주로 진입한 경우에만 표시함. 말뚝이의 마무리 인사와 함께 QR을 띄워 유저가 결과물을 받게 함. 스캔을 마친 유저가 곧장 나가도록 "처음으로" 버튼을 둠
	- QR: Step 5가 발급한 다운로드 URL을 인코딩해 표시하고, 스캔 안내와 다운로드 가능 기간(48시간, 잠정)을 함께 보여줌. 유저가 본인 휴대폰으로 스캔해 4컷 만화를 받음
	- 분기: 처음으로 버튼 터치 또는 화면 타임아웃(기본 60초, 잠정) → 다음 단계 진행

### 4.7.2 클라이언트: 종료 전송과 리셋

#### 1) 진행

- 종료 이벤트(완주 또는 이탈 결과)를 서버로 전송한 뒤 클라이언트 세션 데이터를 초기화하고 종료함
	- 완주는 유형(마침 터치, 감상 화면 타임아웃)을 구분해 기록함: 완주율 관측에서 방치 완주를 분리함
	- 완주와 비완주 종료가 모두 모이는 종착점임. 비완주 종료는 마무리 인사 화면을 건너뛰고 여기로 바로 들어옴
	- 진행 중 관리 데이터(진행 Step, 에러 유형, 동의 기록)는 이벤트로 이미 전송됐으므로([[#3.1 세션 데이터]] 서버 전송 시점), 이 단계는 종료 결과 전송이지 세션 전체를 몰아 저장하는 시점이 아님

### 4.7.3 서버: 세션 종료 확정

#### 1) 진행

- 클라이언트가 보낸 종료 이벤트를 받아 세션을 종료 상태로 확정함
	- 세션 데이터는 보관 정책([[#3.1 세션 데이터]] 보관 기간)에 따라 관리함(콘텐츠 데이터 30일, 컷별 응답 14일, 잠정)
	- 호스팅한 결과물은 다운로드 만료(48시간, 잠정)까지 유지함
	- 완주와 비완주 종료 모두 같은 종료 이벤트 경로로 확정함

## 5.2 에러 케이스

### 5.2.1 케이스 목록과 처리

**처리**는 그 실패가 세션을 어떻게 만드는지고, **원인**은 실패가 누구에게서 비롯되었는지임. 원인이 외부 서비스나 시스템일 경우에만 운영 알림을 보냄. 갈래를 나누는 판정 규칙은 실패 처리 시스템에 있고, 본 표는 그 규칙을 케이스에 적용한 결과임. 이후 동작의 Step 7은 모두 비완주 종료라 마무리 인사 화면을 건너뛰고 세션 종료와 파기 후 시작 화면으로 복귀함.

| 발생 지점 | 처리 | 원인 | 팝업 | 이후 동작 |
|---|---|---|---|---|
| 비속어 필터 검출 | 재입력 | 유저 | 위반 안내 | 같은 화면 재입력, 3회(잠정) 위반 시 종료 |
| 입력 가드레일 위반 검출 | 재입력 | 유저 | 위반 안내 | 같은 화면 재입력, 3회(잠정) 위반 시 종료 |
| 입력 가드레일 호출 실패 | 재입력 | 외부 서비스 | 안내 | 같은 화면 재입력, 위반 횟수에 세지 않음 |
| 입력 가드레일 호출 3회(잠정) 연속 실패 | 중단 | 외부 서비스 | 상황 안내 | Step 7 |
| 음성 인식(STT) 실패 | 대체 입력 | 외부 서비스 | 안내 | 가상 키보드로 계속 입력, 종료 없음 |
| 말뚝이 발화 실패 | 기능 축소 | 시스템 | 없음 | 세션 계속, 대표 이미지와 텍스트로 진행 |
| 세션 생성 실패 | 중단 | 시스템 | 상황 안내 | 시작 화면 복귀 |
| 플롯 배정 실패 | 중단 | 시스템 | 상황 안내 | Step 7 |
| 유저 입력 가공 LLM 호출 실패 | 중단 | 외부 서비스 | 상황 안내 | Step 7, 생성물 파기 |
| 이미지 생성 모델 호출 실패 | 중단 | 외부 서비스 | 상황 안내 | Step 7, 생성물 파기 |
| 출력 가드레일 재생성 한도 초과 | 중단 | 시스템 | 상황 안내 | Step 7, 위험물 파기 |
| 출력 가드레일 호출 실패 | 중단 | 외부 서비스 | 상황 안내 | Step 7, 생성물 파기 |
| 결과물 조립 실패 | 중단 | 시스템 | 상황 안내 | Step 7, 생성물 파기 |
| 결과물 호스팅과 URL 발급 실패 | 중단 | 외부 서비스 | 상황 안내 | Step 7, 생성물 파기 |
| 상태 조회 3회(잠정) 연속 무응답 | 중단 | 시스템 | 상황 안내 | Step 7, 생성물 파기 |
