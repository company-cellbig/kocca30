> 덧뵈기(탈춤)의 양반 풍자를 소재로, 유저가 풍자 템플릿(양반 놀리기 등)에 답을 채우면 자기 탈 캐릭터가 등장하는 4컷 만화를 AI가 만들어 주는 생성형 시범콘텐츠 개발 문서. 유저가 캐릭터 정보를 정하고 말뚝이가 던지는 풍자 플롯 질문에 답하면, 그 답으로 4컷 만화 한 편을 생성해 전송함. [[콘텐츠 기획서 작성 양식]] 적용. 골격 단계로 점차 채움.

# 1. 개요

- **콘텐츠 정의**: 덧뵈기(탈춤)의 양반 풍자를 소재로 한 AI 4컷 만화 생성 콘텐츠. 유저가 풍자 플롯 질문에 답하면 자기 탈 캐릭터가 주인공인 4컷 만화 한 편을 완성함
- **소재**: 남사당놀이 탈놀음 덧뵈기 ([[덧뵈기]])
- **유형**: 생성. 입력에서 완성 결과물(4컷 만화)로 가는 생성이 핵심 산출임 ([[콘셉트 정리#3. 전체 구조 정리]])
- **목표 경험**: 덧뵈기의 풍자 골격(양반 풍자, 말뚝이의 재담식 조롱)은 고정하고, 그 안의 사건과 대사를 유저 입력과 AI 생성으로 채워 매번 다른 4컷 만화를 만듦
- **핵심 메커닉**: AI가 풍자 템플릿(양반 놀리기 등)별 플롯을 사전 생성해 두고, 유저가 템플릿을 고르면 그 템플릿의 컷별 질문에 답해 4컷 만화를 채움 (상세 §4.가 풍자 플롯 구조)
- **플랫폼과 세션**: 키오스크 (16:9 가로형 터치, 1인 사용. [[콘셉트 정리#가. 키오스크]]). 카메라는 쓰지 않고 카드 선택과 텍스트 입력만 받음. 키보드 입력이 불편하면 음성 인식(STT) 병행. 목표 플레이타임은 확인 필요(콘셉트와 로드맵 원문 미명시, 임의 추정 금지)
- **사용자 연속성 (1차연도)**: 익명 1회성으로 운영함(결과물 전송 후 파기). 학습 프로필과 이어하기, 콘텐츠 횡단 누적은 2차연도로 둠 (상세 §5.나 개인정보와 연속성)

# 2. 세션 개요

세션을 한눈에 파악하는 절. 세션 정의와 흐름을 담고, 세션 데이터 상세는 §5.가 세션과 데이터, Step별 상세 명세는 §3 Step 상세에 둠.

## 가. 세션 정의

1회 완결로 자기 탈 캐릭터가 주인공인 4컷 만화 한 편을 만드는 세션임. 컨테이너 정의와 라이프사이클은 공통 정의를 따름.

![[시범콘텐츠 공통 사양#^session-def]]

## 나. 세션 흐름

Step 1 인트로 → Step 2 캐릭터 정보 입력 → Step 3 풍자 템플릿 선택과 플롯 문답 → Step 4 결과물 생성과 대기 화면(병행) → Step 5 결과물 표시(4컷 만화) → Step 6 결과물 전송 → Step 7 종료와 리셋

- **분기**: 대부분 이탈(미동의, 터치 미입력 타임아웃)로 Step 7 직행, 생성 실패는 사과 화면 후 Step 7
- **병행**: Step 4에서 백그라운드 결과물 생성과 포그라운드 대기 화면이 동시 진행
- **파기**: Step 6 전송 후 연락처 즉시 파기, Step 7 종료 시 세션 임시 데이터 파기

## 다. Step별 흐름

상세 레이아웃과 화면 확정은 [[덧뵈기 - 양반 놀리기 4컷 UI]] 소관임. 상세 동작과 규칙은 §4 구성 요소에 둠.

### 1) Step 1. 인트로 (시작 + 동의)

- **트리거**: 유저가 시작 버튼 터치
- **시스템**: 클라이언트 UI (§5.다 5 클라이언트 UI), 백엔드 (§5.다 3 백엔드)
- **화면 흐름**: 시작 화면 → 가이드 화면 → 동의 약관 화면
- **프로세스**
	1. 백엔드: 신규 세션 생성
	2. UI(시작 화면): 시작 안내 표시, 시작 터치 감지
	3. UI(가이드 화면): 진행 흐름 안내
	4. UI(동의 약관 화면): 약관과 동의 토글 표시, 동의 입력 감지 (화면 타임아웃 미적용)
		- 호출 공용 기능: 터치 미입력 타임아웃
		- 분기: 터치 미입력 타임아웃 발동 시 미동의로 간주 → Step 7 직행 (별도 거부 버튼 없음)
	5. 백엔드: 동의 기록 저장 (세션 ID, 약관 버전, 타임스탬프)
- **동의 항목**: 결과물 전송용 개인정보 안내(연락처). 카메라 촬영 없음
- **입력**: 터치 이벤트, 동의 결정
- **출력**: 세션 ID, 동의 기록
- **다음**: Step 2

### 2) Step 2. 캐릭터 정보 입력

- **트리거**: Step 1 동의 완료
- **시스템**: 클라이언트 UI (§5.다 5 클라이언트 UI), 백엔드 (§5.다 3 백엔드)
- **화면 흐름**: 이름 입력 화면 → 캐릭터 카드 선택 화면
- **프로세스**
	1. UI(이름 입력 화면): 이름 입력 수집 (유저 주인공 설정. §4.가 5) 변주의 유저 입력 슬롯과 연동)
	2. UI(이름 입력 화면): 이름 유효성 검증 (클라이언트 비속어 필터)
		- 호출 공용 기능: 입력 유효성 검증
		- 분기: 비속어 검출 시 팝업 안내 → sub-step 1로 재진입
	3. UI(캐릭터 카드 선택 화면): 8개 카드(아이/청소년/청년/장년 × 남/여) 중 1개 선택 수집
		- 호출 공용 기능: 터치 미입력 타임아웃 (이름과 카드 모두 필수 입력 화면, 화면 타임아웃 미적용)
		- 분기: 터치 미입력 타임아웃 → Step 7 직행
	4. 백엔드: 세션에 캐릭터 정보 저장
- **입력**: 이름, 카드 선택(성별 × 연령대)
- **출력**: 세션 캐릭터 정보 갱신
- **다음**: Step 3

### 3) Step 3. 풍자 템플릿 선택과 플롯 문답 (컷별 반복)

- **트리거**: 캐릭터 정보 입력 완료
- **시스템**: AI 시스템 (§4.아 가드레일; 배정 플롯은 §4.나 풍자 플롯 생성 LLM 사전 산출물), 클라이언트 UI (§5.다 5 클라이언트 UI), 백엔드 (§5.다 3 백엔드)
- **화면 흐름**: 풍자 템플릿 선택 화면 → 말뚝이 문답 화면(컷별 반복)
- **프로세스**: 유저가 풍자 템플릿을 고르면 시스템이 그 템플릿 풀에서 랜덤 플롯을 배정(sub-step 1~2), 이후 배정된 플롯의 컷(기/승/전/결, §4.가 풍자 플롯 구조)을 순서대로 sub-step 3~5 묶음 반복
	1. UI(풍자 템플릿 선택 화면): 풍자 템플릿 카드 제시(양반 놀리기 등), 유저 선택 수집
		- 호출 공용 기능: 터치 미입력 타임아웃 (필수 입력 화면, 화면 타임아웃 미적용)
		- 분기: 터치 미입력 타임아웃 → Step 7 직행
	2. 백엔드: 선택 템플릿 풀에서 랜덤 플롯 1개 배정 (사전 생성과 검수된 플롯, §4.가 풍자 플롯 구조)
	3. UI(말뚝이): 말뚝이 캐릭터 + 해당 컷의 사전 생성 질문 표시(고정), 유저 응답 입력 받기 (가상 키보드 기본, 음성 인식(STT) 입력 병행 → 변환된 텍스트로 처리)
		- 호출 공용 기능: 터치 미입력 타임아웃 (필수 입력 화면, 화면 타임아웃 미적용)
		- 분기: 터치 미입력 타임아웃 → Step 7 직행
	4. AI 가드레일: 유저 응답 검사 (§4.아 AI 가드레일)
		- 호출 공용 기능: AI 가드레일
		- 분기: 위반 시 팝업 안내 → sub-step 3으로 재진입 (유저 재입력)
	5. 백엔드: 응답을 세션에 누적 저장
- **입력**: 풍자 템플릿 선택(유저), 컷별 응답(텍스트: 가상 키보드 또는 STT 음성)
- **출력**: 선택 템플릿과 배정 플롯, 컷별 응답 누적, 말뚝이 진행 대화 로그
- **다음**: 모든 컷 완료 시 Step 4

### 4) Step 4. 결과물 생성과 대기 화면 (병행)

- **트리거**: 플롯 문답 완료
- **시스템**: AI 시스템 (§4.다 유저 입력 가공 LLM~라 4컷 만화 이미지 생성 모델, §4.아 AI 가드레일), 백엔드 (§4.마 4컷 만화 결과물 조립, §5.다 3 백엔드), 클라이언트 UI (§5.다 5 클라이언트 UI), 외부 서비스 (§5.다 4 외부 서비스 연동)
- **화면 흐름**: 대기 화면. 결과물 생성은 백그라운드라 화면 없음(실패 시 사과/에러 화면으로 Step 7)
- **프로세스** (백그라운드와 포그라운드 동시, 상태 조회로 동기화)
	- **백그라운드: 결과물 생성**
		1. 유저 입력 가공 LLM (§4.다 유저 입력 가공 LLM): 응답을 컷별 만화 장면과 대사 텍스트로 변환
		2. 4컷 만화 이미지 생성 모델 (§4.라 4컷 만화 이미지 생성 모델): 컷별 만화 이미지 생성(탈 캐릭터 등장)
		3. 결과물 조립 (§4.마 4컷 만화 결과물 조립): 컷 이미지와 말풍선 대사를 4컷 만화로 결합
		4. AI 가드레일 (§4.아 AI 가드레일): 생성물(만화 이미지와 대사) 출력 검사
			- 분기: 위반 시 sub-step 1로 재생성 (N회 한도). 한도 초과 시 상태 `failed`
		5. 백엔드: 검사 통과한 결과물을 저장소에 저장
		- 실패: AI 호출(LLM, 이미지 생성) 실패 시 재시도 N회(예: 2회) 후 `failed` 전환. 포그라운드 상태 조회가 검출 → 사과 화면 → Step 7. 구체 N과 상태 조회 주기는 §3.라 운영 파라미터
		- 백엔드 상태 머신: `generating` / `completed`(가드레일 통과분만) / `failed`(생성 실패 또는 가드레일 한도 초과)
	- **포그라운드: 대기 화면** ([[시범콘텐츠 공통 사양#다. 생성과 변환 대기]] 준용)
		1. UI(대기 화면): 대기 콘텐츠 노출(덧뵈기 소개 영상 §4.사 콘텐츠 자산, 또는 공개 동의분 큐레이션 결과물)
		2. UI(대기 화면): 백엔드 상태 조회 (주기는 §3.라 운영 파라미터)
			- 분기: `generating` → 대기 유지 / `completed` → 즉시 Step 5 / `failed` → 사과 화면 → Step 7 / 상태 조회 연속 무응답 임계 초과 → 에러 화면 → Step 7
- **입력**: 세션 응답 전체, 캐릭터 정보
- **출력**: 4컷 만화 파일
- **다음**: 포그라운드 상태 조회가 `completed`를 받으면 즉시 Step 5

### 5) Step 5. 결과물 표시 (4컷 만화)

- **트리거**: 4컷 만화 파일 생성 완료
- **시스템**: 클라이언트 UI (§5.다 5 클라이언트 UI), 백엔드 (§5.다 3 백엔드)
- **화면 흐름**: 결과물 감상/열람 화면
- **프로세스**
	1. UI(결과물 감상/열람 화면): 4컷 만화 표시
	2. UI(결과물 감상/열람 화면): 확대와 컷 넘김 인터랙션(터치) (터치 미입력 타임아웃 미적용)
		- 호출 공용 기능: 화면 타임아웃
		- 분기: 화면 타임아웃 발동 시 전송 단계(Step 6)로 정상 진행(감상 종료로 간주)
	3. UI(결과물 감상/열람 화면): "전송" 버튼 노출
- **입력**: 4컷 만화 파일
- **출력**: 유저가 결과물 확인
- **다음**: 유저가 "전송" 진행 → Step 6

### 6) Step 6. 결과물 전송

- **트리거**: 유저가 전송 안내 화면에서 진행
- **시스템**: 클라이언트 UI (§5.다 5 클라이언트 UI), 백엔드 (§5.다 3 백엔드), 외부 서비스 (§5.다 4 외부 서비스 연동)
- **화면 흐름**: 연락처 입력과 전송 화면
- **프로세스**
	1. UI(연락처 입력과 전송 화면): 연락처 입력 수집, 개인정보 수집 이용 안내 표시 (필수 입력 화면, 화면 타임아웃 미적용). 전송 탭이 곧 발송 동의, 받지 않기 탭이 거부임(별도 동의 토글 없음)
		- 호출 공용 기능: 입력 유효성 검증, 터치 미입력 타임아웃
		- 분기: 전송 거부 시 SMS 단계 생략 → Step 7
		- 분기: 터치 미입력 타임아웃 발동 시 유저 이탈로 보고 연락처 즉시 파기 → Step 7 직행
	2. 백엔드: 연락처 임시 저장 (개인정보 처리 §5.나 개인정보와 연속성)
	3. 외부 서비스 SMS: 결과물 호스팅 URL이나 이미지 전송
		- 호출 공용 기능: 외부 서비스 호출 래퍼
		- 분기(실패 유형별): 일시 장애 → 재시도 N회(§3.라 운영 파라미터) / 수신 번호 영구 실패 → 재입력 1회 허용 후 Step 7 / 그 외 영구 실패 → 사과 후 Step 7 + 운영 알림
	4. 외부 서비스(SMS): 발송 직후 연락처 즉시 파기 ([[시범콘텐츠 공통 사양#라. 결과물 전송]] 준용)
- **입력**: 연락처, 전송과 받지 않기 선택(= 발송 동의와 거부)
- **출력**: SMS 발송 결과
- **다음**: Step 7

### 7) Step 7. 종료와 리셋

- **트리거**: 결과물 전송 완료, 미동의, 또는 터치 미입력 타임아웃(유저 이탈)
- **시스템**: 클라이언트 UI (§5.다 5 클라이언트 UI), 백엔드 (§5.다 3 백엔드)
- **화면 흐름**: 마무리 인사 화면 → 시작 화면 복귀(Step 1과 공유)
- **프로세스**
	1. UI(마무리 인사 화면): 마무리 인사 표시
	2. 백엔드: 세션 종료, 임시 데이터 파기 (연락처 잔류 시 즉시 파기 = 백스톱. 콘텐츠 데이터 보관 정책은 §5.나 개인정보와 연속성)
	3. UI(시작 화면): 시작 화면 복귀 (다음 유저 대기)
- **입력**: 종료 트리거
- **출력**: 키오스크 idle 상태
- **다음**: 다음 유저용 Step 1 대기

# 4. 구성 요소

콘텐츠를 이루는 요소를 의존 순으로 배열함. 설계 골격(풍자 플롯 구조)을 먼저 두고, 그것을 쓰는 생성 엔진을 파이프라인 순으로, 이어 진행 호스트와 자산, 끝으로 전 단계를 가로지르는 가드레일을 둠. 생성 엔진(나~마)과 가드레일(아)은 역할과 목적, 입력과 출력, 동작과 규칙, 기술 요건, 자산 요구, 가드레일과 실패, 의존을 갖춘 독립 명세로 적음. 설계 골격(가), 진행 호스트(바), 자산(사)은 엔진이 아니라 설계와 연출과 자산 정의라 서술형으로 적음.

## 가. 풍자 플롯 구조

본 콘텐츠의 서사 골격. 모든 생성 엔진이 이 골격을 전제로 동작함.

### 1) 4컷 = 풍자 플롯 단위

- **4컷 정의**: 도입(기)부터 맺음(결)까지 하나의 풍자 줄기로 이어지는 4칸 만화. 마지막 컷에서 골계적 반전(풍자 대상의 허세나 위선이 들통나 무너짐)으로 맺음
- **한 세션 = 한 풍자 템플릿 = 한 편의 4컷 만화**
- **여러 템플릿 중 하나로 생성**: 4컷은 고정된 한 틀이 아니라 풍자 템플릿(양반 놀리기 등) 중 하나로 만들어짐. 각 템플릿은 자기 고유 풍자 초점을 가진 독립 완결 구조임. 1차연도 정의 템플릿과 그 수는 §8 미결(템플릿 로스터)
- **같은 틀, 다른 내용 (비고정 출력)**: 고정된 것은 틀(템플릿의 컷 골격)뿐. 세션마다 다른 결과는 두 축(사전 풀에서 랜덤 배정, 유저 입력)에서 나옴

### 2) 컷 공통 골격 (기-승-전-결)

모든 템플릿은 4컷 기승전결 골격을 공유함. 도입은 짧고, 갈등 고조와 골계적 반전에 무게가 실림.

| 컷 | 기능 | 적용 범위 |
|---|---|---|
| 기(도입) | 주인공(유저 탈 캐릭터)과 풍자 대상 등장, 상황 제시 | 모든 템플릿 공통 |
| 승(전개) | 선택된 템플릿의 갈등 고조(허세나 위선 부풀기) | 템플릿별 |
| 전(절정) | 유저의 한 수로 풍자 대상의 허점 노출 | 템플릿별 |
| 결(반전) | 골계적 추락과 맺음(말뚝이 조롱으로 마무리) | 모든 템플릿 공통 골계 |

- 유형별로 다른 것은 승과 전 2컷이며, 이것이 템플릿을 가름. 기와 결은 골계 골격을 공유함
- 주인공은 유저 탈 캐릭터이고 말뚝이는 풍자를 거드는 화자임 (§4.바 말뚝이 진행 호스트와 일치)

### 3) 유저 탈 캐릭터

- **정의**: 4컷 만화 주인공으로 등장하는 탈을 쓴 캐릭터. 유저를 대신하는 캐릭터로, 캐릭터 정보(연령대 × 성별 8종, §3.다 2) Step 2)로 개인화하고 시각은 덧뵈기 배역 탈 양식을 따름
- **해석 주의 (미결)**: 콘셉트 §4.다 2) 개요의 "사용자 탈을 쓴 캐릭터"를 유저가 직접 디자인한 탈이 아니라 캐릭터 정보로 개인화된 배역 탈 양식 캐릭터로 해석함. 콘셉트 진행에 탈 디자인 단계가 없어 이 해석을 기본값으로 두되, 별도 탈 디자인을 넣을지는 §8 미결(사용자 결정 대상)
- **시각 정체성**: 탈 양식 정합은 §4.라 이미지 생성 모델과 §4.아 가드레일이 §4.사 양식 가이드 기준으로 유지함

### 4) 생성과 제시와 채움 (사전 생성 + 런타임 선택)

풍자 플롯(컷별 질문 포함)은 사전 생성과 검수를 거치고, 런타임은 선택과 응답 수집만 함. 키오스크 무인 운영의 안전과 속도와 안정을 우선한 사전 생성 고정형 하이브리드 방식임 (§4.아 AI 가드레일, [[rfp_제안요청서#나. 연구 내용]] 검증위원회).

- **사전 생성**: 풍자 플롯 생성 LLM(§4.나 풍자 플롯 생성 LLM)으로 템플릿별 다수 플롯을 미리 생성함. 컷별 말뚝이 질문 텍스트까지 고정하고, 사전 가드레일 검수 후 풀에 저장함
- **유저 선택 (템플릿 단위)**: 유저는 풍자 템플릿 중 하나를 선택함(병렬 카드). 시스템이 그 템플릿 풀에서 랜덤으로 플롯 1개를 배정함. 런타임 선택 흐름과 타임아웃은 §3.다 3) Step 3
- **컷별 채움**: 주어진 플롯의 컷(기/승/전/결)을 순서대로 제시(고정 질문)하고 유저가 각 컷에 응답함. 이름과 캐릭터는 슬롯 치환 정도의 가벼운 개인화임
- **만화 생성**: 종료 후 유저 응답 전체를 토대로 컷별 장면과 대사, 이미지를 런타임 생성함(§3.다 4) Step 4, §4.다 유저 입력 가공 LLM)
- **다양성**: 풍자 템플릿 × 템플릿별 사전 풀 크기 × 유저 응답으로 같은 템플릿도 매번 다름

### 5) 변주

변주는 같은 틀(풍자 템플릿과 컷 골격)에 다른 내용(사건, 풍자 대상 형태, 대사)을 넣어 매번 다른 결과를 만드는 것임. 두 갈래에서 일어남.

- **유저 입력 슬롯**: 유저가 채운 입력이 만화 전개의 재료가 됨(원리: 추상화된 위선과 권위 자리를 유저 입력 소재로 채움). 슬롯은 이름(주인공), 템플릿 선택, 컷별 응답(기/승/전/결)
- **AI 질문 변주 (사전 생성)**: 같은 템플릿이라도 질문이 단조롭지 않게, 사전 생성 단계에서 템플릿 풀에 변주를 마련하고 런타임은 랜덤 선택함
	- 사건 형태: 컷 안 사건 컨텍스트 변주 (예: 잔칫집 / 길거리 / 관아)
	- 풍자 대상: 추상화된 권위와 위선 형태 변주 (예: 허세 양반 / 겉치레 / 권세 부리기)
	- 구현은 §4.나 풍자 플롯 생성에서 다양성 메커니즘 적용(prompt 변주, 사건 시드, temperature 조절 등). 사전 가드레일 검수로 §4.아 정책을 풀 전체에 일관 적용
- **변주와 일관성**: 위 차원만 변주하고 컷 공통 골격과 템플릿의 고정 문법은 일관 유지함. 예: 결 컷은 항상 "골계적 추락 + 말뚝이 맺음" 골격을 지키고 그 안의 사건만 다양함
- **세부 설계 (작성 예정)**: 유저 응답에서 사건으로의 매핑 LLM 프롬프트, 템플릿 제시와 선택 로직, 풍자 사건 시드 풀 등

## 나. 풍자 플롯 생성 LLM (사전)

- **역할과 목적**: 풍자 플롯(컷별 장면 골격과 질문)을 사전 생성함. §4.바 말뚝이 진행 호스트의 화법을 적용함
- **입력과 출력**: 입력은 풍자 사건 시드와 말뚝이 페르소나, 컷 문법. 출력은 풍자 플롯 풀(서사 데이터, 텍스트와 JSON)로, 컷별 말뚝이 질문(고정)으로 묶인 완성 플롯(완제품, 런타임 배정 대상)임. 가드레일 검수를 거치고 §3.다 3) Step 3에서 랜덤 배정됨. 풀의 데이터 스키마(컷별 필드), 풀 크기와 버전, 저장과 조회 키(템플릿별), Step 3 소비 계약은 구현 단계에서 확정함(작성 예정). 풍자 사건 시드 풀은 별도 데이터 자산으로 작성 예정
- **동작과 규칙 (생성 4단계)**:
	1. 사건 구성: 풍자 사건 시드에서 기, 승, 결 사건을 골라 한 4컷의 사건 라인을 구성함. 전(절정)은 그 승의 해소로 생성함(승에서 전으로 인과 직결). 다양성은 플롯 수준으로, 한 템플릿당 여러 플롯을 승을 달리해 겹치지 않게 생성함
	2. 장면과 질문 생성: 사건을 말뚝이 재담 화법(§4.바 말뚝이 진행 호스트)으로 장면화하고, 유저(주인공)의 한 수를 묻는 질문을 생성함. 전 컷에서 유저 주도를 유도함. temperature는 0.7~0.9 (§3.라 운영 파라미터)
	3. AI 가드레일 사후 검사 (§4.아 AI 가드레일): 출력 장면과 질문이 가드레일 정책을 통과하는지 검사함
	4. 재생성과 확정: 위반 시 재시도(한도 §3.라 운영 파라미터). 통과분을 플롯에 고정해 풀에 저장함
- **기술 요건**: 생성형 대규모 언어 모델(LLM). 모델 확보는 외부 API나 사전학습 모델 우선 검토(후보 확인 필요). 판정 기준은 컷 문법 정합, 플롯 품질, 가드레일 통과율(정량 미정, 확인 필요). 사전 배치 생성이라 실시간이 아님. AI 모듈 명세 항목은 [[시범콘텐츠 공통 사양#가. AI 시스템]] 준용
- **자산 요구**: 풍자 사건 시드(작성 예정), 말뚝이 페르소나와 컷 문법(§4.바 말뚝이 진행 호스트, §4.가 풍자 플롯 구조)
- **가드레일과 실패**: 사전 플롯 검수가 가드레일 3지점 중 첫 지점임(§4.아 AI 가드레일). 재생성 한도 초과 시 해당 플롯을 폐기함(사전 단계라 유저 영향 없음)
- **의존**: 입력은 풍자 사건 시드(작성 예정)와 §4.가 풍자 플롯 구조. 출력 풍자 플롯 풀은 §3.다 3) Step 3 랜덤 배정과 §5.다 3 백엔드 진행 제어가 사용

## 다. 유저 입력 가공 LLM (런타임)

- **역할과 목적**: 유저의 컷별 응답을 컷별 만화 장면과 대사 텍스트로 변환함 (§3.다 4) Step 4 백그라운드)
- **입력과 출력**: 입력은 컷별 유저 응답과 캐릭터 정보(이름, 연령대, 성별). 출력은 컷별 장면 묘사와 말풍선 대사 텍스트
- **동작과 규칙**: 유저 응답을 말뚝이 풍자 화법(§4.바 말뚝이 진행 호스트)에 녹여 컷별 장면과 대사를 생성함. 이름과 캐릭터 설정은 슬롯 치환 수준의 가벼운 개인화임(§4.가 4 생성과 제시와 채움). 사전 생성 플롯의 컷 컨텍스트를 따름
- **기술 요건**: 생성형 LLM. 모델 확보는 외부 API나 사전학습 모델 우선 검토(후보 확인 필요). 판정 기준은 장면 일관성, 응답 시간(Step 4 대기 영향)(정량 미정, 확인 필요). 명세 항목은 [[시범콘텐츠 공통 사양#가. AI 시스템]] 준용
- **자산 요구**: 말뚝이 화법과 컷 문법(§4.바 말뚝이 진행 호스트, §4.가 풍자 플롯 구조), 사전 생성 풍자 플롯(§4.나 풍자 플롯 생성 LLM)
- **가드레일과 실패**: 생성 장면과 대사는 출력 가드레일(Step 4, §4.아 AI 가드레일) 대상임(유저 입력 삽입 안전 포함). 생성 실패 시 재시도 후 `failed` 전환(§3.다 4) Step 4, §3.라 운영 파라미터)
- **의존**: 입력은 §3.다 3) Step 3 유저 응답과 §4.나 풍자 플롯. 출력 장면과 대사는 §4.라 이미지 생성과 §4.마 결과물 조립이 사용

## 라. 4컷 만화 이미지 생성 모델 (런타임)

- **역할과 목적**: 탈 캐릭터가 등장하는 만화 양식 컷 이미지를 생성함. 탈 캐릭터 시각 정체성을 레퍼런스로 고정하고 양식을 통일함
- **입력과 출력**: 입력은 컷별 장면 묘사와 캐릭터 정보, 양식 레퍼런스(§4.사 콘텐츠 자산). 출력은 컷별 만화 이미지
- **동작과 규칙**: 컷별 장면 묘사에 맞춰 만화 양식 이미지를 생성함. 유저 탈 캐릭터의 시각 정체성과 덧뵈기 탈 양식을 레퍼런스로 고정함(§4.사 캐릭터 레퍼런스). 컷 간 캐릭터 일관성을 유지함
- **기술 요건**: 이미지 생성 모델. 인물 일관성 메커니즘은 §4.사 비교표(프롬프트, IP-Adapter, LoRA)로 아트팀 협의 확정. 모델 확보는 사전학습 이미지 생성 모델이나 외부 API 우선 검토(후보 확인 필요). 판정 기준은 인물 일관성, 양식 정합, 생성 시간(정량 미정, 확인 필요). 명세 항목은 [[시범콘텐츠 공통 사양#가. AI 시스템]] 준용
- **자산 요구**: 탈 캐릭터 레퍼런스, 만화 시각 양식 가이드(§4.사 콘텐츠 자산)
- **가드레일과 실패**: 생성 만화 이미지는 출력 가드레일(Step 4, §4.아 AI 가드레일) 대상임(이미지 안전과 전통 왜곡). 생성 실패 시 재시도 후 `failed` 전환(§3.다 4) Step 4, §3.라 운영 파라미터)
- **의존**: 입력은 §4.다 장면과 §4.사 레퍼런스. 출력 컷 이미지는 §4.마 결과물 조립이 사용

## 마. 4컷 만화 결과물 조립 (백엔드)

- **역할과 목적**: AI가 생성한 컷별 이미지와 대사를 4컷 만화 한 편으로 결합하는 비-AI 오케스트레이션임
- **입력과 출력**: 입력은 컷별 대사(§4.다 유저 입력 가공 LLM)와 컷별 이미지(§4.라 4컷 만화 이미지 생성 모델). 출력은 4컷 만화 파일과 메타(생성 시각 등)
- **동작과 규칙**: 컷 순서대로 이미지를 4칸 레이아웃에 배치하고 말풍선 대사를 얹어 4컷 만화를 조립하고 저장소에 저장함. 출력 가드레일(§4.아 AI 가드레일) 통과분만 저장함. 형식(이미지 묶음, PDF)은 미정
- **기술 요건**: 백엔드 결합과 저장 로직. AI 모델이 아닌 오케스트레이션 계층임(§5.다 3 백엔드). 말풍선 조판과 컷 레이아웃 규격은 작성 예정
- **자산 요구**: 4컷 레이아웃 프레임과 말풍선 양식(§4.사 콘텐츠 자산)
- **가드레일과 실패**: 조립 전 출력 가드레일 검사를 거침. AI 생성 실패나 가드레일 한도 초과 시 `failed` 경로로 합류(§3.다 4) Step 4)
- **의존**: 입력은 §4.다 유저 입력 가공 LLM, §4.라 4컷 만화 이미지 생성 모델. 출력 4컷 만화는 §3.다 5) Step 5 표시와 §3.다 6) Step 6 전송이 사용

## 바. 말뚝이 진행 호스트

본 콘텐츠의 정체성 중심. 유저 탈 캐릭터가 주인공으로 만화 중심에 서고, 풍자 진행을 말뚝이가 재담과 조롱으로 엮음. 공통 골격은 [[시범콘텐츠 공통 사양#6. 진행 호스트]]를 따르고, 아래는 말뚝이 고유 페르소나임.

- **역할과 목적**: 양반을 놀리는 탈춤 풍자의 화자. 유저가 사건 주인공이고 말뚝이는 그 풍자를 거들고 맺는 화자임 (덧뵈기 말뚝이 배역 계승, [[덧뵈기 - 나만의 탈춤 기획서#바. 말뚝이 진행 호스트]]와 일치)
- **동작과 규칙(화법)**: 양반을 재담으로 조롱하는 말뚝이 화법. 컷별 질문 제시와 결 컷 맺음 조롱을 맡음. 세부 페르소나(말투, 어휘, 반응 패턴)는 작성 예정. 말뚝이 배역 해석은 [[덧뵈기]] 작성 후 검증(확인 필요)
- **자산 요구**: 말뚝이 캐릭터 비주얼(시각 정체성 고정, §4.사 콘텐츠 자산), 음성과 대사([[시범콘텐츠 공통 사양#6. 진행 호스트]] 에셋 요구 준용)
- **의존**: §4.나 풍자 플롯 생성 LLM과 §4.다 LLM이 말뚝이 화법을 적용. 렌더링은 §5.다 5 클라이언트 UI

## 사. 콘텐츠 자산

본 콘텐츠 제작에 필요한 자산 목록(발주와 견적 입력). 산출 방식과 호스팅은 §5 공유 계층과 기술 구성을 따름.

분류별 용도: 캐릭터 레퍼런스와 양식 가이드는 생성 레퍼런스(이미지 모델 conditioning). 운영 영상은 실사용(비출력, 만화 미포함). 엔진 서사 데이터는 풍자 사건 시드(입력, 작성 예정)와 풍자 플롯 풀(출력, §4.나 풍자 플롯 생성 LLM)을 참조.

| 자산 | 분류 (산출물) | 비고 |
|---|---|---|
| 덧뵈기 배역 탈 (전체) | 캐릭터 레퍼런스 | 말뚝이, 양반 등 탈 양식. 종수 확인 필요, [[덧뵈기]] 작성 후 보강 |
| 유저 탈 캐릭터 | 캐릭터 레퍼런스 | 연령 × 성별 8종 (§3.다 2) Step 2). 탈 양식 적용 |
| 만화 시각 양식 가이드 | 양식 가이드 (아트 디렉션 문서와 예시) | 탈춤 만화 양식(선화, 색감, 컷 연출) 정의 |
| 4컷 레이아웃 프레임과 말풍선 양식 | 출력 양식 | 4칸 배치 프레임, 말풍선 조판 (§4.마 결과물 조립) |
| 대기 화면 영상 | 운영 영상 (영상 파일) | 덧뵈기 소개. 제작 방식 확인 필요(실사, 애니, AI) |

### 1) 캐릭터 레퍼런스

- **대상**: 만화에 등장하는 탈 캐릭터(유저 탈 캐릭터, 말뚝이, 양반 등)가 시각 정체성 고정(레퍼런스) 대상임. 유저 탈 캐릭터 8종(§3.다 2) Step 2)은 캐릭터 정보로 개인화함
- **시각과 서사 분리**: 풍자 대상의 추상화(§4.아 AI 가드레일)는 서사 차원임. 시각은 덧뵈기 배역 탈 양식을 레퍼런스로 유지함
- **종수 (미확정)**: 배역 탈 목록과 종수는 확인 필요. [[덧뵈기]] 보강 후 종수를 확정함. 종수 미확정이라 아래 메커니즘과 견적은 잠정임
- **산출물 형태 (미확정)**: 참조 이미지 수 장 대 학습셋 수백 장은 일관성 메커니즘에 종속됨(아래 비교표, 아트팀 협의 확정)

캐릭터 레퍼런스를 매 컷 일관 생성하는 방법임. 선택에 따라 위 캐릭터 자산의 산출물 형태와 수량과 공수가 결정됨. 본 콘텐츠는 미정이며 아트팀과 협의해 확정함.

| 메커니즘 | 발주 산출물 | 인물 일관성 | 제작 공수 | 비고 |
|---|---|---|---|---|
| 프롬프트와 스타일 토큰 | 인물별 묘사 프롬프트 + 양식 예시 수 장 | 약함(컷 변동) | 낮음 | 빠르나 정체성 흔들림 |
| IP-Adapter와 참조 이미지 | 인물별 참조 이미지 수 장(정면, 측면, 표정) | 중간 | 중간 | 학습 불필요, 런타임 조건화 |
| LoRA와 파인튜닝 | 인물별 학습 데이터셋 수십~수백 장(태깅) + 학습 | 강함 | 높음 | 인물 수 많을수록 학습 부담 증가 |

## 아. AI 가드레일 (전 단계 횡단)

콘텐츠 정체성과 안전 정책을 정의하고 전 단계에 적용하는 횡단 모듈임.

- **역할과 목적**: 입력과 생성물 안전 검사. 가드레일 정책을 전 단계에 공통 적용함. 무인 운영에서는 사전 검사만으로 안전이 확보되지 않으므로 출력 단계에서도 반드시 검사함
- **입력과 출력**: 입력은 검사 대상(사전 플롯 텍스트, 유저 응답, 생성물 만화 이미지와 대사). 출력은 통과나 위반 판정, 위반 시 재생성이나 차단 트리거
- **동작과 규칙 (적용 3지점, 모두 필수)**:
	- 사전(운영 전 생성): 풍자 플롯 질문 생성 검수 (§4.나 풍자 플롯 생성 LLM)
	- 런타임 입력(Step 3): 유저 응답 검사
	- 런타임 출력(Step 4): 만화 생성물(이미지, 대사) 검사. 검사 항목은 유저 입력 삽입 안전, 전통 정체성 왜곡, 부적절 콘텐츠, 이미지 안전
- **풍자 추상화와 차단**: 양반 풍자 특성상 권력과 위선 풍자를 다루되 특정 실존 대상으로 흐르지 않게 추상화함

| 풍자 초점 | 차단 | 추상화 방향 |
|---|---|---|
| 권력과 계급 풍자(양반 놀리기) | 실제 정치인과 공공인물 풍자 | 추상화된 권위와 허세 |
| 위선 풍자 | 특정 실명과 단체 풍자 | 윤리적 위선(겉치레, 남 속이기 등) |
| 차별과 혐오 표현 | 성별, 지역, 종교 등 혐오 조장 | 보편 골계(권위의 허망한 추락) |

- **안전 체계와 외부 검증**: AI 가드레일과 인트로 동의 약관 절차를 둠. 가드레일 미탐 위험은 외부 검증위원회 자문으로 보완함 ([[rfp_제안요청서#나. 연구 내용]])
- **기술 요건**: 분류와 필터 모델에 자체 규칙을 결합함. 모델 확보는 외부 안전 API나 자체 규칙 우선 검토(후보 확인 필요). 판정 기준은 오탐율, 미탐율, 임계(정량 미정, 확인 필요)
- **자산 요구**: 가드레일 정책 정의, 차단과 추상화 매핑
- **가드레일과 실패**: 위반 시 재생성(한도 §3.라 운영 파라미터), 한도 초과 시 `failed`로 전환해 에러와 fallback 경로에 합류함(§3.다 Step별 흐름, §5.다 6 운영과 모니터링)
- **의존**: AI 모듈 전체(§4.나 풍자 플롯 생성 LLM~라 4컷 만화 이미지 생성 모델)의 입출력에 공통 적용. 실패 경로는 §3.다 Step별 흐름과 §5.다 6 운영과 모니터링
- **세부 정책 (작성 예정)**: 전통 왜곡 판정 기준, 부적절 콘텐츠 분류, 동의 약관 항목 구체화 등

# 5. 공유 계층과 기술 구성

세션, 개인정보, 기술 6영역의 공통 골격은 [[시범콘텐츠 공통 사양]]과 [[플랫폼 사양]]을 참조하고, 본 절은 콘텐츠 고유분만 둠.

## 가. 세션과 데이터

세션 정의는 §2.가 세션 정의, 라이프사이클과 공통 항목은 [[시범콘텐츠 공통 사양#2. 세션]]을 따름. 관리 모듈은 §5.다 3 백엔드임. 아래는 본 콘텐츠 고유 세션 데이터임.

아래는 본 콘텐츠의 세션 저장 데이터임. 콘텐츠 입력은 개인정보가 아니며(만화 생성용), 개인정보는 휴대폰 번호 단일임. 카메라를 쓰지 않아 얼굴 영상이 없음. 표는 어떤 값이 들어가는지까지만 적고, 타입과 저장 스키마 같은 구현 모델은 설계 단계에서 정함.

| 데이터 | 분류 | 들어가는 값과 구성 | 수명 | 비고 |
|---|---|---|---|---|
| 세션 ID | 시스템 | 세션마다 부여되는 고유 식별자 | 휘발 (세션 종료 시 파기) | Step 1에서 생성 |
| 동의 기록 | 시스템 | 약관 버전 + 동의 시각 | 보관 (§5.나 개인정보와 연속성, 잠정 5년) | 약관 버전 체계 운영 결정 |
| 캐릭터 정보 | 콘텐츠 입력 | 연령대(아이/청소년/청년/장년), 성별(남/여), 이름 | 확인 필요 (§8 미결) | 8개 카드 = 연령대 × 성별. 유저 주인공 설정 |
| 선택 템플릿 | 콘텐츠 입력 | 유저가 고른 풍자 템플릿 + 그 템플릿 풀에서 랜덤 배정된 플롯 | 확인 필요 (§8 미결) | §4.가 4) 생성과 제시와 채움 |
| 컷별 응답 | 콘텐츠 입력 | 컷별(기/승/전/결) 유저 응답, 순서대로 누적 | 확인 필요 (§8 미결) | 본편 응답 |
| 말뚝이 진행 대화 로그 | 콘텐츠 입력 | 컷별 말뚝이 질문 + 유저 응답 쌍 | 보관 (§5.나 개인정보와 연속성, 잠정 14일) | 디버깅과 품질 분석용 |
| 4컷 만화 결과물 | 콘텐츠 입력 | 4컷 만화 파일 + 메타(생성 시각 등) | 보관 (§5.나 개인정보와 연속성, 호스팅 잠정 30일) | 포맷 결정 미정 |
| 휴대폰 번호 | 개인정보 | 유저 연락처 (SMS 발송용) | 휘발 (발송 후 즉시 파기, 거부 시 즉시) | Step 6 전송 동의 시 임시 저장. 상세 §5.나 개인정보와 연속성 |

Step별 세션 동작: Step 1 생성, Step 2~Step 6 갱신, Step 7 종료와 임시 데이터 파기와 리셋.

## 나. 개인정보와 연속성

세션(1회 사용) 개인정보의 공통 원칙은 [[시범콘텐츠 공통 사양#8. 개인정보와 가드레일 원칙]]을 따르고, 아래는 본 콘텐츠 고유분임.

### 1) 개인정보 처리

- **개인정보 범위**: 휴대폰 번호 단일(Step 6 임시 저장). 캐릭터 정보, 응답, 대화 로그, 4컷 만화 결과물은 콘텐츠 데이터로 개인정보 영역 밖. 카메라를 쓰지 않아 얼굴 영상이 없음(덜미 유람기와 같은 낮은 민감도)
- **휴대폰 번호 처리**: "임시 저장"은 메모리만 쓰고 디스크 영속화와 로그 기록을 금지함. "즉시 파기"는 SMS 발송 응답 수신 직후(성공과 실패 무관) 메모리를 명시적으로 0으로 덮어쓰고 변수를 해제함
- **데이터 보관 기간 (잠정값, 규정 검토 후 확정)**: 동의 기록 5년, 4컷 만화 결과물 호스팅 30일, 말뚝이 대화 로그 14일 (§3.라 운영 파라미터)
- **동의 미보유 처리**: Step 1에서 세션이 생성되나 미동의(터치 미입력 타임아웃) 시 세션 전체를 즉시 파기함(동의 기록 미생성)
- **입력 유효성 백엔드 재검증**: Step 2 이름과 Step 6 연락처는 클라이언트 검증 외에 백엔드 재검증을 필수로 함(클라이언트 우회 대비)

### 2) 사용자 모델과 연속성

- **1차연도 사용자 모델**: 익명 1회성으로 운영함. 서버 누적은 결과물과 익명 통계뿐임([[플랫폼 사양#5. 사용자 모델 (1차연도)]])
- **2차연도 연속성**: 학습 프로필, 이어하기, 콘텐츠 횡단 누적은 2차연도로 둠([[플랫폼 사양#6. 2차연도 전방 설계 (디지털 도제 연속성, 현재 구현 밖)]])

## 다. 기술 구성

본 콘텐츠 구현 시스템을 영역별로 정리함. 영역 구분과 1차연도 공통 기술 방향(LLM, STT, 모션 인식 한계 등)은 [[시범콘텐츠 공통 사양#7. 기술 구성 (6영역 템플릿)]]을 따르고, 아래는 영역별 본 콘텐츠 구현 내용임.

### 1) AI 시스템

풍자 플롯 생성 LLM, 유저 입력 가공 LLM, 4컷 만화 이미지 생성 모델, AI 가드레일, 4컷 만화 결과물 조립으로 구성됨. 각 모듈 명세는 §4 구성 요소(§4.나 풍자 플롯 생성 LLM~마 4컷 만화 결과물 조립, §4.아 AI 가드레일)에서 다룸.

### 2) 하드웨어 (키오스크)

공통 키오스크 하드웨어를 씀(물리 사양 정본은 [[디바이스 사양]], 공통 골격은 [[시범콘텐츠 공통 사양#나. 하드웨어 (키오스크)]]). 본 콘텐츠가 쓰는 입출력은 터치 입력, 마이크(Step 3 컷 응답 STT), 음향 출력(인트로와 배경음, 말뚝이 음성)임. 카메라는 쓰지 않음.

### 3) 백엔드

키오스크와 AI 서버 통신, 세션 관리, 풍자 플롯 진행 제어(템플릿 선택 → 풀에서 랜덤 플롯 배정 → 컷 순차 제시, §4.가 4 생성과 제시와 채움), 결과물 저장소, 고객 동의 약관 관리(버전과 동의 기록). 결과물 조립은 §4.마 4컷 만화 결과물 조립, 개인정보 처리는 §5.나 개인정보와 연속성.

### 4) 외부 서비스 연동

SMS 발송 서비스, AI API(LLM, 이미지 생성), STT 서비스(음성 입력, Step 3), 결과물 호스팅(전송 링크 방식, 설계 미정).

### 5) 클라이언트 UI (키오스크 앱)

페이지 전환과 터치 인터랙션, 화면 흐름(§3.다 Step 1~Step 7 구현), 말뚝이 진행 호스트 렌더링(§4.바 말뚝이 진행 호스트), 입력 UI(가상 키보드와 음성, 카드 선택), 화면 타임아웃과 터치 미입력 타임아웃 처리와 리셋. 시각과 레이아웃 상세는 [[덧뵈기 - 양반 놀리기 4컷 UI]] 정본.

### 6) 운영과 모니터링

공통 항목(가동 상태, 사용 로그, 에러 fallback)은 [[시범콘텐츠 공통 사양#바. 운영과 모니터링]]을 준용함. 본 콘텐츠 고유로, 가드레일 한도 초과(`failed`) 시에도 에러와 fallback과 같은 경로로 합류함(§4.아 AI 가드레일).

# 6. 산출물

- **형식**: 컷별 이미지와 말풍선 대사로 묶은 4컷 만화. 유저 탈 캐릭터 시각 정체성 유지. 파일 형식(이미지 묶음, PDF)은 미정
- **4D 미연계**: 2D 만화 이미지와 텍스트 산출물로 한정함. 프로젝트 4D 코어와 분리된 산출물임
- **언어 범위**: 1차연도는 한국어 한정. 글로벌 실증은 2차연도 대비 대상
- 세부 규격은 작성 예정

# 7. 일정과 마일스톤 연계

- **개발 순서**: [[1차연도 셀빅 개발 준비자료#나. 콘텐츠 개발 순서]] 생성형 계열(LLM과 이미지 생성, 실시간 동작 없음. 덜미 유람기와 생성 스택 공유). 세부 일정과 마일스톤은 미정

# 8. 리스크와 검증

- **외부 검증**: 검증위원회 자문 ([[rfp_제안요청서#나. 연구 내용]])
- **저작권과 고증**: 덧뵈기 자체는 공유 자산이나 특정 보존회 대본이나 연출 차용 시 권리 확인이 필요함. 말뚝이와 양반 풍자 해석은 [[덧뵈기]] 작성 후 검증
- **미결 (유저 탈 캐릭터 해석)**: 콘셉트 "사용자 탈을 쓴 캐릭터"를 별도 탈 디자인 단계 없이 캐릭터 정보 개인화로 해석함(§4.가 3) 유저 탈 캐릭터). 별도 탈 디자인을 넣을지는 사용자 결정 대상
- **미결 (풍자 템플릿 로스터)**: 1차연도 풍자 템플릿 종류와 수가 미정. 콘셉트는 "양반 놀리기 등"만 명시함. 정의 템플릿 확정은 사용자 결정 대상
- **미결 (데이터 수명 정합, 확인 필요)**: 콘텐츠 입력 3종(캐릭터 정보, 선택 템플릿, 컷별 응답)의 파기 시점이 미정임. 세션 종료 시 임시 데이터로 파기할지, 결과물처럼 보관할지 [[시범콘텐츠 공통 사양]] 정본과의 정합이 안 됨(§5.가 표에 "확인 필요" 표기). 사용자 결정 대상
- 그 외 리스크와 검증 항목은 작성 예정
