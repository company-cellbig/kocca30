> 키오스크 분류 시범콘텐츠가 공유하는 공통 사양 정본. 콘텐츠별 기획서(덜미, 덧뵈기 등)가 본 문서(정본)의 관련 항목을 참조함. 콘텐츠 무관 골격만 담고, 콘텐츠 고유 설계는 각 기획서에 둠.

# 1. 개요

## 가. 적용 범위

- **적용 대상**: 키오스크 분류 시범콘텐츠 ([[콘셉트 정리#가. 키오스크]]). 단일 통합 키오스크 플랫폼에서 1인 사용
- **공통과 고유 경계**: 본 문서는 콘텐츠 무관 골격만 정의함
	- 공통(본 문서): 세션, Step 모델, 공용 기능, 공통 화면, 진행 호스트, 기술 구성 6영역, 개인정보와 가드레일 원칙, 공통 운영 파라미터
	- 고유(각 기획서): Step별 구체 명세(단계 수, 내용, 번호), 콘텐츠 고유 설계(플롯, 채점, 페르소나 등)
- **사용자와 연속성 경계**: 본 문서는 세션(1회 사용, 휘발) 골격까지 다룸. 재방문에 걸친 사용자 누적(학습 프로필, 이어하기, 콘텐츠 횡단 진척과 자산, 그 개인정보와 보안)은 [[플랫폼 사양]]이 정본임

## 나. 문서 맵

본 문서가 정의하는 콘텐츠 무관 골격을 절별로 정리함. 개발자는 필요한 절을 골라 읽으면 됨. 각 콘텐츠 기획서는 이 골격을 자기 콘텐츠에 채움.

| 절 | 정의하는 것 |
|---|---|
| §2 세션 | 1회 사용 단위와 그 저장 데이터, Step별 세션 동작 |
| §3 Step 모델 | Step의 정의와 명세 양식 (기획서가 Step을 적는 골격) |
| §4 공용 기능 | 여러 Step에 걸쳐 적용되는 횡단 기능(입력 검증, 가드레일, 타임아웃 등) |
| §5 공통 화면 | 인트로, 대기, 전송, 종료 공통 화면의 동작(흐름과 예외)과 레이아웃 |
| §6 진행 호스트 | 콘텐츠가 공유하는 안내 캐릭터의 역할 골격과 개발 계약 |
| §7 기술 구성 | 콘텐츠 구현 시스템을 6영역으로 정리하는 템플릿 |
| §8 개인정보와 가드레일 원칙 | 세션 데이터 개인정보 처리와 가드레일 3지점 |
| §9 운영 파라미터 | 콘텐츠 무관 공통 운영 기본값 |
| §10 관련 문서 | 함께 보는 정본과 인용 문서 |
| §11 위키 작성자용 인용 규칙 | (작성자 전용 부록, 개발 사양 아님) 다른 기획서가 본 문서를 끌어 쓰는 방법 |
| §12 공용 화면 예시 이미지 | §5 공통 화면 6개와 플랫폼 이어하기 1개의 콘텐츠 무관 예시 이미지 생성 프롬프트 |

본 문서는 콘텐츠 무관 골격 모음이라 런타임 플로우(Step 순서 흐름)를 갖지 않음. 콘텐츠별 전체 플로우는 각 기획서가 소유함.

# 2. 세션

## 가. 세션 정의

한 유저의 키오스크 사용 전체(시작 Step → 종료 Step)를 감싸는 상위 컨테이너. 하위 Step들이 세션 안에서 순차 실행됨. 세션은 1회 사용 단위로 종료 시 휘발되며, 재방문에 걸친 사용자 누적은 [[플랫폼 사양#2. 사용자 정의와 단계]]가 다룸.

- **라이프사이클**: 생성(시작 Step, 신규) → 상태 저장 반복(진행 중) → 종료 + 리셋(종료 Step)
- **관리 모듈**: §7.다 백엔드 (세션 라이프사이클과 세션 안 데이터 저장 책임)

## 나. 세션 저장 데이터 (공통 항목)

세션이 저장하는 데이터 중 콘텐츠 무관 공통 항목. 콘텐츠 입력과 생성 데이터는 각 기획서가 정의함. 본 표는 **어떤 값이 들어가는지까지만 적고, 데이터 타입이나 DB 저장 스키마 같은 저장 형식은 설계 단계에서 정함**. 다만 콘텐츠가 공통 엔진에 넘기는 설정 필드는 이와 별개라, 필요한 곳에 적음(예: §6 진행 호스트 설정 스키마).

| 데이터 | 분류 | 들어가는 값과 구성 | 수명 | 비고 |
|---|---|---|---|---|
| 세션 ID | 시스템 | 세션마다 부여되는 고유 식별자 | 휘발 (세션 종료 시 파기) | 시작 Step에서 생성 |
| 동의 기록 | 시스템 | 약관 버전 + 동의 시각 | 보관 (휘발 아님, §8) | 약관 버전 체계 운영 결정 |
| 연락처 | 개인정보 | 유저 연락처 (결과물 전송용) | 휘발 (발송 후 즉시 파기) | 전송 동의 시 임시 저장, 거부 시 즉시 파기. 상세 §8 |

- **콘텐츠 입력 데이터**: 캐릭터 정보, 유저 응답, 결과물 등 (각 기획서가 콘텐츠별로 정의)
- **콘텐츠 생성 데이터**: 서사, 일러스트, 사진, 모델 등 (각 기획서가 콘텐츠별로 정의)

## 다. Step별 세션 동작

| Step 단계 | 세션 동작 |
|---|---|
| 시작 Step | 세션 생성 |
| 중간 Step | 세션 데이터 갱신 |
| 종료 Step | 세션 종료 + 임시 데이터 파기 + 리셋 |

- 종료 시 파기되는 것은 세션의 임시 데이터(연락처 등)임. 동의 기록과 사용 로그처럼 보관 대상은 휘발 대상이 아니며, 보관 정책은 §8과 콘텐츠별 기획서를, 재방문 누적 사용자 프로필은 [[플랫폼 사양]]을 따름

# 3. Step 모델

콘텐츠 기획서가 Step을 적는 골격임. Step이 무엇인지(가)와 각 Step을 어떤 항목으로 명세하는지(나)를 정함.

## 가. Step 정의

> [!note] Step 정의
> - **개념**: 시스템 흐름의 순차 단위. 유저가 한 행위로 인식하는 활동 묶음. "지금 어느 단계인가?"에 답하는 단위(시작, 입력, 대기, 감상, 전송, 종료 등)
> - **구성**: 각 Step은 명세 항목으로 정의되고, 공용 기능을 조합해 프로세스를 이룸
> - **하위 단위(sub-step)**: 프로세스는 sub-step을 순서대로 나열한 것. sub-step은 화면 전환, 백엔드 호출, AI 호출 등 실행 단위이며 `N. 행위자: 동작` 한 줄로 표기
> - **행위자**: sub-step의 행위자 지정 규칙
> 	- 기본: UI(클라이언트), AI, 백엔드, 외부 서비스 중 하나. 필요 시 구체 모듈 덧붙임(예: AI 이미지 생성 모델, 외부 서비스 SMS)
> 	- 페르소나: 렌더 주체에 괄호 표기(예: UI(말뚝이))
> 	- 유저 동작: 별도 행위자로 두지 않고 처리하는 UI sub-step에 "유저 ... 캡처/수집"으로 적음

^step-def

## 나. Step 명세 항목

> [!note] Step 명세 항목
> - **트리거**: Step 진입 조건 (유저 액션 또는 직전 Step 완료)
> - **시스템**: 관여하는 기술 구성 모듈
> - **화면**: Step이 표시하는 화면(풀스크린 스크린이나 페이지) 목록과 전환 트리거
> 	- 화면 수: 개발할 스크린 단위(화면 내부 영역과 컴포넌트 분할은 UI 설계 단계)
> 	- 예외: 백그라운드만 있는 Step은 해당 없음
> - **프로세스**: Step 안에서 순차 실행되는 sub-step을 번호로 나열(`N. 행위자: 동작`). 공용 기능 호출 + 자체 로직
> 	- UI sub-step: 해당 화면을 괄호로 표기(예: UI(가이드 화면))
> 	- 병행: 동시 진행 동작은 (병행) 불릿
> 	- 분기와 실패: 갈림이나 실패가 일어나는 sub-step 바로 아래에 하위 불릿으로 적음(`- 분기:` 조건부, `- 실패:` 실패). 분기는 sub-step 단위라서 Step 전체에 별도 분기 필드는 두지 않음
> - **입력**: Step이 받는 데이터와 이벤트
> - **출력**: Step이 산출하는 데이터와 상태
> - **다음**: 다음 Step 또는 종료 조건

^step-spec-items

# 4. 공용 기능

여러 Step에 걸쳐 적용되는 횡단 기능. 제공 모듈은 §7 기술 구성, 정책은 §8 가드레일 원칙과 연동. 각 Step의 프로세스 항목은 아래 콜아웃의 기능을 조합해 작성됨. 적용 방식은 명시 호출형(sub-step에서 직접 호출)과 상시 자동형(백그라운드 적용)으로 나뉨.

> [!note] 공용 기능
> **명시 호출형** (sub-step에서 직접 호출)
> - **입력 유효성 검증**: 유저 입력(이름, 응답, 연락처 등)을 형식, 길이, 필수 기준으로 검사. 음성 입력은 음성 텍스트 변환(STT)을 거친 텍스트가 대상
> - **AI 가드레일**: 입출력 안전성 검사. 적용 3지점(사전, 런타임 입력, 런타임 출력)은 모두 필수([[시범콘텐츠 공통 사양#8. 개인정보와 가드레일 원칙]] 가드레일 3지점). 각 지점을 어느 Step에 매핑할지는 콘텐츠별로 각 기획서가 정의
> - **개인정보 처리와 파기**: 연락처 임시 저장 후 발송 직후(성공, 실패, 거부) 즉시 파기. 종료 Step은 잔류 백스톱. 공통 개인정보 범위는 전송용 연락처뿐, 그 외는 콘텐츠별로 각 기획서가 정의([[시범콘텐츠 공통 사양#8. 개인정보와 가드레일 원칙]])
> - **외부 서비스 호출 래퍼**: STT, AI, 호스팅, SMS 등 외부 호출의 재시도와 타임아웃 표준화
> - **에러와 fallback**: AI 호출이나 외부 서비스 실패 시 유저에게 사과 안내 후 종료 Step
>
> **상시 자동형** (백그라운드 적용)
> - **화면 타임아웃**: 한 화면 체류가 임계를 넘으면 그 화면의 정상 진행 경로로 자동 전환
> 	- 작업 상태: 유저 작업 상태가 있으면 세션 내 확정 저장 후 진행(보관과 파기는 [[시범콘텐츠 공통 사양#8. 개인정보와 가드레일 원칙]]과 [[플랫폼 사양#4. 서버 데이터 모델]]), 없으면 바로 다음으로 진행
> 	- 적용: 추가 필수 입력이나 동의 없이 진행 가능한 화면(감상과 열람, 창작, 카메라와 모션)
> 	- 미적용: 대기 화면, 동의 화면, 필수 입력 화면
> 	- 리셋과 임계: 화면 진입 시 리셋(세션이나 Step 누적이 아님). 임계(예: 60초, 창작이나 촬영 화면은 더 긴 값 예: 5분)는 운영 파라미터
> - **터치 미입력 타임아웃**: 화면의 주요 입력(대부분 터치, 카메라 화면은 사람이나 포즈 검출)이 임계 시간 동안 감지되지 않으면 종료 Step 직행(유저 이탈 대응)
> 	- 미적용: 대기 화면과 감상이나 열람 화면(감상과 열람은 화면 타임아웃만 적용)
> 	- 동의 화면: 발동하면 미동의로 간주
> 	- 리셋과 임계: 입력 감지 시 리셋(세션이나 Step 누적이 아님). 임계(예: 30초)는 운영 파라미터
> - **동시 적용**: 두 타임아웃이 다 적용되는 화면(창작, 카메라와 모션)에서는 먼저 임계에 도달한 쪽이 발동
> 	- 능동 입력(터치, 포즈)이 이어지면 터치 미입력이 리셋되어 화면 타임아웃(정상 진행)으로 귀결
> 	- 입력이 끊기면 터치 미입력(종료 Step)이 먼저 발동
> - **사용 로그와 모니터링**: 전 Step의 진입, 완료, 오류 이벤트 기록(완주율과 오류율 산출 입력)

^step-common-funcs

분기와 에러 처리 흐름은 위 콜아웃의 "에러와 fallback" 항목으로 일원화. 개별 Step 프로세스에서는 호출만 명시함. 타임아웃 임계 등 정량 기본값은 §9 운영 파라미터에 모음.

# 5. 공통 화면

콘텐츠 무관하게 형태가 거의 같은 공통 화면군(인트로, 대기, 전송, 종료). 각 화면의 동작(흐름과 예외)과 레이아웃을 함께 정의함. 각 기획서는 이를 자기 Step 번호에 매핑하고 콘텐츠 고유 디테일(호스트, 비주얼, 카피)을 더함. 타임아웃 정책 정본은 §4 공용 기능.

이어하기(학습 토큰 스캔) 화면은 재방문 연속성에 속해 본 절의 세션 화면군이 아니라 [[플랫폼 사양#다. 이어하기 복원]]이 정본임(§1 사용자와 연속성 경계). 다만 콘텐츠를 가로질러 형태가 같은 공유 화면이라, 각 콘텐츠 UI에서는 세션 공통 화면과 마찬가지로 공용으로 분류하고 고유분(호스트, 비주얼, 카피)만 더함.

## 가. 공통 영역 골격 (9:16 세로)

모든 공통 화면이 공유하는 9:16 키오스크 영역 구조임. 세로 화면을 위에서 아래로 세 영역으로 나누고, 진행 호스트는 이 영역들에 걸치는 별도 슬롯에 놓임. 콘텐츠는 이 골격에 고유 요소(호스트 인물, 콘텐츠 비주얼, 화면 카피)만 끼움.

- **헤더 영역 (상단)**: 화면 제목이나 단계 안내를 둠. 진척이나 게이지 같은 상태 표시도 이 영역이나 본문 모서리에 둘 수 있고, 어디에 둘지는 콘텐츠가 정함
- **본문 영역 (중앙, 최대 비중)**: 화면의 주기능 하나를 담음(폼, 카메라 뷰, 캔버스, 미리보기, 진행 표시 등). 한 화면에 주요 동작은 하나임
- **액션 영역 (하단)**: 주 버튼과 보조 버튼을 둠. 손이 닿기 쉬운 하단에 큰 터치 타깃으로 배치함. 대기나 종료처럼 입력이 없는 화면은 비움
- **호스트 슬롯**: 진행 호스트가 놓이는 자리임(§6 화면 상태 모델). 작업 집중 화면(창작, 촬영, 폼)에서는 작게 두거나 숨김
- **공통 원칙**: 큰 터치 타깃, 명확한 시각 위계, 노년층을 포함한 가독성을 지킴. 화면 한글 카피는 각 기획서가 정함

## 나. 인트로 (시작 + 동의)

- **흐름**: 신규 세션 생성 → 인사말과 가이드 화면 → 고객 동의 약관 화면 → 동의 감지 → 동의 기록 저장
- **예외**
	- 미동의: 터치 미입력 타임아웃 발동 시 미동의 간주 → 종료 Step 직행 (별도 거부 버튼 없음). 동의 화면은 화면 타임아웃 미적용
	- 추가 동의: 콘텐츠가 카메라 등 추가 처리를 쓰면 해당 동의를 약관에 포함
- **레이아웃**: 시작, 가이드, 동의 세 화면으로 나뉨
	- 시작 화면: 헤더에 콘텐츠 타이틀, 본문에 대표 비주얼, 액션에 큰 시작 버튼과 보조 이어하기 버튼을 둠. 호스트가 환영하는 모습으로 등장함. 종료 후 복귀하는 화면이 곧 이 시작 화면임
	- 가이드 화면: 본문에 진행 흐름 안내, 액션에 다음 버튼을 둠. 호스트가 화자로 등장함
	- 동의 약관 화면: 본문에 약관 텍스트와 동의 토글 목록, 액션에 동의하고 시작 버튼(필수 동의 시 활성)과 그만두기 보조 버튼을 둠. 호스트는 작게 두거나 숨김. 타임아웃은 위 예외를 따름

## 다. 생성과 변환 대기

AI가 결과물을 생성하거나 변환하는 동안 진행을 표시하며 기다리는 공통 동작. 시간이 걸리는 AI 작업(덜미의 그림동화 생성, 덧뵈기의 2D 도안에서 3D 탈 변환 등)에 적용함.

- **흐름**: AI 생성이나 변환 요청 → 대기 화면(진행 표시) → 주기적 폴링으로 상태 조회 → 완료 시 다음 Step(결과 감상 등)으로
- **폴링**: 폴링 주기로 백엔드 상태를 조회함(생성 중, 완료, 실패). 무응답이 임계를 넘으면 실패로 처리(주기와 임계는 §9 운영 파라미터)
- **타임아웃**: 대기 화면은 화면 타임아웃과 터치 미입력 타임아웃을 적용하지 않음(작업 진행 중이라 이탈로 보지 않음)
- **실패**: AI 호출이나 외부 서비스 실패는 §4 공용 기능 에러와 fallback으로 일원화함(사과 안내 후 종료 Step)
- **레이아웃**: 본문 중앙에 진행 인디케이터와 작업 비주얼, 상태 문구를 둠. 헤더와 액션은 최소화하거나 비움(입력받지 않음). 호스트 노출은 선택임(대기 중 흥 돋움)

## 라. 결과물 전송

- **정상 흐름**: 연락처 입력과 전송 동의 안내 → 연락처 임시 저장 → 외부 서비스로 전송 → 발송 직후 즉시 파기
- **거부 흐름**: 거부 시 전송 생략, 종료 Step으로
- **실패 흐름** (외부 서비스 호출 래퍼):
	- 일시 장애: 재시도 N회
	- 수신처 영구 실패: 재입력 1회 허용 후 종료
	- 그 외 영구 실패: 사과 후 종료 + 운영 알림
- **레이아웃**: 본문에 연락처 입력 필드와 입력 수단(키패드 등), 개인정보 수집과 이용 안내 문구를 둠. 액션에 전송 버튼과 받지 않기 보조 버튼을 두며, 전송이 곧 발송 동의이고 받지 않기가 거부임(별도 동의 토글 없음). 화면 타임아웃은 미적용함(필수 입력 화면). 호스트는 작게 두거나 숨김
- **개인정보 안내 문구**: 별도 동의 토글을 두지 않는 대신 수집과 이용 고지 요소를 화면에 노출함. 수집 항목(휴대폰 번호), 이용 목적(결과 링크 발송), 보유와 파기(발송 즉시 파기), 거부권(받지 않기로 거부 가능)을 담음. 처리 주체와 정확한 고지 문구는 규정 검토 단계에서 확정함(확인 필요)

## 마. 종료와 리셋

- **흐름**: 마무리 인사 화면 → 세션 종료 + 임시 데이터 파기 → 시작 화면 복귀(다음 유저 대기)
- **레이아웃**: 본문 중앙에 호스트의 작별 인사와 마무리 메시지를 크게 둠. 액션은 없음(자동으로 시작 화면 복귀)

# 6. 진행 호스트

여러 콘텐츠가 공유하는 진행 호스트의 역할 골격과 공통 개발 계약을 정의함. 인물(페르소나)과 슬롯의 구체 값은 콘텐츠별로 각 기획서가 채움.

> [!note] 진행 호스트
> - **정의**: 콘텐츠의 Step 전환과 과업 이해를 안내하는 보조 캐릭터임
> - **제약**: 유저의 선택, 창작, 촬영 같은 행위를 대신 수행하지 않음. 유저가 주인공이고 호스트는 해설과 길잡이 역할만 함
> - **전통 인물 차용**: 남사당놀이 종목의 전통 인물을 가져옴 (예: [[덜미 - 전자책 변환 기획서|덜미]] 박첨지, [[덧뵈기 - 나만의 탈춤 기획서|덧뵈기]] 말뚝이)
> - **역할 골격 (공통)**: 전 Step 진행 안내와 해설. 시작과 마무리를 여닫고 단계 사이를 이어 줌
> - **페르소나 (콘텐츠별)**: 전통 인물과 화법(말투, 어휘, 반응 패턴)을 각 기획서가 정의함
> - **표현 형식**: 스틸이나 애니메이션으로 표시함. 3D 등장 여부는 콘텐츠별 선택임
> - **화면 상태 모델**: 공통 엔진이 받는 입력은 사용 여부, 노출 상태(표시나 숨김), 위치 슬롯, 표정 슬롯, 발화 상태임
> 	- 슬롯의 구체 값(허용 위치, 표정 종류 등)은 각 기획서가 정의함
> 	- 노출 시점: 콘텐츠 단위로 사용 여부를, 화면 단위로 표시 여부를 정함. 호스트는 본문 주기능(게임플레이, 폼, 카메라 뷰 등)을 가리지 않는 위치와 크기로 두고, 작업 집중이 우선인 화면(창작, 촬영 등)에서는 작게 두거나 숨김
> 	- 초기화: 화면 전환 시 노출 상태를 기본값(숨김)으로 되돌림
> 	- 기본값: 사용 여부가 없으면 호스트를 생략으로 처리함
> - **음성**: 대사와 추임새를 음성으로 출력함. 실시간 합성(TTS)인지 사전 녹음 클립인지는 콘텐츠별 선택(확인 필요)
> - **에셋 요구**: 캐릭터 비주얼, 음성(보이스나 녹음 클립), 대사와 추임새 텍스트
> - **공통 설정 스키마 (잠정, 확인 필요)**: 콘텐츠별 호스트를 공통 로더가 읽는 설정 계약. 값은 각 기획서가 채움
> 	- `hostId`: 호스트 식별자 (필수)
> 	- `personaName`: 인물명 (필수)
> 	- `assetRoot`: 에셋 경로 루트 (필수)
> 	- `visualAssets`: 비주얼 에셋 (필수)
> 	- `voiceAssets`: 음성 에셋 (선택, 음성 사용 시)
> 	- `utteranceSet`: 대사와 추임새 (선택)
> 	- `displaySlots`: 위치와 표정 슬롯 정의 (필수)
> 	- 누락 시: 호스트를 쓰는데 필수 필드가 없으면 설정 오류(검증 실패)로 처리함. 호스트 미사용은 위 기본값(생략)이며, 그때만 생략 폴백

^step-host

sub-step 프로세스에서 호스트를 렌더 주체로 적는 표기 규약은 §3.가 Step 정의의 행위자 규칙을 따름(예: UI(말뚝이)).

# 7. 기술 구성 (6영역 템플릿)

콘텐츠 구현 시스템을 6개 영역으로 정리하는 공통 템플릿. 각 영역의 콘텐츠별 모듈은 기획서가 채움.

## 가. AI 시스템

콘텐츠의 AI 모듈(생성, 변환, 채점, 가드레일 등). 모듈 구성은 콘텐츠마다 다르며 각 기획서가 정의함. 비-AI 오케스트레이션(진행 제어, 결과물 조립)은 다. 백엔드.

각 AI 모듈은 아래 명세 항목으로 정의함 (구현 코드와 하이퍼파라미터는 설계 단계, 기획서는 요건까지).

- **역할**: 모듈이 수행하는 작업
- **입력과 출력**: 데이터 형식과 규격
- **모델 확보**: 자체 학습, 사전학습 모델, 외부 API, 파인튜닝 중 방식 (후보, 미정은 확인 필요)
- **판정과 성능 기준**: 정확도, 임계, 응답 속도 등 (정량 미정은 확인 필요, 임의 추정 금지)
- **적용**: 실시간/배치, 서버/온디바이스, 호출 Step
- **실패, 한계, 복구**: 모델 미확보, 저신뢰, 오탐, 미탐, 타임아웃 등 실패 조건과 재시도, 한도, fallback. 해당 Step sub-step 실패 분기와 연결
- **데이터와 평가**: 학습과 레퍼런스 데이터, 검증 방법

## 나. 하드웨어 (키오스크)

키오스크 본체의 물리 구성임.

- 9:16 세로형 디스플레이 (터치 인식)
- 음향 출력 (인트로, 배경음, 보상 사운드)
- 콘텐츠별 입력 장치 (마이크, 카메라, 외부 센서 등)
- 네트워크 연결 (AI 서버 통신, 전송)

## 다. 백엔드

키오스크와 AI 서버를 잇고 세션, Step 진행, 데이터, 약관을 처리하는 서버 계층임.

- **통신**: 키오스크 ↔ AI 서버 API
- **세션과 진행**
	- 세션 관리: 세션별 진행 상태 (§2)
	- 진행 제어: Step 순차 진행, 콘텐츠별 로직
- **데이터**
	- 결과물 조립과 저장: 생성물 결합 + 저장소
	- 개인정보 처리: 연락처 등 (§8)
- **약관**: 고객 동의 약관 관리 (버전과 동의 기록)

## 라. 외부 서비스 연동

콘텐츠가 호출하는 외부 서비스 목록임.

- 전송 서비스 (SMS/이메일 등)
- AI API (LLM, 이미지 생성, 포즈 추정 등 콘텐츠별)
- STT 서비스 (음성 입력 사용 시)
- 결과물 호스팅 (전송 링크 방식 사용 시)

## 마. 클라이언트 UI (키오스크 앱)

키오스크 앱의 화면 전환과 인터랙션 계층임.

- 페이지 전환과 터치 인터랙션 프레임워크
- 화면 흐름 (콘텐츠 Step 순서 구현)
- 진행 호스트 렌더링 (정의 §6, 콘텐츠별 페르소나, 사용 시)
- 입력 UI (가상 키보드, 음성, 카드 선택, 카메라 등 콘텐츠별)
- 화면 타임아웃과 터치 미입력 타임아웃 처리, 다음 유저용 리셋

## 바. 운영과 모니터링

가동 상태와 사용 지표를 관리하는 운영 계층임.

- 키오스크 가동 상태 모니터링
- 사용 로그 (유저 수, 완주율, 오류율)
- 에러 fallback (AI 호출이나 외부 서비스 실패): 처리 규칙은 §4 공용 기능 에러와 fallback 항목으로 일원화

# 8. 개인정보와 가드레일 원칙

## 가. 개인정보 처리 정책 (공통 원칙)

세션(1회 사용) 데이터(연락처 등)의 개인정보를 처리하고 파기하는 공통 원칙임.

- **적용 경계**: 본 절은 세션(1회 사용) 데이터의 개인정보 원칙임. 재방문 누적 사용자 프로필(학습 프로필 등)의 개인정보와 보안은 [[플랫폼 사양#4. 서버 데이터 모델]]이 정본임
- **개인정보 소유 경계**: 공통 필수 항목은 연락처(전송용) 하나. 그 외 개인정보(얼굴, 영상 등)는 콘텐츠별로 각 기획서가 자기 범위를 열거함. 모든 항목의 보관 기간은 규정 검토 후 확정(잠정)
- **연락처 처리**
	- "임시 저장": 메모리 only, 디스크 영속화 금지, 로그 미기록
	- "즉시 파기": 발송 응답 수신 직후(성공이나 실패 무관) 메모리 명시적 0 덮어쓰기 + 변수 해제
- **동의 미보유 상태**: 시작 Step에서 세션 생성되나 미동의 시 세션 전체 즉시 파기 (동의 기록 미생성)
- **입력 유효성 백엔드 재검증**: 클라이언트 검증 외 백엔드 재검증 필수 (클라이언트 우회 대비)
- **데이터 보관 기간**: 동의 기록, 결과물, 로그의 보관 기간은 잠정값(규정 검토 후 확정). 콘텐츠별 데이터 항목은 각 기획서가 정의

## 나. 가드레일 적용 3지점

가드레일은 3지점에 적용. 사전 검수만으로 무인 안전이 닫히지 않으므로 출력 단계에서도 반드시 검사함.

- **사전** (운영 전 생성 단계): 사전 생성물 검수
- **런타임 입력**: 유저 입력 검사
- **런타임 출력**: 생성물(서사, 이미지, 사진 등) 검사

# 11. 위키 작성자용 인용 규칙 (부록)

> 개발 사양이 아니라 위키 작성 참고. 다른 기획서가 본 정본을 끌어 쓰는 방법.

- **인용 원칙**: 콘텐츠별 기획서는 세션과 Step 골격을 본 문서에서, 사용자와 연속성은 [[플랫폼 사양]]에서 임베드나 참조로 인용하고, 콘텐츠 고유 부분만 채움
- **블록 임베드와 참조**: 헤딩 없는 본문 블록(표, 콜아웃 등)은 `![[시범콘텐츠 공통 사양#^블록ID]]` 블록 임베드, 그 외는 `[[시범콘텐츠 공통 사양#섹션]]` 참조
- **헤딩 임베드 회피**: 헤딩 섹션 통째 임베드(`#섹션`)는 호스트 문서 헤딩 계층을 꼬이게 하므로 피함 (헤딩은 각 기획서가 소유)
- **외부 출력**: 임베드는 Obsidian 열람용이며 외부 출력(GitHub/PDF)은 평탄화 필요
- **정본**: 임베드와 wikilink 규칙은 [[CONVENTIONS#마. Wikilink 규칙]]

# 12. 공용 화면 예시 이미지

§5 공통 화면과 플랫폼 이어하기 화면의 콘텐츠 무관 예시 이미지 생성 프롬프트. 콘텐츠 고유 요소를 빼고 공통 레이아웃 골격만 보이게 만듦. 콘텐츠별 실제 화면 이미지는 각 기획서 UI 문서가 고유 요소(호스트 인물, 비주얼, 카피)를 넣어 따로 만듦 (예: [[덧뵈기 - 나만의 탈춤 UI]]).

## 가. 산정과 원칙

- **화면 수**: 7개. 6개는 §5 세션 화면 유형과 1:1 대응함(인트로 3개인 시작, 가이드, 동의 약관과 대기, 전송, 종료). 대기는 콘텐츠에서 변환이나 생성으로 여러 번 인스턴스화하지만, 공통 예시는 유형 1개만 둠. 나머지 1개는 플랫폼 이어하기 화면([[플랫폼 사양#다. 이어하기 복원]])으로, 콘텐츠를 가로질러 형태가 같아 함께 둠
- **콘텐츠 중립**: 진행 호스트는 종목 특정 비주얼 없는 중립 캐릭터 실루엣으로 두어, 호스트가 차지하는 위치와 크기, 본문 주기능을 가리지 않는 배치를 보이게 함. 그 외 콘텐츠 비주얼과 배경만 중립 박스로 표현함. 특정 종목 비주얼(탈, 인형, 전통 무대 등)은 넣지 않음. 종목 비주얼이 들어가면 특정 콘텐츠에 종속되어 콘텐츠 무관 골격이라는 취지가 깨지기 때문임
- **형식**: 9:16 와이어프레임이나 중립 목업. 헤더, 본문, 액션 세 영역과 호스트 슬롯(§5.가)을 눈에 보이게 함
- **카피**: 콘텐츠 무관 기능 버튼(시작하기, 다음, 동의하고 시작, 전송 등)과 콘텐츠 무관 안내/상태 라벨(진행 안내, 진행 중, 마침 인사, 학습 코드를 비춰 주세요 등)은 한글로 적고, 콘텐츠 고유 카피(타이틀, 인사말)는 플레이스홀더로 둠. 콘텐츠 무관 카피만 허용하는 취지이며 종목 고유 문구는 넣지 않음

## 나. 공통 프롬프트 양식

모든 화면 프롬프트가 공유하는 제약과 부정 프롬프트. 화면별 프롬프트(다)는 이 제약을 화면 내용과 함께 담음. 프롬프트는 이미지 생성기 입력용임.

### 1) 공통 제약

- 매체: content-agnostic UI wireframe or neutral mockup, vertical 9:16 kiosk screen
- 레이아웃: header / body / action three-region layout, with a neutral host-slot placeholder
- 중립성: no brand, no specific or branded characters, no cultural motifs; a generic host silhouette is allowed; neutral palette with a single simple accent
- UI 원칙: large touch targets, clear visual hierarchy, high readability
- 텍스트: Korean labels for content-neutral function buttons and content-neutral instruction/status labels, rendered exactly as quoted; content-specific copy shown as gray placeholder boxes

### 2) 부정 프롬프트

- specific content characters or mascots, cultural motifs (masks, puppets, traditional stage)
- garbled or broken Hangul, English UI text, watermark
