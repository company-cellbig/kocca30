> 키오스크 분류 시범콘텐츠가 공유하는 공통 사양. 콘텐츠별 기획서(덜미, 덧뵈기 등)가 본 문서의 관련 항목을 참조함. 콘텐츠 무관 골격만 담고, 콘텐츠 고유 설계는 각 기획서에 둠. 1차연도는 1회 세션 체험 골격을 정의하고, 학습형 도제와 LLM, 온톨로지 등 2차연도 확장은 [[#10. 2차연도 확장 설계 (콘텐츠 골격 확장, 현재 구현 밖)]]에 보존함. 재방문 연속성(학습 프로필, 이어하기)은 [[플랫폼 사양#6. 2차연도 확장 설계 (디지털 도제 연속성, 현재 구현 밖)]]가 다룸.

# 1. 개요

## 1.1 적용 범위

- **적용 대상**: 키오스크 분류 시범콘텐츠 ([[콘셉트 정리#2.1 키오스크]]). 단일 통합 키오스크 플랫폼에서 1인 사용
- **공통과 고유 경계**: 본 문서는 콘텐츠 무관 골격만 정의함
	- 공통(본 문서): 세션, 공용 기능, 실패 처리와 에러 케이스, 공통 화면, 진행 호스트, 공통 기술 방향, 개인정보와 가드레일 원칙, 공통 운영 파라미터
	- 고유(각 기획서): Step별 구체 명세(단계 수, 내용, 번호), 콘텐츠 고유 설계(플롯, 채점, 페르소나 등). Step을 적는 양식은 [[콘텐츠 기획서 작성 양식]]을 따름
- **사용자와 연속성 경계**: 본 문서는 세션(1회 사용, 다음 방문으로 이어지지 않음) 골격까지 다룸. 재방문에 걸친 사용자 누적(학습 프로필, 이어하기, 콘텐츠 횡단 진척과 자산, 그 개인정보와 보안)은 [[플랫폼 사양]]이 다룸

## 1.2 1차연도 범위와 공통 설계 결정 (회의 근거)

본 공통 사양은 1차연도에 남사당 키오스크 콘텐츠 5종이 공유하는 1회 세션 체험 골격을 정의함. 학습형 도제 연속성과 LLM 통합은 2차연도로 두고 [[#10. 2차연도 확장 설계 (콘텐츠 골격 확장, 현재 구현 밖)]]에 보존함.

- **개발 우선순위**: 1차연도는 1회 세션 체험 콘텐츠를 우선 개발함. 무형유산 전승을 위한 학습형 병행과 단계 진입은 2차연도로 둠 ([[컨소시엄 회의록 - 2026-06-22#3.5 콘텐츠와 도제 설계]])
- **도제 난이도 구분**: 남사당은 표준 커리큘럼이 없어 난이도 수준으로 구분함. 콘텐츠별 난이도 적용은 각 기획서가 정의함 ([[컨소시엄 회의록 - 2026-06-22#3.5 콘텐츠와 도제 설계]])
- **공통 비주얼**: 공통 연출은 3D를 지양하고 2D 영상과 AI 생성을 위주로 함 ([[큐랩셀빅 사전회의 - 2026-06-22#2. 핵심 합의]])
	- 지양이지 엄금은 아님. 콘텐츠 고유의 3D 요건(나만의 꼭두각시의 3D 아바타 등)은 [[1차연도 셀빅 개발 준비자료#2. 2026년 셀빅 개발 콘텐츠]]와 각 기획서가 정함
- **현지화(다국어)**: 시작 화면의 언어 선택으로 세션 전체를 그 언어로 제공하는 공통 역량임. 현지화 범위는 UI 카피뿐 아니라 AI 생성물(서사, 음성 등)까지이며, 기본은 한국어이고 1차연도는 한국어와 영어를 지원함. 세션은 현재 언어를 저장하고([[#2.2 세션 저장 데이터 (공통 항목)]]), 각 콘텐츠가 서사와 음성, 가드레일 등 다운스트림을 그 언어로 구현함(참조 구현 [[덜미 - 나만의 유람기 기획서]])
- **연속성 경계**: 재방문 사용자 데이터(학습 프로필, 이어하기, 콘텐츠 횡단 누적)는 [[플랫폼 사양#6. 2차연도 확장 설계 (디지털 도제 연속성, 현재 구현 밖)]]이 다룸. 본 문서 [[#10. 2차연도 확장 설계 (콘텐츠 골격 확장, 현재 구현 밖)]]는 콘텐츠 골격 쪽 확장만 다룸

# 2. 세션

## 2.1 세션 정의

한 유저의 키오스크 사용 전체(시작 Step에서 종료 Step까지)를 감싸는 상위 컨테이너임. 하위 Step들이 세션 안에서 순차 실행됨. 세션은 1회 사용 단위로 다음 방문으로 이어지지 않으며, 재방문 누적은 [[플랫폼 사양#6. 2차연도 확장 설계 (디지털 도제 연속성, 현재 구현 밖)]]가 다룸. 세션 데이터의 보관과 파기 정책은 [[#8. 개인정보와 가드레일 원칙]]을 따름.

- **라이프사이클**: 생성(시작 Step) → 상태 저장 반복(진행 중) → 종료와 리셋(종료 Step)
- **관리 모듈**: 백엔드 (세션 라이프사이클과 세션 안 데이터 저장 책임)

## 2.2 세션 저장 데이터 (공통 항목)

세션이 저장하는 데이터 중 콘텐츠 무관 공통 항목. 콘텐츠 입력과 생성 데이터는 각 기획서가 정의함. 본 표는 **어떤 값이 들어가는지까지만 적고, 데이터 타입이나 DB 저장 스키마 같은 저장 형식은 설계 단계에서 정함**. 다만 콘텐츠가 공통 엔진에 넘기는 설정 필드는 이와 별개라, 필요한 곳에 적음(예: [[#6.3 기술 요건]]의 공통 설정 스키마).

| 데이터 | 분류 | 들어가는 값과 구성 | 보관 기간 | 비고 |
|---|---|---|---|---|
| 세션 ID | 시스템 | 세션마다 부여되는 고유 식별자 | 보관 (잠정, 규정 검토 후 확정) | 시작 Step에서 생성. 디버깅과 품질 분석용 |
| 현재 언어 | 시스템 | 세션에 적용 중인 언어(기본 한국어) | 보관 (잠정, 규정 검토 후 확정) | 시작 화면 언어 선택에서 설정. 현지화 기준 |
| 현재 Step | 시스템 | 현재 진행 중인 Step | 보관 (잠정, 규정 검토 후 확정) | 진행 단계 기록 |
| 에러 유형 | 시스템 | 에러 발생 시 에러 유형 기록 | 보관 (잠정, 규정 검토 후 확정) | 디버깅과 품질 분석용 |
| 동의 기록 | 시스템 | 약관 버전 + 동의 시각 | 보관 (잠정, 규정 검토 후 확정) | 약관 버전 체계 운영 결정([[#8. 개인정보와 가드레일 원칙]]) |

각 기획서의 세션 데이터 표도 같은 분류 열을 두며, 그 열의 값은 아래 3종만 씀. 어떤 항목이 들어가는지는 콘텐츠별로 각 기획서가 정의함.

| 분류 값 | 정의 | 예 |
|---|---|---|
| 시스템 | 세션 운영과 관측에 쓰는 관리 데이터. 콘텐츠 내용이 아님 | 세션 ID, 동의 기록, 사용 로그 |
| 콘텐츠 입력 | 유저가 직접 넣거나 고른 값, 유저를 촬영하거나 측정해 받은 값 | 캐릭터 정보, 유저 응답, 카메라 원본 스트림 |
| 콘텐츠 생성 | 시스템이 콘텐츠 내용으로 만들어 낸 값 | 서사, 일러스트, 3D 모델, 채점 기록, 그리고 이들을 엮은 결과물 |

- **결과물은 콘텐츠 생성임**: 결과물은 유저 입력을 재료로 쓰되 시스템이 만들어 낸 산출물이라 콘텐츠 입력이 아님
- **한 행은 한 분류만 가짐**: 유저 선택과 시스템 배정이 한 값에 섞이면 행을 나눔. 예를 들어 유저가 고른 유형은 콘텐츠 입력이고, 그 유형 풀에서 배정된 사전 생성 플롯은 콘텐츠 생성임
- **개인정보는 분류 값이 아님**: 개인정보 여부는 분류와 별개 기준이라 분류 열에 "개인정보"를 쓰지 않음. 한 데이터가 분류 값과 개인정보 여부를 하나씩 가짐. 예를 들어 기념 사진은 분류가 콘텐츠 생성이고, 개인정보에 해당함. 개인정보 여부는 표 비고와 각 기획서의 개인정보 처리 절에 적음

## 2.3 Step별 세션 동작

| Step 단계 | 세션 동작 |
|---|---|
| 시작 Step | 세션 생성 |
| 중간 Step | 세션 데이터 갱신 |
| 종료 Step | 세션 종료 + 임시 데이터 파기 + 리셋 |

- 종료 시 파기되는 것은 세션의 콘텐츠 고유 임시 데이터(개인정보인 영상, 얼굴 등)임. 세션 ID와 현재 Step, 에러 유형 같은 관리 데이터와 동의 기록, 사용 로그는 보관 대상이라 종료 시 파기하지 않음(보관 기간은 잠정, 규정 검토 후 확정). 콘텐츠 입력과 생성 데이터의 보관 기간은 각 기획서가 정하고, 개인정보 보관과 파기 정책은 [[#8. 개인정보와 가드레일 원칙]]을, 재방문 누적 사용자 프로필은 [[플랫폼 사양]]을 따름

## 2.4 클라이언트에서 서버로 전송 시점

세션 라이프사이클의 상태 저장 반복(진행 중, [[#2.1 세션 정의]])이 언제 서버로 전송하는지를 정함. 이어하기가 없는 1차연도라 전체 상태를 주기로 동기화할 이유가 없고, 서버가 데이터를 필요로 하는 시점에 이벤트로 보냄.

- **원칙 (이벤트 기반)**: 정기 전체 동기화를 두지 않음. 1차연도는 복원(이어하기)이 없어 중간 상태를 지속 저장할 이유가 없으므로 서버가 필요로 하는 시점에 이벤트로 전송함 ([[플랫폼 사양#5. 사용자 모델 (1차연도)]])
- **전송 트리거**: 무엇을 언제 보내는지로 정리함

| 대상 | 전송 시점 |
|---|---|
| 생성 입력(캐릭터 정보, 선택, 응답 등) | 생성을 트리거하는 시점(각 콘텐츠의 생성 Step 진입) |
| 가드레일 검사 대상(입력, 생성물) | 입력이나 생성물이 확정되는 시점 |
| 결과물과 다운로드 URL | 생성 완료 시 ([[플랫폼 사양#4. 결과물 전송과 호스팅]]) |
| 세션 관리와 품질 기록(진행 Step, 에러 유형, 완주와 이탈) | 단계 이동, 에러 발생, 종료 이벤트 시 ([[플랫폼 사양#3.2 저장 데이터 (1차연도)]]) |

- **체크포인트 해상도**: 관측 기록은 Step 경계를 기본으로 하되, 긴 Step 안의 운영상 중요한 지점은 필수 in-Step 이벤트로 보냄
	- **기본**: Step 진입과 종료의 진행 상태와 결과. Step 경계는 의미 단위(입력 완료, 생성, 감상)라 완주율과 오류율 관측의 기본 해상도로 삼음
	- **필수 in-Step 이벤트**: sub-step에 따라 이탈이나 실패 의미가 달라지는 지점은 Step 안에서도 보냄. 장시간 생성과 상태 조회, 타임아웃 취약 캡처, 가드레일 재시도, 수분짜리 창작 화면(플롯 문답, 촬영 등)이 해당함. 이 이벤트 메타데이터(발생 지점, 유형)는 과수집이 아니라 관측 최소치임
	- **전체 상태의 매 sub-step 전송은 안 함**: 무인 키오스크에서 호출이 과하고, 익명 1회성이라 부분 상태 전체의 저장 가치가 낮으며 최소 수집 원칙([[#8. 개인정보와 가드레일 원칙]])과 어긋남. 위 필수 in-Step 이벤트는 이 제한과 별개임
	- **세션 종료 시 일괄만으로는 부족**: 이탈이나 실패로 끝난 세션의 오류를 통째로 놓치고, 생성이 세션 중간에 서버에서 돌아야 해 원천적으로 불가능함
- **예외 (생성 최적화)**: 생성 지연을 줄이려는 생성 입력의 sub-step 단위 증분 전송은 상태 저장이 아니라 생성 최적화라 위 원칙과 별개로 둠
- **전송 신뢰성 (구현 요건)**: 이벤트 전송도 오프라인이나 프로세스 재시작에서 유실될 수 있으므로 유실 방지 장치를 둠. 클라이언트가 이벤트를 durable 큐에 쌓고, session_id와 단조 증가 시퀀스로 순서와 중복을 판별하며, 재시도와 백오프, 서버 멱등 반영(upsert), 오프라인 보관 한도를 둠. 큐에 파기 대상(개인정보)이 남는 경우의 처리를 정함. 세부 방식은 구현에서 확정함
- **최소 전송**: 비완주 종료 시 임시 데이터를 파기하는 원칙([[#8. 개인정보와 가드레일 원칙]])에 맞춰, 관측 목적 전송은 비식별 지향(에러 유형, 진행 Step)으로 함. 응답 원본까지 서버가 보관할지는 규정 검토로 확정함 ([[플랫폼 사양#7. 미결 항목 (확인 필요)]])

# 3. 공용 기능

여러 Step에 걸쳐 적용되는 횡단 기능임. 제공 모듈은 각 콘텐츠 시스템이고, 정책은 [[#8. 개인정보와 가드레일 원칙]]과 연동함. 각 Step의 프로세스 항목은 아래 기능을 조합해 씀. 적용 방식은 명시 호출형(sub-step에서 직접 호출)과 상시 자동형(백그라운드 적용)으로 나뉨. 타임아웃 임계 등 정량 기본값은 [[#9. 운영 파라미터 (공통 기본값)]]에 모음.

## 3.1 명시 호출형 (sub-step에서 직접 호출)

- **입력 유효성 검증**: 유저 입력(이름, 응답 등)을 형식, 길이, 필수 기준으로 검사함. 음성 입력은 음성 텍스트 변환(STT)을 거친 텍스트가 대상임
- **AI 가드레일**: 유해하거나 부적절한 입력과 생성물을 거르는 안전성 검사임. 적용 3지점(사전 생성물 검사, 런타임 입력 검사, 런타임 출력 검사)은 검사 대상이 있으면 모두 필수임(사전 지점의 사람 검수 갈음과 생성 없는 체험형 예외는 [[#8.2 가드레일 적용 3지점]]). 각 지점을 어느 Step에 매핑할지는 콘텐츠별로 각 기획서가 정의함
- **개인정보 처리와 파기**: 공통 필수 개인정보 항목은 없음. 콘텐츠 고유 개인정보(얼굴, 영상 등)는 메모리 임시 처리 후 즉시 파기하고, 결과물 호스팅은 다운로드 만료 시 파기함. 범위와 파기 시점은 콘텐츠별로 각 기획서가 정의함([[#8. 개인정보와 가드레일 원칙]])
- **외부 서비스 호출 래퍼**: STT, AI, 결과물 호스팅 등 외부 호출의 재시도와 타임아웃을 표준화함
- **실패 처리**: 재시도로 복구하지 못한 AI 호출이나 외부 서비스 실패를 처리함. 대체 경로(fallback)가 있으면 세션을 이어 가고, 없으면 상황 안내 후 종료 Step으로 보냄. 분기와 실패 흐름은 이 기능으로 일원화하고, 개별 Step 프로세스에서는 호출만 적음(모델은 [[#4. 실패 처리와 에러 케이스]])

## 3.2 상시 자동형 (백그라운드 적용)

- **화면 타임아웃**: 한 화면 체류가 임계를 넘으면 그 화면의 정상 진행 경로로 자동 전환함
	- 작업 상태: 유저 작업 상태가 있으면 세션 내 확정 저장 후 진행하고(보관과 파기는 [[#8. 개인정보와 가드레일 원칙]], [[플랫폼 사양#3. 서버]]), 없으면 바로 다음으로 진행함
	- 적용: 추가 필수 입력이나 동의 없이 진행 가능한 화면(감상과 열람, 창작, 카메라와 모션)
	- 미적용: 대기 화면, 동의 화면, 필수 입력 화면, 가이드 화면
	- 호스트 발화 중 정지: 발화 중에는 측정을 멈추고 발화 종료나 스킵 후 재개함(잠정). 타이머가 호스트 발화를 중간에 끊지 않게 함(터치 미입력 타임아웃의 발화 중 멈춤과 같은 방식)
	- 리셋과 임계: 화면 진입 시 리셋함(세션이나 Step 누적이 아님). 임계(예: 60초, 창작이나 촬영 화면은 더 긴 값 예: 5분)는 운영 파라미터임
- **터치 미입력 타임아웃**: 화면의 주요 입력(대부분 터치, 카메라 화면은 사람이나 포즈 검출)이 임계 시간 동안 감지되지 않으면 종료 Step으로 보냄(유저 이탈 대응). 비완주라 마무리 화면은 건너뜀([[#5.5 종료와 리셋]])
	- 미적용: 대기 화면과 감상이나 열람 화면(감상과 열람은 화면 타임아웃만 적용)
	- 동의 화면: 발동하면 미동의로 간주함
	- 리셋과 임계: 입력 감지 시 리셋함(세션이나 Step 누적이 아님). 임계(예: 60초)는 운영 파라미터임
- **동시 적용**: 두 타임아웃이 다 적용되는 화면(창작, 카메라와 모션)에서는 먼저 임계에 도달한 쪽이 발동함
	- 능동 입력(터치, 포즈)이 이어지면 터치 미입력이 리셋되어 화면 타임아웃(정상 진행)으로 귀결함
	- 입력이 끊기면 터치 미입력(종료 Step)이 먼저 발동함
- **사용 로그와 모니터링**: 전 Step의 진입, 완료, 오류 이벤트를 기록함(완주율과 오류율 산출 입력)

## 3.3 진행 중 종료

세션을 도중에 끝내는 공용 종료 시스템임. 유저 그만두기(홈 버튼), 터치 미입력 타임아웃, 입력 유효성 위반이나 가드레일 한도 초과가 종료 트리거임.

- **기본 동작**: 진행 중인 화면을 멈추고 종료 Step으로 보내되, 마무리 화면은 건너뜀(완주 전용, [[#5.5 종료와 리셋]]). 세션 종료와 파기만 하고 시작 화면으로 복귀함. 유저 쪽 원인이라 실패 처리가 띄우는 상황 안내 팝업 없이 종료함
- **유저 홈 버튼(그만두기)**: 상호작용 화면 상단 헤더 좌상단에 원형 홈 버튼을 상시 둠. 터치하면 그만두기 확인 팝업(두 버튼, [[#5.8 그만두기 확인 팝업]])을 띄우고, 확정 시 종료하고 취소 시 원래 화면으로 복귀함. 별도 확인 단계 없이 이 팝업이 유저 확인 절차를 겸함. 현 단계에서는 화면 상단 원형 홈 버튼으로 확정함
	- 적용 화면: 입력, 선택처럼 유저가 보고 조작하는 상호작용 화면과 동의 화면. 동의 화면은 별도 미동의 버튼 없이 홈 버튼이 미동의 종료를 겸함([[#5.2 인트로 (시작 + 동의)]]). 인트로 가이드 화면 적용 여부는 콘텐츠가 정함
	- 미적용 화면: 시작, 대기, 종료 화면과 완주 마침 화면. 대기는 작업 진행 중이라 이탈로 보지 않고, 종료 화면은 이미 세션을 닫는 중임. 결과물 감상 화면은 콘텐츠에 따라 다름(완주 버튼이 곧 종료인 콘텐츠는 미배치, 페이지 넘김으로 완주하는 콘텐츠는 홈 버튼 배치)
- **위반 종료**: 입력 유효성 위반이나 가드레일 위반이 한도(예: 3회)에 닿으면 팝업 없이 종료 Step으로 보냄. 매 위반 시 띄우는 위반 안내 팝업이 남은 기회를 미리 알려 유저가 종료를 예상한 상태이기 때문임. 별도 위반 종료 안내 팝업을 두지 않음
- **파기와 보관**: 종료 Step의 세션 데이터 보관과 파기 정책을 그대로 따름(보관 대상은 남기고 파기 대상만 정리하며, 정책은 [[#8. 개인정보와 가드레일 원칙]]과 각 기획서 세션 데이터를 따름). 동의 이전(동의 화면 등) 이탈은 동의 미보유로 처리함

## 3.4 개발 모드 (개발과 QA 빌드 전용)

개발과 품질 검수(QA) 편의를 위한 진행 단축 기능임. 런타임 공용 기능과 분리하며, 실증과 평가 빌드에서는 비활성으로 둠. 콘텐츠가 점프할 수 있는 Step과 난이도는 각 기획서 Step 명세를 따름.

- **Step 점프**: 임의 Step으로 바로 이동해 전반부 반복 없이 후반부 흐름을 확인함
- **난이도 직행**: 저난이도를 거치지 않고 목표 난이도로 바로 진입해 고난이도를 테스트함
- **상태 시드 주입**: 점프 시 앞 Step 산출물이 없어 후반부가 깨지지 않도록, 필요한 진척과 입력을 가짜 값으로 채워 넣음(세션 저장 데이터 [[#2.2 세션 저장 데이터 (공통 항목)]] 기준)
- **활성 게이트**: 개발과 QA 빌드에서만 켬. 실증과 연차 평가 시연 빌드에서는 빌드 플래그로 비활성하고 운영에 노출하지 않음

# 4. 실패 처리와 에러 케이스

런타임 실패를 어떻게 가르고 어떻게 다룰지 정하는 공통 모델. 5종 기획서가 모두 이 모델을 쓰며, 각 기획서는 이 규칙을 자기 콘텐츠의 케이스에 적용한 표(에러 케이스)를 운영 기준 절에 둠.

## 4.1 처리 갈래 (실패가 세션을 어떻게 만드는가)

실패를 네 갈래로 나눔. 콘텐츠에 없는 갈래는 두지 않음(예: 음성 입력이 없는 체험형은 대체 입력이 없음).

| 갈래 | 뜻 | 예 |
|---|---|---|
| 재입력 | 유저 입력만 다시 받으면 이어 감 | 비속어 검출, 입력 가드레일 위반, 얼굴이나 사람 미검출 |
| 대체 입력 | 입력 수단 하나가 막혀 다른 수단으로 바꿔 이어 감 | 음성 인식 실패 시 가상 키보드로 계속 |
| 기능 축소 | 보조 기능이 빠져도 결과물이 남아 그 기능만 빼고 이어 감 | 낭독 음성 합성 실패, 호스트 발화 실패, 채점 단위 점수 보류 |
| 중단 | 핵심 생성이나 변환, 결과물 전달이 실패해 결과물이 남지 않음 | 생성과 변환 파이프라인 실패, 호스팅 실패, 상태 조회 무응답 |

## 4.2 원인 (실패가 누구에게서 비롯됐는가)

원인을 유저, 외부 서비스, 시스템 셋으로 나눔. **운영 알림 여부가 이 축에서 바로 나옴**: 원인이 외부 서비스나 시스템이면 알림 대상이고, 유저면 비대상임. 알림 열을 따로 두지 않음(원인 열과 중복).

- **유저**: 유저 입력이나 발화, 자세가 원인임. 운영이 손댈 것이 없음
- **외부 서비스**: 외부 API나 모델, 호스팅이 죽었거나 느림. 운영 조치가 필요함
- **시스템**: 자체 서버나 파이프라인, 하드웨어가 원인임. 운영 조치가 필요함

## 4.3 중단 공통 처리

- 상황 안내 팝업([[#5.6 실패 안내 (상황 안내 모달 팝업)]])을 띄우고 종료 Step으로 진행하되, 마무리 화면은 건너뜀(완주 전용, [[#5.5 종료와 리셋]]). 별도 실패 화면을 두지 않고 전달하지 못한 생성물을 파기함
- 예외: 세션 생성 실패는 정리할 세션 자체가 없어 종료 Step을 거치지 않고 시작 화면으로 되돌림
- 생성 파이프라인의 중단은 `failed` 상태 하나로 모으고, 어느 단계에서 났는지는 세션 데이터의 에러 유형에 남김
- 호스팅과 다운로드 URL 발급을 생성 구간에서 끝내므로, 유저는 결과물을 보기 전에 실패를 알게 됨

## 4.4 에러 케이스 표 (각 기획서가 씀)

각 기획서는 런타임에 터질 수 있는 실패를 전수로 모은 표를 둠. 열은 다섯임.

| 열 | 담는 것 |
|---|---|
| 발생 지점 | 어디서 터지는가 (비속어 필터 검출, 이미지 생성이나 3D 변환 호출 실패 등) |
| 처리 | 위 [[#4.1 처리 갈래 (실패가 세션을 어떻게 만드는가)]]의 네 갈래 중 하나 |
| 원인 | 위 [[#4.2 원인 (실패가 누구에게서 비롯됐는가)]]의 세 분류 중 하나 |
| 팝업 | 위반 안내, 안내, 상황 안내, 없음 |
| 이후 동작 | 재입력, 종료, 세션 계속 등 |

- 유저가 스스로 고르는 그만두기는 정상 종료라 에러 케이스가 아님. 타임아웃도 이탈 대응이라 넣지 않음
- 실시간 인식의 정상 신호 품질 변동(포즈 저신뢰, 일시적 미검출 등)은 구성요소 장애가 아니라 정상 열화라 표에 넣지 않고 해당 Step 진행 분기에 둠. 표는 구성요소나 외부 서비스, 시스템의 장애나 유저 위반 같은 실패만 담음(기능 축소라도 진행 호스트 발화 실패처럼 구성요소가 실제로 실패하는 것은 담음)
- 위반 한도 초과 종료는 별도 케이스로 두지 않음. 매 위반 시 띄우는 위반 안내 팝업이 남은 기회를 알려 주고, 한도에 닿으면 팝업 없이 종료함
- 화면 문구는 케이스마다 다르게 써서 화면만 보고도 어느 실패인지 가려지게 함

# 5. 공통 화면

콘텐츠 무관하게 형태가 거의 같은 공통 화면군(인트로, 텍스트 입력, 대기, 결과물 감상, 종료, 실패 안내, 그만두기 확인 팝업). 각 화면의 동작(흐름과 예외)과 레이아웃을 함께 정의함. 각 기획서는 이를 자기 Step 번호에 매핑하고 콘텐츠 고유 디테일(호스트, 비주얼, 카피)을 더함. 타임아웃 정책은 [[#3. 공용 기능]]을 따름.

이어하기(학습 토큰 스캔) 화면은 재방문 연속성에 속해 본 절의 세션 화면군이 아니라 [[플랫폼 사양#6. 2차연도 확장 설계 (디지털 도제 연속성, 현재 구현 밖)]]이 다룸([[#1.1 적용 범위]]의 사용자와 연속성 경계). 다만 콘텐츠를 가로질러 형태가 같은 공유 화면이라, 각 콘텐츠 UI에서는 세션 공통 화면과 마찬가지로 공용으로 분류하고 고유분(호스트, 비주얼, 카피)만 더함.

## 5.1 공통 영역 골격

모든 공통 화면이 공유하는 16:9 가로 키오스크 영역 구조임(화면 방향은 [[디바이스 사양]]을 따름). 가로 화면을 헤더(상단), 본문(중앙, 최대 비중), 액션(본문 아래) 세 영역으로 나누고, 진행 호스트는 이 영역들에 걸치는 별도 슬롯에 놓임. 콘텐츠는 이 골격에 고유 요소(호스트 인물, 콘텐츠 비주얼, 화면 카피)만 끼움.

키오스크 화면은 가로 16:9임. 콘텐츠가 생성하는 결과물 이미지(전자책, 4컷 만화 등)의 형식은 화면 방향과 별개이며, 세로 등 콘텐츠별로 각 기획서가 정함.

- **헤더 영역 (상단)**: 화면 제목이나 단계 안내를 둠. 진척이나 게이지 같은 상태 표시도 이 영역이나 본문 모서리에 둘 수 있고, 어디에 둘지는 콘텐츠가 정함. 상단 헤더는 표시 전용(비조작)이나, 좌상단 모서리의 진행 중 종료 홈 버튼(원형 아이콘)만 예외로 조작 요소임([[#3.3 진행 중 종료]]). 최소 필수 정보만 담고, 글자 크기는 대형 화면 시청 거리를 고려해 설계 단계에서 확정함(확인 필요)
- **본문 영역 (중앙, 최대 비중)**: 화면의 주기능 하나를 담음(폼, 카메라 뷰, 캔버스, 미리보기, 진행 표시 등). 한 화면에 주요 동작은 하나임
- **액션 영역 (본문 아래)**: 주 버튼과 보조 버튼을 큰 터치 타깃으로 둠. 화면 물리 최하단이 아니라 중앙 도달 존의 아래쪽(허리 높이 안)에 배치함(대형 가로 화면은 최하단이 허리 아래로 내려가 도달성이 나쁨, 아래 도달성 원칙). 대기나 종료처럼 입력이 없는 화면은 비움
	- **진행 중 종료 버튼 위치**: 진행 중 종료 홈 버튼은 액션 영역이 아니라 헤더 좌상단에 원형 아이콘으로 둠(진행 중 종료 시스템의 유저 버튼, [[#3.3 진행 중 종료]], [[시범콘텐츠 공통 사양#5.8 그만두기 확인 팝업]]). 액션 영역에는 별도 그만두기 버튼을 두지 않음
- **호스트 슬롯**: 진행 호스트가 놓이는 자리임([[#6.2.1 화면 상태 모델]]). 넓은 가로 화면이라 공통 화면 대부분은 중앙 조작 존 옆 여유 공간에 호스트를 또렷한 안내 캐릭터로 둠. 본문이 화면 전체를 쓰는 콘텐츠 화면(창작 캔버스, 카메라 뷰 등)에서만 작게 두거나 숨김
- **도달성 (대형 가로 화면, 중앙 도달 존)**: 참여자가 화면 앞 가운데 서서 터치하므로, 터치 조작 요소(버튼, 입력, 토글)는 **중앙 도달 존**에 모음. 중앙 도달 존은 손이 닿는 화면 가운데 영역(가운데 폭, 눈높이~허리 높이)임
	- **배제 영역**: 좌우 끝과 위아래 가장자리(최상단, 최하단)에는 조작 요소를 두지 않음(65인치 가로는 폭이 넓어 좌우 끝에 손이 안 닿고, 최하단은 허리 아래라 도달성이 나쁨). 넓은 좌우 주변부와 위아래 가장자리는 헤더 표시, 호스트 존재감, 연출, 여백의 자리이며 비워도 됨. UI를 화면 가장자리까지 억지로 늘리지 않음
	- **구체 치수 (확인 필요)**: 도달 존의 x/y 좌표 범위, 화면 설치 높이, 버튼 최소와 최대 높이는 설계와 설치, 사용성 검증 단계에서 확정함(임의 수치 금지)
	- **접근성 신체 범위 (확인 필요)**: 눈높이~허리 기준은 표준 성인 전제임. 휠체어, 아동, 저신장, 장신 사용자의 눈높이와 도달 높이 편차를 어떻게 흡수할지는 접근성 대상 범위와 함께 설계 단계에서 확정함
	- **모션과 카메라 화면 예외**: 카메라나 모션(포즈) 인식 화면은 유저가 화면에서 떨어져(예: 2m) 전신으로 인식되므로 근접 중앙 터치 도달 존이 아니라 전신 프레이밍과 본문 전체를 씀. 터치 조작 화면과 모션 화면의 배치 우선순위는 각 기획서가 정함
- **공통 원칙**: 큰 터치 타깃, 명확한 시각 위계, 노년층을 포함한 가독성을 지킴. 화면 한글 카피는 각 기획서가 정함

## 5.2 인트로 (시작 + 동의)

- **흐름**: 신규 세션 생성 → 인사말과 가이드 화면 → 고객 이용 동의 화면 → 동의 감지 → 동의 기록 저장
- **동의 전송 확인**: 클라이언트는 동의 확정 이벤트의 서버 저장 확인 응답을 받은 뒤에만 다음 단계로 진행함(동의 기록 유실 방지)
- **예외**
	- 미동의: 동의 화면에는 별도 미동의 버튼을 두지 않음. 대신 헤더 좌상단 홈 버튼을 터치하면 그만두기 확인 팝업([[시범콘텐츠 공통 사양#5.8 그만두기 확인 팝업]])을 거쳐 확정 시 미동의로 간주해 종료 Step으로 감(마무리 화면은 건너뜀, [[#5.5 종료와 리셋]]). 터치 미입력 타임아웃은 확인 팝업 없이 바로 미동의 종료임. 동의 화면은 화면 타임아웃 미적용(터치 미입력 타임아웃만 적용)
	- 추가 동의: 콘텐츠가 카메라 등 추가 처리를 쓰면 해당 동의를 약관에 포함함. 생체나 영상정보처럼 별도 명시 동의가 필요한지와 그 형태(별도 확인 요소 여부)는 규정 검토로 확정함([[#8. 개인정보와 가드레일 원칙]])
- **레이아웃**: 시작, 가이드, 동의 세 화면으로 나뉨
	- 시작 화면: 헤더에 콘텐츠 타이틀, 본문에 대표 비주얼, 액션에 큰 시작 버튼을 둠(보조 이어하기 버튼은 2차연도 확장 설계라 1차연도 미배치, [[플랫폼 사양#6. 2차연도 확장 설계 (디지털 도제 연속성, 현재 구현 밖)]]). 언어 선택 요소를 두어 유저가 고른 언어를 세션 현재 언어로 저장함(기본 한국어, [[#1.2 1차연도 범위와 공통 설계 결정 (회의 근거)]] 현지화). 호스트가 환영하는 모습으로 등장함. 종료 후 복귀하는 화면이 곧 이 시작 화면임
	- 가이드 화면: 본문에 진행 흐름 안내, 액션에 다음 버튼을 둠. 진행 중 종료를 적용하면 헤더 좌상단에 홈 버튼을 둠(콘텐츠가 정함, [[#3.3 진행 중 종료]]). 호스트가 화자로 등장함
	- 이용 동의 화면: 본문에 약관 텍스트, 액션에 동의하고 시작 버튼만 두고 헤더 좌상단에 홈 버튼을 둠(진행 중 종료). 동의하고 시작이 곧 약관 동의이며, 별도 미동의 버튼은 두지 않고 홈 버튼이 미동의 종료를 겸함(위 예외). 1차연도는 선택 동의가 없어 별도 동의 토글을 두지 않음(선택 동의와 학습 토큰은 2차연도, [[#10. 2차연도 확장 설계 (콘텐츠 골격 확장, 현재 구현 밖)]]). 약관 본문이 길면 스크롤 영역으로 두고, 버튼은 중앙 도달 존([[#5.1 공통 영역 골격]] 도달성)에 둠. 호스트는 넓은 측면에 또렷한 안내 캐릭터로 둠

## 5.3 생성과 변환 대기

AI가 결과물을 생성하거나 변환하는 동안 진행을 표시하며 기다리는 공통 동작. 시간이 걸리는 AI 작업(덜미의 전자책 생성, 양반 놀리기의 4컷 만화 생성 등)에 적용함.

- **흐름**: AI 생성이나 변환 요청 → 대기 화면(진행 표시) → 주기적 상태 조회 → 완료 시 다음 Step(결과 감상 등)으로
- **상태 조회**: 상태 조회 주기로 백엔드 상태를 조회함(생성 중, 완료, 실패). 무응답이 임계를 넘으면 실패로 처리(주기와 임계는 [[#9. 운영 파라미터 (공통 기본값)]])
- **타임아웃**: 대기 화면은 화면 타임아웃과 터치 미입력 타임아웃을 적용하지 않음(작업 진행 중이라 이탈로 보지 않음)
- **실패**: AI 호출이나 외부 서비스 실패는 [[#3. 공용 기능]] 실패 처리로 일원화함(상황 안내 후 종료 Step)
- **레이아웃**: 본문 중앙에 진행 인디케이터와 작업 비주얼, 상태 문구를 둠. 헤더와 액션은 최소화하거나 비움(입력받지 않음). 호스트는 측면에 또렷한 안내 캐릭터로 두어 대기 중 흥을 돋움

## 5.4 결과물 감상

결과물을 보여 주는 감상 화면임. 받기(QR)는 완주 뒤 종료 Step의 마무리 화면에서 하므로([[#5.5 종료와 리셋]]), 이 화면은 결과물만 보여 주고 스캔은 다음 화면으로 넘김. 연락처를 받지 않고, 결과물을 웹에 호스팅한 뒤 그 다운로드 주소를 QR로 전달하며, 전화번호를 수집하지 않으므로 전송 동의 게이트가 없음.

- **호스팅 시점**: 결과물 호스팅과 만료형 다운로드 URL 발급은 이 화면 이전, 생성 파이프라인 끝에서 마침. 이 화면은 이미 발급된 URL로 QR만 그림
	- 이렇게 하면 유저가 결과물을 감상하기 전에 전달 실패를 알게 됨. 다 보고 난 뒤 "못 보냅니다"를 만나지 않음
- **정상 흐름**: 결과물 표시(페이지나 컷 넘김, 확대) → 완주 진행. 받기(QR)는 종료 Step의 마무리 화면에서 함([[#5.5 종료와 리셋]])
- **실패 흐름**: 호스팅과 URL 발급 실패는 이 화면에 닿기 전 생성 구간에서 갈림. 재시도 한도를 넘기면 대기 화면에서 상황 안내 뒤 종료 Step으로 보냄([[#4. 실패 처리와 에러 케이스]])
- **레이아웃**: 본문에 결과물을 크게 둠. 액션에 완주 버튼을 둠(라벨은 각 기획서가 정함). QR과 스캔 안내는 이 화면에 두지 않고 마무리 화면에 둠([[#5.5 종료와 리셋]]). 연락처 입력 필드와 키패드, 전송이나 받지 않기 버튼, 개인정보 수집 고지는 두지 않음. 호스트는 넓은 측면에 또렷한 안내 캐릭터로 둠
- **타임아웃**: 감상에 시간이 걸리므로 화면 타임아웃을 길게 오버라이드함([[#9. 운영 파라미터 (공통 기본값)]]). 터치 미입력 타임아웃은 미적용
	- 이 화면 타임아웃이 발동하면 완주 버튼 터치와 같이 완주로 보고 마무리 화면으로 정상 진행함([[#5.5 종료와 리셋]]). 화면 타임아웃은 터치로 초기화되지 않는 체류 상한이라 결과물을 천천히 보는 유저도 타임아웃에 걸리는데, 여기서 세션을 끊으면 그 유저가 QR을 받지 못한 채 결과물이 파기됨. 자리를 뜬 유저의 세션은 마무리 화면의 기본 화면 타임아웃이 정리함
- **개인정보**: 전송용으로 수집하는 개인정보가 없음. 결과물(얼굴이 담긴 산출물 포함)의 호스팅과 만료 파기는 각 콘텐츠의 카메라와 결과물 동의, 다운로드 만료 파기로 다룸([[#8. 개인정보와 가드레일 원칙]], [[플랫폼 사양#4. 결과물 전송과 호스팅]]). 다운로드 가능 기간 문구는 규정 검토 단계에서 확정함(확인 필요)

## 5.5 종료와 리셋

세션을 마무리하고 다음 유저를 위해 초기화하는 종료 Step. 진입 경로가 둘이며, 마무리 화면은 완주에서만 거침.

- **진입 경로**: 세션 종료와 임시 데이터 파기는 두 경로가 공통으로 거치고, 마무리 화면만 완주 전용임
	- **완주**: 유저가 결과물 감상 화면에서 완주 버튼을 누르거나 화면 타임아웃으로 정상 진행한 경우([[#5.4 결과물 감상]]). 마무리 화면 → 세션 종료 + 임시 데이터 파기 → 시작 화면 복귀(다음 유저 대기). 종료 이벤트에는 완주 유형(완주 버튼 터치, 감상 화면 타임아웃)을 구분해 기록함: 완주율 관측에서 방치 완주를 분리함
	- **비완주 종료**: 그만두기, 터치 미입력 타임아웃, 입력 유효성이나 가드레일 위반 한도 초과, 실패 중단. 마무리 화면을 건너뛰고 세션 종료 + 임시 데이터 파기 → 시작 화면 복귀
- **마무리 화면 (완주 전용)**: 완주로 진입했을 때만 표시함. 호스트가 마무리 인사를 하고, 반출 결과물이 있는 콘텐츠는 결과물 QR을 함께 띄워 유저가 받아 가게 함. 유저가 곧장 나가도록 "처음으로" 버튼을 둠
	- 적용 범위: 콘텐츠의 결과물 구성에 따라 갈림. 반출 결과물(QR 전달)이 있는 콘텐츠는 이 화면에서 QR을 전달함. 결과물 없이 결과 화면이 있는 콘텐츠(나만의 탈춤)는 이 화면을 두지 않고 결과 화면이 호스트의 마무리 인사를 겸함. 결과물과 결과 화면이 모두 없는 콘텐츠(나만의 꼭두각시)는 QR 없이 호스트 인사만 담은 이 화면을 완주 마침 화면으로 씀
	- QR: 생성 파이프라인 끝에서 발급한 만료형 다운로드 URL을 인코딩해 표시하고, 스캔 안내와 다운로드 가능 기간 문구를 곁에 둠. 유저가 본인 휴대폰으로 스캔해 결과물을 받음
	- "처음으로" 버튼 터치나 화면 타임아웃(기본값) 뒤 시작 화면으로 복귀함. 버튼이 주 종료이고, 타임아웃은 유저가 그냥 자리를 뜰 때의 안전망임
	- 세션 종료와 임시 데이터 파기는 화면 전환을 막지 않음
- **비완주 종료가 마무리 인사를 건너뛰는 이유**: 진행 중 종료의 목적이 키오스크 회전율이라 이탈 유저를 3초 붙잡지 않음. 실패 중단 뒤 호스트 작별 인사는 상황에 맞지 않음([[#3.3 진행 중 종료]], [[#5.6 실패 안내 (상황 안내 모달 팝업)]])
- **레이아웃**: 마무리 화면은 본문 중앙에 결과물 QR과 스캔 안내, 다운로드 가능 기간 문구를 두고 그 아래 "처음으로" 버튼을 두며, 호스트는 측면에서 작별 인사를 함(결과물이 없는 콘텐츠는 QR과 스캔 안내를 두지 않고 호스트 인사와 "처음으로" 버튼만으로 구성함). 완주 전용이라 진행 중 종료용 홈 버튼은 두지 않음

## 5.6 실패 안내 (상황 안내 모달 팝업)

정상 흐름을 잇지 못하는 실패가 났을 때 공통으로 띄우는 상황 안내 모달 팝업. 각 콘텐츠 기획서가 에러 케이스 표에서 "중단"으로 분류한 케이스가 모두 이 팝업으로 모임(생성이나 변환 실패, 가드레일 재생성 한도 초과, 결과물 호스팅 실패, 상태 조회 무응답, 세션 생성 실패, 진행 재료 배정 실패 등). 별도 전체 화면이 아니라 직전 화면 위에 오버레이로 뜸.

- **흐름**: 중단 케이스 검출 → 직전 화면을 어둡게 깐 위에 상황 안내 팝업 표시 → 종료 Step으로 진행(마무리 화면은 건너뜀, [[#5.5 종료와 리셋]]). 파기와 세션 생성 실패 예외는 [[#4.3 중단 공통 처리]]를 따름
- **버튼**: 확인 버튼 하나만 둠. 누르면 즉시 종료 Step으로 가고, 누르지 않아도 잠깐 뒤 자동으로 진행함
	- **"처음으로" 버튼을 두지 않음**: 세션을 살린 채 시작 화면으로 되돌린다는 뜻으로 읽혀, 모든 실패를 종료로 보내는 원칙과 어긋남. 유저가 다시 하려면 종료 뒤 시작 화면에서 새 세션을 시작함
- **표시 원칙**: 유저를 탓하지 않는 짧은 상황 안내만 담음. 실패 원인의 기술 세부나 오류 코드는 노출하지 않음(무인 운영, 노년층 포함 가독성)
- **레이아웃**: 전체 화면을 새로 그리지 않음. 직전 화면을 어둡게(딤) 깐 위에 중앙 모달 다이얼로그 카드를 띄우고, 카드 안에 경고 아이콘, 상황 안내 메시지, 확인 버튼을 둠. 버튼은 중앙 도달 존([[#5.1 공통 영역 골격]] 도달성)에 둠. 호스트는 카드 옆이나 화면 측면에서 다독이는 모습으로 둠
- **카피**: 팝업 한글 카피는 각 기획서가 정함. 케이스마다 문구를 달리해 화면만 보고도 어느 실패인지 가려지게 함

## 5.7 텍스트 입력

유저가 자유 텍스트를 입력하는 공통 화면. 이름 같은 짧은 입력과 진행 호스트의 질문에 대한 서술형 응답 입력에 함께 씀(예: [[덜미 - 나만의 유람기 기획서|유람기]]와 [[덧뵈기 - 양반 놀리기 4컷 기획서|양반 놀리기]]의 이름 입력, 거리별 응답, 컷별 응답). 가상 키보드(한글)를 기본으로 하고 음성 입력(STT)을 병행함. 텍스트 입력이 없는 콘텐츠(카메라나 모션, 선택지 기반)는 이 화면을 쓰지 않음.

- **흐름**: 입력 안내나 질문 표시 → 유저가 가상 키보드로 입력하거나 음성 입력 버튼으로 말함 → 입력 필드에 텍스트가 채워짐 → 다음(제출) → 입력 검사 통과 시 다음 단계
- **음성 입력(STT)**: 모든 텍스트 입력 화면에서 키보드와 병행 제공함(이름 입력 포함). 제공하는 입력 수단을 임의로 제약하지 않고, 손 조작이 어려운 사용자의 대체 입력 수단도 됨
	- 음성 결과는 텍스트로 변환되어 입력 필드에 들어가며(자동 제출 아님), 유저가 키보드로 고칠 수 있음
	- 변환된 텍스트가 입력 검사 대상임([[#3. 공용 기능]] 입력 유효성 검증)
	- 인식 실패나 무음이면 재시도 안내를 띄우고, 유저가 취소하고 키보드로 전환할 수 있음
- **검사와 재입력**: 이름 등 짧은 입력은 클라이언트 비속어 필터로, 서술형 응답은 AI 가드레일로 검사함([[#3. 공용 기능]]). 위반 시 팝업 안내 후 같은 화면에서 재입력함
- **제출 조건**: 빈 입력이나 공백만 입력하면 다음(제출)을 막음(다음 버튼 비활성). 한글 조합 중에는 제출을 막고 조합이 끝난 뒤 제출함. 길이와 허용 문자 등 세부 기준은 [[#3. 공용 기능]]과 구현에서 정함
- **타임아웃**: 필수 입력 화면이라 화면 타임아웃은 미적용하고 터치 미입력 타임아웃만 적용함([[#3. 공용 기능]])
- **레이아웃**: 16:9 골격([[#5.1 공통 영역 골격]])에 영역별로 배치함
	- 헤더: 화면 제목이나 진행 표시
	- 본문 상단: 입력 안내나 호스트 질문(말풍선)
	- 본문 중앙과 하단: 입력 필드, 가상 키보드, 음성 입력 버튼
	- 액션: 다음(제출) 버튼
	- 조작 요소는 손이 닿는 중앙 도달 존([[#5.1 공통 영역 골격]] 도달성)에 모음
- **키보드 영역 제한 (핵심)**: 가상 키보드는 화면 전체를 덮지 않고 하단 영역에 한정함. 입력 안내, 질문, 입력 필드가 키보드 위에 충분히 보이게 세로 공간을 확보함(질문을 보며 답하는 화면이라 질문 가림 금지)
- **호스트**: 질문을 던지는 응답 입력에서는 본문 상단에 화자로 두고, 이름 같은 단순 입력에서는 측면에 안내 캐릭터로 둠. 어느 경우든 입력 필드와 가상 키보드, 질문을 가리지 않는 위치에 둠([[#6. 진행 호스트]])

## 5.8 그만두기 확인 팝업

진행 중 종료 시스템에서 유저가 홈 버튼을 눌렀을 때, 정말 그만둘지 한 번 더 확인받는 공통 모달 팝업임([[#3.3 진행 중 종료]]). 상호작용 화면(입력, 선택, 감상)과 동의 화면의 홈 버튼이 이 팝업을 띄움(가이드 화면 적용은 콘텐츠 선택, [[#5.2 인트로 (시작 + 동의)]]). 상황 안내 팝업([[#5.6 실패 안내 (상황 안내 모달 팝업)]])과 달리 유저 확인용이라 자동 진행하지 않고 두 버튼으로 갈림.

- **흐름**: 홈 버튼 터치 → 직전 화면을 어둡게(딤) 깐 위에 확인 팝업(중앙 카드) 표시 → 계속하기 선택 시 팝업을 닫고 원래 화면 복귀 / 그만두기 선택 시 상황 안내 팝업 없이 종료 Step으로 감(마무리 화면은 건너뜀, [[#5.5 종료와 리셋]])
- **버튼 구성**: 계속하기(주 버튼, 원래 화면 복귀)와 그만두기(보조 버튼, 세션 종료) 두 버튼임. 상황 안내 팝업이 잠깐 표시 후 자동 진행하는 것과 달리, 이 팝업은 유저가 둘 중 하나를 눌러야 갈림이 정해짐
- **표시 원칙**: 짧은 확인 문구만 담음. 그만두면 지금까지 진행이 끝난다는 정도만 알리고, 유저를 재촉하거나 겁주지 않음(무인 운영, 노년층 포함 가독성)
- **무입력 처리**: 팝업 표시 중 터치 미입력 타임아웃 적용 여부와 임계는 설계에서 정함(잠정). 무응답이 이어지면 종료로 귀결하는 방향이 기본 후보이나 현장 확정 필요(확인 필요)
- **레이아웃**: 전체 화면을 새로 그리지 않고 직전 화면 위에 오버레이함(딤 배경은 흐름 참조). 카드 안 안내 문구와 두 버튼(계속하기 주, 그만두기 보조)을 중앙 도달 존([[#5.1 공통 영역 골격]] 도달성)에 둠. 호스트는 카드 옆이나 화면 측면에서 다독이는 모습으로 둠
- **카피**: 팝업 한글 카피는 각 기획서가 정함(콘텐츠 무관 화면 골격은 본 절)

# 6. 진행 호스트

여러 콘텐츠가 공유하는 진행 호스트의 역할 골격과 공통 개발 계약을 정의함. 인물(페르소나)과 슬롯의 구체 값은 콘텐츠별로 각 기획서가 채움. 각 기획서는 진행 호스트를 시스템 독립 명세([[콘텐츠 기획서 작성 양식#4.2 시스템 독립 명세 양식]])로 쓰므로, 아래 공통 계약도 그 명세 항목 순서(역할과 목적, 동작과 규칙, 기술 요건, 필요 리소스, 실패와 복구)로 정리함(참조 구현은 [[덜미 - 나만의 유람기 기획서]] 진행 호스트). 기술 요건은 조건부 항목이라([[콘텐츠 기획서 작성 양식#4.2.1 명세 항목과 순서]]) 음성을 필요 리소스에 두고 별도 기술 결정이 없는 콘텐츠는 이 항목을 생략함(기준 구현 유람기 진행 호스트도 기술 요건 없이 구성).

## 6.1 역할과 목적

콘텐츠의 Step 전환과 과업 이해를 안내하는 보조 캐릭터임. 유저가 주인공이고 호스트는 해설과 길잡이 역할만 하며, 유저의 선택, 창작, 촬영 같은 행위를 대신 수행하지 않음. 전 Step 진행을 안내하고 시작과 마무리를 여닫으며 단계 사이를 이어 줌. 남사당놀이 종목의 전통 인물을 가져와 종목 정체성을 살림(예: [[덜미 - 나만의 유람기 기획서|덜미]] 박첨지, [[덧뵈기 - 나만의 탈춤 기획서|덧뵈기]] 말뚝이).

## 6.2 동작과 규칙

- **페르소나**: 전통 인물과 화법(말투, 어휘, 반응 패턴)을 각 기획서가 정의함
- **발화 방식**: 대사와 추임새를 음성(TTS)으로 재생하고, 같은 대사를 화면에 텍스트로 함께 표시함
- **표현 형식**: 스틸이나 애니메이션으로 표시함. 3D나 디지털 휴먼 아바타 등장 여부는 콘텐츠별 선택임. 입 모양이나 표정 처리 방식(사전 생성 입 모양 애니메이션, 표정 슬롯 등)은 콘텐츠가 정함
- **스킵**: 발화 중 다음으로 진행하면 발화를 중단하고 다음 단계로 넘어감
- **타임아웃 연동**: 발화 중에는 터치 미입력 타임아웃을 멈추고, 발화가 끝난 뒤 시간 측정을 시작함

### 6.2.1 화면 상태 모델

공통 엔진이 받는 입력은 사용 여부, 노출 상태(표시나 숨김), 위치 슬롯, 표정 슬롯(콘텐츠가 표정을 쓰는 경우), 발화 상태임.

- **슬롯 값**: 허용 위치와 표정 종류 등 구체 값은 각 기획서가 정의함
- **노출 시점**: 콘텐츠 단위로 사용 여부를, 화면 단위로 표시 여부를 정함. 호스트는 본문 주기능(게임플레이, 폼, 카메라 뷰 등)을 가리지 않는 위치와 크기로 두고, 작업 집중이 우선인 화면(창작, 촬영 등)에서는 작게 두거나 숨김
- **초기화**: 화면 전환 시 노출 상태를 기본값(숨김)으로 되돌림
- **기본값**: 사용 여부가 없으면 호스트를 생략으로 처리함

## 6.3 기술 요건

- **음성**: 실시간 합성(TTS)은 상용 API(예: 구글)를 유료로 씀. 실시간 합성과 사전 녹음 클립 중 무엇을 쓸지는 콘텐츠별 선택임 ([[큐랩셀빅 사전회의 - 2026-06-22#2. 핵심 합의]])
- **공통 설정 스키마 (잠정, 확인 필요)**: 콘텐츠별 호스트를 공통 로더가 읽는 설정 계약임. 값은 각 기획서가 채움
	- `hostId`: 호스트 식별자 (필수)
	- `personaName`: 인물명 (필수)
	- `assetRoot`: 에셋 경로 루트 (필수)
	- `visualAssets`: 비주얼 에셋 (필수)
	- `voiceAssets`: 음성 에셋 (선택, 음성 사용 시)
	- `utteranceSet`: 대사와 추임새 (선택)
	- `displaySlots`: 위치와 표정 슬롯 정의 (필수)
	- 누락 시: 호스트를 쓰는데 필수 필드가 없으면 설정 오류(검증 실패)로 처리함. 호스트 미사용은 위 기본값(생략)이며, 그때만 생략함

## 6.4 필요 리소스

캐릭터 비주얼, 음성(보이스나 녹음 클립), 대사와 추임새 텍스트.

## 6.5 실패와 복구

아바타 렌더나 TTS 재생이 실패하면 음성과 애니메이션 없이 대표 이미지와 텍스트로 진행함(대사는 표시하고 세션은 계속). 콘텐츠는 호스트 표현이 빠져도 진행이 끊기지 않게 대체 표시를 둠.

# 7. 공통 기술 방향 (회의 근거)

회의에서 정한 1차연도 공통 기술 방향과 제약임. 콘텐츠 구현은 이를 각 시스템에 반영함. 기술은 별도 기술 구성 절이 아니라 각 시스템의 기술 요건 항목에 인라인함(항목 정의는 [[콘텐츠 기획서 작성 양식#4.2 시스템 독립 명세 양식]], 참조 구현은 [[덜미 - 나만의 유람기 기획서]]). 하드웨어는 [[디바이스 사양]], 세션과 개인정보는 [[#2. 세션]]와 [[#8. 개인정보와 가드레일 원칙]], 외부 호출은 [[#3. 공용 기능]] 외부 서비스 호출 래퍼, 운영과 실패 대응은 [[#3. 공용 기능]] 실패 처리와 사용 로그가 다룸.

- **LLM**: 상용이든 오픈소스든 자체 구축이 가능함. 한국전자기술연구원(KETI)이 주 엔진은 아니며, 통합 여부와 온톨로지는 2차연도에 결정함([[#10. 2차연도 확장 설계 (콘텐츠 골격 확장, 현재 구현 밖)]]) ([[컨소시엄 회의록 - 2026-06-22#2. 핵심 합의]], [[큐랩셀빅 사전회의 - 2026-06-22#2. 핵심 합의]])
- **디지털 휴먼**: 진행 호스트 등은 셀빅 기존 디지털 휴먼 자산을 포팅해 구현할 수 있음 ([[큐랩셀빅 사전회의 - 2026-06-22#2. 핵심 합의]])
- **STT와 TTS**: 음성 입력과 합성은 상용 API(예: 구글)를 유료로 씀 ([[큐랩셀빅 사전회의 - 2026-06-22#2. 핵심 합의]])
- **데이터 성격**: AI 학습용 대규모 데이터셋이 아니라 코칭용 정답 데이터(Ground Truth, GT) 중심의 소규모임. 보존회 실연자가 소수라 확보 가능한 데이터가 적음 ([[큐랩셀빅 사전회의 - 2026-06-22#2. 핵심 합의]])
- **모션 인식 한계**: 전신 싱글 카메라 기준 손목까지가 현실적임(표준 인체 모델). 손가락 추적은 장갑 센서 등 별도 장비가 필요해 별도 연구개발(R&D)로 둠. 손 조작이 중요한 콘텐츠(꼭두각시 등)는 이 한계를 설계에 반영함 ([[컨소시엄 회의록 - 2026-06-22#3.4 모션 인식 기술 범위 (연세대)]])

# 8. 개인정보와 가드레일 원칙

## 8.1 개인정보 처리 정책 (공통 원칙)

세션(1회 사용) 데이터의 개인정보를 처리하고 파기하는 공통 원칙임. 결과물 전달은 전화번호 없이 화면 QR로 하므로([[#5.4 결과물 감상]], [[플랫폼 사양#4. 결과물 전송과 호스팅]]) 공통으로 수집하는 개인정보는 없음.

- **적용 경계**: 본 절은 세션(1회 사용) 데이터의 개인정보 원칙임. 재방문 누적 사용자 프로필(학습 프로필 등)의 개인정보와 보안은 [[플랫폼 사양#6. 2차연도 확장 설계 (디지털 도제 연속성, 현재 구현 밖)]]이 다룸
- **개인정보 소유 경계**: 공통 필수 개인정보 항목은 없음(전화번호를 받지 않음). 개인정보(얼굴, 영상, 사진 등)는 콘텐츠별로 각 기획서가 자기 범위를 열거함. 모든 항목의 보관 기간은 규정 검토 후 확정(잠정)
- **콘텐츠 고유 개인정보 처리**: 각 콘텐츠가 쓰는 얼굴이나 영상은 메모리 임시 처리(디스크 영속화 금지, 로그 미기록) 후 처리 직후 즉시 파기함(메모리 명시적 0 덮어쓰기 + 변수 해제). 세부 범위와 파기 시점은 각 기획서가 정의함
- **결과물 호스팅 파기**: 얼굴이 담길 수 있는 결과물은 다운로드 제공 기간만 호스팅하고 만료 시 파기함([[플랫폼 사양#4. 결과물 전송과 호스팅]])
- **동의 미보유 상태**: 시작 Step에서 세션 생성되나 미동의(홈 버튼 또는 터치 미입력 타임아웃) 시 세션을 보존하지 않고 종료 처리에서 전체 파기 (동의 기록 미생성이라 종료 UI 표시 중에도 개인정보 잔류 없음)
- **입력 유효성 백엔드 재검증**: 클라이언트 검증 외 백엔드 재검증 필수 (클라이언트 우회 대비)
- **데이터 보관 기간**: 동의 기록, 결과물, 로그의 보관 기간은 잠정값(규정 검토 후 확정). 콘텐츠별 데이터 항목은 각 기획서가 정의

## 8.2 가드레일 적용 3지점

유해하거나 부적절한 입력과 생성물을 거르는 안전성 검사를 콘텐츠 파이프라인의 세 지점(사전, 런타임 입력, 런타임 출력)에 적용함. 무인 운영에서는 사전 검사만으로 안전이 확보되지 않으므로, 세션 중 들어오는 입력과 나가는 출력도 각각 검사함.

- **사전**: 운영 중 실시간 생성이 아니라 사전에 만들어 두는 자산을 검사함. 이 지점은 AI 가드레일 자동 검사 대신 사전 자산 생성 시스템의 사람 검수로 갈음할 수 있고(참조 구현은 유람기 마당 플롯 생성 LLM의 사람 검수), 그때 런타임 AI 가드레일 명세는 런타임 입력과 출력 2지점만 담음
- **런타임 입력**: 세션 중 유저가 넣는 입력을 AI에 넘기기 전에 검사함. 텍스트 입력(이름, 응답 등)은 음성 텍스트 변환(STT)을 거친 텍스트가 대상이고, 이미지 입력(유저 도안 등)은 이미지 모더레이션이 대상임. 카메라가 자동 캡처한 프레임(베스트샷 등)은 유저가 넣는 창작 입력이 아니므로 런타임 입력 검사 대상이 아니며, 그 프레임에서 유래한 유해물은 런타임 출력 검사가 배포 전 최종 게이트로 거름
- **런타임 출력**: 세션 중 AI가 만든 생성물을 유저에게 보이기 전에 검사함. 서사와 이미지(일러스트, 사진)는 텍스트와 이미지 모더레이션으로, 3D 생성물(변환 탈 모델 등)은 3D 형상 검사로 검사함

각 지점을 어느 Step에 거는지는 콘텐츠별로 각 기획서가 정의함.

**적용 원칙 (검사 대상 기준)**: 세 지점은 그 콘텐츠에 해당 검사 대상이 있으면 모두 필수임. 다만 런타임 AI 생성과 유저 자유 입력이 없는 체험형(예: 사전 제작 재담과 선택지만 쓰는 콘텐츠)은 런타임 두 지점에 검사 대상이 없어, 사전 지점 검수로 갈음함(생성 없는 체험형). 이 경우에도 사전 검수는 필수이며, 런타임에 새 생성물이나 자유 입력이 생기면 그 지점 검사를 다시 적용함. 한편 사전 제작 자산에 유저 세션 값을 결정적으로 끼워 넣기만 하는 산출물(예: 점수를 얹은 기록증)은 새 생성이 아니므로 그 템플릿 사전 검수로 갈음함.

# 9. 운영 파라미터 (공통 기본값)

콘텐츠 무관 공통 운영 파라미터의 잠정 기본값을 정리함. 구현/운영 단계에서 확정함. 콘텐츠 고유 파라미터는 각 기획서가 정의함.

| 파라미터 | 잠정 기본값 | 확정 시점 | 관련 위치 |
|---|---|---|---|
| 화면 타임아웃 | 예: 60초 (창작이나 촬영 화면 오버라이드 예: 5분) | 구현 | 공용 기능. 화면별 오버라이드는 각 기획서 |
| 터치 미입력 타임아웃 | 예: 45초 | 구현 | 공용 기능. 화면 타임아웃보다 짧게 둠 |
| AI 호출 재시도 N | 예: 2회 | 구현 | 공용 기능 외부 호출 래퍼 |

# 10. 2차연도 확장 설계 (콘텐츠 골격 확장, 현재 구현 밖)

1차연도 1회 세션 체험 골격 위에 2차연도에 얹을 콘텐츠 골격 확장의 방향을 보존함. 재방문 사용자 연속성(학습 프로필, 이어하기, 콘텐츠 횡단 누적)의 데이터 모델과 보안은 [[플랫폼 사양#6. 2차연도 확장 설계 (디지털 도제 연속성, 현재 구현 밖)]]이 다루며, 본 절은 콘텐츠 골격 쪽 확장만 다룸. 상세는 2차연도 설계에서 확정함 (작성 예정).

## 10.1 학습형 도제 심화

1차연도는 1회 체험과 난이도 구분까지임. 2차연도는 무형유산 전승을 위한 학습형을 병행함.

- **체험에서 학습으로**: 1차연도 체험 콘텐츠에 학습형 단계와 통과 기준, 다음 단계 진입을 더함 ([[컨소시엄 회의록 - 2026-06-22#3.5 콘텐츠와 도제 설계]])
- **1회 체험에서 연속 학습으로**: 재방문 학습자의 연속 학습을 전제로 함. 진척과 자산의 누적은 [[플랫폼 사양#6. 2차연도 확장 설계 (디지털 도제 연속성, 현재 구현 밖)]] 연속성 모델을 따름
- **난이도에서 단계 체계로**: 남사당은 표준 커리큘럼이 없어 1차연도는 난이도 수준으로만 구분함. 학습형 심화 시 단계 체계를 콘텐츠 골격에 어떻게 녹일지는 2차연도에 설계함 (작성 예정)

## 10.2 LLM과 온톨로지 (2차연도 결정)

1차연도는 콘텐츠별로 상용이나 오픈소스 LLM을 자체 구축함([[#7. 공통 기술 방향 (회의 근거)]]). 2차연도 통합 여부는 미확정임.

- **통합 여부 미결**: 콘텐츠별 LLM을 통합 프레임워크로 묶을지 별도 운영할지는 각 기관 프로토타입 후 2차연도에 결정함. 사전회의의 "LLM 통합은 2차연도"는 잠정 입장이고, 컨소시엄 회의는 통합과 별개 진행을 모두 열어 둠 ([[컨소시엄 회의록 - 2026-06-22#2. 핵심 합의]], [[큐랩셀빅 사전회의 - 2026-06-22#2. 핵심 합의]])
- **온톨로지 DB**: 종목 지식을 온톨로지로 구조화함. 구조는 LLM 방식이 정해진 뒤 확정함 ([[큐랩셀빅 사전회의 - 2026-06-22#3.2 데이터와 LLM]])
- **상세 미정**: 통합과 별도 운영 중 방식, 온톨로지 스키마, 학습 연동은 각 기관 프로토타입 후 결정함 ([[컨소시엄 회의록 - 2026-06-22#4. 미결과 후속 액션]], 작성 예정)
