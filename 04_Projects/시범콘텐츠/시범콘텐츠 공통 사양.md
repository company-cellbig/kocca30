> 키오스크 분류 시범콘텐츠가 공유하는 공통 사양 정본. 콘텐츠별 기획서(덜미/덧뵈기 등)가 본 문서의 블록을 Obsidian 블록 임베드(`![[#^블록ID]]`)나 참조(`[[#섹션]]`)로 인용함. 콘텐츠 무관 골격만 담고, 콘텐츠 고유 설계는 각 기획서에 둠.

# 1. 적용 범위와 사용법

- **적용 대상**: 키오스크 분류 시범콘텐츠 ([[콘셉트 정리#가. 키오스크]]). 단일 통합 키오스크 플랫폼에서 1인 사용
- **공통과 고유 경계**: 본 문서는 세션, Step 프레임(정의, 명세 항목, 공용 기능), 기술 구성 6영역, 개인정보와 가드레일 원칙, 공통 운영 파라미터 등 **콘텐츠 무관 골격**만 정의. Step별 구체 명세(단계 수, 내용, 번호)와 콘텐츠 고유 설계(플롯, 채점, 페르소나 등)는 각 기획서가 자체 기술
- **인용 방식**: 헤딩 없는 본문 블록(표 등)은 `![[시범콘텐츠 공통 사양#^블록ID]]` 블록 임베드, 그 외는 `[[시범콘텐츠 공통 사양#섹션]]` 참조. **헤딩 섹션 통째 임베드(`#섹션`)는 호스트 문서 헤딩 계층을 꼬이게 하므로 피함** (헤딩은 각 기획서가 소유). 임베드는 Obsidian 열람용이며 외부 출력(GitHub/PDF)은 평탄화 필요

# 2. 세션

## 가. 세션 정의

한 유저의 키오스크 사용 전체(시작 Step → 종료 Step)를 감싸는 상위 컨테이너. 하위 Step들이 세션 안에서 순차 실행됨.

- **라이프사이클**: 생성(시작 Step, 신규) → 상태 저장 반복(진행 중) → 종료 + 리셋(종료 Step)
- **관리 모듈**: §4.다 백엔드 (세션 라이프사이클과 세션 안 데이터 저장 책임)

## 나. 세션 저장 데이터 (공통 항목)

세션이 저장하는 데이터 중 콘텐츠 무관 공통 항목. 콘텐츠 입력과 생성 데이터는 각 기획서가 정의함. **타입과 저장 스키마 등 구현 모델은 적지 않음** ("어떤 값이 들어가는가"까지가 기획 범위).

| 데이터 | 분류 | 들어가는 값과 구성 | 비고 |
|---|---|---|---|
| 세션 ID | 시스템 | 세션마다 부여되는 고유 식별자 | 시작 Step에서 생성 |
| 동의 기록 | 시스템 | 약관 버전 + 동의 시각 | 약관 버전 체계 운영 결정 |
| 연락처 | 개인정보 | 유저 연락처 (결과물 전송용) | 전송 동의 시 임시 저장 → 발송 후 즉시 파기 (거부 시 즉시 파기). 상세 §6 |

- 콘텐츠 입력 데이터(캐릭터 정보, 유저 응답, 결과물 등)와 콘텐츠 생성 데이터(서사, 일러스트, 사진, 모델 등)는 각 기획서가 콘텐츠별로 정의

## 다. Step별 세션 동작

| Step 단계 | 세션 동작 |
|---|---|
| 시작 Step | 세션 생성 |
| 중간 Step | 세션 데이터 갱신 |
| 종료 Step | 세션 종료 + 임시 데이터 파기 + 리셋 |

# 3. Step 프레임

## 가. Step 정의

| 항목 | 정의 |
|---|---|
| 개념 | 시스템 흐름의 순차 단위. 유저가 한 행위로 인식하는 활동 묶음. "지금 어느 단계인가?"에 답하는 단위(시작, 입력, 대기, 감상, 전송, 종료 등) |
| 구성 | 각 Step은 명세 항목으로 정의되고, 공용 기능을 조합해 프로세스를 이룸 |
| 하위 단위(sub-step) | 프로세스는 sub-step을 순서대로 나열한 것. sub-step은 화면 전환, 백엔드 호출, AI 호출 등 실행 단위이며 `N. 행위자: 동작` 한 줄로 표기 |
| 행위자 | sub-step의 행위자는 기본 컴포넌트(UI(클라이언트), AI, 백엔드, 외부 서비스) 중 하나로 하되, 필요 시 구체 모듈을 덧붙일 수 있음(예: AI 이미지 생성 모델, 외부 서비스 SMS). 페르소나는 렌더 주체에 괄호 표기(예: UI(말뚝이)). 사용자 동작은 별도 행위자로 두지 않고 이를 처리하는 UI sub-step에 "사용자 ... 캡처/수집"으로 적음 |
^step-def

## 나. Step 명세 항목

| 항목 | 정의 |
|---|---|
| 트리거 | Step 진입 조건 (사용자 액션 또는 직전 Step 완료) |
| 시스템 | 관여하는 기술 구성 모듈 |
| 화면 | Step이 표시하는 화면(풀스크린 스크린/페이지) 목록과 전환 트리거. 화면 수 = 개발할 스크린 단위(화면 내부 영역과 컴포넌트 분할은 UI 설계 단계). 백그라운드만 있는 Step은 해당 없음 |
| 프로세스 | Step 안에서 순차 실행되는 sub-step을 번호로 나열(`N. 행위자: 동작`). 공용 기능 호출 + 자체 로직. UI sub-step은 해당 화면을 괄호로 표기(예: UI(가이드 화면)). 동시 진행 동작은 (병행) 불릿. 조건부 흐름과 실패 경로는 트리거되는 sub-step의 하위 불릿(`- 분기:` 조건부, `- 실패:` 실패)으로 표기 (Step 레벨 분기 필드 없음) |
| 입력 | Step이 받는 데이터와 이벤트 |
| 출력 | Step이 산출하는 데이터와 상태 |
| 다음 | 다음 Step 또는 종료 조건 |
^step-spec-items

## 다. 공용 기능

여러 Step에 걸쳐 적용되는 횡단 기능. 제공 모듈은 기술 구성, 정책은 가드레일 원칙과 연동. 각 Step의 프로세스 항목은 본 표의 기능을 조합해 작성됨. 적용 방식은 **명시 호출형**(sub-step에서 직접 호출)과 **상시/자동형**(백그라운드 적용)으로 나뉨.

| 기능           | 적용 방식  | 세부                                                                                                                                      |
| ------------ | ------ | --------------------------------------------------------------------------------------------------------------------------------------- |
| 입력 유효성 검증    | 명시 호출형 | 유저 입력(이름, 응답, 연락처 등)을 형식, 길이, 필수 기준으로 검사 (음성 입력은 음성 텍스트 변환(STT)을 거친 텍스트 대상)                                                                           |
| AI 가드레일      | 명시 호출형 | 입출력 안전성 검사. 적용 3지점(사전, 런타임 입력, 런타임 출력)은 모두 필수(§6.나), 각 지점을 어느 Step에 매핑할지는 콘텐츠별로 각 기획서가 정의                                                                                 |
| 개인정보 처리/파기   | 명시 호출형 | 연락처 임시 저장 후 발송 직후(성공, 실패, 거부) 즉시 파기 (종료 Step은 잔류 백스톱). 개인정보 범위는 공통이 연락처(전송용), 그 외는 콘텐츠별로 각 기획서가 정의 (§6.가)                                                            |
| 외부 서비스 호출 래퍼 | 명시 호출형 | STT, AI, 호스팅, SMS 등 외부 호출의 재시도와 타임아웃 표준화                                                                                                    |
| 에러/fallback  | 명시 호출형 | AI 호출/외부 서비스 실패 시 사용자 사과 안내 후 종료 Step                                                                                                   |
| 무응답 타임아웃     | 상시/자동형 | 유저 인터랙션 대기 sub-step(입력 대기와 감상)에서 무응답 임계 시 종료 Step 직행. 임계는 각 대기 sub-step의 비활성 시간 기준(sub-step 전환 시 리셋, 세션/Step 누적 아님). 임계(예: 30초)는 운영 파라미터 |
| 사용 로그와 모니터링   | 상시/자동형 | 전 Step의 진입, 완료, 오류 이벤트 기록 (완주율, 오류율 산출 입력)                                                                                                |
^step-common-funcs

분기와 에러 처리 흐름은 본 표의 "에러/fallback" 항목으로 일원화. 개별 Step 프로세스에서는 호출만 명시함.

# 4. 기술 구성 (6영역 템플릿)

콘텐츠 구현 시스템을 6개 영역으로 정리하는 공통 템플릿. 각 영역의 콘텐츠별 모듈은 기획서가 채움.

## 가. AI 시스템

콘텐츠의 AI 모듈(생성, 변환, 채점, 가드레일 등). 모듈 구성은 콘텐츠마다 다르며 각 기획서가 정의함. 비-AI 오케스트레이션(진행 제어, 결과물 조립)은 다. 백엔드.

각 AI 모듈은 아래 명세 항목으로 정의함 (구현 코드와 하이퍼파라미터는 설계 단계, 기획서는 요건까지).

| 항목 | 정의 |
|---|---|
| 역할 | 모듈이 수행하는 작업 |
| 입력과 출력 | 데이터 형식과 규격 |
| 모델 확보 | 자체 학습, 사전학습 모델, 외부 API, 파인튜닝 중 방식 (후보, 미정은 확인 필요) |
| 판정과 성능 기준 | 정확도, 임계, 응답 속도 등 (정량 미정은 확인 필요, 임의 추정 금지) |
| 적용 | 실시간/배치, 서버/온디바이스, 호출 Step |
| 실패, 한계, 복구 | 모델 미확보, 저신뢰, 오탐, 미탐, 타임아웃 등 실패 조건과 재시도, 한도, fallback. 해당 Step sub-step 실패 분기와 연결 |
| 데이터와 평가 | 학습과 레퍼런스 데이터, 검증 방법 |

## 나. 하드웨어 (키오스크)

- 9:16 세로형 디스플레이 (터치 인식)
- 음향 출력 (인트로, 배경음, 보상 사운드)
- 콘텐츠별 입력 장치 (마이크, 카메라, 외부 센서 등)
- 네트워크 연결 (AI 서버 통신, 전송)

## 다. 백엔드

- 키오스크 ↔ AI 서버 API
- 세션 관리 (세션별 진행 상태, §2)
- 진행 제어 (Step 순차 진행, 콘텐츠별 로직)
- 결과물 조립과 저장 (생성물 결합 + 저장소)
- 개인정보 처리 (연락처 등, §6)
- 고객 동의 약관 관리 (버전과 동의 기록)

## 라. 외부 서비스 연동

- 전송 서비스 (SMS/이메일 등)
- AI API (LLM, 이미지 생성, 포즈 추정 등 콘텐츠별)
- STT 서비스 (음성 입력 사용 시)
- 결과물 호스팅 (전송 링크 방식 사용 시)

## 마. 클라이언트 UI (키오스크 앱)

- 페이지 전환과 터치 인터랙션 프레임워크
- 화면 흐름: 콘텐츠 Step 순서 구현
- 진행 호스트 렌더링 (콘텐츠별 페르소나, 사용 시)
- 입력 UI: 가상 키보드, 음성, 카드 선택, 카메라 등 콘텐츠별
- 자동 타임아웃, 다음 유저용 리셋

## 바. 운영과 모니터링

- 키오스크 가동 상태 모니터링
- 사용 로그 (유저 수, 완주율, 오류율)
- 에러 fallback (AI 호출/외부 서비스 실패): 처리 규칙은 공용 기능 에러/fallback 항목으로 일원화

# 5. 공통 Step 동작

콘텐츠 무관하게 형태가 거의 같은 Step의 공통 동작. 각 기획서는 이를 자기 Step 번호에 매핑하고 콘텐츠 고유 디테일을 더함.

## 가. 인트로 (시작 + 동의)

- 신규 세션 생성 → 인사말과 가이드 화면 → 고객 동의 약관 화면 → 동의 감지 → 동의 기록 저장
- 무응답 타임아웃 발동 시 미동의 간주 → 종료 Step 직행 (별도 거부 버튼 없음)
- 콘텐츠가 카메라 등 추가 처리를 쓰면 해당 동의를 약관에 포함

## 나. 결과물 전송

- **정상 흐름**: 연락처 입력과 전송 동의 안내 → 연락처 임시 저장 → 외부 서비스로 전송 → 발송 직후 즉시 파기
- **거부 흐름**: 거부 시 전송 생략, 종료 Step으로
- **실패 흐름** (외부 서비스 호출 래퍼):
	- 일시 장애: 재시도 N회
	- 수신처 영구 실패: 재입력 1회 허용 후 종료
	- 그 외 영구 실패: 사과 후 종료 + 운영 알림

## 다. 종료와 리셋

- 마무리 인사 화면(선택) → 세션 종료 + 임시 데이터 파기 → 시작 화면 복귀(다음 유저 대기)

# 6. 개인정보와 가드레일 원칙

## 가. 개인정보 처리 정책 (공통 원칙)

- **개인정보 소유 경계**: 공통 필수 항목은 연락처(전송용) 하나. 그 외 개인정보(얼굴, 영상 등)는 콘텐츠별로 각 기획서가 자기 범위를 열거함. 모든 항목의 보관 기간은 법무 검토 후 확정(잠정)
- **연락처 처리**
	- "임시 저장": 메모리 only, 디스크 영속화 금지, 로그 미기록
	- "즉시 파기": 발송 응답 수신 직후(성공/실패 무관) 메모리 명시적 0 덮어쓰기 + 변수 해제
- **동의 미보유 상태**: 시작 Step에서 세션 생성되나 미동의 시 세션 전체 즉시 파기 (동의 기록 미생성)
- **입력 유효성 백엔드 재검증**: 클라이언트 검증 외 백엔드 재검증 필수 (클라이언트 우회 대비)
- **데이터 보관 기간**: 동의 기록, 결과물, 로그의 보관 기간은 잠정값(법무 검토 후 확정). 콘텐츠별 데이터 항목은 각 기획서가 정의

## 나. 가드레일 적용 3지점

가드레일은 3지점에 적용. 사전 검수만으로 무인 안전이 닫히지 않으므로 출력 단계에서도 반드시 검사함.

- **사전** (운영 전 생성 단계): 사전 생성물 검수
- **런타임 입력**: 유저 입력 검사
- **런타임 출력**: 생성물(서사, 이미지, 사진 등) 검사
