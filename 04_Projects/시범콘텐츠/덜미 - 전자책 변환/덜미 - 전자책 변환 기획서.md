> 박첨지놀이를 소재로 한 AI 그림동화 시범콘텐츠의 개발 기획서. [[덜미 - 전자책 변환 결정사항]]을 입력으로 작성함. 골격 단계 — 점차 채워나감.

# 1. 개요

## 가. 콘텐츠 정의

박첨지놀이(덜미)를 소재로 한 AI 그림동화 콘텐츠. AI와 유저가 거리(마당) 단위로 이야기를 함께 지어 그림동화 전자책을 완성함.

- **소재**: 한국 전통 인형극 박첨지놀이(덜미) ([[박첨지놀이]])
- **플로우**: AI가 거리 문법 기반 플롯 제시 → 유저가 이름과 거리별 응답(상황별 행동, 이야기 전개)을 입력 → AI가 일러스트와 서사를 묶어 그림동화 전자책 생성 ([[덜미 - 전자책 변환 결정사항]] §1 콘셉트)
- **매체**: 9:16 세로형 키오스크 터치 인터페이스 ([[덜미 - 전자책 변환 결정사항]] §2 제약)
- **핵심 특성**: 비고정 출력 — 덜미 문법은 고정하되 그 안을 유저 입력으로 채워 결과물이 매번 달라짐. 전승과 참여가 동시 성립 ([[덜미 - 전자책 변환 결정사항]] §1)
- **산출물 성격**: 2D 일러스트와 서사 중심 (4D 미연계, [[덜미 - 전자책 변환 결정사항]] §5 개발 전 결정사항 4)

목표, 범위 등 나머지 개요 항목은 작성 예정.

# 2. 시스템 플로우

- 매체: 9:16 세로형 키오스크 터치. 플레이타임 목표 5분 (세션 전체 S1~S7 합산 목표, 강제 카운트다운 아님)
- 큰 흐름(스케치): 인트로(동의 약관) → 거리별 입력 → AI 생성 → 그림동화 결과

> 단계별 진행, 담당 시스템, 프로세스, 입출력을 표기. 사용자 측 기본 흐름(시작/진행/마무리)을 시스템 관점으로 확장. §4 기술 구성의 각 모듈이 단계별로 어떻게 협력하는지 보임.

**표기**: `S` = Step(순차 단계). S1~S7은 재생 순서대로의 단계 ID (§3.가의 `T` = Type와 구분 — T는 카탈로그 ID, 순서 아님)

**개요**: S1 인트로 → S2 캐릭터 정보 입력 → S3 플롯 문답 (반복) → S4 결과물 생성 + 대기 화면 (병행) → S5 결과물 표시 → S6 결과물 전송 → S7 종료/리셋

## 가. 세션

**세션 정의**: 한 유저의 키오스크 사용 전체(S1 시작 → S7 종료)를 감싸는 상위 컨테이너. 하위 Step들이 세션 안에서 순차 실행됨.

**세션 라이프사이클**: 생성(S1, 신규) → 상태 저장 반복(S2~S6, 진행 중) → 종료 + 리셋(S7, 종료)

**관리 모듈**: §4.다 백엔드 (세션 라이프사이클과 세션 안 데이터 저장 책임을 가진 §4 시스템 영역)

**세션 안 저장 데이터**:

- 세션 ID, 고객 동의 약관 동의 기록 (버전, 타임스탬프)
- **콘텐츠 입력** (개인정보 아님 — 그림동화 콘텐츠 생성용):
	- 캐릭터 정보 (성별, 연령대, 이름) — 유저 조연(박첨지 동행) 설정
	- 선택된 마당 유형 (§3.가.2, S3에서 유저 선택)
	- 거리별 응답 누적, 박첨지 진행 대화 로그
	- 그림동화 결과물 파일 (다중 페이지)
- **개인정보**:
	- 전화번호 (S6 전송 동의 시 임시 저장 → SMS 발송 후 즉시 파기, 거부 시 즉시 파기)

**Step별 세션 동작**:

- S1 세션 생성
- S2~S6 세션 데이터 갱신
- S7 세션 종료 + 임시 데이터 파기 + 리셋

## 나. Step

Step은 시스템 플로우의 순차 단위. 본 절에서 Step 정의 및 공용 기능과 Step별 명세를 다룸.

### 1) Step 정의 및 공용 기능

**Step 정의**: 시스템 플로우의 순차 단위. 유저가 한 행위로 인식하는 활동 묶음 — "지금 어느 단계인가?" 질문에 답할 수 있는 단위(시작/입력/대기/감상/전송/종료 등). S1~S7 각 Step은 아래 명세 형식으로 정의되며, 공용 기능을 조합해 프로세스를 구성함.

**Step 명세 항목**

- **트리거**: Step 진입 조건 (사용자 액션 또는 직전 Step 완료)
- **시스템**: 관여하는 §4 기술 구성 모듈
- **프로세스**: Step 안에서 실행되는 sub-step 순서 — sub-step은 활동을 완수하기 위한 실행 단위(화면 전환, 백엔드 호출, AI 호출 등). 유저 감각 인지 여부는 부수적이며, 같은 활동 안의 진행으로 인식됨. 공용 기능 호출 + 자체 로직 포함
- **입력**: Step이 받는 데이터/이벤트
- **출력**: Step이 산출하는 데이터/상태
- **다음**: 다음 Step 또는 종료 조건
- **분기**: 조건부 흐름 (예: 미동의 시 S7 직행)
- **에러 분기**: 실패 시 fallback 경로 (필요 시)

**sub-step 명세 형식**

- **최소 형식**: `N. 행위자: 동작 한 줄` (현행 모든 Step의 프로세스 표기 방식)
- **확장 형식** (분기/에러/공용 기능 호출이 명시 필요할 때): 행위자/동작 줄 아래 들여쓰기로 부연
	- **입력/출력**: 외부/Step 경계에서 처음 받거나 영속화될 때만 명시 (직전 sub-step 흐름이 자명하면 생략)
	- **분기**: sub-step 안 조건부 흐름 (예: 유효성 실패 시 재입력)
	- **에러 처리**: sub-step 자체 재시도 또는 Step 에러 분기로 위임
	- **호출 공용 기능**: §2.나.1) 공용 기능 표 항목 참조
- Step 명세 항목과 이름이 겹치는 항목(입력/출력/분기/에러)은 적용 단위가 다름 — Step 경계 데이터는 Step 명세에, sub-step 경계 데이터는 sub-step 명세에 적음
- 적용 원칙: 단순 시퀀스는 최소 형식만. 가독성을 위해 확장 형식은 의미 있는 변형이 있는 sub-step에만 적용

**공용 기능**: 모든 Step이 호출하는 횡단 기능. 제공 모듈은 §4 기술 구성, 정책은 §3 콘텐츠 설계와 연동. 각 Step의 프로세스 항목은 본 목록의 기능을 조합해 작성됨.

| 기능           | 세부                  | 제공 모듈              | 사용 Step                       | 비고                                |
| ------------ | ------------------- | ------------------ | ----------------------------- | --------------------------------- |
| 무응답 타임아웃     | 유저 인터랙션 대기 sub-step(입력 대기 + 감상)에서 무응답 임계 시 S7 직행 | §4.다 백엔드 + §4.마 UI | S1~S6 중 유저 인터랙션 대기 sub-step | 임계(예: 30초)는 구현 단계 운영 파라미터로 확정     |
| 입력 유효성 검증    | 폼/응답/연락처 형식, 길이, 필수 | §4.마 UI            | S2 캐릭터 정보 / S3 응답 / S6 전화번호   | —                                 |
| AI 가드레일      | 입출력 안전성 검사          | §4.가 AI 시스템        | S3 질문/응답 / S4 서사/일러스트         | 정책 정본 §3.다                        |
| 개인정보 처리/파기   | 임시 저장, 즉시 파기 정책     | §4.다 백엔드           | S6 전화번호 임시 저장 / S7 파기         | 개인정보는 전화번호 단일. 캐릭터 정보/응답은 콘텐츠 데이터 |
| 에러/fallback  | 사용자 사과 안내 후 S7      | §4.바 운영/모니터링       | 전 Step (특히 S3/S4/S6)          | AI 호출 실패, 외부 서비스 실패 모두 적용         |
| 외부 서비스 호출 래퍼 | 재시도, 타임아웃 표준화       | §4.라 외부 서비스        | S3/S4 AI 호출 / S4 호스팅 / S6 SMS | —                                 |
| 사용 로그/모니터링   | Step 진입/완료/오류 이벤트   | §4.바 운영/모니터링       | 전 Step                        | 완주율, 오류율 산출 입력                    |
| 박첨지 캐릭터 렌더링  | 단계 전반 일관성           | §4.마 UI            | S1~S5 전체                      | 정체성 정본 §3.라                       |

공용 기능은 각 Step의 프로세스 항목에서 직접 호출되거나, 백그라운드에서 자동 적용됨(예: 타임아웃, 로그). 분기/에러 처리 흐름은 본 목록의 "에러/fallback" 항목으로 일원화 — 개별 Step 프로세스에서는 호출만 명시함.

### 2) Step별 명세

#### 가) S1. 인트로 (시작 + 동의)

- **트리거**: 유저가 시작 버튼 터치
- **시스템**: 클라이언트 UI (§4.마), 백엔드 (§4.다)
- **프로세스**
	1. 백엔드: 신규 세션 생성
	2. UI: 인사말 화면 표시 + "터치하세요" 안내
	3. UI: 터치 캡처 → 진행 가이드 화면
	4. UI: 터치 캡처 → 고객 동의 약관(주의사항) 화면
	5. UI: 동의 버튼 터치 캡처
		- 호출 공용 기능: 무응답 타임아웃
		- 분기: 무응답 타임아웃 발동 시 미동의로 간주 → S7 직행 (별도 거부 버튼 없음)
	6. 백엔드: 동의 기록 저장 (세션 ID, 약관 버전, 타임스탬프)
- **입력**: 터치 이벤트, 동의 결정
- **출력**: 세션 ID, 동의 기록
- **분기**: 무응답 타임아웃에 의한 미동의 → S7 직행 (sub-step 5 분기 참조)
- **다음**: S2

#### 나) S2. 캐릭터 정보 입력

- **트리거**: S1 동의 완료
- **시스템**: 클라이언트 UI (§4.마), 백엔드 (§4.다)
- **프로세스**
	1. UI: 8개 카드(아이/청소년/청년/장년 × 남/여) 중 1개 선택 + 이름 입력 폼 (유저 조연(박첨지 동행) 설정. §3.나 변주 슬롯 설계와 연동)
	2. UI: 이름 유효성 검증 (클라이언트 비속어 필터)
		- 호출 공용 기능: 입력 유효성 검증
		- 분기: 비속어 검출 시 팝업 안내 → sub-step 1로 재진입
	3. 백엔드: 세션에 캐릭터 정보 저장
- **입력**: 카드 선택(성별 × 연령대), 이름
- **출력**: 세션 캐릭터 정보 갱신
- **다음**: S3

#### 다) S3. 마당 선택 + 플롯 문답 (거리별 반복)

- **트리거**: 캐릭터 정보 입력 완료
- **시스템**: AI 시스템 (§4.가), 클라이언트 UI (§4.마), 백엔드 (§4.다)
- **프로세스**: 유저가 마당 유형을 고르면 시스템이 그 유형 풀에서 랜덤 마당을 배정(sub-step 1~2), 이후 배정된 마당의 4거리(도입/전개/절정/마무리, §3.가.3)를 순서대로 sub-step 3~5 묶음 반복
	1. UI: 마당 유형 4종 카드 제시 → 유저가 1개 선택
		- 호출 공용 기능: 무응답 타임아웃
		- 분기: 무응답 타임아웃 → S7 직행
	2. 백엔드: 선택 유형 풀에서 랜덤 마당 1개 배정 (사전 생성/검수된 플롯, §3.가.4)
	3. UI: 박첨지 캐릭터 + 해당 거리의 사전 생성 질문 표시(고정), 유저 응답 입력 받기
		- 호출 공용 기능: 무응답 타임아웃
		- 분기: 무응답 타임아웃 → S7 직행
	4. AI 가드레일: 유저 응답 검사 (§3.다)
		- 호출 공용 기능: AI 가드레일
		- 분기: 위반 시 팝업 안내 → sub-step 3으로 재진입 (유저 재입력)
	5. 백엔드: 응답을 세션에 누적 저장
- **입력**: 마당 유형 카드, 유저 유형 선택, 거리별 응답(텍스트)
- **출력**: 선택 유형 + 배정 마당, 거리별 응답 누적, 박첨지 진행 대화 로그
- **다음**: 모든 거리 완료 시 S4

#### 라) S4. 결과물 생성 + 대기 화면 (병행)

- **트리거**: 플롯 문답 완료
- **시스템**: AI 시스템 (§4.가), 클라이언트 UI (§4.마), 백엔드 (§4.다), 외부 서비스 (§4.라)
- **프로세스** (백그라운드와 포그라운드 동시, 폴링으로 동기화)
	- **백그라운드 — 결과물 생성**
		1. AI 유저 입력 가공 LLM: 응답을 거리별 서사 텍스트로 변환
		2. AI 이미지 생성 모델: 거리별 일러스트 생성 (§3.라 시각 정체성, §3.마 자산)
		3. AI 결과물 조립: 서사와 일러스트를 그림동화 페이지로 결합
		4. **AI 가드레일: 생성물 출력 검사** (§3.다) — 서사(유저 텍스트 보간 포함)/일러스트가 가드레일 정책 통과하는지 검사
			- 분기: 위반 시 sub-step 1로 재생성 (N회 한도). 한도 초과 시 상태 `failed`
		5. 백엔드: 검사 통과한 결과물을 저장소에 저장
		- 백엔드 상태 머신: `generating` / `completed`(가드레일 통과분만) / `failed` (생성 실패 또는 가드레일 한도 초과)
	- **포그라운드 — 대기 화면**
		1. UI: 대기 콘텐츠 노출 — 덜미 준비 과정 영상 또는 큐레이션된 다른 유저 결과물 (§3.마)
		2. UI: 백엔드 상태 폴링 (주기 예: 1초)
			- 분기:
				- `generating` → 대기 화면 유지
				- `completed` → 즉시 S5 전환
				- `failed` → 사과 화면 → S7
				- 폴링 N회 연속 무응답 (예: 5회) → 자체 에러 화면 → S7
- **입력**: 세션 응답 전체, 캐릭터 이름
- **출력**: 그림동화 파일 (다중 페이지)
- **에러 분기**: AI 호출 실패 **또는 생성물 가드레일 한도 초과** 시 fallback (§4.바 운영/모니터링) — 백그라운드 재시도 N회(예: 2회) 후 실패 시 상태를 `failed`로 전환. 포그라운드가 폴링으로 검출 → 사과 화면 → S7. 구체 N과 폴링 주기는 구현 단계 운영 파라미터로 확정
- **다음**: 포그라운드 폴링이 `completed` 받으면 즉시 S5

#### 마) S5. 결과물 표시

- **트리거**: 그림동화 파일 생성 완료
- **시스템**: 클라이언트 UI (§4.마), 백엔드 (§4.다)
- **프로세스**
	1. UI: 결과물 첫 페이지 표시
	2. UI: 페이지 넘김 인터랙션 (터치) — 감상 sub-step (입력 대기와 동급으로 분류)
		- 호출 공용 기능: 무응답 타임아웃
		- 분기: 무응답 타임아웃 → S7 직행 (감상 종료로 간주)
	3. UI: 마지막 페이지 도달 시 "전송" 버튼 노출 (자동 전환 옵션도 UI 디자인 단계에서 검토)
- **입력**: 그림동화 파일
- **출력**: 유저가 결과물 확인
- **다음**: 유저가 "전송" 버튼 진행 → S6 (전송 안내 화면은 S6 시작 단계에서 표시)

#### 바) S6. 결과물 전송

- **트리거**: 유저가 전송 안내 화면에서 진행
- **시스템**: 클라이언트 UI (§4.마), 백엔드 (§4.다), 외부 서비스 (§4.라)
- **프로세스**
	1. UI: 전화번호 입력 폼, 전송 동의 안내
	2. 백엔드: 전화번호 임시 저장 (개인정보 처리 정책 — 전송 동의 시 SMS 발송 후 즉시 파기, 거부 시 즉시 파기)
	3. 외부 서비스 SMS: 결과물 호스팅 URL 또는 이미지 전송
		- 호출 공용 기능: 외부 서비스 호출 래퍼
		- 분기 (실패 유형별):
			- 통신 경로 일시 장애 (네트워크/게이트웨이/통신사) → 재시도 N회 (예: 2회, 백오프 1초/3초)
			- 수신 번호 영구 실패 (없는 번호, 잘못된 형식, 차단된 번호) → "전화번호 확인" 팝업 + 재입력 1회 허용 후 S7
			- 그 외 영구 실패 (컨텐츠 거부 등) → 사과 후 S7 + 운영 모니터링 알림
- **입력**: 전화번호, 전송 동의
- **출력**: SMS 발송 결과
- **분기**: 거부 시 SMS 단계 생략, S7로
- **다음**: S7

#### 사) S7. 종료 / 리셋

- **트리거**: 결과물 전송 완료 또는 미동의 또는 타임아웃 또는 유저 이탈
- **시스템**: 클라이언트 UI (§4.마), 백엔드 (§4.다)
- **프로세스**
	1. UI: 마무리 인사 화면 (선택)
	2. 백엔드: 세션 종료, 임시 데이터 파기 (개인정보 처리 정책 — 전화번호 잔류 시 즉시 파기. 콘텐츠 데이터는 결과물 호스팅 후 정책 기간 보관)
	3. UI: 시작 화면 복귀 (다음 유저 대기)
- **입력**: 종료 트리거
- **출력**: 키오스크 idle 상태
- **다음**: 다음 유저용 S1 대기

## 다. 데이터 항목

# 3. 콘텐츠 설계

본 콘텐츠의 정체성(박첨지 페르소나, 마당 플롯 구조, 변주, 가드레일 정책, 자산)을 정의. §4 기술 구성은 본 절에서 정의된 것의 구현/배치를 다룸.

## 가. 플롯 구조

> 한 세션 = 한 마당 = 완결된 그림동화 한 편. AI가 덜미 문법으로 4종 마당 유형의 플롯을 사전 생성해 두고, 유저가 유형을 고르면 그 유형 마당 하나가 랜덤으로 주어져 거리 단위로 채움. 박첨지가 주역, 유저는 그 곁에 합류한 조연.

**플롯 단위 = 마당**. 위계는 [[박첨지놀이]] 기준 `굿(극) > 마당(막) > 거리(장/경)`(심우성 남사당놀이 분류). 정리된 덜미 문법(마당/거리 분석으로 추출한 설계 자산)을 토대로 AI가 **다수의 마당 플롯을 생성** — 마당마다 틀(구조)이 다른 여러 골격(4종) ([[덜미 - 전자책 변환 결정사항]] §1 콘셉트).

### 1) 마당 = 플롯 단위

- **마당 정의**: 박첨지 등장(도입)부터 닫는 해설(마무리)까지 하나의 인과 줄기로 이어지는 응집된 극 단위. 원형은 [[박첨지놀이]] 2마당 7거리
- **한 세션 = 한 마당 = 한 편의 그림동화**
- **여러 틀 중 하나로 생성 (4종)**: 마당은 고정된 한 틀이 아니라 4종 유형(§3.가.2) 중 하나로 만들어짐. 각 유형은 자기 고유 절정을 가진 독립 완결 구조라, 어떤 풍자도 격하 없이 자기 마당을 가짐
- **같은 틀, 다른 내용 → 매번 다른 결과 (비고정 출력)**: 고정된 건 틀(유형의 구조)뿐. 세션마다 다른 결과는 두 축에서 나옴:
	- **사전 풀 + 랜덤 선택** — 유형별로 사건/박첨지 질문이 다른 마당 플롯을 다수 사전 생성(검수)해 두고, 런타임에 그 유형 풀에서 랜덤 1개 배정 (예: 위협이 괴물/도적/재난 등 — 풀에 미리 마련). **질문은 플롯에 고정**(런타임 재생성 아님, §3.가.4 / §4.가)
	- **유저 입력** — 이름, 합류 계기, 거리별 답 (이야기 살이 되고 최종 전자책에 반영). 이름/캐릭터는 고정 질문에 슬롯으로 치환 가능
- 틀은 4종으로 한정되지만 사전 풀 크기 × 랜덤 × 유저 입력 조합이 커, 같은 유형이라도 그림동화가 매번 달라짐 ([[덜미 - 전자책 변환 결정사항]] §2 제약, §3.가 가져갈 것 5 에피소드식 구성)

### 2) 마당 유형 (4종)

덜미 7거리의 갈등 핵을 4종 마당 구조로 정리. **각 구조는 전개→절정이 인과로 직결된 독립 완결 단위** — 전개의 갈등 대상이 그 마당의 절정에서 해소됨:

| 마당 유형 | 전개 (갈등) | 절정 (해소) | 풍자 초점 | 원형 거리 |
|---|---|---|---|---|
| 위협-구원형 | 외부 위협 고조 | 홍동지가 힘으로 처치 | 위협의 정체 | 이시미거리 |
| 권력 풍자형 | 권력자 허세 | 골계적 추락 (홍동지 조롱 가능) | 권력/허세 | 매사냥+상여거리 |
| 위선 폭로형 | 위선 행각 | 폭로/망신 (홍동지 축출 가능) | 위선 | 피조리거리 |
| 욕심/다툼형 | 욕심 다툼 | 파국/손해, 떠남 (홍동지 약함, 아래 주) | 욕심 | 꼭두각시거리 |

- 홍동지 응징(가져갈 것 4)은 위협-구원형의 고유 절정이자 권력/위선형에서도 조롱/축출로 변주 발현 — 보편 단일 절정이 아니라 유형별로 다른 해소
- **욕심/다툼형은 홍동지 카타르시스가 약한 유형** — 원형 꼭두각시거리가 박첨지 가정사 중심이라 본디 홍동지 비중이 낮음. 절정에 홍동지 변주를 넣을지는 추후 확장 대상 (현 기획 단계 미구체화)
- 각 유형 내부는 유저 입력 기반 무한 변주 (§3.가.4)

### 3) 마당 공통 골격 (도입/마무리 공유)

모든 유형은 박첨지가 여닫는 공통 골격을 공유. 한 마당 = 4거리. **플레이타임 목표 5분은 세션 전체(S1~S7, 마당 선택 포함) 합산 목표** (§2, 강제 카운트다운 아님). 아래는 본편 거리의 대략 배분 (비-거리 단계와 함께 5분 안에 듦):

| 거리(장면) | 기능 | 공유/가변 | 분량 목표 |
|---|---|---|---|
| 도입 | 박첨지 등장/유람 + 유저(조연) 합류, 첫 재담 | 공유 문법 | ~0.5분 |
| 전개 | 선택된 유형의 갈등 등장 | 유형별 (§3.가.2) | ~1.5분 |
| 절정 | 선택된 유형의 해소 | 유형별 (§3.가.2) | ~1.5분 |
| 마무리 | 무상한 닫음, 박첨지 닫는 해설 | 공유 문법 | ~0.5분 |

- 본편 4거리 ~4분, 나머지 ~1분은 인트로/마당 선택/생성 대기/전송 등 비-거리 단계 (세션 전체 5분 목표 안)
- **도입/마무리는 박첨지가 직접 여닫음** (해설자 겸 주역, 가져갈 것 1). **유저는 박첨지 곁에 합류한 조연** — 주인공이 아니라 박첨지 유람의 동행 ([[덜미 - 전자책 변환 결정사항]] §3.가 가져갈 것 1, §3.라 일치)
- 유형별로 다른 건 **전개+절정 2거리** — 이게 4종 구조를 가름

### 4) 생성/제시/채움 (사전 생성 + 런타임 선택)

> **A 고정 하이브리드** — 마당 플롯(거리별 질문 포함)은 사전 생성/검수, 런타임은 선택과 응답 수집만. 키오스크 무인 운영의 안전/속도/안정 우선 (§3.다, [[ref_제안요청서]] §2 나 검증위원회).

- **사전 생성**: 박첨지 LLM(§4.가)으로 유형별 다수 마당 플롯을 미리 생성 — 거리별 박첨지 질문 텍스트까지 고정. 사전 가드레일 검수 후 풀에 저장 ([[마당 사건 풀]] 시드 활용)
- **유저 선택 (유형 단위)**: 유저는 **마당 유형 4종 중 하나를 선택**(병렬 카드). 시스템이 그 유형 풀에서 **랜덤으로 마당 1개 배정** = 주어진 마당 (§2.나 S3). 무응답 시 타임아웃 정책
- **거리별 채움**: 주어진 마당의 거리(도입/전개/절정/마무리)를 순서대로 제시(고정 질문) → 유저가 각 거리에 응답. 이름/캐릭터는 슬롯 치환 정도의 가벼운 개인화
- **전자책 생성**: 종료 후 유저 응답 전체를 토대로 서사/일러스트를 런타임 생성 (§2.나 S4, §4.가 유저 입력 가공 LLM)
- **다양성**: 마당 유형(4) × 유형별 사전 풀 크기 × 유저 응답 → 같은 유형도 매번 다름. 질문 적응형(유저 답 반영 재질문)은 2년차 검토 ([[로드맵 1단계 2년차]])

### 5) 가드레일 참고 (유지)

- 위선형: 특정 실명/단체 풍자 차단. 윤리적 위선(남을 속이는 행위 등)으로 추상화
- 욕심/다툼형: **처첩 삼각관계 default 금지** ([[덜미 - 전자책 변환 결정사항]] §3 전통의 재창조 §나. 버릴 것). 재산/명예/기회 등으로 추상화
- 권력 풍자형: 실제 정치인/공공인물 풍자 차단. 추상화된 권위만
- 위협-구원형: 위협이 특정 사람/집단 비방으로 흐르지 않게

세부 가드레일 정책은 §3.다 참조.

### 6) 정체성 매핑 (검증)

| 원칙 ([[덜미 - 전자책 변환 결정사항]] §3.가/나) | 적용 위치 |
|---|---|
| 박첨지 = 해설자 겸 주역 (가져갈 것 1) | 도입/마무리 박첨지가 여닫음, 유저는 조연 |
| 재담과 메타연극성 (가져갈 것 2) | 전 거리 박첨지 진행 |
| 풍자 정신 (가져갈 것 3) | 4종 유형 풍자 초점 (위협/권력/위선/욕심) |
| 홍동지 응징 카타르시스 (가져갈 것 4) | 위협-구원형 절정(힘), 권력형(조롱)/위선형(축출) 변주. **욕심/다툼형은 약함 — 추후 확장(§3.가.2)** |
| 에피소드(거리)식 구성 (가져갈 것 5) | 마당 유형 다양성 + 거리 beat + 내용 변주 |
| 골계적 반전 (가져갈 것 6) | 권력 풍자형 절정 (허세의 허망한 추락) |
| 인형극 시각 양식 (가져갈 것 7) | §3.마 자산 적용 |
| 고정 줄거리 버림 (버릴 것 1) | 유형 골격만 고정, 풍자 대상/사건은 유저 입력 변주 |
| 시대적으로 낡은 내용 버림 (버릴 것 2) | 욕심/다툼형 가드레일 (처첩 default 금지) |
| 연행 규모 버림 (버릴 것 3) | 2시간 2마당 7거리 → 5분 한 마당 4거리 |

[[박첨지놀이]] 매핑: 7거리의 갈등 핵 4종(위협/권력/위선/욕심)을 각각 독립 마당 유형으로, 도입(박첨지유람)/마무리(절 짓고 허는 거리)는 공통 골격으로. 어느 풍자도 격하 없이 자기 마당을 가짐.

## 나. 변주 슬롯

**변주** = 같은 틀(마당 유형/거리 골격)에 다른 내용(사건/풍자 대상/인물)을 넣어 매번 다른 결과를 만드는 것 — 변주곡처럼 틀은 그대로, 내용만 바뀜. 본 절은 유저 입력이 그 변주를 일으키는 지점(슬롯)을 정의함.

- 유저 입력(이름, 마당 선택, 거리별 응답)을 이야기 동력으로 전환하는 설계. 변주 명세는 §3.가.4 생성/제시/채움 참조
- 결정사항 §3 전통의 재창조 §다 "유저 세계 → 풍자 대상/갈등 소재 생성" 원리 적용 ([[덜미 - 전자책 변환 결정사항]] §3.다 바꿔서 가져갈 것)
- **AI 질문 변주 정책 (의도/사건 다양화)**: 같은 마당 유형이라도 질문이 단조롭지 않도록 — **사전 생성 단계에서** 유형 풀에 아래 차원의 변주를 충분히 마련하고, 런타임은 그 풀에서 랜덤 선택. 변주 차원:
	- **사건 형태** — 거리 안에서 사건 컨텍스트가 변주 (예: 도입 거리 — 길에서 / 잔치에서 / 시장에서 등)
	- **풍자 대상** — 추상화된 권위/위선 형태 변주 (예: 권력 풍자형 — 허세 권위자 / 겉만 번지르 / 횡포한 자 등)
	- **박첨지 입장** — 목격자 / 당사자 / 풍자자 등 역할 변주

  구현은 §4.가 박첨지 페르소나 LLM의 **사전 질문 생성** 단계에서 다양성 메커니즘 적용 (prompt 변주, 유형별 사건 풀, temperature 조절 등 — 구체 메커니즘은 §4.가 구현 단계에서 발전). 사전 가드레일 검수로 §3.다 정책(특정 실명/단체 차단 등)을 풀 전체에 일관 적용
- **변주 vs 일관성 균형**: 변주 = 사건/풍자 대상/박첨지 입장. 일관성 = 마당 유형/공통 골격의 고정 문법(§3.가.2~3). 예 — 도입 거리는 항상 "박첨지 등장 + 유저 합류" 골격 유지, 그 안의 사건만 다양
- 세부 설계(유저 응답 → 사건 매핑 LLM 프롬프트, 마당 유형 제시/선택 로직) 작성 예정

## 다. 가드레일 (정책)

콘텐츠 정체성/안전 정책을 본 절에서 정의. 구현은 §4.가 AI 시스템의 가드레일 모듈에서.

- AI 가드레일 + 인트로 동의 약관 절차 ([[덜미 - 전자책 변환 결정사항]] §5 개발 전 결정사항 2)
- 검증위원회 자문 ([[ref_제안요청서]] §2 나)
- **가드레일 적용 3지점**: ① 사전 — 마당 플롯 질문 생성 검수 (§4.가), ② 런타임 입력 — 유저 응답 검사 (S3), ③ 런타임 출력 — 전자책 생성물(서사/일러스트) 검사 (S4). 사전 검수만으로 무인 안전이 닫히지 않으므로 런타임 출력 게이트 필수
- **생성물 검사 항목** (S4): 유저 텍스트 보간 안전, 전통 정체성 왜곡, 부적절 콘텐츠, 이미지 안전
- 세부 정책(전통 왜곡 판정 기준, 부적절 콘텐츠 분류, 동의 약관 항목 구체화 등) 작성 예정

## 라. 박첨지 페르소나

본 콘텐츠의 정체성 중심. 모든 플롯 진행을 박첨지가 해설/주역으로 엮음.

- **역할**: 떠돌이 노인 해설자 겸 주역, 거리를 잇는 목소리. 유저는 박첨지 곁에 편입되는 조연 ([[덜미 - 전자책 변환 결정사항]] §3.가 가져갈 것 1)
- **화법**: 산받이/관객과 주고받는 재담 양식 ([[덜미의 각본 재미 요소]] 참조)
- **시각 정체성**: 나무 인형극 박첨지 캐릭터의 도구/의상 고유특징 유지 ([[덜미 - 전자책 변환 결정사항]] §5 개발 전 결정사항 1)
- 세부 페르소나(말투, 어휘, 반응 패턴 등) 작성 예정

## 마. 콘텐츠 자산

콘텐츠가 사용하는 시각/서사 자산. 구체 산출 방식, 호스팅 등은 §4 기술 구성에서.

- **박첨지 캐릭터 디자인** — 인형 시각 정체성 적용 (§3.라)
- **마당 유형 템플릿** — §3.가.2 4종 유형 + §3.가.3 공통 골격(도입/전개/절정/마무리)
- **[[마당 사건 풀]]** — 유형별 사건 컨텍스트 풀 (위협-구원/권력/위선/욕심 + 공통 도입/마무리, 각 5~10개 시드). **사전 질문 생성** 시 박첨지 LLM이 선택 (§3.나 / §4.가). 운영 중 추가/제거
- **마당 플롯 풀 (사전 생성)** — 위 사건 풀을 토대로 박첨지 LLM이 사전 생성한 유형별 마당 플롯(거리별 질문 고정) 모음. 런타임 랜덤 배정 대상 (§3.가.4). 사전 가드레일 검수 필수
- **대기 화면 영상**
	- 덜미 준비 과정 (덜미막 조립 → 인형 정리 → 덜미 고사)
	- 다른 유저 결과물 큐레이션 (공개 동의된 결과물 중 선별)

# 4. 기술 구성

본 콘텐츠 구현에 필요한 시스템을 6개 영역으로 정리. **다른 시스템에 미치는 영향(종속도) 내림차순 배치.** 콘텐츠 자산(박첨지 디자인/플롯 템플릿/대기 영상)은 §3.마로 분리. 로드맵 마일스톤 연계 항목은 [[로드맵 1단계 1년차]]에 별도 명시.

## 가. AI 시스템

- **박첨지 페르소나 LLM (사전 생성)** — §3.라 박첨지 페르소나를 LLM으로 구현. **사전에** 유형별 마당 플롯의 거리별 질문을 생성 ([[로드맵 1단계 1년차]] 3.4 생성형 전통 서사 AI 활용). **질문 생성 4단계**:
	1. **사건 선택**: [[마당 사건 풀]] 시드에서 현 거리의 사건 컨텍스트 선택 (전개/절정은 해당 유형 풀에서). 풀 안에서 다양하게 분포하도록, 중복 회피
	2. **표현 생성**: 선택된 사건 + 박첨지 재담 화법(§3.라) prompt + temperature 0.7~0.9로 질문 텍스트 생성
	3. **AI 가드레일 사후 검사** (§3.다): 출력 질문이 가드레일 정책 통과하는지 검사
	4. **재생성/확정**: 위반 시 표현 생성 재시도(N회 한도). 통과한 질문을 플롯에 **고정**해 풀에 저장
- **마당 플롯 진행기 (런타임)** — 유저의 유형 선택 → 그 유형 풀에서 랜덤 마당 배정 → 거리 순차 제시 (§3.가.4). 런타임 질문 생성 없음(사전 고정)
- **AI 가드레일** — §3.다 가드레일 정책의 적용 모듈 ([[덜미 - 전자책 변환 결정사항]] §5 개발 전 결정사항 2)
- **유저 입력 가공 LLM** — 문답 응답을 거리별 서사 텍스트로 변환
- **이미지 생성 모델** — §3.라 시각 정체성, §3.마 콘텐츠 자산을 기반으로 인형극 양식 이미지 생성 ([[덜미 - 전자책 변환 결정사항]] §5 개발 전 결정사항 1)
- **결과물 조립** — 서사와 일러스트를 그림동화 페이지 단위로 결합
