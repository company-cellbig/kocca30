> 박첨지놀이를 소재로 한 AI 그림동화 공동창작 시범콘텐츠의 개발 기획서. [[덜미 - 전자책 변환 결정사항]]을 입력으로 작성함. 골격 단계 — 점차 채워나감.

# 1. 개요

- 콘텐츠 정의, 목표, [[로드맵 1단계 1년차]] §8 연계
- 작성 예정

# 2. 시스템 플로우

- 매체: 9:16 세로형 키오스크 터치. 플레이타임 5분
- 큰 흐름(스케치): 인트로(동의 약관) → 거리별 입력 → AI 생성 → 그림동화 결과

> 단계별 진행, 담당 시스템, 프로세스, 입출력을 표기. 사용자 측 기본 흐름(시작/진행/마무리)을 시스템 관점으로 확장. §4 기술 구성의 각 모듈이 단계별로 어떻게 협력하는지 보임.

**표기**: `S` = Step(순차 단계). S1~S7은 재생 순서대로의 단계 ID (§3.가의 `T` = Type와 구분 — T는 카탈로그 ID, 순서 아님)

**개요**: S1 인트로 → S2 캐릭터 정보 입력 → S3 플롯 문답 (반복) → S4 결과물 생성 + 대기 화면 (병행) → S5 결과물 표시 → S6 결과물 전송 → S7 종료/리셋

## 가. 세션

**세션 정의**: 한 유저의 키오스크 사용 전체(S1 시작 → S7 종료)를 감싸는 상위 컨테이너. 하위 Step들이 세션 안에서 순차 실행됨.

**세션 라이프사이클**: 생성 + 5분 타이머 시작(S1, 신규) → 상태 저장 반복(S2~S6, 진행 중) → 종료 + 리셋(S7, 종료)

**관리 모듈**: §4.다 백엔드

**세션 안 저장 데이터**:

- 세션 ID, 고객 동의 약관 동의 기록 (버전, 타임스탬프)
- **콘텐츠 입력** (개인정보 아님 — 그림동화 콘텐츠 생성용):
	- 캐릭터 정보 (성별, 연령대, 이름) — 주인공 설정
	- 거리별 응답 누적, 박첨지 진행 대화 로그
	- 그림동화 결과물 파일 (다중 페이지)
- **개인정보**:
	- 전화번호 (S6 전송 동의 시 임시 저장 → SMS 발송 후 즉시 파기, 거부 시 즉시 파기)

**Step별 세션 동작**:

- S1 세션 생성 + 5분 타이머 시작
- S2~S6 세션 데이터 갱신
- S7 세션 종료 + 임시 데이터 파기 + 리셋

## 나. Step

Step은 시스템 플로우의 순차 단위. 본 절에서 Step 정의 및 공용 기능과 Step별 명세를 다룸.

### 1) Step 정의 및 공용 기능

**Step 정의**: 시스템 플로우의 순차 단위. 사용자 측 기본 흐름(시작/진행/마무리)을 시스템 관점으로 분해함. S1~S7 각 Step은 아래 명세 형식으로 정의되며, 공용 기능을 조합해 프로세스를 구성함.

**Step 명세 항목**

- **트리거**: Step 진입 조건 (사용자 액션 또는 직전 Step 완료)
- **시스템**: 관여하는 §4 기술 구성 모듈
- **프로세스**: Step 안에서 실행되는 sub-step 순서 (공용 기능 호출 + 자체 로직)
- **입력**: Step이 받는 데이터/이벤트
- **출력**: Step이 산출하는 데이터/상태
- **다음**: 다음 Step 또는 종료 조건
- **분기**: 조건부 흐름 (예: 미동의 시 S7 직행)
- **에러 분기**: 실패 시 fallback 경로 (필요 시)

**공용 기능**: 모든 Step이 호출하는 횡단 기능. 제공 모듈은 §4 기술 구성, 정책은 §3 콘텐츠 설계와 연동. 각 Step의 프로세스 항목은 본 목록의 기능을 조합해 작성됨.

| 기능 | 세부 | 제공 모듈 | 사용 Step | 비고 |
|---|---|---|---|---|
| 단계별 타임아웃 | 무응답 임계 시 S7 직행 | §4.다 백엔드 + §4.마 UI | S1~S6 전체 | 임계(예: 30초)는 §6 일정에서 확정 |
| 입력 유효성 검증 | 폼/응답/연락처 형식, 길이, 필수 | §4.마 UI | S2 캐릭터 정보 / S3 응답 / S6 전화번호 | — |
| AI 가드레일 | 입출력 안전성 검사 | §4.가 AI 시스템 | S3 질문/응답 / S4 서사/일러스트 | 정책 정본 §3.다 |
| 개인정보 처리/파기 | 임시 저장, 즉시 파기 정책 | §4.다 백엔드 | S6 전화번호 임시 저장 / S7 파기 | 개인정보는 전화번호 단일. 캐릭터 정보/응답은 콘텐츠 데이터 |
| 에러/fallback | 사용자 사과 안내 후 S7 | §4.바 운영/모니터링 | 전 Step (특히 S3/S4/S6) | AI 호출 실패, 외부 서비스 실패 모두 적용 |
| 외부 서비스 호출 래퍼 | 재시도, 타임아웃 표준화 | §4.라 외부 서비스 | S3/S4 AI 호출 / S4 호스팅 / S6 SMS | — |
| 사용 로그/모니터링 | Step 진입/완료/오류 이벤트 | §4.바 운영/모니터링 | 전 Step | 완주율, 오류율 산출 입력 |
| 박첨지 캐릭터 렌더링 | 단계 전반 일관성 | §4.마 UI | S1~S5 전체 | 정체성 정본 §3.라 |

공용 기능은 각 Step의 프로세스 항목에서 직접 호출되거나, 백그라운드에서 자동 적용됨(예: 타임아웃, 로그). 분기/에러 처리 흐름은 본 목록의 "에러/fallback" 항목으로 일원화 — 개별 Step 프로세스에서는 호출만 명시함.

### 2) Step별 명세

#### 가) S1. 인트로 (시작 + 동의)

- **트리거**: 유저가 시작 버튼 터치
- **시스템**: 클라이언트 UI (§4.마), 백엔드 (§4.다)
- **프로세스**
	1. 백엔드: 신규 세션 생성, 5분 타이머 시작
	2. UI: 인사말 화면 표시 + "터치하세요" 안내
	3. UI: 터치 캡처 → 진행 가이드 화면
	4. UI: 터치 캡처 → 고객 동의 약관(주의사항) 화면
	5. UI: 동의 버튼 터치 캡처
	6. 백엔드: 동의 기록 저장 (세션 ID, 약관 버전, 타임스탬프)
- **입력**: 터치 이벤트, 동의 결정
- **출력**: 세션 ID, 동의 기록
- **분기**: 미동의 시 S7 종료로 직행
- **다음**: S2

#### 나) S2. 캐릭터 정보 입력

- **트리거**: S1 동의 완료
- **시스템**: 클라이언트 UI (§4.마), 백엔드 (§4.다)
- **프로세스**
	1. UI: 캐릭터의 성별, 연령대, 이름 입력 폼 (그림동화 주인공 설정. 캐릭터 성별/연령대는 플롯 영향 검증 후 유지 결정 — §3.나 변주 슬롯 설계와 연동)
	2. UI: 입력 유효성 검증
	3. 백엔드: 세션에 캐릭터 정보 저장
- **입력**: 캐릭터의 성별, 연령대, 이름
- **출력**: 세션 캐릭터 정보 갱신
- **다음**: S3

#### 다) S3. 플롯 문답 (거리별 반복)

- **트리거**: 캐릭터 정보 입력 완료
- **시스템**: AI 시스템 (§4.가), 클라이언트 UI (§4.마), 백엔드 (§4.다)
- **프로세스**: 거리별로 반복 (§3.가 5분 조립 규칙 — 만남 → 본편 2개 → 마무리)
	1. AI 거리 문법 플롯 생성기: 다음 거리-type 선택
	2. AI 박첨지 페르소나 LLM: 거리별 질문 생성 (재담 화법, §3.라)
	3. AI 가드레일: 질문 검사 (§3.다)
	4. UI: 박첨지 캐릭터와 질문 표시, 유저 응답 입력 받기
	5. AI 가드레일: 응답 검사
	6. 백엔드: 응답을 세션에 누적 저장
- **입력**: 거리 시퀀스, 유저 응답(텍스트)
- **출력**: 거리별 응답 누적, 박첨지 진행 대화 로그
- **다음**: 모든 거리 완료 시 S4

#### 라) S4. 결과물 생성 + 대기 화면 (병행)

- **트리거**: 플롯 문답 완료
- **시스템**: AI 시스템 (§4.가), 클라이언트 UI (§4.마), 백엔드 (§4.다), 외부 서비스 (§4.라)
- **프로세스** (백그라운드와 포그라운드 동시)
	- **백그라운드 — 결과물 생성**
		1. AI 유저 입력 가공 LLM: 응답을 거리별 서사 텍스트로 변환
		2. AI 이미지 생성 모델: 거리별 일러스트 생성 (§3.라 시각 정체성, §3.마 자산)
		3. AI 결과물 조립: 서사와 일러스트를 그림동화 페이지로 결합
		4. 백엔드: 결과물 저장소에 그림동화 파일 저장
	- **포그라운드 — 대기 화면**
		1. UI: 대기 콘텐츠 노출 — 덜미 준비 과정 영상 또는 큐레이션된 다른 유저 결과물 (§3.마)
		2. 백엔드: AI 처리 진행 상태 폴링/푸시
- **입력**: 세션 응답 전체, 캐릭터 이름
- **출력**: 그림동화 파일 (다중 페이지)
- **에러 분기**: AI 호출 실패 시 fallback (§4.바 운영/모니터링) — 재시도 N회(예: 2회)까지 시도. 실패 시 사과 안내 후 S7. 구체 N은 §6 일정에서 확정
- **다음**: 생성 완료 시 S5

#### 마) S5. 결과물 표시

- **트리거**: 그림동화 파일 생성 완료
- **시스템**: 클라이언트 UI (§4.마), 백엔드 (§4.다)
- **프로세스**
	1. UI: 결과물 첫 페이지 표시
	2. UI: 페이지 넘김 인터랙션 (터치)
	3. UI: 마지막 페이지 도달 시 "전송" 버튼 노출 (자동 전환 옵션도 UI 디자인 단계에서 검토)
- **입력**: 그림동화 파일
- **출력**: 유저가 결과물 확인
- **다음**: 유저가 "전송" 버튼 진행 → S6 (전송 안내 화면은 S6 시작 단계에서 표시)

#### 바) S6. 결과물 전송

- **트리거**: 유저가 전송 안내 화면에서 진행
- **시스템**: 클라이언트 UI (§4.마), 백엔드 (§4.다), 외부 서비스 (§4.라)
- **프로세스**
	1. UI: 전화번호 입력 폼, 전송 동의 안내
	2. 백엔드: 전화번호 임시 저장 (개인정보 처리 정책 — 전송 동의 시 SMS 발송 후 즉시 파기, 거부 시 즉시 파기)
	3. 외부 서비스 SMS: 결과물 호스팅 URL 또는 이미지 전송
- **입력**: 전화번호, 전송 동의
- **출력**: SMS 발송 결과
- **분기**: 거부 시 SMS 단계 생략, S7로
- **다음**: S7

#### 사) S7. 종료 / 리셋

- **트리거**: 결과물 전송 완료 또는 미동의 또는 타임아웃 또는 유저 이탈
- **시스템**: 클라이언트 UI (§4.마), 백엔드 (§4.다)
- **프로세스**
	1. UI: 마무리 인사 화면 (선택)
	2. 백엔드: 세션 종료, 임시 데이터 파기 (개인정보 처리 정책 — 전화번호 잔류 시 즉시 파기. 콘텐츠 데이터는 결과물 호스팅 후 정책 기간 보관)
	3. UI: 시작 화면 복귀 (다음 유저 대기)
- **입력**: 종료 트리거
- **출력**: 키오스크 idle 상태
- **다음**: 다음 유저용 S1 대기

# 3. 콘텐츠 설계

본 콘텐츠의 정체성(박첨지 페르소나, 거리-type 풀, 변주 슬롯, 가드레일 정책, 자산)을 정의. §4 기술 구성은 본 절에서 정의된 것의 구현/배치를 다룸.

## 가. 플롯 구조

박첨지놀이 7거리를 추상화한 **거리-type 풀(6종)**과 5분 분량 조립 규칙으로 비고정 출력을 구현. 거리-type의 원형은 [[박첨지놀이]] 참조.

> **T1~T6은 풀 카탈로그 ID이며 재생 순서가 아님.** 실제 재생은 아래 §5분 조립 규칙에 따라 4거리(T1 + 본편 2개 + T6)로 구성됨.

### 1) 거리-type 풀

| T | 거리-type | 원본 거리 | 고정 문법 | 풍자 초점 | 박첨지 / 홍동지 역할 |
|---|---|---|---|---|---|
| T1 | 만남 거리 | 박첨지유람거리 | 박첨지가 떠돌이 노인으로 등장. 새 인물(유저)을 일행에 들임. 첫 재담 | 도입 | 박첨지: 주역, 환영자 |
| T2 | 위선 폭로 거리 | 피조리거리 | 겉/속 다른 자가 망신/응징당함 | 위선 (가족/이웃 수준) | 박첨지: 목격, 한탄. 홍동지: 응징 가능 |
| T3 | 욕심/다툼 거리 | 꼭두각시거리 | 욕심으로 다툼이 일어나 누군가 떠나거나 손해 | 욕심 (내부 갈등) | 박첨지: 당사자 또는 해설 |
| T4 | 위협/구원 거리 | 이시미거리 | 외부 위협이 닥치고 홍동지가 처치 (응징 카타르시스) | 위협의 정체 | 박첨지: 피해자. 홍동지: 핵심, 힘으로 처치 |
| T5 | 권력 풍자 거리 | 매사냥거리 + 상여거리 | 권력자가 허세 부리다 우스꽝스럽게 추락 (골계적 반전) | 권력/허세 (위계 수준) | 박첨지: 굽실/풍자. 홍동지: 직접 조롱 |
| T6 | 허무 마무리 거리 | 절 짓고 허는 거리 | 무언가 지어졌다 곧 허물어짐. 박첨지의 닫는 해설 | 무상함 | 박첨지: 마지막 해설자 |

각 type의 고정 문법은 [[덜미 - 전자책 변환 결정사항]] §3 전통의 재창조 §가. 가져갈 것을 적용. 사건 내용, 풍자 대상은 §3.나 변주 슬롯을 통해 유저 입력으로 매번 생성됨.

### 2) type별 변주 슬롯 (요약)

| T | 유저 입력으로 채워지는 부분 |
|---|---|
| T1 만남 | 유저의 정체, 합류 계기 (이름, 응답) |
| T2 위선 폭로 | 위선자 정체, 망신 방식 |
| T3 욕심/다툼 | 다툼의 소재 (재산/명예/기회 등), 떠나는 자 |
| T4 위협/구원 | 위협의 형태, 유저 행동 (도망/맞섬/꾀) |
| T5 권력 풍자 | 권력자의 정체, 몰락 방식 |
| T6 허무 마무리 | 허물어지는 것 (앞 거리 누적 반영), 마무리 톤 |

**사건 풀 정본**: 각 type의 사건 컨텍스트 풀은 별도 자산 문서 [[거리-type 사건 풀]] 참조 (§3.마 콘텐츠 자산 등록).

### 3) 5분 조립 규칙

- **고정 시작**: T1 만남 거리 (~1분)
- **본편 2개**: T2/T3/T4/T5 중 유저 입력 기반 선택 (각 ~1~1.5분)
- **고정 닫기**: T6 허무 마무리 거리 (~0.5분)
- 잔여 약 1분: 표지/엔딩 페이지, 거리 간 전환

**조합 권장**

- T4 위협/구원을 본편 한 자리에 우선 포함 권장 — 응징 카타르시스가 덜미 정체성의 핵심
- 본편 조합 수: T4 포함 3가지 [T4+T2, T4+T3, T4+T5] + T4 미포함 3가지 [T2+T3, T2+T5, T3+T5] = **총 6가지 본편 조합**
- 각 type 내부는 유저 입력 기반 무한 변주

### 4) type별 가드레일 참고

- T2 위선 폭로: 특정 실명/단체 풍자 차단. 윤리적 위선(남을 속이는 행위 등)으로 추상화
- T3 욕심/다툼: **처첩 삼각관계 default 금지** ([[덜미 - 전자책 변환 결정사항]] §3 전통의 재창조 §나. 버릴 것). 재산/명예/기회 등으로 추상화
- T4 위협/구원: 위협이 특정 사람/집단 비방으로 흐르지 않게
- T5 권력 풍자: 실제 정치인/공공인물 풍자 차단. 추상화된 권위만

세부 가드레일 정책은 §3.다 참조.

### 5) 풀 검증 (설계 원칙 매핑)

| 원칙 (출처) | 적용 위치 |
|---|---|
| 박첨지 = 해설자 겸 주역 ([[덜미 - 전자책 변환 결정사항]] §3.가 가져갈 것 1) | T1~T6 모두 |
| 재담과 메타연극성 (§3.가 가져갈 것 2) | 모든 type 박첨지 진행 |
| 풍자 정신 (§3.가 가져갈 것 3) | T2/T3/T5 풍자 초점 다중 분포 |
| 홍동지 응징 카타르시스 (§3.가 가져갈 것 4) | T2/T4/T5 |
| 에피소드(거리)식 구성 (§3.가 가져갈 것 5) | 풀 자체 |
| 골계적 반전 (§3.가 가져갈 것 6) | T5 핵심 문법 |
| 인형극 시각 양식 (§3.가 가져갈 것 7) | §3.마 자산 적용 |
| 고정 줄거리 버림 (§3.나 버릴 것 1) | type만 고정, 사건은 유저 입력 변주 |
| 시대적으로 낡은 내용 버림 (§3.나 버릴 것 2) | T3 가드레일 (처첩 default 금지) |
| 연행 규모 버림 (§3.나 버릴 것 3) | 4 거리 / 5분 조립 |

박첨지놀이 7거리 매핑: T5가 매사냥거리+상여거리 통합, 나머지 1:1 매핑. 누락 없음.

## 나. 변주 슬롯

- 유저 입력(이름, 거리별 응답)을 이야기 동력으로 전환하는 설계. type별 슬롯 명세는 §3.가 type별 변주 슬롯 표 참조
- 결정사항 §3 전통의 재창조 §다 "유저 세계 → 풍자 대상/갈등 소재 생성" 원리 적용 ([[덜미 - 전자책 변환 결정사항]] §3.다 바꿔서 가져갈 것)
- **AI 질문 변주 정책 (의도/사건 다양화)**: 같은 type이 두 세션 이상 반복 호출되어도 박첨지 질문이 매번 변주됨. 변주 차원:
	- **사건 형태** — type 안에서 사건 컨텍스트가 변주 (예: T1 만남 — 길에서 / 잔치에서 / 시장에서 등)
	- **풍자 대상** — 추상화된 권위/위선 형태 변주 (예: T5 권력 풍자 — 허세 권위자 / 겉만 번지르 / 횡포한 자 등)
	- **박첨지 입장** — 목격자 / 당사자 / 풍자자 등 역할 변주

  구현은 §4.가 박첨지 페르소나 LLM의 질문 생성 단계에서 다양성 메커니즘 적용 (prompt 변주, type별 사건 풀, temperature 조절 등 — 구체 메커니즘은 §4.가 구현 단계에서 발전). 가드레일 일관성: §3.다 정책(특정 실명/단체 차단 등)은 변주 결과에도 일관 적용
- **변주 vs 일관성 균형**: 변주 = 사건/풍자 대상/박첨지 입장. 일관성 = type의 고정 문법(§3.가 거리-type 풀 표). 예 — T1은 항상 "박첨지 등장 + 일행 들임" 골격 유지, 그 안의 사건만 다양
- 세부 설계(유저 응답 → type 슬롯 매핑의 LLM 프롬프트, 본편 type 선택 알고리즘) 작성 예정

## 다. 가드레일 (정책)

콘텐츠 정체성/안전 정책을 본 절에서 정의. 구현은 §4.가 AI 시스템의 가드레일 모듈에서.

- AI 가드레일 + 인트로 동의 약관 절차 ([[덜미 - 전자책 변환 결정사항]] §5 개발 전 결정사항 2)
- 검증위원회 자문 ([[ref_제안요청서]] §2 나)
- 세부 정책(전통 왜곡 판정 기준, 부적절 콘텐츠 분류, 동의 약관 항목 구체화 등) 작성 예정

## 라. 박첨지 페르소나

본 콘텐츠의 정체성 중심. 모든 플롯 진행을 박첨지가 해설/주역으로 엮음.

- **역할**: 떠돌이 노인 해설자 겸 주역, 거리를 잇는 목소리. 유저는 박첨지 곁에 편입되는 조연 ([[덜미 - 전자책 변환 결정사항]] §3.가 가져갈 것 1)
- **화법**: 산받이/관객과 주고받는 재담 양식 ([[덜미의 각본 재미 요소]] 참조)
- **시각 정체성**: 나무 인형극 박첨지 캐릭터의 도구/의상 고유특징 유지 ([[덜미 - 전자책 변환 결정사항]] §5 개발 전 결정사항 1)
- 세부 페르소나(말투, 어휘, 반응 패턴 등) 작성 예정

## 마. 콘텐츠 자산

콘텐츠가 사용하는 시각/서사 자산. 구체 산출 방식, 호스팅 등은 §4 기술 구성에서.

- **박첨지 캐릭터 디자인** — 인형 시각 정체성 적용 (§3.라)
- **거리별 플롯 템플릿** — 거리-type 풀(§3.가)의 각 type별 골격
- **[[거리-type 사건 풀]]** — type별 사건 컨텍스트 풀 (T1~T6 각 5~10개 시드). §3.나 AI 질문 변주 정책에서 박첨지 LLM이 선택. 운영 중 추가/제거
- **대기 화면 영상**
	- 덜미 준비 과정 (덜미막 조립 → 인형 정리 → 덜미 고사)
	- 다른 유저 결과물 큐레이션 (공개 동의된 결과물 중 선별)

# 4. 기술 구성

본 콘텐츠 구현에 필요한 시스템을 6개 영역으로 정리. **다른 시스템에 미치는 영향(종속도) 내림차순 배치.** 콘텐츠 자산(박첨지 디자인/플롯 템플릿/대기 영상)은 §3.마로 분리. 로드맵 마일스톤 연계 항목은 [[로드맵 1단계 1년차]]에 별도 명시.

## 가. AI 시스템

- **박첨지 페르소나 LLM** — §3.라 박첨지 페르소나를 LLM으로 구현. 거리별 플롯 진행 + 재담 화법 ([[로드맵 1단계 1년차]] 3.4 생성형 전통 서사 AI 활용). **§3.나 AI 질문 변주 정책의 D 하이브리드 구현 — 4단계 메커니즘**:
	1. **사건 선택**: [[거리-type 사건 풀]]에서 현 거리 type의 사건 컨텍스트 후보 중 1개 선택. 유저 직전 응답 + 세션 누적 컨텍스트 고려, 직전 거리와 중복 회피
	2. **표현 생성**: 선택된 사건 컨텍스트 + 박첨지 재담 화법(§3.라) prompt + temperature 0.7~0.9로 질문 텍스트 생성
	3. **AI 가드레일 사후 검사** (§3.다): 출력 질문이 가드레일 정책 통과하는지 검사
	4. **재생성**: 가드레일 위반 시 표현 생성 단계로 재시도 (N회 한도, 한도 초과 시 사건 선택 단계로)
- **거리 문법 플롯 생성기** — §3.가 거리-type 풀과 5분 조립 규칙의 구현
- **AI 가드레일** — §3.다 가드레일 정책의 적용 모듈 ([[덜미 - 전자책 변환 결정사항]] §5 개발 전 결정사항 2)
- **유저 입력 가공 LLM** — 문답 응답을 거리별 서사 텍스트로 변환
- **이미지 생성 모델** — §3.라 시각 정체성, §3.마 콘텐츠 자산을 기반으로 인형극 양식 이미지 생성 ([[덜미 - 전자책 변환 결정사항]] §5 개발 전 결정사항 1)
- **결과물 조립** — 서사와 일러스트를 그림동화 페이지 단위로 결합
