> 덧뵈기(탈춤)를 소재로 한 AR 탈춤 체험 시범콘텐츠 개발 문서. 사용자가 디자인한 탈을 3D로 변환해 AR로 쓰고, 풍물 장단에 맞춰 춤사위를 따라 추며(포즈 채점), 탈 캐릭터와 기념 촬영하는 콘텐츠. [[콘텐츠 기획서 작성 양식]] 적용. 골격 단계로 점차 채움.

# 1. 개요

사용자가 직접 디자인한 탈을 3D로 변환해 AR로 쓰고, 풍물 장단에 맞춰 탈춤 춤사위를 따라 추며, 탈 캐릭터와 기념 촬영하는 체험 콘텐츠.

- **소재**: 남사당놀이 탈놀음 덧뵈기 ([[덧뵈기]])
- **유형**: 체험. 실시간 동작 놀이가 핵심이고, 탈 만들기는 도입 단계임 ([[콘셉트 정리#3. 전체 구조 정리]])
- **핵심 메커닉**: 사용자가 만든 탈을 쓰고 직접 몸으로 춤을 따라 추는 능동 체험. 자세 일치도와 타이밍을 실시간 채점해 신명(興) 게이지로 보상
- **성격**
	- 1회성 체험이 아니라 반복 사용으로 탈춤을 익히는 학습 도구
	- 디지털 도제(Digital Apprentice)식 전승과 교육 지향 ([[rfp_제안요청서#3. 활용방안 예시]])
	- 돌아오는 학습자의 진척을 옵트인으로 누적 (모델은 [[플랫폼 사양#2. 사용자 정의와 단계]])
- **진행 호스트**: 말뚝이. 탈춤 풍자의 화자가 전 Step 진행을 안내하고 추임새로 호응 (§3.바)
- **플랫폼과 세션**: 키오스크 (9:16 세로형 터치 + 카메라 + 마이크, 1인 사용. [[콘셉트 정리#가. 키오스크]]). 목표 플레이타임은 확인 필요(콘셉트와 로드맵 원문 미명시, 임의 추정 금지)
- **산출물**: 기념 사진(2D 탈 캐릭터와 동반 포즈)과 숏폼 리플레이 영상(춤사위 하이라이트와 기념 포즈에 신명 게이지 점수와 등급 스탬프, 음원). 상세는 §5
- **문서 범위**: 콘텐츠 로직(전체 플로우, 구성 요소, 동작과 규칙, 기술 요건, 자산, 가드레일). 화면의 시각과 레이아웃 상세는 [[덧뵈기 - 나만의 탈춤 UI]], 사용자와 연속성은 [[플랫폼 사양]], 1회 세션과 공용 기능 골격은 [[시범콘텐츠 공통 사양]]을 따름
- 목표, 범위 등 나머지 개요 항목은 작성 예정

# 2. 전체 플로우

한 번의 사용(세션) 동안 Step 1에서 7까지 순차 진행하는 런타임 흐름. 상태, 분기, 타임아웃, 병행 처리, 파기 시점을 담음. 화면의 시각 설계는 [[덧뵈기 - 나만의 탈춤 UI]] 참조. Step 골격과 명세 항목은 [[시범콘텐츠 공통 사양#3. Step 모델]] 준용. 흐름이 호출하는 공용 기능(타임아웃, 가드레일, 개인정보 처리, 외부 호출 래퍼, 에러/fallback, 로그)은 아래 표를 따름.

![[시범콘텐츠 공통 사양#^step-common-funcs]]

- **큰 흐름**: Step 1 인트로(동의) → Step 2 탈 디자인 → Step 3 3D 변환과 대기 → Step 4 AR 착용과 춤사위 따라하기(핵심) → Step 5 기념 촬영과 생성 → Step 6 결과물 전송 → Step 7 종료와 리셋

## 가. Step별 흐름

각 Step을 [[시범콘텐츠 공통 사양#3. Step 모델]]의 명세 항목(트리거, 시스템, 프로세스, 입력, 출력, 다음)으로 적음. 프로세스는 sub-step을 `N. 행위자: 동작`으로 번호 나열하고, 분기와 실패는 갈림이나 실패가 일어나는 sub-step 바로 아래 하위 불릿(`- 분기:`, `- 실패:`)에 둠. 분기는 sub-step 단위라 Step 전체 분기 필드를 두지 않음. 상세 동작과 규칙은 §3 구성 요소에 둠.

### 1) Step 1. 인트로 (시작 + 동의)

- **트리거**: 유저가 시작하기 또는 이어하기 터치
- **시스템**: 클라이언트 UI (§4.다 4), 백엔드 (§4.다 2)
- **프로세스**
	1. 백엔드: 신규 세션 생성
	2. UI: 시작 화면에서 처음 시작 또는 이어하기 선택 감지
		- 분기: 이어하기면 sub-step 3, 처음 시작이면 sub-step 5
	3. UI(카메라): 학습 토큰(QR) 판독 (사용자를 담는 카메라 촬영과 구분되는 토큰 판독)
		- 분기: QR 스캔 실패나 무효 토큰이면 처음 시작 흐름(sub-step 5)으로 안내
	4. 백엔드: 진척과 동의 기록 복원 후 Step 2 직행 (가이드와 동의 약관 생략, 흐름은 [[플랫폼 사양#3. 전체 플로우]])
	5. UI: 가이드와 동의 약관 화면 (처음 시작 경로)
		- 처음 시작은 익명 신규로 진행함. 학습 프로필 생성과 토큰 발급은 Step 6
		- 미옵트인은 토큰이 없어 이어하기를 쓰지 못함
	6. UI: 동의 입력 감지 (동의 화면, 화면 타임아웃 미적용)
		- 호출 공용 기능: 터치 미입력 타임아웃
		- 분기: 카메라 촬영 미동의 또는 터치 미입력 타임아웃이면 Step 7 직행
		- 분기: 영상 산출물 동의만 거부하면 Step 4 녹화와 Step 5 영상 생성을 생략하고 사진만 진행
	7. 백엔드: 동의 기록 저장
- **동의 항목**: 필수(카메라 촬영), 선택(AR 영상 녹화와 리플레이 생성과 제공), 선택(학습 프로필 생성과 진척 보관)
- **입력**: 터치 이벤트, (이어하기 시) 학습 토큰(QR), 동의 결정
- **출력**: 세션 ID, 동의 기록, (이어하기 시) 복원된 진척
- **다음**: Step 2 (시작 화면은 Step 7 복귀 화면과 동일한 대기 상태)

### 2) Step 2. 탈 디자인

- **트리거**: Step 1 동의 완료
- **시스템**: 클라이언트 UI (§4.다 4), AI 가드레일 (§3.아), 백엔드 (§4.다 2)
- **프로세스**
	1. UI(탈 디자인 도구): 도안 입력 수집 (도구 사양 §3.나)
		- (병행) UI: 경량 3D 미리보기 실시간 표시
		- 호출 공용 기능: 화면 타임아웃, 터치 미입력 타임아웃 (창작 화면)
		- 분기: 화면 타임아웃(긴 값) 발동 시 현재 도안을 확정 저장하고 sub-step 2로 정상 진행
		- 분기: 터치 미입력 타임아웃 발동 시 유저 이탈로 보고 Step 7 직행
	2. UI: 입력 유효성 검증
		- 호출 공용 기능: 입력 유효성 검증
	3. AI 가드레일: 입력 도안 검사 (§3.아)
		- 호출 공용 기능: AI 가드레일
		- 실패: 부적절 도안 검출 시 차단과 재입력 안내(한도 §2.나), sub-step 1로 재진입. 한도 초과 시 에러/fallback 후 Step 7. 반복 위반 세부 정책(차단 누적 등)은 작성 예정
	4. 백엔드: 세션에 2D 탈 도안 저장
- **입력**: 사용자 드로잉(터치)
- **출력**: 2D 탈 도안
- **다음**: Step 3

### 3) Step 3. 3D 변환 + 대기 화면

- **트리거**: 탈 디자인 완료
- **시스템**: AI 시스템(3D 변환, §3.다), AI 가드레일 (§3.아), 클라이언트 UI (§4.다 4), 백엔드 (§4.다 2)
- **프로세스** (백그라운드와 포그라운드 동시, 폴링으로 동기화)
	- **백그라운드: 3D 변환**
		1. 백엔드: 3D 변환 작업 큐 등록
		2. AI 3D 변환: 2D 도안을 정식 고품질 3D 탈 모델로 변환 (엔진 §3.다)
		3. AI 가드레일: 변환 생성물 검사 (§3.아)
			- 분기: 위반 시 sub-step 2로 재생성(한도 §2.나). 한도 초과 시 상태 failed
		4. 백엔드: 통과한 3D 탈 모델 저장
		- 실패: 변환 실패 시 재시도(한도 §2.나) 후 failed, 에러/fallback 공용 기능
	- **포그라운드: 변환 대기 화면**
		1. UI: 변환 대기 화면 표시 (대기 화면, 두 타임아웃 미적용)
		2. UI: 백엔드 상태 폴링 (주기 §2.나)
			- 분기: 변환 중이면 대기 유지, 완료면 Step 4 전환, failed면 에러/fallback 후 Step 7
			- 분기: 폴링 무응답이 임계(§2.나)를 넘으면 failed로 처리해 에러/fallback 후 Step 7 (대기 화면은 두 타임아웃 미적용이라 무한 대기를 막는 별도 탈출)
- **입력**: 2D 탈 도안
- **출력**: 3D 탈 모델
- **다음**: 변환 완료 시 Step 4

### 4) Step 4. AR 착용 + 춤사위 따라하기 (핵심 체험)

- **트리거**: 3D 변환 완료
- **시스템**: AI 시스템(포즈 채점, §3.라), 클라이언트 UI(AR 렌더러, §4.다 4), 백엔드 (§4.다 2)
- **프로세스**
	1. UI(AR): 3D 탈을 AR로 착용 (카메라 얼굴 추적, 탈 오버레이)
	2. UI: 춤사위 가이드 제시와 사용자 동작 캡처
		- (병행) UI: 영상 동의가 있으면 AR 합성 화면을 리플레이 소재로 임시 녹화(Step 5 입력). 미동의 시 생략
		- 호출 공용 기능: 화면 타임아웃, 터치 미입력 타임아웃 (카메라/모션 화면)
		- 분기: 화면 타임아웃 발동 시 체류 상한으로 보고 Step 5로 정상 진행
		- 분기: 터치 미입력 타임아웃(사람이나 포즈 미검출)이면 유저 이탈로 보고 Step 7 직행
	3. AI 포즈 채점: 자세 일치도와 타이밍 채점, 신명 게이지 상승 (§3.라)
		- 실패: 포즈가 안 잡히거나 신뢰도가 낮으면 재시도 안내(한도 §2.나), 지연 시 해당 구간 점수 보류
	4. UI(말뚝이): 채점에 따라 실시간 추임새
	5. UI: 게이지 결과 연출 (달성 시 환호 사운드 보상, 미달 시 말뚝이가 눙치는 마무리)
- **입력**: 카메라 영상 프레임, 풍물 장단 타이밍
- **출력**: 동작 채점 기록, 신명 게이지, (영상 동의 시) 임시 녹화 영상
- **다음**: Step 5

### 5) Step 5. 기념 촬영

- **트리거**: 춤사위 체험 완료
- **시스템**: AI 시스템(생성, §3.마), AI 가드레일 (§3.아), 클라이언트 UI (§4.다 4), 백엔드 (§4.다 2)
- **프로세스**
	1. UI: 2D 탈 캐릭터(사용자 탈을 쓰고 덧뵈기 탈옷을 입은)를 카메라 뷰에 라이브 합성, 사용자가 그 옆에서 포즈
		- 실패: 카메라에 사람이 안 잡히면 다시 서도록 안내
	2. UI: 카운트다운 촬영 (채점 없음, 촬영 횟수 n회까지)
		- 호출 공용 기능: 화면 타임아웃, 터치 미입력 타임아웃 (카메라/모션 화면)
		- 분기: 유효 촬영이 1회 이상인 채로 촬영 횟수 소진이나 촬영 자체 타임아웃, 또는 화면 타임아웃(긴 안전 상한)이면 sub-step 3으로 정상 진행
		- 분기: 유효 촬영 0회로 타임아웃되면(유효 촬영 전 이탈) 사진 생성을 생략하고 에러/fallback 후 Step 7
		- 분기: 터치 미입력 타임아웃(사람이나 포즈 미검출)이면 Step 7 직행
	3. AI 생성: 기념 사진 생성 (촬영본에 2D 탈 캐릭터 고품질 재합성, 프레임 적용, 점수 스탬프 없음). 생성 §3.마
		- (병행) UI: 생성 대기 화면 표시 (폴링으로 동기화)
		- 실패: 생성 폴링 무응답이 임계(§2.나)를 넘으면 에러/fallback 처리
	4. AI 생성: (영상 동의 시) 숏폼 영상 편집과 인코딩
	5. AI 가드레일: 생성물(사진과 영상) 검사, 통과물만 확정 (§3.아)
		- 실패: 가드레일 미통과나 재생성 한도 초과 시 위험 생성물 파기하고 사진만 제공, 전부 실패 시 에러 안내
- **입력**: 카메라 영상, 사용자 2D 탈 디자인, Step 4 신명 게이지 점수, (영상 동의 시) Step 4 임시 녹화
- **출력**: 기념 사진(점수 스탬프 없음), (영상 동의 시) 숏폼 영상
- **다음**: Step 6 (통과 산출물이 있을 때만 진행)

### 6) Step 6. 결과물 전송

- **트리거**: 기념 사진 생성 완료 (리플레이 영상은 영상 동의 시)
- **시스템**: 클라이언트 UI (§4.다 4), 백엔드(개인정보 처리, §4.다 2), 외부 서비스(SMS, §4.다 3)
- **프로세스**
	1. UI: 결과물 미리보기 (감상/열람 화면)
		- 호출 공용 기능: 화면 타임아웃
		- 분기: 화면 타임아웃 발동 시 sub-step 2(URL 발급)로 정상 진행 (URL 발급을 건너뛰지 않게 미리보기 다음 단계로 보냄)
	2. 백엔드: 사진과 영상을 한 결과 페이지에 담고 만료형 서명 URL(48시간) 발급
	3. UI: 연락처와 전송 동의 입력 수집 (필수 입력 화면, 화면 타임아웃 미적용)
		- 호출 공용 기능: 입력 유효성 검증, 터치 미입력 타임아웃
		- 분기: 전송 동의면 sub-step 4
		- 분기: 전송 거부면 SMS 생략, 받은 연락처 있으면 즉시 파기, 미발행으로 Step 7
		- 분기: 터치 미입력 타임아웃(유저 이탈)이면 연락처 즉시 파기, 전송 생략하고 Step 7
	4. 외부 서비스(SMS): 연락처 임시 저장 → 결과 페이지 링크 발송(사진과 영상 통합 1채널) → 발송 직후 연락처 즉시 파기. 실패는 에러/fallback ([[시범콘텐츠 공통 사양#라. 결과물 전송]] 준용)
	5. 백엔드: (옵트인 시) 이번 세션 진척과 자산(탈 디자인)을 [[플랫폼 사양]] 콘텐츠 횡단 프로필에 연결 저장하고 학습 토큰(QR) 발급 또는 갱신
- **입력**: 터치, 연락처, 전송 동의, (옵트인 시) 프로필 연결 동의
- **출력**: 결과 페이지와 서명 URL, (전송 시) SMS 발송, (옵트인 시) 학습 토큰(QR)
- **파기**: 결과 페이지는 48시간 만료 시 파기, SMS 발송 성공분은 세션 종료와 무관하게 유지, 미발행분만 세션 종료 시 파기 (§4.가 전송 수단별 파기표)
- **다음**: Step 7

### 7) Step 7. 종료와 리셋

- **트리거**: 결과물 전송 완료 또는 미동의 또는 터치 미입력 타임아웃(유저 이탈)
- **시스템**: 클라이언트 UI (§4.다 4), 백엔드 (§4.다 2)
- **프로세스**
	1. UI(말뚝이): 마무리 인사
	2. 백엔드: 세션 종료와 임시 데이터 파기(영상 피드, 남은 연락처). 결과 페이지는 SMS 발송분은 48시간 만료까지 유지하고 미발행분만 파기 (§4.가 전송 수단별 파기표)
	3. UI: 시작 화면 복귀
- **입력**: 직전 Step 완료 또는 이탈 신호
- **출력**: 세션 종료, 임시 데이터 파기 완료
- **다음**: 다음 유저용 Step 1 대기

# 3. 구성 요소

콘텐츠를 이루는 요소를 의존 순(앞 요소가 뒤 요소의 입력 기반)으로 둠. 각 요소는 역할, 입력과 출력, 동작과 규칙, 기술 요건, 자산 요구, 가드레일과 실패, 의존을 모두 갖춘 독립 명세임.

## 가. 탈과 춤사위 고증 (공통 레퍼런스)

전통 고증 레퍼런스. 탈 양식과 춤사위의 전통 기준을 정의해, 여러 구성 요소가 디자인 시작점이나 전통 정합성 판정 기준으로 공유함. 공통 입력 기반이라 맨 앞에 둠.

- **탈**: 덧뵈기 배역 탈(말뚝이, 양반, 먹중, 샌님 등) 양식을 디자인 레퍼런스로 활용 (목록과 종수 확인 필요, [[덧뵈기]] 작성 후 보강)
- **춤사위**: 따라 추기 대상 동작과 풍물 장단의 고증 매핑 (작성 예정, 고증 자문 연계). §3.라 채점의 기준 동작
- **시각 정체성**: 탈 양식과 질감의 전통 정합성 유지 (작성 예정)
- **의존**: 선행 의존 없음(기반). 본 레퍼런스를 §3.나 탈 디자인(시작점), §3.라 포즈 채점(기준 동작), §3.아 가드레일(전통 왜곡 판정 기준)이 공유함. §3.다 3D 변환의 전통 정합성은 §3.아 가드레일을 거쳐 본 기준으로 판정함

## 나. 탈 디자인 도구 (Step 2)

- **역할**: 전통 배역 탈에서 출발하는 드로잉형 도구로 사용자 탈 도안을 받음. 전통 정합성과 디자인 속도를 함께 잡음
- **입력과 출력**: 입력은 사용자 드로잉. 출력은 2D 탈 도안(Step 3 3D 변환 입력, 형식 규격 확인 필요)
- **동작과 규칙**
	- 디자인 방식: 배역 탈 템플릿과 프리셋을 시작점으로 제공하고 그 위에 자유롭게 그림
	- 캔버스: 충분히 높은 해상도 드로잉형. 저해상도 도트 그리드는 쓰지 않음 (해상도값 디자인 단계 확정)
	- 색: 오방색 5정색(청, 적, 황, 백, 흑)을 기본 팔레트로, 단청 계열 보조색을 더해 전통 색감 통일. 정확한 색 수와 보조색은 디자인 단계 확정
	- 대칭: 좌우 대칭(미러) 기본 제공, 해제 토글로 비대칭 허용
	- 보조 도구: 도형 그리기와 전통 문양 스탬프로 비숙련자 보조
	- 실시간 3D 프리뷰: 그린 도안을 3D 탈에 입힌 경량 미리보기 실시간 표시(디자인 확인용). 정식 변환은 Step 3
	- 참조 사례: 모여봐요 동물의 숲 마이 디자인 페이스 페인트에서 대칭, 제한 팔레트, 스탬프, 실시간 프리뷰 차용. 저해상도 도트(32x32)는 탈에 안 맞아 드로잉형으로 분기
		- 출처(대칭, 팔레트, 스탬프): ACNH 커스텀 디자인 https://game8.co/games/Animal-Crossing-New-Horizons/archives/292830
		- 출처(실시간 프리뷰): ACNH 페이스 페인트 https://game8.co/games/Animal-Crossing-New-Horizons/archives/285111
- **기술 요건**: 출력 규격(드로잉 결과를 3D 변환 입력으로 잇는 형식)은 작성 예정. UI 컴포넌트 구현 정본은 §4.다 4)
- **자산 요구**: 탈 디자인 템플릿과 프리셋 (§3.사 1)
- **가드레일과 실패**: 입력 도안 가드레일(부적절 이미지 차단, §3.아 가드레일). 부적절 검출 시 재입력
- **의존**: 입력 기반은 §3.가 탈과 춤사위 고증. 출력 2D 도안이 §3.다 3D 변환의 입력

## 다. 탈 3D 변환 (Step 3)

- **역할**: 2D 탈 도안을 AR 착용용 3D 탈 모델로 변환
- **입력과 출력**: 입력은 2D 탈 도안(Step 2 산출, 형식 확인 필요). 출력은 3D 탈 모델(glTF 등 AR 렌더 형식, 확인 필요)
- **동작과 규칙**: Step 2 경량 미리보기와 달리 정식 고품질 변환. 서버 백그라운드 생성, 대기 화면이 상태 조회 동기화
- **기술 요건**: 2D에서 3D 생성 모델. 자체 학습 부담이 커 외부 API와 사전학습 모델 우선 검토(후보 조사 확인 필요). 판정 기준은 변환 성공률, 전통 정합성(가드레일 연계), 변환 시간(대기 조회 주기 연동, 구현 확정). 변환 품질 평가 기준과 평가 데이터는 작성 예정. AI 모듈 명세는 [[시범콘텐츠 공통 사양#가. AI 시스템]] 준용
- **자산 요구**: 배역 탈 양식 레퍼런스(§3.가 고증)
- **가드레일과 실패**: 변환물 출력 가드레일(Step 3). 변환 실패나 가드레일 한도 초과 시 fallback, 재시도 한도는 §2.나. 변환 모델 미확보 시 대안 검토(확인 필요)
- **의존**: 입력은 §3.나 탈 디자인. 출력 3D 탈은 §3.라 AR 채점이 사용

## 라. 포즈 채점과 신명 게이지 (Step 4, 핵심 메커닉)

- **역할**: 카메라 영상에서 자세를 추정해 춤사위 자세 일치도와 타이밍을 실시간 채점하고 신명(興) 게이지로 시각화, 달성 시 보상하는 핵심 루프
- **입력과 출력**: 입력은 카메라 영상 프레임과 풍물 장단 타이밍. 출력은 포즈 키포인트, 자세 일치도, 타이밍 점수, 신명 게이지 값, 동작 채점 기록
- **동작과 규칙**
	- 채점 입력: 자세 일치도(포즈 추정 기반)와 풍물 장단 대비 타이밍 (기념 촬영 Step 5는 채점 안 함)
	- 게이지와 보상: 채점이 쌓이면 게이지 상승. 달성 시 환호 사운드(군중 추임새, 박수) 보상, 미달 시 마무리
	- 종합 점수 출력: 게이지 종합 점수와 등급은 Step 5 숏폼 영상 스탬프로 출력
	- 학습 진척(디지털 도제): 옵트인 학습자는 재방문 시 학습 토큰(QR)으로 과거 진척을 불러와 향상 곡선과 약점 동작 피드백. 1회성은 당회 채점만 (프로필 모델은 [[플랫폼 사양#2. 사용자 정의와 단계]])
	- 임계와 가중치, 난이도 곡선은 §2.나 운영 파라미터. 세부 설계(가중치, 게이지 임계, 미달 처리, 향상 곡선 산출)는 작성 예정
- **기술 요건**: 실시간 포즈 추정은 사전학습 모델과 온디바이스 SDK 우선 검토(후보 확인 필요). 채점 로직은 레퍼런스 동작 대비 자체 규칙. 판정 기준은 포즈 추정 정확도, 채점 임계와 가중치, 실시간 처리 지연(프레임률). 채점 정확도 검증 방법은 작성 예정. 서버와 온디바이스 여부 확인 필요. AI 명세는 [[시범콘텐츠 공통 사양#가. AI 시스템]] 준용
- **자산 요구**: 춤사위 모션 레퍼런스(§3.사 2), 환호와 추임새 사운드(§3.사 4), 풍물 장단 음원(§3.사 3)
- **가드레일과 실패**: 포즈가 안 잡히거나 신뢰도가 낮으면 재시도 안내(한도 §2.나), 지연 시 구간 점수 보류, 터치 미입력 타임아웃(사람이나 포즈 미검출) 시 Step 7
- **의존**: 입력은 §3.가 고증의 춤사위 기준과 §3.다 3D 탈(AR 착용). 출력 게이지 점수와 임시 녹화가 §3.마 생성의 입력

## 마. 기념 사진과 리플레이 영상 생성 (Step 5)

- **역할**: 촬영본에 2D 탈 캐릭터를 재합성한 기념 사진과, 춤사위 하이라이트에 점수 스탬프를 올린 숏폼 리플레이 영상을 만듦
- **입력과 출력**: 입력은 카메라 영상, 사용자 2D 탈 디자인(캐릭터 합성용), Step 4 신명 게이지 점수, (영상 동의 시) Step 4 임시 녹화. 출력은 기념 사진(점수 스탬프 없음)과 숏폼 영상(점수와 등급 스탬프, 영상 동의 시)
- **동작과 규칙**
	- 기념 사진: 라이브 화면은 포즈용 미리보기, 최종 저장본은 촬영본에 2D 탈 캐릭터를 고품질 재합성하고 테두리 프레임 적용. 점수 스탬프는 넣지 않아 깔끔하게
	- 리플레이 영상: Step 4 하이라이트와 기념 포즈를 이어 붙이고 게이지 점수와 등급 스탬프, 풍물 장단 음원 오버레이. 영상 미동의 시 생략
	- 파이프라인 구현 요건은 §4.라
- **기술 요건**: 리플레이 합성과 인코딩은 키오스크 부하 고려해 서버에서 진행. 정량값(해상도, 비트레이트, 길이, 코덱)은 구현 시 확정
- **자산 요구**: 기념 사진 프레임(§3.사 5), 숏폼 영상 템플릿과 워터마크, 스탬프(§3.사 6), 기념 사진용 2D 탈 캐릭터(§3.사 10), 풍물 장단 음원(§3.사 3)
- **가드레일과 실패**: 생성물(사진과 영상) 출력 가드레일. 미통과나 재생성 한도 초과 시 위험물 파기하고 사진만 제공, 전부 실패 시 에러. 촬영 0회 시 사진 생성 생략하고 fallback
- **의존**: 입력은 §3.라 채점 결과와 임시 녹화. 출력은 §5 산출물과 Step 6 전송

## 바. 말뚝이 진행 호스트

- **역할**: 양반을 놀리는 탈춤 풍자의 화자. 관객과 대거리하는 전통 기능을 진행 안내와 추임새로 계승 (덜미 박첨지 해설자에 대응, [[덜미 - 전자책 변환 기획서#가. 박첨지 진행 호스트]]). 전 Step을 잇는 목소리로 탈 디자인부터 춤사위, 기념 촬영까지 안내 (공통 골격은 [[시범콘텐츠 공통 사양#6. 진행 호스트]])
- **동작과 규칙**: 재담과 추임새. 춤사위 채점 피드백을 추임새로 전달(§3.라 연동). 게이지 미달 시 눙치며 마무리
- **기술 요건**: 말뚝이 호스트 렌더러는 공통 UI 컴포넌트임. 구현 정본은 §4.다 4). 렌더 방식과 구현 기술은 작성 예정
- **자산 요구**: 말뚝이 호스트 에셋(비주얼, 음성(TTS), 추임새와 대사, §3.사 7)
- **가드레일과 실패**: 해당 없음(연출 요소)
- **의존**: 전 Step 연출. 채점(§3.라) 결과를 피드백
- **고증 주의**: 말뚝이 배역 해석은 일반 탈춤 문헌 수준의 추정임. [[덧뵈기]] 작성 후 검증(확인 필요). 세부 페르소나(말투, 어휘, 반응 패턴)는 작성 예정

## 사. 콘텐츠 자산

제작과 발주, 견적 입력용 자산 목록. 정량(수량, 규격, 제작 방식)은 확인 필요(골격, 작성 예정). 각 자산이 어느 구성 요소에 쓰이는지 용도에 표기.

1. **탈 디자인 템플릿과 프리셋** (디자인 입력)
	- 제작 방식: 외주 또는 자체(확인 필요)
	- 용도: 사용자 탈 디자인 시작점 (§3.나, Step 2)
2. **춤사위 모션 레퍼런스** (채점 기준)
	- 제작 방식: 모캡 등(확인 필요), 고증 자문
	- 용도: 따라하기 대상과 채점 기준 (§3.라, Step 4와 5)
3. **풍물 장단 음원** (음향)
	- 제작 방식: 무저작권, 자체, AI 생성
	- 용도: 춤사위 타이밍 기준(Step 4), 리플레이 음원
4. **환호와 추임새 사운드** (음향)
	- 제작 방식: 확인 필요
	- 용도: 신명 게이지 달성 보상 (Step 4)
5. **기념 사진 프레임** (출력 양식)
	- 제작 방식: 외주 또는 자체(확인 필요)
	- 용도: 기념 사진 프레임 (Step 5). 점수 스탬프 없음
6. **숏폼 영상 템플릿과 워터마크, 스탬프** (출력 양식)
	- 제작 방식: 외주 또는 자체(확인 필요)
	- 용도: 숏폼 프레임, 브랜딩, 점수와 등급 스탬프 오버레이 (Step 5)
7. **말뚝이 호스트 에셋** (캐릭터와 음성)
	- 제작 방식: 확인 필요(비주얼, TTS, 대사)
	- 용도: 진행 호스트 (§3.바)
8. **키오스크 UI와 화면 그래픽** (UI 디자인)
	- 제작 방식: 외주 또는 자체(확인 필요)
	- 용도: 전 화면(상세는 [[덧뵈기 - 나만의 탈춤 UI]]). 화면 12개(UI 설계 기준, 잠정값)
9. **대기 화면 콘텐츠** (대기 콘텐츠)
	- 제작 방식: 확인 필요
	- 용도: Step 3 변환 대기, Step 5 생성 대기
10. **기념 사진용 2D 탈 캐릭터** (캐릭터)
	- 제작 방식: 확인 필요(2D 캐릭터 몸과 포즈 컷, 사용자 2D 탈을 얼굴 합성, 3D 아님)
	- 용도: 기념 촬영 동반 캐릭터 (§3.마, Step 5). 기본 1종, 포즈 컷 1종, 9:16 합성용(해상도 확인 필요)

## 아. AI 가드레일 (전 Step 입출력, 횡단)

- **역할**: 탈 디자인 입력, 3D 변환물, 기념 사진과 리플레이 영상 출력의 안전성과 전통 정합성 검사
- **입력과 출력**: 입력은 검사 대상(이미지, 3D, 영상). 출력은 통과 또는 차단 판정과 사유
- **동작과 규칙**: 입력(Step 2)과 출력(Step 3, Step 5) 검사. 공용 기능 AI 가드레일 호출, 적용 3지점 준용 ([[시범콘텐츠 공통 사양#나. 가드레일 적용 3지점]])
	- 입력(Step 2): 부적절 도안 차단 후 재입력
	- 출력(Step 3): 변환물 위반 시 재생성, 한도 초과 시 대체 처리
	- 출력(Step 5): 영상 위반 시 사진만 제공, 전부 위반 시 에러
- **기술 요건**: 부적절 콘텐츠 분류와 전통 왜곡 판정. 외부 가드레일 API와 자체 기준 조합 검토(확인 필요). 판정 기준은 차단 정확도(오탐과 미탐), 재생성 한도, 검사 지연(정량 구현 확정)
- **자산 요구**: 부적절 도안과 전통 왜곡 판정 기준 데이터(작성 예정)
- **가드레일과 실패**: 재시도와 재생성 한도는 §2.나
- **의존**: 횡단. §3.나/다/마의 입출력에 적용하며, 전통 왜곡과 정합성 판정 기준은 §3.가 고증을 따름. 세부 정책(부적절 도안 분류, 전통 왜곡 판정, 동의 항목 구체화)은 작성 예정

# 4. 공유 계층과 기술 구성

세션, 개인정보와 연속성, 기술 6영역은 [[시범콘텐츠 공통 사양]]과 [[플랫폼 사양]]을 따르고, 본 콘텐츠 고유분만 적음.

## 가. 세션과 데이터

라이프사이클과 Step별 동작은 [[시범콘텐츠 공통 사양#2. 세션]] 준용. 본 콘텐츠 고유 데이터(탈 디자인, 3D 모델, 채점, 사진, 영상)로 재정의함.

- **라이프사이클**: 생성(Step 1, 미동의나 타임아웃 시 즉시 파기) → 갱신(Step 2~6 산출물 저장) → 종료(Step 7 파기와 리셋)

세션이 담는 데이터를 분류, 값, 보관과 파기로 정리함. 개인정보 민감 데이터(영상, 사진, 연락처)에 최소 보관 원칙을 적용함. 보관 기간 잠정값은 규정 검토 후 확정함(임의 추정 금지).

| 데이터 | 분류 | 값과 구성 | 보관과 파기 |
| --- | --- | --- | --- |
| 세션 ID | 시스템 | 세션 고유 식별자 | 세션 종료 시 파기 |
| 동의 기록 | 시스템 | 약관 버전 + 동의 일시 + 동의 항목(필수: 카메라 촬영, 선택: 영상 녹화, 학습 프로필) | 보관 (기간 확인 필요) |
| 탈 디자인(2D) | 콘텐츠 | 사용자 2D 탈 도안 | 별도 저장소 보관 |
| 3D 탈 모델 | 콘텐츠 | 변환된 3D 자산 | 별도 저장소 보관 |
| 동작 채점 기록 | 콘텐츠 | 자세 일치도와 타이밍 점수, 신명 게이지 | 익명 통계 보관, 식별 원본은 세션 종료 시 파기 |
| 학습 프로필 | 가명 개인정보 | 가명 식별자 subject_id에 연결된 진척, 약점 동작, 향상 곡선, 탈 디자인 | 옵트인 시 [[플랫폼 사양]] 프로필에 콘텐츠 횡단 누적 |
| 기념 사진 | 콘텐츠 | 사용자와 2D 탈 캐릭터 동반 포즈 사진(점수 스탬프 없음) | 결과 페이지 임시 보관, 48시간 만료 시 파기 |
| 리플레이 영상 | 콘텐츠 | AR 춤사위 하이라이트 + 기념 포즈에 점수와 등급 스탬프 합성 숏폼(MP4) | 결과 페이지 임시 보관, 48시간 만료 시 파기 |
| 영상 피드 | 개인정보 | 카메라 원본 스트림(포즈 추정과 촬영 입력) | 메모리 임시, 처리 직후 파기 |
| 리플레이 임시 녹화 | 개인정보 | AR 합성 화면 프레임 버퍼(영상 동의 시, Step 4) | 메모리와 임시 버퍼, Step 5 인코딩 완료나 세션 종료 시 파기 |
| 연락처 | 개인정보 | 유저 연락처(SMS) | 메모리 임시, 전송 후 즉시 파기 |

임시 데이터를 저장 위치로 나눠 정리함. 상태별 파기 시점은 아래 전송 수단별 파기표를 따름.

- **메모리 임시 보관** (영상 피드, 연락처, 리플레이 임시 녹화)
	- 보관: 메모리나 임시 버퍼에만, 디스크 영속화와 로그 기록 금지
	- 파기: 파기 시점은 위 §4.가 표가 정본. 시점이 되면 메모리를 명시적으로 덮어쓰는 방식으로 즉시 파기함 ([[시범콘텐츠 공통 사양#가. 개인정보 처리 정책 (공통 원칙)]] 준용)
- **결과 페이지 임시 보관** (기념 사진, 리플레이 영상)
	- 보관: 전송용 서버 임시 저장소에만 두고 로그 기록 금지
	- 파기: 48시간 만료 시 파기(만료 전 재열람과 재다운로드 자유). 상태별 처리는 아래 파기표
- **별도 저장소 보관**
	- 목적: 탈 디자인은 재방문과 재사용, 품질 분석. 3D 모델은 재변환 비용 회피. 학습 프로필은 학습 연속성(미옵트인 시 미생성)
	- 파기 시점: 셋 다 미정, 규정 검토 후 확정. 학습 프로필과 옵트인 연결 탈 디자인은 [[플랫폼 사양#4. 서버 데이터 모델]] 보호 원칙 적용, 3D 모델과 단독 탈 디자인은 콘텐츠 자산 저장소 정책(작성 예정)

전송 수단별로 결과 페이지와 연락처 파기 시점을 정리함. 발행과 미발행에 따라 결과 페이지 파기가 갈리므로 상태로 구분함.

| 상태 | 결과 페이지(사진과 영상) 파기 | 연락처 파기 |
| --- | --- | --- |
| SMS 발송 성공 | 48시간 만료 시 파기(세션 종료와 무관하게 유지) | 즉시 파기 |
| 전송 거부 | 미발행, 세션 종료 시 파기 | 즉시 파기 |
| SMS 발송 영구 실패 | 미발행, 세션 종료 시 파기 | 즉시 파기 |
| 터치 미입력 타임아웃 | 미발행, 세션 종료 시 파기 | 즉시 파기 |

- **영상 처리 주의**: 카메라로 얼굴과 신체를 촬영(포즈 추정, 기념 사진, 리플레이)하므로 덜미보다 개인정보 민감도가 높음. 세부 처리와 규정 검토는 아래 나. 개인정보와 연속성

## 나. 개인정보와 연속성

데이터별 보관과 파기는 위 가. 세션 데이터 표가 정본임. 본 절은 본 콘텐츠 고유의 개인정보 범위와 동의를 정의하고, 사용자 프로필과 연속성 공통 정책은 [[플랫폼 사양]]을 따름.

- **개인정보 범위**
	- 연락처 (전송용)
	- 얼굴과 신체 영상 (영상 피드, 개인정보)
	- 기념 사진과 리플레이 영상 (분류는 콘텐츠지만 얼굴과 신체가 담긴 결과물이라 개인정보 처리 병행. 덜미와 달리 영상 포함, 민감도 높음)
	- 옵트인 학습 프로필 (가명 개인정보, 모델은 [[플랫폼 사양#2. 사용자 정의와 단계]])
- **동의 범위**
	- 필수: 카메라 촬영 (AR 얼굴 추적, 포즈 추정, 기념 사진 촬영)
	- 선택: AR 합성 영상 녹화와 리플레이 생성, 제공 (없으면 녹화와 영상 생성 생략, 사진만)
	- 선택: 학습 프로필 생성과 진척 보관 (옵트인, 상세 [[플랫폼 사양#4. 서버 데이터 모델]])
- **사용자 프로필과 연속성 (플랫폼 정본 준용)**: 비연결 설계, 학습 프로필 운용, 동의 변경과 철회, 학습 토큰 보안, 전방 호환(계정)은 [[플랫폼 사양]] 정본 ([[플랫폼 사양#4. 서버 데이터 모델]], [[플랫폼 사양#5. 작업 단위별 실행]]). 본 콘텐츠는 준용하며 탈 디자인 등 자산이 콘텐츠 횡단 프로필에 누적
- **세부 정책 (작성 예정)**: 보관 기간 잠정값은 규정 검토 후 확정, 임의 추정 금지

## 다. 기술 구성 (6영역)

[[시범콘텐츠 공통 사양#7. 기술 구성 (6영역 템플릿)]] 준용. AI 시스템 모듈(3D 변환, 포즈 채점, 가드레일)은 §3 구성 요소에서 다루고, 본 절은 나머지 인프라 영역을 적음.

### 1) 하드웨어 (키오스크)

- **디스플레이**: 9:16 세로형 터치 (크기와 해상도 확인 필요)
- **카메라**: 얼굴 추적 AR과 포즈 추정용 (해상도와 프레임률 확인 필요)
- **음향 출력**: 풍물 장단과 환호 사운드 (스피커 사양 확인 필요)
- **마이크**: 음성 입력 사용 시 (미사용이면 생략 가능, 확인 필요)
- **연산 유닛**: 본체 연산. 온디바이스 추론 채택 시 GPU 사양 확인 필요
- **네트워크**: AI 서버 통신, 사진과 영상 전송 (대역폭 확인 필요)

### 2) 백엔드

| 요소 | 역할 | 요건과 참조 |
| --- | --- | --- |
| API (키오스크와 AI 서버) | 요청과 응답 중계, 신뢰 경계 | 규격과 프로토콜, 인증(기기 자격/토큰 또는 mTLS), TLS, 개인정보 로깅 제외 (확인 필요) |

### 3) 외부 서비스 연동

- **결과물 전송 서비스 (사진과 영상 통합)**
	- 채널: SMS 링크 1채널. 사진과 영상을 한 결과 페이지로 묶어 발송. 연락처 거부 시 미전송
	- 결과 페이지: 만료형 서명 URL(48시간). 영상은 페이지 안 스트리밍이나 다운로드, 만료 전 재접근 허용
	- 저장과 파기: 저장 제공자, URL 만료, 파기 트리거(48시간) 명세 필요(세션 표와 정합). 제공자와 스토리지, 연동 방식 확인 필요
- **AI API (외부 모델 사용 시)**: 3D 변환, 포즈 추정, 가드레일 등 외부 모델 호출(§3 구성 요소). 호출 래퍼와 재시도는 공용 기능 준용. 제공자와 요금 확인 필요

### 4) 클라이언트 UI (키오스크 앱)

화면의 시각과 레이아웃 상세는 [[덧뵈기 - 나만의 탈춤 UI]] 정본. 본 절은 공통 컴포넌트와 구현 기술만 적음.

- **공통 UI 컴포넌트**: 여러 화면이 재사용하는 컴포넌트. 말뚝이 호스트 렌더러(역할 §3.바), AR 렌더러(3D 탈 오버레이), 탈 디자인 도구(동작 §3.나), 카메라 프리뷰와 촬영, 신명 게이지
- **입력 수단**: 터치, 카메라(얼굴과 포즈), 마이크(필요 시)
- **세션 종료와 리셋**: 화면 타임아웃과 터치 미입력 타임아웃 처리, 다음 유저용 시작 화면 복귀(Step 7)
- **구현 기술 (미정, 설계 단계 확정)**: 키오스크 앱 프레임워크, 페이지 전환과 터치 인터랙션 방식, 컴포넌트 렌더러 방식. 공통 컴포넌트를 어떤 기술로 구현할지 정하는 자리이나, 구체 기술 선택은 아직 미정

### 5) 운영과 모니터링

- **가동 모니터링**: 키오스크 온라인과 오프라인, 장애 상태
- **사용 로그와 지표**: 유저 수, 완주율, Step별 이탈, 오류율
- **알림**: AI 호출, 외부 서비스, 파기 실패 시 운영 알림(임계 §2.나)

## 라. 리플레이 영상 파이프라인 (구현 요건)

숏폼 리플레이 영상의 소재 확보부터 제공과 파기까지 구현 요건. 클라이언트(녹화), 백엔드(합성과 인코딩), 외부 서비스(호스팅)에 걸침. 정량값(해상도, 비트레이트, 길이, 코덱, 유효기간)은 구현 단계에서 확정함(임의 추정 금지).

### 1) 처리 단계 (순차)

1. **소재 녹화 (Step 4)**: AR 탈 합성 화면을 클라이언트에서 프레임 캡처해 임시 녹화. 사후 재합성 부담을 피해 렌더된 화면을 그대로 확보. 메모리와 임시 버퍼에만, 디스크 영속화 금지
2. **하이라이트 선별**: 동작 채점 기록으로 고득점 구간 자동 선별. 기준과 구간 길이는 §2.나
3. **합성과 편집 (Step 5)**: 선별 하이라이트와 기념 포즈를 이어 붙이고 세로형(9:16) 프레임, 워터마크, 점수와 등급 스탬프 오버레이, 음원 믹싱
4. **인코딩**: 세로형 MP4, SNS 업로드 호환 우선. 키오스크 부하 고려해 서버 측 인코딩 권장
5. **제공과 다운로드**: 인코딩 완료물을 기념 사진과 함께 단일 결과 페이지로 묶어 서버 임시 저장소 보관. 발급과 전송은 §4.다 3) 외부 서비스 연동, 파기 시점은 §4.가가 정본. 48시간 만료 시 파기, 파기 실패 시 운영 알림

### 2) 전 단계 공통

- **가드레일**: 제공 전 최종 영상 출력 가드레일 검사 (§3.아)
- **대기와 실패 처리**: 인코딩 동안 상태 조회로 동기화한 대기 화면. 실패 시 fallback으로 영상 생략하고 사진만 제공
- **음원**: 무저작권, 자체 제작, AI 생성 풍물 장단 음원만 사용 (SNS 공개 공유 전제 라이선스 리스크 제거). 외부 라이선스 음원 확보가 어려우면 AI 생성 음원을 최종 안전장치로

# 5. 산출물

- **기념 사진**: 맨 얼굴의 사용자 본인과, 사용자가 디자인한 탈을 쓰고 덧뵈기 탈옷을 입은 2D 탈 캐릭터가 나란히 포즈한 사진(탈을 쓴 쪽은 캐릭터뿐). 프레임만 적용하고 점수와 등급 스탬프는 없음(SNS 공유용 깔끔한 사진). AR로 탈을 쓴 표현은 Step 4 춤사위와 리플레이 영상에만 해당
- **숏폼 리플레이 영상**: AR 탈 춤사위 하이라이트와 기념 포즈 합본에 신명 게이지 점수와 등급 스탬프 오버레이, 세로형 MP4, 무저작권/자체/AI 생성 음원 포함
- **전송과 파기 정책**: §4.가 세션 데이터 표. 영상 합성과 제공 상세는 §4.라
- **형식과 규격 (구현 확정)**: 해상도, 길이, 코덱 등
