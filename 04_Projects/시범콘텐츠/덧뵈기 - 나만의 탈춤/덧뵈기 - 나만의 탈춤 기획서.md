# 1. 개요

- **콘텐츠 정의**: 덧뵈기를 소재로 한 가면극 배역 체험 키오스크 콘텐츠. 유저가 마당 하나를 골라 그 마당의 배역이 되어, 광대 수업과 장면 수행으로 가면극을 몸으로 익힘
- **소재**: 남사당놀이 가면극 덧뵈기
- **목표 경험**: 유저가 광대 수련생으로 들어와 배역의 몸짓을 배우고(기초 수업), 상대 배역과 장면을 주고받고(장면 실습), 절정 대목을 완수해(절정 무대) 스승에게 배역 인정을 받음
- **핵심 메커닉**: 말은 시스템이, 몸은 유저가 맡음. 스승(장쇠)과 상대 배역의 재담이 동작 큐를 던지고, 유저가 배역 동작으로 응답하면 판정(자세, 진폭, 홀드, 타이밍)이 상대 배역의 리액션 연출과 신명 게이지로 되돌아옴
- **결과 안내**: 체험이 끝나면 결과 화면에서 점수 대신 배역 인정(인정 선언, 수행 요약, 게이지의 서사 번역)을 안내함. 별도 반출 결과물은 두지 않음

# 2. 전체 플로우

1회 완결로 마당 하나에서 배역 하나를 익혀 3장 장면을 마치고 배역 인정을 받는 세션임. Step 1 인트로 → Step 2 마당과 배역 선택 → Step 3 마당 장면 체험(핵심, 3장 구성) → Step 4 배역 인정 → Step 5 종료와 리셋 순서로 진행함.

- **중단 처리**
	- 대상: 진행 중 이탈과 실패가 모두 이 공통 처리로 모임
	- 처리: 배역 인정 화면을 건너뛰고, 세션을 종료해 임시 데이터를 파기한 뒤 시작 화면으로 돌아감. 실패는 상황 안내 팝업을 띄운 뒤 진행하고, 이탈은 팝업 없이 진행함
- **파기**
	- 정상 종료 시 남은 세션 임시 데이터(장면 수행 기록의 식별 원본)를 파기함
	- 영상 피드는 처리 직후 실시간 파기라 종료 시점에는 남지 않음

# 3. 공용 시스템

## 3.1 세션 데이터

### 3.1.1 역할과 목적

한 세션이 만드는 데이터를 담는 시스템. 전 Step이 같은 상태를 공유하게 하고, 데이터 종류별 보관과 파기를 관리하기 쉽게 함.

### 3.1.2 동작과 규칙

| 데이터      | 분류     | 들어가는 값과 구성                             | 보관 기간                        | 비고                            |
| -------- | ------ | -------------------------------------- | ---------------------------- | ----------------------------- |
| 세션 ID    | 시스템    | 세션마다 부여되는 고유 식별자                       | 보관 (잠정, 규정 검토 후 확정)          | Step 1에서 생성. 디버깅과 품질 분석용      |
| 현재 언어    | 시스템    | 세션에 적용 중인 언어(기본 한국어)                   | 보관 (잠정, 규정 검토 후 확정)          | 시작 화면 언어 선택에서 설정. 현지화 기준      |
| 현재 Step  | 시스템    | 현재 진행 중인 Step                          | 보관 (잠정, 규정 검토 후 확정)          | 진행 단계 기록                      |
| 에러 유형    | 시스템    | 에러 발생 시 에러 케이스 유형 기록                   | 보관 (잠정, 규정 검토 후 확정)          | 디버깅과 품질 분석용                   |
| 동의 기록    | 시스템    | 약관 버전, 동의 시각, 동의 항목(필수: 카메라 촬영)        | 보관 (잠정, 규정 검토 후 확정)          | 약관 버전 체계는 운영 단계에서 결정함         |
| 선택 마당과 배역 | 콘텐츠 입력 | 유저가 고른 마당과 배역의 식별자(그 마당의 대본, 클립, 판정 자산을 가리킴) | 보관 (잠정, 규정 검토 후 확정)          | Step 2 산출. 식별자만 저장(자산은 사전 배포) |
| 장면 수행 기록 | 콘텐츠 생성 | 큐별 판정(성공 여부, 자세와 타이밍 값), 장별 완수, 신명 게이지                 | 익명 통계는 보관, 식별 원본은 세션 종료 시 파기 | Step 3 산출                     |
| 영상 피드    | 콘텐츠 입력 | 카메라 원본 스트림(포즈 추정 입력)                   | 메모리 임시, 처리 직후 파기             | 디스크 저장 금지. 얼굴과 신체 포함          |

- **Step별 세션 동작**
	- Step 1: 생성
	- Step 2~Step 4: 갱신
	- Step 5: 종료, 임시 데이터 파기, 리셋
- **서버 전송 시점 (이벤트 기반)**: 세션 데이터 갱신은 클라이언트 로컬 상태에만 반영하고, 서버로는 정기 전체 동기화 없이 이벤트 시점에만 전송함(이어하기 없는 1차연도 기준)
	- 단계 이동: 각 Step 진입과 종료 시 현재 Step을 전송함
	- 동의 기록: 이용 동의 화면에서 동의 확정 시 동의 이벤트를 전송함. 클라이언트는 서버의 저장 확인 응답을 받은 뒤에만 다음 단계로 진행함(동의 기록 유실 방지)
	- 에러와 이탈: 에러 발생 시, 이탈(약관 미동의, 미입력 타임아웃 종료) 시 전송함
	- 마당과 배역 확정: 선택 마당과 배역 식별자는 Step 2 확정 시 서버 세션에 반영함

## 3.2 개인정보 처리

### 3.2.1 역할과 목적

카메라로 찍는 유저 얼굴과 신체 데이터의 처리 규칙을 정의하는 시스템. 쓰임이 끝난 데이터를 즉시 파기해 유출 위험을 줄임.

### 3.2.2 동작과 규칙

#### 1) 구현 제약

- **개인정보 범위**
	- 얼굴과 신체 영상
- **카메라 동의 게이트**
	- 카메라 촬영이 필수 동의이므로 동의가 없으면 세션을 진행하지 않음
- **영상 피드 처리**
	- 메모리에서 임시로 처리한 뒤 즉시 파기하고, 디스크에 저장하거나 로그로 기록하지 않음.

#### 2) 규정 검토 대기

- **동의 고지 문구**
	- 카메라 영상은 동작 판정 처리에만 쓰고 저장하지 않는다는 내용을 개인정보 수집과 이용 안내에 포함함. 정확한 안내 문구와 동의 범위는 규정 검토 후 확정함
- **보관 기간**
	- 잠정값은 규정 검토 후 확정함
- **재방문 연속성**
	- 학습 프로필, 이어하기, 학습 토큰, 콘텐츠 진행 결과 누적은 2차연도 확장 설계로 두며 1차연도는 익명 1회로 운영함

## 3.3 언어 선택 시스템

### 3.3.1 역할과 목적

세션 전체에 적용할 언어를 정하는 관문. 한국어가 아닌 언어를 쓰는 유저도 자기 언어로 가면극을 체험하게 함.

### 3.3.2 입력과 출력

- **입력**: 유저의 언어 선택
- **출력**: 현재 언어(세션 데이터에 저장). 현지화 JSON(localization.json)에서 해당 언어값을 불러옴

### 3.3.3 동작과 규칙

- 유저가 언어를 선택하고 시작하기 버튼을 터치하면 현재 언어로 반영함. 기본값은 한국어임
- **현지화 범위**: UI 카피, 장쇠와 상대 배역의 대사와 TTS 음성, 배역 인정 문구, 안내 팝업을 현재 언어로 제공함. 지원 언어는 한국어와 영어를 우선 적용함
- **재담 현지화 유의**: 말장난과 고어가 섞인 재담은 직역이 아니라 뜻과 웃음 구조를 살린 의역으로 현지화함(문안 작성과 함께 확정, 작성 예정)

## 3.4 장쇠 스승 호스트

### 3.4.1 역할과 목적

덧뵈기 잽이 장쇠(장고 담당)를 광대 스승이자 세션 진행 호스트로 세운 시스템. 장단을 이끄는 잽이의 전통 자리를 이어받아, 수업과 장면의 동작 큐를 한 목소리로 던지며 유저를 수련생에서 배역으로 이끎.

### 3.4.2 동작과 규칙

- **범위**
	- 전 세션 호스트. 진행 안내(수업, 중계, 인정)와 동작 큐 발화를 겸함
- **페르소나**
	- 능청스러운 고참 광대(잠정). 원전에서 장쇠의 캐릭터 서술이 옅어 스승 페르소나는 창작으로 얹되, 말투와 어휘는 재담 문법을 따름(세부 작성 예정, 고증 자문 연계)
- **마당별 자리**
	- 옴탈잡이와 먹중잡이: 판 밖에서 수업과 중계를 맡는 코치(원전에서 잽이가 판 밖에서 극에 개입하는 자리와 합치)
	- 샌님잡이: 판 밖 진행은 유지하되, 유저 배역(말뚝이)의 대사를 대신 발화함(아래 대사 대행)
- **수업과 교정 피드백**
	- 기초 수업에서 동작 큐를 던지고, 미달 큐에는 교정 피드백(코칭 발화)을 되돌려줌
	- 교정 문구는 판정 요소와 1:1로 짬: 진폭 미달이면 "더 크게!", 홀드 미달이면 "끝을 딱 맺어야지!", 타이밍 이탈이면 "장단에 맞춰!"(문안 작성 예정)
- **대사 대행 (유저 배역의 목소리)**
	- 유저는 대사를 발화하지 않음. 장면에서 유저 배역의 대사 차례는 장쇠(또는 배역 전용 보이스, 잠정)가 대신 발화하고 유저는 몸으로 수행함
	- 덜미(남사당 인형극)에서 대잡이(인형 조종자)가 인형의 목소리를 대신 내는 전통 구조와 동형임
- **발화 방식**
	- TTS 음성으로 대사를 재생하고 같은 대사를 화면에 텍스트로 표시함.
	- 대사와 화면 텍스트는 세션의 현재 언어로 제공함(TTS도 현재 언어로 합성)
	- 발화 중 캐릭터 표현(코드 트윈 기반 흔들림과 입놀림)을 재생함
- **캐릭터 표현 (제작 제약 반영)**
	- 상시 표현은 2D 일러스트에 코드 트윈(숨쉬기, 발화 흔들림)을 얹어 구동함. 립싱크는 맞추지 않음
	- 등장, 인정 선언, 환호 등 핵심 순간만 사전 제작 클립(AI 영상 생성, 사전 검수)을 재생함
- **스킵**
	- 발화 중 다음 버튼을 누르면 발화를 중단하고 다음으로 진행함
- **타임아웃**
	- 발화 중에는 터치 미입력 타임아웃을 멈추고, 발화가 끝난 뒤 시간 체크 시작
- **대사 적용**
	- 대사는 런타임 생성 없이 사전 작성함. 진행 안내, 마당별 수업과 장면 큐, 교정 피드백, 인정 재담을 미리 써 두고 상황에 맞춰 재생함(구체 문안은 작성 예정)

### 3.4.3 필요 리소스

- 장쇠 스승 캐릭터(2D 일러스트, 탈춤 양식과 시각 정체성 일치. 코드 트윈용 분할 이미지)
- 핵심 순간 클립(등장, 인정, 환호. AI 영상 사전 생성과 검수)
- 장쇠 TTS 보이스(지원 언어별 확보 필요)
- 진행, 수업 큐, 교정 피드백, 인정 재담 대사(사전 작성)

### 3.4.4 실패와 복구

캐릭터 렌더나 TTS 재생이 실패하면 음성과 캐릭터 표현 없이 대표 이미지와 텍스트 박스로만 진행함. 대사는 표시하고 세션은 계속함.

## 3.5 진행 중 종료

### 3.5.1 역할과 목적

유저에게 진행 중 그만둘 수단을 주는 시스템. 원치 않는 세션을 빨리 끝내 키오스크 회전율을 높임.

### 3.5.2 동작과 규칙

#### 1) 일반 규칙

- **처리**
	- 진행 중인 화면을 멈추고 배역 인정 화면(완주 전용)을 건너뛰어 세션 종료와 파기 후 시작 화면으로 복귀함(비완주 종료)

#### 2) 유저의 종료 선택 시 규칙

- **처리**
	- 그만두기 터치 시 그만두기 확인 팝업 표시
	- 확인 시 종료 처리하고, 취소 시 원래 화면 복귀
	  ![|500](../../../assets/시범콘텐츠/공통/팝업_그만두기.png)

- **적용 화면**
	- Step 1 가이드 화면, 이용 동의 화면
	- Step 2 마당 선택 화면, 배역 확인 화면
	- Step 3 기초 수업, 장면 실습, 절정 무대 화면
- **예외 (미적용)**
	- Step 1 시작 화면
	- Step 4 배역 인정 화면 (완주 마침 화면, 처음으로 버튼과 화면 타임아웃으로 넘김)
- **그만두기와 동시 이벤트 처리 (카메라 화면)**: Step 3에서 그만두기가 판정이나 타임아웃과 겹칠 때의 규칙임
	- 확정된 그만두기는 진행 중인 큐와 판정 루프를 멈추고 세션 종료로 감
	- 확인 팝업이 열린 동안에는 터치 미입력 타임아웃과 사람이나 포즈 미검출 측정을 멈춤(장쇠 발화 중 멈춤과 같은 방식)
	- 종료는 한 번만 처리해 이중 종료를 막음

## 3.6 화면 타임아웃

### 3.6.1 역할과 목적

유저가 한 화면에 오래 머무는 것을 막아, 무인 키오스크가 한 유저에게 묶이지 않게 하는 시스템.

### 3.6.2 동작과 규칙

- **처리**
	- 한 화면에서 60초(잠정) 이상 머물면 그 화면의 정상 진행 경로로 넘어감
	- 화면별 오버라이드: Step 3 세 화면 합산 5분(잠정). 마당 선택, 배역 확인, 배역 인정 화면은 기본값(60초, 잠정) 적용
	- 장쇠 발화 중에는 측정을 멈추고, 발화가 끝나거나 스킵한 뒤 재개함(잠정)
	  ![|500](../../../assets/시범콘텐츠/공통/타임아웃_화면.png)

- **작업 상태**
	- 유저 선택 상태가 있으면 세션에 확정 저장한 뒤 진행함(선택 마당, 기본 마당이 사전 선택돼 있어 항상 값이 있음). 없으면 바로 다음으로 진행함
- **예외**
	- 필수 입력, 가이드, 팝업 화면 미적용

## 3.7 터치 미입력 타임아웃

### 3.7.1 역할과 목적

입력이 끊긴 유저 이탈을 감지해 방치된 세션을 정리하고 키오스크 회전율을 높이는 시스템.

### 3.7.2 동작과 규칙

- **처리**
	- 한 화면에서 45초(잠정) 이상 터치나 동작 입력이 없으면 이탈로 보고 진행 중 종료 처리
	- 카메라와 모션 화면(Step 3 세 화면)은 터치가 없는 화면이라 사람이나 포즈 미검출을 이탈 기준으로 삼음
	- 장쇠 발화 중에는 측정을 멈추고, 발화가 끝나거나 스킵한 뒤부터 측정 시작
	  ![|500](../../../assets/시범콘텐츠/공통/타임아웃_미입력.png)

- **예외**
	- 감상 성격 화면(배역 인정 화면) 미적용

## 3.8 외부 서비스 호출 래퍼

### 3.8.1 역할과 목적

외부 서비스 호출(TTS)을 감싸는 공통 계층. 재시도와 타임아웃 대응을 한 곳에 모아, 호출마다 장애 처리를 따로 짜지 않게 함.

### 3.8.2 동작과 규칙

- **재시도 횟수**
	- 2회(잠정). 백오프는 1차 1초, 2차 3초(잠정)
- **호출 타임아웃**
	- TTS 30초(잠정)
- **한도 초과**
	- 재시도 한도를 넘긴 실패는 실패 처리로 넘김

## 3.9 실패 처리

### 3.9.1 역할과 목적

런타임 실패의 처리 정책. 무인 운영에서 실패가 방치되지 않게 함.

### 3.9.2 동작과 규칙

이 콘텐츠의 실패는 기능 축소와 중단 둘로 갈림. 유저가 입력하는 텍스트나 음성이 없어, 입력만 다시 받아 잇거나 다른 입력 수단으로 바꿔 잇는 갈래는 없음.

#### 1) 기능 축소

- 보조 기능이 빠져도 체험이 남는 갈래임. 그 기능만 빼고 세션을 이어 감
- 포즈 미검출 구간(판정 보류로 처리), 장쇠 발화 실패, 리액션 클립 재생 실패(정지 이미지와 효과음으로 대체)가 여기 속함

#### 2) 중단

- 세션을 시작하거나 핵심 체험을 이어 갈 수 없는 실패 갈래임(세션 생성 실패, 마당 리소스 로드 실패, 절정 무대 음원 재생 시한 초과, 카메라와 인식 계통의 지속 장애)
- 상황 안내 팝업을 띄우고 배역 인정 화면(완주 전용)을 건너뛰어 세션 종료와 파기 후 시작 화면으로 자동 진행함. 별도 실패 화면을 두지 않음
	- 예외: 세션 생성 실패는 정리할 세션 자체가 없어 종료 처리도 거치지 않고 곧장 시작 화면으로 되돌림

#### 3) 운영 알림

- 원인이 외부 서비스나 시스템이면 운영 알림을 보내고, 유저면 보내지 않음

## 3.10 탈과 마당 대목 고증 (공통 레퍼런스)

### 3.10.1 역할과 목적

배역 탈, 마당 대목, 배역 동작의 고증 기준을 정의하는 설계 레퍼런스. 마당 선택 목록, 장면 대본, 동작 판정, 사전 자산 검수가 같은 기준을 참조해 전통 정합성 판정이 서로 어긋나지 않게 함.

### 3.10.2 동작과 규칙

#### 1) 마당과 배역

- **마당 구성**: 덧뵈기 네 마당(마당씻이, 옴탈잡이, 샌님잡이, 먹중잡이) 중 체험 마당은 옴탈잡이, 샌님잡이, 먹중잡이 3종임. 마당씻이는 극이 아니라 판을 여는 의식이라 체험 마당에서 제외함(도입 여부는 보류, 결정 대기)
- **1차연도 유저 배역 (마당당 1종)**: 옴탈잡이는 꺽쇠, 샌님잡이는 말뚝이, 먹중잡이는 취발이. 유저를 그 마당의 능동 배역(잡는 쪽, 놀리는 쪽, 이기는 쪽) 편에 세우는 배정임
- **상대 배역 (시스템 연기)**: 옴탈잡이는 옴탈(옴중), 샌님잡이는 샌님, 먹중잡이는 먹중. 리액션 연출로 구현함

#### 2) 탈

- 덧뵈기 배역 탈을 사전 제작해 제공함. 전체 10종(샌님, 노친네, 취발이, 말뚝이, 먹중, 옴중, 피조리 甲, 피조리 乙, 꺽쇠, 장쇠) 중 1차연도 등장분은 유저 배역 3종(꺽쇠, 말뚝이, 취발이), 상대 배역 3종(옴중, 샌님, 먹중), 호스트 장쇠임
- 탈 도상은 인물 기호로 해설함: 옴중의 점은 옴 자국, 샌님의 째보 입술은 권위를 깎는 풍자 기호(해설 문구는 각색 원칙을 따름, 작성 예정)
- 한국 탈춤 탈 양식을 유지하고 일본 노멘이나 중국 가면과 혼동하지 않음

#### 3) 마당 대목과 동작 세트

- **대목 선정 원칙**: 원전에서 대사가 동작 지시나 몸 실랑이로 되어 있는 대목만 골라 씀. 유저의 대사 차례를 전부 몸 응답으로 바꿀 수 있는 지점임
- **마당별 원전 대목 (전사본 행 기준)**: 옴탈잡이는 꺽쇠와 옴탈의 실랑이, 샌님잡이는 말뚝이 대거리(480~554행)와 절 배우기(556~608행), 먹중잡이는 취발이 대 먹중 대결(666~672행)
- **동작 세트 (마당당 3개, 잠정)**: 1965년 기록영상 판독에서 확인된 사위와 원전 지시문을 조합하되, 근거가 없거나 수행 주체를 바꾼 동작은 각색임을 병기함. 명칭과 구성은 고증 자문으로 확정함
	- 옴탈잡이(꺽쇠): 살피기(상체 기울임. 원전 428행 지시문 근거, 살피는 주체를 옴탈에서 꺽쇠로 뒤집은 각색), 찔러보기(팔 뻗기. 원전/영상 근거 없는 각색), 휘둘러 쫓기(팔 휘두르기. 원전 428행의 쫓는 상황 근거, 쫓는 주체를 옴탈에서 꺽쇠로 바꾼 점과 동작 형태는 각색)
	- 샌님잡이(말뚝이): 채찍 휘두르기(팔 휘두르기. 말채찍 소품은 원전 120행 말뚝이 복색 근거, 휘두르는 동작은 각색), 거드름 흉내(상체 젖히기. 영상 21:42~22:10 거드름 사위 근거, 취발이 사위를 말뚝이의 양반 흉내로 옮긴 각색), 호령 가리키기(팔 뻗기. 영상 23:58 호령 근거, 취발이 동작을 말뚝이로 옮긴 각색)
	- 먹중잡이(취발이): 어깨 메기(소매 얹기. 영상 8:08~8:12, 21:42~22:10 근거), 한발 차올리기(다리 들기. 영상 8:16, 24:06 근거), 소매 뿌리기(팔 휘두르기. 영상 19:56, 24:38~24:42 근거)
- **전승 춤사위 연결**: 덧뵈기 전승 춤사위 3종(나비춤, 닭이똥 사위, 피조리춤)은 절정 무대의 대결 시퀀스와 연출에 반영하되, 배역별 매핑은 고증 자문에서 확정함

#### 4) 각색 원칙 (전 마당, 고증 자문 연계)

- 옴탈잡이: 옴(피부병) 조롱 개그의 톤을 낮춤(간지럼 소동 방향). 탈 도상 해설은 사실 서술로 함
- 샌님잡이: 째보 탈 도상 해설을 신분 풍자의 기호로 맥락화함. 외모 놀리기 재담과 절 말장난 고어는 현대어 풀이를 병행함
- 먹중잡이: 피조리 관련 성적 재담을 제거하고, 대결 명분을 먹중의 행패 응징으로 단순화함. 파계승 풍자임을 분명히 함
- 전 마당 공통: 고어는 현대어 풀이 병행, 욕설과 육담은 순화함

#### 5) 시각 정체성

- 탈 양식과 질감의 전통 정합성 유지
- 사전 제작 자산(캐릭터, 리액션 클립)은 운영 전 고증 검수를 거침

## 4.2 Step 2. 마당과 배역 선택

### 4.2.1 클라이언트: 마당 선택 화면

#### 1) 진행

- 체험 마당 3종(옴탈잡이, 샌님잡이, 먹중잡이)의 카드를 보여줌. 유저가 마당을 고르거나 기본 선택을 그대로 두고 확정하면 배역 확인 화면으로 진행함
	- 분기: 화면 타임아웃(기본 60초, 잠정) → 현재 선택 마당을 확정하고 다음으로 정상 진행
	- 분기: 미입력 타임아웃 → 종료 처리
	- 분기: 그만두기 선택 시 확인 팝업 → 확정 시 종료 처리

#### 2) 마당 선택 목록

##### (1) 역할과 목적

유저가 체험할 마당 하나를 고르는 선택 도구. 마당마다 재미 유형이 달라(잡기, 놀리기, 이기기) 고르는 것 자체가 극 구조 학습의 시작이 되게 함.

##### (2) 동작과 규칙

- **목록 구성**: 마당 카드 3종. 카드마다 마당 이름, 한 줄 소개(무엇을 하는 장면인가), 유저 배역과 상대 배역을 표기함
	- 옴탈잡이: 슬금슬금 나타난 옴탈을 꺽쇠가 되어 잡아 쫓는 마당
	- 샌님잡이: 거드름 피우는 샌님을 말뚝이가 되어 놀려 뒤집는 마당
	- 먹중잡이: 행패 부리는 먹중을 취발이가 되어 춤으로 눌러 이기는 마당
- **기본 선택**: 진입 시 목록 첫 번째 마당(옴탈잡이, 잠정)을 기본 선택으로 둠
- **미리보기**: 선택한 마당의 절정 장면 요약 클립을 무음 루프로 보여줌(리액션 클립 재활용, 잠정)

### 4.2.2 클라이언트: 배역 확인 화면 (배역 입문)

#### 1) 진행

- 선택 마당의 1차연도 배역 1종을 표시하고, 장쇠가 그 배역의 탈 도상을 재담으로 해설함(왜 이런 얼굴인가). 탈 쓰기 버튼 터치 시 탈 쓰기 연출과 함께 배역을 확정하고 다음 단계로 진행함
	- 장쇠의 변신 규약 선언: 탈을 쓰면 유저가 아니라 그 배역이 된다는 한마디로 이후 수행의 서툶을 배역 연기로 정당화함(문안 작성 예정)
	- 다른 배역 자리는 잠금 슬롯으로 표시함(마당당 배역 확장은 2차연도 확장 설계)
	- 분기: 화면 타임아웃(기본 60초, 잠정) → 배역을 확정하고 다음으로 정상 진행
	- 분기: 미입력 타임아웃 → 종료 처리
	- 분기: 그만두기 선택 시 확인 팝업 → 확정 시 종료 처리

### 4.2.3 서버: 선택 마당과 배역 저장

#### 1) 진행

- 세션에 선택 마당과 배역 식별자를 저장함.

## 4.3 Step 3. 마당 장면 체험 (핵심 체험)

한 마당을 3장으로 진행함: 기초 수업(배역 동작 익히기) → 장면 실습(상대 배역과 큐 주고받기) → 절정 무대(절정 대목 완수). 큐는 스승이나 상대 배역의 발화와 연출로 기대 동작 1개를 지시하는 신호이며(동작 큐), 배운 동작만 이후 장의 큐로 나오고 시킨 동작만 판정함. 세 장은 같은 큐 판정 엔진과 신명 게이지를 공유하고, 마당에 따라 동작 세트, 대본, 상대 배역, 절정 연출이 갈림.

### 4.3.1 클라이언트: 기초 수업 화면 (1장)

#### 1) 진행

1. 장쇠가 수업을 열고("옴탈이란 놈이 나타났다. 잡으려면 세 가지를 익혀라" 류, 문안 작성 예정) 선택 마당의 동작 세트 3개를 하나씩 가르침
2. 동작마다 시범 클립 재생 → 유저 수행 → 판정 → 장쇠 피드백의 루프를 돎
	- 성공 시 다음 동작으로 진행하고, 미수행 시 교정 피드백과 함께 재시도함(동작당 2회 잠정). 재시도를 소진하면 장쇠가 눙치고 통과 처리해 진행을 막지 않음
3. 동작 3개를 마치면 장쇠가 수업을 맺고 장면 실습으로 진행함
	- 분기: 그만두기 선택 시 확인 팝업 → 확정 시 종료 처리
	- 분기: 사람이나 포즈 미검출이 터치 미입력 타임아웃 임계를 넘기면 이탈로 보고 종료 처리

#### 2) 마당별 수업 내용

동작 세트의 고증 근거와 각색 원칙은 탈과 마당 대목 고증 절이 소유함. 판정 특징은 큐 판정 엔진의 판정 요소 조합임.

| 마당 | 동작 1 | 동작 2 | 동작 3 |
|---|---|---|---|
| 옴탈잡이 (꺽쇠) | 살피기 (상체 기울임 + 홀드) | 찔러보기 (팔 뻗기 진폭) | 휘둘러 쫓기 (팔 휘두르기 진폭 + 속도) |
| 샌님잡이 (말뚝이) | 거드름 흉내 (상체 젖히기 + 홀드) | 호령 가리키기 (팔 뻗기 + 홀드) | 채찍 휘두르기 (팔 휘두르기 진폭 + 속도) |
| 먹중잡이 (취발이) | 어깨 메기 (팔 얹기 + 홀드) | 한발 차올리기 (발목 높이 진폭) | 소매 뿌리기 (팔 휘두르기 진폭 + 속도) |

#### 3) 큐 판정과 신명 게이지

##### (1) 역할과 목적

큐에 대한 유저의 몸 응답을 판정해 즉각 피드백으로 되돌리는 핵심 엔진. 세 장이 같은 판정 규칙을 공유해, 배운 동작이 그대로 장면의 응답과 대결의 무기가 되게 함.

##### (2) 입력과 출력

- **입력**: 카메라 영상 프레임, 큐 이벤트(기대 동작 식별자와 판정 구간. 각 장의 진행이 전달)
- **출력**:
	- 큐별 판정 결과 (장쇠 피드백, 상대 배역 리액션 연출, 절정 무대 게이지에 전달)
	- 신명 게이지 값 (화면 게이지 표시)
	- 장면 수행 기록 (세션 데이터에 저장, 배역 인정 화면의 수행 요약 입력)

##### (3) 판정 기본 규칙

- **폐쇄형 큐 원칙**: 판정은 항상 "기대 동작 1개가 특정된 큐"에만 걸림. 자유 표현이나 행동의 의미적 적절성은 판정하지 않음. 기대 동작이 아닌 모든 움직임은 미수행 하나로 수렴해, 행동의 의미를 오독하는 판정을 구조적으로 없앰
- **판정 요소**: 자세(기대 동작 스켈레톤과의 유사도), 진폭(관절 이동 크기), 홀드(자세 유지 시간), 타이밍(판정 구간 안 수행 여부)의 조합. 동작마다 쓰는 요소가 다름(마당별 수업 내용 표의 판정 특징)
- **판정 구간**: 수업과 실습은 큐 발화 종료 후 응답 대기 4초(잠정)를 판정 구간으로 삼음. 절정 무대는 장단 기준의 판정 시각 앞뒤 0.5초(잠정, 리듬 게임 판정 관례 참고)를 씀. 둘 다 실기기 인식 성능을 보고 개발 단계에서 확정함
- **판정 피드백 (3단, 잠정)**: 얼쑤(성공, 진폭 상위), 좋다(성공), 다시(미수행). 영문 등급 표기는 쓰지 않고 스승과 판의 말로 표현함. 미수행 표기 "다시"는 재시도가 있는 기초 수업에서만 노출하고, 실습과 절정에서는 미수행 피드백 없이 진행함(잠정)
- **관대 판정**: 동작의 잘잘못을 정밀히 가리지 않고 수행으로 인정하는 쪽으로 임계를 잡음. 무인 공공 체험에서는 실제로 한 동작을 안 했다고 놓치는 판정이, 어설픈 동작을 후하게 인정하는 판정보다 체험을 크게 해치기 때문임

##### (4) 자세 판정 산출

판정 구간의 프레임들을 아래 5단계로 처리해 큐 1개의 자세 값과 타이밍 값을 냄. 단계 구성은 동작 유사도 판정에 통용되는 기법을 따름.

1. **포즈 추정**: 카메라 프레임에서 유저의 2D 키포인트(관절 좌표 + 신뢰도)를 실시간 추출함
2. **전처리**: 신뢰도 임계(잠정 0.3) 미만 키포인트는 그 프레임의 일치도 비교에서 제외하고, 프레임 간 좌표 떨림은 스무딩으로 완화함
	- 신뢰도 임계는 채택할 포즈 추정 모델의 권장 임계와 실측으로 개발 단계에서 확정함
3. **정규화**: 몸 중심(양 힙의 중점)을 원점으로 옮기고 몸통 길이로 나눠 크기를 맞춤. 유저의 키, 화면 내 위치, 카메라까지의 거리와 무관하게 레퍼런스 스켈레톤과 비교하게 하는 단계임
4. **부위별 유사도**: 부위 벡터(어깨→팔꿈치, 팔꿈치→손목, 힙→무릎 등)의 방향을 레퍼런스 스켈레톤의 같은 부위와 코사인 유사도로 비교하고, 부위별 가중 평균으로 프레임 일치도를 냄
	- 덧뵈기 동작 세트가 팔 중심이라 팔 부위 가중을 상향함(잠정)
	- 관절 각도 차 비교는 동급 대안으로 두고 개발 단계에서 인식 성능을 보고 확정함
5. **판정**: 판정 구간 안 프레임 일치도의 최댓값으로 수행 여부를 가르고, 진폭과 홀드는 같은 구간의 키포인트 궤적에서 산출함(진폭은 관절 이동 크기, 홀드는 임계 이상 자세 유지 시간). 얼쑤 경계값 등 임계는 정량 미정으로 개발 단계에서 확정함

##### (5) 신명 게이지

- **가산 기준**: 큐 성공마다 가산하고, 진폭 상위(얼쑤)에 보너스를 얹음(가산량 정량 미정, 개발 단계 확정). 동작의 잘잘못을 세밀히 매기는 채점이 아니라 판을 달구는 활동 지표임
- **달성 보상**: 게이지가 달성 임계(정량 미정)를 넘기면 환호 사운드(군중 추임새, 박수)로 보상함
- **미달 처리**: 임계 미달이면 장쇠가 눙치며 마무리함(배역 인정 화면의 서사 번역과 연동)
- **학습 진척**: 1차연도는 세션 안 수행으로 끝남. 재방문 진척 누적(마당 수집 현황, 향상 피드백)은 2차연도 확장 설계로 둠
- **세부 설계 (작성 예정)**: 큐별 가산량과 보너스, 달성 임계

##### (6) 기술 요건

- **모델 확보**: 실시간 포즈 추정은 사전학습 모델과 온디바이스 SDK를 우선 검토함(MoveNet, MediaPipe Pose 류 실시간 경량 2D 키포인트 모델이 후보, 확인 필요). 판정 로직은 레퍼런스 동작 대비 자체 규칙
- **판정 기준**: 포즈 추정 정확도, 판정 임계와 가중치, 실시간 처리 지연(프레임률). 판정 정확도 검증 방법은 확인 필요
- **적용**: 실시간 처리. 온디바이스 처리를 우선 검토하고 서버 처리는 대안으로 둠. 라이브는 원거리에서 전신 포즈를 판정하는 단일 구도임. 모션 인식은 전신 싱글 카메라 기준 손목까지가 현실적이라 동작 세트를 이 범위로 설계함(손가락 세부 동작 없음)
- **데이터**: 동작 세트의 모션 레퍼런스가 판정 기준 데이터임. 보존회 실연 촬영으로 확보하고(고증 자문 연계, 확인 필요), 시범 클립과 판정 레퍼런스 스켈레톤을 같은 촬영본에서 파생해 기준과 시범의 원천을 일치시킴

##### (7) 필요 리소스

- 동작 세트 모션 레퍼런스(마당별 3개, 보존회 실연 촬영. 고증 자문 연계, 확보 방식 확인 필요)
- 동작별 판정 레퍼런스 스켈레톤(모션 레퍼런스에서 추출한 키포인트 시퀀스)
- 시범 클립(모션 레퍼런스 촬영본 편집, 좌우 반전 거울 방식)
- 환호와 추임새 사운드(게이지 달성 보상, 제작 방식 확인 필요)

##### (8) 실패와 복구

- 판정 구간 안에서 포즈가 인식되지 않거나 신뢰도가 낮을 경우 및 인식 지연 시 처리
	- 해당 큐는 미수행으로 처리하고 진행함(기초 수업은 재시도 규칙, 실습과 절정은 다음 큐로 진행)
- 사람 미검출이나 포즈 미검출이 터치 미입력 타임아웃 임계를 넘길 시 처리
	- 미입력 타임아웃으로 간주하여 종료 처리
- 카메라 영상이 들어오지 않거나 모든 프레임 저신뢰가 지속될 시 처리(지속 임계는 잠정, 개발 단계 확정)
	- 유저 요인이 아니라 시스템 장애(카메라 고장이나 가림, 조명, 성능 저하)로 보고 상황 안내 팝업 후 중단 처리함. 운영 알림 대상임

### 4.3.2 클라이언트: 장면 실습 화면 (2장)

#### 1) 진행

1. 상대 배역이 등장하고(등장 클립), 장쇠가 장면을 엶
2. 장면 대본의 큐 시퀀스를 진행함: 상대 배역이나 장쇠의 재담에 얹힌 동작 큐 → 유저의 몸 응답(큐 판정) → 상대 배역 리액션 클립의 루프
	- 유저 배역의 대사 차례는 장쇠가 대신 발화하고(대사 대행), 유저는 몸으로 수행함
	- 미수행이어도 장면은 멈추지 않고 상대 배역의 중립 리액션으로 진행함(재시도 없음)
3. 대본의 마지막 큐를 마치면 장쇠가 장면을 맺고 절정 무대로 진행함
	- 분기: 그만두기 선택 시 확인 팝업 → 확정 시 종료 처리
	- 분기: 사람이나 포즈 미검출이 터치 미입력 타임아웃 임계를 넘기면 이탈로 보고 종료 처리

#### 2) 마당별 장면 대본 (개요)

대본의 큐 문안과 합수는 작성 예정이며, 원전 대목과 각색 원칙은 탈과 마당 대목 고증 절이 소유함. 아래는 큐 흐름의 뼈대임.

| 마당 | 장면 | 큐 흐름 (재담에 얹힌 동작 큐 → 기대 동작 → 리액션) |
|---|---|---|
| 옴탈잡이 | 옴탈과의 실랑이 | 옴탈이 슬금슬금 등장 → "살펴봐라"(살피기) → 옴탈이 획 돌아보면 "얼음!"(홀드 유지) → "찔러봐라"(찔러보기) → 옴탈 펄쩍 → "옴 올랐다!"(긁기 소동, 판정 없는 따라 하기 연출) |

#### 3) 상대 배역 리액션 연출

##### (1) 역할과 목적

상대 배역(옴탈, 샌님, 먹중)을 사전 제작 클립으로 연기하는 시스템. 유저 동작이 판정을 통과하는 순간 과장된 리액션을 재생해, 슬랩스틱의 웃음을 유저의 트리거에 대한 보상으로 완성함.

##### (2) 입력과 출력

- **입력**: 큐별 판정 결과(큐 판정에서 수신), 장면 진행 상태(각 장의 진행이 전달)
- **출력**: 상대 배역 클립 재생(화면 연출)

##### (3) 동작과 규칙

- **클립 라이브러리와 상태 머신**: 상대 배역마다 등장, 대기(루프), 큐별 리액션(성공용 과장 리액션, 미수행용 중립 반응), 절정 결말(나가떨어짐 등)의 짧은 클립을 사전 제작하고, 장면 진행 상태에 따라 호출함
- **정지 포즈 북엔드**: 모든 클립은 정지 포즈에서 시작해 정지 포즈로 끝나게 만들어 클립 사이 이음새를 감춤
- **슬랩스틱 분담**: 넘어지기, 나가떨어지기 등 낙법 계열 연기는 상대 배역 클립 전용임. 유저에게는 서서 하는 상체 중심 동작만 요구함(안전 원칙)
- **제작 방식**: AI 영상 생성으로 사전 제작하고 운영 전 검수를 거침(캐릭터 시트 고정으로 일관성 관리, 고증 검수는 탈과 마당 대목 고증 기준). 런타임 생성은 없음

##### (4) 기술 요건

- **재생**: 전부 클라이언트 로컬 재생임. 서버 왕복 없음
- **사전 로드**: 마당 확정(Step 2) 후 Step 3 진입 전에 해당 마당의 클립, 대본, 판정 자산, 음원을 미리 로드해 체험 중 로딩 끊김을 없앰
- **판정 기준**: 클립 호출 지연(판정 확정에서 리액션 재생까지, 정량 미정), 클립 일관성(캐릭터 시트 대비, 검수 기준 작성 예정)

##### (5) 필요 리소스

- 상대 배역 리액션 클립 라이브러리 3종(옴탈, 샌님, 먹중. AI 영상 사전 생성, 정지 포즈 북엔드, 사전 검수)
- 상대 배역 캐릭터 시트(탈과 의상 고정 레퍼런스, 고증 자문 연계)
- 마당별 장면 대본(큐 문안, 대사 대행 문안, 작성 예정)

##### (6) 실패와 복구

- 클립 재생이 실패하면 해당 배역의 정지 이미지와 효과음으로 대체하고 장면을 계속함(기능 축소)
- 클립 로드 실패는 마당 리소스 로드 실패로 묶어 중단 처리함(재시도 2회 잠정)

### 4.3.3 클라이언트: 절정 무대 화면 (3장)

#### 1) 진행

1. 무대 격상 연출: 배역들이 뒤에 일렬로 서는 관망 정렬 배경(잠정)과 함께 장쇠가 절정을 선언하고 장단이 시작됨
2. 장단 음원에 맞춰 절정 시퀀스를 진행함: 배운 동작들이 동작 안내 바의 큐로 연속 등장하고, 유저가 장단 타이밍에 맞춰 수행함
	- 큐 성공마다 절정 게이지(신명 게이지와 별개인 이 장의 결말 트리거)가 차고, 진폭 상위(얼쑤) 판정은 가산이 더 큼
	- 게이지가 차면 남은 시퀀스를 정리하고 즉시 절정 결말 연출을 재생함(잠정): 마당별 결말은 아래 표
	- 음원이 끝날 때까지 게이지 미달이면 결말 연출을 완화판으로 재생하고(문안과 연출 작성 예정) 완주로 처리함
3. 결말 연출을 마치면 완주로 보고 Step 4 배역 인정으로 진행함
	- 분기: 음원 로드 시 확인한 음원 길이 + 30초(잠정)가 지나도 재생이 완료되지 않을 경우 → 시한 초과 실패로 간주하여 중단 처리
	- 분기: 그만두기 선택 시 확인 팝업 → 확정 시 종료 처리
	- 분기: 사람이나 포즈 미검출이 터치 미입력 타임아웃 임계를 넘기면 이탈로 보고 종료 처리

#### 2) 마당별 절정 연출

| 마당 | 절정 시퀀스 | 절정 게이지의 의미 | 결말 연출 |
|---|---|---|---|
| 옴탈잡이 | 몰아내기: 휘둘러 쫓기 중심의 연타 큐, 장단 가속 | 몰이 진행도 | 옴탈이 데굴데굴 굴러 퇴장 |
| 샌님잡이 | 절 배우기: 시범 동작 큐(팔 들기, 꾸부리기)를 유저가 보이면 샌님이 우스꽝스럽게 따라 함 | 절 배우기 진행도 | 샌님이 유저(말뚝이)에게 큰절을 올리고, 유저는 버티고 서서 절 받기(전복 완성) |
| 먹중잡이 | 춤 대결: 배운 동작 3개의 맞대무 시퀀스, 진폭이 클수록 게이지 가속 | 대결 우세 | 먹중이 과장되게 나가떨어짐 |

#### 3) 절정 시퀀스 진행기

##### (1) 역할과 목적

장단 음원을 기준 시계로 절정의 연속 큐를 진행하는 시스템. 턴제인 수업, 실습과 달리 절정을 끊김 없는 리듬 흐름으로 만들어 판을 달굼.

##### (2) 입력과 출력

- **입력**: 선택 마당 식별자, 절정 타임라인 JSON, 장단 음원 재생 위치
- **출력**: 큐 이벤트(기대 동작과 판정 시각, 큐 판정에 전달), 동작 안내 바 표시, 절정 게이지 값

##### (3) 동작과 규칙

- **동작 안내 바 (픽토그램 스크롤)**: 화면 하단의 가로 바. 다가올 동작의 픽토그램이 바 오른쪽 끝에서 등장해 왼쪽의 판정 마커를 향해 일정 속도로 이동하고, 판정 마커에 닿는 순간이 판정 시각임
- **판정 피드백**: 큐의 판정 결과(얼쑤, 좋다, 다시)를 판정 마커 위에 짧게 표기함(큐 판정 출력 연동)
- **절정 타임라인 JSON**: 픽토그램 등장과 판정 타이밍을 음원 재생 시작 기준 초 단위로 관리함. 동작 안내 바와 큐 판정이 이 파일 하나에서 타이밍을 읽어 표시와 판정의 싱크를 맞춤
- **절정 게이지**: 큐 성공마다 차오르고 진폭 상위(얼쑤)에 보너스를 얹음. 신명 게이지와 별개로 이 장의 결말 트리거를 맡음(가산량 정량 미정)

##### (4) 기술 요건

- **재생 동기화**: 음원 재생 위치를 유일한 기준 시계로 삼음. 픽토그램 스크롤 좌표를 매 프레임 이 기준 시계에서 계산하고, 별도 타이머를 두지 않아 오래 재생해도 어긋남(드리프트)이 쌓이지 않게 함
- **적용**: 전부 클라이언트 로컬 재생임. 서버 왕복 없음

##### (5) 필요 리소스

- 절정 타임라인 JSON(마당별)
- 동작별 픽토그램 이미지(동작 안내 바용, 동작 세트와 1:1)
- 장단 음원(마당별, 재생 위치가 기준 시계. 웃다리 풍물 가락에서 선정, 고증 자문 연계)

##### (6) 실패와 복구

- 타임라인 JSON, 픽토그램, 음원 로드나 검증이 실패 시 처리
	- 재시도(2회 잠정) 실행. 한도를 넘기면 마당 리소스 로드 실패로 중단 처리(원인: 시스템)
- 재생 중 일시 끊김
	- 기준 시계(음원 재생 위치) 재동기화로 복구함

## 4.4 Step 4. 배역 인정

### 4.4.1 클라이언트: 배역 인정 화면

#### 1) 진행

- 점수 대신 배역 인정을 표시함. 구성은 셋임
	- **인정 선언**: 장쇠가 인정 재담을 발화함("오늘부로 꺽쇠 노릇 한번 제대로 했다!" 류, 문안 작성 예정). 완주 자체를 인정하며 등급 서열을 매기지 않음
	- **수행 요약**: 장별 완수 현황과 하이라이트 동작 1개를 칭찬 문구로 표시함("네 소매 뿌리기가 제일 시원했다" 류). 장면 수행 기록의 판정 값을 문구로 번역한 것으로 별도 채점이 없음
	- **게이지의 서사 번역**: 신명 게이지 달성이면 "판이 후끈했다" 류의 문구와 환호를, 미달이면 장쇠가 눙치는 문구("다음엔 더 크게 놀아보자" 류)를 표시함. 미달을 실패로 낙인찍지 않음
- 이 화면 진입이 완주 확정임. 진입 시의 단계 이동 이벤트(각 Step 진입 전송)가 서버의 완주 기록을 겸해, Step 5 도달 전에 세션이 끊겨도 완주가 유실되지 않음. Step 5 종료 이벤트는 완주 유형만 보강함
	- 분기: 처음으로 버튼 터치 또는 화면 타임아웃(기본 60초, 잠정) → Step 5 종료와 리셋으로 진행
- **이수 단계 (선택 검토)**: 인정 층위(구경꾼, 초짜 광대, 한몫 광대 류)의 도입 여부는 작성 예정임

	- 완주와 비완주 종료가 모두 모이는 종착점임. 비완주 종료는 배역 인정 화면을 건너뛰고 여기로 바로 들어옴

## 5.2 에러 케이스

### 5.2.1 케이스 목록과 처리

**처리**는 그 실패가 세션을 어떤 상태로 끝내는지를, **원인**은 실패가 어디에서 비롯되었는지를 나타냄. 원인이 외부 서비스나 시스템일 경우에만 운영 알림을 보냄. 갈래를 나누는 판정 규칙은 3.9 실패 처리에 있고, 본 표는 그 규칙을 케이스에 적용한 결과임. 이후 동작의 Step 5는 모두 비완주 종료라 배역 인정 화면을 건너뛰고 세션 종료와 파기 후 시작 화면으로 복귀함.

| 발생 지점                        | 처리    | 원인     | 팝업             | 이후 동작                     |
| ---------------------------- | ----- | ------ | -------------- | ------------------------- |
| 장쇠 TTS 합성이나 호출 실패           | 기능 축소 | 외부 서비스 | 없음             | 세션 계속, 대표 이미지와 텍스트로 진행    |

| 상대 배역 리액션 클립 재생 실패         | 기능 축소 | 시스템    | 없음             | 세션 계속, 정지 이미지와 효과음으로 대체    |
