> 덧뵈기(탈춤)를 소재로 한 AR 탈춤 체험 시범콘텐츠의 개발 기획서. [[콘셉트 정리#1) 나만의 탈춤]]을 입력으로 작성함. 골격 단계로, 점차 채워나감.

# 1. 개요

사용자가 직접 디자인한 탈을 3D로 변환해 AR로 쓰고, 풍물 장단에 맞춰 탈춤 춤사위를 따라 추며, 탈 캐릭터와 기념 촬영하는 체험 콘텐츠.

- **소재**: 남사당놀이 탈놀음 덧뵈기 ([[덧뵈기]])
- **유형**: 체험. 실시간 동작 놀이가 핵심이고, 탈 만들기는 도입 단계임 (유형 정의는 [[콘셉트 정리#3. 전체 구조 정리]])
- **플랫폼**: 키오스크 (세로형 터치 + 카메라와 마이크. [[콘셉트 정리#가. 키오스크]])
- **흐름**: 탈 디자인 → AI 3D 변환 → AR 착용 + 춤사위 따라하기(포즈 채점) → 기념 촬영 → 사진 전송 ([[콘셉트 정리#1) 나만의 탈춤]]). 여기에 숏폼 리플레이 영상 제공을 더함
- **핵심 특성**: 사용자가 만든 탈을 쓰고 직접 몸으로 춤을 따라 추는 능동 체험. 자세 일치도와 타이밍을 실시간 채점해 신명(興) 게이지로 보상
- **진행 호스트**: 말뚝이. 탈춤 풍자의 화자가 전 Step 진행을 안내하고 추임새로 호응 (페르소나는 3장 가. 진행 호스트 참조)
- **산출물**: 기념 사진(포즈 챌린지 베스트샷에 신명 게이지 점수와 등급 스탬프)과 숏폼 리플레이 영상(AR 탈 착용 춤사위, 음원 포함). 상세는 4장 산출물 참조

목표, 범위 등 나머지 개요 항목은 작성 예정.

# 2. 시스템 동작

- 매체: 9:16 세로형 키오스크. 터치, 카메라(포즈와 얼굴 인식), 마이크 입력을 받음. 1인 사용
- 큰 흐름(스케치): 인트로(동의 약관) → 탈 디자인 → 3D 변환 → AR 춤사위 체험 → 기념 촬영 → 결과물 전송 → 종료
- 목표 플레이타임: **확인 필요** (콘셉트와 로드맵 원문 미명시. 임의 추정 금지)

**개요**: Step 1 인트로 → Step 2 탈 디자인 → Step 3 3D 변환 + 대기 화면 → Step 4 AR 착용 + 춤사위 따라하기 → Step 5 기념 촬영 → Step 6 결과물 전송 → Step 7 종료와 리셋

## 가. 세션

한 유저의 키오스크 사용 전체(Step 1 시작 → Step 7 종료)를 감싸는 상위 컨테이너. 하위 Step들이 세션 안에서 순차 실행됨. 라이프사이클과 저장 데이터 모델은 [[시범콘텐츠 공통 사양#2. 세션]] 구조를 준용하되, 본 콘텐츠 고유 데이터(탈 디자인, 3D 모델, 동작 채점, 기념 사진, 리플레이 영상)로 재정의함.

### 1) 세션 라이프사이클

[[시범콘텐츠 공통 사양#다. Step별 세션 동작]] 준용.

- 생성: Step 1 시작 시 신규 세션 생성 + 동의 기록 저장. 미동의 또는 타임아웃 시 세션 즉시 파기(동의 기록 미생성)
- 갱신: Step 2~6 진행 중 각 산출물을 세션에 저장하고 갱신 (탈 디자인 → 3D 탈 모델 → 동작 채점 기록 → 기념 사진과 리플레이 영상 → 연락처)
- 종료: Step 7에서 세션 종료 + 임시 데이터 파기 + 시작 화면 리셋(다음 유저 대기)

### 2) 세션 데이터

세션이 담는 데이터를 분류, 값, 보관과 파기 정책으로 정리함. 개인정보 민감 데이터(영상, 사진, 연락처)에는 최소 보관 원칙을 적용함. 보관 기간 잠정값은 법무 검토 후 확정함 (임의 추정 금지, [[CONVENTIONS#바. 수치/목표 인용 원칙 (엄격)]]).

| 데이터 | 분류 | 값과 구성 | 보관과 파기 |
|---|---|---|---|
| 세션 ID | 시스템 | 세션 고유 식별자 | 세션 종료 시 파기 |
| 동의 기록 | 시스템 | 약관 버전 + 동의 일시 + 동의 항목(카메라 필수, 영상 선택) | 보관 |
| 탈 디자인(2D) | 콘텐츠 | 사용자가 디자인한 2D 탈 도안 | 별도 저장소 보관 (재방문, 재사용, 품질 분석) |
| 3D 탈 모델 | 콘텐츠 | 디자인에서 변환된 3D 자산 | 별도 저장소 보관 |
| 동작 채점 기록 | 콘텐츠 | 자세 일치도와 타이밍 점수, 신명 게이지 | 익명 통계만 보관, 식별 원본은 세션 종료 시 파기 |
| 기념 사진 | 콘텐츠 | 포즈 챌린지 베스트샷 + 신명 게이지 점수와 등급 스탬프 | 메모리 임시 (서버 디스크 비보관), 전송 최종 결과 후 파기 |
| 리플레이 영상 | 콘텐츠 | AR 탈 춤사위 하이라이트 + 기념 포즈 숏폼 (MP4) | 다운로드용 임시 보관, 다운로드 또는 만료 시 파기 (미다운로드 시 세션 종료 시) |
| 영상 피드 | 개인정보 | 카메라 원본 스트림 (포즈 추정과 녹화 입력) | 메모리 임시 (비저장), 세션 종료 시 파기 |
| 연락처 | 개인정보 | 유저 연락처 (SMS/이메일) | 메모리 임시, 전송 최종 결과 후 즉시 파기 |

- 메모리 임시 보관 데이터(영상 피드, 연락처)는 디스크 영속화와 로그 기록 금지, 파기 시 메모리 명시적 덮어쓰기 ([[시범콘텐츠 공통 사양#가. 개인정보 처리 정책 (공통 원칙)]] 준용)
- 익명 채점 통계는 개인 식별 정보(얼굴, 영상, 연락처)와 결합 불가하도록 비연결 설계
- 보관 대상 데이터의 보관 기간과 저장소 정책은 5장 가. 개인정보 처리 정책에서 정의

### 3) 영상 처리 주의

본 콘텐츠는 카메라로 얼굴과 신체를 촬영(포즈 추정 + 기념 사진 + 리플레이 영상)하므로 덜미보다 개인정보 민감도가 높음. 데이터별 보관과 파기는 위 세션 데이터 표를 따르며, 세부 처리 정책과 법무 검토 사항은 5장 가. 개인정보 처리 정책에서 정의.

## 다. Step별 명세

본 콘텐츠 Step별 골격 명세 (상세 작성 예정). 각 Step 화면 수는 기획 잠정값(UI 설계 단계 확정), RFP 정량 요건 아님.

### 1) Step 1. 인트로 (시작 + 동의)

- **트리거**: 유저가 시작 버튼 터치
- **시스템**: 클라이언트 UI, 백엔드 (상세는 5장 기술 구성)
- **화면**: 시작, 가이드, 동의 약관 3개. 전환: 시작 화면 터치(대기 상태) → 다음 → 동의 또는 거부 입력. 시작 화면은 Step 7 복귀 화면과 동일
- **프로세스 (골격)**:
	1. 백엔드: 신규 세션 생성
	2. UI(가이드): 인사말과 가이드 표시
	3. UI(동의 약관): 고객 동의 약관 표시 (**카메라 촬영 동의 필수 + AR 합성 영상 녹화, 리플레이 영상 생성과 제공 동의**)
	4. UI(동의 약관): 동의 입력 감지
		- 분기: 카메라 촬영에 미동의하거나 무응답 타임아웃이면 Step 7로 직행. 영상 산출물 동의(선택)만 거부하면 Step 4 녹화와 Step 5 영상 생성을 생략하고 사진만 진행
	5. 백엔드: 동의 기록 저장
- **다음**: Step 2

### 2) Step 2. 탈 디자인

- **트리거**: Step 1 동의 완료
- **시스템**: 클라이언트 UI, 백엔드 (상세는 5장 기술 구성)
- **화면**: 탈 디자인 도구 (1개). 전환: 도안 확정 → Step 3 (도구 내부 영역 분할은 UI 설계 단계)
- **프로세스 (골격)**:
	1. UI(탈 디자인 도구): 탈 디자인 도구를 제공하고 사용자 도안 입력을 수집 (디자인 방식이 템플릿/조합/드로잉 중 무엇인지는 콘셉트에 미상세, 확인 필요)
	2. 백엔드: 입력 유효성 검증
	3. AI: 가드레일 검사 (부적절 도안 차단, 상세 3장 마. 가드레일)
		- 실패: 부적절 도안 검출 시 차단 + 재입력 안내(재시도), 반복 위반 시 처리 작성 예정
	4. 백엔드: 세션 저장
- **입력**: 사용자 탈 디자인 입력
- **출력**: 2D 탈 도안
- **다음**: Step 3

### 3) Step 3. 3D 변환 + 대기 화면

- **트리거**: 탈 디자인 완료
- **시스템**: AI 시스템, 클라이언트 UI, 백엔드 (상세는 5장 기술 구성)
- **화면**: 변환 대기 (1개, 폴링 진행 표시). 전환: 변환 완료 → Step 4
- **프로세스 (골격)**:
	1. 백엔드: 3D 변환 작업 큐 등록과 시작
	2. AI: 2D 도안을 3D 탈 모델로 변환
		- 실패: 변환 실패 시 fallback (에러/fallback 공용 기능)
	3. AI: 생성물 가드레일 검사
		- 실패: 가드레일 한도 초과 시 fallback (에러/fallback 공용 기능)
	4. 백엔드: 3D 탈 모델 저장
	- (병행) UI(변환 대기): 변환 진행 표시, 백엔드 job 상태 폴링
- **입력**: 2D 탈 도안
- **출력**: 3D 탈 모델
- **다음**: 변환 완료 시 Step 4

### 4) Step 4. AR 착용 + 춤사위 따라하기 (핵심 체험)

- **트리거**: 3D 변환 완료
- **시스템**: AI 시스템(포즈 추정), 클라이언트 UI, 백엔드 (상세는 5장 기술 구성)
- **화면**: AR 춤사위 체험 1개 (동적 화면: AR 카메라 뷰, 춤사위 가이드, 신명 게이지, 말뚝이를 함께 표시). 전환: 춤사위 종료 시 Step 5
- **프로세스 (골격)**:
	1. UI(AR 춤사위 체험): 변환된 3D 탈을 AR로 착용 (카메라 얼굴 추적 → 탈 오버레이)
	2. UI(AR 춤사위 체험): 탈춤 춤사위 가이드 제시, 사용자 동작 캡처
		- 분기: 무응답 타임아웃 → Step 7
	3. AI: 포즈를 추정해 자세 일치도와 타이밍을 채점. 점수가 쌓이면 신명(興) 게이지 상승 (채점 상세는 3장 라. 채점 체계)
		- 실패: 포즈가 안 잡히거나 신뢰도가 낮으면 재시도 안내. 지연되면 해당 구간 점수는 보류
	4. UI(AR 춤사위 체험): 말뚝이가 채점에 따라 실시간 추임새 피드백 (3장 가. 진행 호스트)
	5. UI(AR 춤사위 체험): 게이지 달성 시 환호 사운드(군중 추임새와 박수)로 보상, 미달 시 말뚝이가 눙치며 마무리 (상세 작성 예정)
	- (병행) 백엔드: 영상 동의가 있으면, 춤사위 중 AR 합성 화면을 리플레이 소재로 임시 녹화 (Step 5 영상 편집 입력). 영상 미동의 시 생략
- **입력**: 카메라 동작 영상, 풍물 장단 타이밍
- **출력**: 동작 채점 기록, 신명 게이지 결과, 리플레이용 임시 녹화 영상
- **다음**: Step 5

### 5) Step 5. 기념 촬영 (포즈 챌린지)

- **트리거**: 춤사위 체험 완료
- **시스템**: AI 시스템(포즈 추정), 클라이언트 UI, 백엔드 (상세는 5장 기술 구성)
- **화면**: 포즈 챌린지 촬영, 생성 대기 2개 (생성 대기 화면은 영상 인코딩 동안 노출). 전환: 촬영 완료 → 생성 대기 → 통과 산출물 확정 시 Step 6. 실패와 fallback(사진만 제공 또는 에러 안내)은 아래 sub-step 5 실패 참조
- **프로세스 (골격)**:
	1. UI(포즈 챌린지 촬영): 탈춤 정지 포즈 제시 + 제한 시간, 사용자 포즈 캡처
	2. AI: 포즈 일치 판정 → 베스트샷 캡처
		- 실패: 포즈가 안 잡히거나 신뢰도가 낮으면 제한 시간 안에서 재촬영 안내. 계속 실패하면 베스트샷 없이 진행
	3. 백엔드: Step 4 신명 게이지 점수와 등급 스탬프를 합성한 기념 사진 생성 (탈 쓴 캐릭터와 사용자)
	4. 백엔드: (영상 동의 시) 춤사위 따라하기(Step 4) 하이라이트 + 기념 포즈를 AR 탈 합성 숏폼 영상으로 편집과 인코딩 (풍물 장단 음원 포함). 영상 미동의 시 생략
	5. AI: 생성물(사진과 영상) 가드레일 검사 (3장 마. 가드레일), 통과물만 출력으로 확정
		- 실패: 가드레일을 통과 못 하거나 재생성 한도를 넘으면 위험 생성물을 파기하고 사진만 제공. 사진까지 전부 실패하면 에러 안내 (에러/fallback 공용 기능). Step 6은 통과 산출물이 있을 때만 진행
	- (병행) UI(생성 대기): 사진과 영상을 생성, 인코딩하는 동안 대기 표시
- **입력**: 카메라 영상, 포즈 판정, Step 4 신명 게이지 점수, Step 4 임시 녹화 영상
- **출력**: 기념 사진 (포즈 챌린지 베스트샷 + 신명 게이지 점수와 등급 스탬프), 리플레이 영상 (숏폼 MP4, 영상 동의 시)
- **다음**: Step 6

### 6) Step 6. 결과물 전송

- **트리거**: 기념 사진 생성 완료 (리플레이 영상은 영상 동의 시)
- **시스템**: 클라이언트 UI, 백엔드, 외부 서비스 (상세는 5장 기술 구성)
- **화면**: 결과물 미리보기(사진과 영상), 연락처 입력과 전송 2개 (영상 동의 시 전송 후 다운로드 QR 표시). 전환: 전송 또는 거부 → Step 7
- **프로세스 (골격)**:
	1. UI(결과물 미리보기): 기념 사진과 리플레이 영상 미리보기 (다운로드 수단 노출 전)
	2. UI(연락처 입력과 전송): 연락처 입력 + 전송 동의 입력 수집
		- 분기: 전송을 거부하거나 무응답이면 연락처를 즉시 파기하고, 전송과 다운로드를 생략한 채 Step 7로
	3. 백엔드: 전송 동의 시 연락처 임시 저장
	4. 외부 서비스: 사진 전송 (SMS 링크 또는 이메일, 채널은 확인 필요). 연동 상세는 5장 마. 외부 서비스 연동, 채널 근거는 [[콘셉트 정리#가. 키오스크]]
		- 실패: 전송 실패는 에러/fallback 공용 기능 ([[시범콘텐츠 공통 사양#나. 결과물 전송]] 준용)
	5. 외부 서비스: (영상 동의 시) 리플레이 영상 다운로드 URL 생성 (signed one-time URL)
	6. UI(연락처 입력과 전송): (영상 동의 시) 다운로드 QR 표시
	7. 백엔드: 사진과 연락처는 전송 최종 결과 후, 영상은 다운로드 성공 또는 유효기간 만료 후 파기
- **입력**: 연락처, 전송 동의
- **출력**: 전송과 다운로드 결과
- **다음**: Step 7

### 7) Step 7. 종료와 리셋

- **트리거**: 결과물 전송 완료 또는 미동의 또는 타임아웃 또는 유저 이탈
- **시스템**: 클라이언트 UI, 백엔드 (상세는 5장 기술 구성)
- **화면**: 마무리 인사 (1개) → 시작 화면 복귀. 시작 화면은 Step 1 진입 화면과 동일(신규 아님)
- **프로세스 (골격)**:
	1. UI(마무리 인사): 마무리 인사 표시
	2. 백엔드: 세션 종료 + 임시 데이터 파기 (연락처, 영상 피드, 미다운로드 리플레이 영상)
	3. UI(시작): 시작 화면 복귀 (다음 유저 대기)
- **다음**: 다음 유저용 Step 1 대기

# 3. 콘텐츠 설계

본 콘텐츠의 설계 요소(진행 호스트, 탈과 춤사위 고증, 탈 디자인, 채점 체계, 가드레일)와 제작 자산을 정의. 5장 기술 구성은 본 장에서 정의된 것의 구현과 배치를 다룸.

## 가. 진행 호스트 (말뚝이)

본 콘텐츠의 진행 안내자. 탈춤 풍자의 화자 말뚝이가 전 Step을 잇는 목소리로 등장, 탈 디자인부터 춤사위 따라하기, 기념 촬영까지 안내하고 추임새로 호응함.

- **역할**: 양반을 놀리는 탈춤 풍자의 화자. 관객과 대거리하는 전통 기능을 진행 안내와 추임새로 계승 (덜미 박첨지의 해설자와 길잡이에 대응, [[덜미 - 전자책 변환 기획서#가. 박첨지 페르소나]])
- **화법**: 재담과 추임새. 춤사위 채점 피드백을 추임새로 전달 (3장 라. 채점 체계와 연동)
- **시각 정체성**: 말뚝이 탈과 의상 고유 양식 유지 (고증은 3장 나. 탈과 춤사위 고증 참조)
- **고증 주의**: 말뚝이 배역 해석은 일반 탈춤 문헌 수준(L5 추론, [[CONVENTIONS#사. 외부 근거의 권위 계층]]). [[덧뵈기]] 문서 작성 후 검증 (확인 필요)
- 세부 페르소나(말투, 어휘, 반응 패턴 등) 작성 예정

## 나. 탈과 춤사위 고증

- **탈**: 덧뵈기 탈놀음의 배역 탈(말뚝이, 양반, 먹중, 샌님 등) 양식을 디자인 레퍼런스로 활용 (목록과 종수 **확인 필요**, [[덧뵈기]] 문서 작성 후 보강)
- **춤사위**: 따라 추기 대상 춤사위 동작과 풍물 장단의 고증 매핑 (작성 예정, 고증 자문 연계)
- **시각 정체성**: 탈 양식과 질감의 전통 정합성 유지 방향 (작성 예정)

## 다. 탈 디자인

- 사용자가 탈을 직접 디자인하는 도구의 입력 방식과 제약 (템플릿/조합/드로잉 중 택, **확인 필요**)
- 디자인 결과가 3D 변환(5장 나. AI 시스템) 입력으로 연결되는 형식 규격 (작성 예정)

## 라. 채점 체계 (신명 게이지)

본 콘텐츠 핵심 루프. 실시간 동작을 채점해 신명(興) 게이지로 시각화하고 달성 시 보상.

- **채점 입력**: Step 4는 자세 일치도(포즈 추정 기반)와 풍물 장단 대비 타이밍, Step 5는 정지 포즈 일치도
- **게이지와 보상**: 채점이 쌓이면 신명 게이지 상승. 달성하면 환호 사운드(군중 추임새, 박수)로 보상하고, 미달하면 마무리 처리
- **종합 점수 출력**: 신명 게이지 종합 점수와 등급은 Step 5 기념 사진 스탬프로도 출력
- **세부 설계 (작성 예정)**: 채점 가중치, 게이지 임계, 난이도 곡선, 미달 시 처리 정책

## 마. 가드레일

콘텐츠 안전 정책. 구현은 5장 나. AI 시스템의 AI 가드레일 모듈에서. [[시범콘텐츠 공통 사양#나. 가드레일 적용 3지점]]을 준용하되 본 콘텐츠 입출력에 맞춰 재정의.

- **적용 지점 (골격)**:
	- 입력: 탈 디자인 도안 검사 (Step 2), 부적절 이미지 차단
	- 출력: 3D 변환물(Step 3)과 기념 사진, 리플레이 영상(Step 5)을 검사. 부적절 생성물과 전통 정체성 왜곡을 차단
- **세부 정책 (작성 예정)**: 부적절 도안 분류, 전통 왜곡 판정, 동의 약관(카메라 촬영, 영상 산출물 생성과 제공) 항목 구체화

- 제작 방식: 확인 필요

- 용도: 진행 호스트 말뚝이, 전 Step 안내와 추임새 (3장 가. 진행 호스트)

### 8) 키오스크 UI와 화면 그래픽

- 분류: UI 디자인 자산
- 제작 방식: 외주 또는 자체 (확인 필요)

- 용도: 인트로, 가이드, 동의, 디자인 도구, 대기, 체험, 결과 화면 (5장 바. 클라이언트 UI)

- 형식과 규격(해상도, 길이, 코덱 등)은 구현 단계 확정

# 5. 기술 구성

본 콘텐츠 구현을 횡단 정책(가. 개인정보 처리), 시스템 구성요소(나~사: AI, 하드웨어, 백엔드, 외부 서비스, 클라이언트 UI, 운영), 구현 요건(아. 리플레이 영상 파이프라인)으로 정리. 영상 처리 비중이 커 개인정보 처리 정책을 앞단에 둠. 시스템 구성요소는 [[시범콘텐츠 공통 사양#4. 기술 구성 (6영역 템플릿)]]을 준용하되 본 콘텐츠 고유 모듈(3D 변환, 포즈 추정 채점)로 재구성. (골격, 작성 예정)

## 가. 개인정보 처리 정책

영역을 가로지르는 횡단 정책. 데이터별 보관과 파기 시점은 2장 가. 세션의 세션 데이터 표가 정본이며, 본 절은 범위, 동의, 설계 원칙을 정의함.

- **개인정보 범위**: 연락처(전송용)와 **얼굴과 신체 영상, 기념 사진, 리플레이 영상** (덜미와 달리 영상 처리 포함, 민감도 높음)
- **동의 범위**: 카메라 촬영(포즈 추정)은 필수 동의. AR 합성 영상 녹화와 리플레이 영상 생성/제공은 별도 선택 동의. 영상 동의가 없으면 녹화와 영상 생성을 안 함(사진만 제공)
- **데이터별 처리와 파기**: 2장 가. 세션의 세션 데이터 표 참조 (영상 피드, 사진, 리플레이 영상, 연락처의 보관과 파기를 일원화)
- **비연결 설계**: 익명 채점 통계는 개인 식별 정보(얼굴, 영상, 연락처)와 결합 불가
- **리플레이 영상 파기 트리거**: 파기 시점은 2장 가. 세션 데이터 표가 정본. 5장 아. 리플레이 영상 파이프라인은 트리거를 새로 정의하지 않고 그 시점을 실행하는 구현 메커니즘만 기술
- **세부 정책 (작성 예정)**: 보관 데이터의 보관 기간 잠정값은 법무 검토 후 확정, 임의 추정 금지

## 나. AI 시스템

콘텐츠 AI 모듈. 각 모듈은 공통 사양 AI 모듈 명세 항목을 따름 ([[시범콘텐츠 공통 사양#가. AI 시스템]]).

### 1) 탈 3D 변환 모델

- **역할**: 2D 탈 도안을 AR 착용용 3D 탈 모델로 변환 (Step 3)
- **입력과 출력**: 2D 탈 도안(Step 2 산출, 형식 확인 필요) / 3D 탈 모델(glTF 등 AR 렌더 형식, 확인 필요)
- **모델 확보**: 2D→3D 생성 모델. 자체 학습 부담이 커 외부 API와 사전학습 모델 우선 검토 (후보 조사 확인 필요)
- **판정과 성능 기준**: 변환 성공률, 전통 정합성(가드레일 연계), 변환 시간(대기 폴링 주기 연동, 구현 단계 확정)
- **적용**: Step 3 서버 백그라운드 생성, 대기 화면 폴링 동기화
- **실패, 한계, 복구**: 변환 모델 미확보 시 대안 검토(확인 필요). 변환 실패나 가드레일 한도 초과 시 Step 3 sub-step 실패 분기 fallback. 재시도 한도는 운영 파라미터
- **데이터와 평가**: 배역 탈 양식 레퍼런스(3장 나. 탈과 춤사위 고증), 변환 품질 평가 기준 (작성 예정)

### 2) 포즈 추정과 채점

- **역할**: 카메라 영상에서 자세 추정. 춤사위 자세 일치도와 타이밍 채점 (Step 4), 정지 포즈 일치 판정 (Step 5)
- **입력과 출력**: 카메라 영상 프레임, 포즈 키포인트, 자세 일치도와 타이밍 점수, 신명 게이지 값
- **모델 확보**: 실시간 포즈 추정은 사전학습 모델과 온디바이스 SDK 우선 검토 (후보 확인 필요). 채점 로직은 레퍼런스 동작 대비 자체 규칙
- **판정과 성능 기준**: 포즈 추정 정확도, 채점 임계와 가중치(3장 라. 채점 체계, 구현 확정), 실시간 처리 지연(프레임률)
- **적용**: Step 4와 Step 5 실시간 카메라 입력 처리. 서버/온디바이스 여부 확인 필요
- **실패, 한계, 복구**: 포즈가 안 잡히거나 신뢰도가 낮으면 재촬영 또는 재시도 안내. 지연되거나 계속 실패하면 해당 구간 점수는 보류하고, 무응답 타임아웃 시 Step 7. Step 4와 Step 5 sub-step 실패 분기와 연결
- **데이터와 평가**: 춤사위 레퍼런스 모션(3장 바. 콘텐츠 자산), 채점 정확도 검증 방법 (작성 예정)

### 3) AI 가드레일 (전 Step 입출력 적용)

- **역할**: 탈 디자인 입력, 3D 변환물, 기념 사진과 리플레이 영상 출력의 안전성과 전통 정합성 검사 (3장 마. 가드레일)
- **입력과 출력**: 검사 대상(이미지, 3D, 영상), 통과 또는 차단 판정 + 사유
- **모델 확보**: 부적절 콘텐츠 분류와 전통 왜곡 판정. 외부 가드레일 API와 자체 기준을 조합 검토 (확인 필요)
- **판정과 성능 기준**: 차단 정확도(오탐과 미탐), 재생성 한도, 검사 지연. 정량은 구현 확정
- **적용**: 입력(Step 2)과 출력(Step 3, Step 5) 검사. 공용 기능 'AI 가드레일' 호출, 적용 3지점 준용 ([[시범콘텐츠 공통 사양#나. 가드레일 적용 3지점]])
- **실패, 한계, 복구**: Step별 동작: 입력(Step 2) 부적절 도안 차단 후 재입력, 출력(Step 3) 변환물 위반 시 재생성(한도 초과 시 fallback), 출력(Step 5) 영상 위반 시 사진만 제공, 전부 위반 시 에러. 재시도와 재생성 한도는 운영 파라미터(구현 확정)
- **데이터와 평가**: 부적절 도안과 전통 왜곡 판정 기준 데이터 (작성 예정)

## 다. 하드웨어 (키오스크)

- **디스플레이**: 9:16 세로형 터치 스크린. 크기와 해상도 확인 필요
- **카메라**: 얼굴 추적 AR과 포즈 추정용. 해상도와 프레임률 확인 필요
- **음향 출력**: 풍물 장단과 환호 사운드 재생. 스피커 사양 확인 필요
- **마이크**: 음성 입력 사용 시 (미사용이면 생략 가능, 확인 필요)
- **연산 유닛**: 키오스크 본체 연산. 온디바이스 추론(포즈 추정 등) 채택 시 GPU 사양 확인 필요
- **네트워크**: AI 서버 통신, 사진과 영상 전송. 대역폭 확인 필요

## 라. 백엔드

서버 구성 요소를 책임별로 정리. 각 요소는 역할, 구현 요건, 참조로 기술.

### 1) API (키오스크 ↔ AI 서버)

- **역할**: 키오스크와 AI 서버 간 요청과 응답 중계. 카메라 자산, 생성물, 전송 상태가 오가는 신뢰 경계
- **요건**: 요청과 응답 규격, 프로토콜(확인 필요), 인증 방식(기기 자격/토큰 또는 mTLS 등 확인 필요), 전송 보안(TLS), 개인정보 로깅 제외

### 2) 세션 관리

- **역할**: 세션 라이프사이클과 상태 저장
- **요건**: 기본 키오스크당 1세션 가정 (동시 세션 수 확인 필요)
- **참조**: 2장 가. 세션

### 3) 진행 제어 (상태 머신)

- **역할**: Step 순차 진행 + 각 Step 분기와 에러 분기 제어
- **주요 상태**: 동의 대기와 거부, 영상 동의 off, 변환 실패, 전송 거부, 타임아웃, fallback, 정리와 파기, 리셋
- **참조**: 분기 상세는 2장 다. Step별 명세의 각 Step 분기와 실패 sub-step

### 4) 결과물 조립과 저장소

- **역할**: 3D 모델, 기념 사진, 리플레이 영상을 임시 저장하고 보관과 파기 정책 집행
- **참조**: 2장 가. 세션

### 5) 리플레이 영상 합성과 인코딩

- **역할**: AR 탈 합성, 하이라이트, 음원
- **참조**: 상세는 5장 아. 리플레이 영상 파이프라인

### 6) 개인정보 처리 집행

- **역할**: 연락처, 영상, 사진을 임시 저장하고 즉시 파기
- **참조**: 5장 가. 개인정보 처리 정책

## 마. 외부 서비스 연동

- **사진 전송 서비스**: SMS 또는 이메일 (채널 확인 필요). 전송 방식은 (1) 직접 첨부(이미지) 또는 (2) 호스팅 링크 중 택일 확인 필요. 링크 방식이면 저장 제공자, URL 만료, 전송 후 파기 트리거 명세 필요 (세션 표 사진 임시 보관 정책과 정합). 제공자와 연동 방식 확인 필요
- **리플레이 영상 다운로드 호스팅**: 현장 QR과 signed one-time URL 제공, 임시 저장 후 만료와 파기 (5장 아). 제공자와 스토리지 확인 필요
- **AI API (외부 모델 사용 시)**: 3D 변환, 포즈 추정, 가드레일 등 외부 호출 (5장 나). 호출 래퍼와 재시도는 공용 기능 준용. 제공자와 요금 확인 필요

## 바. 클라이언트 UI (키오스크 앱)

- **UI 기반과 스택**: 키오스크 앱 프레임워크, 페이지 전환과 터치 인터랙션 (기술 스택 확인 필요)
- **공통 UI 컴포넌트** (여러 화면 재사용): 말뚝이 진행 호스트 렌더러(3장 가. 진행 호스트), AR 렌더러(3D 탈 오버레이), 탈 디자인 도구(3장 다. 탈 디자인), 카메라 프리뷰와 촬영, 신명 게이지, 다운로드 QR
- **입력**: 터치, 카메라(얼굴과 포즈), 마이크(필요 시)
- **화면 구성**: 2장 다. Step별 명세의 각 Step 화면 항목 참조 (여기서 재나열 안 함)
- **세션 종료와 리셋**: 자동 타임아웃, 다음 유저용 시작 화면 복귀 (Step 7)

## 사. 운영과 모니터링

- **가동 모니터링**: 키오스크 온라인/오프라인, 장애 상태
- **사용 로그와 지표**: 유저 수, 완주율, Step별 이탈, 오류율 (완주율과 오류율 산출 입력)
- **알림**: AI 호출, 외부 서비스, 파기 실패 시 운영 알림 (임계 확인 필요)
- **에러 fallback**: [[시범콘텐츠 공통 사양#바. 운영/모니터링]] 처리 규칙 준용

## 아. 리플레이 영상 파이프라인 (구현 요건)

숏폼 리플레이 영상의 소재 확보부터 제공과 파기까지 구현 요건. 클라이언트(녹화와 QR), 백엔드(합성과 인코딩), 외부 서비스(다운로드 호스팅)에 걸침. 정량값(해상도, 길이, 코덱, 유효기간)은 구현 단계 확정, 임의 추정 금지.

1. **소재 녹화 (Step 4)**: AR 탈 합성 화면(탈 오버레이된 카메라 화면)을 클라이언트에서 프레임 캡처해 임시 녹화. 사후 재합성 부담을 피하려 렌더된 화면을 그대로 확보. 메모리와 임시 버퍼 보관 (디스크 영속화 금지)
2. **하이라이트 선별**: 동작 채점 기록(자세 점수와 신명 게이지)으로 고득점 구간 자동 선별. 선별 기준과 구간 길이는 운영 파라미터
3. **합성과 편집 (Step 5)**: 선별 하이라이트와 기념 포즈를 이어 붙이고, 세로형(9:16) 프레임, 워터마크, 스탬프를 오버레이. 무저작권/자체 제작/AI 생성 음원 믹싱
4. **인코딩**: 세로형 MP4로 인코딩, SNS 업로드 호환 우선. 해상도, 비트레이트, 코덱, 길이는 구현 단계 확정. 키오스크 부하를 고려해 서버 측 인코딩 권장
5. **제공과 다운로드**: 인코딩 완료물을 서버 임시 저장소에 단일 다운로드용으로 보관 → signed one-time URL(QR/단축 링크) 생성 → 사용자 다운로드. 파기는 단일 권위 트리거로 일원화 = 다운로드 성공 또는 유효기간 만료 중 먼저 오는 시점(미다운로드 시 세션 종료 시 파기). 중복 요청은 만료 전까지 같은 URL 재사용, 파기 실패 시 운영 알림
6. **가드레일**: 최종 영상에 출력 가드레일 검사 (부적절과 전통 왜곡, 3장 마. 가드레일)
7. **대기와 실패 처리**: 인코딩 동안 대기 화면(폴링 동기화). 실패 시 fallback으로 영상 생략하고 사진만 제공 (에러/fallback 공용 기능)
