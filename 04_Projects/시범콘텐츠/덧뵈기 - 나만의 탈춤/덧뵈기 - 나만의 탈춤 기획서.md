# 1. 개요

- **콘텐츠 정의**: 덧뵈기를 소재로 한 가면극 배역 체험 키오스크 콘텐츠. 유저가 마당 하나를 골라 그 마당의 배역이 되어, 광대 수업과 장면 수행으로 가면극을 몸으로 익힘
- **소재**: 남사당놀이 가면극 덧뵈기
- **목표 경험**: 유저가 광대 수련생으로 들어와 배역의 몸짓을 배우고(기초 수업), 상대 배역과 장면을 주고받고(장면 실습), 절정 대목을 완수해(절정 무대) 스승에게 배역 인정을 받음
- **핵심 메커닉**: 말은 시스템이, 몸은 유저가 맡음
	- 스승과 상대 배역의 재담이 동작 신호를 던지고, 유저가 배역 동작으로 응답함
	- 판정 결과는 스승의 피드백과 상대 배역의 반응 연출로 되돌아오고, 최상위 판정(얼쑤)에는 군중 추임새 반응이 더해짐
- **결과 안내**: 체험이 끝나면 결과 화면에서 배역 인정을 안내하고 베스트샷을 제공함

# 2. 전체 플로우

- **중단 처리**
	- 대상: 진행 중 이탈과 실패가 모두 이 공통 처리로 모임
	- 처리: 결과 화면을 건너뛰고, 세션을 종료해 임시 데이터를 파기한 뒤 시작 화면으로 돌아감. 실패는 상황 안내 팝업을 띄운 뒤 진행하고, 이탈은 팝업 없이 진행함
- **파기**
	- 정상 종료 시 남은 세션 임시 데이터(장면 수행 기록의 식별 원본)를 파기함
	- 영상 피드는 처리 직후 실시간 파기라 종료 시점에는 남지 않음

# 3. 공용 시스템

## 3.1 세션 데이터

### 3.1.1 역할과 목적

한 세션이 만드는 데이터를 담는 시스템. 전 Step이 같은 상태를 공유하게 하고, 데이터 종류별 보관과 파기를 관리하기 쉽게 함.

### 3.1.2 동작과 규칙

| 데이터       | 분류     | 들어가는 값과 구성                                               | 보관 기간                        | 비고                            |
| --------- | ------ | -------------------------------------------------------- | ---------------------------- | ----------------------------- |
| 세션 ID     | 시스템    | 세션마다 부여되는 고유 식별자                                         | 보관 (잠정, 규정 검토 후 확정)          | Step 1에서 생성. 디버깅과 품질 분석용      |
| 현재 언어     | 시스템    | 세션에 적용 중인 언어(기본 한국어)                                     | 보관 (잠정, 규정 검토 후 확정)          | 시작 화면 언어 선택에서 설정. 현지화 기준      |
| 현재 Step   | 시스템    | 현재 진행 중인 Step                                            | 보관 (잠정, 규정 검토 후 확정)          | 진행 단계 기록                      |
| 에러 유형     | 시스템    | 에러 발생 시 에러 케이스 유형 기록                                     | 보관 (잠정, 규정 검토 후 확정)          | 디버깅과 품질 분석용                   |
| 동의 기록     | 시스템    | 약관 버전, 동의 시각, 동의 항목(필수: 카메라 촬영)                          | 보관 (잠정, 규정 검토 후 확정)          | 약관 버전 체계는 운영 단계에서 결정함         |
| 선택 마당과 배역 | 콘텐츠 입력 | 유저가 고른 마당과 배역의 식별자(그 마당의 대본, 시범 클립, 포즈 일러스트, 판정 자산을 가리킴) | 보관 (잠정, 규정 검토 후 확정)          | Step 2 산출. 식별자만 저장(자산은 사전 배포) |
| 장면 수행 기록  | 콘텐츠 생성 | 신호별 판정(성공 여부, 자세와 타이밍 값), 장별 완수, 신명 지표(동작 성공과 얼쑤 누계)     | 익명 통계는 보관, 식별 원본은 세션 종료 시 파기 | Step 3 산출                     |
| 영상 피드     | 콘텐츠 입력 | 카메라 원본 스트림(포즈 추정 입력)                                     | 메모리 임시, 처리 직후 파기             | 디스크 저장 금지. 얼굴과 신체 포함          |

- **Step별 세션 동작**
	- Step 1: 생성
	- Step 2~Step 4: 갱신
	- Step 5: 종료, 임시 데이터 파기, 리셋
- **서버 전송 시점 (이벤트 기반)**: 세션 데이터 갱신은 클라이언트 로컬 상태에만 반영하고, 서버로는 정기 전체 동기화 없이 이벤트 시점에만 전송함(이어하기 없는 1차연도 기준)
	- 단계 이동: 각 Step 진입과 종료 시 현재 Step을 전송함
	- 동의 기록: 이용 동의 화면에서 동의 확정 시 동의 이벤트를 전송함. 클라이언트는 서버의 저장 확인 응답을 받은 뒤에만 다음 단계로 진행함(동의 기록 유실 방지)
	- 에러와 이탈: 에러 발생 시, 이탈(약관 미동의, 미입력 타임아웃 종료) 시 전송함
	- 마당과 배역 확정: 선택 마당과 배역 식별자는 Step 2 확정 시 서버 세션에 반영함

## 3.2 개인정보 처리

### 3.2.1 역할과 목적

카메라로 찍는 유저 얼굴과 신체 데이터의 처리 규칙을 정의하는 시스템. 쓰임이 끝난 데이터를 즉시 파기해 유출 위험을 줄임.

### 3.2.2 동작과 규칙

#### 1) 구현 제약

- **개인정보 범위**
	- 얼굴과 신체 영상
- **카메라 동의 게이트**
	- 카메라 촬영이 필수 동의이므로 동의가 없으면 세션을 진행하지 않음
- **영상 피드 처리**
	- 메모리에서 임시로 처리한 뒤 즉시 파기하고, 디스크에 저장하거나 로그로 기록하지 않음.

#### 2) 규정 검토 대기

- **동의 고지 문구**
	- 카메라 영상은 동작 판정 처리에만 쓰고 저장하지 않는다는 내용을 개인정보 수집과 이용 안내에 포함함. 정확한 안내 문구와 동의 범위는 규정 검토 후 확정함
- **보관 기간**
	- 잠정값은 규정 검토 후 확정함
- **재방문 연속성**
	- 학습 프로필, 이어하기, 학습 토큰, 콘텐츠 진행 결과 누적은 2차연도 확장 설계로 두며 1차연도는 익명 1회로 운영함

## 3.3 언어 선택 시스템

### 3.3.1 역할과 목적

세션 전체에 적용할 언어를 정하는 관문. 한국어가 아닌 언어를 쓰는 유저도 자기 언어로 가면극을 체험하게 함.

### 3.3.2 입력과 출력

- **입력**: 유저의 언어 선택
- **출력**: 현재 언어(세션 데이터에 저장). 현지화 JSON(localization.json)에서 해당 언어값을 불러옴

### 3.3.3 동작과 규칙

- 유저가 언어를 선택하고 시작하기 버튼을 터치하면 현재 언어로 반영함. 기본값은 한국어임
- **현지화 범위**: UI 카피, 장쇠와 상대 배역과 유저 배역의 대사 자막, 배역 인정 문구, 안내 팝업을 현재 언어로 제공함. 지원 언어는 한국어와 영어를 우선 적용함
- **재담 현지화 유의**: 말장난과 고어가 섞인 재담은 직역이 아니라 뜻과 웃음 구조를 살린 의역으로 현지화함(문안 작성과 함께 확정, 작성 예정)

## 3.4 장쇠 스승 호스트

### 3.4.1 역할과 목적

덧뵈기의 장쇠(장구 담당)를 진행 호스트로 세워 장단을 이끌며 수업과 체험을 매끄럽게 안내함

### 3.4.2 동작과 규칙

- **페르소나**
	- 능청스러운 남사당놀이패 고참
- **마당별 자리와 발화 분량**
	- 세 마당 공통으로 장쇠는 판 밖에서 수업과 중계를 맡음
	- 1장에서는 동작 신호와 교정 피드백까지 맡고, 2장과 3장에서는 장을 열고 맺는 진행 멘트와 상대 배역 반응 중계를 맡음
- **수업과 교정 피드백**
	- 기초 수업에서 동작 신호를 던지고, 기준에 미달한 응답에는 교정 피드백을 되돌려줌
	- 교정 문구는 판정 요소와 1:1로 짬: 진폭 미달이면 "더 크게!", 홀드 미달이면 "끝을 딱 맺어야지!", 타이밍 이탈이면 "장단에 맞춰!"
- **캐릭터 표현**
	- 장쇠가 발화하는 동안 캐릭터 표현을 함께 재생함
	- 상시 표현은 2D 일러스트에 코드 트윈(숨쉬기, 발화 흔들림, 입 여닫기)을 얹어 구동함. 립싱크는 맞추지 않고 발화하는 동안 입 여닫기를 반복함
	- 등장, 인정 선언, 환호 등 핵심 순간만 사전 제작 클립을 재생함
- **스킵**
	- 발화 중 다음 버튼을 누르면 발화를 중단하고 다음으로 진행함
- **타임아웃**
	- 발화 중에는 터치 미입력 타임아웃을 멈추고, 발화가 끝난 뒤 시간 체크 시작
- **대사 적용**
	- 장쇠의 대사는 런타임 생성 없이 사전 작성함. 진행 안내, 마당별 수업과 장면 신호, 교정 피드백, 상대 배역 반응 중계, 인정 재담을 미리 써 두고 상황에 맞춰 재생함

### 3.4.3 실패와 복구

캐릭터 렌더나 TTS 재생이 실패하면 음성과 캐릭터 표현 없이 대표 이미지와 텍스트 박스로만 진행함. 대사는 표시하고 세션은 계속함.

## 3.5 화자와 보이스

### 3.5.1 역할과 목적

세션에 나오는 화자를 정하고 화자마다 보이스와 화자 표기를 배정함. 유저가 누구의 말인지 바로 가르게 함.

### 3.5.2 동작과 규칙

| 화자                  | 보이스                 | 맡는 말                                                         |
| ------------------- | ------------------- | ------------------------------------------------------------ |
| 장쇠                  | 공용 보이스              | 진행 안내, 수업과 장면 신호, 교정 피드백, 상대 배역 반응 중계(포즈로 못 싣는 반응 서사), 인정 재담 |
| 유저 배역(꺽쇠, 말뚝이, 취발이) | 공용 보이스<br>(필요 시 분리) | 장면에서 유저 배역이 하는 대사                                            |
| 상대 배역(옴탈, 샌님, 먹중)   | 배역별 전용 보이스 3종       | 장면의 대거리 대사                                                   |

- **발화 방식**
	- 음성 합성(TTS)으로 대사를 재생하고 같은 대사를 화면 텍스트로 표시함
- **유저 배역 대사**
	- 유저가 직접 소리 내어 말하지 않음
	- 사전 작성 대본이 유저 배역 자리에 표시되고 음성으로 재생되며, 유저는 대사가 아니라 몸동작을 맡음
- **화자를 가르는 수단**
	- 화면 텍스트에 화자를 함께 표기하고, 장면에서는 말풍선 자리로도 가름
- **대사 원천**
	- 모든 대사는 런타임 생성 없이 사전 작성함
	- 유저 배역과 상대 배역의 대사는 원전 연회본 발췌를 쓰고, 장쇠의 진행 대사는 따로 작성함
	- 원전에서 악사(잽이)가 판에 거는 말은 장쇠가 맡음. 먹중은 원전에 대사가 없는 무언 배역이라 먹중잡이의 대거리 대사도 장쇠가 맡음

### 3.5.3 실패와 복구

TTS 재생이 실패하면 음성만 빠진 채로 화면 텍스트 대사를 이어 가고 세션을 계속함.

## 3.6 진행 중 종료

### 3.6.1 역할과 목적

유저에게 진행 중 그만둘 수단을 주는 시스템. 원치 않는 세션을 빨리 끝내 키오스크 회전율을 높임.

### 3.6.2 동작과 규칙

#### 1) 일반 규칙

- **처리**
	- 진행 중인 화면을 멈추고 배역 인정 화면(완주 전용)을 건너뛰어 세션 종료와 파기 후 시작 화면으로 복귀함(비완주 종료)

#### 2) 유저의 종료 선택 시 규칙

- **처리**
	- 그만두기 터치 시 그만두기 확인 팝업 표시
	- 확인 시 종료 처리하고, 취소 시 원래 화면 복귀
	  ![|500](../../../assets/시범콘텐츠/공통/팝업_그만두기.png)

- **적용 화면**
	- Step 1 가이드 화면, 이용 동의 화면
	- Step 2 마당 선택 화면, 배역 확인 화면
	- Step 3 기초 수업, 장면 실습, 절정 무대 화면
- **예외 (미적용)**
	- Step 1 시작 화면
	- Step 4 배역 인정 화면 (완주 마침 화면, 처음으로 버튼과 화면 타임아웃으로 넘김)
- **그만두기와 동시 이벤트 처리 (카메라 화면)**: Step 3에서 그만두기가 판정이나 타임아웃과 겹칠 때의 규칙임
	- 확정된 그만두기는 진행 중인 동작 신호와 판정 루프를 멈추고 세션 종료로 감
	- 확인 팝업이 열린 동안에는 터치 미입력 타임아웃과 사람이나 포즈 미검출 측정을 멈춤(장쇠 발화 중 멈춤과 같은 방식)
	- 종료는 한 번만 처리해 이중 종료를 막음

## 3.7 화면 타임아웃

### 3.7.1 역할과 목적

유저가 한 화면에 오래 머무는 것을 막아, 무인 키오스크가 한 유저에게 묶이지 않게 하는 시스템.

### 3.7.2 동작과 규칙

- **처리**
	- 한 화면에서 60초(잠정) 이상 머물면 그 화면의 정상 진행 경로로 넘어감
	- 화면별 오버라이드: Step 3 세 화면 합산 5분(잠정). 마당 선택, 배역 확인, 배역 인정 화면은 기본값(60초, 잠정) 적용
	- 장쇠 발화 중에는 측정을 멈추고, 발화가 끝나거나 스킵한 뒤 재개함(잠정)
	  ![|500](../../../assets/시범콘텐츠/공통/타임아웃_화면.png)

- **작업 상태**
	- 유저 선택 상태가 있으면 세션에 확정 저장한 뒤 진행함(선택 마당, 기본 마당이 사전 선택돼 있어 항상 값이 있음). 없으면 바로 다음으로 진행함
- **예외**
	- 필수 입력, 가이드, 팝업 화면 미적용

## 3.8 터치 미입력 타임아웃

### 3.8.1 역할과 목적

입력이 끊긴 유저 이탈을 감지해 방치된 세션을 정리하고 키오스크 회전율을 높이는 시스템.

### 3.8.2 동작과 규칙

- **처리**
	- 한 화면에서 45초(잠정) 이상 터치나 동작 입력이 없으면 이탈로 보고 진행 중 종료 처리
	- 카메라와 모션 화면(Step 3 세 화면)은 터치가 없는 화면이라 사람이나 포즈 미검출을 이탈 기준으로 삼음
	- 장쇠 발화 중에는 측정을 멈추고, 발화가 끝나거나 스킵한 뒤부터 측정 시작
	  ![|500](../../../assets/시범콘텐츠/공통/타임아웃_미입력.png)

- **예외**
	- 감상 성격 화면(배역 인정 화면) 미적용

## 3.9 외부 서비스 호출 래퍼

### 3.9.1 역할과 목적

외부 서비스 호출(TTS)을 감싸는 공통 계층. 재시도와 타임아웃 대응을 한 곳에 모아, 호출마다 장애 처리를 따로 짜지 않게 함.

### 3.9.2 동작과 규칙

- **재시도 횟수**
	- 2회(잠정). 백오프는 1차 1초, 2차 3초(잠정)
- **호출 타임아웃**
	- TTS 30초(잠정)
- **한도 초과**
	- 재시도 한도를 넘긴 실패는 실패 처리로 넘김

## 3.10 실패 처리

### 3.10.1 역할과 목적

런타임 실패의 처리 정책. 무인 운영에서 실패가 방치되지 않게 함.

### 3.10.2 동작과 규칙

이 콘텐츠의 실패는 기능 축소와 중단 둘로 갈림. 유저가 입력하는 텍스트나 음성이 없어, 입력만 다시 받아 잇거나 다른 입력 수단으로 바꿔 잇는 갈래는 없음.

#### 1) 기능 축소

- 보조 기능이 빠져도 체험이 남는 갈래임. 그 기능만 빼고 세션을 이어 감
- 포즈 미검출 구간(판정 보류로 처리), 장쇠 발화 실패(대표 이미지와 텍스트로 진행), 상대 배역 반응 표시 실패(대표 포즈 정지 표시와 효과음으로 대체)가 여기 속함

#### 2) 중단

- 세션을 시작하거나 핵심 체험을 이어 갈 수 없는 실패 갈래임(세션 생성 실패, 마당 리소스 로드 실패, 카메라와 인식 계통의 지속 장애)
- 상황 안내 팝업을 띄우고 배역 인정 화면(완주 전용)을 건너뛰어 세션 종료와 파기 후 시작 화면으로 자동 진행함. 별도 실패 화면을 두지 않음
	- 예외: 세션 생성 실패는 정리할 세션 자체가 없어 종료 처리도 거치지 않고 곧장 시작 화면으로 되돌림

#### 3) 운영 알림

- 원인이 외부 서비스나 시스템이면 운영 알림을 보내고, 유저면 보내지 않음

## 3.11 탈과 마당 대목 고증 (공통 레퍼런스)

### 3.11.1 역할과 목적

배역 탈, 마당 대목, 배역 동작의 고증 기준을 정의하는 설계 레퍼런스. 마당 선택 목록, 장면 대본, 동작 판정, 사전 자산 검수가 같은 기준을 참조해 전통 정합성 판정이 서로 어긋나지 않게 함.

### 3.11.2 동작과 규칙

#### 1) 마당과 배역

- **마당 구성**: 덧뵈기 네 마당(마당씻이, 옴탈잡이, 샌님잡이, 먹중잡이) 중 체험 마당은 옴탈잡이, 샌님잡이, 먹중잡이 3종임
- **유저 배역 (마당당 1종)**: 옴탈잡이는 꺽쇠, 샌님잡이는 말뚝이, 먹중잡이는 취발이. 마당마다 배역은 하나이며 유저가 배역을 고르지 않음
- **상대 배역**: 옴탈잡이는 옴탈(옴중), 샌님잡이는 샌님, 먹중잡이는 먹중

#### 2) 탈

- 덧뵈기 배역 탈을 사전 제작해 제공함
	- 전체 10종: 샌님, 노친네, 취발이, 말뚝이, 먹중, 옴중, 피조리 甲, 피조리 乙, 꺽쇠, 장쇠
	- 그중 등장분: 유저 배역 3종(꺽쇠, 말뚝이, 취발이), 상대 배역 3종(옴중, 샌님, 먹중), 호스트 장쇠

#### 3) 마당 대목과 동작 세트

- **대본 원천**
	- 선택한 마당의 연회본을 앞대목(2장)과 뒷대목(3장)으로 나눠 순서대로 진행함
	- 대사는 원문 그대로 쓰고 한 호흡에 안 들어가는 긴 사설만 문장 경계에서 줄임
- **빼는 대목**
	- 공공 전시에 부적절하거나 유저가 할 일이 없는 대목만 뺌
	- 먹중잡이 끝의 피조리 품평은 넣지 않고, 샌님잡이 도입은 판정 없는 대사 3개로 압축함
- **동작 세트 (마당당 3개, 잠정)**: 1965년 기록영상 판독에서 확인된 사위와 원전 지시문을 조합하되 명칭과 구성은 고증 자문으로 확정함
	- 옴탈잡이(꺽쇠): 살피기(상체 기울임), 찔러보기(팔 뻗기), 휘둘러 쫓기(팔 휘두르기)
	- 샌님잡이(말뚝이): 채찍 휘두르기(팔 휘두르기), 거드름 흉내(상체 젖히기), 호령 가리키기(팔 뻗기)
	- 먹중잡이(취발이): 어깨 메기(소매 얹기), 한발 차올리기(다리 들기), 소매 뿌리기(팔 휘두르기)

#### 4) 각색 원칙 (전 마당, 고증 자문 연계)

- 옴탈잡이: 옴(피부병) 조롱 개그의 톤을 낮춤(간지럼 소동 방향). 탈 도상 해설은 사실 서술로 함
- 샌님잡이: 째보 탈 도상 해설을 신분 풍자의 기호로 맥락화함. 외모 놀리기 재담과 절 말장난 고어는 현대어 풀이를 병행함
- 먹중잡이: 피조리 관련 성적 재담을 제거하고, 대결 명분을 먹중의 행패 응징으로 단순화함. 파계승 풍자임을 분명히 함
- 전 마당 공통: 고어는 현대어 풀이 병행, 욕설과 육담은 순화함

#### 5) 시각 정체성

- 탈 양식과 질감의 전통 정합성 유지
- 사전 제작 자산(장쇠 캐릭터, 상대 배역 포즈 일러스트)은 운영 전 고증 검수를 거침

## 4.2 Step 2. 마당 선택

### 4.2.1 클라이언트: 마당 선택 화면

#### 1) 진행

- 체험 마당 3종(옴탈잡이, 샌님잡이, 먹중잡이)의 카드를 보여줌. 유저가 마당을 고르거나 기본 선택을 그대로 두고 확정하면 배역 확인 화면으로 진행함
	- 분기: 미입력 타임아웃 → 종료 처리
	- 분기: 화면 타임아웃(기본 60초, 잠정) → 현재 선택 마당을 확정하고 다음으로 정상 진행 
	- 분기: 그만두기 선택 시 확인 팝업 → 확정 시 종료 처리

#### 2) 마당 선택 목록

##### (1) 역할과 목적

유저가 체험할 마당 하나를 고르는 선택 도구. 마당마다 재미 유형이 달라(잡기, 놀리기, 이기기) 고르는 것 자체가 극 구조 학습의 시작이 되게 함.

##### (2) 동작과 규칙

- **목록 구성**: 마당 카드 3종. 카드마다 마당 이름, 한 줄 소개, 유저 배역과 상대 배역을 표기함
	- 옴탈잡이: 슬금슬금 나타난 옴탈을 꺽쇠가 되어 잡아 쫓는 마당
	- 샌님잡이: 거드름 피우는 샌님을 말뚝이가 되어 놀려 뒤집는 마당
	- 먹중잡이: 행패 부리는 먹중을 취발이가 되어 춤으로 눌러 이기는 마당
- **기본 선택**: 진입 시 목록 첫 번째 마당을 기본 선택으로 둠
- **미리보기**: 선택한 마당의 절정 장면을 상대 배역 일러스트와 한 줄 소개로 보여줌

### 4.2.2 클라이언트: 배역 확인 화면 (배역 입문)

#### 1) 진행

- 선택 마당의 배역을 표시하고, 장쇠가 그 배역의 탈 도상을 재담으로 해설함(왜 이런 얼굴인가). 탈 쓰기 버튼 터치 시 탈 쓰기 연출과 함께 배역을 확정하고 다음 단계로 진행함
	- 분기: 화면 타임아웃(기본 60초, 잠정) → 배역을 확정하고 다음으로 정상 진행
	- 분기: 미입력 타임아웃 → 종료 처리
	- 분기: 그만두기 선택 시 확인 팝업 → 확정 시 종료 처리

### 4.2.3 서버: 선택 마당과 배역 저장

#### 1) 진행

- 세션에 선택 마당과 배역 식별자를 저장함.

## 4.3 Step 3. 마당 장면 체험 (핵심 체험)

한 마당을 3장으로 진행함: 기초 수업(배역 동작 익히기) → 장면 실습(상대 배역과 동작 신호 주고받기) → 절정 무대(절정 대목 완수)

### 4.3.1 클라이언트: 기초 수업 화면 (1장)

#### 1) 진행

1. 장쇠가 수업을 열고 선택 마당의 동작 세트 3개를 하나씩 가르침
2. 동작마다 시범 클립 재생 → 유저 수행 → 판정 → 장쇠 피드백의 루프를 돎
	- 성공 시 다음 동작으로 진행하고, 미수행 시 교정 피드백과 함께 재시도함(동작당 2회 잠정). 재시도를 소진하면 장쇠가 눙치고 통과 처리해 진행을 막지 않음
3. 동작 3개를 마치면 장쇠가 수업을 맺고 장면 실습으로 진행함
	- 분기: 그만두기 선택 시 확인 팝업 → 확정 시 종료 처리
	- 분기: 사람이나 포즈 미검출이 터치 미입력 타임아웃 임계를 넘기면 이탈로 보고 종료 처리

#### 2) 마당별 수업 내용

동작 세트의 고증 근거와 각색 원칙은 탈과 마당 대목 고증 절이 소유함. 판정 특징은 동작 판정 엔진의 판정 요소 조합임.

| 마당 | 동작 1 | 동작 2 | 동작 3 |
|---|---|---|---|
| 옴탈잡이 (꺽쇠) | 살피기 (상체 기울임 + 홀드) | 찔러보기 (팔 뻗기 진폭) | 휘둘러 쫓기 (팔 휘두르기 진폭 + 속도) |
| 샌님잡이 (말뚝이) | 거드름 흉내 (상체 젖히기 + 홀드) | 호령 가리키기 (팔 뻗기 + 홀드) | 채찍 휘두르기 (팔 휘두르기 진폭 + 속도) |
| 먹중잡이 (취발이) | 어깨 메기 (팔 얹기 + 홀드) | 한발 차올리기 (발목 높이 진폭) | 소매 뿌리기 (팔 휘두르기 진폭 + 속도) |

#### 3) 동작 판정과 신명 지표

##### (1) 역할과 목적

동작 신호에 대한 유저의 몸 응답을 판정해 즉각 피드백으로 되돌리는 핵심 엔진. 세 장이 같은 판정 규칙을 공유해, 배운 동작이 그대로 장면의 응답과 대결의 무기가 되게 함.

##### (2) 입력과 출력

- **입력**
	- 카메라 영상 프레임, 동작 신호 이벤트(기대 동작 식별자와 판정 구간. 각 장의 진행에서 수신)
- **출력**:
	- 신호별 판정 결과 (장쇠 피드백, 상대 배역 반응 연출, 절정 게이지 세 곳에 전달함)
	- 추임새 반응 트리거 (얼쑤 판정 시 발동. 규칙은 신명 지표와 추임새 반응 절 소유)
	- 장면 수행 기록 (신명 지표 포함. 세션 데이터에 저장하며 배역 인정 화면의 수행 요약과 신명의 서사 번역에 입력됨)

##### (3) 판정 기본 규칙

- **지정 동작 판정 원칙**
	- 판정은 항상 기대 동작 1개가 특정된 동작 신호에만 걸림. 자유 표현이나 행동의 의미적 적절성은 판정하지 않음
	- 기대 동작이 아닌 모든 움직임은 미수행 하나로 수렴해, 행동의 의미를 오독하는 판정을 구조적으로 없앰
- **판정 요소**
	- 판정 요소는 자세(기대 동작 스켈레톤과의 유사도), 진폭(관절 이동 크기), 홀드(자세 유지 시간), 타이밍(판정 구간 안 수행 여부)의 조합임
	- 동작마다 쓰는 요소가 다름(마당별 수업 내용 표의 판정 특징)
- **판정 구간**
	- 수업과 실습: 동작 신호 발화가 끝난 뒤의 응답 대기를 판정 구간으로 삼음
	- 대기 산출: 앞선 대사 길이에 비례함(기본 1.4초 + 글자수 × 0.02초, 최대 3.2초). 고정 4초로 두면 "꾸부려라" 같은 한 마디 지시 뒤에도 똑같이 기다려 판이 늘어짐
	- 절정 무대: 같은 응답 대기를 쓰되, 옴탈잡이는 대목이 넘어갈 때마다 0.94배(잠정)씩 좁혀 장단 가속을 표현함(하한은 기본 대기)
	- 확정 시점: 실기기 인식 성능을 보고 개발 단계에서 정함
- **판정 피드백 (3단, 잠정)**
	- 얼쑤(성공, 진폭 상위), 좋다(성공), 다시(미수행)로 가름
	- 영문 등급 표기는 쓰지 않고 스승과 판의 말로 표현함
	- 미수행 표기 "다시"는 재시도가 있는 기초 수업에서만 노출하고, 실습과 절정에서는 미수행 피드백 없이 진행함(잠정)
- **관대 판정**
	- 동작의 잘잘못을 정밀히 가리지 않고 수행으로 인정하는 쪽으로 임계를 잡음
	- 무인 공공 체험에서는 실제로 한 동작을 안 했다고 놓치는 판정이, 어설픈 동작을 후하게 인정하는 판정보다 체험을 크게 해치기 때문임

##### (4) 자세 판정 산출

판정 구간의 프레임들을 아래 5단계로 처리해 동작 신호 1개의 자세 값과 타이밍 값을 냄. 단계 구성은 동작 유사도 판정에 통용되는 기법을 따름.

1. **포즈 추정**: 카메라 프레임에서 유저의 2D 키포인트(관절 좌표 + 신뢰도)를 실시간 추출함
2. **전처리**: 신뢰도 임계(잠정 0.3) 미만 키포인트는 그 프레임의 일치도 비교에서 제외하고, 프레임 간 좌표 떨림은 스무딩으로 완화함
	- 신뢰도 임계는 채택할 포즈 추정 모델의 권장 임계와 실측으로 개발 단계에서 확정함
3. **정규화**: 몸 중심(양 힙의 중점)을 원점으로 옮기고 몸통 길이로 나눠 크기를 맞춤. 유저의 키, 화면 내 위치, 카메라까지의 거리와 무관하게 레퍼런스 스켈레톤과 비교하게 하는 단계임
4. **부위별 유사도**: 부위 벡터(어깨→팔꿈치, 팔꿈치→손목, 힙→무릎 등)의 방향을 레퍼런스 스켈레톤의 같은 부위와 코사인 유사도로 비교하고, 부위별 가중 평균으로 프레임 일치도를 냄
	- 덧뵈기 동작 세트가 팔 중심이라 팔 부위 가중을 상향함(잠정)
	- 관절 각도 차 비교는 동급 대안으로 두고 개발 단계에서 인식 성능을 보고 확정함
5. **판정**: 판정 구간 안 프레임 일치도의 최댓값으로 수행 여부를 가름
	- 진폭과 홀드는 같은 구간의 키포인트 궤적에서 산출함(진폭은 관절 이동 크기, 홀드는 임계 이상 자세 유지 시간)
	- 얼쑤 경계값 등 임계는 정량 미정으로 개발 단계에서 확정함

##### (5) 신명 지표와 추임새 반응

- **신명 지표**: 동작 성공과 진폭 상위(얼쑤)를 세션 동안 누계함(가중 산식은 작성 예정). 동작의 잘잘못을 세밀히 매기는 채점이 아니라 판이 얼마나 달아올랐는가를 남기는 활동 지표임
	- 화면에 상시 게이지로 표시하지 않음: 잘한 순간의 즉각 보상은 판정 피드백과 반응 연출이 이미 맡고, 상시 게이지를 두면 절정 무대에서 화면에 게이지가 2개가 되어 혼동을 부르기 때문임
- **추임새 반응**: 얼쑤 판정 즉시 군중 추임새와 박수 사운드를 재생함. 신명풀이의 추임새(잘한 순간에 터지는 즉석 호응) 원리를 따름. 연속 얼쑤의 사운드 겹침 처리는 작성 예정
- **서사 번역 분기**: 배역 인정 화면이 신명 지표를 분기 임계(정량 미정, 개발 단계 확정)와 비교해 문구를 가름(문구 구성은 배역 인정 화면 소유)
- **학습 진척**: 1차연도는 세션 안 수행으로 끝남. 재방문 진척 누적(마당 수집 현황, 향상 피드백)은 2차연도 확장 설계로 둠

##### (6) 기술 요건

- **모델 확보**
	- 실시간 포즈 추정에는 사전학습 모델과 온디바이스 SDK(소프트웨어 개발 키트)를 우선 검토함(MoveNet, MediaPipe Pose 류 실시간 경량 2D 키포인트 모델이 후보, 확인 필요)
	- 판정 로직은 레퍼런스 동작과 대조하는 자체 규칙임
- **판정 기준**
	- 포즈 추정 정확도, 판정 임계와 가중치, 실시간 처리 지연(프레임률)을 봄
	- 판정 정확도 검증 방법은 확인 필요
- **적용**
	- 실시간 처리임. 온디바이스 처리를 우선 검토하고 서버 처리는 대안으로 둠
	- 라이브는 원거리에서 전신 포즈를 판정하는 단일 구도임
	- 모션 인식은 전신 싱글 카메라 기준 손목까지가 현실적이라 동작 세트를 이 범위로 설계함(손가락 세부 동작 없음)
- **데이터**
	- 동작 세트의 모션 레퍼런스가 판정 기준 데이터임. 보존회 실연 촬영으로 확보함(고증 자문 연계, 확인 필요)
	- 시범 클립과 판정 레퍼런스 스켈레톤을 같은 촬영본에서 파생해 기준과 시범의 원천을 일치시킴

##### (7) 필요 리소스

- 동작 세트 모션 레퍼런스(마당별 3개, 보존회 실연 촬영. 고증 자문 연계, 확보 방식 확인 필요)
- 동작별 판정 레퍼런스 스켈레톤(모션 레퍼런스에서 추출한 키포인트 시퀀스)
- 시범 클립(모션 레퍼런스 촬영본 편집, 좌우 반전 거울 방식)
- 군중 추임새와 박수 사운드(추임새 반응과 배역 인정 환호, 제작 방식 확인 필요)

##### (8) 실패와 복구

- 판정 구간 안에서 포즈가 인식되지 않거나 신뢰도가 낮을 경우 및 인식 지연 시 처리
	- 해당 신호에 대한 응답을 미수행으로 처리하고 진행함(기초 수업은 재시도 규칙을 적용하고, 실습과 절정은 다음 신호로 넘어감)
- 사람 미검출이나 포즈 미검출이 터치 미입력 타임아웃 임계를 넘길 시 처리
	- 미입력 타임아웃으로 간주하여 종료 처리
- 카메라 영상이 들어오지 않거나 모든 프레임 저신뢰가 지속될 시 처리(지속 임계는 잠정, 개발 단계 확정)
	- 유저 요인이 아니라 시스템 장애(카메라 고장이나 가림, 조명, 성능 저하)로 보고 상황 안내 팝업 후 중단 처리함. 운영 알림 대상임

### 4.3.2 클라이언트: 장면 실습 화면 (2장)

#### 1) 진행

1. 상대 배역이 등장하고(등장 포즈와 이펙트), 장쇠가 장면을 엶
2. 장면 대본의 신호 시퀀스를 진행함: 상대 배역이나 장쇠의 재담에 얹힌 동작 신호 → 유저의 몸 응답(동작 판정) → 상대 배역 반응 연출의 루프
	- 유저 배역의 대사 차례가 오면 유저 배역의 말풍선에 그 대사가 나오고, 유저는 몸으로 수행함
	- 미수행이어도 장면은 멈추지 않고 상대 배역의 중립 반응으로 진행함(재시도 없음)
3. 대본의 신호를 모두 마치면 장쇠가 장면을 맺고 절정 무대로 넘어감
	- 분기: 그만두기 선택 시 확인 팝업 → 확정 시 종료 처리
	- 분기: 사람이나 포즈 미검출이 터치 미입력 타임아웃 임계를 넘기면 이탈로 보고 종료 처리

#### 2) 마당별 앞대목 대본

앞대목은 선택한 마당의 연회본을 순서대로 진행함. 대사는 원문이고 각색 원칙은 탈과 마당 대목 고증 절이 소유함.

| 마당 | 원전 대목 | 진행 (상대 배역 원문 대사 → 유저의 기대 동작) |
|---|---|---|
| 옴탈잡이 | 424~444행 | 옴탈 등장 → "이놈이 뭣하는 놈인고"(살피기) → "남의 의관 절단난다"(찔러보기) → "내 네 얼굴 같으면 문지방도 안 넘것다"(휘둘러 쫓기) |
| 샌님잡이 | 470~544행 | 샌님과 노친네 도입 3대사(판정 없음) → "애, 뚝아, 말뚝아!"(채찍 휘두르기) → "양반을 만났으면 절을 하는 게 아니라"(거드름 흉내) → "너 절 모르느냐"(호령 가리키기) |
| 먹중잡이 | 630~656행 | 먹중 등장과 취발이 사설(판정 없음) → "여보게 안암산이 컴컴한 거 모르나"(어깨 메기) → "중이 속가에 내려와 농탕친다네"(소매 뿌리기) → "어디 한번 얼러 보게"(한발 차올리기) |

#### 3) 상대 배역 반응 연출

##### (1) 역할과 목적

상대 배역(옴탈, 샌님, 먹중)과 유저 배역을 판에 나란히 세워 포즈 일러스트와 이펙트로 연기하는 시스템. 유저 동작이 판정을 통과하는 순간 과장된 반응 포즈와 효과음, 장쇠의 중계 재담을 되돌려 슬랩스틱의 웃음을 보상으로 완성함.

##### (2) 입력과 출력

- **입력**: 신호별 판정 결과(동작 판정에서 수신), 장면 진행 상태(각 장의 진행에서 수신)
- **출력**: 상대 배역 포즈 전환과 이펙트 표시(화면 연출), 장쇠 중계 재담 재생 트리거

##### (3) 동작과 규칙

- **판 배치**
	- 상대 배역을 판 왼쪽에, 유저 배역을 오른쪽에 세워 마주 보게 함
	- 각 배역의 대사는 제 머리 위 말풍선에 표시하고, 장쇠는 판 밖 왼쪽 열에서 말함. 누가 말하는지를 자리로 가르는 배치임
- **유저 배역 표시**
	- 탈을 쓴 Step 3 진입 시점부터 판에 서 있음
	- 상대 배역과 같은 반응 규칙을 따르되, 1차연도는 배역당 포즈 1종에 코드 트윈만 얹음(전용 반응 포즈는 2차연도 확장 설계)
- **표시 우선순위**
	- 겹칠 때 배역 포즈가 가장 아래, 말풍선이 그 위, 판정 표시가 가장 위임
	- 말풍선은 배역 그림의 윗변 위에만 놓고 얼굴과 상체를 덮지 않음
	- 동작 안내 바(3장)는 판 밖 하단 띠라 판 안 요소와 겹치지 않음
- **화면 폭 한계 조건**
	- 2인 배치는 판이 넓어야 성립함. 배역 윗변까지의 세로 여유가 말풍선 두 줄에 못 미치면 말풍선이 배역을 덮음
	- 프로토타입 실측(가로형 16:9 기준): 폭 1920 화면은 여유 155px에 겹침 없음, 1600 화면은 108px에 겹침 없음, 1366 화면은 73px로 표시 대사의 38%가 배역을 덮었음
	- 실기기 해상도를 1920 이상으로 잡는 것을 전제로 함. 그보다 좁은 화면에 넣어야 하면 배역 그림을 줄이거나 말풍선을 판 아래로 내리는 배치 변경이 필요함(확인 필요)
- **한 번에 띄우는 글자수**
	- 말풍선이 배역을 덮지 않는 범위에서 정함. 한도는 고정값이 아니라 판 크기에서 산출함(1920 화면 실측 138자)
	- 한도를 넘는 대사는 원문을 고치지 않고 문장 경계에서 나눠 차례로 띄움
- **포즈 세트와 상태 머신**
	- 상대 배역마다 등장, 대기, 신호별 반응(성공용 과장 포즈, 미수행용 중립 포즈), 절정 결말(나가떨어진 자세 등)의 포즈 일러스트를 사전 제작함
	- 장면 진행 상태에 따라 전환함
- **이펙트 전환**
	- 포즈 사이 전환은 코드 트윈(이동, 반전, 흔들림, 튕김)과 효과음으로 연출함. 장쇠 캐릭터 표현과 같은 구동 방식임
- **장쇠 중계**
	- 포즈와 이펙트로 싣지 못하는 반응 서사("저놈 봐라, 뒷걸음질을 친다!" 류)는 장쇠가 중계 재담으로 발화함(신호별 성공과 미수행 2벌, 문안 작성 예정)
	- 판정 직후 장쇠 자리에 표시하고 유저 배역이 응수하는 동안 남겨, 다음 대목이 열릴 때 걷음
- **슬랩스틱 분담**: 넘어지기, 나가떨어지기 등 낙법 계열 연기는 상대 배역 전용임(결말 포즈와 튕김 이펙트로 표현)
- **제작 방식**: 2D 포즈 일러스트를 사전 제작하고 운영 전 검수를 거침(캐릭터 시트 고정으로 일관성 관리, 고증 검수는 탈과 마당 대목 고증 기준). 런타임 생성은 없음

##### (4) 기술 요건

- **표시**: 전부 클라이언트 로컬 처리임. 서버 왕복 없음
- **사전 로드**: 마당 확정(Step 2) 후 Step 3 진입 전에 해당 마당의 포즈 일러스트, 대본, 판정 자산, 음원을 미리 로드해 체험 중 로딩 끊김을 없앰
- **판정 기준**: 반응 표시 지연(판정 확정에서 포즈 전환까지, 정량 미정), 일러스트 일관성(캐릭터 시트 대비, 검수 기준 작성 예정)

##### (5) 필요 리소스

- 상대 배역 포즈 일러스트 세트 3종(옴탈, 샌님, 먹중. 배역당 포즈 4~6종 잠정: 등장, 대기, 과장 반응, 중립, 절정 결말에서 배역별로 가감. 코드 트윈용 분할 이미지, 사전 검수)
- 상대 배역 캐릭터 시트(탈과 의상 고정 레퍼런스, 고증 자문 연계)
- 반응 효과음(움찔, 도약, 튕김 등. 제작 방식 확인 필요)
- 유저 배역 포즈 일러스트 3종(꺽쇠, 말뚝이, 취발이. 1차연도는 배역당 1종, 코드 트윈용)
- 마당별 장면 대본(신호 문안, 유저 배역 대사 문안, 장쇠 중계 재담 문안. 작성 예정)

##### (6) 실패와 복구

- 포즈 전환이나 이펙트가 실패하면 해당 배역의 대표 포즈 정지 표시와 효과음으로 대체하고 장면을 계속함(기능 축소)
- 장쇠나 상대 배역의 음성 재생이 실패하면 음성 없이 화면 텍스트와 포즈로 장면을 계속함(기능 축소)
- 포즈 일러스트 로드 실패는 마당 리소스 로드 실패로 묶어 중단 처리함(재시도 2회 잠정)

### 4.3.3 클라이언트: 절정 무대 화면 (3장)

#### 1) 진행

1. 무대 격상 연출: 배역들이 뒤에 일렬로 서는 관망 정렬 배경(잠정)과 함께 장쇠가 절정을 선언하고 장단이 시작됨
2. 뒷대목 대본을 순서대로 진행함: 앞대목과 같은 턴제 루프이며, 배운 동작이 다음 응수 차례로 동작 안내 바에 줄 서 있음
	- 동작 성공마다 절정 게이지(이 장의 결말을 가르는 값)가 차고, 진폭 상위(얼쑤) 판정은 가산이 더 큼
	- 대본을 마쳤을 때 게이지가 만충이면 절정 결말 연출을 재생함: 마당별 결말은 아래 표
	- 미달이면 결말 연출을 완화판으로 재생하고(문안과 연출 작성 예정) 완주로 처리함
3. 결말 연출과 마당별 원전 마무리 대사를 마치면 완주로 보고 Step 4 배역 인정으로 진행함
	- 분기: 그만두기 선택 시 확인 팝업 → 확정 시 종료 처리
	- 분기: 사람이나 포즈 미검출이 터치 미입력 타임아웃 임계를 넘기면 이탈로 보고 종료 처리

#### 2) 마당별 뒷대목 연출

뒷대목도 연회본을 순서대로 진행하고, 대본을 마쳤을 때의 절정 게이지로 결말을 가름.

| 마당 | 원전 대목 | 진행 | 절정 게이지의 의미 | 결말 연출 |
|---|---|---|---|---|
| 옴탈잡이 | 446~466행 | 얼굴 내력 문답으로 붙었다가 채검에서 옴이 드러나고, 발악하는 옴탈을 춤으로 몰아냄 | 몰이 진행도 | 옴탈이 화면 밖으로 튕겨 나가 퇴장 |
| 샌님잡이 | 556~616행 | 샌님이 절을 가르친다며 지시를 쏟아내고, 말뚝이가 그 말을 그대로 되받아 넘기다 판이 뒤집힘 | 절 배우기 진행도 | 샌님이 말뚝이에게 큰절을 올리고, 유저는 버티고 서서 절을 받음 |
| 먹중잡이 | 658~678행 | 말 대신 춤으로 붙는 대목. 먹중은 무언 배역이라 도발을 동작으로만 걸고 장쇠가 판을 중계함 | 대결 우세도 | 먹중이 취발이의 코를 때리고 달아나 판이 취발이에게 넘어감 |

#### 3) 절정 시퀀스 진행기

##### (1) 역할과 목적

뒷대목 대본을 응수 단위로 진행하고 절정 게이지를 산출하는 시스템. 장단 박과 응답 대기 조절로 앞대목보다 판을 몰아감.

##### (2) 입력과 출력

- **입력**: 선택 마당 식별자, 뒷대목 대본(원문 대사, 기대 동작 배정, 반응과 중계 문구), 신호별 판정 결과
- **출력**: 동작 신호 이벤트(기대 동작과 응답 대기, 동작 판정에 전달), 동작 안내 바 표시, 절정 게이지 값

##### (3) 동작과 규칙

- **진행 단위**
	- 앞대목과 같은 턴제 루프임
	- 상대 배역의 원문 대사(먹중잡이는 무언 도발) → 유저 응수와 판정 → 반응 연출과 장쇠 중계 → 유저 배역의 원문 응답을 대본 끝까지 되풀이함
- **장단**
	- 마당별 장단을 배경 박으로 깖(옴탈잡이 112, 샌님잡이 96, 먹중잡이 104 BPM 잠정)
	- 진행을 재는 기준 시계가 아니라 판의 열기를 얹는 배경임
- **장단 가속**
	- 옴탈잡이에만 적용함. 대목이 넘어갈 때마다 응답 대기를 0.94배(잠정)씩 좁혀 몰아치는 느낌을 냄
	- 하한은 기본 응답 대기라 손이 못 따라갈 만큼 좁아지지 않음
- **동작 안내 바**
	- 화면 하단의 가로 바임. 뒷대목에서 나올 응수 동작의 픽토그램이 오른쪽에 차례로 줄 서 있음
	- 대목이 끝날 때마다 한 칸씩 왼쪽으로 미끄러져 표시선에 듦
	- 표시선에 든 동작은 아래 띠가 남은 응답 시간에 비례해 줄어들고, 판정이 나면 픽토그램이 성공이나 미수행 표시로 바뀜
- **판정 피드백**
	- 판정 결과(얼쑤, 좋다, 다시)를 판 위에 짧게 표기함(동작 판정 출력 연동)
- **절정 게이지**
	- 뒷대목 응수 개수로 100을 나눈 몫이 응수 성공마다 차오르고, 진폭 상위(얼쑤)는 가산이 더 큼(잠정 배분: 얼쑤 1.15배, 좋다 0.85배라 모두 얼쑤라야 만충)
	- 이 장의 결말을 가르는 화면 표시 게이지이며, 내부 활동 지표인 신명 지표와는 별개로 산출함

##### (4) 기술 요건

- **적용**: 전부 클라이언트 로컬 재생임. 서버 왕복 없음
- **표시와 판정의 연결**: 응답 대기는 앞선 대사 길이에서 산출하므로, 안내 바의 남은 시간 띠도 그 값을 그대로 씀

##### (5) 필요 리소스

- 마당별 뒷대목 대본(원문 대사, 기대 동작 배정, 반응과 중계 문안)
- 동작별 픽토그램 이미지(동작 안내 바용, 동작 세트와 1:1)
- 장단 음원(마당별 배경 박. 웃다리 풍물 가락에서 선정, 고증 자문 연계)

##### (6) 실패와 복구

- 대본, 픽토그램, 음원 로드나 검증이 실패 시 처리
	- 재시도(2회 잠정) 실행. 한도를 넘기면 마당 리소스 로드 실패로 중단 처리(원인: 시스템)
- 장단 재생이 끊길 시 처리
	- 배경 박이라 진행에 영향이 없음. 장단 없이 대본을 이어 감(기능 축소)

## 4.4 Step 4. 배역 인정

### 4.4.1 클라이언트: 배역 인정 화면

#### 1) 진행

점수 대신 배역 인정을 표시함.

- **인정 선언**
	- 장쇠가 인정 재담을 발화함("오늘부로 꺽쇠 노릇 한번 제대로 했다!" 류, 문안 작성 예정)
	- 완주 자체를 인정하며 등급 서열을 매기지 않음
- **수행 요약**
	- 장별 완수 현황과 하이라이트 동작 1개를 칭찬 문구로 표시함("네 소매 뿌리기가 제일 시원했다" 류)
	- 장면 수행 기록의 판정 값을 문구로 번역한 것으로 별도 채점이 없음
- **신명의 서사 번역**
	- 신명 지표가 분기 임계(정량 미정) 이상이면 "판이 후끈했다" 류의 문구를 표시하고 환호 연출을 재생함
	- 미만이면 장쇠가 눙치는 문구("다음엔 더 크게 놀아보자" 류)를 표시함. 임계 미만을 실패로 낙인찍지 않음
- **완주 확정**
	- 이 화면 진입이 완주 확정임. 진입 시의 단계 이동 이벤트(각 Step 진입 전송)가 서버의 완주 기록을 겸해, Step 5 도달 전에 세션이 끊겨도 완주가 유실되지 않음
	- Step 5 종료 이벤트는 완주 유형만 보강함
	- 분기: 처음으로 버튼 터치 또는 화면 타임아웃(기본 60초, 잠정) → Step 5 종료와 리셋으로 진행
- **이수 단계 (선택 검토)**
	- 인정 층위(구경꾼, 초짜 광대, 한몫 광대 류)의 도입 여부는 작성 예정임

## 4.5 Step 5. 종료와 리셋

완주와 비완주 두 경로로 진입하고 모두 세션 종료와 파기 실행함. 별도 UI 없음.
### 4.5.1 클라이언트: 종료 이벤트 전송과 리셋

#### 1) 진행

- 종료 이벤트(완주 또는 이탈 결과)를 서버로 전송하고, 서버의 저장 확인 응답을 받은 뒤 클라이언트 세션 데이터를 초기화함
	- 확인 응답을 재시도(2회 잠정) 후에도 받지 못하면 로컬 세션 데이터를 파기하고 시작 화면으로 복귀함(다음 유저의 키오스크 점유가 우선)
	- 미종료로 남은 서버 세션의 정리 방식은 서버 구현에서 확정함(확인 필요)
	- 완주는 유형(처음으로 버튼 터치, 배역 인정 화면 타임아웃)을 구분해 기록함: 완주율 관측에서 방치 완주를 분리함
	- 완주와 비완주 종료가 모두 모이는 종착점임. 비완주 종료는 배역 인정 화면을 건너뛰고 여기로 바로 들어옴

## 5.2 에러 케이스

### 5.2.1 케이스 목록과 처리

**처리**는 그 실패가 세션을 어떤 상태로 끝내는지를, **원인**은 실패가 어디에서 비롯되었는지를 나타냄. 원인이 외부 서비스나 시스템일 경우에만 운영 알림을 보냄. 갈래를 나누는 판정 규칙은 실패 처리 절에 있고, 본 표는 그 규칙을 케이스에 적용한 결과임. 이후 동작의 Step 5는 모두 비완주 종료라 배역 인정 화면을 건너뛰고 세션 종료와 파기 후 시작 화면으로 복귀함.

| 발생 지점                        | 처리    | 원인     | 팝업             | 이후 동작                     |
| ---------------------------- | ----- | ------ | -------------- | ------------------------- |
| 장쇠와 상대 배역의 TTS 합성 또는 호출 실패           | 기능 축소 | 외부 서비스 | 없음             | 세션 계속, 화면 텍스트와 포즈 이미지로 진행    |
| 장쇠 캐릭터 렌더나 음성 재생 실패         | 기능 축소 | 시스템    | 없음             | 세션 계속, 대표 이미지와 텍스트로 진행    |
| 상대 배역 포즈 전환이나 이펙트 실패        | 기능 축소 | 시스템    | 없음             | 세션 계속, 대표 포즈 정지 표시와 효과음으로 대체    |
| 마당 리소스 로드나 검증 실패(재시도 한도 초과) | 중단    | 시스템    | 상황 안내          | Step 5                    |
| 카메라 미수신이나 모든 프레임 저신뢰 지속(임계 잠정) | 중단    | 시스템    | 상황 안내          | Step 5                    |
| 세션 생성 실패                     | 중단    | 시스템    | 상황 안내          | 시작 화면 복귀                  |
