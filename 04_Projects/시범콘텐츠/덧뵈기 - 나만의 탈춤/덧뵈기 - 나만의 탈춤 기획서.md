> 덧뵈기(탈춤)를 소재로 한 AR 탈춤 체험 시범콘텐츠의 개발 기획서. [[콘셉트 정리#1) 나만의 탈춤]]을 입력으로 작성함. 골격 단계로, 점차 채워나감.

# 1. 개요

사용자가 직접 디자인한 탈을 3D로 변환해 AR로 쓰고, 풍물 장단에 맞춰 탈춤 춤사위를 따라 추며, 탈 캐릭터와 기념 촬영하는 체험 콘텐츠.

- **소재**: 남사당놀이 탈놀음 덧뵈기 ([[덧뵈기]])
- **유형**: 체험. 실시간 동작 놀이가 핵심이고, 탈 만들기는 도입 단계임 (유형 정의는 [[콘셉트 정리#3. 전체 구조 정리]])
- **성격**
	- 1회성 체험이 아니라 반복 사용으로 탈춤을 익히는 학습 도구
	- 디지털 도제(Digital Apprentice)식 전승과 교육 지향 ([[ref_제안요청서#3. 활용방안 예시]])
	- 돌아오는 학습자의 진척을 옵트인으로 누적 (상세는 3장 라. 채점 체계, 5장 가. 개인정보 처리 정책)
- **플랫폼**: 키오스크 (세로형 터치 + 카메라와 마이크. [[콘셉트 정리#가. 키오스크]])
- **흐름**: 탈 디자인 → AI 3D 변환 → AR 착용 + 춤사위 따라하기(포즈 채점) → 기념 촬영 → 사진 전송 ([[콘셉트 정리#1) 나만의 탈춤]]). 여기에 숏폼 리플레이 영상 제공을 더함
- **핵심 특성**: 사용자가 만든 탈을 쓰고 직접 몸으로 춤을 따라 추는 능동 체험. 자세 일치도와 타이밍을 실시간 채점해 신명(興) 게이지로 보상
- **진행 호스트**: 말뚝이. 탈춤 풍자의 화자가 전 Step 진행을 안내하고 추임새로 호응 (페르소나는 3장 가. 진행 호스트 참조)
- **산출물**: 기념 사진(2D 탈 캐릭터와 나란히 찍은 동반 포즈 사진)과 숏폼 리플레이 영상(춤사위 하이라이트와 기념 포즈에 신명 게이지 점수와 등급 스탬프, 음원 포함). 상세는 4장 산출물 참조

목표, 범위 등 나머지 개요 항목은 작성 예정.

# 2. 시스템 동작

- **매체**: 9:16 세로형 키오스크. 터치, 카메라(포즈와 얼굴 인식), 마이크 입력을 받음. 1인 사용
- **큰 흐름**: Step 1 인트로(동의 약관) → Step 2 탈 디자인 → Step 3 3D 변환 + 대기 화면 → Step 4 AR 착용 + 춤사위 따라하기 → Step 5 기념 촬영 → Step 6 결과물 전송 → Step 7 종료와 리셋
- **목표 플레이타임**: **확인 필요** (콘셉트와 로드맵 원문 미명시. 임의 추정 금지)

## 가. 세션

한 유저의 키오스크 사용 전체(Step 1 시작 → Step 7 종료)를 감싸는 상위 컨테이너. 하위 Step들이 세션 안에서 순차 실행됨. 라이프사이클과 저장 데이터 모델은 [[시범콘텐츠 공통 사양#2. 세션]] 구조를 준용하되, 본 콘텐츠 고유 데이터(탈 디자인, 3D 모델, 동작 채점, 기념 사진, 리플레이 영상)로 재정의함.

### 1) 세션 라이프사이클

[[시범콘텐츠 공통 사양#다. Step별 세션 동작]] 준용.

- **생성**: Step 1 시작 시 신규 세션 생성 + 동의 기록 저장. 미동의 또는 터치 미입력 타임아웃 시 세션 즉시 파기(동의 기록 미생성)
- **갱신**: Step 2~6 진행 중 각 산출물을 세션에 저장하고 갱신 (탈 디자인 → 3D 탈 모델 → 동작 채점 기록 → 기념 사진과 리플레이 영상 → 연락처)
- **종료**: Step 7에서 세션 종료 + 임시 데이터 파기 + 시작 화면 리셋(다음 유저 대기)

### 2) 세션 데이터

세션이 담는 데이터를 분류, 값, 보관과 파기 정책으로 정리함. 개인정보 민감 데이터(영상, 사진, 연락처)에는 최소 보관 원칙을 적용함. 보관 기간 잠정값은 법무 검토 후 확정함 (임의 추정 금지, [[CONVENTIONS#바. 수치/목표 인용 원칙 (엄격)]]).

| 데이터        | 분류      | 값과 구성                                                | 보관과 파기                                |
| ---------- | ------- | ---------------------------------------------------- | ------------------------------------- |
| 세션 ID      | 시스템     | 세션 고유 식별자                                            | 세션 종료 시 파기                            |
| 동의 기록      | 시스템     | 약관 버전 + 동의 일시 + 동의 항목(필수: 카메라 촬영, 선택: 영상 녹화, 학습 프로필) | 보관 (기간 확인 필요)                         |
| 탈 디자인(2D)  | 콘텐츠     | 사용자가 디자인한 2D 탈 도안                                    | 별도 저장소 보관                             |
| 3D 탈 모델    | 콘텐츠     | 디자인에서 변환된 3D 자산                                      | 별도 저장소 보관                             |
| 동작 채점 기록   | 콘텐츠     | 자세 일치도와 타이밍 점수, 신명 게이지                               | 익명 통계 보관, 식별 원본은 세션 종료 시 파기           |
| 학습 프로필     | 가명 개인정보 | 가명 토큰(subject_id)에 연결된 채점 진척, 약점 동작, 향상 곡선, 탈 디자인    | 옵트인 시 별도 저장소 보관                       |
| 기념 사진      | 콘텐츠     | 사용자와 2D 탈 캐릭터 동반 포즈 사진 (점수 스탬프 없음)                      | 결과 페이지에 임시 보관, 48시간 만료 시 파기           |
| 리플레이 영상    | 콘텐츠     | AR 탈 춤사위 하이라이트 + 기념 포즈에 점수와 등급 스탬프 합성 숏폼 (MP4)                      | 결과 페이지에 임시 보관, 48시간 만료 시 파기           |
| 영상 피드      | 개인정보    | 카메라 원본 스트림 (포즈 추정과 기념 사진 촬영 입력)                                | 메모리에 임시 보관, 처리 직후 파기                  |
| 리플레이 임시 녹화 | 개인정보    | AR 합성 화면 프레임 버퍼 (영상 동의 시, Step 4 녹화)                 | 메모리와 임시 버퍼, Step 5 인코딩 완료나 세션 종료 시 파기 |
| 연락처        | 개인정보    | 유저 연락처 (SMS)                                         | 메모리에 임시 보관, 전송 후 즉시 파기                |

임시 데이터를 저장 위치로 나눠 보관과 파기를 정리함. 상태별 파기 시점은 아래 전송 수단별 파기표를 따름.

- **메모리 임시 보관**: 영상 피드, 연락처, 리플레이 임시 녹화
	- 보관: 메모리나 임시 버퍼에만 두고 디스크 영속화와 로그 기록을 금지함
	- 파기: 영상 피드와 연락처는 처리나 전송 직후 메모리를 명시적으로 덮어씀 ([[시범콘텐츠 공통 사양#가. 개인정보 처리 정책 (공통 원칙)]] 준용). 리플레이 임시 녹화는 Step 5 인코딩 완료나 세션 종료 시 파기 (5장 아. 리플레이 영상 파이프라인)
- **결과 페이지 임시 보관**: 기념 사진, 리플레이 영상
	- 보관: 전송용으로 서버 임시 저장소(결과 페이지)에 임시로 두되, 디스크 영속화는 이 저장소에만 허용하고 로그 기록은 금지함
	- 파기: 48시간 만료 시 파기함 (만료 전까지는 재열람과 재다운로드 자유). 발행과 미발행 상태별 세션 종료 처리는 아래 전송 수단별 파기표를 따름

전송 수단별로 결과 페이지(사진과 영상)와 연락처의 파기 시점을 정리함. 발행과 미발행에 따라 결과 페이지 파기 시점이 갈리므로 상태로 구분함.

| 상태                | 결과 페이지(사진과 영상) 파기 시점          | 연락처 파기 |
| ----------------- | ----------------------------- | ------ |
| SMS 발송 성공         | 48시간 만료 시 파기 (세션 종료와 무관하게 유지) | 즉시 파기  |
| 전송 거부 (결과물 받기 거부) | 미발행, 세션 종료 시 파기               | 즉시 파기  |
| SMS 발송 영구 실패      | 미발행, 세션 종료 시 파기               | 즉시 파기  |
| 터치 미입력 타임아웃       | 미발행, 세션 종료 시 파기               | 즉시 파기  |
- **별도 저장소 보관 (목적과 파기 시점)**:
	- 목적: 탈 디자인은 재방문, 재사용, 품질 분석. 3D 모델은 재변환 비용 회피. 학습 프로필은 학습 연속성(미옵트인 시 미생성)
	- 파기 시점: 셋 다 미정, 법무 검토 후 확정 (파기 시점 정본은 2장 가 세션 데이터 표). 학습 프로필(가명 개인정보)과 옵트인 연결된 탈 디자인은 5장 가. 개인정보 처리 정책의 보호 원칙과 동의를 적용하고, 3D 모델과 단독 탈 디자인은 콘텐츠 자산으로 별도 저장소 정책(작성 예정)을 따름
- **동작 채점 누적**: 옵트인 학습 프로필이 있으면 식별 원본 대신 진척으로 누적
- **비연결 설계**: 집계 채점 통계 분석(완주율, 자주 틀리는 동작 등 콘텐츠와 운영 개선)에 개인 신원은 필요 없고, 신원과 묶으면 유출 피해와 법적 리스크만 커짐. 그래서 집계 통계는 신원을 알 수 있는 정보(얼굴, 영상, 연락처)와 묶지 않고, 학습 진척은 가명 토큰에만 붙여 신원과 분리함
- **재식별 위험**: 학습 진척과 탈 디자인은 이름이나 얼굴이 없어도 쌓이면 누구인지 좁혀질 수 있음. 직접 신원정보를 안 붙였어도 익명으로 보지 않고 가명 개인정보로 보호함 (상세는 5장 가)
- **보관 기간**: 보관 대상 데이터(동의 기록, 별도 저장소 자산)의 보관 기간은 법무 검토 후 확정. 정본은 2장 가 세션 데이터 표

### 3) 영상 처리 주의

본 콘텐츠는 카메라로 얼굴과 신체를 촬영(포즈 추정 + 기념 사진 + 리플레이 영상)하므로 덜미보다 개인정보 민감도가 높음. 데이터별 보관과 파기는 위 세션 데이터 표와 그 아래 규칙을 따르며, 세부 처리 정책과 법무 검토 사항은 5장 가. 개인정보 처리 정책에서 정의함.

## 다. Step별 명세

본 콘텐츠 Step별 골격 명세 (상세 작성 예정). 각 Step 화면 수는 기획 잠정값(UI 설계 단계 확정), RFP 정량 요건 아님.

### 1) Step 1. 인트로 (시작 + 동의)

- **트리거**: 유저가 시작하기 또는 이어하기 버튼 터치
- **시스템**: 클라이언트 UI, 백엔드 (상세는 5장 기술 구성)
- **화면**: 시작, 가이드, 동의 약관 3개. 전환: 대기 상태의 시작 화면에서 처음 시작과 이어하기로 분기함. 처음 시작은 가이드와 동의 약관을 거쳐 Step 2로 진입하고, 이어하기는 학습 토큰 복원으로 Step 2에 바로 진입함 (상세는 아래 프로세스). 시작 화면은 Step 7 복귀 화면과 동일
- **프로세스 (골격)**:
	1. 백엔드: 신규 세션 생성
	2. UI(시작): 처음 시작과 이어하기 분기
		- 이어하기 선택 시: 키오스크 카메라로 학습 토큰(QR)을 판독해 진척과 동의 기록을 복원하고 Step 2로 직행함 (가이드와 동의 약관 생략). 이 판독은 QR만 읽으며, 사용자를 담는 카메라 촬영(필수 동의 대상)과 구분됨
		- 스캔 실패나 무효 토큰이면 처음 시작 흐름(아래 3~6)으로 안내
		- 처음 시작이면 익명 신규로 진행 (학습 프로필 신규 생성과 토큰 발급은 Step 6에서). 미옵트인 학습자는 발급받은 토큰이 없어 이어하기를 쓰지 않음 (5장 가. 개인정보 처리 정책의 학습 프로필)
	3. UI(가이드): 인사말과 가이드 표시
	4. UI(동의 약관): 사용자 동의 약관 표시
		- 필수 동의: 카메라 촬영
		- 선택 동의: AR 합성 영상 녹화와 리플레이 영상 생성, 제공
		- 선택 동의: 학습 프로필 생성과 진척 보관
	5. UI(동의 약관): 동의 입력 감지
		- 분기: 카메라 촬영에 미동의하거나 터치 미입력 타임아웃이면 Step 7로 직행 (동의 화면, 화면 타임아웃 미적용). 영상 산출물 선택 동의만 거부하면 Step 4 녹화와 Step 5 영상 생성을 생략하고 사진만 진행
	6. 백엔드: 동의 기록 저장 (학습 프로필 옵트인 시 동의 기록을 프로필에 연결해 다음 방문 이어하기 복원에 사용)
- **입력**: 시작하기 또는 이어하기 터치, (처음 시작 시) 동의 입력, (이어하기 시) 학습 토큰 QR
- **출력**: 신규 세션, 동의 기록(처음 시작은 신규 입력, 이어하기는 복원), (옵트인 시) 복원하거나 생성한 학습 프로필
- **다음**: Step 2

### 2) Step 2. 탈 디자인

- **시스템**: 클라이언트 UI, 백엔드 (상세는 5장 기술 구성)

- **프로세스 (골격)**:
	1. UI(탈 디자인 도구): 배역 탈 템플릿을 시작점으로 한 드로잉형 탈 디자인 도구를 제공하고 사용자 도안 입력을 수집 (상세는 3장 다. 탈 디자인)
		- 호출 공용 기능: 화면 타임아웃(창작 화면, 긴 값), 터치 미입력 타임아웃
		- 분기: 화면 타임아웃 발동 시 현재 도안을 확정해 저장한 뒤 정상 진행 경로(유효성 검증, 가드레일 검사)를 따라 Step 3으로 넘어감. 터치 미입력 타임아웃 발동 시 유저 이탈로 보고 Step 7 직행
	2. 백엔드: 입력 유효성 검증
	3. AI: 가드레일 검사 (부적절 도안 차단, 상세 3장 마. 가드레일)
		- 실패: 부적절 도안 검출 시 차단 + 재입력 안내(재시도), 반복 위반 시 처리 작성 예정
	4. 백엔드: 세션 저장
	- (병행) UI(탈 디자인 도구): 그린 도안을 3D 탈에 입힌 경량 미리보기를 실시간 표시 (디자인 확인용, 정식 변환은 Step 3)
- **입력**: 사용자 탈 디자인 입력
- **출력**: 2D 탈 도안 (Step 3 정식 3D 변환 입력). 경량 3D 미리보기는 디자인 확인용 화면 표시이며 다운스트림 산출물이 아님
- **다음**: Step 3

### 3) Step 3. 3D 변환 + 대기 화면

- **트리거**: 탈 디자인 완료
- **시스템**: AI 시스템, 클라이언트 UI, 백엔드 (상세는 5장 기술 구성)
- **화면**: 변환 대기 (1개, 진행 상태를 주기적으로 조회해 표시). 전환: 변환 완료 → Step 4
- **프로세스 (골격)**:

	2. AI: 2D 도안을 3D 탈 모델로 변환 (Step 2 경량 미리보기와 달리 정식 고품질 변환)
		- 실패: 변환 실패 시 fallback (에러/fallback 공용 기능)
	3. AI: 생성물 가드레일 검사
		- 실패: 가드레일 한도 초과 시 fallback (에러/fallback 공용 기능)

	- (병행) UI(변환 대기): 변환 진행 표시, 백엔드 변환 작업 상태를 주기적으로 조회

- **출력**: 3D 탈 모델

### 4) Step 4. AR 착용 + 춤사위 따라하기 (핵심 체험)

- **트리거**: 3D 변환 완료
- **시스템**: AI 시스템(포즈 추정), 클라이언트 UI, 백엔드 (상세는 5장 기술 구성)
- **화면**: AR 춤사위 체험 1개 (동적 화면: AR 카메라 뷰, 춤사위 가이드, 신명 게이지, 말뚝이를 함께 표시). 전환: 춤사위 종료 시 Step 5
- **프로세스 (골격)**:
	1. UI(AR 춤사위 체험): 변환된 3D 탈을 AR로 착용 (카메라 얼굴 추적 → 탈 오버레이)
	2. UI(AR 춤사위 체험): 탈춤 춤사위 가이드 제시, 사용자 동작 캡처 (카메라/모션 화면)
		- 호출 공용 기능: 화면 타임아웃, 터치 미입력 타임아웃
		- 분기: 화면 타임아웃 발동 시 체류 상한으로 보고 정상 진행 경로를 따라 Step 5로 넘어감. 터치 미입력 타임아웃은 사람이나 포즈 미검출로 판정하며, 발동 시 유저 이탈로 보고 Step 7 직행
	3. AI: 포즈를 추정해 자세 일치도와 타이밍을 채점. 점수가 쌓이면 신명(興) 게이지 상승 (채점 상세는 3장 라. 채점 체계)
		- 실패: 포즈가 안 잡히거나 신뢰도가 낮으면 재시도 안내. 지연되면 해당 구간 점수는 보류
	4. UI(AR 춤사위 체험): 말뚝이가 채점에 따라 실시간 추임새 피드백 (3장 가. 진행 호스트)
	5. UI(AR 춤사위 체험): 게이지 달성 시 환호 사운드(군중 추임새와 박수)로 보상, 미달 시 말뚝이가 눙치며 마무리 (상세 작성 예정)
	- (병행) 백엔드: 영상 동의가 있으면, 춤사위 중 AR 합성 화면을 리플레이 소재로 임시 녹화 (Step 5 영상 편집 입력). 영상 미동의 시 생략
- **입력**: 카메라 동작 영상, 풍물 장단 타이밍
- **출력**: 동작 채점 기록, 신명 게이지 결과, 리플레이용 임시 녹화 영상
- **다음**: Step 5

### 5) Step 5. 기념 촬영

- **트리거**: 춤사위 체험 완료
- **시스템**: 클라이언트 UI(AR 카메라), 백엔드 (상세는 5장 기술 구성)
- **화면**: 기념 촬영, 생성 대기 2개 (생성 대기 화면은 영상 인코딩 동안 노출). 전환: 촬영 완료 → 생성 대기 → 통과 산출물 확정 시 Step 6. 실패와 fallback(사진만 제공 또는 에러 안내)은 아래 sub-step 5 실패 참조
- **프로세스 (골격)**:
	1. UI(기념 촬영): 2D 탈 캐릭터(사용자가 디자인한 탈을 쓰고 덧뵈기 탈옷을 입음)를 카메라 뷰에 라이브로 합성해 화면 한쪽에서 탈춤 포즈로 보여줌. AR로 자기 탈을 쓴 사용자가 그 캐릭터 옆에서 같이 포즈를 잡음
	2. UI(기념 촬영): 사용자가 준비되면 카운트다운 뒤 촬영. 채점 없음. 촬영은 정해진 촬영 횟수(n회, 운영 파라미터)까지 진행하며, 촬영 횟수 소진이나 촬영 자체 타임아웃 시 다음 sub-step(기념 사진 생성)으로 넘어감 (카메라/모션 화면)
		- 호출 공용 기능: 화면 타임아웃(촬영 화면, 긴 값), 터치 미입력 타임아웃
		- 실패: 카메라에 사람이 안 잡히면 다시 서도록 안내
		- 실패: 촬영 0회로 진행되면(유효 촬영 전에 화면 타임아웃이나 촬영 자체 타임아웃 발동) 사진 생성을 생략하고 에러/fallback 공용 기능으로 처리 (Step 6은 통과 산출물이 있을 때만 진행)
		- 분기: 화면 타임아웃은 안전 상한(긴 값)이며 발동 시 정상 진행 경로를 따라 생성 단계로 넘어감. 터치 미입력 타임아웃은 사람이나 포즈 미검출로 판정하며, 발동 시 유저 이탈로 보고 Step 7 직행
	3. 백엔드: 기념 사진 생성. 촬영된 사용자 모습에 2D 탈 캐릭터를 고품질로 재합성해 한 장의 기념 사진을 만들고 테두리 프레임을 적용함 (라이브 화면은 포즈용 미리보기, 최종 저장본은 이 재합성 결과). 점수와 등급 스탬프는 넣지 않아 사진을 깔끔하게 둠
	4. 백엔드: (영상 동의 시) 숏폼 영상 편집과 인코딩. Step 4 춤사위 하이라이트와 기념 포즈를 이어 붙이고 신명 게이지 점수와 등급 스탬프, 풍물 장단 음원을 오버레이함. 영상 미동의 시 생략
	5. AI: 생성물(사진과 영상) 가드레일 검사 (3장 마. 가드레일), 통과물만 출력으로 확정
		- 실패: 가드레일을 통과 못 하거나 재생성 한도를 넘으면 위험 생성물을 파기하고 사진만 제공. 사진까지 전부 실패하면 에러 안내 (에러/fallback 공용 기능). Step 6은 통과 산출물이 있을 때만 진행
	- (병행) UI(생성 대기): 사진과 영상을 생성, 인코딩하는 동안 대기 표시
- **입력**: 카메라 영상, 사용자 2D 탈 디자인(캐릭터 합성용), Step 4 신명 게이지 점수, (영상 동의 시) Step 4 임시 녹화 영상
- **출력**: 기념 사진 (사용자와 2D 탈 캐릭터 동반 포즈, 점수 스탬프 없음), 숏폼 영상 (하이라이트와 기념 포즈에 점수와 등급 스탬프, 영상 동의 시)
- **다음**: Step 6

### 6) Step 6. 결과물 전송

- **트리거**: 기념 사진 생성 완료 (리플레이 영상은 영상 동의 시)
- **시스템**: 클라이언트 UI, 백엔드, 외부 서비스 (상세는 5장 기술 구성)
- **화면**: 결과물 미리보기(사진과 영상), 연락처 입력과 전송 2개. 사진과 영상을 한 결과 페이지에 묶어 SMS 링크 1개로 발송. 연락처를 거부하거나 터치 미입력 타임아웃이면 결과물을 받지 못하고 종료. 전환: 전송 또는 거부 → Step 7
- **프로세스 (골격)**:
	1. UI(결과물 미리보기): 기념 사진과 리플레이 영상 미리보기 (전송 수단 노출 전, 감상/열람 화면, 터치 미입력 타임아웃 미적용)
		- 호출 공용 기능: 화면 타임아웃
		- 분기: 화면 타임아웃 발동 시 정상 진행 경로를 따라 연락처 입력과 전송 화면으로 넘어감
	2. 백엔드: 기념 사진과 (영상 동의 시) 리플레이 영상을 하나의 결과 페이지에 담고 만료형 서명 URL(signed expiring URL, 48시간) 발급. 사진과 영상을 한 링크로 통합함. URL 정책(만료 전 재접근)은 5장 마. 외부 서비스 연동
	3. UI(연락처 입력과 전송): 연락처 입력 + 전송 동의 입력 수집 (필수 입력 화면, 화면 타임아웃 미적용)
	4. 분기 (전송 수단):
		- 전송 동의: 백엔드가 연락처 임시 저장 → 외부 서비스가 결과 페이지 링크를 SMS로 발송 (사진과 영상 통합 1채널) → 발송 직후 연락처 즉시 파기. 연동 상세는 5장 마. 외부 서비스 연동, 채널 근거는 [[콘셉트 정리#가. 키오스크]]
			- 실패: 전송 실패는 에러/fallback 공용 기능 ([[시범콘텐츠 공통 사양#나. 결과물 전송]] 준용)
		- 전송 거부 (결과물 받기 거부): SMS 발송 생략, 받은 연락처가 있으면 즉시 파기. 결과물 미발행으로 공유 없이 Step 7로
		- 터치 미입력 타임아웃 (유저 이탈): 연락처 즉시 파기, 전송 생략하고 Step 7로
	5. 백엔드: 기념 사진과 리플레이 영상은 48시간 만료 시 파기 (만료 전까지는 재열람과 재다운로드 자유). SMS 발송 성공 뒤에는 세션 종료와 무관하게 유지하며, 결과 페이지 미발행 상태만 세션 종료 시 파기 (상태별 상세는 2장 가. 세션 데이터 표 아래 전송 수단별 파기표)
	6. 백엔드와 UI: (학습 프로필 옵트인 시) 이번 세션 진척을 프로필에 저장하고 학습 토큰(QR) 발급 또는 갱신 (다음 방문 복원용). 미옵트인 시 생략
- **입력**: 연락처, 전송 동의
- **출력**: 전송 결과 (SMS 링크)
- **다음**: Step 7

### 7) Step 7. 종료와 리셋

- **트리거**: 결과물 전송 완료 또는 미동의 또는 터치 미입력 타임아웃 (유저 이탈)
- **시스템**: 클라이언트 UI, 백엔드 (상세는 5장 기술 구성)
- **화면**: 마무리 인사 (1개) → 시작 화면 복귀. 시작 화면은 Step 1 진입 화면과 동일
- **프로세스 (골격)**:
	1. UI(마무리 인사): 마무리 인사 표시
	2. 백엔드: 세션 종료와 세션 임시 데이터 파기 (영상 피드, 남은 연락처). 결과 페이지(사진과 영상)는 SMS로 발송한 경우 48시간 만료까지 유지하고, 미발행 상태(전송 거부, SMS 발송 영구 실패, 터치 미입력 타임아웃)만 세션 종료 시 파기 (2장 가. 전송 수단별 파기표)
	3. UI(시작): 시작 화면 복귀 (다음 유저 대기)
- **입력**: 종료 트리거, 파기 대상 세션 임시 데이터
- **출력**: 임시 데이터 파기 완료, 리셋된 시작 화면
- **다음**: 다음 유저용 Step 1 대기

# 3. 콘텐츠 설계

본 콘텐츠의 설계 요소(진행 호스트, 탈과 춤사위 고증, 탈 디자인, 채점 체계, 가드레일)와 제작 자산을 정의함. 5장 기술 구성은 본 장에서 정의된 것의 구현과 배치를 다룸.

## 가. 진행 호스트 (말뚝이)

본 콘텐츠의 진행 안내자. 탈춤 풍자의 화자 말뚝이가 전 Step을 잇는 목소리로 등장, 탈 디자인부터 춤사위 따라하기, 기념 촬영까지 안내하고 추임새로 호응함.

- **역할**: 양반을 놀리는 탈춤 풍자의 화자. 관객과 대거리하는 전통 기능을 진행 안내와 추임새로 계승 (덜미 박첨지의 해설자와 길잡이에 대응, [[덜미 - 전자책 변환 기획서#가. 박첨지 페르소나]])
- **화법**: 재담과 추임새. 춤사위 채점 피드백을 추임새로 전달 (3장 라. 채점 체계와 연동)
- **시각 정체성**: 말뚝이 탈과 의상 고유 양식 유지 (고증은 3장 나. 탈과 춤사위 고증 참조)
- **고증 주의**: 말뚝이 배역 해석은 일반 탈춤 문헌 수준(L5 추론, [[CONVENTIONS#사. 외부 근거의 권위 계층]]). [[덧뵈기]] 문서 작성 후 검증 (확인 필요)
- **세부 페르소나 (작성 예정)**: 말투, 어휘, 반응 패턴 등

## 나. 탈과 춤사위 고증

- **탈**: 덧뵈기 탈놀음의 배역 탈(말뚝이, 양반, 먹중, 샌님 등) 양식을 디자인 레퍼런스로 활용 (목록과 종수 **확인 필요**, [[덧뵈기]] 문서 작성 후 보강)
- **춤사위**: 따라 추기 대상 춤사위 동작과 풍물 장단의 고증 매핑 (작성 예정, 고증 자문 연계)
- **시각 정체성**: 탈 양식과 질감의 전통 정합성 유지 방향 (작성 예정)

## 다. 탈 디자인

Step 2의 탈 디자인 도구 사양. 빈 캔버스가 아니라 전통 배역 탈에서 출발하는 드로잉형으로 설계해, 전통 정합성과 디자인 속도를 함께 잡음.

- **디자인 방식**: 드로잉형으로, 배역 탈 템플릿과 프리셋을 시작점으로 제공하고 그 위에 자유롭게 그림 (자산은 3장 바 1) 탈 디자인 템플릿과 프리셋)
- **캔버스와 해상도**: 드로잉형 캔버스를 충분히 높은 해상도로 둠. 저해상도 도트 그리드는 쓰지 않음 (구체 해상도값은 디자인 단계 확정)
- **색**: 제한 팔레트로 전통 색감(오방색 등)을 통일하고 빠른 디자인을 유도함 (팔레트 구성과 색 수 확인 필요)
- **대칭**: 좌우 대칭(미러) 모드를 기본 제공하고, 해제 토글로 비대칭도 허용함 (탈은 좌우 대칭 형태가 많음)
- **보조 도구**: 도형 그리기와 전통 문양 스탬프로 비숙련자를 보조함
- **실시간 3D 프리뷰**: Step 2에서 그린 도안을 3D 탈 형태에 입힌 경량 미리보기를 실시간으로 보여줌 (디자인 확인용). 정식 고품질 3D 변환은 Step 3에서 별도로 수행함
- **출력 규격 (작성 예정)**: 드로잉 결과가 3D 변환(5장 나. AI 시스템) 입력으로 연결되는 형식 규격
- **참조 사례**: 모여봐요 동물의 숲 마이 디자인 페이스 페인트를 참조함. 대칭 모드, 제한 팔레트, 스탬프, 실시간 프리뷰를 차용하고, 저해상도 도트는 본 콘텐츠 탈에 맞지 않아 드로잉형으로 분기함

## 라. 채점 체계 (신명 게이지)

본 콘텐츠 핵심 루프. 실시간 동작을 채점해 신명(興) 게이지로 시각화하고 달성 시 보상함.

- **채점 입력**: Step 4의 자세 일치도(포즈 추정 기반)와 풍물 장단 대비 타이밍 (Step 5 기념 촬영은 채점하지 않음)
- **게이지와 보상**: 채점이 쌓이면 신명 게이지 상승. 달성하면 환호 사운드(군중 추임새, 박수)로 보상하고, 미달하면 마무리 처리
- **종합 점수 출력**: 신명 게이지 종합 점수와 등급은 Step 5 숏폼 영상 스탬프로도 출력
- **학습 진척 (디지털 도제)**: 옵트인 학습자는 재방문 시 가명 토큰으로 과거 진척을 불러와 향상 곡선과 약점 동작 피드백을 받음. 1회성 사용자는 당회 채점만 제공 (프로필 설계는 5장 가. 개인정보 처리 정책)
- **세부 설계 (작성 예정)**: 채점 가중치, 게이지 임계, 난이도 곡선, 미달 시 처리 정책, 진척 누적과 향상 곡선 산출

## 마. 가드레일

콘텐츠 안전 정책. 구현은 5장 나. AI 시스템의 AI 가드레일 모듈에서 다룸. [[시범콘텐츠 공통 사양#나. 가드레일 적용 3지점]]을 준용하되 본 콘텐츠 입출력에 맞춰 재정의함.

- **적용 지점 (골격)**:
	- 입력: 탈 디자인 도안 검사 (Step 2), 부적절 이미지 차단
	- 출력: 3D 변환물(Step 3)과 기념 사진, 리플레이 영상(Step 5)을 검사. 부적절 생성물과 전통 정체성 왜곡을 차단
- **세부 정책 (작성 예정)**: 부적절 도안 분류, 전통 왜곡 판정, 동의 약관(카메라 촬영, 영상 산출물 생성과 제공) 항목 구체화

## 바. 콘텐츠 자산

> 본 콘텐츠 제작에 필요한 자산 목록(발주와 견적 입력). 산출 방식은 5장 기술 구성에서. 정량(수량, 규격, 제작 방식)은 확인 필요 (골격, 작성 예정).

- **수량과 규격**: 배역 탈 양식 기반, 종수와 형식 확인 필요

- **수량과 규격**: 동작 수와 형식 확인 필요

### 3) 풍물 장단 음원

- **분류**: 음향 자산

- **수량과 규격**: 곡수와 길이 확인 필요

### 4) 환호와 추임새 사운드

- **분류**: 음향 자산
- **제작 방식**: 확인 필요
- **수량과 규격**: 개수 확인 필요
- **용도**: 신명 게이지 달성 보상 (Step 4)

### 5) 기념 사진 프레임

- **분류**: 출력 양식 자산
- **제작 방식**: 디자인 외주 또는 자체 (확인 필요)
- **수량과 규격**: 종수와 해상도 확인 필요
- **용도**: 기념 사진 양식 프레임 (Step 5). 점수와 등급 스탬프는 넣지 않음 (스탬프는 아래 6) 숏폼 영상 템플릿)

### 6) 숏폼 영상 템플릿과 워터마크, 스탬프

- **분류**: 출력 양식 자산
- **제작 방식**: 디자인 외주 또는 자체 (확인 필요)
- **수량과 규격**: 세로형(9:16) 프레임, 확인 필요
- **용도**: 숏폼 프레임, 브랜딩, 워터마크, 신명 게이지 점수와 등급 스탬프 오버레이 (Step 5)

# 4. 산출물

- **기념 사진**: AR로 자기 탈을 쓴 사용자 본인과, 사용자가 디자인한 탈을 쓰고 덧뵈기 탈옷을 입은 2D 탈 캐릭터가 나란히 포즈한 사진. 프레임만 적용하고 점수와 등급 스탬프는 넣지 않음 (SNS 공유용 깔끔한 사진)
- **숏폼 리플레이 영상**: AR 탈 착용 춤사위 하이라이트와 기념 포즈 합본에 신명 게이지 점수와 등급 스탬프를 오버레이, 세로형 MP4, 무저작권, 자체 제작, AI 생성 음원 포함
- **전송과 파기 정책**: 전송, 제공, 파기는 2장 가. 세션 데이터 표. 영상 합성과 제공 상세는 5장 아. 리플레이 영상 파이프라인
- **형식과 규격 (구현 단계 확정)**: 해상도, 길이, 코덱 등

# 5. 기술 구성

본 콘텐츠 구현을 횡단 정책(가. 개인정보 처리), 시스템 구성요소(나~사: AI, 하드웨어, 백엔드, 외부 서비스, 클라이언트 UI, 운영), 구현 요건(아. 리플레이 영상 파이프라인)으로 정리함. 영상 처리 비중이 커 개인정보 처리 정책을 앞단에 둠. 시스템 구성요소는 [[시범콘텐츠 공통 사양#4. 기술 구성 (6영역 템플릿)]]을 준용하되 본 콘텐츠 고유 모듈(3D 변환, 포즈 추정 채점)로 재구성함. (골격, 작성 예정)

## 가. 개인정보 처리 정책

여러 영역에 공통으로 걸치는 정책임. 데이터별 보관과 파기 시점은 2장 가. 세션의 세션 데이터 표가 정본이며, 본 절은 범위, 동의, 설계 원칙을 정의함.

- **개인정보 범위**
	- 연락처 (전송용)
	- 얼굴과 신체 영상 (영상 피드, 개인정보)
	- 기념 사진과 리플레이 영상 (분류는 콘텐츠지만 얼굴과 신체가 담긴 결과물이라 개인정보 처리를 함께 적용. 덜미와 달리 영상 처리 포함, 민감도 높음)
	- 옵트인 학습 프로필 (가명 개인정보, 상세는 아래 학습 프로필 항목)
- **동의 범위**
	- 필수 동의: 카메라 촬영 (AR 얼굴 추적, 포즈 추정, 기념 사진 촬영)
	- 선택 동의: AR 합성 영상 녹화, 리플레이 영상 생성과 제공 (없으면 녹화와 영상 생성을 생략하고 사진만 제공)
	- 선택 동의: 학습 프로필 생성과 진척 보관 (옵트인)
- **데이터별 처리와 파기**: 위 도입부의 세션 데이터 표 정본을 따름 (영상 피드, 사진, 리플레이 영상, 연락처의 파기 시점을 표 하나로 일원화)
- **비연결 설계**
	- 익명 통계: 신원을 알 수 있는 정보와 묶지 않음
	- 학습 프로필 진척: 가명 토큰에만 붙이고 얼굴, 영상, 연락처 같은 직접 식별정보와는 묶지 않음
	- 한계: 직접 식별정보를 안 붙였어도 완전 익명으로 보지 않음 (가명 개인정보로 보호하는 근거는 아래 학습 프로필의 보호 항목)
- **학습 프로필** (옵트인, 가명 개인정보)
	- 용도: 돌아오는 학습자의 진척 누적
	- 방식: 무계정 베어러 가명 토큰 (가입과 개인식별정보(PII) 없음)
	- 보호: 진척과 탈 디자인이 쌓이면 누구인지 좁혀질 수 있으므로, 익명으로 보지 않고 가명 개인정보로 취급함
	- 동의: 별도 선택 동의로 생성, 미동의 시 익명 1회성 유지 (디지털 도제, [[ref_제안요청서#3. 활용방안 예시]])
	- 복원: 다음 방문에 시작 화면에서 이어하기로 토큰을 스캔하면 진척과 함께 직전 동의 기록을 불러와 동의 약관을 다시 받지 않음 (동의 기록은 토큰에 연결된 프로필에 보관)
- **동의 변경과 철회 (확인 필요)**: 재방문자는 이어하기를 선택하면 동의 약관을 건너뛰므로, 복원된 동의를 바꾸거나 철회하는 경로를 별도로 둠
	- 변경과 철회: 학습 프로필 관리 진입점에서 선택 동의를 다시 켜고 끄거나, 동의를 철회하고 프로필과 토큰을 삭제함 (철회 시 익명 1회성으로 되돌리고 토큰을 무효화함)
	- 미확정: 진입점 위치(시작 화면 또는 결과 화면 등)와 본인 확인 방식은 UX와 법무 검토 단계에서 확정함. 아래 아동과 학교 사용 정책의 열람과 삭제권과도 어긋나지 않게 맞춤
- **학습 토큰 보안 (확인 필요)**: QR 학습 토큰은 베어러 방식이라 토큰을 가진 사람이 곧 접근 권한을 가짐. 아래 보안 항목을 설계에 명시함
	- 보호 범위: 토큰으로 진척뿐 아니라 직전 동의 기록까지 복원되므로, 토큰을 뺏기면 동의 상태도 노출될 수 있음. 동의 기록은 토큰 안이 아니라 서버 프로필에 보관함(토큰은 내용을 안 담는 참조값). 아래 항목으로 토큰 자체를 보호함
	- 토큰 값: 추측 못 하게 무작위성을 높이고(고엔트로피), 안에 의미 정보를 안 담는 불투명 값으로 만듦
	- 저장: 서버에는 원문이 아니라 해시로 저장함 (유출돼도 토큰 복원 불가)
	- 표시와 수명: QR 화면 표시 시간과 토큰 유효 시간을 짧게 둠 (노출과 유출 위험을 줄임)
	- 생명주기: 주기적 교체(회전), 폐기, 재발급, 토큰 값 중복 방지, 스캔 시도 횟수 제한(rate limit)
	- 유출 대비: 접근 토큰과 분리, 감사 로그에서 개인정보 제외, 분실이나 도난 시 복구 불가 고지
- **전방 호환 (향후 계정 확장 검토, 현재 구현 범위 아님)**
	- 적용 시점: 현재는 무계정 가명 토큰만 구현. 아래는 나중에 계정(분실 복구, 기기 간 연속성)을 붙일 때를 대비한 방향이며 이번 구현 범위가 아님
	- 설계 방향: 진척을 토큰이 아니라 내부 식별자(subject_id, 진척의 실제 소유자)에 묶고, 로그인 자격증명에서 그 식별자를 찾는 경로를 인증 모듈로 분리. 한 식별자가 토큰과 계정 등 여러 자격증명을 갖도록 데이터 모델을 열어 둠
	- 구현 전 정의 필요(작성 예정): 식별자(subject_id), 자격증명(credential), 프로필(profile) 상태 모델. 계정 연결, 복수 토큰 병합, 충돌, 철회, 부분 실패, 재시도와 idempotency, 익명 통계와 옵트인 프로필 분리 규칙 포함
- **아동과 학교 사용 정책 (확인 필요)**
	- 전제: RFP의 학교, 문화원 등 공공 체험과 교육 활용 ([[ref_제안요청서#3. 활용방안 예시]])
	- 법무 검토 후 확정 항목: 보호자와 기관 동의, 보관 기간, 열람과 삭제권, 기관별 접근 제한과 테넌트 분리, 탈 디자인 저장 최소화 (임의 추정 금지)
- **리플레이 영상 파기 트리거**: 5장 아. 리플레이 영상 파이프라인은 트리거를 새로 정의하지 않고, 세션 데이터 표(2장 가)의 파기 시점을 집행하는 구현만 기술
- **세부 정책 (작성 예정)**: 보관 데이터의 보관 기간 잠정값은 법무 검토 후 확정, 임의 추정 금지

## 나. AI 시스템

콘텐츠 AI 모듈. 각 모듈은 공통 사양 AI 모듈 명세 항목을 따름 ([[시범콘텐츠 공통 사양#가. AI 시스템]]).

### 1) 탈 3D 변환 모델

- **역할**: 2D 탈 도안을 AR 착용용 3D 탈 모델로 변환 (Step 3)
- **입력과 출력**: 입력은 2D 탈 도안(Step 2 산출, 형식 확인 필요), 출력은 3D 탈 모델(glTF 등 AR 렌더 형식, 확인 필요)
- **모델 확보**: 2D→3D 생성 모델. 자체 학습 부담이 커 외부 API와 사전학습 모델 우선 검토 (후보 조사 확인 필요)
- **판정과 성능 기준**: 변환 성공률, 전통 정합성(가드레일 연계), 변환 시간(변환 대기 상태 조회 주기 연동, 구현 단계 확정)
- **적용**: Step 3 서버 백그라운드 생성, 대기 화면 상태 조회 동기화
- **실패, 한계, 복구**: 변환 모델 미확보 시 대안 검토 (확인 필요). 변환 실패나 가드레일 한도 초과 시 Step 3 sub-step 실패 분기로 대체 처리(fallback)함. 재시도 한도는 운영 파라미터
- **데이터와 평가**: 배역 탈 양식 레퍼런스(3장 나. 탈과 춤사위 고증), 변환 품질 평가 기준 (작성 예정)

### 2) 포즈 추정과 채점

- **역할**: 카메라 영상에서 자세 추정. 춤사위 자세 일치도와 타이밍 채점 (Step 4)
- **입력과 출력**: 입력은 카메라 영상 프레임, 출력은 포즈 키포인트와 자세 일치도, 타이밍 점수, 신명 게이지 값
- **모델 확보**: 실시간 포즈 추정은 사전학습 모델과 온디바이스 SDK 우선 검토 (후보 확인 필요). 채점 로직은 레퍼런스 동작 대비 자체 규칙
- **판정과 성능 기준**: 포즈 추정 정확도, 채점 임계와 가중치(3장 라. 채점 체계, 구현 확정), 실시간 처리 지연(프레임률)
- **적용**: Step 4 실시간 카메라 입력 처리. 서버/온디바이스 여부 확인 필요
- **실패, 한계, 복구**: 포즈가 안 잡히거나 신뢰도가 낮으면 재시도 안내. 지연되거나 계속 실패하면 해당 구간 점수는 보류하고, 터치 미입력 타임아웃(사람이나 포즈 미검출) 시 Step 7. Step 4 sub-step 실패 분기와 연결
- **데이터와 평가**: 춤사위 레퍼런스 모션(3장 바. 콘텐츠 자산), 채점 정확도 검증 방법 (작성 예정)

### 3) AI 가드레일 (전 Step 입출력 적용)

- **역할**: 탈 디자인 입력, 3D 변환물, 기념 사진과 리플레이 영상 출력의 안전성과 전통 정합성 검사 (3장 마. 가드레일)
- **입력과 출력**: 입력은 검사 대상(이미지, 3D, 영상), 출력은 통과 또는 차단 판정과 사유
- **모델 확보**: 부적절 콘텐츠 분류와 전통 왜곡 판정. 외부 가드레일 API와 자체 기준을 조합 검토 (확인 필요)
- **판정과 성능 기준**: 차단 정확도(오탐과 미탐), 재생성 한도, 검사 지연. 정량은 구현 확정
- **적용**: 입력(Step 2)과 출력(Step 3, Step 5) 검사. 공용 기능 'AI 가드레일' 호출, 적용 3지점 준용 ([[시범콘텐츠 공통 사양#나. 가드레일 적용 3지점]])
- **실패, 한계, 복구**: Step별로, 입력(Step 2)은 부적절 도안 차단 후 재입력, 출력(Step 3)은 변환물 위반 시 재생성(한도 초과 시 대체 처리), 출력(Step 5)은 영상 위반 시 사진만 제공하고 전부 위반 시 에러. 재시도와 재생성 한도는 운영 파라미터 (구현 확정)
- **데이터와 평가**: 부적절 도안과 전통 왜곡 판정 기준 데이터 (작성 예정)

## 라. 백엔드

서버 구성 요소를 책임별로 정리함. 각 요소는 역할을 적고, 구현 요건이나 주요 상태, 참조를 필요에 따라 덧붙임.

### 1) API (키오스크 ↔ AI 서버)

- **역할**: 키오스크와 AI 서버 간 요청과 응답 중계. 카메라 자산, 생성물, 전송 상태가 오가는 신뢰 경계
- **요건**: 요청과 응답 규격, 프로토콜(확인 필요), 인증 방식(기기 자격/토큰 또는 mTLS 등 확인 필요), 전송 보안(TLS), 개인정보 로깅 제외

### 2) 세션 관리

- **역할**: 세션 라이프사이클과 상태 저장
- **요건**: 기본 키오스크당 1세션 가정 (동시 세션 수 확인 필요)
- **참조**: 2장 가. 세션

### 3) 진행 제어 (상태 머신)

- **역할**: Step 순차 진행 + 각 Step 분기와 에러 분기 제어
- **주요 상태**: 동의 대기와 거부, 영상 동의 거부, 변환 실패, 전송 거부, 타임아웃, 대체 처리(fallback), 정리와 파기, 리셋
- **참조**: 분기 상세는 2장 다. Step별 명세의 각 Step 분기와 실패 sub-step

### 4) 결과물 조립과 저장소

- **역할**: 3D 모델, 기념 사진, 리플레이 영상을 임시 저장하고 보관과 파기 정책 집행
- **참조**: 2장 가. 세션

### 5) 리플레이 영상 합성과 인코딩

- **역할**: AR 탈 합성, 하이라이트, 음원
- **참조**: 상세는 5장 아. 리플레이 영상 파이프라인

### 6) 개인정보 처리 집행

- **역할**: 연락처, 영상, 사진을 임시 저장하고 즉시 파기
- **참조**: 5장 가. 개인정보 처리 정책

## 마. 외부 서비스 연동

- **결과물 전송 서비스 (사진과 영상 통합)**
	- 채널: SMS 링크 1채널. 기념 사진과 리플레이 영상을 한 결과 페이지로 묶어 발송. 연락처를 거부하면 결과물을 전송하지 않음
	- 결과 페이지: 만료형 서명 URL(48시간)로 제공. 영상은 페이지 안에서 스트리밍하거나 내려받음. 만료 전 재접근 허용
	- 저장과 파기: 저장 제공자, URL 만료, 파기 트리거(48시간 만료) 명세 필요 (세션 표 사진과 영상 임시 보관 정책과 정합)
	- 제공자와 스토리지, 연동 방식 확인 필요
- **AI API (외부 모델 사용 시)**: 3D 변환, 포즈 추정, 가드레일 등 외부 모델 호출 (5장 나)
	- 호출 정책: 호출 래퍼와 재시도는 공용 기능 준용
	- 제공자와 요금 확인 필요

## 바. 클라이언트 UI (키오스크 앱)

- **공통 UI 컴포넌트** (여러 화면 재사용)
	- 말뚝이 진행 호스트 렌더러 (3장 가. 진행 호스트)
	- AR 렌더러 (3D 탈 오버레이)
	- 탈 디자인 도구 (3장 다. 탈 디자인)
	- 카메라 프리뷰와 촬영
	- 신명 게이지

## 아. 리플레이 영상 파이프라인 (구현 요건)

숏폼 리플레이 영상의 소재 확보부터 제공과 파기까지의 구현 요건임. 클라이언트(녹화), 백엔드(합성과 인코딩), 외부 서비스(결과 페이지 호스팅)에 걸침. 정량값(해상도, 비트레이트, 길이, 코덱, 유효기간)은 구현 단계 확정, 임의 추정 금지.

### 1) 처리 단계 (순차)

1. **소재 녹화 (Step 4)**: AR 탈 합성 화면(탈 오버레이된 카메라 화면)을 클라이언트에서 프레임 캡처해 임시 녹화. 사후 재합성 부담을 피하려 렌더된 화면을 그대로 확보. 메모리와 임시 버퍼에만 보관, 디스크 영속화 금지
2. **하이라이트 선별**: 동작 채점 기록(자세 점수와 신명 게이지)으로 고득점 구간 자동 선별. 선별 기준과 구간 길이는 운영 파라미터
3. **합성과 편집 (Step 5)**: 선별 하이라이트와 기념 포즈를 이어 붙이고, 세로형(9:16) 프레임, 워터마크, 신명 게이지 점수와 등급 스탬프를 오버레이. 음원 믹싱
4. **인코딩**: 세로형 MP4로 인코딩, SNS 업로드 호환 우선. 키오스크 부하를 고려해 서버 측 인코딩 권장
5. **제공과 다운로드**: 인코딩 완료물을 기념 사진과 함께 단일 결과 페이지로 묶어 서버 임시 저장소에 보관함. 결과 페이지 발급과 전송(만료형 서명 URL, SMS 발송)은 5장 마. 외부 서비스 연동, 파기 시점은 2장 가. 세션 데이터 표가 정본임. 본 단계는 그 시점을 집행하는 구현만 담당함. 48시간 만료 시 파기, 파기 실패 시 운영 알림

### 2) 전 단계 공통 사항

위 순차 단계 전체에 동시에 걸치는 항목임.

- **가드레일**: 제공 전 최종 영상에 출력 가드레일 검사 (부적절과 전통 왜곡, 3장 마. 가드레일)
- **대기와 실패 처리**: 인코딩 동안 상태 조회로 동기화한 대기 화면 표시. 실패 시 fallback으로 영상 생략하고 사진만 제공 (에러/fallback 공용 기능)
- **음원**: 무저작권, 자체 제작, AI 생성 풍물 장단 음원만 사용 (합성과 편집 단계에 믹싱, SNS 공개 공유 전제로 라이선스 리스크 제거). 외부 라이선스 음원 확보가 어려우면 AI 생성 음원을 최종 안전장치로 사용
