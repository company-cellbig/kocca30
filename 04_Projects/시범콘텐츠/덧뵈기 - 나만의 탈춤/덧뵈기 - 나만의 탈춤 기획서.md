> 덧뵈기(탈춤)를 소재로, 유저가 자기가 디자인한 탈을 쓰고 풍물 장단에 맞춰 춤사위를 따라 추며 자기만의 탈춤 한 판을 완성하는 AR 체험 시범콘텐츠의 개발 기획서.

# 1. 개요

- **콘텐츠 정의**: 덧뵈기(탈춤)를 소재로 한 증강현실(AR) 탈춤 체험 키오스크 콘텐츠. 유저가 만든 탈을 쓰고 탈춤을 직접 따라 추는 능동 체험임
- **소재**: 남사당놀이 탈놀음 덧뵈기
- **목표 경험**: 덧뵈기의 전통 골격(풍물 장단, 전승 춤사위)은 고정하고, 유저가 디자인한 탈과 직접 춘 춤으로 자기만의 탈춤을 완성함
- **핵심 메커닉**: 춤사위의 자세 일치도와 풍물 장단 타이밍을 실시간 채점해 신명(興) 게이지로 보상함
- **산출물**: 맨 얼굴의 유저 본인과 유저가 디자인한 탈을 쓴 2D 탈 캐릭터가 나란히 포즈한 기념 사진. 테두리 프레임을 두르고 신명 게이지 점수와 등급을 스탬프로 표기함

# 2. 전체 플로우

1회 완결로 자기만의 탈춤 한 판을 체험하고 기념물을 남기는 세션임. Step 1 인트로 → Step 2 탈 디자인 → Step 3 3D 변환과 대기 화면(병행) → Step 4 AR 착용과 춤사위 따라하기(핵심) → Step 5 기념 촬영과 생성(병행) → Step 6 결과물 전송 → Step 7 종료와 리셋.

- **큰 분기**: 대부분 이탈(미동의, 터치 미입력 타임아웃)로 Step 7 직행, 변환과 생성 실패는 에러와 fallback 후 Step 7
- **병행**: Step 3에서 백그라운드 3D 변환과 포그라운드 대기 화면이 동시 진행, Step 5에서 백그라운드 기념 사진 생성과 포그라운드 대기가 동시 진행. 둘 다 상태 조회로 동기화함
- **파기**: Step 6 전송 후 연락처 즉시 파기, Step 7 종료 시 세션 임시 데이터 파기

# 3. 공용 시스템

여러 sub-step에 걸쳐 쓰이는 시스템과 횡단 정책, 설계 골격임. 배열은 많이 의존받는 기반부터 둠.

## 가. 세션 데이터

### 1) 역할과 목적

한 세션이 만드는 데이터를 담는 시스템. 전 Step이 같은 상태를 공유하게 하고, 데이터 종류별 보관과 파기 관리를 용이하게 함.

### 2) 동작과 규칙

본 콘텐츠의 세션 저장 데이터를 분류, 값, 수명으로 정리함. 표는 어떤 값이 들어가는지까지만 적고, 타입과 저장 스키마 같은 구현 모델은 설계 단계에서 정함. 개인정보 민감 데이터(영상 피드, 기념 사진, 휴대폰 번호)에 최소 보관 원칙을 적용함.

| 데이터 | 분류 | 들어가는 값과 구성 | 수명 | 비고 |
|---|---|---|---|---|
| 세션 ID | 시스템 | 세션마다 부여되는 고유 식별자 | 휘발 (세션 종료 시 파기) | Step 1에서 생성 |
| 동의 기록 | 시스템 | 약관 버전 + 동의 일시 + 동의 항목(필수: 카메라 촬영) | 보관 (기간은 규정 검토 후 확정) | 약관 버전 체계 운영 결정 |
| 탈 디자인(2D) | 콘텐츠 | 유저 2D 탈 도안 | 별도 저장소 보관 (파기 시점 미정, 규정 검토 후 확정) | Step 2 산출 |
| 3D 탈 모델 | 콘텐츠 | 변환된 3D 탈 자산 | 별도 저장소 보관 (파기 시점 미정, 규정 검토 후 확정) | Step 3 산출 |
| 동작 채점 기록 | 콘텐츠 | 자세 일치도와 타이밍 점수, 신명 게이지 | 익명 통계는 보관, 식별 원본은 세션 종료 시 파기 | Step 4 산출 |
| 기념 사진 | 콘텐츠 | 유저와 2D 탈 캐릭터가 동반 포즈한 사진(점수와 등급 스탬프) | 결과 페이지 임시 보관. 발행분은 48시간 만료 시 파기, 미발행분은 세션 종료 시 파기 | Step 5 산출 |
| 영상 피드 | 개인정보 | 카메라 원본 스트림(AR 얼굴 추적, 포즈 추정, 기념 촬영 입력) | 메모리 임시, 처리 직후 파기 | 디스크 저장 금지 |
| 휴대폰 번호 | 개인정보 | 유저 연락처(SMS 발송용) | 휘발 (발송 후 즉시 파기, 거부 시 즉시) | Step 6 전송 동의 시 임시 저장 |

- **Step별 세션 동작**: Step 1 생성, Step 2~Step 6 갱신, Step 7 종료와 임시 데이터 파기와 리셋
- **저장 위치**: 영상 피드와 휴대폰 번호는 메모리나 임시 버퍼에만 두고 디스크 영속화와 로그 기록을 하지 않음. 기념 사진은 전송용 서버 임시 저장소에만 두고 로그 기록을 하지 않음. 탈 디자인과 3D 탈 모델은 재사용과 재변환 비용 회피, 품질 분석을 위해 별도 저장소에 보관함
- **파기 방식**: 파기 시점이 되면 메모리를 명시적으로 덮어쓰는 방식으로 즉시 파기함

## 나. 개인정보 처리

### 1) 역할과 목적

유저 연락처와 얼굴, 신체가 담긴 데이터를 다루는 시스템. 필요한 최소 시간만 보관하고 즉시 파기해 개인정보 리스크를 줄이는 게 목적. 카메라로 얼굴과 신체를 촬영해 덜미(꼭두각시)보다 개인정보 민감도가 높음.

### 2) 동작과 규칙

- **개인정보 범위**
	- 휴대폰 번호 (전송용)
	- 얼굴과 신체 영상 (영상 피드. AR 얼굴 추적, 포즈 추정, 기념 촬영에 쓰임)
	- 기념 사진 (분류는 콘텐츠지만 얼굴과 신체가 담긴 결과물이라 개인정보로 병행 처리함)
- **동의 범위**
	- 필수: 카메라 촬영 (AR 얼굴 추적, 포즈 추정, 기념 사진 촬영)
	- 고지: 기념 사진은 얼굴과 신체가 담긴 결과물임. 이를 생성하고 저장하며 결과 페이지로 48시간 제공하는 처리를 개인정보 수집과 이용 안내에 포함함. 정확한 안내 문구와 동의 범위는 규정 검토 후 확정함
- **휴대폰 번호 처리**: 발송에 필요한 동안만 보관하고 영구 저장이나 로그 기록은 하지 않음. 발송 응답 수신 직후(성공, 실패, 거부 무관) 파기하고, 세션 종료 시 잔류분이 있으면 파기함(백스톱)
- **영상 피드 처리**: 메모리 임시 처리 후 즉시 파기함. 디스크 저장이나 로그 기록을 하지 않음
- **재방문 연속성**: 학습 프로필, 이어하기, 학습 토큰, 콘텐츠 횡단 누적은 2차연도 전방 설계로 두며 1차연도는 익명 1회로 운영함
- **세부 정책 (작성 예정)**: 보관 기간 잠정값은 규정 검토 후 확정하며 임의 추정하지 않음

## 다. 탈과 춤사위 고증 (공통 레퍼런스)

### 1) 역할과 목적

전통 탈 양식과 춤사위의 전통 기준을 정의하는 설계 레퍼런스. 직접 생성하지는 않고 기준만 정의함. 여러 시스템(탈 디자인, 포즈 채점, 가드레일)이 디자인 시작점이나 전통 정합성 판정 기준으로 공유하는 공통 입력 기반이라 맨 앞에 둠.

### 2) 동작과 규칙

- **탈**: 덧뵈기 배역 탈(말뚝이, 양반, 먹중, 샌님 등) 양식을 디자인 레퍼런스로 활용함 (목록과 종수 확인 필요, 소재 원본 보강 예정)
- **춤사위**: 따라 추기 대상 동작과 풍물 장단의 고증 매핑 (작성 예정, 고증 자문 연계). 포즈 채점의 기준 동작이 됨
- **시각 정체성**: 탈 양식과 질감의 전통 정합성 유지 (작성 예정)

## 라. AI 가드레일

### 1) 역할과 목적

입력과 생성물의 안전과 전통 정합성을 검사하는 횡단 시스템. 유해하거나 전통을 왜곡한 콘텐츠가 유저에게 노출되지 않게 막는 게 목적.

### 2) 입력과 출력

- **입력**: 검사 대상(유저 탈 도안, 변환 3D 탈 모델, 생성 기념 사진, 사전 제작 자산)
- **출력**: 통과나 차단 판정과 사유. 위반 시 재생성이나 차단 트리거 실행

### 3) 동작과 규칙

적용 지점을 셋으로 나눔. 전통 왜곡과 정합성 판정 기준은 탈과 춤사위 고증을 따름.

- **사전(운영 전 제작)**: 탈 템플릿과 프리셋, 춤사위 모션 레퍼런스, 말뚝이 대사 등 사전 제작 자산 검수
- **런타임 입력(Step 2)**: 부적절 탈 도안 차단 후 재입력 안내. 재입력 한도 3회(잠정) 초과 시 에러와 fallback 후 Step 7. 반복 위반 세부 정책(차단 누적 등)은 작성 예정
- **런타임 출력(Step 3, Step 5)**: 변환 3D 탈 모델과 생성 기념 사진 검사. 위반 시 재생성 한도 2회(잠정)까지 재생성하고, 한도 초과 시 위험 생성물을 파기하고 에러와 fallback 처리

### 4) 기술 요건

- **검사 범위**: 이미지(도안, 기념 사진)와 3D(변환 탈 모델)를 검사하므로 이미지 모더레이션과 3D 형상 검사가 필요함
- **접근 (결정 필요)**: 범용 유해물은 외부 안전 API로 거르고, 전통 정체성 왜곡처럼 범용 API가 못 잡는 판정은 자체 규칙이나 도메인 분류기로 보완함. API 대 자체 구축 비중은 후보 조사 후 확정
- **품질 기준**: 무인 운영이라 미탐(유해물 통과)이 오탐보다 위험하므로 미탐을 낮추는 보수적 임계로 잡음. 오탐율, 미탐율, 임계 목표는 검증 데이터 확보 후 정량 확정
- **지연 예산**: 런타임 입력과 출력 검사는 유저 대기 구간이라 검사 응답 지연 상한이 필요함(정량 미정)

## 마. 화면 타임아웃

### 1) 역할과 목적

한 화면에 장시간 체류하는 것을 방지하는 시스템.

### 2) 동작과 규칙

- **처리**: 한 화면에서 N초(예: 60초) 이상 체류하면 다음 단계로 진행함. 창작과 촬영 화면(탈 디자인, 기념 촬영)은 작업 시간이 길어 5분(잠정)으로 상향함
- **예외**: 필수 입력, 호스트 대화, 대기, 팝업 화면은 미적용

## 바. 터치 미입력 타임아웃

### 1) 역할과 목적

유저 이탈에 대응해 방치된 세션을 정리하여 키오스크 회전율을 높이는 시스템.

### 2) 동작과 규칙

- **처리**: 한 화면에서 N초(예: 45초) 이상 터치나 동작 입력이 없으면 이탈로 보고 종료 처리함. 카메라와 모션 화면은 사람이나 포즈 미검출을 이탈 기준으로 함
- **호스트 발화 화면**: 말뚝이 발화 종료나 스킵 후부터 측정을 시작함(발화 중에는 멈춤)
- **예외**: 대기, 감상 화면은 미적용

## 사. 외부 서비스 호출 래퍼

### 1) 역할과 목적

외부 서비스 호출(AI, 3D 변환, 이미지 생성, SMS)을 감싸는 공통 계층. 재시도와 타임아웃 대응을 한 곳에 모아, 매 호출마다 장애 처리를 따로 짜지 않게 함.

### 2) 동작과 규칙

- **재시도**: 2회(잠정)
- **호출 타임아웃**: SMS 10초, 3D 변환과 이미지 생성 60초(모두 잠정)
- **한도 초과**: 재시도 한도를 넘긴 실패는 에러와 fallback으로 넘김

## 아. 에러와 fallback

### 1) 역할과 목적

콘텐츠 전반의 실패를 받아 처리하는 단일 종료 경로. 무인 운영에서 오류가 방치되지 않도록 세션을 안전하게 마무리하는 게 목적.

### 2) 동작과 규칙

- **진입 조건**: 재시도 한도를 넘긴 외부 호출 실패(AI, 3D 변환, 이미지 생성, SMS), 가드레일 재생성 한도 초과, 생성 파이프라인 실패, 전송 영구 실패
- **공통 처리**: 유저에게 안내 팝업을 띄우고 종료 처리(Step 7)함
- **유형별 처리**
	- 생성이나 변환 실패, 가드레일 한도 초과: 사과 후 Step 7. 미완성이나 위반 생성물은 파기
	- 전송 영구 실패: 사과 후 Step 7. 기념 사진은 이미 생성됐으므로 결과 페이지는 유지하고, 후속 조치를 위해 운영에 알림
- **운영 알림**: 후속 조치가 필요한 실패(전송 실패 등)나 연속 3회 실패 또는 5분 오류율 10%(잠정) 임계 도달 시 운영에 알림

## 자. 말뚝이 진행 호스트

### 1) 역할과 목적

양반을 놀리는 탈춤 풍자의 화자로, 관객과 대거리하는 전통 기능을 진행 안내와 추임새로 계승하는 전 Step 진행 호스트. 탈 디자인부터 춤사위, 기념 촬영까지 한 목소리로 잇고 덧뵈기의 전통 정체성을 살림.

### 2) 동작과 규칙

- **범위**: 전 Step 진행 호스트
- **재담과 추임새**: 춤사위 채점 피드백을 추임새로 전달함. 게이지 미달 시 눙치며 마무리함
- **발화 방식**: TTS 음성으로 대사를 재생하고 같은 대사를 화면에 텍스트로 표시함. 발화 중 다음 버튼을 누르면 발화를 중단하고 다음으로 진행함
- **타임아웃 연동**: 발화 중에는 터치 미입력 타임아웃을 멈추고, 발화가 끝난 뒤 측정을 시작함
- **세부 페르소나 (작성 예정)**: 말투, 어휘, 반응 패턴. 대사 적용 방법은 논의 후 추가 예정
- **고증 주의**: 말뚝이 배역 해석은 일반 탈춤 문헌 수준의 추정임. 소재 원본 작성 후 검증함(확인 필요)

### 3) 필요 리소스

- 말뚝이 호스트 캐릭터(탈춤 양식, 애니메이션 가능하게 제작, 기념 사진 탈 캐릭터와 시각 정체성 일치)
- 동작 애니메이션 세트(대기, 인사, 말하기, 제스처)
- 말뚝이 TTS 보이스
- 추임새와 대사 (제작 방식 확인 필요)

### 4) 실패와 복구

아바타 렌더나 TTS 재생 실패 시 음성과 애니메이션 없이 텍스트 박스로만 진행함(대사는 표시하고 세션은 계속).

# 4. 개별 시스템

공용이 아닌 Step별 진행과 그 안의 생성, 변환, 채점 엔진임. Step 진행 순으로 두고, 엔진은 해당 Step 안에 둠. UI와 백엔드 진행 단계는 진행과 분기만 적고, 독립 명세가 필요한 엔진만 자기 완결 명세를 붙임.

## 가. Step 1. 인트로 (시작 + 동의)

### 1) 백엔드

- **진행**: 신규 세션 생성(익명)

### 2) UI(시작 화면)

- **진행**: 시작하기 버튼 터치 시 다음 단계 진행. 시작 화면은 Step 7 복귀 화면과 동일한 대기 상태임

### 3) UI(가이드 화면)

- **진행**: 진행 흐름 안내, 다음 버튼 터치 시 다음 단계 진행
- **적용 시스템**: 화면 타임아웃, 터치 미입력 타임아웃

### 4) UI(동의 약관 화면)

- **진행**: 약관 표시, 동의하고 시작하기 터치 시 다음 단계 진행(화면 타임아웃 미적용)
	- 분기: 그만두기 터치, 카메라 촬영 미동의, 또는 터치 미입력 타임아웃 시 Step 7 직행
- **적용 시스템**: 터치 미입력 타임아웃

### 5) 백엔드

- **진행**: 동의 기록 저장(세션 ID, 약관 버전, 타임스탬프, 동의 항목)

## 나. Step 2. 탈 디자인

### 1) UI(탈 디자인 도구 화면)

- **진행**: 도안 입력 수집, 경량 3D 미리보기를 실시간 병행 표시, 확정 시 다음 단계 진행
	- 분기: 화면 타임아웃(창작 화면 5분, 잠정) 발동 시 현재 도안을 확정 저장하고 다음 단계로 정상 진행
	- 분기: 터치 미입력 타임아웃 발동 시 이탈로 보고 Step 7 직행
- **적용 시스템**: 화면 타임아웃, 터치 미입력 타임아웃, AI 가드레일(입력 도안 검사)

### 2) 백엔드

- **진행**: 세션에 2D 탈 도안 저장

### 3) 탈 디자인 도구 (개별 시스템)

#### 가) 역할과 목적

전통 배역 탈에서 출발하는 드로잉형 도구로 유저 탈 도안을 받는 시스템. 전통 정합성과 디자인 속도를 함께 잡는 게 목적.

#### 나) 입력과 출력

- **입력**: 유저 드로잉(터치)
- **출력**: 2D 탈 도안(3D 변환 입력, 형식 규격 확인 필요)

#### 다) 동작과 규칙

- **디자인 방식**: 배역 탈 템플릿과 프리셋을 시작점으로 제공하고 그 위에 자유롭게 그림
- **캔버스**: 충분히 높은 해상도 드로잉형. 저해상도 도트 그리드는 쓰지 않음(해상도값 디자인 단계 확정)
- **색**: 오방색 5정색(청, 적, 황, 백, 흑)을 기본 팔레트로, 단청 계열 보조색을 더해 전통 색감을 통일함. 정확한 색 수와 보조색은 디자인 단계 확정
- **대칭**: 좌우 대칭(미러) 기본 제공, 해제 토글로 비대칭 허용
- **보조 도구**: 도형 그리기와 전통 문양 스탬프로 비숙련자를 보조함
- **실시간 3D 프리뷰**: 그린 도안을 3D 탈에 입힌 경량 미리보기를 실시간 표시함(디자인 확인용). 정식 변환은 Step 3
- **설계 차용**: 모여봐요 동물의 숲 마이 디자인의 대칭과 제한 팔레트, 스탬프, 실시간 프리뷰 방식을 차용함. 저해상도 도트(32x32)는 탈에 안 맞아 드로잉형을 택함

#### 라) 기술 요건

출력 규격(드로잉 결과를 3D 변환 입력으로 잇는 형식)은 작성 예정. UI 컴포넌트 구현은 UI 문서가 다룸.

#### 마) 필요 리소스

탈 디자인 템플릿과 프리셋(배역 탈 기반, 제작 방식 확인 필요).

#### 바) 실패와 복구

입력 도안은 AI 가드레일 검사를 받음. 부적절 도안 검출 시 재입력(한도 3회, 잠정), 한도 초과 시 에러와 fallback.

## 다. Step 3. 3D 변환 + 대기 화면 (병행)

백그라운드 변환과 포그라운드 대기가 동시 진행되고 상태 조회로 동기화됨. 3D 변환은 백그라운드라 화면이 없음.

### 1) 백그라운드: 3D 변환

- **변환 파이프라인**
	1. 백엔드: 3D 변환 작업 큐 등록
	2. AI 3D 변환: 2D 도안을 정식 고품질 3D 탈 모델로 변환
	3. AI 가드레일: 변환 생성물 검사
		- 분기: 위반 시 2로 재생성(한도 2회, 잠정). 한도 초과 시 상태 `failed`
	4. 백엔드: 통과한 3D 탈 모델 저장
- **실패(변환 단계 공통)**: 변환 호출 실패 시 재시도 2회(잠정) 후 `failed` 전환(에러와 fallback)
- **상태 머신**: `converting` / `completed`(가드레일 통과분만) / `failed`(변환 실패 또는 가드레일 한도 초과)

### 2) 포그라운드: 변환 대기 화면

- **UI(변환 대기 화면)**: 변환 대기 콘텐츠 노출(덧뵈기 준비 과정 영상 등), 백엔드 상태 조회(주기 2초, 잠정). 두 타임아웃 미적용
	- 분기: `converting` → 대기 유지 / `completed` → 즉시 Step 4 / `failed` → 에러와 fallback 후 Step 7
	- 분기: 상태 조회 무응답이 임계(연속 무응답 상한, 잠정)를 넘으면 `failed`로 처리해 에러와 fallback 후 Step 7. 대기 화면은 두 타임아웃 미적용이라 무한 대기를 막는 별도 탈출임

### 3) 탈 3D 변환 (개별 시스템)

#### 가) 역할과 목적

2D 탈 도안을 AR 착용용 3D 탈 모델로 변환하는 런타임 엔진. Step 2 경량 미리보기와 달리 정식 고품질 변환을 만드는 게 목적.

#### 나) 입력과 출력

- **입력**: 2D 탈 도안(형식 확인 필요)
- **출력**: 3D 탈 모델(glTF 등 AR 렌더 형식, 확인 필요)

#### 다) 동작과 규칙

키오스크 부하를 고려해 서버 백그라운드에서 변환하고, 대기 화면이 상태 조회로 동기화함. 전통 정합성은 AI 가드레일을 거쳐 탈과 춤사위 고증 기준으로 판정함.

#### 라) 기술 요건

2D에서 3D 생성 모델. 자체 학습 부담이 커 외부 API와 사전학습 모델을 우선 검토함(후보 조사 확인 필요). 판정 기준은 변환 성공률, 전통 정합성, 변환 시간(대기 조회 주기와 연동). 품질 평가 기준과 평가 데이터는 작성 예정. 변환 모델 미확보 시 대안 검토(확인 필요).

#### 마) 실패와 복구

변환물은 출력 가드레일 검사를 받음. 호출 실패나 가드레일 미통과는 변환 파이프라인의 `failed` 처리(에러와 fallback)로 이어짐.

## 라. Step 4. AR 착용 + 춤사위 따라하기 (핵심 체험)

### 1) UI(AR 춤사위 체험 화면)

- **진행**
	1. 3D 탈을 AR로 착용(카메라 얼굴 추적, 탈 오버레이)
	2. 춤사위 가이드 제시와 유저 동작 캡처
	3. 게이지 결과 연출(달성 시 환호 사운드 보상, 미달 시 말뚝이가 눙치는 마무리)
	- 분기: 화면 타임아웃 발동 시 체류 상한으로 보고 Step 5로 정상 진행
	- 분기: 터치 미입력 타임아웃(사람이나 포즈 미검출)이면 이탈로 보고 Step 7 직행
- **적용 시스템**: 화면 타임아웃, 터치 미입력 타임아웃, 포즈 채점과 신명 게이지, 말뚝이 진행 호스트(실시간 추임새)

### 2) 포즈 채점과 신명 게이지 (개별 시스템, 핵심 메커닉)

#### 가) 역할과 목적

카메라 영상에서 자세를 추정해 춤사위 자세 일치도와 타이밍을 실시간 채점하고 신명(興) 게이지로 시각화, 달성 시 보상하는 핵심 루프. 유저가 직접 춘 춤에 즉각 피드백을 주는 게 목적.

#### 나) 입력과 출력

- **입력**: 카메라 영상 프레임, 풍물 장단 타이밍
- **출력**: 포즈 키포인트, 자세 일치도, 타이밍 점수, 신명 게이지 값, 동작 채점 기록

#### 다) 동작과 규칙

- **채점 입력**: 자세 일치도(포즈 추정 기반)와 풍물 장단 대비 타이밍. 기념 촬영(Step 5)은 채점하지 않음
- **채점 기준(잠정)**: 일치도 임계 70%, 자세 대 타이밍 가중치 7 대 3. 사용성 검증 후 조정함
- **게이지와 보상**: 채점이 쌓이면 게이지가 오름. 누적 80%(잠정) 달성 시 환호 사운드(군중 추임새, 박수)로 보상하고, 미달 시 말뚝이가 눙치며 마무리함
- **난이도 곡선(잠정)**: 초반 60%에서 후반 75%로 단계 상향
- **종합 점수와 등급 출력**: 게이지 종합 점수와 등급은 Step 5 기념 사진 스탬프로 표기함
- **학습 진척**: 1차연도는 당회 채점만 함. 재방문 진척 누적(향상 곡선, 약점 동작 피드백)은 2차연도 전방 설계로 둠
- **세부 설계 (작성 예정)**: 가중치, 게이지 임계, 미달 처리, 향상 곡선 산출

#### 라) 기술 요건

실시간 포즈 추정은 사전학습 모델과 온디바이스 SDK를 우선 검토함(후보 확인 필요). 채점 로직은 레퍼런스 동작 대비 자체 규칙. 판정 기준은 포즈 추정 정확도, 채점 임계와 가중치, 실시간 처리 지연(프레임률). 채점 정확도 검증 방법과 서버 대 온디바이스 여부는 확인 필요.

#### 마) 필요 리소스

- 춤사위 모션 레퍼런스(따라 추기 대상과 채점 기준, 모캡 등 확인 필요, 고증 자문)
- 풍물 장단 음원(타이밍 기준, 무저작권이나 자체, AI 생성)
- 환호와 추임새 사운드(게이지 달성 보상, 제작 방식 확인 필요)

#### 바) 실패와 복구

포즈가 안 잡히거나 신뢰도가 낮으면 재시도 안내(한도 3회, 잠정). 3회 초과 시 해당 구간 점수를 보류하고 다음 구간으로 진행함(채점 루프는 계속). 지연 시에도 해당 구간 점수를 보류함. 터치 미입력 타임아웃(사람이나 포즈 미검출) 시 Step 7.

## 마. Step 5. 기념 촬영 + 생성 (병행)

### 1) UI(기념 촬영 화면)

- **진행**
	1. 2D 탈 캐릭터(유저 탈을 쓰고 덧뵈기 탈옷을 입은)를 카메라 뷰에 라이브 합성, 유저가 그 옆에서 포즈
	2. 카운트다운 촬영(카운트다운 3초 잠정, 채점 없음, 촬영 횟수 3회까지 잠정)
	- 실패: 카메라에 사람이 안 잡히면 다시 서도록 안내
	- 분기: 유효 촬영 1회 이상인 채로 촬영 횟수 소진이나 촬영 타임아웃(10초, 잠정), 또는 화면 타임아웃(창작 화면 5분, 잠정)이면 생성으로 정상 진행
	- 분기: 유효 촬영 0회로 타임아웃되면 사진 생성을 생략하고 에러와 fallback 후 Step 7
	- 분기: 터치 미입력 타임아웃(사람이나 포즈 미검출)이면 Step 7 직행
- **적용 시스템**: 화면 타임아웃, 터치 미입력 타임아웃, 기념 사진 생성, AI 가드레일(생성 사진 검사)

### 2) 포그라운드: 생성 대기 화면

- **UI(생성 대기 화면)**: 생성 대기 표시, 백엔드 생성 상태 조회로 동기화
	- 분기: 생성 중이면 대기 유지, 완료면 Step 6으로 진행, failed면 에러와 fallback 후 Step 7
	- 분기: 상태 조회 무응답이 임계(연속 무응답 상한, 잠정)를 넘으면 failed로 처리해 에러와 fallback 후 Step 7

### 3) 기념 사진 생성 (개별 시스템)

#### 가) 역할과 목적

촬영본에 2D 탈 캐릭터를 재합성하고 신명 게이지 점수와 등급을 스탬프로 표기한 기념 사진을 만드는 시스템. 유저가 가져갈 한 판의 기념물을 만드는 게 목적.

#### 나) 입력과 출력

- **입력**: 카메라 촬영본, 유저 2D 탈 디자인(캐릭터 합성용), Step 4 신명 게이지 점수와 등급
- **출력**: 기념 사진(점수와 등급 스탬프)

#### 다) 동작과 규칙

라이브 화면은 포즈용 미리보기이고, 최종 저장본은 촬영본에 2D 탈 캐릭터를 고품질 재합성하고 테두리 프레임을 두른 뒤 신명 게이지 점수와 등급을 스탬프로 표기함. 사진 합성과 스탬프 오버레이는 키오스크 부하를 고려해 서버에서 진행함. 해상도와 파일 형식은 구현 시 확정.

#### 라) 필요 리소스

- 기념 사진 프레임(테두리)
- 점수와 등급 스탬프(신명 게이지 표기)
- 기념 사진용 2D 탈 캐릭터(유저 2D 탈을 얼굴에 합성하는 2D 캐릭터 몸과 포즈 컷, 3D 아님. 기본 1종과 포즈 컷 1종, 비율과 해상도 확인 필요)

#### 마) 실패와 복구

생성 기념 사진은 출력 가드레일 검사를 받음. 미통과나 재생성 한도 2회(잠정) 초과 시 위험물 파기, 재생성 실패 시 에러. 유효 촬영 0회 시 사진 생성을 생략하고 fallback.

## 바. Step 6. 결과물 전송

### 1) UI(결과물 미리보기 화면)

- **진행**: 결과물 미리보기
	- 분기: 화면 타임아웃 발동 시 URL 발급을 건너뛰지 않게 다음 단계(URL 발급)로 정상 진행
- **적용 시스템**: 화면 타임아웃

### 2) 백엔드

- **진행**: 기념 사진을 결과 페이지에 담고 만료형 서명 URL(48시간, 개발 중 조정) 발급

### 3) UI(연락처 입력과 전송 화면)

- **진행**: 연락처 입력과 전송 선택 수집(필수 입력 화면, 화면 타임아웃 미적용). 전송 버튼 탭이 곧 발송 동의, 받지 않기 탭이 전송 거부임(별도 동의 토글 없이 화면에 개인정보 수집과 이용 안내 문구 노출)
	- 연락처 형식 검사: 010으로 시작하는 11자리 숫자
	- 분기: 형식 검사 실패 시 팝업 안내 후 재입력. 실패 3회(잠정) 초과 시 Step 7 직행
	- 분기: 전송 동의(전송 탭)면 다음 단계(SMS) 진행
	- 분기: 전송 거부(받지 않기 탭)면 SMS 생략, 받은 연락처 있으면 즉시 파기, 미발행으로 Step 7
	- 분기: 터치 미입력 타임아웃(이탈)이면 연락처 즉시 파기, 전송 생략하고 Step 7
- **적용 시스템**: 터치 미입력 타임아웃

### 4) 외부 서비스(SMS)

- **진행**: 연락처 임시 저장 → 결과 페이지 링크 발송(SMS 1채널) → 발송 직후 연락처 즉시 파기
	- 분기(실패 유형별): 일시 장애는 재시도 2회(잠정), 수신 번호 영구 실패는 재입력 1회 허용 후 Step 7, 그 외 영구 실패는 사과 후 Step 7과 운영 알림
- **적용 시스템**: 외부 서비스 호출 래퍼, 에러와 fallback
- **파기**: 결과 페이지는 발행분 48시간 만료 시 파기(세션 종료와 무관), 미발행분은 세션 종료 시 파기. 연락처는 상태 무관 즉시 파기

## 사. Step 7. 종료와 리셋

### 1) UI(말뚝이 마무리 인사)

- **진행**: 말뚝이 마무리 인사

### 2) 백엔드

- **진행**: 세션 종료와 임시 데이터 파기(영상 피드, 남은 연락처). 결과 페이지는 SMS 발송분을 48시간 만료까지 유지하고 미발행분만 파기

### 3) UI(시작 화면)

- **진행**: 시작 화면 복귀(다음 유저 대기, Step 1과 공유)
