> 덧뵈기를 소재로, 유저가 자기가 디자인한 탈을 증강현실(AR)로 쓰고 풍물 장단에 맞춰 춤사위를 따라 추며 자기만의 탈춤 한 판을 완성하는 AR 체험 시범콘텐츠의 개발 기획서.

# 1. 개요

- **콘텐츠 정의**: 덧뵈기를 소재로 한 증강현실(AR) 탈춤 체험 키오스크 콘텐츠
- **소재**: 남사당놀이 탈놀음 덧뵈기
- **목표 경험**: 덧뵈기의 전통 골격인 풍물 장단과 전승 춤사위는 고정하고, 유저가 디자인한 탈을 쓰고 춤사위를 직접 따라 추어 자기만의 탈춤 한 판을 완성함
- **핵심 메커닉**: 춤사위 자세 일치도와 풍물 장단 타이밍을 실시간 채점해 신명 게이지로 보상함
- **산출물**: 맨 얼굴의 유저와 유저가 디자인한 탈을 쓴 2D 탈 캐릭터가 나란히 포즈한 기념 사진. 테두리 프레임을 두르고 신명 게이지 점수와 등급을 스탬프로 표기함

# 2. 전체 플로우

1회 완결로 자기만의 탈춤 한 판을 체험하고 기념물을 남기는 세션임. Step 1 인트로 → Step 2 탈 디자인 → Step 3 3D 변환과 대기 화면(병행) → Step 4 AR 착용과 춤사위 따라하기(핵심) → Step 5 기념 촬영과 생성(병행) → Step 6 결과물 전송 → Step 7 종료와 리셋.

- **큰 분기**: 이탈 분기(유저 그만두기, 터치 미입력 타임아웃, 카메라 촬영 미동의, 입력 도안 가드레일 재검출 한도 초과)는 진행 중 종료로 Step 7 직행. 3D 변환과 기념 사진 생성 실패는 실패 처리 후 Step 7
- **병행**: Step 3에서 백그라운드 3D 변환과 포그라운드 대기 화면이 동시 진행하고, Step 5에서 백그라운드 기념 사진 생성과 포그라운드 대기가 동시 진행함. 둘 다 상태 조회로 동기화함
- **파기**: Step 7 종료 시 세션 임시 데이터 파기(영상 피드). 기념 사진은 다운로드 호스팅 만료 시 파기하며 연락처는 수집하지 않음

# 3. 공용 시스템

## 가. 세션 데이터

### 1) 역할과 목적

한 세션이 만드는 데이터를 담는 시스템. 전 Step이 같은 상태를 공유하게 하고, 데이터 종류별 보관과 파기 관리를 용이하게 함.

### 2) 동작과 규칙

본 콘텐츠가 세션에 저장하는 데이터를 분류, 값, 보관 기간으로 정리함. 표는 어떤 값이 들어가는지까지만 적고, 데이터 타입이나 저장 스키마 같은 저장 형식은 설계 단계에서 정함. 개인정보 민감 데이터(영상 피드, 기념 사진)에 최소 보관 원칙을 적용함. 결과물을 화면 QR로 익명 다운로드해 전화번호를 받지 않으므로 세션이 저장하는 연락처는 없음.

| 데이터 | 분류 | 들어가는 값과 구성 | 보관 기간 | 비고 |
|---|---|---|---|---|
| 세션 ID | 시스템 | 세션마다 부여되는 고유 식별자 | 보관 (잠정, 규정 검토 후 확정) | Step 1에서 생성. 디버깅과 품질 분석용 |
| 현재 Step | 시스템 | 현재 진행 중인 Step | 보관 (잠정, 규정 검토 후 확정) | 진행 단계 기록 |
| 에러 유형 | 시스템 | 에러 발생 시 에러 유형 기록 | 보관 (잠정, 규정 검토 후 확정) | 디버깅과 품질 분석용 |
| 동의 기록 | 시스템 | 약관 버전 + 동의 시각 + 동의 항목(필수: 카메라 촬영) | 보관 (잠정, 규정 검토 후 확정) | 약관 버전 체계 운영 결정 |
| 탈 디자인(2D) | 콘텐츠 입력 | 유저 2D 탈 도안 | 별도 저장소 보관 (파기 시점 규정 검토 후 확정) | Step 2 산출 |
| 3D 탈 모델 | 콘텐츠 생성 | 변환된 3D 탈 자산 | 별도 저장소 보관 (파기 시점 규정 검토 후 확정) | Step 3 산출 |
| 동작 채점 기록 | 콘텐츠 생성 | 자세 일치도와 타이밍 점수, 신명 게이지 | 익명 통계는 보관, 식별 원본은 세션 종료 시 파기 | Step 4 산출 |
| 기념 사진 | 콘텐츠 생성 | 유저와 2D 탈 캐릭터가 동반 포즈한 사진(점수와 등급 스탬프) | 호스팅 만료 시 파기 (다운로드 제공 기간, 잠정 48시간) | Step 5 산출. 개인정보(얼굴과 신체 포함) |
| 다운로드 URL | 콘텐츠 생성 | 기념 사진 호스팅 주소(만료형) | 호스팅 만료까지 유지 | Step 6에서 발급 |
| 영상 피드 | 콘텐츠 입력 | 카메라 원본 스트림(AR 얼굴 추적, 포즈 추정, 기념 촬영 입력) | 메모리 임시, 처리 직후 파기 | 디스크 저장 금지. 개인정보 |

- **Step별 세션 동작**: Step 1 생성, Step 2~Step 6 갱신, Step 7 종료와 임시 데이터 파기와 리셋
- **저장 위치**: 영상 피드는 메모리나 임시 버퍼에만 두고 디스크 영속화와 로그 기록을 하지 않음. 기념 사진은 다운로드 호스팅 임시 저장소에만 두고 로그 기록을 하지 않음. 탈 디자인과 3D 탈 모델은 재사용과 재변환 비용 회피, 품질 분석을 위해 별도 저장소에 보관함
- **분류 축과 개인정보 축**: 분류는 시스템, 콘텐츠 입력, 콘텐츠 생성 셋만 씀. 개인정보 여부는 분류와 직교하는 성질이라 분류 값이 아니라 비고에 적음(영상 피드와 기념 사진이 개인정보)
- **보관 기간 잠정값**: 시스템 데이터는 디버깅과 품질 분석을 위해 잠정 보관하고 규정 검토 후 확정함. 콘텐츠 데이터의 파기 시점도 규정 검토 후 확정하며 임의 추정하지 않음

## 나. 개인정보 처리

### 1) 역할과 목적

유저 얼굴과 신체가 담긴 데이터를 다루는 시스템. 필요한 최소 시간만 보관하고 즉시 파기해 개인정보 리스크를 줄이는 게 목적. 카메라로 얼굴과 신체를 촬영하므로 개인정보 민감도가 높음. 결과물은 화면 QR로 익명 다운로드해 전화번호를 받지 않으므로 연락처는 다루지 않음.

### 2) 동작과 규칙

- **개인정보 범위**
	- 얼굴과 신체 영상(영상 피드. AR 얼굴 추적, 포즈 추정, 기념 촬영에 쓰임)
	- 기념 사진(분류는 콘텐츠 생성이지만 얼굴과 신체가 담긴 결과물이라 개인정보로 병행 처리함)
- **동의 범위**
	- 필수: 카메라 촬영(AR 얼굴 추적, 포즈 추정, 기념 사진 촬영)
	- 고지: 기념 사진은 얼굴과 신체가 담긴 결과물임. 이를 생성하고 저장하며 다운로드로 잠정 48시간 제공하는 처리를 개인정보 수집과 이용 안내에 포함함. 정확한 안내 문구와 동의 범위는 규정 검토 후 확정함
- **영상 피드 처리**: 메모리 임시 처리 후 즉시 파기함. 디스크 저장이나 로그 기록을 하지 않음
- **결과물 전달**: 화면 QR로 익명 다운로드하며 연락처를 수집하지 않음. 기념 사진 호스팅과 만료 파기 정본은 플랫폼 사양임
- **재방문 연속성**: 학습 프로필, 이어하기, 학습 토큰, 콘텐츠 횡단 누적은 2차연도 전방 설계로 두며 1차연도는 익명 1회로 운영함
- **보관 기간 (규정 검토 후 확정)**: 보관 기간 잠정값은 규정 검토 후 확정하며 임의 추정하지 않음

## 다. 말뚝이 진행 호스트

### 1) 역할과 목적

양반을 놀리는 탈춤 풍자의 화자로, 관객과 대거리하는 전통 기능을 진행 안내와 추임새로 계승하는 전 Step 진행 호스트. 탈 디자인부터 춤사위, 기념 촬영까지 한 목소리로 잇고 덧뵈기의 전통 정체성을 살림. 유저가 주인공이고 말뚝이는 해설과 길잡이 역할만 하며 유저의 창작이나 춤을 대신 수행하지 않음.

### 2) 동작과 규칙

- **범위**: 전 Step 진행 호스트
- **페르소나**: 말뚝이 전통 인물과 화법(말투, 어휘, 반응 패턴)은 세부 설계에서 정함(작성 예정, 대사 적용 방법은 논의 후 추가)
- **재담과 추임새**: 춤사위 채점 피드백을 추임새로 전달함. 게이지 미달 시 눙치며 마무리함
- **발화 방식**: TTS 음성으로 대사를 재생하고 같은 대사를 화면에 텍스트로 표시함. 발화 중 다음 버튼을 누르면 발화를 중단하고 다음으로 진행함
- **표현 형식**: 2D 플랫 일러스트로 표시함(3D 아님). 본문 주기능을 가리지 않는 위치와 크기로 두고, 작업 집중이 우선인 화면(탈 디자인, AR 춤사위, 기념 촬영)에서는 작게 두거나 숨김
- **타임아웃 연동**: 발화 중에는 터치 미입력 타임아웃을 멈추고, 발화가 끝난 뒤 측정을 시작함
- **고증 주의**: 말뚝이 배역 해석은 일반 탈춤 문헌 수준의 추정임. 소재 원본 작성 후 검증함(확인 필요)

### 3) 필요 리소스

- 말뚝이 호스트 캐릭터(탈춤 양식, 2D 플랫 일러스트, 애니메이션 가능하게 제작, 기념 사진 탈 캐릭터와 시각 정체성 일치)
- 동작 애니메이션 세트(대기, 인사, 말하기, 제스처)
- 말뚝이 TTS 보이스
- 추임새와 대사(제작 방식 확인 필요)

### 4) 실패와 복구

아바타 렌더나 TTS 재생 실패 시 음성과 애니메이션 없이 대표 이미지와 텍스트 박스로만 진행함(대사는 표시하고 세션은 계속).

## 라. 진행 중 종료

### 1) 역할과 목적

유저에게 진행 중 종료할 수단을 제공하고 이탈한 세션을 정리하여 키오스크 회전율을 높이는 시스템. 유저 그만두기, 터치 미입력 타임아웃, 입력 도안 가드레일 한도 초과가 이 시스템의 종료 트리거임. 동의 약관 화면에서 그만두기나 터치 미입력이 발동하면 카메라 촬영 미동의로 종료함(전체 플로우 큰 분기의 미동의 이탈).

### 2) 동작과 규칙

#### 가) 일반 규칙

진행 중인 화면을 멈추고 Step 7 종료로 직행함. 유저 쪽 능동 이탈이라 실패 처리가 띄우는 상황 안내 팝업 없이 종료함(가드레일 위반 종료만 아래 위반 종료 안내 팝업을 거침).

#### 나) 유저 그만두기

- 상호작용 화면 액션 영역에 그만두기 보조 버튼을 상시 둠
- 터치 시 그만두기 확인 팝업(계속하기, 그만두기 두 버튼)을 띄우고, 그만두기 확정 시 종료하며 계속하기 선택 시 원래 화면으로 복귀함
- **적용 화면**: 가이드 화면, 동의 약관 화면, 탈 디자인 도구 화면. 동의 약관 화면의 미동의 그만두기도 이 확인 팝업을 공유함
- **미적용 화면**: 시작 화면, 변환과 생성 대기 화면, AR 춤사위 체험 화면, 기념 촬영 화면, 결과물 미리보기와 QR 화면, 마무리 인사 화면. 대기는 작업 진행 중이라 이탈로 보지 않고, AR 춤사위와 기념 촬영은 손을 쓰지 않는 화면이라 터치 미입력 타임아웃(사람이나 포즈 미검출)으로 이탈을 잡으며, 감상 성격 화면은 화면 타임아웃으로 넘김

#### 다) 가드레일 위반 시 종료

- 입력 도안 가드레일 재검출이 한도 3회(잠정)를 넘으면 위반 종료 안내 팝업(원 버튼)을 띄우고 확인 시 종료함
- 재검출 횟수는 화면마다 초기화하여 따로 셈

## 마. 화면 타임아웃

### 1) 역할과 목적

한 화면에 장시간 체류하는 것을 방지하는 시스템.

### 2) 동작과 규칙

- **처리**: 한 화면에서 60초(잠정) 이상 체류하면 그 화면의 정상 진행 경로로 넘어감. 창작과 촬영 화면(탈 디자인, 기념 촬영)은 작업 시간이 길어 5분(잠정)으로 상향함. 마무리 인사 화면은 3초(잠정)로 낮춤
- **작업 상태**: 유저 작업 상태가 있으면 세션 내 확정 저장 후 진행하고(탈 디자인 도안), 없으면 바로 다음으로 진행함
- **예외**: 필수 입력, 호스트 대화, 대기, 팝업 화면은 미적용

## 바. 터치 미입력 타임아웃

### 1) 역할과 목적

유저 이탈에 대응해 방치된 세션을 정리하여 키오스크 회전율을 높이는 시스템.

### 2) 동작과 규칙

- **처리**: 한 화면에서 45초(잠정) 이상 터치나 동작 입력이 없으면 이탈로 보고 진행 중 종료로 처리함. 카메라와 모션 화면(AR 춤사위, 기념 촬영)은 사람이나 포즈 미검출을 이탈 기준으로 함
- **호스트 발화 화면**: 말뚝이 발화 종료나 스킵 후부터 측정을 시작함(발화 중에는 멈춤)
- **예외**: 대기 화면과 감상 성격 화면(결과물 미리보기, QR)은 미적용

## 사. AI 가드레일

### 1) 역할과 목적

입력과 생성물의 안전과 전통 정합성을 검사하는 횡단 시스템. 유해하거나 전통을 왜곡한 콘텐츠가 유저에게 노출되지 않게 막는 게 목적.

### 2) 입력과 출력

- **입력**: 검사 대상(유저 탈 도안, 변환 3D 탈 모델, 생성 기념 사진, 사전 제작 자산)
- **출력**: 통과나 차단 판정과 사유. 위반 시 재생성이나 차단 트리거 실행

### 3) 동작과 규칙

적용 지점을 셋으로 나눔. 전통 왜곡과 정합성 판정 기준은 탈과 춤사위 고증을 따름.

- **사전(운영 전 제작)**: 탈 템플릿과 프리셋, 춤사위 모션 레퍼런스, 말뚝이 대사 등 사전 제작 자산 검수
- **런타임 입력(Step 2)**: 부적절 탈 도안 차단 후 재입력 안내. 재검출 한도 3회(잠정) 초과 시 진행 중 종료로 처리함. 반복 위반 세부 정책(차단 누적 등)은 작성 예정
- **런타임 출력(Step 3, Step 5)**: 변환 3D 탈 모델과 생성 기념 사진 검사. 위반 시 재생성 한도 2회(잠정)까지 재생성하고, 한도 초과 시 위험 생성물을 파기하고 실패 처리로 보냄

### 4) 기술 요건

- **검사 범위**: 이미지(도안, 기념 사진)와 3D(변환 탈 모델)를 검사하므로 이미지 모더레이션과 3D 형상 검사가 필요함
- **모델 확보 (결정 필요)**: 범용 유해물은 외부 안전 API로 거르고, 전통 정체성 왜곡처럼 범용 API가 못 잡는 판정은 자체 규칙이나 도메인 분류기로 보완함. API 대 자체 구축 비중은 후보 조사 후 확정
- **품질 기준**: 무인 운영이라 미탐(유해물 통과)이 오탐보다 위험하므로 미탐을 낮추는 보수적 임계로 잡음. 오탐율, 미탐율, 임계 목표는 검증 데이터 확보 후 정량 확정
- **지연 예산**: 런타임 입력과 출력 검사는 유저 대기 구간이라 검사 응답 지연 상한이 필요함(정량 미정)

## 아. 외부 서비스 호출 래퍼

### 1) 역할과 목적

외부 서비스 호출(AI, 3D 변환, 이미지 생성, 결과물 호스팅)을 감싸는 공통 계층. 재시도와 타임아웃 대응을 한 곳에 모아, 매 호출마다 장애 처리를 따로 짜지 않게 함.

### 2) 동작과 규칙

- **재시도**: 2회(잠정)
- **호출 타임아웃**: 3D 변환과 이미지 생성, 결과물 호스팅 60초(모두 잠정)
- **한도 초과**: 재시도 한도를 넘긴 실패는 실패 처리로 넘김

## 자. 실패 처리

### 1) 역할과 목적

콘텐츠 전반의 실패를 받아 처리하는 단일 종료 경로. 무인 운영에서 오류가 방치되지 않도록 세션을 안전하게 마무리하는 게 목적.

### 2) 동작과 규칙

자동 복구(재시도, 재생성)를 다 쓴 뒤에도 남는 실패를 종료 경로로 보냄. 본 콘텐츠는 결과물(기념 사진)이 없으면 세션을 이어 갈 수 없어 부분 실패 갈래를 두지 않고, 실패는 모두 종료로 수렴함.

- **진입 조건**: 재시도 한도를 넘긴 외부 호출 실패(AI, 3D 변환, 이미지 생성, 결과물 호스팅), 가드레일 재생성 한도 초과, 3D 변환 파이프라인 실패, 기념 사진 생성 파이프라인 실패, 유효 촬영 0회, 결과물 호스팅 영구 실패, 상태 조회 무응답 임계 초과
- **공통 처리**: 상황 안내 팝업을 띄우고 Step 7 종료로 자동 진행함. 별도 실패 화면을 두지 않고 전달하지 못한 미완성이나 위반 생성물은 파기함
- **유형별 처리**
	- 생성이나 변환 실패, 가드레일 한도 초과, 유효 촬영 0회: 상황 안내 뒤 Step 7. 미완성이나 위반 생성물은 파기
	- 결과물 호스팅 영구 실패: 상황 안내 뒤 Step 7. 재시도 한도를 넘겨 기념 사진을 호스팅하지 못한 경우이며, 후속 조치를 위해 운영에 알림
- **운영 알림**: 후속 조치가 필요한 실패(결과물 호스팅 실패 등)나 연속 3회 실패 또는 5분 오류율 10%(잠정) 임계 도달 시 운영에 알림(알림 채널 미정)

## 차. 탈과 춤사위 고증 (공통 레퍼런스)

### 1) 역할과 목적

전통 탈 양식과 춤사위의 전통 기준을 정의하는 설계 레퍼런스. 기준만 정의하고 직접 생성하지는 않음. 탈 디자인 도구, 포즈 채점, 가드레일이 디자인 시작점이나 전통 정합성 판정 기준으로 공유하는 공통 입력 기반임.

### 2) 동작과 규칙

- **탈**: 덧뵈기 배역 탈(말뚝이, 양반, 먹중, 샌님 등) 양식을 디자인 레퍼런스로 활용함(목록과 종수 확인 필요, 소재 원본 보강 예정). 한국 탈춤 탈 양식을 유지하고 일본 노멘이나 중국 가면과 혼동하지 않음
- **춤사위**: 따라 추기 대상 동작과 풍물 장단의 고증 매핑(작성 예정, 고증 자문 연계). 포즈 채점의 기준 동작이 됨
- **시각 정체성**: 탈 양식과 질감의 전통 정합성 유지(작성 예정)

- **대칭**: 좌우 대칭(미러) 기본 제공, 해제 토글로 비대칭 허용

# 6. Step 3. 3D 변환 + 대기 화면 (병행)

백그라운드 변환과 포그라운드 대기가 동시 진행되고 상태 조회로 동기화됨. 3D 변환은 백그라운드라 화면이 없음.

## 가. 백그라운드: 3D 변환

- **상태 머신**: `converting` / `completed`(가드레일 통과분만) / `failed`(변환 실패 또는 가드레일 한도 초과)

### 2) 탈 3D 변환 (개별 시스템)

#### 가) 역할과 목적

2D 탈 도안을 AR 착용용 3D 탈 모델로 변환하는 런타임 엔진. Step 2 경량 미리보기와 달리 정식 고품질 변환을 만드는 게 목적.

#### 나) 입력과 출력

- **입력**: 2D 탈 도안(형식 확인 필요)
- **출력**: 3D 탈 모델(glTF 등 AR 렌더 형식, 확인 필요)

#### 다) 동작과 규칙

키오스크 부하를 고려해 서버 백그라운드에서 변환하고, 대기 화면이 상태 조회로 동기화함. 전통 정합성은 AI 가드레일을 거쳐 탈과 춤사위 고증 기준으로 판정함.

#### 라) 기술 요건

2D에서 3D 생성 모델. 자체 학습 부담이 커 외부 API와 사전학습 모델을 우선 검토함(후보 조사 확인 필요). 판정 기준은 변환 성공률, 전통 정합성, 변환 시간(대기 조회 주기와 연동). 품질 평가 기준과 평가 데이터는 작성 예정. 변환 모델 미확보 시 대안 검토(확인 필요).

#### 마) 실패와 복구

변환물은 출력 가드레일 검사를 받음. 호출 실패나 가드레일 미통과는 변환 파이프라인의 `failed` 처리(실패 처리)로 이어짐.

## 나. 포그라운드: 변환 대기 화면

### 1) 진행

- 변환 대기 콘텐츠 노출(덧뵈기 준비 과정 영상 등), 백엔드 상태 조회(주기 2초, 잠정). 두 타임아웃 미적용
	- 분기: `converting` → 대기 유지 / `completed` → 즉시 Step 4 / `failed` → 실패 처리 후 Step 7
	- 분기: 상태 조회가 연속 3회(잠정, 조회 주기 2초 기준 약 6초) 무응답이면 `failed`로 처리해 실패 처리 후 Step 7. 대기 화면은 두 타임아웃 미적용이라 무한 대기를 막는 별도 탈출임

# 7. Step 4. AR 착용 + 춤사위 따라하기 (핵심 체험)

## 가. UI(AR 춤사위 체험 화면)

### 1) 진행

1. UI: 3D 탈을 AR로 착용(카메라 얼굴 추적, 탈 오버레이)
2. UI: 춤사위 가이드 제시와 유저 동작 캡처
3. UI(말뚝이): 게이지 결과 연출(달성 시 환호 사운드 보상, 미달 시 말뚝이가 눙치는 마무리)
	- 분기: 화면 타임아웃 발동 시 체류 상한으로 보고 Step 5로 정상 진행
	- 분기: 터치 미입력 타임아웃(사람이나 포즈 미검출)이면 이탈로 보고 진행 중 종료

### 2) 포즈 채점과 신명 게이지 (개별 시스템, 핵심 메커닉)

#### 가) 역할과 목적

카메라 영상에서 자세를 추정해 춤사위 자세 일치도와 타이밍을 실시간 채점하고 신명(興) 게이지로 시각화, 달성 시 보상하는 핵심 루프. 유저가 직접 춘 춤에 즉각 피드백을 주는 게 목적.

#### 나) 입력과 출력

- **입력**: 카메라 영상 프레임, 풍물 장단 타이밍
- **출력**: 포즈 키포인트, 자세 일치도, 타이밍 점수, 신명 게이지 값, 동작 채점 기록

#### 다) 동작과 규칙

- **채점 입력**: 자세 일치도(포즈 추정 기반)와 풍물 장단 대비 타이밍. 기념 촬영(Step 5)은 채점하지 않음
- **채점 기준(잠정)**: 일치도 임계 70%, 자세 대 타이밍 가중치 7 대 3. 사용성 검증 후 조정함
- **게이지와 보상**: 채점이 쌓이면 게이지가 오름. 누적 80%(잠정) 달성 시 환호 사운드(군중 추임새, 박수)로 보상하고, 미달 시 말뚝이가 눙치며 마무리함
- **난이도 곡선(잠정)**: 초반 60%에서 후반 75%로 단계 상향
- **종합 점수와 등급 출력**: 게이지 종합 점수와 등급은 Step 5 기념 사진 스탬프로 표기함
- **학습 진척**: 1차연도는 당회 채점만 함. 재방문 진척 누적(향상 곡선, 약점 동작 피드백)은 2차연도 전방 설계로 둠
- **세부 설계 (작성 예정)**: 가중치, 게이지 임계, 미달 처리, 향상 곡선 산출

#### 라) 기술 요건

실시간 포즈 추정은 사전학습 모델과 온디바이스 SDK를 우선 검토함(후보 확인 필요). 채점 로직은 레퍼런스 동작 대비 자체 규칙. 판정 기준은 포즈 추정 정확도, 채점 임계와 가중치, 실시간 처리 지연(프레임률). 채점 정확도 검증 방법과 서버 대 온디바이스 여부는 확인 필요. 모션 인식은 전신 싱글 카메라 기준 손목까지가 현실적이라 춤사위 채점 대상 동작을 이 범위로 설계함.

#### 마) 필요 리소스

- 춤사위 모션 레퍼런스(따라 추기 대상과 채점 기준, 모캡 등 확인 필요, 고증 자문)
- 풍물 장단 음원(타이밍 기준, 무저작권이나 자체, AI 생성)
- 환호와 추임새 사운드(게이지 달성 보상, 제작 방식 확인 필요)

#### 바) 실패와 복구

포즈가 안 잡히거나 신뢰도가 낮으면 재시도 안내(한도 3회, 잠정). 3회 초과 시 해당 구간 점수를 보류하고 다음 구간으로 진행함(채점 루프는 계속). 지연 시에도 해당 구간 점수를 보류함. 터치 미입력 타임아웃(사람이나 포즈 미검출) 시 진행 중 종료.

# 8. Step 5. 기념 촬영 + 생성 (병행)

기념 촬영 뒤 백그라운드 생성과 포그라운드 대기가 동시 진행되고 상태 조회로 동기화됨.

## 가. UI(기념 촬영 화면)

### 1) 진행

1. UI: 2D 탈 캐릭터(유저 탈을 쓰고 덧뵈기 탈옷을 입은)를 카메라 뷰에 라이브 합성, 유저가 그 옆에서 포즈
2. UI: 카운트다운 촬영(카운트다운 3초 잠정, 채점 없음, 촬영 횟수 3회까지 잠정)
	- 실패: 카메라에 사람이 안 잡히면 다시 서도록 안내
	- 분기: 유효 촬영이 1회 이상이면 생성으로 정상 진행함. 진행 계기는 촬영 횟수 소진, 촬영 타임아웃(10초, 잠정), 화면 타임아웃(창작 화면 5분, 잠정) 중 먼저 오는 것
	- 분기: 유효 촬영 0회로 타임아웃되면 사진 생성을 생략하고 실패 처리 후 Step 7
	- 분기: 터치 미입력 타임아웃(사람이나 포즈 미검출)이면 진행 중 종료

## 나. 백그라운드: 기념 사진 생성

### 1) 진행

- **생성 파이프라인**
	1. 백엔드: 기념 사진 생성 작업 큐 등록
	2. AI 기념 사진 생성: 촬영본에 2D 탈 캐릭터를 고품질 재합성하고 테두리 프레임과 신명 게이지 점수, 등급 스탬프를 표기
	3. AI 가드레일: 생성 기념 사진 검사
		- 분기: 위반 시 2로 재생성(한도 2회, 잠정). 한도 초과 시 위험물 파기, 상태 `failed`
	4. 백엔드: 통과한 기념 사진 저장
- **실패(생성 단계 공통)**: 생성 호출 실패 시 재시도 2회(잠정) 후 `failed` 전환(실패 처리). 유효 촬영 0회는 생성을 생략하고 `failed`
- **상태 머신**: `generating` / `completed`(가드레일 통과분만) / `failed`(생성 실패, 가드레일 한도 초과, 유효 촬영 0회)

### 2) 기념 사진 생성 (개별 시스템)

#### 가) 역할과 목적

촬영본에 2D 탈 캐릭터를 재합성하고 신명 게이지 점수와 등급을 스탬프로 표기한 기념 사진을 만드는 시스템. 유저가 가져갈 한 판의 기념물을 만드는 게 목적.

#### 나) 입력과 출력

- **입력**: 카메라 촬영본, 유저 2D 탈 디자인(캐릭터 합성용), Step 4 신명 게이지 점수와 등급
- **출력**: 기념 사진(점수와 등급 스탬프)

#### 다) 동작과 규칙

라이브 화면은 포즈용 미리보기이고, 최종 저장본은 촬영본에 2D 탈 캐릭터를 고품질 재합성하고 테두리 프레임을 두른 뒤 신명 게이지 점수와 등급을 스탬프로 표기함. 사진 합성과 스탬프 오버레이는 키오스크 부하를 고려해 서버에서 진행함. 해상도와 파일 형식은 구현 시 확정.

#### 라) 필요 리소스

- 기념 사진 프레임(테두리)
- 점수와 등급 스탬프(신명 게이지 표기)
- 기념 사진용 2D 탈 캐릭터(유저 2D 탈을 얼굴에 합성하는 2D 캐릭터 몸과 포즈 컷, 3D 아님. 기본 1종과 포즈 컷 1종, 비율과 해상도 확인 필요)

#### 마) 실패와 복구

생성 기념 사진은 출력 가드레일 검사를 받음. 미통과나 재생성 한도 2회(잠정) 초과 시 위험물 파기, 재생성 실패 시 생성 파이프라인의 `failed` 처리(실패 처리). 유효 촬영 0회 시 사진 생성을 생략하고 실패 처리.

## 다. 포그라운드: 생성 대기 화면

### 1) 진행

- 생성 대기 표시, 백엔드 상태 조회(주기 2초, 잠정)로 동기화. 두 타임아웃 미적용
	- 분기: `generating` → 대기 유지 / `completed` → 즉시 Step 6 / `failed` → 실패 처리 후 Step 7
	- 분기: 상태 조회가 연속 3회(잠정) 무응답이면 `failed`로 처리해 실패 처리 후 Step 7
