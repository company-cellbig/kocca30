> 셀빅 개발 총괄 회의용 준비 자료. 2026-06-22 두 회의에서 확정한 셀빅 1년차(2026) 범위를 정리하고, 콘텐츠 5종, 키오스크 디바이스, 무형유산 자료 획득 세 축의 결정/준비 항목과 블로커를 회의 의제로 묶음. 각 콘텐츠 정본은 개별 기획서, 디바이스 정본은 [[디바이스 사양]], 서버 정본은 [[플랫폼 사양]], 일정 정본은 [[로드맵 1단계 1년차]]이고, 본 문서는 회의 준비용 종합임.

# 1. 목적과 범위

- **목적**: 개발 총괄과의 1년차 개발 회의 전, 셀빅이 맡은 범위와 회의에서 결정/준비해야 할 항목을 한곳에 모음
- **범위**: 셀빅 소관인 남사당놀이 콘텐츠 5종, 그 콘텐츠가 쓰는 키오스크 디바이스, 개발에 필요한 무형유산 자료 획득. 택견(큐랩)과 모션 인식 코어(연세대, 큐랩)는 의존 인터페이스로만 참조함
- **읽는 법**: §2에서 확정 범위를 잡고, §3~§5에서 축별 준비/결정 항목을 보고, §6에서 회의 결정 요청을 종합함

# 3. 콘텐츠 5종 개발 준비

콘텐츠별 기획 성숙도와 핵심 AI, 1순위 준비 항목을 요약표로 먼저 보고, 이어 콘텐츠별 결정/준비 체크리스트를 둠. 필요 원천 자료는 §5에서 매핑함.

| 콘텐츠 | 유형 | 기획 성숙도 | 핵심 AI | 1순위 준비 |
|---|---|---|---|---|
| 나만의 꼭두각시 | 체험 | 콘셉트 개요(stub) | 얼굴 특징 추출, 3D 아바타 생성, 실시간 채점 | 세부 기획서 작성 |
| 나만의 유람기 | 생성 | 상세 기획서(draft) | 플롯 생성과 서사 LLM, 이미지 생성, 가드레일 | 사건 풀 완성, 산출물 형식 확정 |
| 버나잡이 한 판 | 체험 | 콘셉트 개요(stub) | 물리 시뮬레이션, 대거리 판정 | 세부 기획서, 센서 막대와 물리 엔진 |
| 나만의 탈춤 | 체험 | 상세 기획서(draft) | 2D→3D 변환, 포즈 추정과 채점, 사진과 영상 생성 | 변환과 포즈 모델 확보, 토큰 흐름 정합 |
| 양반 놀리기 4컷 | 생성 | 콘셉트 개요(stub) | 플롯 LLM, 만화 이미지 생성, 가드레일 | 세부 기획서, 가드레일 풍자 범위 |

5종 중 2종(나만의 유람기, 나만의 탈춤)만 상세 기획서가 있고, 3종은 콘셉트 개요뿐임. 개요 3종의 기획서 작성이 7월 핵심 개발 전 최우선 준비임.

## 가. 나만의 꼭두각시 (덜미, 체험)

- **현황**: 콘셉트 개요만 있음 ([[콘셉트 정리]] §4.가.1). 독립 기획서 없음
- **핵심 루프**: 얼굴 촬영으로 목각 인형 질감 3D 아바타 생성 → 산받이가 미션과 재담 제시 → 양손 조작과 장단 타이밍 → 신명 게이지 → 기념 촬영
- **결정과 준비**
	- 세부 기획서 작성: Step 명세, 아바타 조작 메커니즘(어떤 손동작이 어떤 동작을 부르는지), 산받이 페르소나
	- 3D 아바타 생성 방식 결정(자체 학습 대 외부 API)
	- 양손 조작 인식 방식: 뎁스 카메라 손 인식은 손목까지가 현실적이라(§4.가) 조작 설계가 이 한계를 넘지 않아야 함
	- 캐릭터 고증과 음성: 박첨지, 홍동지, 산받이 캐릭터 레퍼런스와 산받이 음성(TTS). 필요 자료는 §5.나

## 나. 나만의 유람기 (덜미, 생성)

- **현황**: 상세 기획서 draft ([[덜미 - 전자책 변환 기획서]]). S1~S7 명세 완성. **1년차 익명 1회성 운영을 이미 명시**(기획서 §1.가)
- **핵심 루프**: 캐릭터 정보 입력 → 마당 유형 선택과 거리별 플롯 문답 → LLM 서사와 이미지 생성 → 그림동화 전자책 → SMS 전송
- **결정과 준비**
	- 사건 풀 완성: [[마당 사건 풀]] 거리와 유형별 목표 5~10 대비 현재 절정이 약 4로 보강 필요
	- 산출물 형식 확정: PDF, EPUB, 이미지 묶음 중 미정
	- 캐릭터 일관성 메커니즘 결정: 프롬프트, IP-Adapter, LoRA 중 아트팀 협의 (기획서 §3.마)
	- 작성 대기: 박첨지 페르소나 세부, 가드레일 세부 정책, 사전 플롯 풀 생성 일정

## 다. 버나잡이 한 판 (버나, 체험)

- **현황**: 콘셉트 개요만 있음 ([[콘셉트 정리]] §4.나.1). 독립 기획서 없음
- **핵심 루프**: 센서 막대로 버나, 접시, 대접을 돌려 회전과 균형을 물리 시뮬레이션 → 매호씨가 재담으로 도발하면 제한 시간 안에 대거리 선택지로 응수 → 적절성 판정과 묘기 유지로 신명 게이지
- **결정과 준비**
	- 세부 기획서 작성: Step 명세, 재담 대거리 로직
	- 센서 막대 도입 여부: 분실과 관리, 충전 이슈로 시연용 한정 가능성 (디바이스 RnD, §4.나)
	- 물리 엔진 결정(자체 대 외부)
	- 자산: 매호씨 재담 DB(도발, 응수, 추임새)와 음성, 풍물 장단 음원. 필요 자료는 §5.나

## 라. 나만의 탈춤 (덧뵈기, 체험)

- **현황**: 상세 기획서 draft ([[덧뵈기 - 나만의 탈춤 기획서]])와 UI 문서. Step 1~7과 운영 파라미터 명세. **단 토큰과 옵트인 프로필, 이어하기 흐름을 전제로 짜여 있어 1년차 익명 1회성 결정과 어긋남**(Step 1 이어하기, Step 6 토큰 발급). 정합 필요는 §6
- **핵심 루프**: 탈 디자인 → 3D 변환 → AR 착용과 춤사위 따라추기(포즈 채점, 신명 게이지) → 기념 촬영(2D 탈 캐릭터 합성) → 리플레이 영상 → SMS
- **결정과 준비**
	- 토큰 흐름 정합: Step 1 이어하기와 Step 6 토큰, 옵트인 프로필을 1년차 익명 1회성으로 조정하고, 토큰과 프로필은 2차연도 구조 설계로 미룸
	- 핵심 모델 확보: 2D→3D 변환 모델과 실시간 포즈 추정 모델(자체 대 외부 API나 온디바이스 SDK), 미확보 시 대안
	- 작성 대기: 포즈 채점 정확도 검증 방법, 채점 세부(가중치, 게이지 임계, 미달 처리)
	- 자산: 탈 디자인 템플릿과 프리셋, 춤사위 모션 레퍼런스(모캡과 고증), 리플레이 음원(무저작권이나 AI 생성), 말뚝이 호스트 에셋. 필요 자료는 §5.나

## 마. 양반 놀리기 4컷 (덧뵈기, 생성)

- **현황**: 콘셉트 개요만 있음 ([[콘셉트 정리]] §4.다.2). 독립 기획서 없음. 나만의 유람기와 생성형 구조를 공유하는 자매 콘텐츠
- **핵심 루프**: 캐릭터 정보 입력 → 풍자 플롯 문답 → 사용자 탈을 쓴 캐릭터가 등장하는 4컷 만화 AI 생성 → 전송
- **결정과 준비**
	- 세부 기획서 작성: 나만의 유람기 생성형 골격을 재사용 가능
	- 4컷 만화 생성 파이프라인과 사용자 탈의 만화 캐릭터화 방식
	- 가드레일 풍자 범위 정책: 실명과 단체 풍자 차단, 추상 대상 전환. 검증위원회 연계
	- 자산: 양반, 샌님, 말뚝이 캐릭터와 4컷 레이아웃 양식

## 바. 공통 개발 골격

5종이 공통으로 따르는 골격임. 콘텐츠 고유 설계가 아니라 플랫폼 공통이라 한곳에 모음.

- **준용 정본**: 세션, [[시범콘텐츠 공통 사양#3. Step 모델]], 공용 기능(타임아웃, 가드레일, 외부 호출 래퍼, 에러 처리), 기술 6영역
- **결정과 준비**
	- 공용 임계값 확정: 화면과 터치 미입력 타임아웃, 폴링 주기, 재시도 한도. 현재 잠정값임 ([[시범콘텐츠 공통 사양#9. 운영 파라미터 (공통 기본값)]])
	- 진행 호스트 음성 발주: 박첨지(덜미)와 말뚝이(덧뵈기) 페르소나 세부와 TTS 음성. 버나 매호씨도 동일
	- 데이터 보관 기간(동의 기록, 결과물, 로그)은 규정 검토로 확정 (미정)
	- 런처 통합: 콘텐츠는 독립 개발하고 런처로 메뉴만 통합

# 4. 키오스크 디바이스 개발 준비

디바이스 정본은 [[디바이스 사양]]임. 본 절은 셀빅 1년차 준비 관점에서 결정/확인 항목만 추림.

## 가. 하드웨어 (큐랩 주도, 셀빅 맞춤)

- **확정**: 가로형 키오스크, 모션 인식(뎁스) 카메라, 바닥 프로젝션 ([[디바이스 사양#2. 키오스크]])
- **검토 중**: 65인치, 뎁스 카메라 모델(키넥트나 오르벡), 라이다 채택
- **결정과 확인**
	- 큐랩 규격 확정 시점: 셀빅 커스터마이징의 선행 조건임
	- 통합 규격: 셀빅 포토부스(세로형)와 큐랩 케이팝(가로형) 자산을 단일 규격으로 통합
	- 카메라 센싱 한계 반영: 손목까지가 현실적이고 1인이 정확도와 속도에 유리함 (콘텐츠 조작 설계 제약, [[디바이스 사양#라. 카메라 센싱 범위 (연세대)]])

## 나. 콘텐츠별 액세서리와 센서 (셀빅 RnD)

- 버나 센서 막대: 도입 여부와 시연용 한정 가능성
- 덜미 꼭두각시: 얼굴 촬영 카메라(하드웨어 영향 적음)
- 나만의 탈춤: 포즈와 AR용 카메라, 온디바이스 추론 채택 시 연산 유닛(GPU) 사양
- 색인 정본: [[디바이스 사양#5. 콘텐츠별 하드웨어 쟁점 (색인)]]

## 다. 서버 (1년차 익명 1회성)

1년차는 학습 토큰을 빼고 익명 1회성으로 가되, 2차연도에 토큰과 프로필을 추가할 수 있게 구조만 설계함. 빼는 것은 재방문 이어하기용 학습 토큰이고, 결과물 다운로드 QR은 별개라 유지함.

- **1년차 가동**: 결과물 저장(웹 호스팅과 다운로드 QR), 익명 통계(유저 수, 완주율, 오류율 비식별 집계), 세션 관리. 기기 간 동기화 없음 ([[디바이스 사양#4. 공통 결정과 제약]])
- **2차연도 구조 설계**: 학습 토큰, 옵트인 프로필, 이어하기, 콘텐츠 횡단 누적은 1년차 미구현. 데이터 모델만 열어 둠
- **익명 상태의 관찰 수단**: 익명 통계는 휘발성 세션 식별자로 1회 사용을 묶고, 영구 subject_id와 분리함. 개발 중 점검은 세 가지로 함. 세션 안 실시간 진척, 익명 통계, 개발 빌드 한정 디버그 진입점(중간 Step 진입이고 운영 빌드에서는 제외). 운영 모델인 익명 1회성은 건드리지 않음
- **결정과 확인**
	- 서버 개발 주체: 큐랩 대 셀빅
	- 익명 통계 스키마와 지표 범위
	- 결과물 호스팅과 QR 다운로드 방식
	- 2차연도 토큰과 프로필 구조 설계 범위
- **정본 포인터**: 서버 데이터 모델 상세는 [[플랫폼 사양#4. 서버 데이터 모델]]. 단 플랫폼 사양 본문은 아직 토큰을 전제하므로, 익명 1회성 기준 개정이 후속 과제임 (§8)

## 다. 라이선스 이슈

- **공공누리 제4유형**(출처표시, 비상업적, 변경금지): 열람과 고증 참고는 가능하나, AI 학습용 가공은 자료이용신청과 별도 허가가 필요함 ([[남사당놀이 아카이브 데이터셋 활용 검토#3. 종합 판정]])
- **초상권과 저작인접권**: 보존회 실연자 대상. 신규 촬영 시 MOU로 처리
- **사립 자료**: 한국민속극박물관은 공공누리 미적용, 직접 협의
- **음원**: 풍물 장단과 재담 음성은 권리 협의 또는 무저작권이나 자체나 AI 생성. 리플레이 영상 음원은 SNS 공유 리스크로 무저작권이나 AI 생성 권장
- **STT와 TTS**: 상용 API 유료 사용
