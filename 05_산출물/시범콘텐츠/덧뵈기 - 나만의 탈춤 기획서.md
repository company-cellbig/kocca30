# 1. 개요

- **콘텐츠 정의**: 덧뵈기를 소재로 한 가면극 배역 체험 키오스크 콘텐츠
- **소재**: 남사당놀이 가면극 덧뵈기
- **목표 경험**: 유저가 배역의 몸짓을 배우고, 상대 배역과 장면을 주고받고, 절정 대목을 완수하여 스승에게 배역 인정을 받음
- **핵심 메커닉**
	- 장쇠와 상대 배역, 유저 배역의 대사 모두 시스템이 발화함
	- 카메라로 잡은 유저의 몸짓은 판정에만 사용하여 유저 모습은 플레이화면에 비추지 않고 유저 배역의 애니메이션으로 대신 표시함
	- 판정 결과는 스승의 피드백과 상대 배역의 반응 연출로 되돌아오고, 최상위 판정에는 군중 추임새 반응이 더해짐
- **결과 안내**
	- 체험이 끝나면 마무리 화면에서 이수 단계와 수행 요약, 베스트샷을 보여줌. 
	- 베스트샷은 판 벌이기에서 갈무리한 유저 사진 한 장이고, QR로 다운로드 가능

- **중단 처리**
	- 대상: 진행 중 이탈과 실패가 모두 이 공통 처리로 모임
	- 처리: 결과 화면을 건너뛰고, 세션을 종료해 임시 데이터를 파기한 뒤 시작 화면으로 돌아감. 실패는 상황 안내 팝업을 띄운 뒤 진행하고, 이탈은 팝업 없이 진행함
- **파기**
	- 정상 종료 시 남은 세션 임시 데이터(장면 수행 기록의 식별 원본)를 파기함
	- 영상 피드는 처리 직후 실시간 파기라 종료 시점에는 남지 않음
		- 베스트샷만 예외임. 결과와 마무리 화면에 들어설 때 서버에 올리므로, 세션이 끝난 뒤에도 호스팅 사본이 다운로드 만료(48시간, 잠정)까지 남았다가 지워짐. 클라이언트 사본은 다른 세션 데이터와 함께 파기함

# 3. 공용 시스템

## 3.1 세션 데이터

### 3.1.1 역할과 목적

한 세션이 만드는 데이터를 담는 시스템. 전 Step이 같은 상태를 공유하게 하고, 데이터 종류별 보관과 파기를 관리하기 쉽게 함.

### 3.1.2 동작과 규칙

| 데이터       | 분류     | 들어가는 값과 구성                                               | 보관 기간                        | 비고                            |
| --------- | ------ | -------------------------------------------------------- | ---------------------------- | ----------------------------- |
| 세션 ID     | 시스템    | 세션마다 부여되는 고유 식별자                                         | 보관 (잠정, 규정 검토 후 확정)          | Step 1에서 생성. 디버깅과 품질 분석용      |
| 현재 언어     | 시스템    | 세션에 적용 중인 언어(기본 한국어)                                     | 보관 (잠정, 규정 검토 후 확정)          | 시작 화면 언어 선택에서 설정. 현지화 기준      |
| 현재 Step   | 시스템    | 현재 진행 중인 Step                                            | 보관 (잠정, 규정 검토 후 확정)          | 진행 단계 기록                      |
| 에러 유형     | 시스템    | 에러 발생 시 에러 케이스 유형 기록                                     | 보관 (잠정, 규정 검토 후 확정)          | 디버깅과 품질 분석용                   |
| 동의 기록     | 시스템    | 약관 버전, 동의 시각, 동의 항목(필수: 카메라 촬영)                          | 보관 (잠정, 규정 검토 후 확정)          | 약관 버전 체계는 운영 단계에서 결정함         |
| 선택 마당과 배역 | 콘텐츠 입력 | 유저가 고른 마당과 배역의 식별자(그 마당의 대본, 시범 클립, 배역 애니메이션, 판정 자산을 가리킴) | 보관 (잠정, 규정 검토 후 확정)          | Step 2 산출. 식별자만 저장(자산은 사전 배포) |
| 장면 수행 기록  | 콘텐츠 생성 | 신호별 판정(장 구분, 판정 3단, 자세와 타이밍 값), 장별 완수, 신명 지표(동작 성공과 얼쑤 누계)  | 익명 통계는 보관, 식별 원본은 세션 종료 시 파기 | Step 3 산출                     |
| 영상 피드     | 콘텐츠 입력 | 카메라 원본 스트림(포즈 추정 입력)                                     | 메모리 임시, 처리 직후 파기             | 디스크 저장 금지. 얼굴과 신체 포함          |
| 베스트샷      | 콘텐츠 생성 | 판 벌이기에서 갈무리한 정지 화상 1장                                    | 클라이언트 사본은 메모리 임시로 세션 종료 시 파기, 호스팅 사본은 다운로드 만료까지 유지 | Step 4 진입 시 서버 업로드. 클라이언트 디스크 저장 금지. 얼굴과 신체 포함 |
| 다운로드 URL  | 콘텐츠 생성 | 베스트샷 호스팅 주소(만료형)                                         | 호스팅 만료까지 유지                  | Step 4에서 발급하고 같은 화면이 QR로 인코딩. 세션 ID와 이어 붙여 저장 금지 |

- **Step별 세션 동작**
	- Step 1: 생성
	- Step 2~Step 4: 갱신
	- Step 5: 종료, 임시 데이터 파기, 리셋
- **서버 전송 시점 (이벤트 기반)**: 세션 데이터 갱신은 클라이언트 로컬 상태에만 반영하고, 서버로는 정기 전체 동기화 없이 이벤트 시점에만 전송함(이어하기 없는 1차연도 기준)
	- 단계 이동: 각 Step 진입과 종료 시 현재 Step을 전송함
	- 동의 기록: 이용 동의 화면에서 동의 확정 시 동의 이벤트를 전송함. 클라이언트는 서버의 저장 확인 응답을 받은 뒤에만 다음 단계로 진행함(동의 기록 유실 방지)
	- 에러와 이탈: 에러 발생 시, 이탈(약관 미동의, 미입력 타임아웃 종료) 시 전송함
	- 마당과 배역 확정: 선택 마당과 배역 식별자는 Step 2 확정 시 서버 세션에 반영함

## 3.2 개인정보 처리

### 3.2.1 역할과 목적

카메라로 찍는 유저 얼굴과 신체 데이터의 처리 규칙을 정의하는 시스템. 쓰임이 끝난 데이터는 곧바로 지우고, 유저가 받아 가는 사진 한 장만 기간을 정해 남김.

### 3.2.2 동작과 규칙

#### 1) 구현 제약

- **개인정보 범위**
	- 얼굴과 신체 영상
- **카메라 동의 게이트**
	- 카메라 촬영이 필수 동의이므로 동의가 없으면 세션을 진행하지 않음
- **영상 피드 처리**
	- 메모리에서 임시로 처리한 뒤 즉시 파기하고, 디스크에 저장하거나 로그로 기록하지 않음
	- 예외는 베스트샷 1장뿐임. 이 한 장은 유저가 받아 가는 반출물이라 아래 취급 규칙을 따름
- **베스트샷 취급**
	- 완주해 결과와 마무리 화면에 들어설 때 서버에 올리고 만료형 다운로드 주소를 받음. 그 주소로 화면에 QR을 그려 유저가 자기 휴대폰으로 받아 감
	- 클라이언트 사본은 메모리에만 두고 세션 종료와 함께 파기함. 클라이언트 디스크에는 저장하지 않음
	- 호스팅 사본은 세션 밖에서 다운로드 만료(48시간, 잠정)까지 남고, 만료와 함께 서버에서 지움
	- 다운로드 주소는 추측할 수 없는 난수로 발급하고 세션 ID나 장면 수행 기록과 이어 붙여 저장하지 않음. 연락처는 받지 않음
	- 비완주 종료는 결과와 마무리 화면을 건너뛰므로 업로드가 일어나지 않음. 회수할 사본이 남지 않는 구조임

#### 2) 규정 검토 대기

- **동의 고지 문구**
	- 개인정보 수집과 이용 안내에 아래 내용이 들어가야 함. 정확한 문구와 동의 범위는 규정 검토 후 확정함
		- 카메라 영상을 동작 판정에만 쓰고 따로 저장하지 않는다는 것
		- 체험 중 한 장면을 사진으로 갈무리한다는 것
		- 그 사진을 서버에 올려 정해진 기간 동안 내려받을 수 있게 한다는 것과 그 기간
		- 기간이 지나면 사진을 자동으로 지운다는 것
		- 주소를 아는 사람은 누구나 받을 수 있는 익명 링크이며 연락처는 받지 않는다는 것
		- 사진에 얼굴과 신체가 들어가고 배경에 다른 사람이 함께 찍힐 수 있다는 것
- **보관 기간**
	- 다운로드 가능 기간 잠정값은 48시간이며 규정 검토 후 확정함
- **재방문 연속성**
	- 학습 프로필, 이어하기, 학습 토큰, 콘텐츠 진행 결과 누적은 2차연도 확장 설계로 두며 1차연도는 익명 1회로 운영함

## 3.3 언어 선택 시스템

### 3.3.1 역할과 목적

세션 전체에 적용할 언어를 정하는 관문. 한국어가 아닌 언어를 쓰는 유저도 화면 글로 가면극을 따라오게 함.

### 3.3.2 입력과 출력

- **입력**: 유저의 언어 선택
- **출력**: 현재 언어(세션 데이터에 저장). 현지화 JSON(localization.json)에서 해당 언어값을 불러옴

### 3.3.3 동작과 규칙

- 유저가 언어를 선택하고 시작하기 버튼을 터치하면 현재 언어로 반영함. 기본값은 한국어임
- **현지화 범위**: UI 카피, 장쇠와 상대 배역과 유저 배역의 대사 자막, 결과와 마무리 문구(인정 선언 재담, 이수 단계 칭호, 수행 요약, 베스트샷과 QR 안내), 안내 팝업을 현재 언어로 제공함. 지원 언어는 한국어와 영어임(우선 적용)
- **음성 제외**: 음성은 언어와 상관없이 한국어로 재생함. 언어별 음성 확보가 어려워 글자만 현지화하며, 비한국어 세션은 한국어 음성에 현재 언어 자막을 얹는 방식임
- **재담 현지화 유의**: 말장난과 고어가 섞인 재담은 직역이 아니라 뜻과 웃음 구조를 살린 의역으로 현지화함(문안 작성과 함께 확정, 작성 예정)

## 3.4 진행 호스트

### 3.4.1 역할과 목적

덧뵈기의 장쇠(장구 담당)를 진행 호스트로 세워 장단을 이끌며 세 장의 진행을 매끄럽게 안내함

### 3.4.2 동작과 규칙

- **페르소나**
	- 능청스러운 남사당놀이패 고참
- **마당별 자리와 발화 분량**
	- 세 마당 공통으로 장쇠는 판 밖에서 익히기와 중계를 맡음
	- 1장에서는 동작 신호와 교정 피드백까지 맡고, 2장과 3장에서는 장을 열고 맺는 진행 멘트와 상대 배역 반응 중계를 맡음
- **익히기와 교정 피드백**
	- 익히기에서 동작 신호를 던지고, 기준에 미달한 응답에는 교정 피드백을 되돌려줌
	- 교정 문구는 판정 요소와 1:1로 맞춤: 진폭 미달이면 "더 크게!", 홀드 미달이면 "끝을 딱 맺어야지!", 타이밍 이탈이면 "장단에 맞춰!"
- **캐릭터 표현**
	- 배역과 마찬가지로 상태별 2D 애니메이션을 사전 제작하고, 진행 상황에 따라 상태를 바꿔 재생함
	- 갖추는 상태: 대기, 발화, 등장, 인정 선언, 환호
	- 발화 상태는 립싱크를 맞추지 않고 발화하는 동안 입 여닫기를 반복함
- **스킵**
	- 발화 중 다음 버튼을 누르면 발화를 중단하고 다음으로 진행함
- **타임아웃**
	- 발화 중에는 터치 미입력 타임아웃을 멈추고, 발화가 끝난 뒤 시간 체크 시작
- **대사 적용**
	- 장쇠의 대사는 런타임 생성 없이 사전 작성함. 진행 안내, 마당별 익히기와 장면 신호, 교정 피드백, 상대 배역 반응 중계, 인정 재담을 미리 써 두고 상황에 맞춰 재생함

### 3.4.3 실패와 복구

캐릭터 애니메이션이나 음성 합성(TTS) 재생이 실패하면 음성과 캐릭터 표현 없이 대기 상태 정지 그림과 텍스트 박스로만 진행함. 세션은 계속함.

## 3.5 화자와 보이스

### 3.5.1 역할과 목적

세션에 나오는 화자를 정하고 화자마다 보이스와 화자 표기를 배정함. 유저가 누구의 말인지 바로 가르게 함.

### 3.5.2 동작과 규칙

| 화자                  | 보이스                 | 맡는 말                                                         |
| ------------------- | ------------------- | ------------------------------------------------------------ |
| 장쇠                  | 공용 보이스              | 진행 안내, 익히기와 장면 신호, 교정 피드백, 상대 배역 반응 중계(포즈로 못 싣는 반응 서사), 인정 재담 |
| 유저 배역(꺽쇠, 말뚝이, 취발이) | 공용 보이스<br>(필요 시 분리) | 장면에서 유저 배역이 하는 대사                                            |
| 상대 배역(옴탈, 샌님, 먹중)   | 배역별 전용 보이스 3종       | 장면의 대거리 대사                                                   |

- **발화 방식**
	- 음성 합성(TTS)으로 대사를 재생하고 같은 대사를 화면 텍스트로 표시함
	- 음성은 한국어 고정이고, 화면 텍스트만 세션의 현재 언어로 표시함
- **유저 배역 대사**
	- 유저가 직접 소리 내어 말하지 않음
	- 사전 작성 대본이 유저 배역 자리에 표시되고 음성으로 재생되며, 유저는 대사가 아니라 몸동작을 맡음
- **화자를 가르는 수단**
	- 화면 텍스트에 화자를 함께 표기하고, 장면에서는 말풍선 자리로도 가름
- **대사 원천**
	- 모든 대사는 런타임 생성 없이 사전 작성함
	- 유저 배역과 상대 배역의 대사는 원전 연회본 발췌를 쓰고, 장쇠의 진행 대사는 따로 작성함
	- 원전에서 악사(잽이)가 판에 거는 말은 장쇠가 맡음. 먹중은 원전에 대사가 없는 무언 배역이라 먹중잡이의 대거리 대사도 장쇠가 맡음

### 3.5.3 실패와 복구

TTS 재생이 실패하면 음성만 빠진 채로 화면 텍스트 대사를 이어 가고 세션을 계속함.

## 3.6 동작 판정과 신명 지표

### 3.6.1 역할과 목적

동작 신호에 대한 유저의 몸 응답을 판정해 즉각 피드백으로 되돌리는 핵심 엔진으로 Step 3의 세 장이 같은 판정 규칙을 공유함

### 3.6.2 입력과 출력

- **입력**
	- 카메라 영상 프레임
	- 판정 요청(기대 동작 식별자 1개와 판정 구간을 담음)
- **출력**:
	- 신호별 판정 결과 (장쇠 피드백, 상대 배역 반응 연출, 절정 게이지 세 곳에 전달함)
	- 추임새 반응 트리거 (얼쑤 판정 시 발동. 규칙은 신명 지표와 추임새 반응 절 소유)
	- 장면 수행 기록 (신명 지표 포함. 세션 데이터에 저장하며 결과와 마무리 화면의 수행 요약과 이수 단계에 입력됨)
	- 베스트샷 후보 프레임 (판 벌이기의 얼쑤 판정 시점에 갈무리해 결과와 마무리 화면에 전달함)

### 3.6.3 판정 기본 규칙

- **지정 동작 판정 원칙**
	- 판정은 판정 요청이 특정한 기대 동작 1개에만 걸림. 자유 표현이나 행동의 의미적 적절성은 판정하지 않음
	- 기대 동작이 아닌 모든 움직임은 미수행 하나로 수렴해, 행동의 의미를 오독하는 판정을 구조적으로 없앰
- **판정 요소**
	- 판정 요소는 자세(기대 동작 스켈레톤과의 유사도), 진폭(관절 이동 크기), 홀드(자세 유지 시간), 타이밍(판정 구간 안 수행 여부)의 조합임
- **판정 구간**
	- 익히기와 겨루기: 동작 신호 발화가 끝난 뒤의 응답 대기(2초, 잠정)를 판정 구간으로 삼음
	- 판 벌이기: 같은 응답 대기를 쓰되, 옴탈잡이 마당에서는 응답 대기를 대목이 넘어갈 때마다 0.94배(잠정)씩 좁혀 장단 가속을 표현함(하한 1.4초, 잠정)
	- 확정 시점: 실기기 인식 성능을 보고 개발 단계에서 정함
- **판정 피드백 (3단, 잠정)**
	- 대성공(성공, 진폭 상위), 성공(성공), 미수행(실패)로 가름
	- 미수행 시 다시 진행하는 것은 재시도가 있는 익히기에서만 함. 겨루기와 판 벌이기에서는 판을 끊지 않고 다음 대목으로 넘어감
- **관대 판정**
	- 동작의 잘잘못을 정밀히 가리지 않고 수행으로 인정하는 쪽으로 임계를 잡음
	- 무인 공공 체험에서는 실제로 한 동작을 안 했다고 놓치는 판정이, 어설픈 동작을 후하게 인정하는 판정보다 체험을 크게 해치기 때문임

### 3.6.4 자세 판정 산출

판정 구간의 프레임들을 아래 5단계로 처리해 판정 요청 1개의 자세 값과 타이밍 값을 냄. 단계 구성은 동작 유사도 판정에 통용되는 기법을 따름.

1. **포즈 추정**: 카메라 프레임에서 유저의 2D 키포인트(관절 좌표 + 신뢰도)를 실시간 추출함
2. **전처리**: 신뢰도 임계(잠정 0.3) 미만 키포인트는 그 프레임의 일치도 비교에서 제외하고, 프레임 간 좌표 떨림은 스무딩으로 완화함
	- 신뢰도 임계는 채택할 포즈 추정 모델의 권장 임계와 실측으로 개발 단계에서 확정함
3. **정규화**: 몸 중심(양 힙의 중점)을 원점으로 옮기고 몸통 길이로 나눠 크기를 맞춤. 유저의 키, 화면 내 위치, 카메라까지의 거리와 무관하게 레퍼런스 스켈레톤과 비교하게 하는 단계임
4. **부위별 유사도**: 부위 벡터(어깨→팔꿈치, 팔꿈치→손목, 힙→무릎 등)의 방향을 레퍼런스 스켈레톤의 같은 부위와 코사인 유사도로 비교하고, 부위별 가중 평균으로 프레임 일치도를 냄
	- 덧뵈기 동작 세트가 팔 중심이라 팔 부위 가중을 상향함(잠정)
	- 관절 각도 차 비교는 동급 대안으로 두고 개발 단계에서 인식 성능을 보고 확정함
5. **판정**: 판정 구간 안 프레임 일치도의 최댓값으로 수행 여부를 가름
	- 진폭과 홀드는 같은 구간의 키포인트 궤적에서 산출함(진폭은 관절 이동 크기, 홀드는 임계 이상 자세 유지 시간)
	- 얼쑤 경계값 등 임계는 정량 미정으로 개발 단계에서 확정함

### 3.6.5 신명 지표와 추임새 반응

- **신명 지표**: 동작 성공과 진폭 상위(얼쑤)를 세션 동안 누계함(가중 산식은 작성 예정). 동작의 잘잘못을 세밀히 매기는 채점이 아니라 판이 얼마나 달아올랐는가를 남기는 활동 지표임
- **추임새 반응**: 대성공 판정 즉시 군중 추임새와 박수 사운드를 재생함. 추임새 사운드 겹침 시 후속 사운드는 재생하지 않음
- **이수 단계 분기**: 획득한 누적 신명 지표를 기준으로 이수 단계는 3단계로 구분
- **베스트샷 갈무리**: 판 벌이기에서 얼쑤 판정이 난 시점의 카메라 프레임을 메모리에 복사해 둠
	- 얼쑤가 여러 번이면 진폭이 가장 큰 판정의 프레임을 남기고 나머지는 버림
	- 얼쑤가 없으면 성공 판정 중 마지막 프레임을 씀. 성공이 하나도 없으면 갈무리하지 않고 결과와 마무리 화면에서 이 자리를 비움
	- 갈무리는 판 벌이기에서만 함. 가장 달아오른 대목의 한 장을 남기려는 것이라 익히기와 겨루기에서는 하지 않음
- **학습 진척**: 1차연도는 세션 안 수행으로 끝남. 재방문 진척 누적(마당 수집 현황, 향상 피드백)은 2차연도 확장 설계로 둠

### 3.6.6 기술 요건

- **모델 확보**
	- 실시간 포즈 추정에는 사전학습 모델과 온디바이스 SDK(소프트웨어 개발 키트)를 우선 검토함(MoveNet, MediaPipe Pose 류 실시간 경량 2D 키포인트 모델이 후보, 확인 필요)
	- 판정 로직은 레퍼런스 동작과 대조하는 자체 규칙임
- **판정 기준**
	- 포즈 추정 정확도, 판정 임계와 가중치, 실시간 처리 지연(프레임률)을 봄
	- 판정 정확도 검증 방법은 확인 필요
- **적용**
	- 실시간 처리임. 온디바이스 처리를 우선 검토하고 서버 처리는 대안으로 둠
	- 라이브는 원거리에서 전신 포즈를 판정하는 단일 구도임
	- 모션 인식은 전신 싱글 카메라 기준 손목까지가 현실적이라 동작 세트를 이 범위로 설계함(손가락 세부 동작 없음)
- **데이터**
	- 동작 세트의 모션 레퍼런스가 판정 기준 데이터임. 보존회 실연 촬영으로 확보함(고증 자문 연계, 확인 필요)
	- 시범 클립과 판정 레퍼런스 스켈레톤을 같은 촬영본에서 파생해 기준과 시범의 원천을 일치시킴

### 3.6.7 실패와 복구

- 판정 구간 안에서 포즈가 인식되지 않거나 신뢰도가 낮을 경우 및 인식 지연 시 처리
	- 해당 신호에 대한 응답을 미수행으로 처리하고 진행함(익히기는 재시도 규칙을 적용하고, 겨루기와 판 벌이기는 다음 신호로 넘어감)
- 사람 미검출이나 포즈 미검출이 터치 미입력 타임아웃 임계를 넘길 시 처리
	- 미입력 타임아웃으로 간주하여 종료 처리
- 카메라 영상이 들어오지 않거나 모든 프레임 저신뢰가 지속될 시 처리(지속 임계는 잠정, 개발 단계 확정)
	- 유저 요인이 아니라 시스템 장애(카메라 고장이나 가림, 조명, 성능 저하)로 보고 상황 안내 팝업 후 중단 처리함. 운영 알림 대상임

## 3.7 진행 중 종료

### 3.7.1 역할과 목적

유저에게 진행 중 그만둘 수단을 주는 시스템. 원치 않는 세션을 빨리 끝내 키오스크 회전율을 높임.

### 3.7.2 동작과 규칙

#### 1) 일반 규칙

- **처리**
	- 진행 중인 화면을 멈추고 결과와 마무리 화면(완주 전용)을 건너뛰어 세션 종료와 파기 후 시작 화면으로 복귀함(비완주 종료)

#### 2) 유저의 종료 선택 시 규칙

- **처리**
	- 그만두기 터치 시 그만두기 확인 팝업 표시
	- 확인 시 종료 처리하고, 취소 시 원래 화면 복귀
	  ![|500](../../assets/시범콘텐츠/공통/팝업_그만두기.png)

- **적용 화면**
	- Step 1 가이드 화면, 이용 동의 화면
	- Step 2 마당 선택 화면, 배역 확인 화면
	- Step 3 익히기, 겨루기, 판 벌이기 화면
- **예외 (미적용)**
	- Step 1 시작 화면
	- Step 4 마무리 화면
- **그만두기와 동시 이벤트 처리 (카메라 화면)**: Step 3에서 그만두기가 판정이나 타임아웃과 겹칠 때의 규칙임
	- 그만두기가 확정되면 진행 중인 동작 신호와 판정을 멈추고 세션 종료로 넘어감
	- 확인 팝업이 열린 동안에는 사람이나 포즈 미검출 측정만 멈추고 누적값을 0으로 되돌림.
	- 터치 미입력 타임아웃은 팝업이 열린 동안에도 계속 측정함.
	- 종료는 한 번만 처리해 이중 종료를 막음

## 3.8 화면 타임아웃

### 3.8.1 역할과 목적

유저가 한 화면에 오래 머무는 것을 막아, 무인 키오스크가 한 유저에게 묶이지 않게 하는 시스템.

### 3.8.2 동작과 규칙

- **처리**
	- 한 화면에서 60초(잠정) 이상 머물면 그 화면의 정상 진행 경로로 넘어감
	- 화면별 오버라이드: Step 3 세 화면 합산 5분(잠정). 마당 선택, 배역 확인, 결과와 마무리 화면은 기본값(60초, 잠정) 적용
	- 장쇠 발화 중에는 측정을 멈추고, 발화가 끝나거나 스킵한 뒤 재개함(잠정)
	  ![|500](../../assets/시범콘텐츠/공통/타임아웃_화면.png)

- **작업 상태**

## 3.9 터치 미입력 타임아웃

### 3.9.1 역할과 목적

입력이 끊긴 유저 이탈을 감지해 방치된 세션을 정리하고 키오스크 회전율을 높이는 시스템.

### 3.9.2 동작과 규칙

- **처리**
	- 한 화면에서 45초(잠정) 이상 터치나 동작 입력이 없으면 이탈로 보고 진행 중 종료 처리
	- 카메라와 모션 화면(Step 3 세 화면)은 터치가 없는 화면이라 사람이나 포즈 미검출을 이탈 기준으로 삼음
	- 그 화면에서도 확인 팝업이 열린 동안에는 미검출 대신 터치 무입력을 이탈 기준으로 삼음. 팝업은 터치를 기다리는 상태임
	- 장쇠 발화 중에는 측정을 멈추고, 발화가 끝나거나 스킵한 뒤부터 측정 시작. 다만 확인 팝업이 열려 있으면 발화 중에도 계속 측정함
	  ![|500](../../assets/시범콘텐츠/공통/타임아웃_미입력.png)

- **예외**
	- 감상 성격 화면(마무리 화면) 미적용

## 3.10 외부 서비스 호출 래퍼

### 3.10.1 역할과 목적

외부 서비스 호출(TTS)을 감싸는 공통 계층. 재시도와 타임아웃 대응을 한 곳에 모아, 호출마다 장애 처리를 따로 짜지 않게 함.

### 3.10.2 동작과 규칙

- **재시도 횟수**
	- 2회(잠정). 백오프는 1차 1초, 2차 3초(잠정)
- **호출 타임아웃**
	- TTS 30초(잠정)
- **한도 초과**
	- 재시도 한도를 넘긴 실패는 실패 처리로 넘김

## 3.11 실패 처리

### 3.11.1 역할과 목적

런타임 실패의 처리 정책. 무인 운영에서 실패가 방치되지 않게 함.

### 3.11.2 동작과 규칙

이 콘텐츠의 실패는 기능 축소와 중단 둘로 갈림. 유저가 입력하는 텍스트나 음성이 없어, 입력만 다시 받아 잇거나 다른 입력 수단으로 바꿔 잇는 갈래는 없음.

#### 1) 기능 축소

- 보조 기능이 빠져도 체험이 남는 갈래임. 그 기능만 빼고 세션을 이어 감
- 포즈 미검출 구간(판정 보류로 처리), 장쇠 발화 실패(대기 상태 정지 그림과 텍스트로 진행), 상대 배역 반응 표시 실패(대기 상태 정지 그림과 효과음으로 대체)가 여기 속함

#### 2) 중단

- 세션을 시작하거나 핵심 체험을 이어 갈 수 없는 실패 갈래임(세션 생성 실패, 마당 리소스 로드 실패, 카메라와 인식 계통의 지속 장애)
- 상황 안내 팝업을 띄우고 마무리 화면을 건너뛰어 세션 종료와 파기 후 시작 화면으로 자동 진행함. 별도 실패 화면을 두지 않음
	- 예외: 세션 생성 실패는 정리할 세션 자체가 없어 종료 처리도 거치지 않고 곧장 시작 화면으로 되돌림

#### 3) 운영 알림

- 원인이 외부 서비스나 시스템이면 운영 알림을 보내고, 유저면 보내지 않음

## 3.12 탈과 마당 대목 고증 (공통 레퍼런스)

### 3.12.1 역할과 목적

배역 탈, 마당 대목, 배역 동작의 고증 기준을 정의하는 설계 레퍼런스. 마당 선택 목록, 장면 대본, 동작 판정, 사전 자산 검수가 같은 기준을 참조해 전통 정합성 판정이 서로 어긋나지 않게 함.

### 3.12.2 동작과 규칙

#### 1) 마당과 배역

| 마당   | 유저 배역 | 상대 배역 |
| ---- | ----- | ----- |
| 옴탈잡이 | 꺽쇠    | 옴탈    |
| 샌님잡이 | 말뚝이   | 샌님    |
| 먹중잡이 | 취발이   | 먹중    |

#### 2) 탈 캐릭터

- 덧뵈기 탈 캐릭터 중 총 7종을 사전 제작
	- 유저 배역 3종(꺽쇠, 말뚝이, 취발이), 상대 배역 3종(옴중, 샌님, 먹중), 호스트 장쇠

#### 3) 마당 대목과 동작 세트

- **대본 원천**
	- 선택한 마당의 연회본을 앞대목(2장)과 뒷대목(3장)으로 나눠 순서대로 진행함
	- 대사는 원문 그대로 쓰고 한 호흡에 안 들어가는 긴 사설만 문장 경계에서 줄임
- **빼는 대목**
	- 공공 전시에 부적절하거나 유저가 할 일이 없는 대목만 뺌
	- 먹중잡이 끝의 피조리 품평은 넣지 않고, 샌님잡이 도입은 판정 없는 대사 3개로 압축함
- **공용 동작 세트**
	- 상대 배역: 등장, 대기, 신호별 반응(성공용 과장 반응, 미수행용 중립 반응), 결말(나가떨어지는 연기 등)
	- 유저 배역: 대기, 판정별 반응(성공, 미수행), 절정 결말의 승리 포즈
- **마당 별 동작 세트**: 1965년 기록영상 판독에서 확인된 사위와 원전 지시문을 조합하되 명칭과 구성은 고증 자문으로 확정함
	- 옴탈잡이(꺽쇠): 손 치켜들기(한 팔 높이 들기), 찔러보기(팔 뻗기), 휘둘러 쫓기(팔 휘두르기)
		- 첫 동작을 손 치켜들기로 둔 근거: 원전에서 살피는 쪽은 옴탈이고 꺽쇠는 쫓기다 어이없어함(전사본 428행). 유저 동작을 어이없어하는 몸짓으로 두어 원전의 주체를 지킴(2026-08-18 사용자 결정). 이어지는 꺽쇠 대사 "하늘 높은 줄 모르고"와도 붙음
		- 몸짓 형태: 한 팔을 머리 위로 곧게 치켜들어 손바닥을 펴고, 상체를 앞으로 숙인 채 버팀. 탈은 표정이 고정이라 놀람을 얼굴로 못 내므로 몸으로 크게 냄
	- 샌님잡이(말뚝이): 채찍 휘두르기(팔 휘두르기), 거드름 흉내(상체 젖히기), 삿대질(팔 뻗기)
	- 먹중잡이(취발이): 어깨 메기(소매 얹기), 한발 차올리기(다리 들기), 소매 뿌리기(팔 휘두르기)

#### 4) 각색 원칙 (전 마당, 고증 자문 연계)

- 옴탈잡이: 옴(피부병) 조롱 개그의 톤을 낮춤(간지럼 소동 방향). 탈 도상 해설은 사실 서술로 함
- 샌님잡이: 째보 탈 도상 해설을 신분 풍자의 기호로 맥락화함. 외모 놀리기 재담과 절 말장난 고어는 현대어 풀이를 병행함
- 먹중잡이: 피조리 관련 성적 재담을 제거하고, 대결 명분을 먹중의 행패 응징으로 단순화함. 파계승 풍자임을 분명히 함
- 전 마당 공통: 고어는 현대어 풀이 병행, 욕설과 육담은 순화함

#### 5) 시각 정체성

- 탈 양식과 질감의 전통 정합성 유지
- 사전 제작 자산(장쇠 캐릭터, 배역 애니메이션)은 운영 전 고증 검수를 거침

### 4.2.1 클라이언트: 마당 선택 화면

	- 분기: 미입력 타임아웃 → 종료 처리

#### 2) 마당 선택 목록

##### (1) 역할과 목적

유저가 체험할 마당 하나를 고르는 선택 도구. 마당마다 재미 유형이 달라(잡기, 놀리기, 이기기) 고르는 것 자체가 극 구조 학습의 시작이 되게 함.

##### (2) 동작과 규칙

- **목록 구성**: 마당 카드 3종. 카드마다 마당 이름, 한 줄 소개, 유저 배역과 상대 배역을 표기함
	- 옴탈잡이: 슬금슬금 나타난 옴탈을 꺽쇠가 되어 잡아 쫓는 마당
	- 샌님잡이: 거드름 피우는 샌님을 말뚝이가 되어 놀려 뒤집는 마당
	- 먹중잡이: 행패 부리는 먹중을 취발이가 되어 춤으로 눌러 이기는 마당
- **기본 선택**: 진입 시 목록 첫 번째 마당을 기본 선택으로 둠
- **미리보기**: 선택한 마당의 절정 장면 이미지 표시

## 4.3 Step 3. 마당 장면 체험 (핵심 체험)

한 마당을 3장으로 진행함: 익히기(배역 동작 배우기) → 겨루기(상대 배역과 동작 신호 주고받기) → 판 벌이기(절정 대목 완수).

### 4.3.1 클라이언트: 익히기 화면 (1장)

<img src="../../assets/시범콘텐츠/탈춤/3_1.png" width="500">

#### 1) 진행

1. 장쇠가 익히기를 열고 선택 마당의 동작 세트 3개를 하나씩 가르침
2. 동작마다 시범 클립 재생 → 유저 수행 → 판정 → 장쇠 피드백을 되풀이함
	- 성공 시 다음 동작으로 진행하고, 미수행 시 교정 피드백과 함께 재시도함(동작당 2회 잠정). 재시도를 소진하면 장쇠가 눙치고 통과 처리해 진행을 막지 않음
3. 동작 3개를 마치면 장쇠가 익히기를 맺고 겨루기로 진행함
	- 분기: 그만두기 선택 시 확인 팝업 → 확정 시 종료 처리
	- 분기: 사람이나 포즈 미검출이 터치 미입력 타임아웃 임계를 넘기면 이탈로 보고 종료 처리

#### 2) 마당별 익히기 내용

동작 세트의 고증 근거와 각색 원칙은 탈과 마당 대목 고증 절이 소유함. 판정 특징은 동작 판정 엔진의 판정 요소 조합임.

| 마당 | 동작 1 | 동작 2 | 동작 3 |
|---|---|---|---|
| 옴탈잡이 (꺽쇠) | 손 치켜들기 (한 팔 높이 들기 + 홀드) | 찔러보기 (팔 뻗기 진폭) | 휘둘러 쫓기 (팔 휘두르기 진폭 + 속도) |
| 샌님잡이 (말뚝이) | 거드름 흉내 (상체 젖히기 + 홀드) | 삿대질 (팔 뻗기 + 홀드) | 채찍 휘두르기 (팔 휘두르기 진폭 + 속도) |
| 먹중잡이 (취발이) | 어깨 메기 (팔 얹기 + 홀드) | 한발 차올리기 (발목 높이 진폭) | 소매 뿌리기 (팔 휘두르기 진폭 + 속도) |

### 4.3.2 클라이언트: 겨루기 화면 (2장)

<img src="../../assets/시범콘텐츠/탈춤/3_2.png" width="500">

#### 1) 진행

1. 상대 배역이 등장하고(등장 포즈와 이펙트), 장쇠가 장면을 엶
2. 장면 대본의 신호를 차례로 진행함: 상대 배역이나 장쇠의 재담에 얹힌 동작 신호 → 유저의 몸 응답(동작 판정) → 상대 배역 반응 연출을 되풀이함
	- 유저 배역의 대사 차례가 오면 유저 배역의 말풍선에 그 대사가 나오고, 유저는 몸으로 수행함
	- 미수행이어도 장면은 멈추지 않고 상대 배역의 중립 반응으로 진행함(재시도 없음)
3. 대본의 신호를 모두 마치면 장쇠가 장면을 맺고 판 벌이기로 넘어감
	- 분기: 그만두기 선택 시 확인 팝업 → 확정 시 종료 처리
	- 분기: 사람이나 포즈 미검출이 터치 미입력 타임아웃 임계를 넘기면 이탈로 보고 종료 처리

#### 2) 마당별 앞대목 대본

앞대목은 선택한 마당의 연회본을 순서대로 진행함. 대사는 원문이고 각색 원칙은 탈과 마당 대목 고증 절이 소유함.

| 마당   | 진행 (상대 배역 원문 대사 → 유저의 기대 동작)                                                                             |
| ---- | -------------------------------------------------------------------------------------------------------- |
| 옴탈잡이 | 옴탈 등장 → 쫓으며 살피는 연기와 "이놈이 뭣하는 놈인고"(손 치켜들기) → "남의 의관 절단난다"(찔러보기) → "내 네 얼굴 같으면 문지방도 안 넘것다"(휘둘러 쫓기)      |
| 샌님잡이 | 샌님과 노친네 도입 3대사(판정 없음) → "애, 뚝아, 말뚝아!"(채찍 휘두르기) → "양반을 만났으면 절을 하는 게 아니라"(거드름 흉내) → "너 절 모르느냐"(삿대질)        |
| 먹중잡이 | 먹중 등장과 취발이 사설(판정 없음) → "여보게 안암산이 컴컴한 거 모르나"(어깨 메기) → "중이 속가에 내려와 농탕친다네"(소매 뿌리기) → "어디 한번 얼러 보게"(한발 차올리기) |

#### 3) 상대 배역 반응 연출

##### (1) 역할과 목적

상대 배역(옴탈, 샌님, 먹중)과 유저 배역을 판에 나란히 세우고, 그 연기를 2D 애니메이션과 이펙트로 내는 시스템. 유저 동작이 판정을 통과하는 순간 과장된 반응 연기와 효과음, 장쇠의 중계 재담을 되돌려 슬랩스틱의 웃음을 보상으로 완성함.

##### (2) 입력과 출력

- **입력**: 신호별 판정 결과(동작 판정에서 수신), 장면 진행 상태(각 장의 진행에서 수신)
- **출력**: 배역 애니메이션 전환과 이펙트 표시(화면 연출), 장쇠 중계 재담 재생 트리거

##### (3) 동작과 규칙

- **판 배치**
	- 상대 배역을 판 왼쪽에, 유저 배역을 오른쪽에 세움
	- 각 배역의 대사는 제 머리 위 말풍선에 표시하고, 장쇠는 판 밖 왼쪽 열에서 말함
- **유저 배역 표시**
	- 반응 규칙은 상대 배역과 같되, 갖추는 상태 구성은 다름(아래 애니메이션 세트와 상태)
	- 판정이 확정되면 그 결과에 맞는 상태로 넘어감. 성공이면 유저가 수행한 배역 동작을 판 위의 유저 배역이 그대로 이어 연기하고, 미수행이면 미수행용 중립 반응으로 넘어감
	- 유저가 제 몸짓의 결과를 배역의 몸으로 확인하는 자리임
- **표시 우선순위**
	- 겹칠 때 배역 애니메이션이 가장 아래, 말풍선이 그 위, 판정 표시가 가장 위임
	- 말풍선은 배역 그림의 윗변 위에만 놓고 얼굴과 상체를 덮지 않음
- **한 번에 띄우는 글자수**
	- 말풍선이 배역을 덮지 않는 범위에서 정함
	- 한도를 넘는 대사는 원문을 고치지 않고 문장 경계에서 나눠 차례로 띄움
- **애니메이션 세트와 상태(Animation State)**
	- 배역마다 상태별 2D 애니메이션을 사전 제작하고, 장면 진행과 판정 결과에 따라 상태를 바꿔 재생함
- **장쇠 중계**
	- 포즈와 이펙트로 싣지 못하는 반응 서사("저놈 봐라, 뒷걸음질을 친다!" 류)는 장쇠가 중계 재담으로 발화함
- **제작 방식**
	- 런타임 생성 없이 사전 제작본만 쓰고, 운영 전 검수를 거침

##### (4) 기술 요건

- **표시**: 전부 클라이언트 로컬 처리임. 서버 왕복 없음
- **사전 로드**: 마당 확정(Step 2) 후 Step 3 진입 전에 해당 마당의 배역 애니메이션, 대본, 판정 자산, 음원을 미리 로드해 체험 중 로딩 끊김을 없앰
- **판정 기준**: 반응 표시 지연(판정 확정에서 애니메이션 전환까지, 정량 미정), 그림 일관성(캐릭터 시트 대비, 검수 기준 작성 예정)

##### (5) 실패와 복구

- 애니메이션 전환이나 이펙트가 실패하면 해당 배역의 대기 상태 정지 그림과 효과음으로 대체하고 장면을 계속함(기능 축소)
- 장쇠나 상대 배역의 음성 재생이 실패하면 음성 없이 화면 텍스트와 애니메이션으로 장면을 계속함(기능 축소)
- 배역 애니메이션 로드 실패는 마당 리소스 로드 실패로 묶어 중단 처리함(재시도 2회 잠정)

### 4.3.3 클라이언트: 판 벌이기 화면 (3장)

<img src="../../assets/시범콘텐츠/탈춤/3_3.png" width="500">

#### 1) 진행

1. 무대 격상 연출: 배역들이 뒤에 일렬로 서는 관망 정렬 배경(잠정)과 함께 장쇠가 절정을 선언하고 장단이 시작됨
2. 뒷대목 대본을 순서대로 진행함: 앞대목과 같이 차례를 주고받는 진행이며, 앞으로 받을 응수 동작이 동작 안내 바에 차례로 놓임
	- 응수 성공 시 절정 게이지가 차되, 판정 등급에 따라 게이지 가산량이 다름
	- 대본을 마쳤을 때 게이지가 가득 찼으면 절정 결말 연출을 재생함: 마당별 결말은 아래 표
	- 미달이면 완화 결말을 재생하고(문안과 연출 작성 예정) 완주로 처리함
3. 결말 연출과 마당별 원전 마무리 대사를 마치면 완주로 보고 Step 4 결과와 마무리로 진행함
	- 분기: 그만두기 선택 시 확인 팝업 → 확정 시 종료 처리
	- 분기: 사람이나 포즈 미검출이 터치 미입력 타임아웃 임계를 넘기면 이탈로 보고 종료 처리

#### 2) 마당별 뒷대목 연출

뒷대목도 연회본을 순서대로 진행하고, 대본을 마쳤을 때의 절정 게이지로 결말을 가름.

| 마당   | 진행                                                  | 결말 연출                               |
| ---- | --------------------------------------------------- | ----------------------------------- |
| 옴탈잡이 | 얼굴 내력 문답으로 붙었다가 채검에서 옴이 드러나고, 발악하는 옴탈을 춤으로 몰아냄      | 옴탈이 화면 밖으로 튕겨 나가 퇴장                 |
| 샌님잡이 | 샌님이 절을 가르친다며 지시를 쏟아내고, 말뚝이가 그 말을 그대로 되받아 넘기다 판이 뒤집힘 | 샌님이 말뚝이에게 큰절을 올리고, 유저는 버티고 서서 절을 받음 |
| 먹중잡이 | 말 대신 춤으로 붙는 대목. 먹중은 무언 배역이라 도발을 동작으로만 걸고 장쇠가 판을 중계함 | 먹중이 취발이의 코를 때리고 달아나 판이 취발이에게 넘어감    |

#### 3) 절정 시퀀스 진행기

##### (1) 역할과 목적

뒷대목 대본을 응수 단위로 진행하고 절정 게이지를 산출하는 시스템. 장단 박과 응답 대기 조절로 앞대목보다 판을 몰아감.

##### (2) 입력과 출력

- **입력**: 선택 마당 식별자, 뒷대목 대본, 신호별 판정 결과
- **출력**: 판정 요청, 동작 안내 바 표시, 절정 게이지 값

##### (3) 동작과 규칙

- **진행 단위**
	- 앞대목과 같이 차례를 주고받는 진행임
	- 상대 배역의 원문 대사(먹중잡이는 무언 도발) → 유저 응수와 판정 → 반응 연출과 장쇠 중계 → 유저 배역의 원문 응답을 대본 끝까지 되풀이함
- **장단**
	- 마당별 장단을 배경 박으로 깖(옴탈잡이 112, 샌님잡이 96, 먹중잡이 104 BPM 잠정)
	- 진행을 재는 기준 시계가 아니라 판의 열기를 얹는 배경임
- **장단 가속**
	- 옴탈잡이에만 적용함. 대목이 넘어갈 때마다 응답 대기를 0.94배(잠정)씩 좁혀 몰아치는 느낌을 냄
	- 하한은 기본 응답 대기라 손이 못 따라갈 만큼 좁아지지 않음
- **동작 안내 바**
	- 화면 하단의 가로 바임. 뒷대목에서 나올 응수 동작의 픽토그램이 오른쪽에 차례로 줄 서 있음
	- 대목이 끝날 때마다 한 칸씩 왼쪽으로 미끄러져 표시선에 듦
	- 표시선에 든 동작은 아래 띠가 남은 응답 시간에 비례해 줄어들고, 판정이 나면 픽토그램이 성공이나 미수행 표시로 바뀜
- **판정 피드백**
	- 판정 결과(얼쑤, 좋다, 다시)를 판 위에 짧게 표기함(동작 판정 출력 연동)
- **절정 게이지**
	- 100을 뒷대목 응수 개수로 나눈 값(소수 유지, 절사 없음)만큼 응수 성공마다 게이지가 차오르고, 진폭 상위(대성공)는 가산이 더 큼(잠정 배분: 대성공 1.15배, 성공 0.85배)
	- 게이지는 100에서 멈춤(초과분은 버림). 잠정 배분 기준으로 미수행 없이 대성공을 절반 이상 받으면 가득 차고, 성공만으로는 85에 그쳐 완화 결말로 감
	- 이 장의 결말을 가르는 화면 표시 게이지이며, 내부 활동 지표인 신명 지표와는 별개로 산출함

##### (4) 기술 요건

- **적용**: 전부 클라이언트 로컬 재생임. 서버 왕복 없음

##### (5) 실패와 복구

- 대본, 픽토그램, 음원 로드나 검증이 실패 시 처리
	- 재시도(2회 잠정) 실행. 한도를 넘기면 마당 리소스 로드 실패로 중단 처리(원인: 시스템)
- 장단 재생이 끊길 시 처리
	- 배경 박이라 진행에 영향이 없음. 장단 없이 대본을 이어 감(기능 축소)

## 4.4 Step 4. 결과와 마무리

### 4.4.1 클라이언트: 결과와 마무리 화면

<img src="../../assets/시범콘텐츠/탈춤/4_1.png" width="500">

#### 1) 진행

- **인정 선언**
	- 장쇠가 인정 재담을 발화함
	- 완주를 먼저 인정하고 그 위에 이수 단계를 얹음
- **이수 단계 (칭호)**
	- 세션 동안 쌓인 신명 지표가 얼마나 되는지로 가름. 낮은 쪽부터 구경꾼, 초짜 광대, 한몫 광대임(칭호 이름 잠정, 고증 자문 연계)
	- 단계를 가르는 경계값 둘은 정량 미정이며, 실기기에서 유저들이 실제로 쌓는 값을 보고 개발 단계에서 정함
- **수행 요약**
	- 1장 익히기, 2장 겨루기, 3장 판 벌이기를 각각 한 줄로 두고, 장마다 판정 3단의 개수를 대성공, 성공, 미수행 순으로 표시함
	- 하이라이트 동작 1개를 칭찬 문구로 함께 표시함
- **베스트샷**
	- 판 벌이기에서 갈무리한 한 장을 화면에 띄움. 사진 위에 마당 이름, 배역 이름, 이수 단계를 얹은 액자로 보여 줌
	- 갈무리한 장이 없으면 이 자리를 비우고 나머지 구성만 표시함
- **받기 (QR)**
	- 이 화면에 들어설 때 베스트샷을 서버에 올리고, 받은 다운로드 주소로 QR을 그려 액자 옆에 띄움. 유저가 자기 휴대폰으로 스캔해 사진을 받아 감
	- QR 옆에 스캔 안내와 내려받을 수 있는 기간(48시간, 잠정)을 적음
	- 베스트샷이 없거나 업로드가 실패하면 QR 자리를 비우고 나머지 구성만 표시함
- **완주 확정**
	- 이 화면 진입이 완주 확정이자 베스트샷 업로드 시점임. 진입 시의 단계 이동 이벤트(각 Step 진입 전송)가 서버의 완주 기록을 겸해, Step 5 도달 전에 세션이 끊겨도 완주가 유실되지 않음
	- 분기: 처음으로 버튼 터치 또는 화면 타임아웃(기본 60초, 잠정) → Step 5 종료와 리셋으로 진행

### 4.4.2 서버: 베스트샷 호스팅과 만료 파기

#### 1) 진행

- 클라이언트가 올린 베스트샷을 받아 웹에 호스팅하고, 만료형 다운로드 주소를 발급해 돌려줌. 클라이언트가 그 주소로 QR을 그림
- 올리는 것은 액자 합성본임. 화면에 띄우는 것과 같은 그림(마당 이름, 배역 이름, 이수 단계를 얹은 액자)을 그대로 올리고, 액자 없는 카메라 원본은 올리지도 제공하지도 않음
- 유저가 그 주소로 여는 다운로드 페이지의 화면과 규칙은 결과물 다운로드 페이지 사양이 소관임
- 주소는 추측할 수 없는 난수로 만들고 세션 ID나 장면 수행 기록과 이어 붙여 저장하지 않음. 받는 사람을 식별하지 않는 익명 다운로드임
- 다운로드 기간(48시간, 잠정)이 지나면 호스팅 사본과 주소를 함께 지움. 세션 종료와는 별개로 도는 만료 파기임
- 업로드나 호스팅이 실패하면 QR 없이 진행함(기능 축소). 세션은 계속 진행되고 유저는 화면에서 베스트샷을 보기만 함
	- 공통 실패 모델은 호스팅 실패를 중단으로 처리하지만 이 콘텐츠는 예외로 기능 축소를 적용함. 반출물이 핵심 산출물인 콘텐츠와 달리 이 콘텐츠의 완주는 체험 완료로 이미 성립해, 덤인 사진의 전달 실패로 세션을 끝내는 것이 더 큰 손실이기 때문임
	- 실패는 세션 데이터의 에러 유형에 기록해 QR 미전달을 운영에서 관측하게 함. 화면에는 QR 자리만 비우고 별도 안내를 띄우지 않음

## 4.5 Step 5. 종료와 리셋

완주와 비완주 두 경로로 진입하고 모두 세션 종료와 파기를 실행함. 별도 UI 없음.

### 4.5.1 클라이언트: 종료 이벤트 전송과 리셋

#### 1) 진행

- 종료 이벤트(완주 또는 이탈 결과)를 서버로 전송하고, 서버의 저장 확인 응답을 받은 뒤 클라이언트 세션 데이터를 초기화함
	- 확인 응답을 재시도(2회 잠정) 후에도 받지 못하면 로컬 세션 데이터를 파기하고 시작 화면으로 복귀함(다음 유저의 키오스크 점유가 우선)
	- 미종료로 남은 서버 세션의 정리 방식은 서버 구현에서 확정함(확인 필요)
	- 완주는 유형(처음으로 버튼 터치, 결과와 마무리 화면 타임아웃)을 구분해 기록함: 완주율 관측에서 방치 완주를 분리함
	- 완주와 비완주 종료가 모두 모이는 종착점임. 비완주 종료는 결과와 마무리 화면을 건너뛰고 여기로 바로 들어옴

### 4.5.2 서버: 세션 종료와 임시 데이터 파기

#### 1) 진행

- 세션 종료를 확정하고 세션 데이터를 정리함(장면 수행 기록의 식별 원본은 파기하고 익명 통계만 남김. 영상 피드는 처리 직후 이미 파기됨)
- 베스트샷 호스팅 사본과 다운로드 주소는 세션 종료로 지우지 않음. 세션과 수명이 달라 다운로드 만료(48시간, 잠정) 때 지움

## 5.2 에러 케이스

### 5.2.1 케이스 목록과 처리

**처리**는 그 실패가 세션을 어떤 상태로 끝내는지를, **원인**은 실패가 어디에서 비롯되었는지를 나타냄. 원인이 외부 서비스나 시스템일 경우에만 운영 알림을 보냄. 갈래를 나누는 판정 규칙은 실패 처리 절에 있고, 본 표는 그 규칙을 케이스에 적용한 결과임. 이후 동작의 Step 5는 모두 비완주 종료라 결과와 마무리 화면을 건너뛰고 세션 종료와 파기 후 시작 화면으로 복귀함.
