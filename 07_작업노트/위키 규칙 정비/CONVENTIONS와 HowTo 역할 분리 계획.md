> `CONVENTIONS.md`와 HowTo 문서 9개의 소유 범위를 다시 나누기 위한 비교 결과와 실행 계획임. 이번 문서는 정비 계획만 다루며 규칙 원문은 바꾸지 않음.

# 1. 검토 범위와 방법

- **기준 문서**: 저장소 전체의 위키 작성 표준인 [[CONVENTIONS|위키 작성 규칙]] 1~414행을 기준으로 삼음
- **비교 범위**: `01_HowTo/`의 마크다운 문서 9개를 파일별로 처음부터 끝까지 읽음
- **비교 순서**: H01부터 H09까지 한 문서씩 비교했으며 여러 HowTo 문서를 한 번에 합쳐 판정하지 않음
- **분절 기준**: HowTo 문서에서 규칙의 주체, 적용 대상, 실행 절차 또는 소유 문서가 바뀌는 지점을 근거 단위로 나눔
- **판정 종류**:
	- 중복: 같은 규칙이나 절차를 두 문서가 함께 설명함
	- 경계: 내용은 연결되지만 어느 문서가 정본(해당 규칙의 단일 기준 문서)인지 불명확하거나 예외가 빠짐
	- 고유: 해당 HowTo의 작업에만 필요한 절차나 사례임

# 3. 역할 분리 원칙

세 문서군의 역할을 규칙, 방법, 운영 주체로 구별함.

| 소유처 | 맡을 내용 | 넣지 않을 내용 |
|---|---|---|
| `CONVENTIONS.md` | 모든 위키 문서에 공통으로 적용하는 저장 위치, 문서 형식, 문체, 링크, 근거, 헤딩, 폴더별 수정 가능 여부와 로그 형식 | 특정 파일 형식의 도구 사용법, 과거 사고 경위, 검수 프롬프트 전문, 콘텐츠별 제작법 |
| `01_HowTo/` | 특정 작업을 실제로 수행하는 순서, 판단 기준, 예외, 문제 해결, 사례와 재현 방법 | 저장소 전체에 새 의무를 부과하는 상위 정책, 에이전트 역할과 승인 권한 |
| `AGENTS.md` | 작성자, 외부 검토자와 사용자의 역할별 실행 권한, 호출 조건, 승인 게이트와 필수 검사 시점 | 문체 세부 예시, 도구별 변환 알고리즘, 개별 콘텐츠 제작법 |

내용의 소유처는 다음 질문으로 판정함.

1. 어떤 위키 문서를 쓰더라도 지켜야 하면 `CONVENTIONS.md`가 소유함
2. 특정 작업이나 파일 형식에서만 필요하면 해당 HowTo가 소유함
3. 누가 언제 실행하고 승인하는지를 정하면 `AGENTS.md`가 소유함
4. 과거 결함의 증상, 원인과 재발 질문이면 [[반복 결함 카탈로그]]가 소유함

예외로 외부 검토에 필요한 규칙의 자체 완결형 복제는 허용함. 이때는 원본 규칙과 동기화해야 하는 파생 텍스트로 표시함.

# 5. CONVENTIONS 정리 방향

`CONVENTIONS.md`는 세부 작업 설명서가 아니라 저장소 전체의 짧은 계약으로 정리함.

## 5.1 유지할 내용

- **핵심 원칙**: Atomic Notes, 한국어 우선, 엔티티 분리, 상호 연결과 사실 우선 원칙을 유지함
- **저장소 구조**: 폴더별 역할, 참조 방향, 산출물층과 작업노트층의 경계, 읽기 전용 영역을 유지함
- **문서 계약**: 프론트매터, 제목원, 기본 문체, 위키링크, 인용과 근거 등급을 유지함
- **공통 문법**: 헤딩 깊이와 번호 체계, anchor 규칙을 유지함
- **정적 완료 조건**: MOC 등록 필요 여부, 로그 항목 형식과 수정 문서의 날짜 규칙을 유지함

## 5.2 줄일 내용

- 목록과 표의 선택 기준, 라벨형 불릿과 중첩 불릿의 상세는 [[문서 작성 세부 규칙]]으로 보냄
- 수집, 질의, 유지의 실행 순서와 문서 생성 단계는 [[위키 운영 워크플로]]로 보냄
- 절 참조 이관의 역사, 과거 오변환 수치와 복구 방법은 [[절 참조 오변환 점검 절차]]로 보냄
- 변환기, 이미지 생성과 번역에만 필요한 설정 및 사례는 해당 HowTo에만 둠

## 5.3 새로 명확히 할 내용

- **변환 산출물 예외**: `02_References/converted/`가 일반 위키 프론트매터와 문체 규칙의 적용 대상인지 명시함
- **원문 보존 우선순위**: 변환본이 원문의 가운뎃점과 em dash를 보존할 때 일반 문체 금지보다 우선하는지 명시함
- **수치 근거 범위**: 과제 수치, 외부 사실, 코드 상수와 내부 시험 집계를 같은 방식으로 인용해야 하는지 구별함
- **파생 규칙 관리**: 검수 프롬프트처럼 규칙을 복제해야 하는 문서는 원본 anchor와 동기화 책임을 표시함
- **절차와 결과 구분**: 문서를 만드는 순서는 HowTo와 `AGENTS.md`가, 완성 문서가 만족할 형식은 `CONVENTIONS.md`가 소유하도록 명시함

# 6. 문서별 정리 계획

이 절은 [[#4. 근거 단위와 정리 방향 대응]]의 판단을 실제 변경 목록으로 풀어 씀. 실제 정비에서는 HowTo 문서를 한 번에 묶지 않고 아래 아홉 문서를 각각 별도 단계로 처리함.

## 6.1 H01 docx 변환 파이프라인

- HWPX와 DOCX 파서, 출력 형식, 검수 큐와 문제 해결은 유지함
- 디렉터리의 일반 정의와 로그 양식은 반복하지 않고 `CONVENTIONS.md`를 가리킴
- 작업자가 알아야 하는 실제 입출력 경로는 절차 이해에 필요한 최소 반복으로 유지함
- 변환본 프론트매터와 원문 부호 보존을 공통 규칙의 명시적 예외로 맞춤

## 6.2 H02 PDF 읽기 절차

- 실질적인 중복이 없으므로 내용 이동 없이 유지함
- `CONVENTIONS.md`에는 PDF 도구 순서를 새로 넣지 않음
- 다른 문서를 정비한 뒤 관련 링크와 상위 정본 표현만 재확인함

## 6.3 H03 문서 작성 세부 규칙

- 문서 유형별 구조, 형식 선택, 라벨형 불릿과 중첩 불릿의 상세 정본으로 확정함
- `CONVENTIONS.md`의 ‘한 불릿 한 생각’, 긴 항목 분리와 작성 전 구조 설계 세부를 이 문서로 흡수함
- `CONVENTIONS.md`에는 구조 우선 원칙과 이 문서로 가는 필수 링크만 남김
- 원자료를 구조화하기 전 근거를 추출하는 규칙은 사실 보존과 관련되므로 `CONVENTIONS.md`에 유지함

## 6.4 H04 반복 결함 카탈로그

- 발견 날짜, 증상, 진단, 실제 사례와 재발 검수 질문을 모두 유지함
- 각 항목의 `권고 점검`은 새 규칙의 소유처가 아니라 현행 정본을 검사하는 질문임을 문서 상단에서 명시함
- PROCESS-002처럼 `CONVENTIONS.md`와 상세가 반복되는 항목도 역사와 검수 패킷의 자체 완결성을 위해 유지하되 파생 관계를 표시함
- 현행 규칙이 바뀌어도 과거 발견 사실은 고치지 않고, 권고 질문과 정본 링크만 동기화함

## 6.5 H05 외부 검수 포커스

- 외부 세션에 전달하는 프롬프트 전문과 발췌 조합은 유지함
- P1부터 P5까지의 블록과 가독성 블록에서 공통 규칙을 복제한 부분은 `CONVENTIONS.md`와 [[문서 작성 세부 규칙]]에서 파생됐다고 표시함
- 원본 규칙이 바뀔 때 함께 점검해야 할 anchor 목록을 문서에 둠
- 검토자 권한, 호출 조건과 승인 게이트는 `AGENTS.md`를 정본으로 삼고 중복 설명을 줄임

## 6.6 H06 위키 운영 워크플로

- 수집, 질의, 유지와 Overview 갱신의 실행 절차를 전담함
- `CONVENTIONS.md`의 문서 생성과 갱신 순서를 이 문서로 옮기고, 공통 문서에는 필수 결과만 남김
- 모든 작업에서 로그를 남겨야 하는 시점은 `AGENTS.md`가 소유함. 수집, 질의와 유지 안의 구체적인 기록 시점은 이 문서가 소유하고, 로그 형식은 `CONVENTIONS.md`가 소유함
- MOC의 역할 정의는 `CONVENTIONS.md`에 유지하고, 등록 시점과 연쇄 갱신 방법은 이 문서가 소유함

## 6.7 H07 인포그래픽 생성 지침

- 렌더 문자열, 레이아웃, 프롬프트, 이미지 생성과 검수 절차를 유지함
- 분석 뒤 구조화와 쉬운 낱말 사용은 일반 규칙을 다시 설명하지 않고 정본을 가리킨 뒤 이미지 적용만 적음
- 내부 시험에서 나온 렌더 문자열 항목 수는 재현 가능한 근거를 연결하거나 정확한 수치를 제거함
- 모델명, 해상도와 품질 설정은 사실 주장인지 실행 설정인지 구분하고 갱신 책임을 명시함

## 6.8 H08 절 참조 오변환 점검 절차

- 마이그레이션 이력, 오변환 흔적, 자동 탐지 한계, 표본 검증과 복구 절차를 전담함
- `CONVENTIONS.md`의 폐지 경위와 과거 사례를 이 문서로 옮김
- `CONVENTIONS.md`에는 절 참조는 wikilink anchor만 쓴다는 규칙, 금지 표기와 허용 예외만 남김
- 번호 자동 부여 도구의 현재 동작은 `CONVENTIONS.md`에 유지하고, 오변환을 추적하는 사용법만 이 문서에 둠

## 6.9 H09 클라이언트 데이터 번역 규칙

- 영어 UI의 대소문자, 부호, 음역, 이름 풀과 검수 절차를 유지함
- `06_클라이언트 데이터/`의 일반 역할은 `CONVENTIONS.md`가 소유하고 이 문서는 대상 파일만 식별함
- JSON 사용자 관리 권한은 이 작업에만 적용되는 규칙으로 유지함
- L4 외부 자료는 주장의 바로 뒤에 출처를 연결하는 현재 인용 원칙에 맞춰 재검토함

# 8. 실행 순서

한 단계에서 HowTo 문서 하나만 `CONVENTIONS.md`와 대조하고 정리함. 서로 의존하는 변경도 해당 단계 안에서 필요한 두 문서만 수정함.

1. **기준선 고정**: 각 anchor를 가리키는 기존 wikilink와 자동 검사 결과를 저장하고 선결 정책 네 항목을 사용자 결정으로 확정함
2. **H03 정리**: [[문서 작성 세부 규칙]]에 정보 구조 상세를 모은 뒤 `CONVENTIONS.md`의 중복을 줄임
3. **H06 정리**: [[위키 운영 워크플로]]에 생성, 갱신과 운영 순서를 모은 뒤 `CONVENTIONS.md`에는 정적 완료 조건만 남김
4. **H08 정리**: [[절 참조 오변환 점검 절차]]에 과거 경위와 복구법을 모은 뒤 공통 문서에는 현재 규칙만 남김
5. **H01 정리**: [[docx 변환 파이프라인]]의 경로 설명을 줄이고 변환본 예외를 두 문서에 일치시킴
6. **H04 정리**: [[반복 결함 카탈로그]]를 사례와 재발 질문의 소유처로 명확히 하고 현행 규칙 링크를 맞춤
7. **H05 정리**: [[외부 검수 포커스]]의 파생 블록과 동기화 대상을 표시함
8. **H07 정리**: [[인포그래픽 생성 지침]]의 일반 작성 원칙 반복과 수치 근거를 정리함
9. **H09 정리**: [[클라이언트 데이터 번역 규칙]]의 데이터층 설명을 최소화하고 번역 전용 규칙을 유지함
10. **H02 확인**: [[PDF 읽기 절차]]는 내용 이동 없이 링크와 소유 표현만 최종 확인함
11. **전체 정합화**: MOC 요약, 관련 문서, `AGENTS.md`의 규칙 참조와 바뀐 anchor를 전수 확인함

각 단계는 별도 작성 사이클로 수행함. 앞 단계가 커밋되고 사용자 게이트가 끝나기 전에는 다음 HowTo 문서로 넘어가지 않음.

# 9. 검증과 완료 기준

## 9.1 단계별 검증

- 변경 전후에 해당 규칙의 저장소 전체 사용처를 `rg`로 찾아 누락을 확인함
- `node scripts/wiki_number.mjs --write`, `node scripts/wiki_lint.mjs`, `node scripts/quote_check.mjs`를 각 사이클에서 실행함
- 바뀐 헤딩의 모든 wikilink anchor를 실제 대상 헤딩과 대조함
- 새 정본 문장은 독립 맥락 가독성 검토를 거침
- 규칙 소유처를 옮기는 큰 변경은 G1 뒤 외부 검토 패킷으로 사실과 정합, 적대, 가독성을 검토함

## 9.2 최종 완료 조건

- 공통 규칙마다 정본 소유처가 하나로 식별됨
- HowTo에 남은 공통 규칙 복제는 필요한 파생 텍스트로 표시됨
- `CONVENTIONS.md`만 읽어도 공통 의무와 필요한 HowTo를 찾을 수 있음
- 작업자는 각 HowTo만 읽어도 해당 작업을 수행할 수 있음
- 각 HowTo는 새 상위 정책을 독자적으로 만들지 않음
- 변환본, 수치 근거와 파생 규칙의 예외가 명시됨
- 자동 검사에서 오류가 0건이고 모든 MOC 및 anchor가 유효함
