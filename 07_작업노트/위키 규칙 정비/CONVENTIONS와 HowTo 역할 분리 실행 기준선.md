## 3.4 사용 기준

- 헤딩이나 링크를 바꾸는 2~12단계가 끝날 때마다 두 표를 같은 방법으로 다시 집계함
- 링크 수 감소는 해당 단계 diff에서 의도적으로 링크를 지운 경우에만 허용함. 대응하는 삭제가 없으면 참조 유실 가능성으로 판정함
- 고유 링크 대상의 변경은 기존 anchor와 새 anchor의 대응표로 설명해야 함. 대응표에 없는 감소, 분기와 중복은 anchor 유실이나 오변환 가능성으로 판정함
- 새 링크와 바뀐 링크는 실제 헤딩 대조와 lint 오류 0건을 모두 충족해야 함
- 표의 값은 변화 탐지용 기준선이며 그 자체가 완료 조건은 아님

# 4. 자동 실행 결과 기준선

세 자동 명령은 2026-09-08에 기준 커밋의 문서 상태를 대상으로 실행함.

| 실행 명령 | 결과 | 잔류 항목 |
|---|---|---|
| `node scripts/wiki_number.mjs --write` | 마크다운 68개 스캔, 넘버링 어긋남 0건 | 없음 |
| `node scripts/wiki_lint.mjs` | 마크다운 68개 스캔, 오류 0건 | 경고 28건: 미작성 링크 6건, 참조 순서 위반 22건 |
| `node scripts/quote_check.mjs` | 행 번호가 붙은 인용 대조 대상 0건, 어긋남 0건 | 전사본을 정하지 못해 건너뛴 문서 7개 |

경고 28건은 이번 역할 분리 작업에서 생긴 것이 아니며 단계별 비교를 위해 그대로 기록함. 완료 기준은 오류 0건을 유지하고, 변경한 anchor와 파생 텍스트에 새 경고를 만들지 않는 것임.

`wiki_number.mjs --write`는 당시 실제 실행한 변경 명령을 기록한 것이며 읽기 전용 재현 명령이 아님. 원본 작업 트리에서 상태만 확인할 때는 `node scripts/wiki_number.mjs --check`를 사용하고, `--write` 재실행이 필요하면 `git archive`로 기준 커밋을 별도 임시 디렉터리에 풀어 만든 스냅샷에서 수행함.
