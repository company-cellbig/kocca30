> [[CONVENTIONS와 HowTo 역할 분리 실행 기준선]] 커밋을 새 Claude Code 세션에서 검토할 때 전달하는 독립 맥락 검수 패킷임. 사실과 정합, 적대, 가독성 검토를 각각 수행하고 파일은 수정하지 않은 채 발견만 보고하도록 지시함.

# 1. 사용 방법

- 새 Claude Code 세션을 열고 이 문서의 `검수 지시문` 절부터 끝까지 전달함
- 작성 대화, 작성 의도와 중간 추론은 전달하지 않음
- Claude Code가 이 저장소, Git 이력과 로컬 Codex 설정을 직접 읽을 수 있는 위치에서 실행함
- 검토 보고를 받은 뒤 발견별 수용, 보류와 반려는 사용자가 결정함

# 2. 검수 지시문

당신은 이 변경의 외부 검토자다. [[#5. 금지 사항]]을 준수하고 발견만 보고하라.

변경 판정 대상은 대상 커밋의 diff임. 저장소 규칙과 원자료는 대상 커밋 판본을 읽고, 기준선 수치만 부모 커밋 판본에서 재현하라. 로컬 설정과 공식 문서는 현재 상태를 확인하는 근거이므로 대상 커밋 당시의 상태를 단독으로 확정하는 데 쓰지 마라. 검토 무발견은 결함 부재의 증명이 아니므로 수행 범위와 발견 건수만 보고하라.

## 2.3 기준선 사실 대조

중심 문서의 수치는 대상 커밋이 아니라 부모 커밋의 상태를 고정한 값임. 원 저장소의 파일과 Git 상태를 바꾸지 말고, 저장소 밖 임시 디렉터리에 부모 커밋 스냅샷을 풀어 대조하라. 임시 스냅샷 안의 파일은 자동 검사에 필요한 범위에서 수정할 수 있음.

```powershell
$reviewRoot = Join-Path ([IO.Path]::GetTempPath()) ('conventions-review-' + [guid]::NewGuid())
New-Item -ItemType Directory -Path $reviewRoot -ErrorAction Stop
$archivePath = Join-Path $reviewRoot 'parent.tar'
git archive --output="$archivePath" f454564a812042f241cc70af4650ea6a75d649be
if ($LASTEXITCODE -ne 0) { throw 'git archive 실패' }
tar -xf $archivePath -C $reviewRoot
if ($LASTEXITCODE -ne 0) { throw 'tar 압축 해제 실패' }
Push-Location $reviewRoot
try {
	node scripts/wiki_number.mjs --write
	if ($LASTEXITCODE -ne 0) { throw 'wiki_number 실패' }
	node scripts/wiki_lint.mjs
	if ($LASTEXITCODE -ne 0) { throw 'wiki_lint 실패' }
	node scripts/quote_check.mjs
	if ($LASTEXITCODE -ne 0) { throw 'quote_check 실패' }
} finally {
	Pop-Location
}
```

- **기준 커밋**: `f454564a812042f241cc70af4650ea6a75d649be`
- **문서 크기**: 대상 커밋의 중심 문서 2절 표에 열거된 루트 문서 3개와 HowTo 문서 9개의 바이트 및 행 수를 전부 재계산함
- **anchor 집계**
	- 기준 커밋의 모든 마크다운 파일에서 대상 커밋 중심 문서 3절 표에 열거된 문서 10개를 가리키는 wikilink를 추출함
	- `[[문서명]]`, `[[문서명#anchor]]`와 별칭형을 포함하고, 같은 줄의 복수 링크도 각각 셈
	- 고유 대상은 별칭을 버린 문서명과 anchor 원문 문자열의 조합임
	- 활성 값은 `99_Logs/`와 경로에 `_archive/`가 있는 문서만 제외함
- **자동 검사**: 부모 커밋에서 `wiki_number`, `wiki_lint`와 `quote_check`를 각각 실행해 중심 문서의 기준선 표와 대조함
- **로컬 설정**: 접근할 수 있으면 `C:\Users\cellbig\.codex\config.toml`, 전역 `AGENTS.md`와 `AGENTS.override.md`의 존재 및 설정값을 직접 확인함. 접근할 수 없으면 `검증 불가`로 보고함
- **정책 결정**: 채택한 정책 4건이 계획 문서 8절의 권장안과 같은지 대조함. 채택 권한이나 승인 여부는 검토자가 판정하지 않음

# 3. 검토 지침

이 저장소는 마크다운 문서 저장소임. 다음 우선순위로 비판적 검수를 수행하라. `괜찮아 보임`은 사유가 아니며 결함을 적극적으로 찾아야 함. 접근할 수 없는 근거만 `검증 불가`로 보고하라.

세 검토를 한 번에 섞지 말고 `사실과 정합`, `적대`, `가독성` 순서로 각각 독립 수행한 뒤 발견도 같은 구분으로 보고하라.

## 3.1 사실과 정합

### 3.1.1 P1 사실 오류와 출처 불일치

- 기준 커밋, 부모 관계와 변경 파일 목록이 Git 객체와 일치하는가
- 문서 크기 12개, anchor 집계표의 문서별 값과 합계, 자동 검사 결과를 직접 재계산했을 때 일치하는가
- 부모 커밋 기준선 68개와 대상 커밋의 새 문서를 포함한 상태를 혼동하지 않았는가
- `project_doc_max_bytes` 설정 유무, 전역 지침 존재 여부와 기본 한도 32 KiB 주장이 로컬 설정 및 공식 문서와 일치하는가
- 외부 근거와 내부 재현 결과가 구별되고 각 수치의 재현 기준이 충분한가

### 3.1.2 P5 위키 정합성

- 기준선 문서의 링크가 실제로 정책 결정, 실행 순서와 규칙 내용을 담은 절을 가리키는가
- 계획 문서, 기준선 문서, MOC 요약과 로그의 범위 및 수치가 서로 일치하는가
- `CONVENTIONS.md`, HowTo와 `AGENTS.md`의 소유 관계가 한 문서로 식별되며 서로 상세를 미루는 빈 참조가 없는가
- 기준선 문서가 이후 단계의 실행 기록과 혼동되지 않고 현재 상태를 고정하는 역할을 수행하는가
- 깨진 링크, anchor 정합과 MOC 등록의 기계 검사는 반복하지 말고 의미 정합만 봐라

## 3.2 적대

### 3.2.1 P2 논리적 비약과 추론 정정

- link 집계의 `전체`, `활성`, `링크`와 `고유 대상`이 서로 다른 단위로 일관되게 구별되는가
- `99_Logs/`와 `_archive/`만 제외한 값을 `활성`이라고 부르는 분류가 오해를 만들거나 다른 비활성 문서를 포함하지 않는가
- 기준 커밋 하나만으로 정확한 링크 위치와 문서 상태를 재현할 수 있다는 주장이 충분한가
- 로컬 설정에 명시값이 없다는 사실에서 기본 한도가 적용된다는 결론으로 넘어가는 데 빠진 조건이 없는가
- 채택한 정책 4건이 원계획의 권장안보다 범위를 넓히거나 새 정책을 몰래 추가하지 않았는가
- 정책 소유처가 겹치거나 예외 원칙과 상세 절차가 서로 충돌할 여지가 없는가

### 3.2.2 P3 누락된 반론과 견고성

- 기준 커밋의 링크 집계가 숨김 폴더, 로그 이력, 폐기 문서와 미작성 링크를 어떻게 다루는지 충분히 설명하는가
- 문서 바이트와 행 수의 계산 환경 및 줄바꿈 차이가 재현성에 영향을 주는 한계가 빠지지 않았는가
- 공식 문서나 로컬 설정이 바뀌면 기준선의 사실과 현재 운영 규칙을 혼동할 위험이 없는가
- 코드 상수와 내부 시험 집계의 근거를 허용한다는 정책이 재현 절차, 커밋과 변경 책임을 빠뜨리지 않았는가
- 파생 규칙의 동기화 책임이 실제 후속 문서에서 누가 언제 점검할지 정할 수 있는 수준인가
- 기존 경고 28건을 그대로 두는 판단이 이번 변경의 새 경고를 가리는 방식으로 쓰이지 않는가

### 3.2.3 반복 결함 우선 점검

`01_HowTo/반복 결함 카탈로그.md` 본문 전체를 읽고 대상 변경에서 재발한 항목을 우선 찾아라. 특히 다음 결함류를 주의하되 여기에만 한정하지 마라.

- `STRUCT-001`: 계획, 기준선, MOC와 로그 사이에 오래된 수치나 역할 표현이 남음
- `STRUCT-002`, `STRUCT-003`, `STRUCT-005`: 링크 수, 고유 대상, 정책과 소유처처럼 종류나 위계가 다른 항목을 같은 표에서 혼동함
- `STRUCT-008`, `STRUCT-009`: 한 불릿에 여러 판정 기준을 넣거나 정보 성격과 맞지 않는 형식을 선택함
- `CONTENT-002`: 이름과 한 줄 라벨만 있고 기준선의 용도나 재현 방법이 없음
- `CONTENT-005`: 공통 규칙, 작업 절차와 승인 권한의 소유처를 잘못 지목함
- `LOGIC-003`: 채택되지 않은 계획의 권장안을 현행 정본처럼 인용함
- `PROCESS-001`: 문서 한 곳만 고치고 MOC, 로그와 관련 문서에 같은 변경을 반영하지 않음
- `PROCESS-002`: 기준선 집계 결과를 먼저 정하고 원자료를 그 값에 끼워 맞춤

## 3.3 가독성

맥락 없는 독자로 각 문장을 읽고 다음을 적극 지적하라.

- 정의하지 않은 용어나 지시어
- 구어체, 비표준어와 임의 조어
- 같은 뜻을 다른 문장으로 반복하는 군더더기
- 단순 문장 나열과 의미 분류 부족
- 한 단계 불릿에 역할, 단계나 종류가 여러 개 들어간 구조
- 조건과 결과인데 평문으로 쓴 경우 등 목록 형식 오선택
- 같은 수준 항목의 문법 형태가 다른 비병렬 구조
- `내용`, `기타`와 `참고`처럼 정보가 없는 항목명
- 음슴체, 가운뎃점, em dash와 슬래시 절제 위반
- `기준선`, `anchor`, `전체 링크`, `고유 대상`과 `활성`을 처음 보는 독자가 한 번에 구별할 수 있는가
- 현재 상태, 기준 커밋 상태와 이후 단계의 목표 상태를 문장마다 혼동 없이 읽을 수 있는가

기조는 회의가 기본임. 단순히 합리적으로 보인다는 판단은 승인 사유가 아님. `CONVENTIONS.md`의 수치 및 목표 인용 원칙과 외부 근거의 권위 계층, `AGENTS.md`의 검수 기준과 호출 방식을 우선 가이드로 삼아라.

| 예: F-01 | P1 | 파일명:행 | 무엇이 틀리거나 모호한지 | 직접 대조한 파일과 위치 | 그대로 둘 때 생기는 문제 | 최소 정정안 | L1~L5 또는 해당 없음 |

- 위치는 `파일명:행`으로 적고 가능하면 대상 문구를 짧게 병기함
- 근거는 직접 확인한 저장소 파일, Git 객체와 행을 적음
- 내부 파일, Git 객체나 문장 자체만 근거이면 외부 근거 등급에 `해당 없음`을 적음
- 외부 근거를 사용한 발견은 외부 근거 등급에 L1부터 L5 중 하나를 적음
- 외부 근거가 약하면 근거 칸 앞에 `[근거 약함]`을 추가함
- 같은 원인의 반복은 대표 발견 아래 모든 위치를 나열함

마지막에는 다음 내용만 요약하라.

- 검토한 커밋과 파일
- 세 검토별 발견 건수
- 검증하지 못한 범위와 이유
- 반복 결함 카탈로그에서 대조한 항목

# 5. 금지 사항

- 작성 의도와 중간 추론을 추정하지 않음
- 원 저장소의 파일과 로그를 수정하지 않음. 부모 커밋의 임시 스냅샷은 자동 검사에 필요한 범위에서만 수정할 수 있음
- Git 등록, 커밋, 전송과 브랜치 조작을 하지 않음
- 발견을 자동 반영하지 않음
- 승인, 통과와 최종 판정을 선언하지 않음
