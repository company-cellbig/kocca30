# 1. 작업 원칙

- **입력 범위**: 착수 기준선 사건 1,343건과 한 차례 보충 처리 사건 18건
- **작업 단위**: 원시 목록의 결과물 키 139개. 키 하나에 여러 결과물이 섞였으면 나누고, 여러 키가 같은 결과물을 가리키면 합침
- **근거 보존**: 모든 포함 사건을 하나 이상의 결과물 ID에 연결하고 합치거나 나눈 이유를 기록함
- **경로 대조**: 로그의 당시 경로, Git 이름 변경 이력과 현행 파일을 함께 확인함
- **생명주기**: 현행, 수정 중, 대체 또는 폐기로 표시하고 삭제된 결과물도 이력에서 제외하지 않음
- **분류 시점**: 통합 결과물과 구성 파일을 확정한 뒤 매체 형식, 세부 분류, 활용 목적과 인공지능 활용 방식을 부여함

- **처리 범위**: 결과물 키 27개에 속한 사건 234건
- **통합 결과**: 신규 결과물 24건. 문서 20건, 소프트웨어 4건

	- 포함 사건 207건이 모두 하나 이상의 결과물 ID에 대응함
	- 한 사건이 여러 운영 문서나 자동화 도구를 함께 고친 경우에는 해당 결과물에 중복 연결했으므로 대응 관계는 256건임
	- 원시 목록의 포함, 제외, 확인 필요 판정을 그대로 유지했으며 각각 207건, 27건, 0건임

	- 운영 규칙 키는 실제 파일인 에이전트 지침, 위키 작성 규칙, 검수 포커스와 결함 카탈로그로 나눔

- **제외 유지**: 개인 편집기 설정 2건, 파일 이동 및 삭제 7건, Git 설정과 조작 18건은 별도 내용 결과물을 만들지 않아 결과물 ID를 부여하지 않음

## 4.7 I07 조사, 원자료와 기타 매체 키

### 4.7.1 대조 결과

- **처리 범위**: 원시 목록의 같은 유형 후보를 묶어 만든 결과물 키 40개와 소속 사건 137건
- **통합 결과**: 포함 사건 136건을 신규 결과물 38건과 I01-I06에서 이미 ID를 부여한 결과물 19건에 연결함
	- 신규 38건: 문서 36건, 영상 1건, 3D 자산 1건
	- 기존 19건: 문서 15건, 이미지 2건, 소프트웨어 1건, 데이터 1건
- **대응 검산**
	- 포함 사건 136건이 모두 하나 이상의 결과물 ID에 대응함
	- 한 사건이 여러 개념 문서나 기존 기획서를 함께 고친 경우 여러 결과물 ID에 연결함
	- 원시 목록의 포함, 제외, 확인 필요 판정을 그대로 유지했으며 각각 136건, 0건, 1건임
- **통합 및 분리 기준**
	- 조사로 작성한 문서와 확보한 원자료를 나누고, 영상 파일과 영상 분석서를 각각 영상과 문서로 분류함
	- 같은 파일의 작성, 개명, 이동과 삭제는 한 계보로 합치고, 개념서와 기획서 또는 계획과 실행 목록처럼 목적이 다른 파일은 나눔
	- 채팅에만 남은 논문 입수 조사와 대외 연락 문안도 독립된 텍스트 결과물로 보존하되 구현 형식을 채팅 텍스트로 표시함
- **확인 필요 유지**: `L0122-02`의 키오스크 예시 이미지는 생성 사실만 확인되고 저장 위치와 현재 파일의 존재 여부를 확인할 수 없어 결과물 ID를 부여하지 않음
