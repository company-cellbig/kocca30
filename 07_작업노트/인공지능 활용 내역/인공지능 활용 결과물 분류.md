# 2. 분류 원칙

## 2.1 대분류 기준

여러 파일로 이뤄진 결과물도 과제에서 맡는 중심 기능 하나를 기준으로 대분류함.

- **문서**: 사람이 읽는 글, 표와 발표 내용이 중심인 결과물임. Markdown뿐 아니라 DOCX, PPTM과 PDF 원자료도 실행보다 읽기와 전달이 중심이면 문서로 분류함
- **이미지**: 정지된 한 화면의 시각물이 중심인 결과물임. 캐릭터, 배경, 소품, UI 시안과 인포그래픽을 포함함
- **영상**: 시간축을 따라 재생되는 시각물이 중심인 결과물임. 생성 영상과 분석용 기록영상을 포함함
- **소프트웨어**: 실행, 상호작용과 자동 처리가 중심인 코드 결과물임. HTML 프로토타입, 변환기, 검사기, 훅과 자동화 스크립트를 포함함
- **데이터**: 프로그램이 읽고 쓰는 구조화 값이 중심인 결과물임. 실행 상태 객체와 JSON 전달 패키지를 포함함
- **3D 자산**: 입체 형상이나 공간 데이터가 중심인 결과물임. 렌더링한 정지 화면은 이미지로, 재생 영상은 영상으로 분류해 3D 자산과 구별함
- **음원과 음성**: 소리 재생 자체가 중심인 독립 결과물임. 이번 조사에서는 확인되지 않음

## 2.2 결과물 통합 기준

- **계보 판단**
	- 같은 결과물의 생성, 수정, 이름 변경, 이동과 삭제는 하나의 계보로 합침
	- 원시 목록에서 결과물 후보를 묶은 임시 식별자를 결과물 키라고 함. 키 하나에 서로 다른 결과물이 섞였으면 나누고, 여러 키가 같은 파일이나 기능의 계보를 가리키면 합침
- **묶음 판단**
	- 파일 경로, Git 이름 변경 이력, 기능, 목적과 생명주기를 함께 대조함
	- 같은 전달 목적, 작업 세션이나 패키지로 만든 여러 파일은 대분류와 관계없이 결과물 하나로 셈
	- 묶음 사례는 다음과 같음
		- R0004: HTML과 JavaScript 패키지
		- R0093: 참고 이미지 5개
		- R0141: JSON과 개발자 안내
		- R0151: 기록영상 3개
		- R0153: GLB 2개
- **대응 보존**: 사건 하나가 여러 결과물을 함께 만들거나 고쳤으면 관련 결과물 모두에 연결함

## 2.3 인공지능 활용 포함 기준

인공지능이 처음부터 만들지 않았더라도 내용 생성, 구조 설계, 분석, 코딩, 수정, 검수 중 하나에 실질적으로 기여했으면 포함함. 기여 범위는 `인공지능 활용 방식` 항목에서 구별함.

## 2.4 생명주기 기준

- **현행**: 현재 유효하며 그대로 사용할 수 있는 결과물임
- **수정 중**: 결과물은 존재하지만 작성이나 개정이 진행 중이라 정본으로 확정되지 않은 상태임
- **대체**: 같은 기능이나 내용을 후속 결과물이 이어받아 이전 결과물이 더는 정본이 아닌 상태임
- **폐기**: 해당 결과물 자체를 더는 쓰지 않고 같은 계보의 후속 결과물로 유지하지 않는 상태임
