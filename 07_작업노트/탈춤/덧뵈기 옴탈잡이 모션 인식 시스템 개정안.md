> [[덧뵈기 - 탈놀음 한바탕 기획서]] 3.5 중 옴탈잡이에 적용할 내용을 양손 추적, 단계별 입력 손 정책과 충돌 영역을 가진 손 위치 포인터 방식으로 고치는 사용자 검토용 초안임.

# 1. 적용 범위

- **반영 범위**
	- 기획서 3.5 중 옴탈잡이에 적용할 교체안을 정리함
	- 개요에는 정의와 목적만 두고, 처리 순서는 동작 방식에서 설명함
- **입력 정책**
	- 조우, 잡아채기와 몰아내기는 입력 손 한 개를 사용함
	- 채검하기는 양손을 각각 입력으로 사용함
- **충돌 판정**
	- 손 위치 포인터를 중심 좌표와 원형 충돌 영역을 함께 가진 입력체로 정의함
	- 포인터 충돌 영역과 목표 관심 영역(ROI)이 닿는지를 기준으로 판정하며 중첩률은 사용하지 않음
	- 정확한 충돌 영역 크기와 움직임 기준값은 설치 환경에서 조정함
- **수정 제외**
	- 원 기획서와 `assets/시범콘텐츠/탈놀음/플로우_모션인식.png`는 수정하지 않음

# 2. 기획서 반영안

## 2.1 개요

- **정의**
	- 등록된 유저의 양손 위치를 나타내는 포인터와 목표 관심 영역(ROI)의 충돌을 판정해 게임 입력으로 바꾸는 모션 인식 시스템임
- **목적**
	- 별도 컨트롤러 없이 등록된 유저가 손 움직임으로 콘텐츠를 직관적으로 조작하게 함

## 2.2 레퍼런스

### 2.2.1 EyeToy: Play - Kung Foo

- **게임 정보**
	- 타이틀: _EyeToy: Play_
	- 미니게임: **Kung Foo**
	- 장르: 체감형/파티 미니게임
	- 플레이 영상: https://youtu.be/0h1EKk6JpK8?si=GEQY9L-9jSdw3drs
- **게임 개요**
	- 카메라를 이용해 신체 움직임으로 화면상의 오브젝트와 상호작용하는 체감형 콘텐츠임
	- 화면 중앙의 플레이어를 향해 여러 방향에서 등장하는 적을 신체 움직임으로 타격함
- **주요 특징**
	- 별도 컨트롤러 없이 신체 자체를 입력 수단으로 사용함
	- 카메라에 비친 자신의 모습으로 신체의 화면상 위치와 움직임의 결과를 즉시 확인함
	- 화면상의 대상 위치에 맞춰 신체를 움직이는 간단한 조작을 사용함
- **레퍼런스 적용 요소**
	- 유저의 신체 움직임을 콘텐츠 입력으로 직접 사용함
	- 화면상의 캐릭터와 오브젝트 위치를 유저의 실제 움직임과 연결함
	- 본 콘텐츠는 카메라 영상을 표시하지 않으므로 입력에 사용하는 손의 위치를 손 위치 포인터로 대신 보여줌
	- 포인터의 보이는 영역과 충돌 영역을 일치시켜 화면에서 보이는 접촉과 입력 판정을 연결함

## 2.3 동작 방식

### 2.3.1 유저 식별 및 등록

- 화면의 가이드라인을 기준으로 체험 위치에 선 유저를 식별함
- 식별된 유저를 현재 세션의 추적 대상으로 등록함
- 등록되지 않은 주변 인원은 추적과 입력 판정에서 제외함
- ==등록 직후에는 입력 손을 지정하지 않음==

### 2.3.2 유저와 양손 추적

- 등록된 유저의 신체 영역을 카메라 영상에서 계속 추적함
- 등록된 유저의 왼손과 오른손 위치를 각각 추적함
- 양손의 위치를 화면 좌표로 변환함
- 양손마다 위치, 이동 방향, 이동 거리, 이동 속도와 추적 신뢰도를 산출함
- 각 손의 화면 좌표를 해당 손 위치 포인터와 원형 충돌 영역의 중심점으로 사용함

### 2.3.3 단계별 입력 손 정책

단계마다 단일 손 또는 양손 입력 정책을 적용함.

| 적용 단계 | 입력 정책 | 입력 손 처리 | 표시 포인터 |
|---|---|---|---|
| 옴탈 조우 | 단일 손 | 유효 움직임이나 현재 판정 ROI 접근 조건을 먼저 충족한 손을 입력 손으로 지정함 | 입력 손 한 개 |
| 옴탈 잡아채기 | 단일 손 | 유효 움직임이나 옴탈 머리 ROI 접근 조건을 먼저 충족한 손을 입력 손으로 지정함 | 입력 손 한 개 |
| 옴탈 채검하기 | 양손 | 입력 손을 하나로 지정하지 않고 양손을 각각 판정함 | 왼손과 오른손 두 개 |
| 옴탈 몰아내기 | 단일 손 | 유효 움직임이나 현재 판정 ROI 접근 조건을 먼저 충족한 손을 입력 손으로 지정함 | 입력 손 한 개 |

- **단일 손 지정**
	- 두 손이 같은 시점에 조건을 충족하면 오른손을 입력 손으로 지정함
	- 입력 손을 지정하면 현재 입력이 끝날 때까지 다른 손으로 전환하지 않음
- **현재 입력 범위**
	- 조우와 몰아내기는 유효 타격이 성립하거나 현재 단계가 끝날 때 현재 입력을 종료함
	- 잡아채기는 옴탈 머리와 충돌한 때부터 잡아채기 동작을 마치거나 현재 단계가 끝날 때까지를 현재 입력으로 봄
- **입력 손 해제**
	- 조우와 몰아내기의 유효 타격, 잡아채기 완료, 목표 소멸, 입력 취소, 현재 단계 종료 또는 입력 손 추적 실패 시 입력 손을 해제함
	- 입력 손을 해제한 뒤에는 양손을 다시 비교해 다음 입력 손을 지정함
- **양손 채검**
	- 양손을 독립적으로 판정하고 손마다 입력 쿨다운을 적용함

### 2.3.4 손 위치 포인터 표시와 갱신

- **표시 수**
	- 단일 손 단계에서는 입력 손을 지정하면 해당 손의 화면 좌표에 포인터 한 개를 표시함
	- 채검하기에서는 왼손과 오른손의 화면 좌표에 포인터를 각각 표시함
- **위치와 충돌 영역**
	- 포인터 중심점은 인식한 손의 화면 좌표를 따라 이동함
	- 포인터에는 화면 표시 크기와 같은 원형 충돌 영역을 부여함
	- 포인터의 보이는 가장자리가 목표 ROI에 닿는 시점에 시스템도 충돌로 판정함
- **입력 피드백**
	- 손 떨림과 인식값의 작은 변화는 보정한 뒤 포인터에 반영함
	- 유효 입력으로 판정되지 않은 움직임도 현재 손 위치를 알려주기 위해 포인터 이동에는 반영함
	- 충돌이 시작되면 포인터 또는 목표의 색상이나 크기를 바꿔 접촉 결과를 즉시 보여줌
	- 손 추적이 끊기거나 유저가 체험 영역을 벗어나면 해당 손의 포인터를 숨김

### 2.3.5 ROI 충돌과 유효 입력 판정

- **충돌 영역**
	- 관심 영역(ROI)은 입력 판정을 위해 화면상의 목표에 설정하는 충돌 영역임
	- 포인터의 원형 충돌 영역과 현재 판정 ROI가 닿거나 교차하면 충돌로 판정함
- **판정 원칙**
	- 충돌은 입력 판정에만 사용하며 물리 반응을 자동으로 적용하지 않음
	- 두 영역이 조금이라도 닿으면 충돌이 성립하므로 최소 중첩률은 사용하지 않음
	- 충돌 시작, 충돌 유지와 충돌 종료를 구분하고 단계에 필요한 사건만 사용함

단계별 목표, 유효 입력과 무효 처리는 다음과 같음.

| 적용 단계 | 목표 ROI | 유효 입력 판정 | 무효 처리 |
|---|---|---|---|
| 옴탈 조우 | 화면 좌우에 나타난 옴탈 | 입력 손 포인터의 충돌 영역이 옴탈 ROI와 충돌하고 입력 손의 수평 움직임이 기준 이상이면 유효함 | 충돌이 없거나 입력 손의 수평 움직임이 기준 이하이면 무효로 처리함 |
| 옴탈 잡아채기 | 옴탈 머리 영역 | 입력 손 포인터의 충돌 영역이 머리 ROI와 처음 충돌하면 옴탈을 포인터에 결합함. 이후 옴탈이 포인터에 끌려 손의 움직임을 따라 이동함 | 머리 ROI와 충돌하기 전에는 옴탈을 잡거나 이동시킨 것으로 처리하지 않음 |
| 옴탈 채검하기 | 화면을 가득 채운 옴탈 얼굴 | 각 손의 포인터 충돌 영역이 얼굴 ROI와 충돌하고 해당 손의 휘두르기 움직임이 기준 이상이면 타격 1회로 판정함 | 해당 손의 충돌이 없거나 휘두르기 움직임이 기준 이하이면 그 손의 타격을 무효로 처리함 |
| 옴탈 몰아내기 | 날아오는 옴탈 얼굴 | 입력 손 포인터의 충돌 영역이 옴탈 ROI와 충돌하고 입력 손의 움직임이 기준 이상이면 유효함 | 충돌이 없거나 입력 손의 움직임이 기준 이하이면 무효로 처리함 |

- **잡아채기 결합**
	- 옴탈을 포인터에 결합한 뒤에는 머리 ROI와의 충돌 유지를 요구하지 않음
- **반복 타격**
	- 조우, 채검하기와 몰아내기에서는 충돌을 유지하는 것만으로 입력을 반복하지 않음
	- 새 휘두르기 움직임이 성립하고 해당 손의 입력 쿨다운이 끝났을 때 다음 타격을 인정함
- **데이터 관리**
	- ROI 위치와 크기, 충돌 사건, 움직임 기준과 쿨다운은 데이터 테이블로 관리함

### 2.3.6 게임 입력 변환

- **단계 반응**
	- 조우와 몰아내기에서는 옴탈 피격 반응을 실행함
	- 잡아채기에서는 충돌 시작 시 옴탈을 포인터에 결합하고 이후 포인터 좌표로 옴탈 위치를 갱신함
	- 채검하기에서는 손마다 유효 타격을 기록하고 옴탈 얼굴의 피격 반응을 실행함
- **결과 반영**
	- 유효하다고 판정한 ROI에 연결된 정보를 게임 입력으로 변환함
	- 입력 결과를 수행 기록과 진행 인디케이터에 반영함
- **다음 입력 준비**
	- 단일 손 단계에서 현재 입력을 마치면 입력 손을 해제함
	- 채검하기에서는 입력 손 해제 없이 양손을 계속 추적함
	- 다음 입력은 단계 정책에 따라 입력 손 지정 또는 손별 입력 쿨다운부터 준비함

## 2.4 설정 및 예외 처리

### 2.4.1 주요 설정값

모션 인식과 입력 판정에 필요한 값은 JSON 데이터 테이블로 관리하고 실제 설치 환경에서 조정함.

| 항목 | 설명 |
|---|---|
| 유저 식별 영역 | 최초 유저 식별 및 등록에 사용하는 화면상의 위치와 영역 정보 |
| 유저 식별 신뢰도 기준 | 유저 식별 성공 여부를 판단하는 최소 기준 |
| 유저 추적 신뢰도 기준 | 등록된 유저의 추적 상태를 정상으로 판단하는 최소 기준 |
| 손 추적 신뢰도 기준 | 왼손 또는 오른손 위치를 정상적으로 인식했다고 판단하는 최소 기준 |
| 움직임 검출 임계값 | 손의 움직임을 검출 대상으로 인정하는 최소 기준 |
| 최소 움직임 영역 비율 | 미세 움직임과 영상 노이즈를 제외하는 최소 범위 |
| 입력 손 선택 기준 | 검출 임계값을 넘은 움직임 가운데 손을 입력 손으로 지정하는 최소 이동 거리와 속도 |
| 동시 조건 판정 시간 | 두 손의 유효 움직임이나 ROI 접근 조건을 같은 시점에 성립한 것으로 보는 시간 범위 |
| 손 위치 좌표 보정값 | 인식한 손 위치를 화면상의 포인터 위치에 맞추는 좌표 보정값 |
| 포인터 이동 보정값 | 손 떨림과 인식값 변화로 생기는 포인터 흔들림을 줄이는 값 |
| 포인터 충돌 영역 형태 | 화면에 보이는 포인터와 충돌 판정에 함께 사용할 영역 형태. 원형을 기본으로 사용함 |
| 포인터 충돌 영역 크기 | 화면에 보이는 포인터와 원형 충돌 영역에 함께 적용할 지름 |
| 충돌 이탈 지연 시간 | 충돌이 끊긴 상태가 얼마나 이어져야 충돌 종료로 판정할지를 정하는 시간 |
| 포인터 숨김 기준 시간 | 해당 손을 인식하지 못했을 때 포인터를 숨기기까지 허용하는 시간 |
| 입력 쿨다운 | 같은 움직임으로 연속 입력되는 것을 막는 시간 |
| 추적 실패 허용 시간 | 일시적인 유저 추적 실패를 허용하는 시간 |
| 재식별 전환 시간 | 추적 실패가 계속될 때 유저 재식별로 전환하는 기준 시간 |

- 포인터 표시 크기와 충돌 영역 크기는 같은 값으로 관리함
- 포인터와 ROI가 조금이라도 닿으면 충돌로 판정하므로 최소 중첩률 설정값은 두지 않음

### 2.4.2 ROI 데이터

개별 ROI 정보는 JSON 데이터 테이블로 관리함.

| 항목 | 설명 |
|---|---|
| ROI ID | ROI 고유 식별값 |
| 적용 단계 | ROI를 사용하는 옴탈잡이 진행 단계 |
| 입력 정책 | 단일 손 또는 양손 판정 방식 |
| 판정 유형 | 충돌 타격 또는 충돌 후 끌기 |
| 목표 오브젝트 | ROI를 따라 이동하거나 반응할 화면상의 대상 |
| ROI 형태 | 목표에 적용할 원형 또는 사각형 충돌 영역 |
| X/Y | 화면 내 ROI 기준 위치 |
| Width/Height/Radius | ROI 형태에 따른 충돌 영역의 크기 |
| 입력 손 접근 기준 | 단일 손 단계에서 포인터 표시 전에 입력 손을 지정하는 거리 또는 진입 기준 |
| 충돌 사건 | 충돌 시작, 유지 또는 종료 가운데 입력 판정에 사용할 사건 |
| 움직임 기준 | 이동 방향, 거리와 속도 가운데 유효 입력에 사용할 조건 |
| 충돌 후 동작 | 피격 반응, 포인터 결합 또는 끌기처럼 충돌 뒤 실행할 처리 |
| 입력 쿨다운 | 해당 ROI에서 다음 유효 입력을 허용하기까지의 시간 |
| 연결 입력 | 판정 성공 시 발생시키는 게임 입력 |

### 2.4.3 예외 처리

| 유형 | 처리 |
|---|---|
| 유저 추적 실패 | 입력 판정과 포인터 표시를 중지함. 실패가 일정 시간 이상 이어지면 유저 식별과 등록을 다시 진행함 |
| 단일 손 단계의 입력 손 추적 실패 | 해당 포인터를 숨기고 현재 입력을 취소한 뒤 입력 손을 해제함 |
| 잡아채기 중 입력 손 추적 실패 | 포인터를 숨김. 포인터에 결합한 옴탈을 원위치로 돌릴지 현재 위치에 둘지는 `[확정 필요]`임 |
| 채검하기 중 한쪽 손 추적 실패 | 정상 추적되는 손의 포인터와 타격 판정은 유지함. 양손 참여를 단계 완료 조건으로 삼을지는 `[확정 필요]`임 |
| 유저 영역 이탈 | 입력을 제한하고 포인터를 숨긴 뒤 정상 체험 위치로 돌아오도록 안내함 |
| 다중 인원 간섭 | 등록된 유저의 신체와 양손만 추적과 입력 판정에 사용함 |
| 단일 손 단계의 양손 동시 입력 | 두 손이 같은 시점에 조건을 충족하면 오른손을 입력 손으로 지정함 |
| 인접 ROI 동시 충돌 | 한 포인터가 둘 이상의 ROI와 동시에 충돌하면 적용할 우선순위는 `[확정 필요]`임 |
| 미세 움직임과 오검출 | 최소 움직임 영역 비율과 움직임 검출 임계값을 충족하지 못하면 입력으로 처리하지 않음 |
| ROI 경계의 포인터 흔들림 | 충돌은 즉시 시작하고, 포인터 이동 보정값과 충돌 이탈 지연 시간을 적용해 충돌 종료의 반복을 줄임 |
| 연속 입력과 중복 입력 | 충돌 유지 자체는 새 입력으로 보지 않고 움직임 기준과 입력 쿨다운을 다시 충족해야 다음 입력으로 처리함 |
| 카메라 입력 이상 | 모션 입력과 포인터 표시를 중단하고 세션 진행 실패 처리를 실행함 |

# 3. 플로우 이미지 수정안

현재 `assets/시범콘텐츠/탈놀음/플로우_모션인식.png`에는 단계별 입력 정책, 포인터 충돌 영역과 잡아채기 결합 과정이 없으므로 다음 내용을 보강해야 함.

- **공통 노드**
	- `유저 추적 및 영역 추출`을 `유저와 양손 추적 및 영역 추출`로 바꿈
	- `움직임 검출`을 `양손 위치 및 움직임 검출`로 바꿈
	- 양손 추적 뒤에 `단계별 입력 정책 확인`을 추가함
	- `손 위치 포인터 활성화`를 `원형 충돌 영역을 가진 포인터 표시`로 바꿈
	- `ROI 입력 판정`을 `포인터 충돌 영역과 목표 ROI 충돌 판정`으로 바꿈
- **단일 손 분기**
	- `입력 손 지정 및 고정`과 `입력 손 포인터 표시`를 추가함
	- 단일 손 입력이 끝나는 지점에 `입력 손 해제`를 추가함
- **양손 분기**
	- `양손 포인터 표시 및 손별 판정`을 추가함
	- 채검하기에는 입력 손 해제 대신 손별 입력 쿨다운 뒤 양손 추적으로 돌아가는 흐름을 둠
- **잡아채기 분기**
	- `옴탈과 포인터 결합` 및 `포인터 좌표로 옴탈 이동`을 추가함

공통 진입 흐름은 다음과 같음.

`시스템 시작 → 유저 식별 및 등록 → 유저와 양손 추적 및 영역 추출 → 양손 위치 및 움직임 검출 → 단계별 입력 정책 확인`

단일 손 단계의 권장 흐름은 다음과 같음.

`입력 손 지정 및 고정 → 입력 손 포인터 표시 및 충돌 영역 갱신 → 목표 ROI 충돌 판정 → 움직임 기준 확인 → 유효 입력 변환 → 입력 손 해제 → 체험 진행 여부 확인`

채검하기의 권장 흐름은 다음과 같음.

`양손 포인터 표시 및 충돌 영역 갱신 → 손별 얼굴 ROI 충돌 판정 → 손별 휘두르기 기준 확인 → 유효 타격 변환 → 손별 입력 쿨다운 → 양손 추적 반복`

잡아채기의 충돌 이후 흐름은 다음과 같음.

`입력 손 포인터와 머리 ROI 충돌 → 옴탈과 포인터 결합 → 포인터 좌표로 옴탈 이동 → 잡아채기 완료 판정 → 결합 해제 및 입력 손 해제`

- 충돌이나 움직임 기준을 충족하지 못하면 해당 단계의 포인터 갱신으로 돌아감
- 체험이 진행 중이면 양손 추적을 반복하고, 끝났으면 시스템을 종료함

# 4. 확정 필요

프로토타입 제작 전에 다음 항목을 사용자 결정이나 설치 테스트로 확정해야 함.

- **잡아채기**
	- 완료를 판정할 이동 거리, 이동 시간 또는 목표 위치
	- 입력 손 추적이 끊겼을 때 옴탈을 원위치로 돌릴지 현재 위치에 둘지 여부
- **채검하기**
	- 단계 완료에 양손의 최소 참여를 요구할지 여부
- **충돌 판정**
	- 한 포인터가 인접한 둘 이상의 ROI와 동시에 충돌할 때 적용할 우선순위
	- 포인터 표시 및 충돌 영역의 지름
	- 충돌 이탈 지연 시간, 움직임 기준과 손별 입력 쿨다운
