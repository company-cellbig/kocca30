> [[덧뵈기 - 탈놀음 한바탕 기획서]] 3.5 중 옴탈잡이에 적용할 내용을 양손 추적, 활성 손 자동 선택과 공통 손 위치 포인터 방식으로 고치는 사용자 검토용 초안임.

# 1. 적용 범위

- 기획서 3.5 중 옴탈잡이에 적용할 교체안을 정리함
- 옴탈잡이의 조우, 잡아채기, 채검하기와 몰아내기에 같은 입력 흐름을 적용함
- 개요에는 정의와 목적만 두고, 처리 순서는 동작 방식에서 설명함
- 원 기획서와 `assets/시범콘텐츠/탈놀음/플로우_모션인식.png`는 수정하지 않음

# 2. 기획서 반영안

## 2.1 개요

- **정의**
	- 카메라로 등록된 유저의 신체와 양손을 추적하고 손 움직임을 게임 입력으로 변환하는 시스템임
	- 양손에서 유효 움직임 조건이나 현재 활성 ROI 접근 조건이 처음 성립한 시점을 비교해 더 이른 손을 `활성 손`으로 선택함
	- 활성 손의 위치를 화면상의 `손 위치 포인터`로 표시함
- **목적**
	- 별도 컨트롤러 없이 직관적인 신체 동작으로 콘텐츠를 조작하게 함
	- 카메라 영상을 화면에 표시하지 않아도 유저가 자신의 입력 위치를 확인하게 함
	- 왼손과 오른손을 미리 정하지 않고 유저가 먼저 사용한 손으로 조작하게 함
	- 군중 환경에서 등록된 체험자만 안정적으로 입력하게 함

## 2.2 레퍼런스

### 2.2.1 EyeToy: Play - Kung Foo

- **게임 정보**
	- 타이틀: _EyeToy: Play_
	- 미니게임: **Kung Foo**
	- 장르: 체감형/파티 미니게임
	- 플레이 영상: https://youtu.be/0h1EKk6JpK8?si=GEQY9L-9jSdw3drs
- **게임 개요**
	- 카메라를 이용해 신체 움직임으로 화면상의 오브젝트와 상호작용하는 체감형 콘텐츠임
	- 화면 중앙의 플레이어를 향해 여러 방향에서 등장하는 적을 신체 움직임으로 타격함
- **주요 특징**
	- 별도 컨트롤러 없이 신체 자체를 입력 수단으로 사용함
	- 카메라에 비친 자신의 모습으로 신체의 화면상 위치와 움직임의 결과를 즉시 확인함
	- 화면상의 대상 위치에 맞춰 신체를 움직이는 간단한 조작을 사용함
- **레퍼런스 적용 요소**
	- 유저의 신체 움직임을 콘텐츠 입력으로 직접 사용함
	- 화면상의 캐릭터와 오브젝트 위치를 유저의 실제 움직임과 연결함
	- 본 콘텐츠는 카메라 영상을 표시하지 않으므로 활성 손의 위치를 손 위치 포인터로 대신 보여줌
	- 옴탈잡이 모든 입력 단계에서 양손 추적, 활성 손 선택과 포인터 표시라는 같은 흐름을 사용함

## 2.3 동작 방식

### 2.3.1 유저 식별 및 등록

- 화면의 가이드라인을 기준으로 체험 위치에 선 유저를 식별함
- 식별된 유저를 현재 세션의 추적 대상으로 등록함
- 등록되지 않은 주변 인원은 추적과 입력 판정에서 제외함
- 등록 직후에는 활성 손을 지정하지 않음

### 2.3.2 유저와 양손 추적

- 등록된 유저의 신체 영역을 카메라 영상에서 계속 추적함
- 등록된 유저의 왼손과 오른손 위치를 각각 추적함
- 양손의 위치를 화면 좌표로 변환함
- 양손마다 위치, 이동 방향, 이동 거리, 이동 속도와 추적 신뢰도를 산출함

### 2.3.3 활성 손 선택

- 양손마다 유효 움직임 조건과 현재 활성 ROI 접근 조건을 각각 확인함
- 양손에서 유효 움직임 조건이나 현재 활성 ROI 접근 조건이 처음 성립한 시점을 비교함
- 두 조건 가운데 하나라도 더 먼저 성립한 손을 활성 손으로 선택함
- 두 손의 조건이 같은 시점에 성립했을 때 적용할 우선순위는 `[확정 필요]`임
- 활성 손을 선택하면 현재 입력이 끝날 때까지 다른 손으로 전환하지 않음
- 현재 입력은 활성 손을 선택한 때부터 게임 입력이 성공하거나 현재 단계가 끝날 때까지임
- 게임 입력이 성공하거나 현재 단계가 끝나면 활성 손을 해제함
- 목표 소멸, 입력 취소 또는 활성 손 추적 실패를 현재 입력의 종료로 볼지는 `[확정 필요]`임
- 활성 손을 해제한 뒤에는 양손을 다시 비교해 다음 활성 손을 선택함

### 2.3.4 손 위치 포인터 표시와 갱신

- 활성 손을 선택하면 해당 손의 화면 좌표에 손 위치 포인터를 표시함
- 활성 손의 움직임에 따라 포인터 위치를 계속 갱신함
- 손 떨림과 인식값의 작은 변화는 보정한 뒤 포인터에 반영함
- 유효 입력으로 판정되지 않은 움직임도 현재 손 위치를 알려주기 위해 포인터 이동에는 반영함
- 활성 손 추적이 끊기거나 유저가 체험 영역을 벗어나면 포인터를 숨김

### 2.3.5 ROI 입력 판정

- 관심 영역(ROI)은 입력 판정을 위해 화면상에 설정하는 가상의 영역임
- 현재 단계에서 활성화된 ROI와 손 위치 포인터의 위치를 비교함
- 옴탈잡이 네 입력 단계에서 양손 추적, 활성 손 선택, 포인터 표시와 ROI 비교라는 같은 처리 순서를 사용함
- 단계별 차이는 ROI 데이터에 등록된 판정 기준으로 제어함

기존 단계별 판정은 다음 표와 같음.

| 적용 단계 | 목표 ROI | 유효 입력 판정 |
|---|---|---|
| 옴탈 조우 | 화면 좌우에 나타난 옴탈 | 포인터가 옴탈 ROI와 중첩되고 활성 손의 수평 움직임이 기준 이상이면 유효함 |
| 옴탈 잡아채기 | 옴탈 머리의 잡아채기 아이콘 | 포인터가 ROI 안에서 지정 시간 유지되면 유효함 |
| 옴탈 채검하기 | 옴탈 얼굴의 채검하기 아이콘 | 포인터가 ROI 안에서 지정 시간 유지되면 유효함 |
| 옴탈 몰아내기 | 날아오는 옴탈 | 포인터가 옴탈 ROI와 중첩되고 활성 손의 움직임이 기준 이상이면 유효함 |

기획서에서 바꿀 단계별 판정과 무효 처리는 기존안과 비교할 수 있도록 다음 표로 정리함.

| 적용 단계 | 목표 ROI | 유효 입력 판정 | 무효 처리 |
|---|---|---|---|
| 옴탈 조우 | 화면 좌우에 나타난 옴탈 | 포인터가 옴탈 ROI와 중첩되고 활성 손의 수평 움직임이 기준 이상이면 유효함 | 포인터가 옴탈 ROI와 중첩되지 않거나 활성 손의 수평 움직임이 기준 이하이면 무효로 처리함 |
| 옴탈 잡아채기 | 옴탈 머리 영역 | 포인터가 옴탈 머리 ROI와 중첩되면 잡아채기를 시작함. 이후 옴탈이 포인터에 끌려 손의 움직임을 따라 이동함 | 포인터가 옴탈 머리 ROI와 중첩되기 전에는 옴탈을 잡거나 이동시킨 것으로 처리하지 않음 |
| 옴탈 채검하기 | 화면을 가득 채운 옴탈 얼굴 | 양손의 포인터를 모두 표시함. 각 손의 포인터가 옴탈 얼굴 ROI와 중첩된 상태에서 해당 손의 휘두르기 움직임이 기준 이상이면 타격 1회로 판정함 | 손의 포인터가 옴탈 얼굴 ROI와 중첩되지 않거나 해당 손의 휘두르기 움직임이 기준 이하이면 그 손의 타격을 무효로 처리함 |
| 옴탈 몰아내기 | 날아오는 옴탈 | 포인터가 옴탈 ROI와 중첩되고 활성 손의 움직임이 기준 이상이면 유효함 | 포인터가 옴탈 ROI와 중첩되지 않거나 활성 손의 움직임이 기준 이하이면 무효로 처리함 |

기존 3열 표의 보충 규칙은 다음과 같음.

- 옴탈 조우와 몰아내기에서는 포인터가 목표와 닿아도 움직임이 기준 이하이면 무효로 처리함
- 잡아채기와 채검하기에서는 포인터가 ROI를 벗어나면 유지 시간을 초기화함
- ROI에 적용할 위치, 크기, 활성 손 접근 기준, 움직임 기준과 유지 시간은 데이터 테이블로 관리함

### 2.3.6 게임 입력 변환

- 유효하다고 판정한 ROI에 연결된 정보를 게임 입력으로 변환함
- ROI에 설정된 캐릭터 행동과 목표 반응을 실행함
- 입력 결과를 수행 기록과 진행 인디케이터에 반영함
- 현재 입력을 마치면 활성 손을 해제하고 다음 입력을 준비함

## 2.4 설정 및 예외 처리

### 2.4.1 주요 설정값

모션 인식과 입력 판정에 필요한 값은 JSON 데이터 테이블로 관리하고 실제 설치 환경에서 조정함.

| 항목 | 설명 |
|---|---|
| 유저 식별 영역 | 최초 유저 식별 및 등록에 사용하는 화면상의 위치와 영역 정보 |
| 유저 식별 신뢰도 기준 | 유저 식별 성공 여부를 판단하는 최소 기준 |
| 유저 추적 신뢰도 기준 | 등록된 유저의 추적 상태를 정상으로 판단하는 최소 기준 |
| 손 추적 신뢰도 기준 | 왼손 또는 오른손 위치를 정상적으로 인식했다고 판단하는 최소 기준 |
| 움직임 검출 임계값 | 손의 움직임을 검출 대상으로 인정하는 최소 기준 |
| 최소 움직임 영역 비율 | 미세 움직임과 영상 노이즈를 제외하는 최소 범위 |
| 활성 손 선택 기준 | 검출 임계값을 넘은 움직임 가운데 손을 활성 손으로 선택하는 최소 이동 거리와 속도 |
| 동시 조건 판정 시간 | 두 손의 유효 움직임 또는 ROI 접근 조건을 같은 시점에 성립한 것으로 보는 시간 범위 |
| 손 위치 좌표 보정값 | 인식한 손 위치를 화면상의 포인터 위치에 맞추는 좌표 보정값 |
| 포인터 이동 보정값 | 손 떨림과 인식값 변화로 생기는 포인터 흔들림을 줄이는 값 |
| 포인터 숨김 기준 시간 | 활성 손을 인식하지 못했을 때 포인터를 숨기기까지 허용하는 시간 |
| 입력 쿨다운 | 같은 움직임으로 연속 입력되는 것을 막는 시간 |
| 추적 실패 허용 시간 | 일시적인 유저 추적 실패를 허용하는 시간 |
| 재식별 전환 시간 | 추적 실패가 계속될 때 유저 재식별로 전환하는 기준 시간 |

### 2.4.2 ROI 데이터

개별 ROI 정보는 JSON 데이터 테이블로 관리함.

| 항목 | 설명 |
|---|---|
| ROI ID | ROI 고유 식별값 |
| 적용 단계 | ROI를 사용하는 옴탈잡이 진행 단계 |
| 판정 유형 | 움직임 타격 또는 위치 유지 |
| X/Y | 화면 내 ROI 기준 위치 |
| Width/Height | ROI 판정 영역의 크기 |
| 활성 손 접근 기준 | 손이 해당 ROI에 접근했다고 판단하는 거리 또는 진입 기준 |
| 판정 기준 | 이동 방향, 거리, 속도, 중첩 또는 유지 시간 |
| 연결 입력 | 판정 성공 시 발생시키는 게임 입력 |

### 2.4.3 예외 처리

| 유형 | 처리 |
|---|---|
| 유저 추적 실패 | 입력 판정과 포인터 표시를 중지함. 실패가 일정 시간 이상 이어지면 유저 식별과 등록을 다시 진행함 |
| 활성 손 추적 실패 | 포인터를 숨기고 입력 판정을 중지함. 현재 입력의 취소와 활성 손 재선택 여부는 `[확정 필요]`임 |
| 한쪽 손 추적 실패 | 정상 추적되는 다른 손만 활성 손 후보로 사용할지는 `[확정 필요]`임 |
| 유저 영역 이탈 | 입력을 제한하고 포인터를 숨긴 뒤 정상 체험 위치로 돌아오도록 안내함 |
| 다중 인원 간섭 | 등록된 유저의 신체와 양손만 추적과 입력 판정에 사용함 |
| 양손 동시 움직임 | 현재 활성 ROI 접근 조건까지 같은 시점에 성립하면 적용할 우선순위는 `[확정 필요]`임 |
| 미세 움직임과 오검출 | 최소 움직임 영역 비율과 움직임 검출 임계값을 충족하지 못하면 입력으로 처리하지 않음 |
| 포인터 흔들림 | 포인터 이동 보정값을 적용한 좌표를 화면에 표시함 |
| 연속 입력과 중복 입력 | 입력 쿨다운을 적용해 입력 간격과 재판정 조건을 조정함 |
| 카메라 입력 이상 | 모션 입력과 포인터 표시를 중단하고 세션 진행 실패 처리를 실행함 |

# 3. 플로우 이미지 수정안

현재 `assets/시범콘텐츠/탈놀음/플로우_모션인식.png`에는 양손 추적과 활성 손 선택 및 해제 과정이 없으므로 다음 내용을 보강해야 함.

- `손 위치 포인터 활성화`를 `활성 손 선택 및 고정` 뒤로 옮김
- `유저 추적 및 영역 추출`을 `유저와 양손 추적 및 영역 추출`로 바꿈
- `움직임 검출`을 `양손 위치 및 움직임 검출`로 바꿈
- `포인터 위치 갱신` 앞에 `활성 손 선택 및 고정`을 추가함
- `포인터 위치 갱신`을 `손 위치 포인터 표시 및 위치 갱신`으로 바꿈
- `게임 입력 변환` 뒤에 `활성 손 해제`를 추가함
- 게임 입력 성공 외에 현재 입력을 끝내기로 확정한 조건도 `활성 손 해제`에 연결함
- 단계별 입력 방식 분기는 추가하지 않음. 단계 차이는 ROI 판정 기준으로 처리함

권장 흐름은 다음과 같음.

`시스템 시작 → 유저 식별 및 등록 → 유저와 양손 추적 및 영역 추출 → 양손 위치 및 움직임 검출 → 활성 손 선택 조건 확인 → 활성 손 선택 및 고정 → 손 위치 포인터 표시 및 위치 갱신 → ROI 입력 판정 → 유효 입력이면 게임 입력 변환 → 활성 손 해제 → 체험 진행 여부 확인`

- 활성 손 선택 조건을 충족하지 못하면 체험 진행 여부를 확인한 뒤 양손 추적으로 돌아감
- ROI 입력이 무효이면 양손 추적을 계속하되 활성 손을 유지한 채 손 위치 포인터 갱신으로 돌아감
- 체험이 진행 중이면 유저와 양손 추적을 반복하고, 끝났으면 시스템을 종료함
