> [[덧뵈기 - 탈놀음 한바탕 기획서]] 3.5의 옴탈잡이 모션 인식을 등록 유저의 양손 추적, 입력마다 한 손 지정, 원형 충돌 영역을 가진 손 위치 포인터 방식으로 고치는 사용자 검토안임.

# 1. 적용 범위

- **반영 대상**
	- 기획서 3.5의 옴탈잡이 모션 인식 교체안을 정리함
	- 양손 추적부터 입력 손 해제까지의 공통 처리와 단계별 판정을 다룸
- **공통 원칙**
	- 양손을 항상 추적하되 현재 입력에는 한 손만 입력 손으로 지정함
	- 현재 입력이 끝나면 입력 손을 해제하고 양손을 다시 비교함
	- 입력 손 지정에는 손 움직임만 사용하고 ROI는 사용하지 않음
- **수정 제외**
	- 원 기획서와 assets/시범콘텐츠/탈놀음/플로우_모션인식.png는 수정하지 않음
	- 정확한 기준값은 프로토타입과 설치 환경에서 확정함

# 2. 기획서 반영안

## 2.1 개요

### 2.1.1 정의

- 카메라로 등록 유저의 신체와 양손을 추적하고 손 움직임을 게임 입력으로 변환하는 시스템임

### 2.1.2 진행

- 양손 중 입력 손 지정 움직임 기준을 먼저 충족한 손을 입력 손으로 지정함
- 입력 손의 포인터와 목표 관심 영역(ROI)의 충돌 및 단계별 움직임을 판정함
- 현재 입력이 끝나면 입력 손을 해제하고 양손을 다시 비교함

### 2.1.3 목적

- 등록 유저가 별도 컨트롤러 없이 손을 움직여 옴탈을 직관적으로 조작하게 함

## 2.2 레퍼런스

### 2.2.1 EyeToy: Play - Kung Foo

- **게임 정보**
	- 타이틀: _EyeToy: Play_
	- 미니게임: **Kung Foo**
	- 장르: 체감형 파티 미니게임
	- 플레이 영상: https://youtu.be/0h1EKk6JpK8?si=GEQY9L-9jSdw3drs
- **적용 요소**
	- 신체 움직임을 화면상의 목표와 연결함
	- 별도 컨트롤러 없이 손 움직임을 입력으로 사용함
	- 카메라 영상을 대신하는 손 위치 포인터로 입력 위치를 보여줌

## 2.3 공통 처리

### 2.3.1 유저 식별과 추적

- 화면의 가이드라인을 기준으로 체험 위치에 선 유저를 식별함
- 식별된 유저에게 현재 세션의 추적 ID를 부여함
- 추적 ID를 유지하면서 등록 유저의 신체 영역을 주변 인원과 구분함
- 신체 영역 자체는 게임 입력 판정에 사용하지 않음
- 등록 유저의 신체 영역에 연결된 양손만 입력 후보로 사용함
- 등록 유저 추적이 끊기면 입력 판정과 포인터 표시를 중지함
- 실패가 추적 실패 허용 시간을 넘으면 현재 입력을 취소하고 입력 손을 해제하며, 재식별 전환 시간을 넘으면 유저를 다시 식별함

### 2.3.2 양손 위치와 움직임 추적

- 등록 유저의 왼손과 오른손 위치를 각각 추적함
- 양손의 위치를 화면 좌표로 변환함
- 손마다 이동 방향, 이동 거리, 이동 속도와 추적 신뢰도를 산출함
- 입력 손을 지정하지 않은 동안 양손의 움직임을 계속 비교함

### 2.3.3 입력 손 지정과 해제

- **지정 조건**
	- 현재 입력 손이 없고 손 추적 신뢰도가 기준 이상인 때만 지정 여부를 판정함
	- 입력 손 지정 움직임 기준을 먼저 충족한 손을 입력 손으로 지정함
	- 두 손이 동시 조건 판정 시간 안에 기준을 충족하면 오른손을 지정함
	- ROI 위치, ROI 거리와 ROI 충돌 여부는 입력 손 지정에 사용하지 않음
- **유지**
	- 입력 손을 지정한 때부터 현재 입력이 끝날 때까지 다른 손으로 바꾸지 않음
	- 입력 손을 지정한 시점의 움직임부터 단계별 유효 입력 판정에 포함함
- **해제**
	- 타격 1회 성립, 잡아채기 완료, 입력 취소, 목표 소멸, 단계 종료 또는 입력 손 추적 실패 시 해제함
	- 지정 뒤 입력 대기 제한 시간 안에 단계별 입력 시작 조건이 성립하지 않으면 해제함
- **다음 입력**
	- 해제할 때 양손의 움직임 기준 위치를 현재 위치로 초기화함
	- 방금 사용한 손에는 손별 입력 쿨다운을 적용함
	- 초기화 뒤 발생한 새 움직임부터 양손을 다시 비교해 다음 입력 손을 지정함

### 2.3.4 손 위치 포인터와 ROI 충돌

- 입력 손을 지정하면 해당 손의 화면 좌표에 손 위치 포인터 한 개를 표시함
- 포인터 중심점은 입력 손의 화면 좌표를 따라 이동함
- 포인터에는 화면 표시 크기와 같은 원형 충돌 영역을 부여함
- 목표 관심 영역(ROI)은 화면상의 목표에 설정하는 충돌 영역임
- 포인터 충돌 영역과 목표 ROI가 닿거나 교차하면 충돌로 판정함
- 두 영역이 조금이라도 닿으면 충돌이 성립하며 최소 중첩률은 사용하지 않음
- 충돌이 시작되면 포인터 또는 목표의 색상이나 크기를 바꿔 결과를 보여줌
- 손 떨림과 짧은 추적값 변화는 좌표 보정과 충돌 이탈 지연으로 완화함

### 2.3.5 게임 입력 변환

- 입력 손 지정은 입력 후보를 정하는 절차이며 게임 입력 성공을 뜻하지 않음
- 조우, 채검하기와 몰아내기는 포인터와 목표 ROI가 충돌하고 휘두르기 기준이 성립하면 타격 1회로 판정함
- 잡아채기는 포인터와 머리 ROI의 최초 충돌로 끌기를 시작하고 별도 완료 조건이 성립하면 입력을 완료함
- 유효 입력에 연결된 목표 반응, 수행 기록과 진행 표시를 갱신함
- 같은 충돌을 유지하는 것만으로 입력을 반복하지 않음
- 다음 유효 입력은 새 움직임과 손별 입력 쿨다운을 모두 충족해야 함

## 2.4 단계별 입력

### 2.4.1 기존 기획서 판정

기존 단계별 판정은 개정안과 비교할 수 있도록 다음 표로 유지함.

| 적용 단계 | 목표 ROI | 유효 입력 판정 |
|---|---|---|
| 옴탈 조우 | 화면 좌우에 나타난 옴탈 | 포인터가 옴탈 ROI 안에 있고 입력 손의 수평 움직임이 기준 이상이면 유효함 |
| 옴탈 잡아채기 | 옴탈 머리의 잡아채기 아이콘 | 포인터가 ROI 안에서 지정 시간 유지되면 유효함 |
| 옴탈 채검하기 | 옴탈 얼굴의 채검하기 아이콘 | 포인터가 ROI 안에서 지정 시간 유지되면 유효함 |
| 옴탈 몰아내기 | 날아오는 옴탈 | 포인터가 옴탈 ROI 안에 있고 입력 손의 움직임이 기준 이상이면 유효함 |

### 2.4.2 개정 판정

기획서에서 바꿀 목표 ROI, 유효 입력 판정과 무효 처리는 다음과 같음.

| 적용 단계 | 목표 ROI | 유효 입력 판정 | 무효 처리 |
|---|---|---|---|
| 옴탈 조우 | 화면 좌우에 번갈아 나타난 옴탈 | 입력 손 포인터가 옴탈 ROI와 충돌하고 같은 손의 수평 휘두르기가 기준 이상이면 타격 1회로 판정함 | 충돌이 없거나 수평 휘두르기가 기준 이하이면 타격으로 세지 않고 입력 손을 유지한 채 제한 시간까지 다시 판정함 |
| 옴탈 잡아채기 | 옴탈 머리 | 입력 손 포인터가 머리 ROI와 처음 충돌하면 옴탈을 포인터에 결합하고 끌기를 시작함. 이후 옴탈이 손의 움직임을 따라 이동하며 별도 완료 조건이 성립하면 입력을 완료함 | 머리 ROI와 충돌하기 전에는 옴탈을 잡거나 이동시킨 것으로 처리하지 않고 입력 손을 유지한 채 제한 시간까지 다시 판정함 |
| 옴탈 채검하기 | 화면을 가득 채운 옴탈 얼굴 | 현재 입력 손의 포인터가 얼굴 ROI와 충돌하고 같은 손의 휘두르기가 기준 이상이면 타격 1회로 판정함 | 충돌이 없거나 휘두르기가 기준 이하이면 타격으로 세지 않고 입력 손을 유지한 채 제한 시간까지 다시 판정함 |
| 옴탈 몰아내기 | 날아오는 옴탈 얼굴 | 입력 손 포인터가 옴탈 ROI와 충돌하고 같은 손의 휘두르기가 기준 이상이면 타격 1회로 판정함 | 충돌이 없거나 휘두르기가 기준 이하이면 타격으로 세지 않고 입력 손을 유지한 채 제한 시간까지 다시 판정함 |

- **입력 종료**
	- 조우, 채검하기와 몰아내기는 타격 1회가 성립할 때 입력 손을 해제하고 양손 기준 위치를 초기화한 뒤 새 움직임부터 다시 비교함
	- 잡아채기는 완료 조건이 성립할 때 옴탈과 포인터의 결합을 풀고 입력 손을 해제하며, 양손 기준 위치를 초기화한 뒤 새 움직임부터 다시 비교함
- **채검하기**
	- 한 번의 타격에는 현재 입력 손 한 손만 사용함
	- 타격마다 입력 손을 새로 지정하므로 다음 타격에서는 직전과 다른 손도 사용할 수 있음
- **잡아채기**
	- 옴탈을 포인터에 결합한 뒤에는 머리 ROI와의 충돌 유지를 요구하지 않음

## 2.5 데이터와 예외

### 2.5.1 주요 설정값

모션 인식과 입력 판정에 필요한 값은 JSON 데이터 테이블로 관리하고 설치 환경에서 조정함.

| 항목 | 설명 |
|---|---|
| 유저 식별 영역 | 최초 유저 식별과 등록에 사용하는 화면 영역 |
| 유저 식별 신뢰도 기준 | 유저 식별 성공 여부를 판단하는 최소 기준 |
| 유저 추적 신뢰도 기준 | 등록 유저의 추적 상태를 정상으로 판단하는 최소 기준 |
| 손 추적 신뢰도 기준 | 손 위치를 정상적으로 인식했다고 판단하는 최소 기준 |
| 입력 손 지정 움직임 기준 | 입력 손을 지정할 최소 이동 거리와 속도 |
| 동시 조건 판정 시간 | 양손이 움직임 기준을 동시에 충족한 것으로 보는 시간 범위 |
| 입력 대기 제한 시간 | 입력 손 지정 뒤 단계별 입력 시작 조건이 성립하기까지 기다리는 시간 |
| 손 위치 좌표 보정값 | 인식한 손 위치를 화면 좌표에 맞추는 값 |
| 포인터 이동 보정값 | 포인터의 작은 흔들림을 줄이는 값 |
| 포인터 충돌 영역 형태 | 포인터 충돌 영역의 형태. 원형을 사용함 |
| 포인터 충돌 영역 크기 | 화면 표시와 충돌 판정에 함께 사용할 포인터 지름 |
| 충돌 이탈 지연 시간 | 충돌이 끊긴 상태가 얼마나 이어져야 종료로 판정할지를 정하는 시간 |
| 포인터 숨김 기준 시간 | 입력 손을 연속해서 인식하지 못했을 때 포인터를 숨기고 현재 입력을 취소하는 기준 시간 |
| 손별 입력 쿨다운 | 사용한 손의 다음 입력을 허용하기까지의 시간 |
| 추적 실패 허용 시간 | 일시적인 유저 추적 실패를 허용하는 시간 |
| 재식별 전환 시간 | 추적 실패가 이어질 때 재식별로 전환하는 시간 |

- 입력 손 지정 움직임 기준과 단계별 유효 움직임 기준은 별도 값으로 관리함
- 포인터 표시 크기와 충돌 영역 크기는 같은 값으로 관리함
- 충돌은 접촉 여부만 판정하므로 최소 중첩률은 설정값으로 두지 않음

### 2.5.2 ROI 데이터

개별 목표 ROI는 다음 값을 JSON 데이터 테이블로 관리함.

| 항목 | 설명 |
|---|---|
| ROI ID | ROI 고유 식별값 |
| 적용 단계 | ROI를 사용하는 옴탈잡이 단계 |
| 목표 오브젝트 | ROI가 설정되며 충돌 결과에 따라 이동하거나 반응하는 화면상의 대상 |
| ROI 형태 | 원형 또는 사각형 충돌 영역 |
| X/Y | 화면 내 ROI 기준 위치 |
| Width/Height/Radius | ROI 형태에 따른 충돌 영역 크기 |
| 충돌 사건 | 충돌 시작, 유지 또는 종료 가운데 사용할 사건 |
| 유효 움직임 기준 | 이동 방향, 거리와 속도 조건 |
| 충돌 후 동작 | 피격, 포인터 결합 또는 끌기 처리 |
| 입력 완료 조건 | 타격 1회 또는 잡아채기 완료 조건 |
| 연결 입력 | 판정 성공 시 발생시킬 게임 입력 |

### 2.5.3 예외 처리

| 유형                | 처리                                                                                     |
| ----------------- | -------------------------------------------------------------------------------------- |
| 등록 유저 추적 실패       | 입력 판정과 포인터 표시를 중지함. 추적 실패 허용 시간을 넘으면 현재 입력을 취소하고 입력 손을 해제하며, 재식별 전환 시간을 넘으면 유저를 다시 식별함 |
| 입력 손 추적 실패        | 실패가 포인터 숨김 기준 시간을 넘으면 현재 입력을 취소하고 포인터를 숨긴 뒤 입력 손을 해제함                                  |
| 입력 손이 아닌 손의 추적 실패 | 현재 입력은 유지하고 해당 손을 다음 입력 후보에서 제외함                                                       |
| 유저 영역 이탈          | 현재 입력을 취소하고 입력 손을 해제한 뒤 포인터를 숨기고 정상 체험 위치로 돌아오도록 안내함                                   |
| 다중 인원 간섭          | 등록 유저의 신체 영역에 연결된 양손만 추적과 입력에 사용함                                                      |
| 양손 동시 움직임         | 오른손을 입력 손으로 지정함                                                                        |
| ROI 경계의 포인터 흔들림   | 좌표 보정과 충돌 이탈 지연을 적용함                                                                   |
| 연속 입력과 중복 입력      | 입력 손 해제와 손별 입력 쿨다운 뒤 새 움직임을 다시 판정함                                                     |
| 카메라 입력 이상         | 모션 입력과 포인터 표시를 중단하고 세션 실패 처리를 실행함                                                      |

### 2.5.4 확정 필요

- **잡아채기**
	- 완료를 판정할 이동 거리, 이동 시간 또는 목표 위치
	- 입력 손 추적이 끊겼을 때 옴탈을 원위치로 돌릴지 현재 위치에 둘지 여부
- **입력 안정성**
	- 입력 손 지정 움직임 기준과 입력 대기 제한 시간
	- 손별 입력 쿨다운
- **충돌 판정**
	- 포인터 충돌 영역의 지름과 충돌 이탈 지연 시간
	- 한 포인터가 둘 이상의 ROI와 동시에 충돌할 때 적용할 우선순위

# 3. 플로우 이미지 수정안

## 3.1 노드 수정

- **유저와 손 추적**
	- 유저 추적 및 영역 추출을 등록 유저와 양손 추적으로 바꿈
	- 양손 위치와 움직임 검출 뒤에 입력 손 지정 조건 확인을 추가함
- **입력 손과 포인터**
	- 입력 손 지정 및 고정 뒤에 입력 손 포인터 표시를 추가함
	- 포인터 위치 갱신을 포인터 위치 및 원형 충돌 영역 갱신으로 바꿈
- **판정과 반복**
	- ROI 입력 판정을 포인터 충돌 영역과 목표 ROI 충돌 판정으로 바꿈
	- 게임 입력 변환 뒤에 입력 손 해제와 양손 재비교를 추가함
	- 채검하기도 공통 입력 손 지정과 해제 흐름을 사용함
- **잡아채기**
	- 머리 ROI 충돌 뒤에 옴탈과 포인터 결합 및 포인터 좌표로 옴탈 이동을 추가함

## 3.2 권장 흐름

공통 흐름은 다음과 같음.

시스템 시작 → 유저 식별 및 등록 → 등록 유저와 양손 추적 → 양손 움직임 비교 → 입력 손 지정 및 고정 → 입력 손 포인터 표시 및 충돌 영역 갱신 → 목표 ROI 충돌과 단계별 움직임 판정 → 유효 입력 변환 → 입력 손 해제 → 양손 기준 위치 초기화 → 새 움직임 비교

잡아채기의 충돌 이후 흐름은 다음과 같음.

입력 손 포인터와 머리 ROI 충돌 → 옴탈과 포인터 결합 → 포인터 좌표로 옴탈 이동 → 잡아채기 완료 판정 → 결합 해제 → 입력 손 해제 → 양손 기준 위치 초기화 → 새 움직임 비교

- 단계별 입력 시작 조건이 성립하지 않으면 입력 손을 유지한 채 포인터와 충돌 판정을 계속 갱신함
- 입력 대기 제한 시간이 끝나면 입력 손을 해제하고 양손을 다시 비교함
- 체험이 끝나면 양손 추적을 중지하고 시스템을 종료함
