> 기존 인포그래픽 지침을 기준 정본으로 유지하고, SKILL.md에 실행 순서와 근거 확인 및 진행 조건을 두어 지침 미준수를 줄이는 도입안임. 실제 스킬 등록과 검사 및 자동 차단은 아직 구현하지 않음.

# 1. 적용 범위와 목표

- **목표**: 작성자가 지침 이행을 확인하고 미준수를 처리한 뒤 결과를 전달하도록 함
- **사용자 역할**: 원하는 내용과 표현, 요청 범위의 변경 및 지침 예외를 결정함
- **작성자 역할**: 기존 지침의 이행 여부를 확인하고 직접 요청 범위의 누락과 실행 오류를 정정함
- **현재 상태**: 이 문서는 도입안임. 기존 지침과 프로젝트 운영 규칙을 변경하거나 별도 스킬을 등록한 상태가 아님
- **적용 대상**: 원자료를 분석해 인포그래픽을 새로 생성하거나 기존 인포그래픽을 정정하는 작업임

성공 여부는 생성 횟수 감소가 아니라 필수 요구의 이행 근거, 누락 발견, 정정과 보고의 일치로 판단함. 생성 모델의 표현 오류와 지침 미준수를 구분해 기록함.

# 2. 문서별 역할과 사용 조건

기준과 실행 절차의 소유처를 다음과 같이 나눔.

| 구성 | 소유할 내용 | 유지 방식 |
|---|---|---|
| [[AGENTS]] | 공통 권한, 규칙 로딩, 로그, 검수 게이트와 커밋 | 기존 운영 규칙 유지 |
| [[인포그래픽 생성 지침]] | 내용 분석, 문자열, 구성, 프롬프트와 이미지 검수 기준 | 기준의 정본 유지 |
| 제안하는 `SKILL.md` | 정본 로딩, 단계별 입력과 출력, 근거 대조와 진행 조건 | 기준 전문을 복사하지 않고 실제 파일 참조 |
| 작업별 기록 | 적용 요구, 완성 설계, 실행 내역과 검수 증거 | 대조한 파일 버전과 함께 보존 |
| 제안하는 양식과 스크립트 | 기록 형식과 기계 검사 | 정본 변경 시 대응 항목 점검 |

스킬의 이름과 설명에는 인포그래픽 생성 및 정정 요청에 사용하는 절차임을 명시함. 일반 사진, 캐릭터 원화나 영상 생성에는 적용하지 않도록 범위를 적음. 스킬은 별도 에이전트가 아니라 작성자가 선택해 읽는 작업 지침임. 이 구조는 [OpenAI 스킬 안내](https://learn.chatgpt.com/docs/build-skills)에 근거함.

스킬 등록 뒤에는 프로젝트 `AGENTS.md`의 인포그래픽 작업 경로와 연결하는 변경을 별도로 검토함. 현재도 지침을 읽도록 하는 규칙은 있으므로 자동 선택만을 미준수 해결책으로 삼지 않음.

사용자 지정과 적용되는 운영 및 도구 지침을 먼저 대조함. 기존 이미지 생성 스킬의 기본 도구와 저장소 실행 설정이 다르면 차이를 기록하고 적용할 경로를 확정함. 지원하지 않는 설정을 실행한 것으로 기록하거나 임의의 대체값을 같은 설정으로 취급하지 않음.

# 3. 지난 미준수에 대한 대응

아래는 2026-09-14 꼭두각시 인포그래픽 재검토에서 확인한 문제를 대응 절차에 연결한 것임. 당시 생성 자료는 [생성 기록](../../assets/시범콘텐츠/꼭두각시/꼭두각시_개요_인포그래픽_생성기록_2026-09-14.txt)에 있으며, 재검토 이력은 커밋 `9ed166a`에 보존되어 있음.

## 3.1 지침 이행과 보고의 문제

누락 여부를 판단할 때는 생성 전에 남긴 설계, 실제 호출과 생성 후 검수 자료를 각각 대조함.

| 문제 | 도입할 대응 | 확인할 근거 |
|---|---|---|
| 블록별 유형 판정과 서사 설계 누락 | 생성 전 분석표 고정 | 유형, 관계와 원자료 위치 |
| 격자 및 비격자 지시 혼합 | 선택 계열과 최종 프롬프트 대조 | 계열 선언과 충돌 문구 점검 |
| 핵심 메시지의 제목 반영 누락 | 메시지와 제목 문자열 연결 | 분석표, 문자열 목록과 제목 지시 |
| 지침 기본 도구와 설정을 재현하지 않음 | 예정값과 실제 호출 및 응답 구분 | 모델, 품질, 해상도와 실제 크기 |
| 목업 내부 제한을 프롬프트에서 변경 | 정본 제한과 프롬프트 대조 | 제한 문구와 화면 영역 검수 |
| 확대 검수 기록 부재와 검수 완료 전 후속 생성 | 회차별 검수를 마친 뒤 다음 행동 판정 | 확대 관찰, 전사본과 기계 대조 결과 |
| 부분 검수를 전체 무발견으로 보고 | 확인 범위별 결과 작성 | 항목별 상태와 남은 미확인 범위 |

## 3.2 별도로 판단할 디자인과 근거의 문제

- 허용된 히어로 밴드와 하단 패널 패턴 자체를 위반으로 판정하지 않음. 같은 내용을 반복하는 배치와 잘못 읽힐 수 있는 연결은 원자료 및 용도와 대조함
- 단순한 시선 흐름 화살표와 실제 시스템의 순서 및 의존 관계를 구분함. 원문이 정하지 않은 순서를 관계 설명으로 추가했으면 사실 대조 대상에 포함함
- 실물 내부 구조처럼 학습 사실로 읽히는 묘사는 원자료와 대조함. 근거가 없으면 사실처럼 표현하지 않고 추상화하거나 미결로 남김
- 이미지의 완성도와 지침 준수 여부를 별도로 기록함. 보기 좋다는 판단으로 미준수를 통과시키지 않음

# 4. 제안하는 스킬 실행 순서

다음 순서는 기존 지침의 네 단계를 실제 산출물과 판정으로 연결하는 보강안임. 생성 전 독립 준수 대조와 아래 진행 조건은 새로 도입할 절차이며 현행 구현으로 보고하지 않음.

## 4.1 지침 로딩과 요구 확정

1. 사용자 요청에서 원자료, 분석 범위, 용도와 화면비를 확인함
2. 적용되는 프로젝트 규칙과 인포그래픽 지침을 끝까지 읽음
3. 읽은 파일 경로와 버전 해시를 기록함. 해시는 내용 변경 감지용이며 읽기 수행의 증명으로 삼지 않음
4. 정본의 모든 조항을 적용, 조건부 적용, 권고와 사용자 변경으로 구분함. 조건부 항목에는 조건 충족 여부와 사유를 적음
5. 적용할 실행 설정을 확정하고 실제 도구가 지원하는지 확인함

현행 기본 설정은 [[인포그래픽 생성 지침#5. 생성과 검수]]에서 읽음. 현재는 힉스필드 `gpt_image_2`, 16:9, 1차 1k/medium이며 사용자 요청 시에만 2k/high로 생성함. 화면비 등 사용자 지정은 요청대로 반영함. 정정 생성도 사용자 요청 없이 2k/high로 높이지 않음.

## 4.2 분석과 구성 설계

1. 원자료를 끝까지 읽고 근거와 포함 범위를 정리함. 새 개수나 분류를 도출하면 [[CONVENTIONS#3.8 구조 우선 작성 (정보 설계)]]의 최초 추출과 대응 이력을 먼저 남김
2. 핵심 메시지와 서사를 작성하고 블록별 유형을 판정함
3. 순서, 병렬과 의존 관계를 구분해 원자료 위치와 연결함
4. 레이아웃 계열과 패턴, 시각 요소 및 라벨 소속을 정함
5. 모든 문자열과 기호, 위치 및 횟수를 확정함
6. 원문에 없는 설계 추가와 제외 항목을 구분하고 분석 및 설계를 생성 전에 저장함

분석표에는 블록 ID, 원자료 위치, 전달할 내용, 정보 유형, 관계, 시각 요소와 문자열 ID를 기록함. 단순히 칸이 채워졌다는 이유로 내용의 타당성을 통과시키지 않음.

## 4.3 프롬프트 작성과 생성 전 판정

1. 완성 설계와 확정 문자열을 사용해 영어 프롬프트를 작성함
2. 지침 조항별로 설계와 프롬프트 및 예정 호출 인수의 해당 위치를 대조함
3. 별도 맥락의 검토자에게 정본, 원자료, 완성 설계, 프롬프트와 예정 설정만 전달함. 작성 의도나 중간 추론은 전달하지 않음
4. 기계 판정 항목과 내용 대조 항목의 결과를 합쳐 생성 전 상태를 판정함
5. 정정할 누락은 작성자가 처리하고 영향 범위를 다시 대조함
6. 생성 전 필수 항목이 모두 통과했을 때 대조한 버전의 프롬프트와 설정으로 도구를 호출함

독립 대조는 작성자의 준수 점검을 보완하는 제안임. [[AGENTS#2.4 사용자 승인 게이트]]의 외부 검토나 사용자 판정을 대신하지 않음. 사용자 승인이 필요한 정책 변경과 요청 범위 밖 사실 변경은 기존 운영 규칙에 따라 처리함.

## 4.4 생성 후 판정과 전달

1. 실제 호출 인수, 응답의 모델 표기, 작업 ID와 결과 파일을 기록함. 응답에 없는 값은 확인 불가로 남김
2. 작성자가 원자료와 설계 및 이미지를 직접 대조함. 목업과 미세 영역은 확대해서 확인함
3. [[인포그래픽 생성 지침#5. 생성과 검수]]의 직접 대조, 블라인드 전사와 기계 대조를 순서대로 마침
4. 메시지, 관계, 레이아웃, 시각적 근거, 목업 제한과 실제 규격을 확인함
5. 회차별 결과를 기록한 뒤 재생성 기준에 따라 정정 여부를 판정함. 내용을 바꾸면 생성 전 영향 항목도 다시 대조함
6. 결과 전달 조건을 충족하면 이미지와 기록을 보존하고 로그, 필수 자동 검사와 커밋을 수행함
7. 사용자에게 실제 설정, 확인 범위, 발견과 정정 건수 및 남은 미확인 항목을 보고함

정정으로 다른 위치가 바뀔 수 있으므로 새 이미지의 전체 문자열 검수는 다시 수행함. 지정 외 미세 유사 문자의 허용은 정본 기준대로 판정하고 근거를 남김. 보고에는 지침 미준수와 생성 모델의 표현 오류 및 디자인 판단을 구분함.

# 5. 체크리스트와 진행 조건

## 5.1 판정 기록 형식

각 항목은 하나의 판정을 다루고 근거 위치를 가짐. 필수 여부와 판정 상태를 별도 필드로 기록함.

| 필드 | 기록할 값 |
|---|---|
| 요구 ID와 정본 위치 | 조항 ID, 파일, 실제 헤딩과 해당 문구 위치 |
| 판정 시점 | 생성 전 또는 생성 후 |
| 적용 구분 | 필수, 조건부 또는 권고 |
| 판정 기준 | 무엇과 무엇이 일치해야 하는지 |
| 근거 | 파일 경로, 항목 ID와 대조한 버전 |
| 상태 | 통과, 미통과, 미확인 또는 해당 없음 |
| 발견과 처리 | 문제, 정정 내용, 재대조 결과 또는 잔류 사유 |

- **통과**: 적용되는 기준을 실제 자료와 대조했고 근거를 제시할 수 있음
- **미통과**: 기준과 어긋나는 자료나 결과가 있음
- **미확인**: 자료 부재나 판독 및 실행 확인 불가로 판정하지 못함
- **해당 없음**: 조건부 항목의 조건이 성립하지 않으며 사유가 있음

사용자 지정은 해당 없음으로 처리하지 않고 적용값과 요청 근거를 기록함. 권고를 필수로 승격하거나 조건부 요구를 전부 필수로 처리하지 않음. 다음 목록은 체크 항목의 예시이며, 실제 목록은 정본 전체와 대조해 누락 없이 작성함.

## 5.2 생성 전 체크 항목 예시

- [ ] 핵심 메시지와 실제 제목 문자열이 연결되어 있음
- [ ] 모든 블록의 정보 유형과 관계가 지정되고 원자료와 일치함
- [ ] 확정 문자열에 기호, 위치와 횟수가 배정되어 있음
- [ ] 문자열의 형태, 길이와 반복이 정본 기준에 맞음
- [ ] 선택한 계열과 스타일 선언 및 영역별 배치 지시가 일치함
- [ ] 한국어 렌더 문자열과 영어 연출이 분리되어 있음
- [ ] 텍스트 통제 조항의 위치와 내용이 정본에 맞음
- [ ] 화면 목업을 두면 내부 추상 도형 제한을 반영함
- [ ] 차트를 두면 추세 방향과 수치 처리 방식을 확정함
- [ ] 예정 호출 설정이 적용값과 일치하고 실제 도구가 지원함
- [ ] 독립 대조와 기계 검사의 필수 발견을 처리함

## 5.3 생성 후 체크 항목 예시

- [ ] 실제 호출과 응답 및 파일 규격을 예정값과 대조함
- [ ] 이미지의 메시지, 관계와 구성을 확정 설계와 대조함
- [ ] 사실로 읽히는 구조와 장면을 근거 자료와 대조함
- [ ] 목업과 미세 영역의 확대 관찰을 기록함
- [ ] 정답을 주지 않은 별도 맥락의 전사본이 있음
- [ ] 오탈자, 목록 외 텍스트와 횟수 초과 및 단어 겹침을 대조함
- [ ] 브랜드와 로고 및 차트 방향을 직접 관찰과 전사 결과로 대조함
- [ ] 경계 판독과 판독 불가 영역의 위치 및 허용 사유를 기록함
- [ ] 정정한 이미지에 대한 재검수 결과가 있음
- [ ] 보고 범위와 실제 검수 범위가 일치함

## 5.4 진행과 중단 조건

- 생성 전 적용되는 필수 항목에 미통과나 미확인이 남으면 생성하지 않음
- 생성 후 적용되는 필수 항목에 미통과나 미확인이 남으면 완성 결과로 전달하지 않음. 필요한 경우 검토용 결과임을 명시해 문제를 보고함
- 미통과 항목은 요청 범위와 권한 안에서 작성자가 정정함. 사용자가 체크리스트를 대신 검수하도록 하지 않음
- 설계, 문자열, 프롬프트나 설정을 바꾸면 영향받는 생성 전 판정을 다시 수행함. 새 이미지는 이전 이미지의 검수 결과를 이어받지 않음
- 별도 검토자의 무발견을 결함 부재의 증명으로 표현하지 않음. 위키 자동 검사 통과를 이미지 지침 준수로 확대하지 않음

# 6. 필요한 참고 문서와 지원 파일

## 6.1 기존 참고 문서로 충족하는 범위

작업마다 필요한 범위를 읽고 적용 파일과 버전을 기록함.

| 참고 자료 | 용도 |
|---|---|
| [[인포그래픽 생성 지침]] | 이미지 제작 기준 대조 |
| [[AGENTS]], [[CONVENTIONS]] | 운영 권한, 근거 추출과 위키 관리 |
| [[문서 작성 세부 규칙]] | 분석 기록과 보고의 구조 및 가독성 |
| [[반복 결함 카탈로그]] | 부분 정정, 빈 양식 채움과 정본 오귀속 점검 |
| [[외부 검수 포커스]] | 외부 검토를 진행할 때의 패킷 구성 |
| [[이미지 생성 테스트 기록]] | 과거 프롬프트와 실패 유형 참고 |
| 작업별 원자료와 실물 참고 자료 | 주장과 관계 및 사실로 읽히는 묘사 대조 |

과거 테스트의 설정과 예외 판정을 현행 규칙으로 사용하지 않음. 가격, 지원 설정과 모델 성능 같은 서비스 정보는 필요한 시점에 공식 자료나 실제 호출로 확인함.

## 6.2 새로 마련할 양식

아래 이름은 제안이며 파일은 아직 생성하지 않음. 먼저 스킬과 기록 양식을 마련한 뒤 기계 판정이 필요한 부분을 스크립트로 옮김.

| 제안 파일 | 입력 | 출력과 용도 |
|---|---|---|
| `SKILL.md` | 사용자 요청과 정본 경로 | 이 문서의 절차를 수행하는 스킬 진입점 |
| `실행 기록 양식.md` | 요구와 분석, 설계 및 실행 결과 | 작업별 설계와 판정 근거 기록 |
| `준수 대조 양식.json` | 정본 조항과 근거 파일 | 요구 ID, 시점, 적용 조건, 상태와 버전 관리 |
| `렌더 문자열 양식.json` | 확정 문자열과 배치 | 문자열 ID, 종류, 위치와 횟수의 단일 목록 |
| `독립 준수 검토 지시문.md` | 정본, 원자료와 완성 설계 및 프롬프트 | 생성 전 누락과 충돌의 위치 및 근거 보고 |
| `블라인드 전사 지시문.md` | 이미지 파일만 제공 | 모든 텍스트, 위치, 경계 판독과 차트 관찰 기록 |

전사 지시에는 정답 문자열이나 설계 설명을 넣지 않음. 독립 준수 대조에는 정답과 원자료가 필요하므로 전사 작업과 입력을 공유하지 않음.

## 6.3 구현할 검사 스크립트

각 스크립트는 판정 가능한 범위를 명시하고 구조화된 결과 및 종료 코드를 출력하도록 설계함. 아래 기능은 미구현임.

| 제안 파일 | 입력 | 검사와 출력 |
|---|---|---|
| `infographic_preflight.mjs` | 설계, 준수 대조, 문자열과 예정 호출 | 필수 기록 누락, ID 대응, 문자열 길이와 배정 횟수, 제목 및 설정 일치 검사 |
| `infographic_text_check.mjs` | 문자열 목록과 위치가 포함된 전사본 | 누락, 추가와 횟수 초과 및 단어 겹침 후보 보고 |
| `infographic_release_check.mjs` | 실행 기록, 이미지 규격과 회차별 검수 결과 | 실제 설정 불일치, 검수 증거 누락과 버전 변경 및 전달 조건 검사 |

명사형 여부, 정보 관계의 타당성, 프롬프트 의미 충돌과 이미지의 로고 및 시각적 사실은 위 검사만으로 통과시키지 않음. 문자열 분리 전사와 위치 차이는 직접 대조 대상으로 남기고 단어 겹침은 후보를 검토해 판정함. 정본 변경 감지는 검사를 다시 요구하는 신호이며, 새 조항의 검사 기준을 자동으로 작성한 것으로 취급하지 않음.

자동 차단이 필요하면 검사와 생성 요청을 연결하는 실행 경로도 구현해야 함. 통과 결과를 대조한 파일 해시와 실제 호출 인수에 묶고, 경로 밖 직접 호출이 가능한지도 확인함. 검사 스크립트만 추가하거나 스킬에 중단 문구만 적은 상태를 기술적 강제 차단으로 보고하지 않음.

# 7. 도입 순서와 확인 방법

사용자에게 매번 지침 준수를 확인시키지 않도록 작성자 쪽 절차와 그 작동 여부를 먼저 확인함.

1. 이 실행안의 역할 분담과 진행 조건을 검토함
2. 저장소용 스킬과 기록 양식을 작성하고 현행 지침의 모든 조항이 판정 항목에 대응하는지 확인함
3. 읽기 전용 기계 검사부터 구현하고 독립 내용 대조와의 경계를 확인함
4. 생성 호출 경로 연동과 우회 가능성을 확인한 뒤 구현 수준을 보고함
5. 생성 도구 호출 없이 결함을 넣은 설계와 기록으로 중단 조건을 시험함
6. 실제 생성 요청에서 기록, 검수와 정정 절차가 이어지는지 확인함. 기본 1k/medium과 사용자 요청 시 2k/high 조건을 유지함

최초 시험은 다음 사례를 포함함. 이름만 있는 양식과 정상 기록을 구분할 수 있는지 확인하는 것이 목적임.

| 시험 입력 | 기대 처리 |
|---|---|
| 블록 하나의 유형 누락 | 생성 전 미통과 |
| 비격자 선언과 격자 배치 지시 충돌 | 내용 대조에서 발견, 정정 후 재판정 |
| 목업 내부에 구체적 장면 허용 | 정본과의 충돌 발견 |
| 사용자 요청 없이 2k/high 지정 | 설정 검사 미통과 |
| 검사 뒤 프롬프트 변경 | 기존 통과 무효, 영향 항목 재대조 |
| 전사본이나 확대 검수 근거 없음 | 전달 판정 미확인 |
| 텍스트만 통과한 전체 준수 보고 | 보고 범위 불일치 발견 |
| 새 이미지에 이전 검수 기록 연결 | 버전 불일치로 전달 미통과 |

이번 문서 작성으로 위 시험을 수행한 것은 아님. 이후 보고에서 문서화, 스킬 등록, 검사 구현, 호출 경로 연동과 실제 시험 결과를 구분함.
