> 문서 구조화의 상세 정본임. 작성 전 절차, 유형별 기본 구조, 구조 단위, 분류와 배열, 읽기 쉬운 개조식, 목록 형식과 불릿 규칙을 정의함. 구조 우선 원칙과 원자료 추출 규칙은 [[CONVENTIONS#3.8 구조 우선 작성 (정보 설계)]]이, 작성 과정의 셀프체크는 [[AGENTS|에이전트 작업 지침]]이 소유함.

# 1. 문서 유형별 기본 구조

문서 성격에 맞게 택일하고 가감함.

- 개념 설명: 개요 → 핵심 개념 → 세부 항목 → 예시 → 주의 → 요약
- 절차 안내: 목적 → 전제 → 단계별 절차 → 확인 방법 → 문제 해결
- 비교: 비교 기준 → 항목별 비교표 → 장단점 → 선택 기준 → 권장안
- 정책과 규칙: 적용 범위 → 원칙 → 세부 규칙 → 예외 → 체크리스트

# 2. 구조화 규칙

원자료에서 개수, 분류, 단계나 목차를 도출하는 분석은 [[CONVENTIONS#3.8 구조 우선 작성 (정보 설계)]]의 근거 단위 추출을 마친 뒤 이 절을 적용함. 원자료 분석이 아닌 작업은 바로 작성 전 절차로 들어감.

## 2.1 작성 전 절차

본문을 쓰기 전에 다음 순서로 구조를 설계함.

1. 독자와 목적 파악: 누가 읽고, 읽은 뒤 무엇을 이해하거나 실행해야 하는지 정함
2. 의미 단위 분류: 원자료 기반 분석에서는 추출한 근거 단위를 분류하고, 그 밖의 작업에서는 작성할 내용을 분류함. 정의, 배경, 목적, 핵심 개념, 절차, 기준, 예외, 주의, 예시, 결론과 다음 행동 등을 분류 항목으로 삼음
3. 목차 먼저 설계: 분류에 맞는 헤딩과 항목 구조를 잡고 나서 본문을 채움
4. 작성 후 재구조화: 문장 나열처럼 보이는 곳을 헤딩, 목록, 표와 중첩 불릿으로 다시 나눔

## 2.2 구조 단위, 분류와 배열

- 한 문단에는 한 주제만 둠. 4줄 이상으로 길어지면 목록, 표, 하위 헤딩이나 중첩 불릿으로 분리함
- 라벨형 불릿의 설명이 길거나 항목이 여러 개면 [[#4.3 라벨형 불릿 규칙]]의 분리 기준을 적용함
- 같은 성격은 같은 항목 아래 묶고, 다른 성격은 한 묶음에 섞지 않음
- 같은 수준의 항목은 같은 문법 형태로 맞춤 (병렬 구조). 예: 한 묶음을 모두 "라벨: 값" 또는 모두 "~함"으로 통일
- 추상 설명 뒤에는 가능하면 예시를 붙임. 실행할 내용은 체크리스트나 번호 단계로, 비교는 표로
- 중요도, 순서, 의존관계가 있으면 명시

# 3. 금지

- 긴 문장을 여러 개 이어붙여 한 덩어리로 적기
- 헤딩 없이 문단만 나열하기
- "또한", "그리고", "이와 함께"만 반복하며 잇기
- 원문 순서에 끌려가기 (독자가 이해하기 좋은 순서로 재배열)
- 모호한 항목명("내용", "기타", "참고")만 반복하기

# 4. 읽기 쉬운 개조식과 목록 형식

이 절은 읽기 쉬운 개조식과 내용 성격에 맞는 목록 형식을 정함. 불릿은 문장 나열 도구가 아니라 정보 구조화 도구이며 라벨형과 중첩 불릿에도 아래 규칙을 적용함.

## 4.1 목록 형식 선택

내용 성격별 권장 형식은 다음과 같음.

| 내용 성격 | 형식 |
|---|---|
| 순서 무관한 병렬, 단순 목록이나 요약, 짧은 속성, 빠른 확인 | 일반 불릿 |
| 항목마다 짧은 설명(라벨: 내용으로 끝남) | 라벨형 불릿 (`- **라벨**: 설명`) |
| 상위 항목에 하위 내용이나 긴 설명이 필요함 | 중첩 불릿 (2단계) |
| 순서, 절차, 우선순위, 플로우 | 번호 목록 |
| 같은 기준으로 여러 항목 비교, 조건과 결과 연결, 상태값, 데이터 필드, 리소스와 예외 정의 (값이 짧고 균일할 때) | 표 |

중첩 불릿은 조건, 예외, 예시 또는 절차가 딸린 항목에 적합함. 담당자별 작업을 나누거나 입력과 출력, 저장 방식을 함께 설명할 때도 적합함.

표는 값이 짧고 균일할 때만 적합함. 값이 길거나 들쭉날쭉하면(예: 예외 처리 설명) 셀이 과적되니 라벨형이나 중첩 불릿을 씀. 여러 형식이 겹치면 다음 우선순위로 판정함.

1. 순서가 핵심이면 번호 목록을 씀
2. 값이 짧고 균일하면 표를 씀
3. 항목마다 설명이 길거나 하위 내용이 있으면 중첩 불릿을 씀
4. 단순 동등 나열이면 일반 불릿을 씀

## 4.2 읽기 쉬운 개조식

개조식은 훑어보기 쉽게 쓰는 형식이며 압축 도구가 아님. 음슴체를 지키되 한 번에 이해되게 씀.

- **한 불릿 한 생각**: 한 불릿에는 개념 하나만 둠. 셋 이상을 묶으면 중첩 불릿으로 분리함
- **슬래시 절제**: `/`는 진짜 대안(SMS/이메일)이나 동의어에만 씀. 관계 있는 항목은 "와", "및" 또는 줄바꿈으로 풀고, "A/B/C 시 D 또는 E"처럼 압축하지 않음
- **목록과 표 앞 길잡이**
	- 표나 불릿 묶음 앞에는 묶음의 내용을 한 줄로 안내함
	- 열 머리말이나 헤딩을 되풀이하기만 하는 안내문은 두지 않음. 예: `분류, 값, 보관과 파기.` 대신 `세션 데이터의 종류와 값, 보관 방식과 파기 방식을 정리함.`으로 씀
	- 헤딩이 하위 절만 묶으면 별도 안내문 없이 바로 하위 절로 들어감
- **음슴체 완결**
	- 조사와 연결을 살린 짧은 문장으로 쓰고 `임`, `함`, `씀`과 같은 명사형으로 닫음
	- `미검출/저신뢰/지연 시 보류` 대신 `미검출되거나 신뢰도가 낮거나 처리가 지연되면 보류함.`으로 씀
	- `최소 보관 원칙.`처럼 명사로 끊지 않고 `최소 보관 원칙을 적용함.`으로 씀
	- 라벨과 값으로 구성된 불릿이나 표 셀의 명사 종결은 허용함
- **두괄식과 자족성**: 핵심을 먼저 적고, 불릿 하나만 읽어도 뜻이 통하게 씀. 맥락 없는 라벨로 내용을 대신하지 않음 ([[반복 결함 카탈로그]] CONTENT-002)
- **시각적 호흡**: 빽빽한 한 줄보다 짧은 두세 줄로 나눔. 제목과 본문 묶음이 생기면 헤딩으로 분리함 ([[반복 결함 카탈로그]] STRUCT-007)

## 4.3 라벨형 불릿 규칙

- 라벨은 명사형으로, 한 묶음 안에서 같은 추상 수준으로 맞춤
- 콜론은 볼드 밖에 둠: `**라벨**: 설명` (`**라벨:**` 아님)
- 설명은 1문장 이내가 원칙. 1문장을 넘기거나 항목이 3개 이상이면 중첩(2단계)으로 분리 ([[#2. 구조화 규칙]])
- 한 묶음의 항목별 설명 길이를 비슷하게 유지
- 라벨이 모호하면 더 구체적인 이름으로. "기타", "내용", "참고" 같은 포괄 라벨은 지양 ([[#3. 금지]])

## 4.4 중첩 불릿 규칙

- 중첩은 상위와 하위 관계가 있을 때, 긴 목록을 범주로 묶을 때, 한 항목에 하위 요소가 필요할 때만 씀
- 최대 2단계. 3단계 이상 필요하면 제목과 소제목(헤딩)으로 분리 ([[CONVENTIONS#4. 헤딩 / 넘버링]])
- 상위는 범주명, 하위는 세부 내용. 같은 단계는 같은 문법 형태로 맞춤(병렬)
- 하위 항목이 1개뿐이면 중첩하지 말고 상위 문장에 포함 ([[반복 결함 카탈로그]] STRUCT-004). 단, 형제 라벨 묶음이 병렬이고 그중 일부가 다중 하위를 가질 때는, 시각 일관성을 위해 단일 하위 라벨도 중첩을 허용함(항목별 최적화보다 묶음 병렬성 우선). 이 허용은 재료가 있는 항목에 한하며, 병렬을 채우려고 재료 없는 항목을 만들지 않음 ([[CONVENTIONS#1. 핵심 원칙]] 7)
