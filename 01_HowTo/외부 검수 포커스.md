> Codex 작성자가 외부 검수 패킷에 첨부하는 표준 비판적 검수 프롬프트와 발췌 조합 및 패킷 구성 방법임. 검토자의 권한과 호출 조건, 사용자 승인 게이트는 [[AGENTS|에이전트 작업 지침]]이 소유함.

# 1. 배경

이 저장소는 마크다운 문서가 주요 산출물이므로 일반 코드 검토 대신 문서의 사실성, 논리성, 가독성과 위키 정합성을 우선하는 포커스 텍스트가 필요함. 외부 검토자가 작성 맥락 없이도 지정된 범위를 대조할 수 있도록 필요한 질문을 자체 완결형 검수 패킷으로 전달함.

아래 검수 블록은 공통 규칙을 검토 질문으로 바꾼 파생 텍스트임. 새 작성 규칙이나 운영 권한을 만들지 않음.

원본 anchor의 의미가 바뀌면 대응하는 검수 블록이 같은 기준을 묻는지 함께 점검함. 표에 적힌 작성과 운영 의무는 각 원본 문서가 소유하고, 외부 검토에 필요한 자체 완결형 문구와 발췌 조합은 이 문서가 소유함.

검수 패킷의 기본 표기는 다음과 같음 ([[#5. 검수 패킷 운용 규칙]] 참조). 검토 지침에는 5절의 표준 머리말을 포함함. 머리말이 출력과 금지 사항을 이미 지정하므로 같은 문장을 별도 필드에 반복하지 않음.

```
검토 종류: 사실/정합
검토 지침: <5절 표준 머리말 + 아래 머리말 + P1 + P5 + 끝맺음>
대상: <대상 커밋 해시, 부모 커밋 해시, 변경 파일, 범위>
근거: <원자료 경로 또는 해당 없음>
```

```
이 저장소는 LLM Wiki(마크다운 문서 저장소). 다음 우선순위로 비판적 검수
수행. "괜찮아 보임"은 사유가 아님: 결함을 적극적으로 찾을 것.
대조가 필요한 항목은 패킷에 적힌 파일과 원자료를 직접 열어 수행하고,
접근할 수 없는 근거만 "검증 불가"로 보고할 것.

[P1 사실 오류/출처 미스매치]
- 수치/일정/인용이 출처(_locked 또는 wikilink 대상) 원문과 일치하는가
- 출처 없이 들어간 정량 주장이 있는가

[P2 논리적 비약/추론 정정]
- 합계/누적/인과 관계에 비약 (예: 연차별 합 ≠ 총량)
- 한 문서 단정 사실이 다른 문서/출처와 모순
- A→B, B→A 상호 참조에서 양쪽 다 "상세는 저쪽"으로 미뤄 실체(정의/값/명세)가 부재한 순환 참조인가 (각자 실체 보유한 정상 정본 분담과 구별)
- 원자료 분석에서 범위와 분절 기준을 먼저 기록하고, 결과 개수, 목차나 단계명을 정하기 전에 최초 추출표를 고정했는가. 모든 근거 단위가 새 구조에 대응하거나 제외 사유를 가지며, 합친 이유, `설계 추가`와 변경 이력이 드러나는가. 가능한 다른 묶음을 원전의 유일한 구조처럼 단정하지 않았는가

[P3 누락된 반론/견고성]
- 외부 검증 없이 "확정" 표기된 추정값
- 원문 모순이 정상화되어 감사 추적이 사라졌는가
- 주장에 한계 조건이 빠져 있는가

[P4 톤/구조 일관성 (CONVENTIONS.md 3.4 문체)]
- 음슴체(~임/~함) 준수, 가운뎃점(`·`) 금지, em dash 금지, 두괄식/개조식

[P5 위키 정합성]
- 참조가 실제로 그 내용을 담은 곳을 가리키는가 (제목만 맞고 내용이 없는 참조)
- 상호 참조가 서로 미루기만 해 실체가 어느 쪽에도 없지 않은가
- 깨진 링크, anchor 정합, MOC 등록은 scripts/wiki_lint.mjs가
  기계로 잡으므로 여기서 보지 않음

기조: 회의가 기본. 단순 "합리적으로 보임"은 approve 사유가 아님:
외부 근거가 있어야 통과. CONVENTIONS.md 3.6 수치/목표 인용 원칙, 3.7
외부 근거의 권위 계층 및 AGENTS.md 3. 검수 기준과 호출 방식 우선 가이드.
```

# 3. 발췌 종류별 가이드 (사실/정합, 적대, 가독성)

발췌 종류는 P1부터 P5까지의 검토 시선을 나누기 위한 구성 단위임. 필요한 발췌를 같은 검수 패킷에 넣을 수 있으나 발견은 종류별로 구분함.

## 3.1 사실/정합 발췌 (P1 + P5)

- 머리말 (회의 기조 + "괜찮아 보임" approve 사유 아님 문장)
- [P1 사실 오류/출처 미스매치] 블록 전문
- [P5 위키 정합성] 블록 전문
- 끝맺음 ("[[CONVENTIONS#3.6 수치/목표 인용 원칙 (엄격)]], [[CONVENTIONS#3.7 외부 근거의 권위 계층]] 및 [[AGENTS#3. 검수 기준과 호출 방식]] 우선 가이드" 문장)

검토 지침 예시:

```
검토 종류: 사실/정합
검토 지침: <5절 표준 머리말 + 머리말 + P1 + P5 + 끝맺음>
```

**시선**: 출처가 원문과 일치하고 참조가 실체에 닿는가. 깨진 링크, anchor 정합, MOC 등록은 `scripts/wiki_lint.mjs`가 기계로 잡으므로 여기서 시키지 않음. 검토자는 검수 패킷에 적힌 저장소 파일과 원자료를 직접 열어 대조함.

## 3.2 적대 발췌 (P2 + P3 + 반복 결함 카탈로그)

- 머리말 (회의 기조)
- [P2 논리적 비약/추론 정정] 블록 전문
- [P3 누락된 반론/견고성] 블록 전문
- 끝맺음
- **추가 첨부**: [[반복 결함 카탈로그]] 본문: 과거 반복 결함의 재발 우선 점검 지시

검토 지침 예시:

```
검토 종류: 적대
검토 지침: <5절 표준 머리말 + 머리말 + P2 + P3 + 끝맺음 + 반복 결함 카탈로그 본문>
```

**시선**: 논리 비약, 누락 반론, 한계 조건. 회의 기조 강화. 작성자가 자기 작업에 관대해지는 사각지대 보완.

## 3.3 가독성 발췌 (P4 + 명료성, 낯선 독자 시선)

작성자가 자기 글에서 발견하기 어려운 모호한 용어, 구어체와 반복을 독립 맥락에서 찾음. 어떤 검토자가 언제 수행하는지와 대체 조건은 [[AGENTS#2.2.1 작성자]], [[AGENTS#2.2.2 외부 검토자]], [[AGENTS#2.4.3 작은 변경 사이클 면제 (엄격)]]와 [[AGENTS#3.2 외부 검토자 호출]]을 따름.

**첨부 블록**: 머리말(회의 기조) + 아래 [가독성/명료성] 블록 + 끝맺음

**패킷 구성**: 첨부 블록, 대상 커밋 해시, 부모 커밋 해시, 변경 파일과 범위를 적음. 전달 주체와 세션 조건은 [[AGENTS#2.2.2 외부 검토자]]가 소유함.

```
[가독성/명료성 (낯선 독자 시선)]
맥락 없는 독자로 각 문장을 읽고 다음을 적극 지적:
- 정의 안 된 용어나 지시어 (예: "분석"이 무슨 분석인지 안 적음, 막연한 "이 기능", "해당 값")
- 구어체, 비표준어, 임의 조어 (예: "이름 없는 토큰" 같은 비표준 표현)
- 같은 뜻을 다른 문장으로 반복하는 군더더기
- 단순 문장 나열 (의미 분류와 항목화 안 됨, 라벨에 서너 줄 욱여넣음)
- 1단계 불릿에 복수 항목(역할/단계/종류별) 욱여넣기, 제목이 복수 주제('A와 B')인데 본문 평면 나열
- 목록 형식 오선택 (조건-결과인데 평문, 담당자별로 갈리는데 한 불릿, 길고 이질적 값인데 표로 셀 과적)
- 같은 수준 항목의 비병렬 구조 (문법 형태 제각각)
- 모호한 항목명("내용", "기타", "참고")만 반복
- 음슴체, 가운뎃점, em-dash, 슬래시 절제 위반 (CONVENTIONS 문체와 구조 우선 작성)
기준: 처음 보는 개발자나 심사자가 한 번에 이해하는가.
```

# 4. 우선순위 설계 근거

| 층위 | 의미 | 검출 사례 (가설) |
|---|---|---|
| P1 사실 오류 | 가장 비싼 결함: 잘못된 수치가 산출물로 나가는 위험 | RFP 인용 수치 변조 |
| P2 논리적 비약 | 그럴듯한 추론이 검증된 사실로 둔갑하는 위험 | _locked 추론 정정, 합산 모순 |
| P3 누락 반론 | 작성자가 자기 작업에 관대해지는 사각지대 | "확정" 표기된 추정, 한계 조건 누락 |
| P4 톤/구조 | 점진 부식: 개별 위반은 사소하나 누적되면 위키 가치 훼손 | 음슴체 위반, 라벨 과적 |
| P5 위키 정합성 | 참조가 실체에 닿는가 | 제목만 맞는 참조, 상호 미루기로 빈 참조 |

# 5. 검수 패킷 운용 규칙

이 절은 검수 패킷의 필수 필드와 출력 형식을 소유함. 검토자의 권한, 호출 조건, 전달 주체와 G1 및 G2 결정은 [[AGENTS#2.2.2 외부 검토자]], [[AGENTS#2.4 사용자 승인 게이트]]와 [[AGENTS#3.2 외부 검토자 호출]]을 따름.

검수 패킷은 다음 머리말을 포함함. 파일 수정과 승인 판정을 금지하는 문장은 [[AGENTS#2.2.2 외부 검토자]]와 [[AGENTS#2.4 사용자 승인 게이트]]에서 파생한 자체 완결형 지시임.

```text
당신은 이 변경의 외부 검토자다. 파일을 수정하지 말고 발견만 보고하라.
작성자의 의도나 중간 추론을 추정하지 말고 완성된 변경과 지정된 원자료를 직접 대조하라.
검토 무발견은 결함 부재의 증명이 아니다. 수행 범위와 발견 건수만 보고하라.
각 발견은 발견 종류, 위치, 문제, 근거, 영향, 제안 순서로 작성하라.
Git을 조작하거나 발견을 자동 반영하거나 승인 및 최종 판정을 선언하지 말라.
```

| 필드 | 필수 내용 |
|---|---|
| 검토 종류 | `사실/정합`, `적대`, `가독성` 가운데 수행할 종류 |
| 대상 | 대상 커밋 해시, 부모 커밋 해시, 변경 파일 경로와 검토 범위 |
| 검토 지침 | 선택한 발췌와 위 머리말 |
| 근거 | 직접 대조할 원자료 경로 또는 `해당 없음` |
| 출력 | 발견 종류, 위치, 문제, 근거, 영향과 제안 |
| 금지 사항 | 작성 의도 추측, 파일과 Git 수정, 발견 자동 반영과 승인 판정 금지 |

- 발췌를 나누지 않고 한 번에 대조하기로 결정된 검수에는 표준 포커스 텍스트 전문을 첨부할 수 있음. 검수 실시 여부는 [[AGENTS#3.2 외부 검토자 호출]]이 소유함
- 동일 모델 독립 맥락 대체 검토도 같은 포커스 텍스트와 패킷 형식을 사용함. 대체 검토의 진입 조건은 [[AGENTS#2.2.2 외부 검토자]]가 소유함
